# Qt — framework notes

Read alongside `../coding.md` and `cpp.md`. Qt is a framework, not a
language, so both apply; where `cpp.md` and this file differ, **this one
wins for Qt code** — a Qt codebase that fights Qt's conventions reads as
foreign in its own project.

## Version floor

Qt 6 minimum. Some Qt 5 idioms still compile under 6 — those are the main
way a Qt codebase ages badly, because nothing errors. Others were removed
outright and fail the build. Both are listed below, split, because the
first needs a hand audit and the second does not.

## Casing

Qt's own convention, which its headers, docs and every example follow:

- `PascalCase` — classes, and the `Q`-prefix is Qt's own, not yours
- `camelCase` — methods, signals, slots, variables
- `m_` prefix — member fields
- `SCREAMING_SNAKE` — macros only

## Idioms

- New-style connections: `connect(sender, &Class::signal, receiver,
  &Class::slot)`. Never the `SIGNAL()` / `SLOT()` macros.
- `QOverload<...>::of(...)` to disambiguate an overloaded signal.
- Parent-child ownership — never manually `delete` a parented child.
- `Q_OBJECT` on every `QObject` subclass, without exception.
- `QPointer<T>` for non-owning references to a `QObject` whose lifetime
  you do not control.
- `tr()` around every user-visible string, from the first commit.
  Retrofitting translation across a finished UI is many times the work
  of never skipping it.
- `QSaveFile` for atomic writes, not `QFile` with `Truncate`.
- **Owner-only permissions on any file holding config or secrets.** Qt has
  no single call for this, so it is a rule rather than an idiom — most
  projects write a small helper (`QFile::setPermissions` with
  `ReadOwner | WriteOwner`) and route every such write through it. The
  helper's name is local: one project here calls it `setOwnerOnlyPerms()`,
  which is that project's symbol and not a Qt API. Corrected 2026-08-12,
  when it was listed here beside `tr()` and `QSaveFile` as though it were
  one.
- `QStringLiteral` / `QStringView` in preference to an implicit
  `QString` from a `char*`.

## Retired — Qt 5 spellings

**Still compile under Qt 6, so only a reader catches them:**

- `SIGNAL()` / `SLOT()` macros → new-style `connect`
- `QWeakPointer<T>` for QObject lifetime → `QPointer<T>`

**Removed in Qt 6 — the build catches these, so budget no audit:**

- `QRegExp` → `QRegularExpression`. Moved out of Qt Core; compiles only
  against Qt5Compat, and adding that module to keep it is the outcome
  this list exists to prevent.
- `qrand()` / `qsrand()` → `QRandomGenerator`.

Split 2026-08-14 (ROADMAP CFG-0108): all four sat under a heading reading
*"that still compile"*, which is false of the last two — verified against
this machine's Qt 6 headers, where neither `QRegExp` nor `qrand` is
present in QtCore.

## What checks this

**Qt is the best-covered of the three, because `clazy` is a Qt-aware
analyser and most of this file's idioms are checks it ships.** Names below
were verified against the installed `clazy`.

| Rule | What catches a breach |
|------|----------------------|
| Version floor — Qt 6 minimum | **Split, and the section says so.** The removed Qt 5 spellings (`QRegExp`, `qrand()`) fail the build, so nothing else is needed. The surviving ones do not, which is what the two rows below are for |
| New-style `connect`, never `SIGNAL()` / `SLOT()` | `clazy`'s `old-style-connect`, with `connect-non-signal` beside it |
| `QOverload<...>::of(...)` to disambiguate | `clazy`'s `overloaded-signal` |
| `Q_OBJECT` on every `QObject` subclass | `clazy`'s `missing-qobject-macro` |
| `tr()` around every user-visible string | **`Partial:`** `clazy`'s `tr-non-literal` catches a `tr()` given a non-literal. **Nothing** catches the omission this rule is actually about — a user-visible string never wrapped at all is ordinary code, and the section says retrofitting is many times the work |
| `QWeakPointer<T>` → `QPointer<T>` for QObject lifetime | **nothing** — the section says so outright: it still compiles, so only a reader catches it |
| Casing — Qt's convention, including the `m_` prefix | **`Partial:`** `clang-tidy`'s `readability-identifier-naming`, and only where the project configures it — see `cpp.md`'s row, which this inherits |
| Parent-child ownership — never `delete` a parented child | **nothing that decides it.** A double free may surface under ASan at runtime; the idiom itself is not checked |
| `QSaveFile` for atomic writes; `QStringLiteral` / `QStringView` | **`Partial:`** `clazy`'s `qstring-allocations` level reaches some implicit `QString` construction. **Nothing** checks the `QSaveFile` rule — a `QFile` with `Truncate` is valid code |
| Owner-only permissions on config or secrets | **nothing, and this is the row to worry about.** The section says Qt has no single call for it, so the helper's name is local — there is no symbol to grep and no check to write without knowing the project's own |
