# ANTS-1633 — `cold_eyes_brief` cites code paths from non-spec doc lanes

**Pull:** 28 (2026-05-19)
**Kind:** enhancement
**Lanes:** mcp-cold-eyes, coldeyesengine

## Problem

ANTS-1440 wired `extractCitedCodePaths` for spec lanes (the
`docs/specs/<ID>.md` shape) — the brief envelope surfaces a
`cited_code_paths[]` array so per-lane reviewers can pre-flight
the cited `file:line` pairs for staleness without their own
grep + stat round-trip. The regex was scoped to Ants's
`src/foo.{h,cpp}` mention style.

RetroArch's `/cold-eyes 2026-05-18` dispatched
`cold_eyes_brief(lane="fork-ops", doc_paths=["docs/private/ROADMAP.md",
"docs/private/AUDIT-POLICY.md"])` and got back
`cited_code_paths: []` even though the ROADMAP body cites hundreds
of source `file:line` pairs (`s3.c:1941`,
`menu/menu_setting.c:18832`, etc.). Every lane agent then did its
own `grep -n` + `wc -l` work to verify cited line ranges — 1-2
tool calls per lane × 8 lanes = 8-16 extra round-trips per
`/cold-eyes` run.

## Approach

Generalise the citation regex to language-agnostic
`<path>:<line>` matches, keeping the existing `src/*.{h,cpp}`
pass for back-compat with Ants's own docs. Separate the cited
paths into two arrays:

- `cited_code_paths[]` — regex match resolved on disk under
  the project root.
- `stale_citations[]` — regex match did NOT resolve. Per-lane
  reviewers treat non-empty entries as accuracy-dimension
  findings (cited file moved / deleted / never existed).

The generalised regex accepts the extensions a `/cold-eyes` lane
is likely to be reviewing in a non-Ants project:

```
\b((?:[A-Za-z0-9_][A-Za-z0-9_.-]*/)*
   [A-Za-z0-9_][A-Za-z0-9_.-]*
   \.(?:c|cpp|h|hpp|cc|cxx|py|ts|tsx|js|jsx|
       go|rs|lua|java|kt|swift|m|mm|sh)):\d+
```

Trailing `:<digits>` guards against version-string false-
positives (`1.2.3:4`) and URL ports (`example.com:443`).

## Invariants

- **INV-A / language-agnostic citations resolve.** Citations of
  the form `<path>:<line>` for any extension in the recognised
  set (`.c/.cpp/.h/.hpp/.py/.ts/.tsx/.js/.jsx/.go/.rs/.lua/.java/`
  `.kt/.swift/.m/.mm/.sh/.cc/.cxx`) are returned in
  `cited_code_paths[]` when the path resolves under the project
  root.
- **INV-B / cited-but-missing surface as stale.** When
  `extractCitedCodePaths` is called with a non-null
  `staleCitationsOut`, paths the regex matched but the
  filesystem could not resolve under projectPath are sorted into
  the output list. The brief envelope surfaces them as
  `stale_citations[]`.
- **INV-C / no version-string false positives.** Tokens like
  `1.2.3:4`, `2026-05-19`, and `example.com:443/foo` do NOT
  appear in either array. The regex requires a recognised
  extension at the end of the path component.
- **INV-D / BriefManifest carries staleCitations.** The
  `assembleBriefManifest` path populates
  `BriefManifest::staleCitations` alongside `citedCodePaths`,
  so callers reading the manifest directly (not via MCP) see
  both arrays.
- **INV-13 (carried) / path-escape rejection.** Neither array
  contains paths with `..` segments or absolute paths. For
  resolved paths, the existing `isInsideProject` canonicalises
  through symlinks. For stale paths, a lexical check rejects
  obvious escape attempts before they surface to the caller.

## Test scope

`tests/features/cold_eyes_engine/test_cold_eyes_engine.cpp` —
four new `Ants1633*` tests cover INV-A through INV-D plus the
regex-rejection cases. The existing ENG-9 path-rule defence test
continues to pass.

## Out of scope

- Inlining cited bodies. The `extract` pass only returns the
  path list; the per-lane reviewer agent still reads each
  cited file via its Read tool (ANTS-1319 INV-3 unchanged).
- Heuristics for which file:line citations are "load-bearing"
  vs "incidental mention". Caller treats the full list.
- File-watcher invalidation on the doc body. Each
  `cold_eyes_brief` call re-reads the doc; small fixed cost
  vs the value of always-fresh results.
