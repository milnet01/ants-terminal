# ANTS-1419 — Hoist `CallerCwdContract` declaration into `registerToolProvider` signature

**Pull:** 28 (2026-05-19)
**Kind:** refactor
**Lanes:** claudeintegration, mainwindow, mcp-security

## Problem

ANTS-1404 (Phase 3a, shipped 2026-05-16) classified every registered
MCP tool with a `CallerCwdContract` enum and added refusal at the
dispatcher for the `Required` group. The classification lives in
`ClaudeIntegration::callerCwdContractFor(toolName)` — a static
if-else table separate from the `registerToolProvider("name",
handler)` call sites in `setupClaudeMcpProviders` (mainwindow.cpp).

The table is graceful when a tool is missing (defaults to `Required`
since the ANTS-1520 fall-through flip), and ANTS-1417's coverage
test catches the gap at test-time. But the explicit declaration —
"this tool's contract is `X` because of `Y`" — sits in a file
~700 lines away from the registration that wires the handler. Two
sources of truth, kept in sync by humans and a runtime grep test.

## Approach

Make the contract a positional argument of `registerToolProvider`:

```cpp
m_claudeIntegration->registerToolProvider(
    "verify_changes",
    ClaudeIntegration::CallerCwdContract::Required,
    [this](const QJsonObject &args) -> QString { ... });
```

Each registration declares its security classification next to its
handler — no separate lookup. The `m_toolProviders` map value type
becomes a `RegisteredTool` struct bundling `handler` + `contract`,
and the dispatcher consults the stored contract via
`m_toolProviders.find(toolName)` before falling back to the static
table for inline-dispatched tools (`get_session_info`, `tool_info`).

The static `callerCwdContractFor` helper survives as a back-compat
accessor — several feature tests (`mcp_required_contract_baseline`,
`mcp_caller_cwd_contracts*`) call it directly without instantiating
`ClaudeIntegration`. Removing it would force a much wider test
rewrite for marginal gain; instead, `registerToolProvider` adds a
runtime **drift check**: the passed contract must equal the
table's value, else the registration is refused (a compiled
`return;` — ANTS-1834), the debug log records the mismatch, and a
debug build additionally aborts via `Q_ASSERT_X`. A future
maintainer who updates one source but not the other gets a refused
tool (loud in its own right) in every build config — not just a
debug-only assert that vanishes under `NDEBUG`.

## Invariants

- **INV-1 / `registerToolProvider` takes a contract.** The header
  signature is `void registerToolProvider(const QString &name,
  CallerCwdContract contract, ToolHandler handler);`. Both
  parameter names appear in declaration order.
- **INV-2 / every call site passes a contract.** All 44
  `m_claudeIntegration->registerToolProvider("<name>", ...)`
  invocations in `src/mainwindow.cpp` include
  `ClaudeIntegration::CallerCwdContract::<…>` as the second
  positional argument. Compile-time enforced: the build fails if
  a call drops the contract (signature mismatch — gcc/clang
  cannot select the lambda overload).
- **INV-3 / drift refused in every build (ANTS-1834).**
  `registerToolProvider`'s body queries `callerCwdContractFor(name)`
  and, on mismatch, refuses the registration via a compiled
  `return;` (the tool is not registered), logs the diagnostic via
  `DebugLog::Claude`, and additionally aborts via `Q_ASSERT_X` in
  debug builds. The prior Release behavior — log + continue,
  registering with the call-site contract — silently shipped a
  possibly-mis-classified tool: a `Required` tool registered as
  `Optional` would bypass the `caller_cwd_required` refusal. Pinned
  by `mcp_call_site_contract` INV-6.
- **INV-4 / map value type carries the contract.**
  `m_toolProviders` is `std::map<QString, RegisteredTool>` where
  `RegisteredTool { ToolHandler handler; CallerCwdContract
  contract; }`.
- **INV-5 / dispatcher prefers the stored contract.** The
  `tools/call` dispatch site reads `it->second.contract` from
  `m_toolProviders.find(toolName)` when present, else falls
  back to `callerCwdContractFor(toolName)` for inline tools.

## Test scope

`tests/features/mcp_call_site_contract/test_mcp_call_site_contract.cpp`
— five source-scrape invariants covering header signature, every
mainwindow.cpp call site, drift assertion, map value type, and
dispatcher behavior. The existing
`mcp_caller_cwd_contracts_coverage` test continues to pass: the
static table remains the back-compat source-of-truth tests query.

Verified — temporarily stripping the contract argument from one
call site:
- Build fails to link (signature mismatch — the lambda overload
  cannot bind).
- INV-2 of the new test fails with the offending tool name
  listed.

## Out of scope

- Removing the static `callerCwdContractFor` table. Phase 2
  cleanup; deferred until the test surface stops calling the
  static API directly.
- Enforcing `TabSpecific` contracts at dispatch time. ANTS-1415
  tracks that work — the routing-vs-anchoring overlap with
  ANTS-1392 needs its own spec.

## Acceptance

- `cmake --build build` succeeds with all 44 call sites carrying
  the contract.
- `ctest --test-dir build` reports 1187 / 1187 pass (1182
  baseline + 5 new INV).
- `mcp_call_site_contract.Inv2EveryCallSitePassesContract` fails
  when a call site drops the contract.
