# ANTS-1287 — Roadmap-query indexed parser cache

**Status:** 📋 → (in implementation 2026-05-14)
**Kind:** optimize
**Source:** indie-review-2026-05-13
**Pairs with:** ANTS-1125 (history-archive rotation), ANTS-1117 (roadmap-query verb), ANTS-1247 (status filter).

## 1. Problem

`mcp__ants__roadmap_query` is the canonical way Claude reads the
project's ROADMAP.md (today 10,822 lines, 351 KiB) instead of
re-loading the file as tokens each turn. The IPC verb is implemented
by `RemoteControl::cmdRoadmapQuery` (`src/remotecontrol.cpp:598`),
which delegates to `RoadmapDialog::parseBullets`
(`src/roadmapdialog.cpp:528`).

`parseBullets` walks every line of the markdown body — `lines = text.split('\n')`
followed by an `i < lines.size()` loop that calls `headingLevel` and
runs at least one regex against each bullet body. On a cache miss
(after a roadmap edit, or when the wall-clock TTL of 100 ms expires
in `kRoadmapCacheTtlMs`), every section is re-parsed even when the
caller wants only one section's bullets.

The current cache (`RemoteControl::m_roadmapCacheBullets`,
`remotecontrol.h:217-221`) memoises **the parsed bullet array**.
It does not memoise **where each section starts and ends** in the
source. Partial queries — "give me only the 0.8.0 block" — still
pay the full-file parse cost on every cold cache hit.

A separate cheap pass that records only `## heading` / `### heading`
line ranges, keyed by mtime like the existing bullet cache, lets a
partial query re-parse only the slice it asked for. For ROADMAP.md
today that is roughly an order-of-magnitude reduction in per-call
parse work on cold hits.

## 2. Surface

### 2.1 MCP / IPC argument

Add an optional `section` argument to `roadmap_query`:

```json
{
  "name": "roadmap_query",
  "arguments": {
    "status":  "active",   // existing, ANTS-1247
    "section": "080"       // NEW, optional — slug of a ## or ### heading
  }
}
```

- Empty / missing `section` → behaviour unchanged from today
  (full-file path; status filter applies as in ANTS-1247).
- Present `section` → engine resolves the slug against the heading
  index, slices the file by that section's `[lineStart, lineEnd)`
  range, and reparses only the slice.
- Unknown slug → `{ok:false, code:"bad_section", error:"unknown
  section: <verbatim, ≤ 64 bytes, control bytes → '?'>"}`. Same
  hygiene rule as INV-11 from ANTS-1247.

`section` and `status` are orthogonal: callers may pass both. The
section narrows the bullet set; the status filter applies on top.

### 2.2 Engine module — `src/roadmapindex.{h,cpp}` (new)

Pure (Qt6::Core-only) — lives in `ants_core_lib`. No QDialog deps.

```cpp
namespace RoadmapIndex {

struct Section {
    QString slug;           // unique slug across the doc (e.g. "performance-2")
    QString headingText;    // raw text after the `##` / `###` prefix
    int     level     = 0;  // 2 for ##, 3 for ###
    int     lineStart = -1; // 0-indexed line of the heading itself
    int     lineEnd   = -1; // 0-indexed, exclusive end of the section
};

// Walk only heading lines. lineEnd[i] = first subsequent heading
// with level <= level[i], or total_lines if section i is last.
QVector<Section> buildIndex(const QString &markdown);

// Find a section by slug. Returns nullptr if no match.
const Section *findBySlug(const QVector<Section> &index, const QString &slug);

// Slice a single section out of `markdown`. Returns text for
// lines [lineStart, lineEnd) joined with '\n'. The first line of
// the slice is the section heading itself.
QString sliceSection(const QString &markdown, const Section &section);

// Canonical home for slug helpers (used by RoadmapDialog too;
// removing the file-local statics in roadmapdialog.cpp).
int     headingLevel(const QString &raw, QString *text = nullptr);
QString slugifyHeading(const QString &heading);
QString uniqueSlug(QSet<QString> &seen, const QString &heading);

}
```

### 2.3 Wiring in `RemoteControl::cmdRoadmapQuery`

Cache additions (`remotecontrol.h`):

```cpp
mutable QVector<RoadmapIndex::Section> m_roadmapIndex;
mutable QHash<QString, QJsonArray>     m_roadmapSectionCache;
```

Both share the existing `m_roadmapCachePath` / `m_roadmapCacheMtimeMs` /
`m_roadmapCacheStampMs` keys. Invalidation: when mtime advances or
TTL expires for the bullet cache, the index and section cache also
clear.

Dispatch:

```text
if section.isEmpty():
    # existing full-file path, unchanged
else:
    if cache stale: clear m_roadmapIndex + m_roadmapSectionCache
    if m_roadmapIndex.isEmpty(): buildIndex(read full file)
    sec = findBySlug(m_roadmapIndex, section)
    if !sec: return {ok:false, code:"bad_section", ...}
    if m_roadmapSectionCache.contains(section.slug):
        bullets = m_roadmapSectionCache[slug]
    else:
        slice   = sliceSection(file, *sec)
        bullets = parseBullets(slice) → JSON array, with sectionSlug overwritten to sec->slug (INV-7)
        m_roadmapSectionCache[slug] = bullets
    apply status filter (existing post-cache filter)
    return {ok:true, bullets, path, count, filter, section}
```

## 3. Invariants

- **INV-1.** `section` is optional. Missing / empty `section` is exact
  back-compat: full-file path, existing cache, no behaviour change.
- **INV-2.** Slug lookup is exact-match against `RoadmapIndex::Section::slug`.
  No prefix/substring matching, no case-folding (slugs are already
  lowercase). Unknown slug → `bad_section`.
- **INV-3.** `lineEnd` is exclusive. Section[i].lineEnd ==
  Section[i+1-with-level≤i].lineStart (or `total_lines` for the
  last section). H1 (`# `) and H4 (`#### `) lines do not start a
  Section (parity with `parseBullets`, which only tracks H2/H3 in
  `currentSectionSlug`); they are treated as content of whichever
  H2/H3 they fall inside.
- **INV-4.** Slug parity. `RoadmapIndex::slugifyHeading` and
  `uniqueSlug` produce the same value as parseBullets'
  `sectionSlug` field for the same `## heading` text in the same
  document order. Enforced by removing the file-local statics in
  `roadmapdialog.cpp` and routing both consumers through the
  engine.
- **INV-5.** Section cache key is the slug. mtime advance or TTL
  expiry clears the whole hash; per-key eviction is not required
  (section count ≪ 200 in any realistic doc — see § 6 for the RAM
  bound).
- **INV-6.** Section mode uses `m_roadmapSectionCache` only; it
  does **not** populate or read `m_roadmapCacheBullets`. Switching
  modes pays one cold parse for the new mode.
- **INV-7.** Bullets returned in section mode have
  `sectionSlug == requested slug`. The engine overwrites the
  per-bullet field after parseBullets, since slug uniqueness in a
  slice cannot reproduce mid-document slug-N suffixes without
  re-seeding parseBullets' internal `seen` set (which would widen
  its public surface for no consumer benefit).
- **INV-8.** Status filter (ANTS-1247) applies post-section. The
  response carries `filter`, `count`, and `path` exactly as today;
  `section` is echoed when present.
- **INV-9.** Index build walks every line once (`split('\n')` like
  `parseBullets`), but each line incurs only the four `startsWith`
  prefix checks. No bullet regex passes, no `BulletRecord`
  allocations, no continuation-line inner loop. The expensive
  per-bullet work stays in `parseBullets` and only fires on the
  slice in section mode.
- **INV-10.** Error-message hygiene matches ANTS-1247 INV-11: the
  verbatim `section` echo in `bad_section` is capped at 64 bytes
  and bytes `< 0x20` are replaced with `'?'`.
- **INV-11.** Bad request shapes return `{ok:false, code, error}`
  with no exception. `section.isString()` gate at the MCP dispatch
  layer matches the existing `status` gate.

## 4. Failure modes

| Scenario | Behaviour |
|---|---|
| section absent | Full-file path (unchanged) |
| section empty string | Full-file path |
| section unknown slug | `bad_section`, cache untouched |
| section with controlchar | Hygiene applied; verbatim echo cleaned |
| section + status both set | Both apply; status filters within section |
| Roadmap edited mid-call | Existing mtime check picks up next call |
| ROADMAP.md absent | `no_roadmap_loaded` (existing, unchanged) |

## 6. Performance / RAM

### 6.1 Build cost

`buildIndex` walks `markdown.split('\n')` once and runs
`startsWith` against four prefix strings per line. For ROADMAP.md
today (10,822 lines; 17 H2 + 132 H3 = 149 indexable sections; H1
× 1 and H4 × 18 are not indexed — INV-3) the per-call cost is
the line split plus 4 × 10,822 cheap prefix compares.

By contrast, `parseBullets` walks every line, runs `headingLevel`,
allocates a `BulletRecord` per status-emoji bullet, and runs five
multi-line regex matches per bullet body — across the whole doc.

Order-of-magnitude expectation: `buildIndex` dominated by the line
split; `parseBullets` dominated by bullet regex passes. The slice
path replaces an N-line bullet walk with a (k-line) bullet walk
where k ≪ N for a typical section. Numbers will be measured by
the engine unit test under § 5.1 as informational telemetry, not
as gating thresholds — the structural win does not depend on a
specific µs/ms ratio.

### 6.2 RAM bound

- `m_roadmapIndex`: ~149 `Section` records × (slug + headingText +
  2× int) ≈ ~12 KiB at today's ROADMAP shape (17 H2 + 132 H3).
- `m_roadmapSectionCache`: one `QJsonArray` per slug ever queried.
  Worst case: every section queried at least once → roughly the
  size of `m_roadmapCacheBullets` distributed across hash buckets.
  Net change vs today: ~+200-300 KiB worst case (every section
  cached); 0 in the common one-section-queried path.

Total tracker memory for ANTS-1287 in the realistic case (Claude
queries 2-5 sections per turn): ~20-40 KiB. Within the
"every feature states a memory budget" rule from project memory.

### 6.3 Per-call overhead on full-file path

Zero. The full-file path does not touch `m_roadmapIndex` or
`m_roadmapSectionCache` (INV-6). The branch on `section.isEmpty()`
is the only added work, a single QString compare.

## 7. Migration of file-local helpers

`slugifyHeading`, `uniqueSlug`, and `headingLevel` are currently
file-local statics in `roadmapdialog.cpp` (lines 218, 485, 511).
They are called from:

- `parseBullets` (line 528) — uses all three.
- `extractToc` (caller of `headingLevel`).
- `renderCardsHtml` (caller of `headingLevel` + `uniqueSlug`).

ANTS-1287 moves the three function bodies into the
`RoadmapIndex` namespace. The roadmap dialog adds
`#include "roadmapindex.h"` and replaces the static calls with
qualified calls (`RoadmapIndex::slugifyHeading(...)` etc.). No
behaviour change is intended; the function bodies are copied
byte-for-byte.

Lock-step risk: if the engine's slug rules drift from
parseBullets', section-mode and full-mode would return different
`sectionSlug` values. The migration eliminates the divergence
risk by giving both call-sites a single source of truth.

  request/response shape; chunking is deferred.
- Heading-level granularity beyond `##` / `###`. Bullets above any
  heading (level 0) are not addressable via `section` (the
  full-file path covers them).
