# ANTS-1555 — per-project `.audit_cache/` infrastructure for `audit_run`

**Status:** spec draft (2026-05-18).
**Kind:** implement.
**Source:** ROADMAP.md ANTS-1555 (in-session-2026-05-18, pull-8 dependency
surfaced while sizing ANTS-1504).
**Blocker for:** ANTS-1504 (`since-last-run` mode). Composes with
ANTS-1577 (which was shipped as ANTS-1512 — `audit_run` scoped-check
mode) and ANTS-1580 (test-audit resume-an-audit pattern).
**Pairs with:** ANTS-1254 (`last_audit_summary` — already reads
`<project>/.audit_cache/audit-*.sarif`).

## 1. Problem

`AuditRunner::runAudit` (`src/auditrunner.cpp:418-423`,
`allocSarifPath`) currently writes SARIF to
`/tmp/audit-<sid>-<seq>.sarif` — no per-project cache, no manifest,
no retention. Three consequences:

1. **Cross-session amnesia.** `last_audit_summary` discovers SARIF in
   `<project>/.audit_cache/` (`src/claudeintegration.cpp:2253`),
   but MCP-driven sweeps put their output in `/tmp/`. The two paths
   never see each other. Callers asking
   `last_audit_summary` for the most recent run after an `audit_run`
   sweep silently miss it.
2. **No prior-run anchor.** ANTS-1504 (`since-last-run` mode) and
   ANTS-1513/1580 (test-audit resume) both need a stable
   per-project pointer to the prior sweep's commit + sarif. Today
   there is none.
3. **Tmpfile churn.** `/tmp/audit-<sid>-<seq>.sarif` accumulates over
   the session (no reaper); restart-cleaned only via tmpwatch.

Meanwhile, the AuditDialog GUI **already** writes
`<project>/.audit_cache/audit-<yyyyMMdd-HHmmss>.sarif` +
`audit-*.html` (`src/auditdialog.cpp:3293-3346`) on Export-SARIF.
The directory exists, is gitignored project-wide, and is the
authoritative cache root by convention. ANTS-1555 routes the MCP
runner through the same layout — with a manifest so prior runs are
addressable, and a retention reaper to bound disk use.

## 2. Surface

### 2.1 Directory layout

```
<project>/.audit_cache/
├── audit-<iso-utc>-<git-sha>.sarif    NEW — written by audit_run
├── audit-<iso-utc>-<git-sha>.html     NEW — optional, when formats includes html
├── audit-<yyyyMMdd-HHmmss>.sarif      pre-existing — auditdialog GUI Export-SARIF
├── audit-<yyyyMMdd-HHmmss>.html       pre-existing — auditdialog GUI Export-HTML
├── trend.json                         pre-existing — auditdialog (severity history)
├── baseline.json                      pre-existing — auditdialog (delta marker)
└── index.json                         NEW — manifest tracking audit_run history
```

**ISO timestamp encoding** uses `yyyy-MM-ddTHH-mm-ssZ` (colons
replaced with hyphens — filesystem-safe). Git SHA is the short form
(first 7 chars) when inside a git repo; the literal `nogit` when
not. Examples:
- `audit-2026-05-18T18-32-00Z-acdce78.sarif`
- `audit-2026-05-18T18-32-00Z-nogit.sarif`

The two naming families coexist by construction: the MCP family
always carries a `T<HH>-<MM>-<SS>Z` block + 7-or-`nogit` suffix; the
GUI family is `<8 digit date>-<6 digit time>` with no `T`/`Z`.
The reaper (§ 2.4) keys off **manifest history entries it owns**,
not glob patterns — it only deletes files it previously wrote and
is now dropping from history. AuditDialog-written files are never
touched.

### 2.2 Manifest (`.audit_cache/index.json`)

```json
{
  "version": 1,
  "last_run": {
    "iso_timestamp": "2026-05-18T18:32:00Z",
    "commit": "acdce78",
    "branch": "main",
    "scope": "auto",
    "sarif": "audit-2026-05-18T18-32-00Z-acdce78.sarif",
    "html":  "audit-2026-05-18T18-32-00Z-acdce78.html",
    "elapsed_total_ms": 18450,
    "total_raw": 184,
    "total_actionable": 31,
    "by_tool": {
      "cppcheck": { "elapsed_ms": 1234, "raw_count": 5,  "status": "ok" },
      "ruff":     { "elapsed_ms": 567,  "raw_count": 0,  "status": "ok" }
    }
  },
  "history": [
    { "iso_timestamp": "2026-05-18T18:30:00Z", "commit": "acdce78",
      "sarif": "audit-2026-05-18T18-30-00Z-acdce78.sarif" }
  ]
}
```

`last_run` is the *most* recent entry; `history[]` is the prior
runs in reverse-chronological order (newest first), capped at
**10 entries** (§ 2.4 INV-3). The `last_run` is **not** duplicated
into `history[]`; on the next run it migrates there.

`commit`, `branch` fields are best-effort. Resolution:
- `commit` = `git -C <root> rev-parse --short HEAD` (7-char) or
  the literal `"nogit"` if the call fails / non-zero exit.
- `branch` = `git -C <root> rev-parse --abbrev-ref HEAD` or empty.

`html` is omitted when no HTML was emitted.

`by_tool` includes every tool that completed (status ∈
{ok, timed_out, crashed}); skipped tools (not_runnable) are not
recorded — they imply nothing was scanned.

### 2.3 API extensions (`auditrunner.h`)

```cpp
struct RunResult {
    // ... existing fields ...

    // ANTS-1555 — per-project .audit_cache/ surface.
    QString    cachePath;   // empty when cache write failed / disabled
    QJsonObject priorRun;   // snapshot of prior manifest.last_run; empty on first run
};
```

`sarifPath` is unchanged in meaning but its **value** now points
into `.audit_cache/` (not `/tmp/`). For backward compatibility,
when the project root is not writeable (rare — e.g. read-only mount),
`runAudit` falls back to the legacy `/tmp/audit-<sid>-<seq>.sarif`
path **AND** sets `cachePath` empty. Callers that depend on
`sarifPath` continue to work; callers that need stable cache
anchoring (ANTS-1504, future test-audit resume) check `cachePath`.

### 2.4 Retention reaper

Runs at the end of each successful `runAudit` (after the manifest
is written). Algorithm:

```
manifest = load_manifest()
keep_files = { manifest.last_run.sarif, manifest.last_run.html (if present) }
for entry in manifest.history[:10]:
    keep_files += { entry.sarif, entry.html (if present) }
to_drop = manifest.history[10:]
for entry in to_drop:
    rm <project>/.audit_cache/<entry.sarif>      # best-effort
    rm <project>/.audit_cache/<entry.html>       # best-effort if entry.html present
manifest.history = manifest.history[:10]
save_manifest(manifest)
```

Reaper deletes **only files it tracks in its own dropped-history
entries** — never globs, never files written by auditdialog GUI or
`trend.json`/`baseline.json`. A failure to delete (file already
gone, permissions) is logged via qWarning but doesn't fail the run.

## 4. Out of scope (deferred to follow-up roadmap items)

- **ANTS-1504** — `since-last-run` scope mode (consumes `priorRun`
  + computes `git diff` for narrow re-scan). Tracked separately.
- **ANTS-1513/1580** — Test-audit resume-an-audit pattern (would
  layer additional `.audit_cache/test_audit_<token>/` siblings).
- **SARIF result-entry merging** — ANTS-1504 needs to merge
  carry-forward findings into a new SARIF document. Out of scope
  here; the spec for that lands with ANTS-1504.
- **Cache-by-content key.** Some callers might want to cache by
  `(commit, tool set)` and short-circuit identical sweeps. v1
  doesn't dedupe; every `audit_run` writes a new file. ANTS-1504's
  delta envelope is the cheaper substitute.

## 5. Module split

New files:
- `src/auditcache.h` — `Manifest`, `ManifestEntry`, `recordRun(...)`,
  `loadManifest(...)`, `cacheDirFor(...)`, `cachePathFor(...)`.
- `src/auditcache.cpp` — implementation.

Wired into `auditrunner.cpp`:
- `runAudit` calls `loadManifest(canonProject)` near the top (after
  PathValidation) and copies `manifest.last_run` into `r.priorRun`.
- After the SARIF write succeeds, replace the legacy `allocSarifPath`
  call with `cachePathFor(canonProject, iso, sha)` + the cache write.
  Fall back to `allocSarifPath` if the cache write failed.
- Final step: `recordRun(canonProject, r, req.scope, rawByTool)`
  which appends to history + reaps.

CMake: `auditcache.cpp` joins `ants_audit_lib` (alongside
auditengine/auditrunner). No new external deps.

Sized at ~250 lines C++ (manifest helpers + reaper + auditrunner
integration) + ~120 lines tests.

## 7. Cold-eyes notes

- **Theme:** the directory `.audit_cache/` is already owned by
  AuditDialog GUI; this spec joins the existing layout rather than
  creating a sibling. Discoverability win for callers who already
  know to look there.
- **RAM budget:** manifest is bounded — 11 entries × ~200 B each
  + last_run ≈ 3-5 KiB on disk, parsed transiently into a
  `QJsonObject`. No persistent in-process state.
- **Cross-doc impact:** `CLAUDE.md § Module map` gets a new bullet
  for `auditcache`. `last_audit_summary` description already names
  `.audit_cache/audit-*.sarif`; no change needed there. `CHANGELOG`
  entry under 0.7.92.
- **No new external libraries**; QSaveFile + QFile + QDir.
