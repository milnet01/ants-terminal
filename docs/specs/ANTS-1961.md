# ANTS-1961 — `feedback_query` MCP tool (read the un-triaged tail of a `*_Ants_MCP_Feedback.md` file)

**Status:** accepted (2026-06-03) — implemented on main, feature tests green (cold-eyes loops 1–4 folded). Amended 2026-06-30 (ANTS-3366/3371/3376/3384, INV-12/13/14) and re-run through a fresh 4-loop cold-eyes pass — see § 8.
**Kind:** implement.
**Source:** ROADMAP.md ANTS-1961 (user-request-2026-06-03, Vestige
feedback-file ingestion).
**Pairs with:** ANTS-1962 (`feedback_log`, the write counterpart — shares
the `FeedbackFile` module and the suffix guard); ANTS-1855 (`read_log` —
the sibling read tool whose path-resolution + byte-cap pattern is reused).
**Format contract:** [`docs/standards/mcp-feedback-files.md`](../standards/mcp-feedback-files.md)
(the parser contract is defined there; this spec wires it into an MCP verb).

## 1. Problem

Other Claude Code sessions (Vestige, MAME Curator, Album Builder,
RetroArch, RetroDB) report Ants-MCP problems into per-project
`*_Ants_MCP_Feedback.md` files at the shared root
`/mnt/Games/Scripts/Linux/`. The Ants maintainer session reviews these
weekly, but it only cares about the **un-triaged tail** — everything a
contributor appended since the last maintainer tracking block. Today that
means a full `Read` of the file (the largest, `3D_Engine`, is ~3,460
lines / ~240 KB and growing), every review, just to find the last few
hundred lines that are new. That is the exact token sink the MCP layer
exists to remove (~60 K tokens/review on the big file).

**Layman:** lets the Ants maintainer session pull just the *new* feedback
from a cross-session report file, instead of re-reading the whole thing
every week.

### 2.1 Target resolution

- `path` (string, **optional** since ANTS-3376) — the feedback file. A
  relative path resolves under the `caller_cwd` root; an absolute path is
  used as-is (the canonical case: the shared-root files live outside any
  contributor project, e.g.
  `/mnt/Games/Scripts/Linux/3D_Engine_Ants_MCP_Feedback.md`). **When `path`
  is omitted** the verb derives the conventional
  `<caller_cwd-leaf>_Ants_MCP_Feedback.md` at the shared root (the parent
  of `caller_cwd` — `mcp-feedback-files.md` § "File location & name"), the
  same way `roadmap_log` / `changelog_log` anchor on `caller_cwd`; the
  reply then carries `path_derived:true`. Omitting `path` **with a
  `caller_cwd` that is set but unresolvable** (a non-existent dir →
  empty canonical path → nothing to derive from) is the only remaining
  handler `bad_args` case. A truly **empty/absent** `caller_cwd` never
  reaches the handler — the `CallerCwdContract::Required` dispatcher gate
  rejects it first with `caller_cwd_required` (INV-4); the direct-handler
  feature tests bypass that gate, so they observe `bad_args`.
- **Suffix guard (canonical home: `mcp-feedback-files.md` § "File location
  & name").** The resolved basename MUST end in the exact, case-sensitive
  literal `_Ants_MCP_Feedback.md`; otherwise refuse `{ok:false,
  code:"not_feedback_file"}`. The standard owns the guard literal and the
  refusal code (both `feedback_query` and `feedback_log` cite it rather
  than restating it); the guard lets the verb safely accept out-of-root
  paths — it can only ever touch a feedback file.
- Validated with `PathValidation::validatePath(rawPath, rootCanonical,
  "feedback_query", "path", /*allowOutsideRoot=*/true)` — the 5-arg form
  with the `allowOutsideRoot` bool at `src/pathvalidation.h:46-50`.
  Traversal / malformed → `check.bad` → return `check.err` (code
  `bad_path`). A well-formed path that does not exist → `check.bad=false`
  with empty `check.resolved` (`src/pathvalidation.h` — "empty if it does
  not exist") → `{ok:false, code:"not_found"}`. Read from `check.resolved`
  otherwise.
- The suffix guard is checked on the **resolved/canonical** basename, so a
  symlink or `..` that lands on a non-feedback file is rejected.

### 2.2 The delta (parser contract)

The delta and mapped-ID computation is **defined in full** in
`mcp-feedback-files.md` § "The un-triaged delta (parser contract)". This
spec does not restate the algorithm; it pins the response shape and the
edge-case mapping. The implementation is the pure `FeedbackFile::parse`:

```cpp
namespace FeedbackFile {
struct ParseResult {
    QString     delta;               // text from the first contributor heading
                                     // after the last maintainer heading to EOF
    bool        deltaPresent = false;
    int         deltaStartLine = -1; // 1-based line of the FIRST contributor
                                     // heading of the delta; -1 when empty
    int         deltaLineCount = 0;  // lines in the full (pre-cap) delta
    QStringList mappedIds;           // unique, sorted; ANTS-[0-9]+ from
                                     // maintainer-block bodies only
    int         maintainerBlockCount = 0;
    int         lastMaintainerLine = -1; // 1-based; -1 when none
};
ParseResult parse(const QString &fileContent);
}
```

`src/feedbackfile.h` carries the **full** `FeedbackFile` namespace — both
this spec's `ParseResult`/`parse` and ANTS-1962's `Finding`/`TrackingRow`
/render helpers — as one shared module header in `ants_core_lib`.

Boundary rules (restated only as the test surface — the standard is
canonical): fenced regions (`^\s{0,3}(```|~~~)`, closed on the same fence
char) are skipped; only `^# ` / `^## ` (exactly one or two hashes) outside
fences are boundaries; `###` and deeper headings are inert body lines,
never boundaries; a heading is **maintainer** iff it matches the anchor
regex `^## 📋 Ants Terminal roadmap tracking( update)? \(` whose canonical
home is `mcp-feedback-files.md` § "Maintainer tracking block", else
**contributor**.

### 2.3 Response

Success:

```json
{
  "ok": true,
  "path": "/mnt/Games/Scripts/Linux/3D_Engine_Ants_MCP_Feedback.md",
  "delta": "## 2026-06-01 — session\n\n### …",
  "delta_present": true,
  "delta_line_count": 142,
  "delta_start_line": 880,
  "mapped_ids": ["ANTS-1493", "ANTS-1855"],
  "maintainer_block_count": 4,
  "last_maintainer_line": 870,
  "truncated": false,
  "etag": "ab12cd34"
}
```

- Fully-triaged file (no contributor heading after the last maintainer
  block): `delta:""`, `delta_present:false`, `delta_line_count:0`,
  `delta_start_line:-1`, but `mapped_ids` still populated.
- Zero maintainer blocks: delta = everything after the first heading (the
  H1 title) to EOF; `mapped_ids:[]`; `maintainer_block_count:0`;
  `last_maintainer_line:-1`.
- `path_derived:true` is added (only) when the path was derived from
  `caller_cwd` (INV-14); `tracking` is added (only) when
  `include_tracking:true` (below) — both are absent otherwise.

A `not_found` failure (a well-formed, non-existent feedback file) returns
instead (INV-13/INV-14). `candidates` lists the sibling
`*_Ants_MCP_Feedback.md` paths in the resolved directory, **name-ordered
with the caller's own `<leaf>` file (if present) floated to `[0]`**. The
example below is the **own-match** branch — the caller's `RetroDB` sibling
exists, so it is floated first and `all_other_projects` is absent:

```json
{
  "ok": false,
  "code": "not_found",
  "error": "feedback_query: \"…/Wrong_Ants_MCP_Feedback.md\" does not exist",
  "candidates": ["/mnt/Games/Scripts/Linux/RetroDB_Ants_MCP_Feedback.md"],
  "hint": "no file at that path; this project's own RetroDB_Ants_MCP_Feedback.md is listed first under candidates"
}
```

`candidates` + `hint` appear only when a sibling exists. There are three
hint branches in `fbNotFound`: (1) **own-match** (above) — own file floated
to `[0]`, no flag; (2) **leaf-mismatch** — the caller has a resolvable leaf
but no sibling matches it: `all_other_projects:true` with a hint naming the
leaf, so the caller can tell its file is genuinely absent (not merely
mis-named); (3) **no-leaf** — `caller_cwd` is unresolvable (empty leaf), so
ranking is impossible: a generic "N sibling files exist" hint, no
`all_other_projects` flag.

#### `include_tracking` (ANTS-3371)

`include_tracking` (bool, optional, default false) adds a `tracking`
array to the success response — every maintainer tracking-table data row,
in document order across all maintainer blocks:

```json
"tracking": [
  {"item": "First idea", "ids": ["ANTS-1000"], "status": "📋"},
  {"item": "First idea", "ids": ["ANTS-1000"], "status": "✅",
   "notes": "Shipped 2026-06-30."}
]
```

`mapped_ids` is a flat de-duped ID list; it cannot answer "which of my
prior suggestions shipped" because it carries no status. `tracking` does:
each row carries `{item, ids, status, notes?}` (`notes` omitted when the
row's Notes cell is absent/empty). Rows appear in document order, so a
later block's row for the same item/ID supersedes an earlier one — the
caller reads the last occurrence for the current status. Header and
`|---|` separator rows are skipped; an `n/a` ID cell yields an empty
`ids`. The key is absent entirely when `include_tracking` is unset (lean
envelope). Parsed by the same `FeedbackFile::parse` pass that builds
`mapped_ids` (INV-11), so it adds no extra file read.

### 2.4 Byte cap

- `max_bytes` (int, optional) — default 512 KiB, server-clamped to a 4 MiB
  ceiling (the `read_log` byte-cap defaults, `src/readlog.h:18-19`,
  ANTS-1855). When the delta exceeds the cap, the response keeps the
  **head** of the delta (oldest findings first, from `delta_start_line`
  forward) up to the cap and sets `truncated:true`. `delta_line_count`
  still reports the full pre-truncation count.
- Head-not-tail is deliberate: the maintainer triages the oldest
  un-triaged findings first, stamps a tracking block (ANTS-1962
  `append_tracking`) which advances the watermark, then re-queries to get
  the next chunk — so head-first plus watermark-advance drains the backlog
  in order without ever losing a finding.

### 2.5 ETag

`feedback_query` opts into the ANTS-1499 304 pattern by adding a
`feedback_query` clause to the `isEtagSupportedTool()` `||`-chain
(`src/claudeintegration.cpp`, the chain currently listing `roadmap_query`
/ `current_state` etc. — `read_log` is deliberately NOT in it) and using
the block-local `makeEtagMatchProp()` lambda in the schema builder. The
etag is computed by the centralized dispatch-layer `applyEtagPattern`
(a `sha256` of the response body), so it changes iff the emitted delta /
`mapped_ids` change — the handler supplies no `etag` field of its own. A
matching `etag_match` short-circuits to `{ok:true, unchanged:true, etag}`
without re-emitting the delta — the common case across repeated calls in
one review session.

## 3. Invariants

- **INV-1** — `feedback_query` is read-only: it never creates, writes, or
  changes the mtime of the target file. *Test:* T1 (smoke: mtime stable
  across a call).
- **INV-2** — The resolved basename must end in the exact case-sensitive
  literal `_Ants_MCP_Feedback.md`, else refuse `not_feedback_file` (the
  tool-side suffix guard, shared with ANTS-1962). *Test:* T7.
- **INV-3** — A supplied `path` is routed through
  `PathValidation::validatePath` with `allowOutsideRoot=true`; a
  traversal/malformed path → `bad_path`; a well-formed non-existent path →
  `not_found`. `path` is **optional** (ANTS-3376, INV-14): it is required
  only when no `caller_cwd` is resolvable to derive a default from, in
  which case omitting it → `bad_args`. *Test:* T7.
- **INV-4** — `caller_cwd` is Required: a truly empty/absent value is
  rejected by the `CallerCwdContract::Required` dispatcher gate with
  `caller_cwd_required` **before the handler runs** (so it precedes INV-3's
  handler-level `bad_args`, which fires only for a *set-but-unresolvable*
  `caller_cwd`). A relative `path` resolves under the caller_cwd root, an
  absolute `path` is used as-is. *Test:* T7 (handler-direct, so the
  contract gate is bypassed — see INV-3).
- **INV-5** — The delta is the exact text from the first contributor
  heading after the last maintainer heading to EOF, computed per
  `mcp-feedback-files.md`: fenced regions skipped, only `^# `/`^## `
  outside fences are boundaries (`###`+ inert), maintainer headings
  identified by the anchor regex. This single-step framing is equivalent
  to the standard's two-step algorithm only because the append-at-end rule
  guarantees the last maintainer block is the bottom-most — no maintainer
  heading follows the delta-start (`mcp-feedback-files.md` § "The
  un-triaged delta (parser contract)" — "…no contributor heading follows
  it, by the append-at-end rule"). *Test:* T1, T2, T6.
- **INV-6** — Two delta-present states: (a) zero maintainer blocks → delta
  = everything after the first heading (H1 title) to EOF, so
  `delta_present:true`; (b) fully-triaged (a maintainer block exists but no
  contributor heading follows it) → empty delta, `delta_present:false`.
  `mapped_ids` is computed in both. *Test:* T3, T4.
- **INV-7** — `mapped_ids` = unique, sorted `ANTS-[0-9]+` matches found
  **within maintainer-block bodies only**, never a whole-file scan;
  contributor-cited IDs are excluded. *Test:* T5.
- **INV-8** — The success response carries `delta`, `delta_present`,
  `delta_line_count`, `delta_start_line`, `mapped_ids`,
  `maintainer_block_count`, `last_maintainer_line`, `truncated`, `etag`
  (plus `path_derived:true` when the path was derived — INV-14, and
  `tracking` when `include_tracking:true` — INV-12). The **`not_found`**
  envelope instead carries `candidates` + `hint` (INV-13) and, on a
  derived/omitted-path miss, `all_other_projects` (INV-14).
  `delta_start_line` is the 1-based line of the first contributor heading
  of the delta (that heading line is included in `delta`). *Test:* T1.
- **INV-9** — When the delta exceeds the byte cap (default 512 KiB, ceiling
  4 MiB) the response keeps the head of the delta and sets `truncated:true`;
  `delta_line_count` reports the full pre-truncation count. *Test:* T8.
- **INV-10** — ETag opt-in (via `isEtagSupportedTool`): a matching
  `etag_match` short-circuits to `{ok:true, unchanged:true, etag}`; the
  etag is the dispatch-layer `sha256` of the response body, so it changes
  iff the emitted delta / `mapped_ids` change. *Test:* the 304
  short-circuit is injected centrally at the dispatch layer, so it is
  **not** exercised by this feature bundle (the feature `spec.md` marks it
  out of scope) — covered by the dispatch-layer ETag tests instead.
- **INV-11** — `FeedbackFile::parse` is a pure function in `ants_core_lib`
  (no Qt GUI / MCP / filesystem dependency beyond the in-memory string),
  unit-testable in isolation. *Test:* T1–T6 drive it directly.
- **INV-12** (ANTS-3371) — `include_tracking:true` adds a `tracking`
  array of `{item, ids, status, notes?}` rows parsed from every maintainer
  tracking table, in document order; header + `|---|` separator rows are
  skipped, an `n/a` ID cell yields empty `ids`, and `notes` is omitted when
  the row has no Notes cell. The key is **absent** when the flag is unset
  (lean-envelope default). Parsed in the same `parse` pass as `mapped_ids`
  — no extra file read. *Test:* T10 (parse), T11 (envelope + absent-by-default).
- **INV-13** (ANTS-3366) — A `not_found` envelope is augmented with a
  `candidates` array (the sibling `*_Ants_MCP_Feedback.md` paths in the
  resolved file's directory, name-ordered — with the caller's own-`<leaf>`
  file floated to `[0]` per INV-14) plus a `hint` string, when any sibling
  exists; a directory with no siblings yields neither key (lean envelope).
  This lets a caller that derived the wrong basename recover the right one
  without shelling out to `ls`. *Test:* T14.
- **INV-14** (ANTS-3376) — When `path` is omitted, the verb derives
  `<caller_cwd-leaf>_Ants_MCP_Feedback.md` at the shared root (the parent
  of `caller_cwd`) and sets `path_derived:true` on the reply; with a
  set-but-unresolvable `caller_cwd` it refuses `bad_args` (INV-3/INV-4). On
  `not_found`, the INV-13 `candidates` list floats the caller's own file
  (`<leaf>_Ants_MCP_Feedback.md`) to `candidates[0]`; if no candidate
  matches the leaf, the envelope sets `all_other_projects:true` so the
  caller can tell its file is genuinely absent rather than mis-named.
  *Test:* T12 (`DerivesDefaultPathFromCallerCwd` — derive + read-back, and
  the `all_other_projects:true` branch on a no-own-sibling miss), T13
  (`NotFoundFloatsOwnFileFirst` — own-file floated to `candidates[0]` with
  `all_other_projects` left unset).

## 4. RAM / build cost

- `feedback_query` reads the **whole** file into memory (the delta and the
  mapped-ID scan need every maintainer block, wherever it sits), so peak
  working set is the full file size — bounded by the filesystem, NOT by
  `max_bytes` (the largest corpus file is ~240 KB today). `max_bytes`
  (§ 2.4) caps only the emitted `delta` field, not the read.
  `FeedbackFile::parse` is a pure in-memory string transform with no
  retained state, no cache, no eviction policy.
- New sources `src/feedbackfile.{h,cpp}` join the existing `ants_core_lib`
  (shared with ANTS-1962) — **no new build target**. The
  feature-conformance test joins an existing `tests/features/*` bundle
  (no standalone executable). External libs: none beyond Qt6 Core.

## 5. Out of scope

- **ANTS-1961(b)** — SessionStart surfacing of pending-addenda counts
  across all feedback files. Tracked as **ANTS-1964**; this spec ships
  only the verb.
- Parsing contributor findings into structured fields: contributor blocks
  are free-form prose (per the standard), so the delta is returned as raw
  text — the maintainer reads it. No structured-finding extraction.

## 6. Tests

Feature-conformance bundle `tests/features/mcp_feedback_query/`
(`spec.md` + `test_mcp_feedback_query.cpp`, added to an existing bundle's
`SOURCES`; label `features;fast`). Drives `FeedbackFile::parse` directly
(pure) plus the handler seam for envelope/refusal coverage. Verify each
fails against pre-fix source first.

- **T1** — multi maintainer block, mixed heading forms (the three
  recognised watermark variants): delta starts at the first contributor
  heading after the *last* (max-position) maintainer block
  (`DeltaAfterLastMaintainer`, parser). The full INV-8 envelope-field set
  is asserted separately by `HandlerEnvelopeFields` (the handler seam). The
  etag 304 round-trip is dispatch-layer and out of scope here (INV-10).
- **T2** — fenced code region containing `## Active` below the last
  maintainer block: not treated as a boundary; delta not split.
- **T3** — zero maintainer blocks: delta = everything after the H1 title;
  `mapped_ids:[]`.
- **T4** — fully-triaged (no contributor heading after the last maintainer
  block): empty delta, `delta_present:false`, `mapped_ids` populated.
- **T5** — mapped-ID scoping: an `ANTS-NNNN` cited in *contributor* prose
  below the watermark is NOT in `mapped_ids`; one inside a maintainer table
  IS.
- **T6** — `###`/deeper headings inside both contributor and maintainer
  blocks are inert (never split a block).
- **T7** — refusals: missing `path` **with no resolvable `caller_cwd`** →
  `bad_args` (ANTS-3376: with a resolvable `caller_cwd` the path is derived
  instead); a path not ending `_Ants_MCP_Feedback.md` → `not_feedback_file`;
  a traversal path → `bad_path`; a non-existent feedback file → `not_found`.
- **T8** — byte cap: a delta larger than `max_bytes` returns the head,
  `truncated:true`, and a `delta_line_count` equal to the full count.
- **T9** — opportunistic smoke check: when the real corpus files are
  present at the shared root, run `parse` over each — no crash, and
  `maintainer_block_count` matches a `grep -c` of the anchor regex. When
  the files are absent (e.g. CI), T9 is **skipped** (logged, returns pass)
  — it is a smoke check, not a gate, so its determinism does not depend on
  environment state.
- **T10** (ANTS-3371, `TrackingRowsExtracted`) — `parse` over two
  maintainer blocks fills `trackingRows` in document order: comma-split
  IDs, `n/a` → empty `ids`, the Notes column captured, header + separator
  rows skipped, a later block's row appended after the earlier one.
- **T11** (ANTS-3371, `IncludeTrackingEnvelope`) — the handler omits
  `tracking` by default and emits the `{item, ids, status}` array (status
  emoji preserved) when `include_tracking:true`.
- **T12** (ANTS-3376, `DerivesDefaultPathFromCallerCwd`) — `path` omitted
  with a project dir under a shared root: an existing
  `<leaf>_Ants_MCP_Feedback.md` reads back with `path_derived:true`; a
  derived-but-absent default returns `not_found` with
  `all_other_projects:true` when only other projects' files sit alongside.
- **T13** (ANTS-3376, `NotFoundFloatsOwnFileFirst`) — a `not_found`
  candidate list with the caller's own `<leaf>` sibling present floats it to
  `candidates[0]` (ahead of name-order) and leaves `all_other_projects`
  unset.
- **T14** (ANTS-3366, `NotFoundListsSiblingCandidates`) — a `not_found`
  for a wrong (e.g. doubled-suffix) basename lists the sibling
  `*_Ants_MCP_Feedback.md` files under `candidates` (+ `hint`); a directory
  with no siblings yields no `candidates` key (INV-13).
