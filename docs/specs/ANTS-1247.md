# ANTS-1247 — `status` filter on `roadmap_query` (MCP + IPC)

**Status:** spec, ship-ready after cold-eyes pass.
**Source:** user-2026-05-12 (token-reduction priority).
**Predecessor:** ANTS-1244 § 9 flagged this as the highest-leverage open
follow-up after the 3-verb MCP wiring landed.

## 1. Problem

ANTS-1244 surfaced `roadmap_query` as an MCP tool, replacing a
~123 K-token `Read ROADMAP.md` with a ~13 K-token parsed-bullet JSON
array — **~110 K-token saving per session that needs roadmap context**.

But ~13 K is still a lot when the typical question is *"what should I
work on next?"* — a query that only needs the **active** items
(📋 planned + 🚧 in-progress), not the 311 ✅ shipped entries that
dominate today's payload.

Measured 2026-05-12 (`ROADMAP.md` 498 518 bytes / 9 028 lines, parser-
shaped count via `parseBullets` semantics — every `^[-*] (✅|🚧|📋|💭)`
top-level bullet). Per-bullet compact-JSON cost re-derived locally
(emit shape matches `remotecontrol.cpp:553-562`: id+status+headline+
kind+lanes):

| Slice            | Count | Bytes  | ~Tokens (bytes/4) |
|------------------|------:|-------:|-------------------:|
| **all** (default)| 399   | 48 779 | ~12 195 |
| active (📋+🚧)   |  57   |  7 017 |  ~1 754 |
| shipped (✅)     | 311   | 38 269 |  ~9 567 |
| considering (💭) |  31   |  3 495 |    ~873 |

Per-bullet average: **~122 B**. Active-only is **~7× smaller**
(48 779 / 7 017 ≈ 6.95×) than the default response — saves ~10.4 K
tokens on every "what's next" query, on top of ANTS-1244's ~110 K.
Cumulative saving on a single-active-query session vs. baseline
`Read ROADMAP.md`: **~121 K tokens** (~123 K Read → ~1.75 K).

Note on ANTS-1244 drift: that spec quoted **~133 B/bullet**; the
re-measurement here gives ~122 B (ROADMAP.md has grown since
ANTS-1244 was written, and the bullet shape inputs averaged out
slightly leaner). The 1244 figures are not patched retroactively —
they were ship-correct at write time; this spec is the canonical
replacement for forward references.

## 2. Surface

Add an optional `status` argument to both ship-V1 surfaces:

| Surface  | Where                                                 |
|----------|-------------------------------------------------------|
| MCP tool | `roadmap_query` tool's `inputSchema.properties`       |
| IPC verb | `cmdRoadmapQuery(const QJsonObject &req)` (sig widen) |

**CLI is out of V1.** Rationale (pulled out of the table to keep §2
scannable):
- `src/main.cpp:236-289` declares `--remote`, `--remote-socket`,
  `--remote-tab`, `--remote-text`, `--remote-cwd`, `--remote-command`,
  `--remote-title`, `--remote-lines` as dedicated `QCommandLineOption`
  flags. There's no generic kv→JSON pass-through.
- Adding `--remote-status` is one option decl + one `args["status"] =
  parser.value(remoteStatusOpt)` line — but the token saving this spec
  buys is on the MCP-tool surface, not the CLI. Defer until a script
  user actually asks.

Accepted values: `"all"` (default), `"active"`, `"shipped"`.
Case-insensitive. Empty string / missing → `"all"`.

**Provider signature widens** (Karpathy §3 surgical — narrow change,
no incidental refactor): `setRoadmapQueryProvider`'s argument changes
from `std::function<QString()>` to `std::function<QString(const QString
&status)>`. The MainWindow lambda builds a `QJsonObject{{"status",
status}}` (when non-empty) and calls `m_remoteControl->cmdRoadmapQuery(req)`.
The dispatcher in `claudeintegration.cpp` extracts `arguments.status`
(when `isString()`) and forwards it; case-folding lives **inside
`cmdRoadmapQuery`** only — dispatcher passes through verbatim, single
source of truth (resolves cold-eyes open question on case-fold
location).

**Provider-sprawl note.** This widen, plus ANTS-1248..1252's new
setters, push `claudeintegration.h` to ~16 `setXProvider`/`m_xProvider`
pairs. Per cold-eyes pass 2 (optimisation lane): Rule-of-Three is
exceeded. Consolidation into a `std::map<QString,
std::function<QString(const QJsonObject&)>>` + a single
`registerToolProvider(name, fn)` is allocated as **ANTS-1253**
(follow-up sweep after the pack ships) — out of scope for this spec
to preserve §3-surgical scope.

Out of scope (V1): a `"considering"` filter, multi-status union
(`status: ["active", "shipped"]`). The three buckets above cover the
two known callers (Claude planning queries → `active`; release-notes
or "what shipped recently" → `shipped`) and the default
(`all`, preserves ANTS-1244's contract).

## 3. Response shape

Existing fields preserved; one new field (`filter`) added.

```jsonc
{
  "ok": true,
  "path": "/abs/path/to/ROADMAP.md",
  "bullets": [ /* filtered array */ ],
  "count":  57,           // still bullets.size() — see note below
  "filter": "active"      // NEW: canonicalized lowercase echo
}
```

`count` remains the literal `bullets.size()` (current code:
`remotecontrol.cpp:573` emits `m_roadmapCacheBullets.size()`). The
only contract shift is what `bullets` *contains* once a filter is
supplied. **Strict refinement:** zero-arg / `"all"` call yields the
same `count` as today, byte-for-byte; filtered calls report the
post-filter size.

Error shape for unknown status values (mirrors existing error paths;
follows the `bad_<arg>` convention introduced in
`docs/standards/mcp-errors.md`):

```jsonc
{ "ok": false, "error": "unknown status filter: <verbatim>", "code": "bad_status" }
```

`<verbatim>` is capped at 64 bytes and bytes < 0x20 are replaced
with `?` to prevent ANSI-escape / control-char passthrough into
chat UI (sec lane S1247-1).

## 4. Caching

Existing cache (`m_roadmapCachePath` / `m_roadmapCacheMtimeMs` /
`m_roadmapCacheStampMs` / `m_roadmapCacheBullets`) **continues to hold
the full unfiltered array**. Filtering happens at response build
time — sub-millisecond walk that builds a fresh filtered `QJsonArray`
of ≤ 311 shallow-copies (no re-parse). Estimate: 0.5-2 ms on a warm
cache; first-call parse is the expensive step and stays cached.

Rationale: per-filter cache slots are a waste — three filters × the
existing slot is 3× the memory for zero perceptible win on a 53 KiB
payload. The walk is cheap; the parse + I/O the cache exists to elide
are the expensive parts and they stay cached.

Cache invariant (INV-10 in ANTS-1117) **unchanged**: refresh window is
still mtime-OR-100ms; the filter never invalidates.

## 5. Invariants

Each is anchored to a `// ANTS-1247-INV-N` comment at the load-bearing
site in source, so a future refactor that moves the line also moves
the test.

- **INV-1 (back-compat).** Calling `cmdRoadmapQuery(QJsonObject{})` —
  i.e. the existing zero-arg-equivalent shape — returns every bullet
  `parseBullets(markdown)` produces against the current ROADMAP.md,
  with no filter dropping any. The `399` figure in §1's table is a
  spec-time measurement, not an invariant (this very spec's own §6
  step 7 lands an ANTS-1247 ✅ bullet which moves the count to 400 —
  drift is expected). The contract is "no filter ⇒ no drop", not
  "size equals N". Anchor: `remotecontrol.cpp` `cmdRoadmapQuery` head.
- **INV-2 (active filter correctness).** `status: "active"` returns
  exactly the bullets whose `status` field is `"📋"` or `"🚧"`. No
  ✅, no 💭. Anchor: filter switch.
- **INV-3 (shipped filter correctness).** `status: "shipped"` returns
  exactly the bullets whose `status` field is `"✅"`. Anchor: same.
- **INV-4 (case-insensitive).** `"Active"`, `"ACTIVE"`, `"active"`
  all map to the same filter. Anchor: filter parse.
- **INV-5 (unknown-status error).** Any non-empty `status` value not
  in `{"all", "active", "shipped"}` returns
  `{ok:false, code:"bad_status"}` and **does not invalidate the
  cache**. Anchor: filter parse + error-shape construction.
- **INV-6 (cache invariant preserved).** Two calls within 100 ms with
  different filters must NOT trigger a re-parse — the second
  reuses `m_roadmapCacheBullets`. Anchor: TTL check unchanged.
- **INV-7 (filter echo).** Response includes a `filter` field carrying
  the canonical lowercase resolved filter (`"all"` when absent).
  Anchor: response assembly.
- **INV-8 (MCP schema).** The `roadmap_query` entry in `tools/list`
  declares `status` in `inputSchema.properties` with
  `enum: ["all","active","shipped"]` and a description that quotes
  the active/all token counts. Anchor: tools/list registration in
  `claudeintegration.cpp`.
- **INV-9 (MCP dispatch).** The `tools/call` case for `roadmap_query`
  forwards `arguments.status` (when `isString()`) to the provider
  lambda, which threads it through to `cmdRoadmapQuery(req)`. Anchor:
  dispatch case in `claudeintegration.cpp`.
- **INV-10 (count semantics).** `count` field reflects
  `bullets.size()` post-filter, not the unfiltered total. Anchor:
  response assembly. Note: this **updates** ANTS-1244 INV-2 which
  defined `count` as "total bullets parsed"; once `status` ≠ "all"
  is supported, that definition is refined to "size of `bullets`
  after filter" (zero-arg/all path is byte-identical).
- **INV-11 (error-message hygiene).** `error` field's
  attacker-supplied `<verbatim>` substring is capped at 64 bytes
  and bytes < 0x20 are replaced with `?` (sec S1247-1).

## 8. Memory budget

Per-call peak: one temporary filtered `QJsonArray` plus the response
`QJsonObject`. At full unfiltered size (399 bullets) the array is
~48 KiB; at active-only (57 bullets) it's ~7 KiB. The filter walk
shallow-copies cached `QJsonObject` entries — no re-parse, no deep
copy. Peak released after response sent. The error-case object is
the same size as today's error path.

## 9. Out of scope

- **Multi-status union** (`status: ["active", "shipped"]`). YAGNI for
  V1; the three single-bucket options cover known callers. If a
  caller needs (active + considering) they can call twice and merge.
- **`considering` filter** (💭-only). Brainstorm bullets are rarely
  what Claude needs to plan from; the cost of an extra enum value is
  one line of code but the cost of an extra MCP tool description
  token (the model sees every tool's schema in context) is
  permanent. Defer to a follow-up if asked.
- **Schema-enrichment fields** (`source`, `layman`, `summary`). Still
  out of scope, as flagged in ANTS-1244 § 9. Doubling payload is a
  separate trade-off; this spec doesn't touch it.

## 10. Risks / mitigations

| Risk | Mitigation |
|------|-----------|
| Existing `--remote roadmap-query` callers break. | The change is additive — zero-arg call returns the same payload as today (INV-1). |
| `count` semantic shift breaks a caller that read `count` as "total parsed". | Mitigated by INV-1: when `status` is absent/`"all"`, post-filter `count` = pre-filter `count`. Only callers that opt-in see a different number, which is the point. |
| Future audit run greps for old single-string `cmdRoadmapQuery()` signature. | We update the header decl, the impl, and the one caller site (in `remotecontrol.cpp` dispatch + `mainwindow.cpp` provider lambda). Grep `cmdRoadmapQuery\(\)` post-change to confirm zero hits. |
| MCP description bloats tool-schema tokens enough to negate the saving on small payloads. | Schema delta is ~80-120 tokens (the enum + a description that cites the active/all byte counts; comparable to ANTS-1244's `roadmap_query` description). First call that picks `active` over `all` recoups ~10.4 K tokens. Net positive after a single use, even amortised across the schema's per-session resend cost. |
