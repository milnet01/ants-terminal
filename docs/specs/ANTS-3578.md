# ANTS-3578 — Delta-envelope foundation: partial "changed-since" MCP responses (ANTS-3534 / 3544 / 3546)

**Status:** spec draft (2026-07-19). Cold-eyes loop log at § 10.
**Kind:** implement.
**Source:** ROADMAP.md ANTS-3578 (`🔌 MCP integration deepening — token + perf`);
in-session-2026-07-19, designed jointly with the user as the shared foundation
for the three "don't re-send unchanged bytes" token-savers ANTS-3534 / 3544 /
3546 (the "caching trio").
**Builds on:** the existing all-or-nothing **ETag-304** path — `etagFor`
(`src/claudeintegration.cpp:11309`, `hex16(sha256(payload))`), `applyEtagPattern`
(`:11316`), `isEtagSupportedTool` (`:11254`, already lists all four target
verbs); the **offload/spill** content-store — `offloadBody`
(`src/mcpspill.cpp:138`, `handle = sha256(body).hex()`), `readSpill` / spill caps
(`src/mcpspill.h`); the **process-scoped LRU** pattern — `m_idempotentReadCache`
/ `m_idempotentReadLru` (`src/claudeintegration.h:593`, cap 32 / TTL 100 ms); and
**`CodebaseIndex::StaleSet`** (`src/codebaseindex.h:75`, already computed by
`serve()`).
**Distinct from:** ANTS-3543 (downshift a *would-be-truncated* list to lean rows
— a within-one-response saving). This foundation is a *cross-response* saving:
don't re-send bytes the caller already has from a prior response.

## 1. Problem

Every read verb's re-poll is all-or-nothing. `etagFor` hashes the **entire**
response envelope, so `applyEtagPattern` can only answer "byte-identical → 304"
or "different → here is the whole body again." Three common patterns re-pay a
full body for a near-unchanged one:

- **codebase_index** (ANTS-3544) — session bootstrap eagerly refreshes it
  (ANTS-2140), and any one-file edit mutates the map. The caller re-pays the
  whole symbol/lane map though almost every file is unchanged.
- **append-only query corpora** (ANTS-3534) — `roadmap_query` / `changelog_query`
  / `feedback_query` grow by a few entries between polls; the etag changes, so
  the whole list is re-sent.
- **repeated identical reads** (ANTS-3546) — a subagent review loop reads the
  *same* region five times; nothing changed, but without the caller replaying an
  `etag_match` cursor each time, every read re-pays the bytes. `token_usage`
  can't even see this cost (ties ANTS-3536).

All three want the same thing the 304 can't give: **"send only what changed
since the response I already have."** This spec builds that once and adapts it
three ways.

**Layman:** When you ask for the same big thing again and only a little changed,
the app re-sends all of it. This adds a shared "here's just what changed since
last time" mode, used by three features that each waste tokens re-sending data
you already have.

## 2. Surface

The three items differ **only in how they key a change** (per-file, per-entry,
per-body-hash). Everything else — the response shape, the input channel, the
correctness rule, the memory home — is shared. Build the shared part once (§ 2.1),
then three thin adapters (§ 2.2–2.4).

### 2.1 Shared foundation

**(a) The delta envelope — a response-shape convention, not a framework.** A
delta-capable verb, when it can, returns a `delta` object instead of the full
payload array/map:

```jsonc
{ "ok": true,
  "delta": { "added": [...], "changed": [...], "removed": [<ids/paths>],
             "unchanged": <count-or-list> },
  "base_etag": "<the etag the delta is computed against>",
  "etag":      "<the new full-body etag>" }
```

- `delta` is **truthy-only** — absent on a full response (ANTS-3532 compact /
  `fields=` leave it alone, same discipline as `downshifted`/`truncated`).
- `base_etag` echoes the caller's cursor; `etag` is the new full-body etag. A
  caller holding the `base_etag` body can apply the delta to reconstruct the
  `etag` body — so the two etags make the delta **verifiable**, not a leap of
  faith.

**(b) `etag_match` doubles as the cursor — no new input arg.** The existing
`etag_match` string (already wired for every target verb, `makeEtagMatchProp`)
is reused as the "since" token. `applyEtagPattern`'s current contract is
unchanged when the etags match exactly (still `{unchanged:true, etag}`); the new
behaviour fires only when `etag_match` is **non-empty, does not equal** the
current etag, **and** the verb can map it to a prior emission it can diff
against. Otherwise → full body + fresh etag (see (d)).

**(c) The shared store — one process, one home.** The MCP server is a single
`QLocalServer` per Ants process (`claudeintegration.cpp:1254`), so every CC
session/subagent shares its in-memory caches. New server-side memory lives beside
`m_idempotentReadCache`: bounded (fixed cap + wall-clock TTL, mirroring cap 32 /
TTL 100 ms), holding **hashes/handles/small snapshots only — never unbounded
bodies** (§ 4). This is what lets ANTS-3546's dedup span subagents for free.

**(d) Fallback is mandatory — delta is never a correctness dependency.** When a
verb cannot produce a *provably correct* delta (unknown/evicted base, an
unsupported change type, any doubt), it returns the **full body** with a fresh
`etag`, exactly as today. A wrong or lossy delta is never emitted. This keeps the
feature a pure optimisation: worst case is today's cost, never a wrong answer.

**Dispatch seam.** All of this attaches at the existing `applyEtagPattern` call
site inside `onMcpConnection` (`claudeintegration.cpp:10576`), after the
idempotent-read cache and before wrap/`fields=`/compact — the same place the 304
already lives. The per-verb delta computation is provided by the handler (the
handler knows its data shape); the foundation owns only the envelope + cursor +
store conventions.

### 2.2 Adapter A — `codebase_index` per-file delta (ANTS-3544) · **flagship, build first**

Nearly free: `CodebaseIndex::serve()` **already** computes
`StaleSet {changed, added, removed, mapSourceChanged}` (`codebaseindex.h:75`) on
every warm call by comparing per-file `mtimeMs` (`FileEntry::mtimeMs`) against the
on-disk cached index, and today **discards** it (only a `refreshed` count
survives into the response). The adapter:

- Gives each `FileEntry` a stable **per-file sub-etag** (hash of its serialized
  symbol block; `mtimeMs` alone is a weaker fallback). The full-body `etag`
  stays the whole-map hash.
- When `etag_match` is a *stale* index etag the server can still map to a prior
  index (via a small per-etag snapshot in the shared store, or by recomputing the
  StaleSet against the cached prior index), it returns
  `delta:{ added:[{file,symbols}], changed:[{file,symbols}], removed:[paths],
  unchanged:<count> }` — only changed/added files carry symbols; unchanged files
  are a count (or a path list under a verbose flag).
- session_orient's eager re-orient (ANTS-2140) that replays the prior index etag
  then pays only the changed-file symbols. This is the highest-value case.

### 2.3 Adapter B — server-side auto-304 on repetition (ANTS-3546)

Fires on byte-identical **repetition**, not size. Add `m_emittedHashLru`
(hash → `{stampMs, handle}`) beside `m_idempotentReadCache`:

- Whenever a body is spilled by `offloadBody` (which already content-addresses it
  by `sha256`), record its handle in the LRU.
- Before emitting any offload-eligible body, compute its handle; if it is already
  in the LRU **and** the spill file `spillPath(handle)` still exists, return
  `{unchanged:true, handle, emitted_recently:true}` instead of the bytes — the
  caller re-fetches via `read_spill` exactly as for a size-offload.
- **Staleness:** evict an entry when its underlying file's mtime changes (a
  changed corpus must never 304 stale); the LRU is bounded (cap + TTL) and holds
  only hashes+handles. Distinct from `etag_match` (client-cursor) — this needs
  **no client memory**; the server remembers what it emitted.

### 2.4 Adapter C — append-verb delta (ANTS-3534) · **hardest; phase carefully**

Per-corpus cursor, because the corpora differ in how safely a tail cursor works:

- **`feedback_query`** — already has a line-number watermark
  (`feedbackfile.cpp:1066`, the maintainer-line cursor); the delta is "finding
  blocks below the watermark." Easiest; the model for the others.
- **`changelog_query`** — append-only with dated `## [version]` section
  boundaries at the top; the cursor is the newest version the caller already has.
  Easy.
- **`roadmap_query`** — **unsafe for a tail watermark.** Position-is-priority
  reordering and in-place status flips (`📋`→`✅`) mutate entries *above* any tail
  cursor. Roadmap must use **per-entry sub-hashing** (added/changed/removed keyed
  by `[ANTS-NNNN]` id + a per-bullet content hash — converging with § 2.2's
  per-file technique), or fall back to a full body. INV-13/14 forbid a tail-only
  roadmap delta.

Interacts with the ANTS-1117 100 ms parser-cache TTL (the delta is computed off
the same cached parse) and, per the ANTS-3534 body, may not be worth it below the
offload threshold — see § 5 phasing.

## 3. Invariants

### Foundation

- **INV-1** — a delta-capable verb returns either the full body (+ `etag`), or
  `{unchanged:true, etag}` (exact match, unchanged today's behaviour), or
  `{delta:{…}, base_etag, etag}` — and `delta` is **truthy-only** (absent on a
  full response). *Test:* pure test on the envelope helper across the three
  outcomes; scrape that no verb emits an empty `delta`.
- **INV-2** — the cursor is the existing `etag_match` string; **no new input arg**
  is added for it. A caller passing a stale `etag_match` gets a delta when the
  server can map it, else a full body — never a `bad_args`. *Test:* schema scrape
  (no new prop) + behavioural (stale etag → delta or full, never error).
- **INV-3** — `base_etag` in a delta response equals the `etag_match` it was
  computed against, and `etag` is the new full-body etag; applying `delta` to a
  `base_etag` body yields a body whose recomputed etag equals `etag`. *Test:* pure
  round-trip — build base, apply delta, hash, assert equals `etag`.
- **INV-4** — when a correct delta cannot be produced (unknown/evicted base,
  unsupported change type, any uncertainty), the verb returns the **full body**
  with a fresh `etag` — never a wrong or partial delta. Delta is an optimisation,
  never a correctness dependency. *Test:* behavioural — evict the base, re-poll →
  full body, correct content.
- **INV-5** — every new server-side store is **bounded** (fixed cap + TTL,
  mirroring `m_idempotentReadCache`) and holds only hashes / handles / small
  snapshots, never unbounded bodies. *Test:* source-scrape the cap + TTL
  constants; a stress test that N distinct emissions never grows the store past
  the cap.

### Adapter A — codebase_index (ANTS-3544)

- **INV-6** — `codebase_index` with a stale mappable `etag_match` returns
  `delta:{added, changed, removed, unchanged}` computed from the `StaleSet`
  `serve()` already builds — only changed/added files carry symbols. *Test:*
  pure test driving `serve()` with a prior index + a one-file change → delta names
  exactly that file.
- **INV-7** — each `FileEntry` carries a stable per-file sub-etag so the delta can
  list unchanged files without their symbols; the whole-map `etag` is unchanged in
  shape. *Test:* pure — two builds differing in one file share every other file's
  sub-etag.
- **INV-8** — a re-orient replaying the prior index etag pays only changed-file
  symbols, not the whole map. *Test:* behavioural — full map bytes ≫ delta bytes
  for a one-file change.

### Adapter B — auto-304 (ANTS-3546)

- **INV-9** — on emitting an offload-eligible body the server records its `sha256`
  handle in `m_emittedHashLru`; a later about-to-emit body whose handle is in the
  LRU **and** whose spill file exists returns `{unchanged:true, handle,
  emitted_recently:true}` instead of the bytes. *Test:* pure test on the
  LRU-check helper (hash present + spill exists → 304 envelope).
- **INV-10** — the auto-304 fires on byte-identical **repetition** regardless of
  size, and only when the body is re-fetchable via `read_spill` (spill file
  present) — never leaving the caller unable to get the bytes. *Test:* behavioural
  — repeat an identical small-but-spilled read → second call 304s; a read with no
  live spill → full body.
- **INV-11** — an emitted-hash entry is evicted when its underlying file's mtime
  changes (a changed corpus never 304s stale); the LRU is bounded, hashes+handles
  only. *Test:* behavioural — emit, touch the file, re-poll → full body (not a
  stale 304).

### Adapter C — append-verb delta (ANTS-3534)

- **INV-12** — `feedback_query` (line watermark) and `changelog_query` (dated
  section boundary) return only entries after the caller's cursor when given a
  mappable `etag_match`. *Test:* behavioural per verb — append one entry, re-poll
  with prior etag → delta of exactly that entry.
- **INV-13** — `roadmap_query` **never** emits a tail-only delta: because entries
  reorder and flip status above any tail cursor, it uses per-entry sub-hashing
  (id + content hash) for added/changed/removed, or falls back to a full body.
  *Test:* behavioural — flip a status on an early bullet, re-poll → that bullet is
  in `changed` (a tail watermark would miss it) **or** a full body is returned;
  never a delta that omits it.
- **INV-14** — no append-verb delta silently omits a changed entry: an in-place
  edit or status flip *above* the cursor is reported in `changed`, or the verb
  falls back to full. *Test:* behavioural — edit an entry above the cursor →
  present in `changed` or full body; never absent.

## 4. RAM / build cost

- **Memory:** two new bounded stores in the single server process — (1)
  `m_emittedHashLru` (ANTS-3546): `hash→{stampMs, handle}`, cap in the low tens
  (mirror `kIdempotentReadCacheCap=32`) + TTL, ~tens of bytes/entry → **< a few
  KB**; (2) an optional per-etag base snapshot for codebase_index/roadmap deltas
  — if used, cap it hard (a handful of recent index/roadmap etags) and store the
  *prior index/parse* the delta diffs against, evicted by the same LRU. Prefer
  recomputing the delta against the existing on-disk cache (codebase_index) over
  holding snapshots, to keep this near-zero. No unbounded growth; every store
  names its cap here. Per-file/per-entry sub-etags are small strings recomputed
  from data already in memory.
- **Build:** no new target, no new external library. Reuses `QCryptographicHash`
  (already used by `etagFor`) and the existing spill/LRU machinery.

## 5. Out of scope / phasing

Recommended build order (cheapest-and-safest first — each ships independently on
the shared § 2.1 foundation):

1. **§ 2.1 foundation + Adapter A (ANTS-3544)** — the flagship. `StaleSet` already
   exists, so this is mostly "stop discarding the diff + gate on `etag_match` +
   add per-file sub-etags." Highest value (session bootstrap), lowest risk.
2. **Adapter B (ANTS-3546)** — moderate: one LRU + a spill-liveness check, reusing
   the offload path. Real win for subagent review loops; cross-subagent for free.
3. **Adapter C (ANTS-3534)** — hardest. Ship **feedback + changelog first** (they
   have safe cursors); **roadmap per-entry sub-hashing last, or defer** to its own
   follow-up if the sub-hash cost outweighs the saving (the ANTS-3534 body's own
   "worth it below the offload threshold?" open question).

Explicitly **out of scope** here: a generic client-side delta-apply library (the
client is Claude Code, which reconstructs from `base_etag`+`delta` itself); any
change to the exact-match 304 behaviour (unchanged); ANTS-3543's within-response
downshift (orthogonal).

## 6. Tests

Feature test dir `tests/features/delta_envelope/` (foundation, label
`features;fast`) plus per-adapter coverage folded into each verb's existing
feature suite where one exists:

- **Foundation (INV-1..5):** pure tests on the envelope/cursor helper and the
  bounded-store cap/TTL; the round-trip (INV-3) and fallback (INV-4) are the
  load-bearing ones — build a base body, apply a delta, assert the reconstructed
  etag matches; evict the base, assert a correct full body.
- **Adapter A (INV-6..8):** pure tests on `CodebaseIndex::serve()` / the StaleSet
  → delta mapping (the diff machinery is already pure and unit-tested).
- **Adapter B (INV-9..11):** pure tests on the emitted-hash LRU helper + spill
  liveness; behavioural repetition/staleness through the offload path.
- **Adapter C (INV-12..14):** behavioural per corpus — the roadmap
  reorder/status-flip case (INV-13/14) is the critical one; it must be RED against
  a naive tail-watermark implementation before the sub-hash/fallback is restored.

Per the project convention, each new test must fail against pre-fix source first.

## 8. Open questions

- **base-snapshot vs recompute.** For codebase_index the delta can be recomputed
  against the on-disk cached index (near-zero RAM) — preferred. For roadmap, is a
  small per-etag parse snapshot worth the RAM, or is recompute-from-cache enough?
  Resolve at Adapter-C design time.
- **etag → base mapping.** How does a verb map an incoming `etag_match` back to the
  prior state it should diff against — a reverse index of recent etags → cached
  state, bounded? Foundation-level; settle in phase 1.
- **roadmap sub-hash payoff.** Per the ANTS-3534 body: below the offload
  threshold, is a roadmap delta worth the per-entry hashing? May defer roadmap
  entirely (INV-13's fallback keeps it correct meanwhile).

## 9. Security boundaries

No new trust boundary. Deltas cross the same authenticated UDS/MCP socket as full
responses (SO_PEERCRED UID + 0700). Spill re-fetch (ANTS-3546) reuses the existing
0600 content-addressed spill files under `~/.cache`. No user input is newly
trusted; `etag_match` is an opaque server-minted token, validated by lookup (an
unknown value → fallback, never an error path or a file read).
