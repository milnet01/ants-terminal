# ANTS-1424 — `roadmap_log` MCP write verb

## Problem

`roadmap_query` (read) is the only MCP surface that touches
`ROADMAP.md`. Logging a new bullet requires the assistant to:

1. Read `.roadmap-counter` to allocate the next ID.
2. Read `docs/standards/roadmap-format.md` to recall the bullet
   shape (status + ID + bold headline + body + Layman + Kind +
   Source + optional Lanes).
3. Format the bullet string.
4. Edit `ROADMAP.md` to insert at the right section.
5. Rewrite `.roadmap-counter` with the bumped value.

User observation (2026-05-16): "isn't that exactly what Ants
MCP can do?" — every assistant logging an item today bypasses
the token-economy machinery the rest of the MCP buys. The shape
is also easy to get wrong (status emoji codepoint, ID padding,
indentation) which forces rework.

## Goal

A single MCP verb `roadmap_log({...})` that:

- Validates the bullet's required fields and the section
  slug.
- Allocates the next ID from `.roadmap-counter`.
- Formats the bullet per `docs/standards/roadmap-format.md` § 3.
- Inserts it at the end of the named section (before the next
  `##` / `###` heading).
- Rewrites `.roadmap-counter` atomically.
- Returns `{ok:true, id, file, line, bytes_written}`.

## Design

### Schema

```jsonc
{
  "name": "roadmap_log",
  "description": "Append a new roadmap bullet to ROADMAP.md ...",
  "inputSchema": {
    "type": "object",
    "properties": {
      "caller_cwd":  { "type": "string", "description": "Required ..." },
      "section":     { "type": "string", "description": "Slug from roadmap_query" },
      "status":      { "type": "string",
                       "enum": ["planned", "in-progress",
                                "shipped", "considered"] },
      "headline":    { "type": "string", "maxLength": 200 },
      "kind":        { "type": "string",
                       "enum": ["implement", "fix", "audit-fix",
                                "review-fix", "doc", "doc-fix",
                                "refactor", "test", "chore",
                                "release", "perf", "security",
                                "feature", "enhancement",
                                "investigate", "research",
                                "accessibility", "optimize",
                                "package", "marketing", "ux"] },
      "source":      { "type": "string", "maxLength": 200 },
      "body":        { "type": "string", "maxLength": 4000 },
      "layman":      { "type": "string", "maxLength": 400 },
      "lanes":       { "type": "array",  "items": { "type": "string" } },
      "id_hint":     { "type": "integer", "minimum": 1 }
    },
    "required": ["caller_cwd", "section", "status",
                 "headline", "kind", "source"],
    "additionalProperties": false
  }
}
```

### Contract

`CallerCwdContract::Required`. The verb mutates project state
(ROADMAP.md + `.roadmap-counter`), so the ANTS-1404 dispatcher
refuses absent `caller_cwd`. PathValidation (`ANTS-1295`)
anchors `ROADMAP.md` and `.roadmap-counter` to the caller's
project root.

### Status → emoji map

| `status` arg   | Emoji written |
|----------------|---------------|
| `planned`      | 📋             |
| `in-progress`  | 🚧             |
| `shipped`      | ✅             |
| `considered`   | 💭             |

Word form is the canonical wire shape; emoji codepoints are
hard to type for some assistants. The verb writes the emoji.

### ID allocation

```
counter = read(.roadmap-counter)
if (id_hint is set):
    if (id_hint <= counter): return {ok:false, code:"id_taken"}
    new_id = id_hint
else:
    new_id = counter + 1
write(.roadmap-counter, new_id)
```

The atomic rewrite uses `QSaveFile` for crash-safety. No flock
in v1 — concurrent MCP writes against the same `.roadmap-counter`
within the same Ants instance are serialised on the MCP socket's
single-threaded handler.

### Bullet format

```
- {emoji} [ANTS-NNNN] **{headline}**
  {body — optional, indented two spaces; line-wrapped at ~70
   columns by the verb; preserves the user's existing wrap if
   the body arg arrives pre-wrapped}
  **Layman:** {layman — optional}
  Kind: {kind}.
  Lanes: {comma-joined} {— optional}.
  Source: {source}.
```

The verb does NOT line-wrap the body — that's a non-trivial
formatting concern. v1 expects the caller to pass a body that's
already wrapped; the verb writes it verbatim with a two-space
indent on each line.

### Section locator

Reuses `RoadmapIndex::buildIndex` (already used by
`cmdRoadmapQuery`'s section path). `findBySlug(index, slug)`
locates the section bounds; the insertion point is **immediately
before the next `##` or `###` heading** (or EOF if the section
is the file's last).

### Envelope

**Success:**
```json
{
  "ok": true,
  "id": "ANTS-1424",
  "file": "ROADMAP.md",
  "line": 5612,
  "bytes_written": 432
}
```

**Error codes:**
- `caller_cwd_required` — dispatcher (ANTS-1404).
- `bad_path` — PathValidation (ANTS-1295).
- `missing_field` — required arg absent.
- `bad_status` — status not in enum.
- `bad_kind` — kind not in enum.
- `bad_section` — section slug not found in ROADMAP.md.
- `headline_empty` — headline arg present but empty.
- `id_taken` — `id_hint` ≤ current counter.
- `counter_read_failed` — `.roadmap-counter` unreadable.
- `counter_write_failed` — atomic rewrite failed.
- `roadmap_write_failed` — ROADMAP.md write failed.
- `no_roadmap` — ROADMAP.md not found under caller_cwd.

## Invariants

- **INV-1.** Verb registered as MCP tool with the schema above.
- **INV-2.** Classified `CallerCwdContract::Required`.
- **INV-3.** Allocated ID equals
  `max(counter+1, id_hint or 0)`; counter is bumped to match.
- **INV-4.** Bullet inserted at the end of the named section.
  Existing bullets in the section unchanged.
- **INV-5.** Status emoji written corresponds to the `status`
  arg per the table above.
- **INV-6.** On any error, no partial write to ROADMAP.md and
  no counter advance.
- **INV-7.** Concurrent calls within the same MCP server
  serialise on the socket handler — counter can never go
  backwards.
- **INV-8.** Response carries `id` (full `ANTS-NNNN` string) +
  `line` (1-based, where the new bullet starts) +
  `bytes_written` (size of the appended content).

Label `features;fast`. Source-scrape for the regression
contract; behavioural correctness (actual file writes) is
covered by a separate scratch-fixture integration test in
v2 (deferred to keep this ticket's scope tight).

## Out of scope (v2 / v3)

- Updating existing bullets (`roadmap_update`).
- Removing bullets (`roadmap_retire`).
- Body line-wrapping helper.
- `flock` on `.roadmap-counter` for cross-process safety.
- Behavioural test using a real ROADMAP.md fixture in a
  tempdir.
- Adding the new bullet to a specific `####` subsection (only
  `##` / `###` slugs supported in v1).

## RAM budget

Per call: one file read (counter ~10 B), one file read
(ROADMAP.md ~700 KiB), one file write (ROADMAP.md ~700 KiB +
bullet ~500 B), one file rewrite (counter ~10 B). Negligible
in steady state — call frequency is human-paced.

## Build cost

~250 LoC: ~150 LoC `cmdRoadmapLog` + ~40 LoC schema in
claudeintegration.cpp + ~10 LoC contract classification + ~50
LoC test file. One TU touched, no new headers.
