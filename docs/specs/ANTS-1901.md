# ANTS-1901 — Master Ants-MCP on/off toggle with graceful degrade

**Status:** accepted (2026-06-25, cold-eyes loops 1–5 folded; user
signed off at the `--max-loops` cap — last 2 passes 0 CRITICAL, all
verified findings folded).
**Kind:** feature.
**Source:** ROADMAP.md ANTS-1901 (user-request-2026-05-27, raised during
ANTS-1897 implementation; default-on confirmed by user 2026-06-25).
**Pairs with:** ANTS-1897 (orientation prelude + per-feature toggle —
this inserts the master toggle above it; ANTS-1897 INV-14 owns the
host-path `ANTS_MCP_SOCKET` export this gates), ANTS-1900 (the
flatpak-path PTY env-var export of that same socket), ANTS-1735 (auto
model switcher).

**Layman:** Ants quietly runs a little helper that lets Claude Code use
its cheaper built-in tools and read terminal state. Right now there's no
way to turn that helper off. This adds one master switch — "Enable Ants
MCP integration" in Settings — that's ON by default. Flip it off and
Ants stops the helper: Claude can no longer call Ants's tools, the
start-of-session cheat-sheet stops appearing, and the auto model-switcher
goes quiet. Every feature that leans on the helper notices it's gone and
behaves sensibly instead of breaking.

> **Anchor convention (whole spec):** line numbers throughout are
> anchors, not contracts — implement by grepping for the named symbol
> (e.g. `if (!enabled) return;`, `startMcpServer(`), not the literal
> line. This codebase's own line comments are known to drift, and a
> sibling spec (ANTS-1897) already cites pre-drift numbers for the same
> `startMcpServer` block.

## 1. Problem

The Ants MCP server starts unconditionally. `setupStatusBarChrome()`
binds the socket and exports its path with no user gate:

- `src/mainwindow.cpp:4046-4048` — builds `/tmp/ants-terminal-mcp-<pid>`
  and calls `m_claudeIntegration->startMcpServer(mcpSocket)`.
- `src/mainwindow.cpp:4058` — `qputenv("ANTS_MCP_SOCKET", …)` so child
  PTYs (hence Claude sessions) can find the socket.
- `src/mainwindow.cpp:4062` — installs the SessionStart orientation hook
  whenever `claudeMcpOrientationEnabled()` (default true).

A user who does not want Ants observing their Claude sessions, or who
simply wants the integration off, has no switch. The consequences:

1. **No opt-out of observation.** The socket is always live; any Claude
   session in an Ants tab can call the `mcp__ants__*` verbs that read
   terminal state, scrollback, and project files.
2. **No master over the per-feature toggles.** ANTS-1897 added a
   per-feature orientation toggle and ANTS-1735 added auto-switcher
   tuning keys, but there is no top-level switch above them — the
   visual hierarchy the ROADMAP calls for (master → per-feature opt-ins)
   does not exist.
3. **The live keystroke actuator has no MCP-level kill switch.** The
   auto model switcher's `/model` injection
   (`src/claudestatuswidgets.cpp:1735-1739`) is gated only by its own
   `switch_enabled` key; there is no single "turn the whole integration
   off" control that also silences it.

## 2. Surface

### 2.1 Config key — `claude.mcp_enabled`

New boolean, **default `true`**, mirroring the simplest existing
`claude.*` bool (`claude.mcp_orientation_enabled`, NOT the
`claudeAutoModel()` whitelist-object pattern).

**`src/config.h`** (near the other `claudeMcp*` accessors, ~L136-139):

```cpp
bool claudeMcpEnabled() const;
void setClaudeMcpEnabled(bool enabled);
```

**`src/config.cpp`** (mirror `setClaudeMcpOrientationEnabled`, ~L552-559):

```cpp
bool Config::claudeMcpEnabled() const {
    return m_data.value("claude.mcp_enabled").toBool(true);   // default ON
}
void Config::setClaudeMcpEnabled(bool enabled) {
    if (!storeIfChanged("claude.mcp_enabled", enabled)) return;
    save();
}
```

The default `true` lives only in the `.toBool(true)` getter; the dotted
key is absent from `config.json` until first toggled (so existing configs
inherit ON without a migration).

### 2.2 Startup gate (next-launch semantics)

Wrap the socket-bind + env-export block at `mainwindow.cpp:4046-4058` and
fold the orientation-install condition at `mainwindow.cpp:4062`:

```cpp
if (m_config.claudeMcpEnabled()) {
    QString mcpSocket = QDir::tempPath() + "/ants-terminal-mcp-" +
                        QString::number(QApplication::applicationPid());
    m_claudeIntegration->startMcpServer(mcpSocket);
    qputenv("ANTS_MCP_SOCKET", mcpSocket.toLocal8Bit());

    if (m_config.claudeMcpOrientationEnabled()) {
        // … existing ANTS-1897 install block …
    } else {
        ants::mcp_orientation::uninstall();
    }
} else {
    // Master switch off: no socket, no /tmp file, no env export.
    // Remove any stale orientation hook so disabled installs don't
    // leave a cheat-sheet entry behind in ~/.claude/settings.json.
    ants::mcp_orientation::uninstall();
}
```

The existing ANTS-1897 INV-14 ordering-rationale comment at
`mainwindow.cpp:4050-4057` (and the orientation-install comment at
`:4060-4061`) are preserved verbatim inside the new `if` — the snippet
above elides them as `…`, it does not delete them.

When off: no socket binds, no `/tmp/ants-terminal-mcp-*` file is created,
`ANTS_MCP_SOCKET` is never exported (so the orientation script's
`[ -S "$ANTS_MCP_SOCKET" ]` guard self-silences in any pre-existing
shell), and the hook entry is removed. This is the primary mechanism —
the socket simply does not exist when the master switch is off.

`m_claudeIntegration->setMcpEnabled(m_config.claudeMcpEnabled())` is
called once here too, seeding the dispatcher's live bit (§ 2.4) to match
the startup decision.

### 2.3 Auto model switcher degrade

`ClaudeStatusBarController::refreshAutoModelSwitch()`
(`src/claudestatuswidgets.cpp:1479`) already early-returns on its own
gate (`if (!enabled) return;`, ~L1509). Add a master-switch early return
alongside it:

```cpp
if (!cfg.claudeMcpEnabled()) return;   // master MCP switch off
```

`cfg` is the mtime-guarded `cachedConfig()` the controller reads each
tick (ANTS-2116, `claudestatuswidgets.cpp:1481`) — `setClaudeMcpEnabled`
calls `save()`, which rewrites `config.json` and bumps its mtime, so the
next tick observes the new value. This degrades **immediately** on a
runtime toggle, with no restart. The early return sits before both
`decide()` (~L1677) and the `/model` injection (~L1735), so the switcher
neither evaluates nor actuates. It
also sits before both ledger writes — the firing ledger
(`ModelSwitchLedger::appendRecord`, `claudestatuswidgets.cpp:1765`) and
the near-miss ledger (`ModelNearMissLedger::appendRecord`,
`claudestatuswidgets.cpp:2220`, in `maybeEmitNearMiss`) — so the
`model_switch_ledger` records (the ROADMAP's umbrella term for both)
stop being written transitively, with no per-write gate needed.

The model state chip (ANTS-1888) is transcript-driven
(`m_tracker->shellState(pid)`, `claudestatuswidgets.cpp:1493`), not
MCP-driven, so it keeps showing the current tier. Its only MCP-derived
annotation — the pending-switch tier (`m_autoSwitchPendingTier`, set
~L1723) — is downstream of the early return, so it simply stays cleared.
No separate chip wiring is required.

### 2.4 Verb-dispatch guard — `mcp_disabled`

`ClaudeIntegration` holds no `Config` reference, so it carries its own
live bit set from `MainWindow`:

**`src/claudeintegration.h`:**

```cpp
void setMcpEnabled(bool enabled) { m_mcpEnabled = enabled; }
// …
bool m_mcpEnabled = true;   // master switch mirror (ANTS-1901)
```

Insert at the very top of the `tools/call` branch
(`src/claudeintegration.cpp:8652`) — before the caller_cwd contract
gate, which itself already runs before the cache lookup (per the
contract comment at `claudeintegration.cpp:8686`, "Runs BEFORE the
cache lookup"). Placing the guard there means a disabled session never
serves even a memoised response. Refuse every verb when the bit is off:

```cpp
if (!m_mcpEnabled) {
    QJsonObject env;
    env["ok"]    = false;
    env["code"]  = QStringLiteral("mcp_disabled");
    env["error"] = QStringLiteral(
        "Ants MCP integration is disabled (Settings → General → "
        "\"Enable Ants MCP integration\"). Re-enable it to use this tool.");
    responseText = QString::fromUtf8(
        QJsonDocument(env).toJson(QJsonDocument::Compact));
    toolHandled    = true;
    dispatchResult = QStringLiteral("mcp_disabled");
    // fall through to the shared recordCall / recordMcpTrace path
}
```

The envelope matches the established refusal shape (`{ok:false, code,
error}`, cf. the `caller_cwd_required` emit at `claudeintegration.cpp:8739`
and `csErr` at `remotecontrol.cpp:11303`) and is surfaced in `mcp_trace` +
`token_usage`'s failed-call accumulator via the existing
`dispatchResult` mechanism.

**Why this guard exists given § 2.2 already removes the socket:** the two
cover different windows.

- **Startup-disabled:** no socket binds (§ 2.2), so the dispatcher is
  unreachable. The guard is moot here.
- **Runtime toggle-off (socket already bound this session):** tearing
  down a live socket mid-session risks interrupting an in-flight Claude
  MCP call, so § 2.6 keeps the socket bound until the next launch.
  `setMcpEnabled(false)` flips the bit, and this guard makes every verb
  refuse with `mcp_disabled` for the rest of the session — an immediate,
  safe behavioural opt-out without a risky teardown.

This satisfies the ROADMAP's explicit ask for a `mcp_disabled` envelope
on `model_switch_stats` (`remotecontrol.cpp:11519`) by covering it — and
every other verb — uniformly at the chokepoint, rather than per-verb.

### 2.5 Settings UI — master checkbox above the children

In the **General** tab (`setupGeneralTab`, `settingsdialog.cpp:140-396`
— the tab that already hosts the Claude integration toggles; NOT the
"AI Assistant" tab at `setupAiTab` `:552`, which is for legacy
AI-provider config), add `m_claudeMcpEnabled` as a master checkbox
**above** the auto-switch group (`settingsdialog.cpp:259`) and the
orientation checkbox (`settingsdialog.cpp:338`), mirroring
`m_claudeMcpOrientation` (declared `settingsdialog.h:98`; created
`settingsdialog.cpp:338`; loaded `settingsdialog.cpp:1027-1028`; applied
`settingsdialog.cpp:1154`).

- **Label:** "Enable Ants MCP integration".
- **Tooltip / sub-label:** notes that turning it **on** takes effect on
  restart (the socket binds at launch); turning it **off** stops Ants's
  tools immediately.
- **Cascade:** when unchecked, disable (grey out) the auto-switch group
  and the orientation checkbox — they are meaningless without MCP. Copy
  the existing `mirrorMaster` enable/disable cascade at
  `settingsdialog.cpp:315-331` (the lambda + its `QCheckBox::toggled`
  connect; cf. ANTS-1897 INV-14).
- **Apply:** `applySettings()` (`settingsdialog.cpp:1119`) writes
  `m_config.setClaudeMcpEnabled(m_claudeMcpEnabled->isChecked())`
  alongside the sibling toggles.

### 2.6 Runtime propagation

The `emit settingsChanged()` at the tail of `applySettings()`
(`settingsdialog.cpp:1281`) is connected in `MainWindow`
(`mainwindow.cpp:1959`). Add to that handler:

```cpp
if (m_claudeIntegration)
    m_claudeIntegration->setMcpEnabled(m_config.claudeMcpEnabled());
```

This gives the immediate verb-refusal on toggle-off (§ 2.4). The socket
itself is **not** bound or torn down here — binding is a launch-time
decision (§ 2.2), and the UI sub-label states "on" needs a restart.
Toggle-off additionally removes the orientation hook for future sessions
via the same handler calling `ants::mcp_orientation::uninstall()` when
`!claudeMcpEnabled()`.

### 2.7 Degrade matrix

Every MCP-dependent consumer and how it behaves when the master switch
is off (the ROADMAP's required dependency-matrix):

| # | Consumer | Degrade site | How it's covered |
|---|---|---|---|
| 1 | MCP socket bind + `/tmp` file + `ANTS_MCP_SOCKET` export | `mainwindow.cpp:4046-4058` | Direct gate (§ 2.2) — none of it runs when off. |
| 2 | Auto model switcher `/model` actuator (ANTS-1735) | `claudestatuswidgets.cpp:~1509` | Direct early return (§ 2.3) — no decide, no inject. |
| 3 | Model state chip (ANTS-1888) | n/a (transcript-driven) | Transitive — keeps showing the tier; pending-switch annotation stays cleared via #2. |
| 4 | All MCP verbs incl. `model_switch_stats` (ANTS-1891) | `claudeintegration.cpp:8652` | Socket absent at startup (§ 2.2); `mcp_disabled` envelope on runtime toggle-off (§ 2.4). |
| 5 | Orientation SessionStart hook (ANTS-1897) | `mainwindow.cpp:4062` + the `settingsChanged` handler | Direct gate (§ 2.2) + `uninstall()` (§ 2.6). |
| 6 | `model_switch_ledger` writes | `claudestatuswidgets.cpp:1765` / `:2220` | Transitive — both writes are downstream of #2's early return. |
| 7 | Config plumbing | `config.cpp` / `config.h` | New `claude.mcp_enabled` key (§ 2.1). |

Rows 1, 2, 4, 5, 7 each have a direct invariant (INV-2, INV-4, INV-5,
INV-3, INV-1 respectively). Rows 3 (model chip) and 6 (ledger writes)
are intentionally invariant-less — both are covered *transitively* by
INV-4's early return, so a separate invariant would test the same code.

## 3. Invariants

- **INV-1** — `Config` exposes `claudeMcpEnabled()` defaulting to `true`
  on an absent key, and `setClaudeMcpEnabled()` round-trips through
  `save()`/reload. *Test:* `mcp_master_toggle` config round-trip — fresh
  `Config` reports `true`; set `false`, reload from disk, reports
  `false`.
- **INV-2** — There is exactly one `startMcpServer` call and one
  `qputenv("ANTS_MCP_SOCKET", …)`, both structurally inside a
  `claudeMcpEnabled()` branch whose `else` binds no socket — so a false
  value at startup skips both. *Test:* source-grep `mainwindow.cpp` —
  **exactly one** `startMcpServer(` and **exactly one**
  `qputenv("ANTS_MCP_SOCKET"` in the file (a second occurrence anywhere
  fails the count==1 assertion), and a `claudeMcpEnabled()` branch opens
  before the `startMcpServer(` line. The `else`-binds-nothing half is
  covered by INV-3 (its `uninstall()`-in-`else` grep), not re-asserted
  here. Structural lock; the feature-test harness is source-grep, per
  `flatpak_host_shell`.
- **INV-3** — The orientation-hook install is gated such that a disabled
  master switch removes any existing hook (`uninstall()` reached) and
  never installs. *Test:* source-grep `mainwindow.cpp` — the `else`
  branch of the master gate calls `ants::mcp_orientation::uninstall()`.
- **INV-4** — `refreshAutoModelSwitch()` early-returns when
  `claudeMcpEnabled()` is false, before `decide()`, the `/model`
  injection, and both ledger writes. *Test:* source-grep
  `claudestatuswidgets.cpp` — a `claudeMcpEnabled()` early return precedes
  the `QStringLiteral("/model ")` injection literal (the call spans
  lines: `sendToPty(` then `QStringLiteral("/model ")` — match the
  literal, not a `sendToPty("/model ` token that does not exist).
- **INV-5** — The `tools/call` dispatcher returns
  `{ok:false, code:"mcp_disabled"}` for any verb when `m_mcpEnabled` is
  false, and the guard sits ahead of the caller_cwd gate so a disabled
  session never serves a cached body. *Test:* source-grep
  `claudeintegration.cpp` — a `!m_mcpEnabled` guard emitting `code`
  `mcp_disabled` appears after the `method == "tools/call"` branch opens
  (`:8652`) and before the `env["code"] = QStringLiteral("caller_cwd_required")`
  assignment (`:8739`) — i.e. it is the first refusal gate in the
  branch. (Name that specific emit site, not a bare `caller_cwd_required`
  match — the string also appears in hint/example text.)
- **INV-6** — The Settings **General** tab has a master checkbox that,
  when unchecked, disables the auto-switch group and orientation
  checkbox. *Test:* source-grep `settingsdialog.cpp` — `m_claudeMcpEnabled`
  created inside `setupGeneralTab`, written in `applySettings`, and
  driving an enable/disable cascade on the child controls.
- **INV-7** — `settingsChanged` propagates the new value to
  `ClaudeIntegration::setMcpEnabled` at runtime. *Test:* source-grep
  `mainwindow.cpp` — the `settingsChanged` lambda calls `setMcpEnabled`.
The `mcp_disabled` taxonomy registration is a **release-coupling
requirement, not a runtime invariant**, so it lives in § 7 (Cross-doc
impact) with its own test surface — keeping the INV namespace
runtime-only (INV-1…INV-7).

## 5. RAM / build cost

Negligible. One `bool` config key (absent from disk until toggled) and
one `bool` member on the existing `ClaudeIntegration` singleton. No new
state that grows, no eviction policy needed, no new external library. The
test adds one source file to an existing bundle (no new link target).

## 6. Out of scope

- **Menubar entry (ROADMAP part c).** The ROADMAP floated an optional
  `View → Claude → MCP integration` menu action. The Settings master
  toggle fully satisfies the on/off requirement; a menubar duplicate is
  convenience, not contract, and adds an action-state-sync surface to
  maintain. Deferred — a thin checkable `QAction` mirroring
  `claudeMcpEnabled()`. **Split to its own follow-up, ANTS-2172**, so
  this item ships the load-bearing gating and the convenience duplicate
  is tracked separately (the ROADMAP ANTS-1901 bullet's part (c) +
  "also in the menubar" Layman line were moved there). This is the only
  part of the original ANTS-1901 ask this spec intentionally drops.
- **Live socket bind/teardown on runtime toggle.** Turning the switch
  **on** mid-session does not bind the socket (next launch does);
  turning it **off** does not unlink the socket file (next launch does).
  The dispatcher guard (§ 2.4) makes off behave correctly without a
  mid-call teardown. A future item could add safe live bind/teardown if
  a restart-free experience is wanted.
