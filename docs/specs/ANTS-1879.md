# ANTS-1879 — `roadmap_log op:append_batch` verb

**Status:** spec draft, cold-eyes loops 1 + 2 + 3 + 4 folded (2026-05-26).
**Kind:** enhancement.
**Source:** ROADMAP.md ANTS-1879 (vestige-feedback-2026-05-26 Obs #22).
**Composes with:** ANTS-1878 (`op:create_section` returns a slug this
verb appends into).
**Pairs with:** ANTS-1690 (`op:flip_batch`, the same single-read +
single-commit shape on the write side).

**Layman:** Appending 14 bullets to one section today means 14
round-trips through the tool. A batch append (one call that carries
the whole list) matches what Edit can do in a single edit. Pure
latency-and-token optimisation; no behaviour change for callers that
keep using `op:append`.

## 1. Problem

Vestige's audio-architecture addendum needed 14 bullets under one
section. `cmdRoadmapLogAppend` (`src/remotecontrol.cpp:3001`) is a
per-bullet verb — every call reads ROADMAP.md, reads
`.roadmap-counter`, allocates one id, splices one bullet, writes both
files. Fourteen calls means:

1. 14 separate read-modify-write cycles, each racing the
   QFileSystemWatcher and the next call's read.
2. 14 atomic-commit pairs (`ROADMAP.md` + `.roadmap-counter`), each
   call individually transactional but the **batch as a whole** can
   fail at bullet K leaving K-1 ids consumed and one extra
   `pending` write half-applied at the OS level.
3. Tool-call transport overhead per bullet — the dominant cost when
   the bullet bodies are short.

`op:flip_batch` already solved the analogous problem on the
status-flip side (ANTS-1690, doc comment at
`remotecontrol.cpp:3996-4009`, handler at `:4010`). The same shape
— one read, one in-memory transform, one atomic commit — fits the
append path naturally.

## 2. Surface

### 2.1 Verb shape

`op:"append_batch"` accepted by `RemoteControl::cmdRoadmapLog`
alongside the existing `append`, `flip`, `flip_batch`, `annotate`,
and `create_section` (ANTS-1878) ops:

```jsonc
{
  "op": "append_batch",
  "caller_cwd": "/path/to/project",
  "section": "phase-10-6-multi-threading-concurrency",
  "bullets": [
    {
      "headline": "Worker pool sizing.",
      "status": "planned",
      "kind": "implement",
      "source": "audio-addendum-2026-05-26",
      "body": "Optional body prose.",
      "layman": "Optional layman line.",
      "lanes": ["audio", "threading"],
      "id_hint": 99000  // optional, must exceed current counter (synthetic example)
    },
    { /* next bullet */ }
  ]
}
```

All bullets land in the same `section`. New declarations in
`src/remotecontrol.h` (next to `cmdRoadmapLogFlipBatchForTest` at
`remotecontrol.h:621`):

```cpp
// op:append_batch dispatch from cmdRoadmapLog (m_main-independent).
QJsonDocument cmdRoadmapLogAppendBatch(const QJsonObject &req);
// Test seam — same shape as cmdRoadmapLogFlipBatchForTest.
QJsonDocument cmdRoadmapLogAppendBatchForTest(const QJsonObject &req);
```

`id_hint` is honoured **only on the first bullet**; a `id_hint` on
any bullet at index ≥ 1 is silently ignored (the batch's id
sequence must remain contiguous — see INV-6).

### 2.2 Atomic shape (single read, single commit per file)

1. Validate top-level fields (`caller_cwd`, `section`, non-empty
   `bullets` array).
2. Single read of ROADMAP.md + `.roadmap-counter`. Run the
   format-detect (`unrecognised_format`), section-locator
   (`bad_section` / `bad_case`), and counter-state gates
   (`counter_missing` / `counter_read_failed` /
   `stable_prefix_unsupported`, ANTS-1877) **before** per-bullet
   validation. Any of these short-circuits the whole batch with no
   `skipped[]` — same envelope shape as the single-bullet path.
   ANTS-3397 — the counter-state gate auto-creates `.roadmap-counter`
   at 0 (rather than refusing `counter_missing`) when the roadmap has
   no counter file AND no bullet ids of any kind (greenfield); a
   roadmap that already carries ids but lacks the counter still refuses
   (`counter_missing`). Parity with the single-bullet path.
3. Per-bullet pre-validate `headline`, `status`, `kind`, `source`,
   plus the enum gates on `status` (planned/in-progress/shipped/
   considered) and `kind` (the existing
   `cmdRoadmapLogAppend`-validated set). A bullet that fails
   validation is captured in `skipped[]` with its index + code; the
   batch continues for the rest. An **individual bullet with every
   required field missing** is also a per-bullet validation
   failure (`code: "missing_field"`, NOT a hard refusal — it joins
   `skipped[]` like any other). The empty-array case is already
   gated in step 1.
4. Allocate N ids sequentially from `counter+1` (honouring an
   optional `id_hint` on the **first** bullet only — keeping the
   batch's id sequence contiguous).
5. Format each accepted bullet into its `- <emoji> [ANTS-NNNN] **…**`
   block using the same helper as the single-bullet path. Extract
   the existing block at `cmdRoadmapLogAppend:3293-3344` into a
   private member helper with this signature:
   ```cpp
   QString RemoteControl::formatRoadmapBullet(
       const QJsonObject &bulletReq,
       const QString    &idStr,
       const QString    &statusEmoji,
       QStringList      &scrubbedNames);  // out — tool-XML names stripped
   ```
   The out-param mirrors the existing flow at
   `remotecontrol.cpp:3314-3318`, where `rcScrubLeakedToolXml` fills
   `scrubbedNames` to surface a response-level `warnings` array.
   `cmdRoadmapLogAppend` is updated to call the new helper as part
   of the same change (INV-10).
6. Splice all N blocks at `section.lineEnd` in one slice, then
   atomically commit ROADMAP.md, then atomically commit
   `.roadmap-counter` bumped to `counter + N`. **On counter-commit
   failure, roll ROADMAP.md back to the pre-splice content** —
   mirrors the existing single-bullet rollback
   (`remotecontrol.cpp:3383-3415`).

### 2.3 Refusal codes

- `missing_field` — top-level (`caller_cwd`, `section`) or `bullets`
  empty.
- `bad_section` / `bad_case` — parity with single-bullet path.
- `unrecognised_format` — parity.
- `counter_missing` / `counter_read_failed` / `stable_prefix_unsupported`
  — parity (ANTS-1877).
- `id_taken` — `id_hint` ≤ current counter (only honoured on the
  first bullet).
- `headline_empty`, `bad_status`, `bad_kind` — per-bullet validation
  failure surfaces in `skipped[]` (not a hard refusal).
- `roadmap_write_failed` / `counter_write_failed` — atomic-commit
  faults; ROADMAP.md is rolled back on counter-commit failure.

### 2.4 Success envelope

```jsonc
{
  "ok": true,
  "ids": ["ANTS-1900", "ANTS-1901", "ANTS-1902"],
  "file": "ROADMAP.md",
  "lines": [4321, 4332, 4344],   // 1-based per accepted bullet
  "bytes_written": 1248,         // total UTF-8 of accepted blocks
  "applied_count": 3,
  "skipped":       [             // empty when none skipped
    { "bullet_index": 7, "code": "headline_empty",
      "error": "headline must not be empty" }
  ],
  "skipped_count": 1
}
```

`skipped[]` row uses `bullet_index` — append-specific noun, not to
be renamed to flip_batch's `locator_index`
(`remotecontrol.cpp:4118`). The two verbs have different per-row
identifiers because the entities differ (bullets vs locators); only
the envelope shape (`ok:true` even on empty result, paired
`<verb>_count` + `skipped_count`) is shared.

**Partial-apply policy — semantic parity with `flip_batch`.** Per
`cmdRoadmapLogFlipBatch` at `remotecontrol.cpp:4244-4256`,
flip_batch returns `ok:true` even when **every** locator skipped
(empty `flipped:[]`, populated `skipped:[]`). `append_batch`
mirrors that semantic: an all-skipped batch returns `ok:true`,
`ids:[]`, `applied_count:0`, populated `skipped:[]`, and the
ROADMAP.md / counter files are NOT touched (no atomic commit needed
when nothing changed). The caller distinguishes "everything ok" vs
"nothing applied" via `applied_count` and `skipped_count`, not via
`ok`.

**Field-name asymmetry, intentional.** The aggregate count field is
`applied_count` (not `flipped_count` — append doesn't "flip"). The
parity claim is *semantic* (envelope shape: `ok:true` for the
empty-result case, paired aggregate + `skipped` arrays), not
byte-for-byte field-name parity. An implementer doing the
"parity with flip_batch" pass should NOT rename `applied_count`
back to `flipped_count`.

### 2.5 Per-bullet body scrubbing

Each bullet's `body` runs through `rcScrubLeakedToolXml` exactly as
`cmdRoadmapLogAppend` does (`remotecontrol.cpp:3316-3324`).
Scrubbed sibling names from all accepted bullets roll up into ONE
response-level `warnings[0].lost_parameters` array (deduplicated —
same name across multiple bullets appears once). The single
warning is emitted only when at least one bullet had a scrub hit,
matching the single-bullet path's `body_scrubbed_tool_xml` warning
shape (`remotecontrol.cpp:3429-3439`).

### 2.6 Schema description

The `roadmap_log` schema lives in `src/claudeintegration.cpp:5669+`
(NOT `src/mainwindow.cpp` — that file only `registerToolProvider`s
the name + delegate). The same change:

1. Extends the `op` enum description string and the `op` property's
   JSON `enum` array to include `"append_batch"`.
2. Adds a `bullets` property (JSON array of objects) describing the
   per-bullet shape. Existing single-bullet params (`headline`,
   `kind`, `source`, etc.) stay top-level for the `append` path.
3. Refreshes `selection_hint` (`claudeintegration.cpp:5726-5732`)
   to mention `append_batch` as the cheaper N-bullet form.

## 4. RAM / build cost

The batch holds N bullets in memory before splicing; N is
practically ≤ 30 (Vestige's worst observed case is 14) so the cost is
trivially bounded. ROADMAP.md is already read in full by the
single-bullet path. No new external libs. Adds ~150 lines to
`src/remotecontrol.cpp` (helper extraction + new handler) and one
source-grep test bundle.

## 5. Out of scope

- **Cross-section batching** — bullets in one batch must share a
  section. A future extension could accept `bullets[].section` to
  scatter across sections; not needed for the documented use-case.
- **`id_hint` per bullet** — single first-bullet hint is enough to
  pin the start of the sequence. Per-bullet hints would force the
  counter into a non-contiguous shape with no concrete user request
  for it.
- **Stable-prefix project support** — `op:append_batch` inherits the
  `stable_prefix_unsupported` refusal (ANTS-1877); batch support for
  stable-prefix projects is the same follow-up work.

## 6. Tests

Feature test: `tests/features/mcp_roadmap_log_append_batch/`. Covers
INV-1..INV-10. Label `features;fast`. The test bundle:

1. Builds a synthetic ROADMAP.md + `.roadmap-counter` in a
   `QTemporaryDir`; calls `cmdRoadmapLogAppendBatchForTest(req)`;
   asserts envelope + resulting file content.
2. Drives the validation matrix: full-success batch, mixed
   accepted/skipped batch, all-skipped batch, `id_hint` collision,
   `bad_section`, `unrecognised_format`, counter-commit rollback
   (via `setForceCounterCommitFailForTest`).
3. Source-greps `src/remotecontrol.cpp` for the dispatch branch and
   the shared `formatRoadmapBullet` helper.
