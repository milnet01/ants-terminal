# ANTS-1282 — `indie_review_corroborate` accepts a directory path

**Status:** spec draft, pre cold-eyes (2026-05-13). Loop log at end
(§ 11).
**Source:** ROADMAP.md ANTS-1282 (`🔌 MCP integration deepening —
token + perf (2026-05-13)` block).
**Blocked by:** none — pairs with ANTS-1281 (shipped same cycle).
**Pairs with:** ANTS-1279 (orchestrator depends on this + ANTS-1281).

## 1. Problem

`mcp__ants__indie_review_corroborate` today requires `reports`: a
JSON object mapping `lane_name → report_markdown`. The caller
(typically an `/indie-review` orchestrator that just received 14
per-lane reports from dispatched subagents) has to:

1. Read each report file into memory.
2. Build a `{lane_name: report_text}` map.
3. Pass that map as the `reports` MCP argument.

Step 3 is the cost: the request payload **echoes every report's
full text back through the MCP socket**, and the parent context
holds all 14 reports in memory simultaneously to construct the
JSON. Typical report sizes from a `/indie-review` sweep:

| Quartile | Report size (markdown) |
|---:|---:|
| p25 | ~3 KiB |
| p50 | ~6 KiB |
| p75 | ~15 KiB |
| max | ~40 KiB |

14 reports × ~8 KiB median = **~112 KiB** transiting parent
context once just to call `corroborate`. ANTS-1281 already cut the
brief-side; ANTS-1282 cuts the corroborate-side.

The fix is mechanical: let `corroborate` accept `reports_dir: <path>`
as an alternative input. The MCP server reads every `*.md` file in
that directory itself (lane name = filename stem). Caller no longer
holds the reports in context.

## 2. Surface

### 2.1 Request-shape diff

**Before (current, kept):**

```json
{
  "reports":   {"vtparser": "<markdown>", "terminalgrid": "<markdown>", ...},
  "min_lanes": 2
}
```

**After (this ship — additive):**

```json
{
  "reports_dir": ".indie-review/2026-05-13/",
  "min_lanes":   2
}
```

Either `reports` (inline map, v1 path) OR `reports_dir` (server reads
disk, v2 path) is accepted. Exactly one must be provided. The
existing `reports` path remains unchanged — backwards compatible.

### 2.2 Directory resolution

`reports_dir` is resolved **relative to projectPath** (the focused
project root, same root used by the brief / partition tools). If
the caller passes an absolute path, the spec rejects it (path
traversal guard — INV-3 below).

Directory contents: every `*.md` file in the top level (not
recursive). Lane name = filename stem (`vtparser.md` → lane
`vtparser`). Non-`.md` files ignored. Empty files become empty
reports (zero findings).

### 2.3 Engine API

New free function alongside the existing `corroboratedFindings`:

```cpp
namespace IndieReviewEngine {

// ANTS-1282: read reports from disk and corroborate. The disk
// variant. The existing in-memory `corroboratedFindings` stays
// for callers that already have report text in memory.
QList<CorroboratedFinding> corroboratedFindingsFromDir(
    const QString &projectPath,
    const QString &reportsDirRelative,
    int minLanes = 2);

}
```

`reportsDirRelative` is project-relative; the engine resolves it
against `projectPath`, canonicalises both, and rejects the call if
the resolved dir escapes the project root (INV-3 path-traversal
guard).

### 2.4 MCP response — extra metadata

Response gains two fields when invoked via `reports_dir`:

```json
{
  "ok":                true,
  "findings":          [...],
  "total_input_bytes": 87523,
  "total_findings":    12,
  "reports_dir":       ".indie-review/2026-05-13/",
  "reports_read":      14
}
```

`reports_read` = count of `*.md` files actually consumed; lets the
caller verify all expected lanes landed. When invoked via the v1
`reports` map, `reports_dir` is omitted and `reports_read` reflects
the map size.

### 2.5 MCP tool description

Updated to describe both input shapes:

> Cross-lane corroboration filter. Input: EITHER `reports`
> (inline map of `{lane: report_text}`, v1) OR `reports_dir`
> (project-relative directory of `*.md` files, v2 — saves parent
> context by reading from disk server-side; ANTS-1282). Returns
> findings cited by ≥ `min_lanes` distinct lanes at the same
> (file, line). Pure regex pass; no LLM. Provide exactly one of
> `reports` or `reports_dir`. Optional: `min_lanes` (default 2).

## 3. Invariants

- **INV-1** — XOR input. The tool MUST reject calls that provide
  BOTH `reports` AND `reports_dir`, and calls that provide neither.
  Error returned: `bad_args` with a descriptive message
  ("provide exactly one of reports or reports_dir").

- **INV-2** — Output shape parity. For any pair of equivalent
  inputs (same lane → text mapping, whether passed inline or read
  from disk), the `findings` array is identical (same order, same
  contents). Verifiable by round-tripping: write reports to a
  temp dir, call corroborate via `reports_dir`, compare against
  the same call via inline `reports`.

- **INV-3** — Path-traversal guard. `reports_dir` MUST canonicalise
  to a path under `projectPath`. Absolute paths are rejected as
  `bad_args`. `..` segments are canonicalised first; if the result
  escapes, rejected.

  **Amended by ANTS-3713.** The MCP layer accepts
  `allow_outside_project:true` — the same opt-in name and posture as
  `test_audit_synthesis_prompt`'s (ANTS-1455) — so lane reports can sit in
  the session scratchpad instead of the working tree. The relaxation lives
  entirely at the boundary: `PathValidation::validatePath` still applies the
  NFC, control-character and canonicalisation checks and only skips the root
  anchor, then hands the anchored directory to
  `corroboratedFindingsFromCanonicalDir`. The engine's
  `corroboratedFindingsFromDir` is unchanged and still refuses an absolute
  path, so INV-3 holds verbatim for every caller that has not opted in.

- **INV-4** — Non-`.md` files in `reports_dir` are ignored, not
  rejected. The directory can legitimately hold other artefacts
  (e.g. a top-level `README.md` describing the sweep, a
  `summary.json`). Only `*.md` files at the top level are read.
  Sub-directories not recursed.

- **INV-5** — Lane name from filename stem. `vtparser.md` →
  lane `vtparser`. Hidden files (`.foo.md`) are skipped. Filename
  collisions are impossible by construction (filesystem enforces
  uniqueness).

- **INV-6** — Missing-directory error. If `reports_dir` resolves
  successfully but doesn't exist on disk, return `not_found` with
  the resolved path. If it exists but contains no `*.md` files,
  return `ok: true` with empty `findings[]` and `reports_read: 0`
  (caller decides whether that's an error).

- **INV-7** — Backwards compat. Existing callers passing
  `reports: {...}` continue to work unchanged. The legacy code
  path is not touched.

- **INV-8** — File-size cap. Each `*.md` file read is capped at
  64 KiB (matches `extractFileLineCitations`'s
  `kMaxScanBytes` from `indiereviewengine.cpp:215`). Reports
  larger than 64 KiB are truncated at read time; corroboration
  scans only the first 64 KiB. Mirrors the existing v1
  truncation rule.

## 4. Failure modes

- **`reports_dir` resolves outside projectPath** — rejected as
  `bad_args` with the resolved path in the error message
  (avoids the silent-skip that v1 brief-builder does on similar
  paths; corroborate is a higher-level operation and "I read no
  files" is the wrong answer).

- **`reports_dir` exists but is a regular file, not a directory**
  — rejected as `bad_args` ("reports_dir must be a directory").

- **One report file fails to read** (permission denied, vanishes
  mid-scan) — log + skip that lane, continue with the rest. The
  `reports_read` count reflects the actually-consumed files.

- **Both `reports` and `reports_dir` provided** — INV-1 rejection.

## 5. Performance / RAM budget

- Per-call RAM: same as v1 `corroboratedFindings` (the engine
  builds the same internal `QHash<QString, QString>` after reading
  files). Net RAM = sum of file sizes ≤ 14 × 64 KiB = ~896 KiB
  worst case. Negligible.
- Disk: one open/read per `*.md` file. ~14 reads per `/indie-review`
  sweep. Each read is sequential, no random IO.
- No new caches, threads, watchers.
- Token savings (the actual win): caller no longer transits all
  reports through parent context. ANTS-1281 saved ~10–30 K
  tokens × 14 lanes on the brief side; ANTS-1282 saves the
  same ballpark on the corroborate side (the reports go in,
  not source bodies — but the volume is comparable).

## 6. Test plan

Add `tests/features/indie_review_corroborate_dir/` with:

- `spec.md` — human contract.
- `test_indie_review_corroborate_dir.cpp` — GoogleTest blocks:
  1. **OutputShapeParity** (INV-2): build a temp dir with 3 fake
     reports citing one shared `(file, line)` from 2 lanes. Run
     corroborate both ways (inline + dir). Assert findings
     identical.
  2. **PathTraversalRejected** (INV-3): call with
     `reports_dir: "../../etc"` — assert engine returns empty
     (path-guard tripped).
  3. **NonMarkdownIgnored** (INV-4): dir with `vtparser.md` +
     `summary.json` + `subdir/other.md`. Only `vtparser.md` consumed.
  4. **MissingDirEmpty** (INV-6): dir doesn't exist — engine
     returns empty list (no crash).
  5. **NoMarkdownFiles** (INV-6): dir exists but contains zero
     `.md` files — engine returns empty list.
  6. **TruncationAt64KiB** (INV-8): one report is 100 KiB; only
     the first 64 KiB scanned for citations. Cited line beyond
     the 64 KiB cutoff is not in the output.

Wire in `test_claude` bundle (same place as
`indie_review_brief_manifest`).
