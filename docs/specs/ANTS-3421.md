# ANTS-3421 — `feedback_log op:"compact_shipped"`: collapse a confirmed-shipped finding write-up to a one-line stub

**Status:** accepted — cold-eyes loops 1–5 folded, converged (2026-07-02).
**Kind:** enhancement.
**Source:** ROADMAP.md ANTS-3421 (user-request-2026-07-02).
**Composes with:** ANTS-1961 (`feedback_query` / `FeedbackFile::parse`), ANTS-1962 (`feedback_log` / block renderers), ANTS-3371 (`ParseResult::trackingRows`).

## 1. Problem

The cross-session `*_Ants_MCP_Feedback.md` files grow without bound. Every
contributor finding stays at full multi-paragraph verbosity **forever**,
even after its roadmap item ships and the originating session confirms the
fix works. The largest file is already 3,671 lines
(`3D_Engine_Ants_MCP_Feedback.md`) and every one is re-parsed on each
`session_orient` `feedback_pending` scan (`src/remotecontrol.cpp` →
`FeedbackFile::parse`) and every `feedback_query` (`cmdFeedbackQuery`,
`src/remotecontrol.cpp:10640`). A smaller file is cheaper to parse and
keeps the un-triaged delta easy to spot.

The lifecycle that produces a *trimmable* finding (confirmed 2026-07-02):

1. A contributor session appends a finding write-up (`op:append_finding`).
2. The maintainer triages it → mints `ANTS-NNNN` → stamps a maintainer
   tracking row mapping the finding to the ID (`op:append_tracking`,
   status 📋). This block is the watermark.
3. The maintainer implements it → appends a tracking row marking the ID ✅.
4. The originating session reports it **complete** (a status row / prose
   confirming the `ANTS-NNNN` works).

Only a finding that has reached step 4 is trimmable. There is today no
maintainer-side way to reclaim its bytes short of a hand-edit — which is
exactly the kind of raw edit the format's watermark contract warns against
(`docs/standards/mcp-feedback-files.md` § "Contributor don'ts", § parser
contract). A hand-edit near a maintainer block can resurrect old findings
into the delta or hide new ones.

### 1.1 The linkage problem (why the maintainer names the target)

The maintainer tracking tables reference each finding by a **loose
paraphrase**, not by a stable anchor. In the `MAME_Curator` file's
`## 📋 Ants Terminal roadmap tracking (added 2026-05-19)` block the closed
row reads `| #3 — "Ants MCP not used by this session" — info only |
(self-resolved) | ✅ |` — a paraphrase with no machine link back to the
original `## 3. Ants MCP not used by this session…` write-up heading (and,
in this case, no ANTS-NNNN at all). A tool that *guessed* the block from the
paraphrase could collapse the wrong block in a 3,600-line shared file.

So the design splits the two concerns cleanly:

- **Which block** is located **deterministically by its exact heading**
  (§2.1) — that, not the id, is what prevents a wrong-block collapse.
- **Whether it shipped** is gated on an explicit `id` the maintainer names,
  which the tool verifies is ✅ in a tracking table (§2.3). The tool does
  **not** cross-check that the id "belongs to" the heading — it trusts the
  maintainer's assertion that the named block shipped as that id, and
  surfaces the exact breadcrumb under `dry_run` for eyeball before writing.

The maintainer (who is reading the file and the step-4 confirmation) names
the target explicitly; the tool applies the deterministic gates below. This
is the user-selected design (2026-07-02). **v1 scope: ID-tracked findings
only** — an id-less closure (`(self-resolved)`, `(schema fix)`,
`(no roadmap item)`; the dominant closed form in the corpus) has no
ANTS-NNNN to gate on and is deferred (§5).

## 2. Surface

A new **maintainer-only** verb mode on the existing `feedback_log` tool:
`op:"compact_shipped"`. It reuses the whole `feedback_log` plumbing already
in `cmdFeedbackLog` (`src/remotecontrol.cpp:10738`): `resolveFeedbackPath`
(path validation + suffix guard + `caller_cwd` contract + ANTS-3376
derivation), the `dry_run` convention, and the `QSaveFile` atomic write.
The pure collapse logic lives in `src/feedbackfile.cpp`
(`ants_core_lib`, Qt6::Core-only, unit-testable — same home as `parse` /
`renderTrackingBlock`).

### 2.1 Request shape

```jsonc
{
  "op": "compact_shipped",
  "caller_cwd": "…",              // required (contract)
  "path": "…_Ants_MCP_Feedback.md", // optional (ANTS-3376 derivation)
  "dry_run": true,                // strongly recommended first
  // illustrative — a maintainer-named target (heading text is a paraphrase
  // here; a real call passes the block's verbatim heading line):
  "targets": [
    {
      "heading": "## 2. roadmap_log op:flip can't parse the ants-v1 emoji roadmap",
      "id": "ANTS-3351",          // ANTS-NNNN this block shipped as (cited + gated ✅)
      "session": "MAME",          // optional; stub breadcrumb author
      "date": "2026-07-01"        // optional YYYY-MM-DD; stub breadcrumb date
    }
  ]
}
```

- `targets` — non-empty array; each entry names one contributor block to
  collapse.
- `heading` — the exact boundary heading **line text** of the block
  (`^#` or `^##`). Primary locator; matched **trimmed-vs-trimmed** against
  the file's heading lines (both sides stripped of trailing whitespace).
- `heading_line` — optional 1-based line number. When given it is the
  locator and `heading` (if also given) must match that line, else the
  target is refused. Required to disambiguate a `heading` that occurs more
  than once (the corpus repeats generic headings like `## What worked well`
  ~8×; numbered finding headings like `## 2. …` are unique).
- `id` — **required** (v1): the ANTS-NNNN the block shipped as. Cited in the
  breadcrumb and gated (§2.3). Id-less closures are out of scope (§5).
- `session` / `date` — free text for the stub breadcrumb. `session`
  defaults to the file's project token (basename minus
  `_Ants_MCP_Feedback.md`); `date` defaults to today.

### 2.2 The collapse

For each **applied** target, the block body — every line *after* the
heading line up to (but excluding) the **next boundary heading of either
level** (one *or* two hashes, fence-aware), byte-identical to `parse()`'s
block-end computation (`feedbackfile.cpp:139-147`: "the first boundary
heading of EITHER kind after `start`") — is replaced by a blank line then a
single breadcrumb line, ensuring exactly one trailing blank line before the
next boundary (or a single trailing newline at EOF when the collapsed block
is the file's last block). Blocks are therefore **flat and disjoint**, never nested
markdown sections. The heading line itself is left **verbatim**
(illustrative):

```markdown
## 2. roadmap_log op:flip can't parse the ants-v1 emoji roadmap

→ shipped ANTS-3351, confirmed MAME 2026-07-01 (write-up compacted, ANTS-3421)
```

Keeping the heading verbatim preserves the `#`/`##` block boundary, so the
delta parser's classification (maintainer vs contributor) is unchanged: the
same maintainer heading stays the watermark and both `mappedIds` and the
`delta` text are byte-identical after the collapse (§3 INV-6). The stub
sentinel — the first non-blank body line beginning `→ shipped ANTS-` —
drives idempotency (§3 INV-7).

Because a block ends at the next boundary of *either* level, naming a **`#`
session heading** whose body contains `##` sub-sections collapses only the
preamble *up to the first `##`* — the sibling `##` sub-blocks are separate
blocks and must be named individually. Tool-authored blocks (whose findings
are inert `###` sub-headings, per ANTS-1962 `renderFindingBlock`) have no
inner boundary and so collapse whole; only hand-authored multi-`##` sessions
need per-sub-block targeting.

### 2.3 Gates (deterministic, tool-enforced)

The wrapper runs `FeedbackFile::parse(content)` once, then resolves each
target against the original content. **Gates evaluate top-to-bottom; the
first failing gate's `code` is returned.** A target is **applied** only if
all hold; otherwise it lands in `skipped[]` with that `code` and the file
bytes for that block are untouched:

| # | Gate | Refusal `code` | Rule |
|---|------|----------------|------|
| 1 | Heading resolves to exactly one `#`/`##` boundary (fence-aware) | `target_not_found` (0 matches; a `heading_line` that disagrees with `heading`; or a `heading_line` pointing at a non-boundary line) / `target_ambiguous` (>1, echoes candidate lines) | Locate the block. |
| 2 | Heading is **not** the file's first boundary heading (the H1 title / contributor banner block) | `title_block` | Never collapse the header + the ANTS-2226 contributor pointer. |
| 3 | Block is **not** a maintainer tracking block (anchor regex) | `maintainer_block` | Never collapse a watermark. |
| 4 | Heading line **strictly above** `lastMaintainerLine` | `in_delta` (below the watermark) / `not_triaged` (file has zero maintainer blocks) | Never touch the un-triaged tail. |
| 5 | `id` ∈ the **effective** tracking row's parsed ID list (`TrackingRow::ids`) **and** that row's status cell **begins with** ✅ (U+2705) | `not_shipped` (echoes the status found, or "no tracking row") | Only compact shipped items. |
| 6 | Block contains **at most one** `### ` finding sub-heading (fence-aware) | `multi_finding` (echoes the count) | Never collapse a multi-finding block: `renderFindingBlock` emits N findings as `###` under one `##`/`#` boundary, so a whole-block collapse would erase the write-ups of still-open sibling findings and misattribute them to `id`. Multi-finding blocks are deferred (§5). |
| 7 | Block body's first non-blank line does **not** begin with the `→ shipped ANTS-` sentinel | `already_compacted` | Idempotent. |

After all targets are resolved, any two whose resolved heading lines
**collide** (the same block named twice) are both refused `duplicate_target`
— a double-collapse of one block would apply stale line numbers on the
second pass (§2.4). This cross-target check runs only over targets that
**pass gate 1** (a colliding pair must have resolved) and **takes precedence
over gates 2–7** for that pair, so INV-13's outcome is deterministic.

Malformed input refuses `bad_args` before any target is resolved: an empty
`targets` array, a target missing `id` or `heading`, or an `id` not matching
`^ANTS-[0-9]+$` (the format check also keeps the `→ shipped ANTS-`
idempotency sentinel valid — gate 7 / INV-7). A non-existent feedback file
refuses `not_found` (via `resolveFeedbackPath`, as `feedback_query` does).

Effective row = the **last** (document-order) tracking row whose parsed
`ids` contains `id` (later supersedes earlier, matching ANTS-3371's rule);
its status cell must **begin with** ✅ (U+2705) — a leading token, so
`✅`, `✅ shipped (…)` and `✅ (partial)` count, but a cell like
`❓ (not ✅ yet)` or `📋 (was ✅, reopened)` does **not** false-match.
(Tool-authored rows always carry an exact single-emoji status —
`append_tracking` validates against `kStatusSet`, `remotecontrol.cpp:10841`
— so the leading-token rule only distinguishes hand-authored multi-token
corpus cells.)

The ✅-shipped gate is the tool's hard guardrail against a fat-fingered
target; the step-4 *contributor confirmation* is the maintainer's
responsibility (it is often free prose, and a maintainer ✅ recorded in
prose rather than a pipe-table row does not populate `trackingRows`, so the
gate is table-based by design — see §5). The op name and the required
maintainer role encode that intent.

### 2.4 Batch semantics & write

All target ranges are resolved against the **original** content, then
applied **bottom-up** (descending resolved heading line) so collapsing an
earlier block never shifts a later target's line numbers. Applied collapses
land in one `QSaveFile` commit (atomic, same as the append ops). Per-target
failures do not abort the batch (parity with `roadmap_log` `flip_batch` /
`append_batch`). `dry_run:true` computes every outcome + the byte report and
writes nothing.

### 2.5 Response envelope

The wrapper splits the pure helper's `CompactResult::results` (one entry per
input target, input order) into the envelope's `outcomes` (the **applied**
targets, each with `start_line` / `end_line` / `bytes_*`) and `skipped` (the
**refused** targets, each with `code` / `reason`); `path_derived:true` is
echoed when the path was derived (ANTS-3376), for parity with the sibling
ops. A `target_ambiguous` skip additionally carries `candidates:[<line>,…]`
— the colliding heading lines — so the caller can disambiguate via
`heading_line`.

```jsonc
{
  "ok": true, "op": "compact_shipped", "path": "…", "dry_run": false,
  "applied_count": 1,
  "bytes_saved": 1842,            // signed Σ(bytes_before − bytes_after) over applied
  "outcomes": [
    { "heading": "## 2. roadmap_log op:flip…", "id": "ANTS-3351",
      "applied": true, "start_line": 987, "end_line": 1005,
      "bytes_before": 1931, "bytes_after": 89, "bytes_saved": 1842 }
  ],
  "skipped": [
    { "heading": "## 4. …", "id": "ANTS-1600",
      "code": "not_shipped", "reason": "effective status 📋" }
  ]
}
```

`bytes_before` / `bytes_after` measure the target's **whole block** (heading
line through the last body line before the next boundary); a bodyless block
(heading immediately followed by the next boundary) has `bytes_before` = the
heading line's bytes. Because the heading is preserved, the saving equals the
body reduction. `bytes_saved` is a **signed** sum: a block already shorter
than the stub yields a value ≤ 0. A ≤ 0 target is **still applied** — the
collapse also *normalises* every confirmed finding to a uniform stub, so
byte-savings is not a gate; `dry_run` surfaces the sign so the maintainer can
drop such a target if they only want net savings.

### 2.6 Pure helper (feedbackfile.h / .cpp)

```cpp
namespace FeedbackFile {

struct CompactTarget {
    QString heading;        // verbatim boundary heading (trailing ws trimmed)
    int     headingLine = -1; // optional 1-based locator/disambiguator
    QString id;             // ANTS-NNNN
    QString session;        // stub breadcrumb author (caller-resolved default)
    QString date;           // stub breadcrumb date  (caller-resolved default)
};

struct CompactOutcome {
    QString heading, id;
    bool    applied = false;
    QString code, reason;   // code == "" on success
    int     startLine = -1, endLine = -1;   // 1-based block range (heading..last body line)
    int     bytesBefore = 0, bytesAfter = 0;
};

struct CompactResult {
    QString newContent;                 // full file after all applied collapses
    QVector<CompactOutcome> results;    // one per input target, input order
                                        // (wrapper splits into envelope
                                        //  outcomes[] applied + skipped[])
    long    bytesSaved = 0;
};

// Pure. Runs parse(content) internally for the watermark + tracking rows,
// resolves + gates each target, collapses applied blocks bottom-up.
CompactResult compactShipped(const QString &content,
                             const QVector<CompactTarget> &targets);

}  // namespace FeedbackFile
```

The block-boundary scan (fence opener `^\s{0,3}(```|~~~)`, boundaries only
`^# `/`^## ` outside fences, maintainer-anchor regex) is **extracted from
`parse()` into a shared internal helper** and reused here — the parser
contract must have exactly one implementation
(`docs/standards/mcp-caches.md`-style single-source rule; reuse per
`CLAUDE.md` §3). The extraction must expose the full boundary
list gate 1 (fence-aware heading resolution) and gate 2 (first-boundary)
need — `{line, text, isMaintainer}` per boundary — plus the
"block-end from a given boundary line" primitive (the
`feedbackfile.cpp:139-147` either-kind scan), **without** regressing
`parse()` pass-2's `mappedIds` computation, which currently interleaves the
boundary scan with the two-pass maintainer/contributor classification.
Gate 6's fence-aware `### ` count re-runs the file-local fence scanner
(`fenceOpenerChar` / `fenceRe`, `feedbackfile.cpp:29-56`) over the target
block body, so a `###` inside a fenced code region is not counted as a
finding heading.

## 3. Invariants

- **INV-1** — `op:"compact_shipped"` replaces an applied target's block body
  (lines after the heading to the next boundary of either level) with the
  §2.2 shape — a blank line, then the single breadcrumb `→ shipped <id>,
  confirmed <session> <date> (write-up compacted, ANTS-3421)`, then one
  trailing blank line (or a single trailing newline at EOF for the file's
  last block) — and leaves the heading line byte-for-byte unchanged. *Test:*
  `feedback_log_compact_shipped` — body collapsed to the exact §2.2 shape,
  heading intact.
- **INV-2** — A target whose `id` is not in an effective tracking row whose
  status cell **begins with** ✅ (U+2705) is refused `not_shipped`; its block
  bytes are unchanged. *Test:* target with a 📋 id → `skipped`; a
  `❓ (not ✅ yet)` cell does not satisfy the gate; block intact.
- **INV-3** — A target heading **below** `lastMaintainerLine` (the
  un-triaged delta) is refused `in_delta`; when the file has zero
  maintainer blocks every target is refused `not_triaged`. *Test:* heading
  below the watermark → `skipped`.
- **INV-4** — A target resolving to a maintainer tracking block is refused
  `maintainer_block`. *Test:* target the 📋 heading → `skipped`.
- **INV-5** — Heading resolution: 0 matches → `target_not_found`; >1 →
  `target_ambiguous` echoing candidate line numbers; a `heading_line` that
  disagrees with `heading`, or points at a non-boundary line → `target_not_found`.
  *Test:* duplicate heading without `heading_line` → ambiguous; with it →
  applied; a `heading_line` on a non-boundary line → `target_not_found`.
- **INV-6** — Boundary/watermark preservation: `parse()` of the
  post-compaction content returns `mappedIds` and `delta` (text)
  **byte-identical** to `parse()` of the pre-compaction content — the
  maintainer bodies and the un-triaged tail are never touched, and each
  collapsed block keeps its boundary heading. The numeric
  `lastMaintainerLine` legitimately *decreases* as body lines above it are
  removed and is **not** asserted equal. *Test:* parse-before vs parse-after
  — identical `mappedIds`, identical `delta`, and identical `trackingRows`
  (gate 5's input is untouched). Load-bearing: `mappedIds` scans maintainer
  bodies only, so the breadcrumb's own `ANTS-NNNN` — living in a contributor
  block — is never counted. Byte-identity assumes the collapsed body is
  **fence-balanced** (well-formed per the format contract); `parse()` tracks
  fence state file-globally (`feedbackfile.cpp:88-93`), so removing a body
  with an unbalanced fence is out of scope.
- **INV-7** — Idempotent: a target whose body's **first non-blank line**
  begins with the `→ shipped ANTS-` sentinel is refused `already_compacted`;
  a re-run over the same targets makes no byte change. (If the `id` was
  re-opened after the stub was written, gate 5 refuses `not_shipped` before
  gate 7 reaches — the block is still byte-unchanged.) *Test:* compact twice
  → second run applies 0, bytes unchanged.
- **INV-8** — Atomic + partial: applied collapses commit in one `QSaveFile`
  write; per-target failures populate `skipped[]` without aborting valid
  targets; `dry_run:true` returns full `outcomes` + `bytes_saved` and the
  on-disk bytes are unchanged. *Test:* mixed valid/invalid batch + dry_run.
- **INV-9** — `bytes_saved` = the **signed** Σ over applied targets of
  `bytes_before − bytes_after`. *Test:* byte arithmetic on a known fixture,
  including a terse-block fixture where the value is ≤ 0.
- **INV-10** — Bottom-up application: given ≥2 valid targets, each is
  collapsed against original line positions (an earlier collapse never
  shifts a later target's resolved range). *Test:* two-target fixture where
  naive top-down would corrupt the second range.
- **INV-11** — A target resolving to the file's **first** boundary heading
  (the H1 title / contributor banner block) is refused `title_block`; the
  ANTS-2226 contributor pointer is never collapsed. *Test:* target the H1 →
  `skipped`, banner intact.
- **INV-12** — Gate determinism: a target tripping several per-target gates
  returns the **first** failing gate's code in §2.3 table order (except a
  cross-target `duplicate_target` collision, which precedes gates 2–7).
  *Test:* a heading both below the watermark and carrying an un-shipped id
  returns `in_delta` (gate 4), not `not_shipped` (gate 5).
- **INV-13** — Two targets resolving to the **same** heading line are both
  refused `duplicate_target`; no block is collapsed twice. *Test:* a batch
  naming one block twice → both `skipped`, block collapsed 0 times, bytes
  reflect no double-application.
- **INV-14** — A target block containing **≥2** `### ` finding sub-headings
  (fence-aware) is refused `multi_finding`; its bytes are unchanged (a
  whole-block collapse would erase un-shipped siblings). *Test:* a `## date`
  block with two `###` findings → `skipped`, block intact.
- **INV-15** — Effective-status supersession: an `id` that is ✅ in an
  earlier tracking row but 📋/🔄 in a **later** row is refused `not_shipped`
  (the last document-order row wins, per ANTS-3371). *Test:* a reopened-id
  fixture (✅ then 📋) → `skipped`.

## 4. RAM / build cost

No persistent state and no new build target: `compactShipped` is pure
string work over content the wrapper already reads fully into memory (as
`cmdFeedbackQuery` / `cmdFeedbackLog` already do). Largest corpus file
~3,671 lines / a few hundred KB — a single transient copy of the content,
freed on return. No new external library.

## 5. Out of scope

- **Auto-detecting the step-4 contributor confirmation** — often free
  prose (`ANTS-2051 now VERIFIED FIXED ✅`), not a parseable table; left to
  the maintainer's judgment in naming targets. A future
  `contributor_confirmed:true/false` advisory hint could be added if the
  confirmation form is standardised — tracked separately if wanted.
- **Auto-discovery of all trimmable blocks** (the fuzzy paraphrase↔heading
  match) — deliberately rejected in §1.1.
- **Multi-finding blocks** (a `## date` session with ≥2 `###` findings under
  one boundary — the `renderFindingBlock` shape for a multi-finding
  `append_finding`): refused `multi_finding` (INV-14). v1 collapses only
  single-finding blocks because `###` is not a parser boundary, so a
  per-finding collapse can't be located yet. A v2 could target a `###`
  sub-block once the boundary set is widened; tracked separately if wanted.
  The `###`-count reliably detects the **tool-authored** `renderFindingBlock`
  shape; a *hand-authored* multi-finding block that delimits findings
  differently (prose, or `####`) has zero `### ` and passes gate 6, so
  off-template blocks fall back to the maintainer's judgment + the `dry_run`
  preview (an oversized `bytes_before` is the tell). A byte-ratio backstop is
  a possible follow-up. (An unfenced `### ` inside a single legit finding's
  body is a **safe over-refusal** — it trips `multi_finding` rather than
  risking data loss.)
- **Id-less closures** (`(self-resolved)`, `(schema fix)`,
  `(no roadmap item)` + ✅ — the dominant closed form in the corpus): v1
  requires an ANTS-NNNN to gate + cite, so these are not compactable yet.
  A follow-up could gate them on the located block's own status signal;
  tracked separately if wanted.
- **Compacting maintainer tracking blocks** — never (INV-4). Their bytes
  are the watermark ledger.
- **Cross-session write isolation** — like every `feedback_log` op,
  compaction is atomic-*replace* (`QSaveFile`, INV-8) but not *isolated*: a
  `compact_shipped` racing a contributor's `append_finding` on the same file
  is a last-writer-wins read-modify-write. This is pre-existing to all
  `feedback_log` ops, not introduced here; an mtime-recheck guard would be a
  separate hardening item.
