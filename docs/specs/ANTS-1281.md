# ANTS-1281 — `indie_review_brief` returns template, not source bodies

**Status:** spec draft, pre cold-eyes (2026-05-13). Loop log at end (§ 11).
**Source:** ROADMAP.md ANTS-1281 (line in `🔌 MCP integration deepening
— token + perf (2026-05-13)` block).
**Blocked by:** none — ANTS-1112 v1 shipped the engine in 0.7.89.
**Pairs with:** ANTS-1279 (orchestrator), ANTS-1282 (corroborate
directory input). This is the smallest of the three and can ship
standalone; ANTS-1279 depends on it.

## 1. Problem

`mcp__ants__indie_review_brief lane=X` today returns one field
`brief` — a string concatenating:

```
=== Lane: <name> ===
Summary: <one-line summary>
Source files (N):
- src/<file1>.h
- src/<file1>.cpp
...

=== file: src/<file1>.h ===
<full body of file1.h>

=== file: src/<file1>.cpp ===
<full body of file1.cpp>

...

=== ROADMAP slice ===
<lines mentioning this lane>

=== Standards reference (not inlined; reviewer fetches if needed) ===
- docs/standards/coding.md
- docs/standards/testing.md
- docs/standards/documentation.md
```

The source-file bodies are the dominant cost. For the 14 lanes of a
`/indie-review` sweep:

| Lane (sample) | Source bytes inlined | Brief total bytes |
|---|---:|---:|
| `vtparser` | ~38 KiB (`vtparser.{h,cpp}`) | ~42 KiB |
| `terminalgrid` | ~210 KiB (5 files) | ~215 KiB |
| `terminalwidget` | ~180 KiB | ~185 KiB |
| `auditdialog` | ~340 KiB | ~345 KiB |
| `claudetasklist` | ~28 KiB | ~32 KiB |

(Bytes measured 2026-05-13 by inspection — INV-1 below requires these
to be regenerated when this spec ships, not relied on as exact.)

These bytes ALL traverse parent (orchestrator) context: the
orchestrator calls the MCP, holds the response, then re-emits it
inside the subagent-dispatch prompt. A 14-lane sweep transits
roughly **1.2–1.6 MiB of source through parent context** for no
reason — the orchestrator does not *read* the bodies, only relays
them.

The roadmap entry quantifies the win at "~10–30 K tokens per lane in
parent context" — broadly consistent with 30–200 KiB per lane at
~4 chars/token.

## 2. Surface

### 2.1 Response shape diff

**Before (current):**

```json
{
  "ok": true,
  "lane": "vtparser",
  "brief": "<huge concatenated string, ~42 KiB>",
  "source_count": 2,
  "byte_count": 42301
}
```

**After (this ship):**

```json
{
  "ok": true,
  "lane": "vtparser",
  "brief": "<lighter brief: header + source-list + roadmap-slice + standards-refs + 'read each file yourself' instruction; ~2 KiB — NO source bodies>",
  "source_paths": ["src/vtparser.h", "src/vtparser.cpp"],
  "contract_docs": ["docs/standards/coding.md", "docs/standards/testing.md", "docs/standards/documentation.md"],
  "external_specs": [],
  "dimension_weighting": {},
  "source_count": 2,
  "byte_count": 1873
}
```

**Migration choice (refinement vs the original roadmap entry).** The
`brief` field is **kept**, not renamed to `brief`. Its
content drops the source-body inlining. Callers that today receive
`brief` and pass it to a subagent continue working — the subagent
now gets a prompt that says "read each source file yourself" instead
of pre-loaded source content. New structured fields
(`source_paths`, `contract_docs`, …) are added alongside `brief` for
programmatic access without re-parsing the template text. Original
roadmap-entry proposal renamed `brief` → `brief`,
which was a hard break for any out-of-tree consumer; the kept-name
version costs nothing extra and avoids silent skill regressions.

`byte_count` now measures the new lighter `brief` bytes (caller-visible
expansion cost), not the original v1 brief size — INV-3 below.

### 2.2 `brief` content

Header + source-paths list + ROADMAP slice + standards reference
(unchanged from current brief) **minus the per-file `=== file: ===`
sections**, **plus** a new instruction block immediately after the
source-list and immediately before the ROADMAP slice:

```
Read each source file in the list above using your Read tool BEFORE
beginning the review. The contract docs listed at the bottom are
project standards — read them only if your review surfaces a
violation you want to cite by line. The MCP server has deliberately
NOT inlined source bodies into this brief; doing so would inflate
parent (orchestrator) context for no reviewer benefit.
```

Exact wording is part of the engine implementation, not this spec —
spec only requires:

- The phrase "Read each source file in the list above using your
  Read tool" verbatim (so test_mcp_indie_review_tools can grep).
- An explanation that source bodies are intentionally not inlined.

### 2.3 `contract_docs` content

Hardcoded to the three standards docs the current brief lists by
link. If the project's standards directory grows, this is the
single point that broadens. Always project-relative.

### 2.4 `external_specs` / `dimension_weighting` (reserved)

Both ship as `[]` / `{}` in v1. Spec'd as fields so the schema is
stable when:

- `external_specs[]` later carries per-lane spec-file paths (e.g.
  `docs/specs/ANTS-1112.md` for the `indiereviewengine` lane) —
  follow-up item, not this spec.
- `dimension_weighting{}` later carries `{"security": 2,
  "performance": 1}` style bias hints driven by lane name — also
  follow-up.

Reserving them now avoids a second schema break later.

### 2.5 Engine API

```cpp
namespace IndieReviewEngine {

struct BriefManifest {
    QString     brief;
    QStringList sourcePaths;         // project-relative, mirrors lane.sourcePaths
    QStringList contractDocs;        // project-relative, e.g. docs/standards/coding.md
    QStringList externalSpecs;       // reserved, empty in v1
    // dimensionWeighting deferred — Qt doesn't carry a generic
    // string-keyed JSON value in this engine; MCP layer emits `{}`.
};

BriefManifest assembleBriefManifest(const QString &projectPath,
                                    const Lane &lane);

// Retained for backwards compatibility and the v1-shape tests.
// New callers SHOULD use assembleBriefManifest. Deprecated in v2.
QString assembleBrief(const QString &projectPath, const Lane &lane);

}  // namespace
```

`assembleBrief` is retained until ANTS-1282 / ANTS-1279 also ship —
keeping it lets the MCP server respond to either shape if we ever
expose a `legacy=true` opt-in, and keeps the existing test
`test_mcp_indie_review_tools` from going red on this ship.

### 2.6 MCP tool description

`indie_review_brief` description in `claudeintegration.cpp` updates
from "Return the verbatim brief text … header + source bodies …" to
"Return a brief manifest for one lane: prompt template + source-path
list + contract-doc list. Source bodies are NOT inlined; the
subagent reads them via its Read tool. Saves ~10–30 K orchestrator
tokens per lane vs the v1 shape that inlined bodies."

## 3. Invariants

- **INV-1** — Token-cost regression test. A feature-conformance test
  builds a synthetic lane with one 100 KiB source file and verifies
  `assembleBriefManifest(...).brief.size()` < 8 KiB.
  Asserts the body-stripping is real.

- **INV-2** — Source-paths preserved verbatim. `manifest.sourcePaths`
  == `lane.sourcePaths` (no filtering, no rewriting). The path
  ordering and content match `derivePartition`'s output exactly.

- **INV-3** — `byte_count` MCP field measures `brief`
  bytes only. Not source bodies, not `contract_docs` content.

- **INV-4** — Path-traversal guard parity. The same canonicalisation
  + under-projectPath check that `assembleBrief` runs on each source
  file (rejects paths escaping projectPath) also applies in
  `assembleBriefManifest` — paths that fail the check are dropped
  from `sourcePaths` **and** from the source-paths list rendered
  into `brief`. v1 currently drops only from the
  file-body inlining; the listed-path remained. INV-4 tightens this.

- **INV-5** — `brief` contains the verbatim sentinel
  `"Read each source file in the list above using your Read tool"`.
  Test asserts this so future edits don't drop the instruction
  silently — without it the subagent has no signal that source
  bodies are missing on purpose.

- **INV-6** — `contract_docs` is the **fixed** list `["docs/standards/coding.md",
  "docs/standards/testing.md", "docs/standards/documentation.md"]`
  in the v1 brief's authored order (coding → testing →
  documentation; NOT alphabetical — alpha would be coding /
  documentation / testing). Other files in `docs/standards/`
  (commits.md, roadmap-format.md) are intentionally omitted to
  match the current brief contract; reviewers cite them only when
  the lane warrants. Not configurable in v1. Future extension
  point lives at the assembly site.

- **INV-7** — Backwards compat: `assembleBrief` continues to
  produce v1-shape output for any internal caller (currently only
  the tests). Removing it is a separate ship.

- **INV-8** — Schema: response object continues to set
  `additionalProperties: false`. New fields added to schema
  declaration in `claudeintegration.cpp` alongside the existing
  ones; existing test `AllSchemasUseAdditionalPropertiesFalse`
  passes unchanged.

## 4. Failure modes

- **Lane has zero source paths.** `manifest.sourcePaths = []`.
  `brief` still emits the header + ROADMAP slice +
  standards refs. The subagent sees "Source files (0):" and the
  read-instruction is still emitted (harmless). Same as v1 today.

- **Source file fails canonicalisation.** Dropped from both the
  `sourcePaths` array and the path list rendered into the template
  (per INV-4). Logged behaviour: silent drop (mirrors v1).

- **`ROADMAP.md` missing.** Slice section omitted from
  `brief` (mirrors v1 behaviour).

- **Standards docs missing on disk.** `contract_docs` still emits
  the canonical 3-path list — the v1 brief already only listed them
  as links without reading their bodies, so the v2 manifest doesn't
  need to verify their existence either. Subagent will fail its
  later Read if a doc is genuinely missing; that surfaces a real
  doc-drift issue.

## 6. Performance / RAM budget

- Engine call: same file-system access pattern as v1's `assembleBrief`,
  minus the per-file slurp into `out`. **Net effect:** the engine
  no longer holds the concatenated source-body string in memory at
  all — peak RAM per call drops from `O(sum_of_source_bytes)` to
  `O(template_text_size)` ≈ 2–4 KiB.
- MCP response payload: drops from ~40–340 KiB per lane to
  ~2–4 KiB. Smaller socket frame, smaller JSON-parse cost on the
  Claude Code side, smaller transit through Claude's context.
- No new caches, no new threads, no new file watchers.

## 7. Workflow integration

The `/indie-review` skill (`~/.claude/skills/indie-review/SKILL.md`)
needs a one-paragraph update describing the new manifest shape and
that the dispatched subagent must Read source paths itself. The
skill is **outside the repo tree** — flagged in the doc-drift task,
documented in CHANGELOG so users with cached skill copies know to
update.

`/indie-review --fix <ref>` flow doesn't change — single-agent
review still uses the brief and the new manifest works there too
(single lane, single subagent, same Read instruction).

## 8. Migration

- The `brief` field disappears from the response. No deprecation
  window — the only known consumer is the indie-review skill, which
  ships in the user's `~/.claude/skills/`. CHANGELOG entry MUST
  flag this clearly so any third-party MCP client reading
  `indie_review_brief` updates accordingly.
- The engine API adds `assembleBriefManifest` alongside `assembleBrief`.
  Internal callers migrate; `assembleBrief` is retained for one
  release cycle (drops in 0.7.93 or whenever ANTS-1282 ships, per
  the v1-deprecation policy in `docs/standards/coding.md`).
