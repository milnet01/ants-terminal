# ANTS-1401 — Central `ResolvedRoot` helper for `caller_cwd`

## Problem

Three call paths decode the same `caller_cwd` JSON argument with subtly
different rules, and the spread invites the next regression. Today's
spread:

| Path | Call site | Behaviour on empty `caller_cwd` | Behaviour on unresolvable `caller_cwd` |
|------|-----------|---------------------------------|----------------------------------------|
| `terminalForCaller` (in `mainwindow.cpp:2748`) | tab-anchored MCP tools (`get_scrollback`, `get_git_status`, `get_environment`, `get_last_command`) | returns `focusedTerminal()` | returns `nullptr` |
| `resolveRootCanonical(main, req)` (in `remotecontrol.cpp:1370`) | path-anchored MCP tools (`verify_changes`, `last_audit_summary`, mutating verbs gated by RcGate) | returns focused-tab project root | echoes the canonical caller path |
| `cmdSessionMemory` (in `remotecontrol.cpp:3565`) | session_memory get/list | falls through to `resolveRootCanonical(main, req)` | n/a — distinct code path with its own canonicalise step |

Symptoms this spread has already produced:

- ANTS-1396 (shipped 2026-05-14): `terminalForCaller` returning
  `focusedTerminal()` for a *mismatched* `caller_cwd` was a silent
  cross-project leak. Fix added Case 3 (`nullptr` on mismatch) but
  only in `terminalForCaller`. The two other paths still differ.
- ANTS-1336 (this bundle): `cmdSessionMemory` reads a user-supplied
  `cwd` arg without anchoring it against any caller-derived
  identity. Closing that hole reuses the same canonicalise +
  compare logic — third repetition of the same primitive.
- ANTS-1404 (this bundle): per-tool contract enforcement needs a
  *single* canonical "where did this resolve and via which branch"
  answer to make refusal vs accept-and-anchor vs accept-and-ignore
  decisions consistently.
- ANTS-1400 (this bundle): the diagnostic `caller_cwd_info` verb
  returns *exactly* the `Source` enum this helper introduces.

Without consolidation, the next `caller_cwd` regression will land
in whichever path got missed, and each path's regression test will
look superficially correct against its own assumptions.

## Goal

One free function in `src/remotecontrol.cpp` (and matching header)
that takes `(MainWindow *, const QJsonObject &req)` and returns a
tagged variant describing the resolution. All four call paths
(`terminalForCaller`, `resolveRootCanonical(main, req)`,
`cmdSessionMemory`, and the future `caller_cwd_info` verb) can be
written on top of this helper without losing nuance. **Refactor
only — no observable behaviour change in this ticket.** Behavioural
fixes layer on top in ANTS-1336 / 1404 / 1400.

## Design

### `ResolvedRoot` POD

A new header `src/resolvedroot.h` exposes:

```cpp
namespace ants {

struct ResolvedRoot {
    enum class Source {
        ExplicitMatch,    // caller_cwd present + canonicalises +
                          //   matches an open tab's shellCwd
        EmptyFallback,    // caller_cwd absent/empty → focused tab
        NoMatch,          // caller_cwd present + canonicalises +
                          //   no open tab matches
        Unresolvable      // caller_cwd present but
                          //   canonicalFilePath() returned empty
    };

    QString               cwd;       // canonical FS path, or empty
                                     //   on NoMatch/Unresolvable
    Source                source = Source::EmptyFallback;
    std::optional<int>    tabIndex;  // set iff Source==ExplicitMatch
                                     //   or EmptyFallback with a
                                     //   focused tab
};

}  // namespace ants
```

The header has zero Qt dependencies beyond `QString` and `<optional>`;
it is includable from `remotecontrol.cpp`, `mainwindow.cpp`, and the
future `tests/features/caller_cwd_resolution/` test without dragging
a transitive include of either header.

### `resolveCallerCwdRoot`

A new free function in `remotecontrol.cpp` (matching the file-local
convention used by `resolveRootCanonical`):

```cpp
ants::ResolvedRoot resolveCallerCwdRoot(MainWindow *main,
                                        const QJsonObject &req);
```

Single source of truth for the decision tree:

```
caller_cwd argument absent or empty?
├── YES → Source::EmptyFallback
│         cwd      = resolveRootCanonical(main)   // focused tab
│         tabIndex = focused tab index when shellCwd canonicalises
│
└── NO  → canonicalFilePath(caller_cwd) returns empty?
          ├── YES → Source::Unresolvable
          │         cwd = ""    tabIndex = nullopt
          │
          └── NO  → iterate tabs, find one whose shellCwd
                   canonicalises to caller_cwd's canonical form?
                   ├── YES → Source::ExplicitMatch
                   │         cwd      = canonical caller_cwd
                   │         tabIndex = matching tab index
                   │
                   └── NO  → Source::NoMatch
                            cwd      = canonical caller_cwd
                            tabIndex = nullopt
```

The four-case shape mirrors `terminalForCaller`'s decision tree
post-ANTS-1396 verbatim; this helper is the same logic surfaced as
data instead of returning a pointer.

### Existing wrappers — back-compat shims

ANTS-1401 is refactor-only. The two existing entry points keep
their signatures and become one-line wrappers around the new helper:

```cpp
QString resolveRootCanonical(MainWindow *main, const QJsonObject &req) {
    const ants::ResolvedRoot rr = resolveCallerCwdRoot(main, req);
    // Pre-helper behaviour:
    //   - empty caller_cwd → focused-tab root
    //   - present + canonicalises → echo (regardless of match)
    //   - present + unresolvable → return ""
    // The new enum carries this in Source; map back to QString.
    switch (rr.source) {
        case ants::ResolvedRoot::Source::EmptyFallback:
        case ants::ResolvedRoot::Source::ExplicitMatch:
        case ants::ResolvedRoot::Source::NoMatch:
            return rr.cwd;
        case ants::ResolvedRoot::Source::Unresolvable:
            return QString();
    }
    return QString();  // unreachable; satisfies -Wreturn-type
}

TerminalWidget *MainWindow::terminalForCaller(const QString &callerCwd) const {
    // Re-fab req-shape so we route through one helper. The two
    // entry points historically took different argument shapes for
    // their own reasons; centralise via the variant.
    QJsonObject req;
    if (!callerCwd.isEmpty()) req["caller_cwd"] = callerCwd;
    const ants::ResolvedRoot rr = ants::resolveCallerCwdRoot(this, req);
    switch (rr.source) {
        case ants::ResolvedRoot::Source::EmptyFallback:
            return focusedTerminal();
        case ants::ResolvedRoot::Source::ExplicitMatch:
            return rr.tabIndex ? terminalAtTab(*rr.tabIndex)
                               : nullptr;
        case ants::ResolvedRoot::Source::NoMatch:
        case ants::ResolvedRoot::Source::Unresolvable:
            return nullptr;
    }
    return nullptr;
}
```

The pre-fix `terminalForCaller` enumerates tabs and returns
`TerminalWidget *`; `resolveCallerCwdRoot` enumerates tabs and
returns an index. Translating index → widget at the wrapper layer
is a one-liner via the existing `terminalAtTab(int)`.

`cmdSessionMemory`'s read path (line 3565) is touched in
ANTS-1336, not here. Pre-refactor it keeps calling
`resolveRootCanonical(m_main, req)` which now routes through the
new helper transparently.

## Invariants

- **INV-1.** `resolveCallerCwdRoot` is the only place in the codebase
  that calls `QFileInfo::canonicalFilePath` on a `caller_cwd`
  argument. (Grep: `git grep -n "caller_cwd.*canonical\|callerCwd.*canonical"
  -- src/` returns one hit post-refactor.)

- **INV-2.** `resolveCallerCwdRoot(main, {})` returns
  `Source::EmptyFallback` with `cwd == resolveRootCanonical(main)` (the
  no-arg overload) — matching pre-refactor empty-caller behaviour.

- **INV-3.** `resolveCallerCwdRoot(main, {"caller_cwd": "/tmp"})`
  with no tab whose shellCwd canonicalises to `/tmp` returns
  `Source::NoMatch` with `cwd == "/tmp"`, `tabIndex == nullopt`.

- **INV-4.** `resolveCallerCwdRoot(main, {"caller_cwd":
  "/path/that/does/not/exist"})` returns `Source::Unresolvable`
  with empty `cwd`, `tabIndex == nullopt`.

- **INV-5.** When two tabs share the same canonical shellCwd (rare
  — same `cd` target), the helper returns the *lowest* tab index.
  Tie-break is deterministic and matches the existing
  `terminalForCaller` loop order (`for (int i = 0; ...)`).

- **INV-6.** No public/protected member of `MainWindow` is changed.
  The helper is a free function that calls `terminalAtTab`,
  `shellCwd`, and `m_tabWidget->count()` via the same access points
  the prior code used.

- **INV-7.** `terminalForCaller`'s observable behaviour is
  byte-identical to pre-refactor for the four caller cwds the
  existing call sites supply (empty, exact match, mismatch, bad
  path). The ANTS-1396 source-scrape regression test
  (`tests/features/terminal_for_caller_isolation/`) is updated in
  the same commit to scan `resolveCallerCwdRoot`'s body for the
  literals that migrated there, plus an added `WrapperDelegatesToHelper`
  case locking in that the wrapper cannot re-grow its own
  canonicalisation path.

- **INV-8.** No new state. The helper is stateless — it reads
  `MainWindow` queries and returns a value type.

## Test

`tests/features/caller_cwd_resolution/`:

1. **EmptyFallback** — `resolveCallerCwdRoot(main, {})` with one tab
   open in `/tmp/proj_a`. Assert `source == EmptyFallback`, `cwd
   == canonical /tmp/proj_a`, `tabIndex == 0`.

2. **ExplicitMatch** — two tabs, one in `/tmp/proj_a`, one in
   `/tmp/proj_b`. `req = {"caller_cwd": "/tmp/proj_b"}`. Assert
   `source == ExplicitMatch`, `cwd == canonical /tmp/proj_b`,
   `tabIndex == 1`.

3. **NoMatch** — same two tabs. `req = {"caller_cwd": "/tmp/proj_c"}`
   (a real dir, but no tab in it). Assert `source == NoMatch`,
   `cwd == canonical /tmp/proj_c`, `tabIndex == nullopt`.

4. **Unresolvable** — `req = {"caller_cwd":
   "/nonexistent/path/that/will/not/canonicalise/xyz123"}`. Assert
   `source == Unresolvable`, `cwd == ""`, `tabIndex == nullopt`.

5. **Wrapper compat — `terminalForCaller`** — call wrapper with each
   of the four `callerCwd` inputs above. Assert pointer return
   matches the pre-refactor logic (focused / nullptr / matching
   widget / nullptr respectively).

6. **Wrapper compat — `resolveRootCanonical(req)`** — call wrapper
   with each of the four inputs. Assert returned QString matches
   pre-refactor (focused-root / matched-canonical / matched-canonical
   / empty).

Label `features;fast`. The test links the three relevant `.cpp`
TUs without GUI deps; tabs are simulated with a stub
`MainWindow` shim that returns canned `shellCwd()` strings (same
pattern as the ANTS-1396 regression test in
`tests/features/caller_cwd_silent_fallback/`).

## Implementation order

1. Land header `src/resolvedroot.h` + helper definition in
   `remotecontrol.cpp` (alongside the existing two
   `resolveRootCanonical` overloads).
2. Rewrite the two existing overloads as wrappers around the new
   helper.
3. Rewrite `MainWindow::terminalForCaller` as a wrapper.
4. Add the 6-case regression test under
   `tests/features/caller_cwd_resolution/`.
5. Verify the four ANTS-1396 test cases (in
   `tests/features/caller_cwd_silent_fallback/`) still pass without
   modification — they exercise `terminalForCaller`'s wrapper path.
6. Confirm `ctest --output-on-failure --label features` is green.

## Out of scope

- Behavioural fixes. ANTS-1336 (session_memory cwd arg) and
  ANTS-1404 (per-tool contracts) ship as separate items and
  build on this helper.
- The `caller_cwd_info` MCP verb. That ships as ANTS-1400 and
  is essentially `QJsonDocument(resolveCallerCwdRoot(...))`.
- Any tools/list schema change. Schema surfacing is unchanged.
- `terminalAtTab` / `shellCwd` / `focusedTerminal` internals.

## RAM budget

Zero. `ResolvedRoot` is a value type (~40 B on the stack per call);
no heap, no cache. The helper does the same number of canonicalisations
as the pre-refactor path (one per tab + one for caller_cwd, capped
at `tabCount + 1`).

## Build cost

Negligible. One new header (≈ 30 lines) compiled wherever `mainwindow.cpp`
and `remotecontrol.cpp` already include `<QFileInfo>`. No new TUs;
the helper body lives in `remotecontrol.cpp` next to its kin.
