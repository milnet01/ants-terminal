## 1. Problem

`codebase_index` (ANTS-1637, shipped) maps a project's **source**
(files → symbols → lanes) so a session stops re-deriving the code shape with
`grep`/`file_outline`/CLAUDE.md reads. There is **no equivalent for
documentation**. A session asking "where is the contract / standard / decision
/ design for X?" today falls back to:

1. `spec_query` (`src/remotecontrol.cpp` `cmdSpecQuery`) reads **one** spec
   under `docs/specs/` — the caller must already know the id, and it never
   sees `docs/standards/`, `docs/decisions/`, `docs/journal/`, or top-level
   docs (README/CHANGELOG/CLAUDE.md).
2. `project_layout` locates *directories* only (and its standards-file
   enumeration was itself buggy until ANTS-2138) — it does not read doc
   content.
3. `subsystem` is the source-lane catalogue, not a doc index.
4. `find_sources` (ANTS-1636) does content-aware topic→files scoring but
   **walks `src/` + `tests/` only** — "find_sources is for source code, not
   docs/" (`src/findsources.h:6-9`, confirmed `findsources.cpp:186-190`).

So doc discovery costs repeated `grep`/`Read` — the exact per-task token tax
`codebase_index` removed for source, still unpaid for docs.

**The 2026-06-15 cross-project survey re-grounded the roadmap sketch.** The
roadmap bullet was written from Ants Terminal's own conventions; surveying all
15 projects showed those do not generalise, and Ants MCP serves *every*
project via `caller_cwd` (like `codebase_index`). Three corrections result:

1. **Cross-references are relative markdown links `[text](path.md)`, not
   `[[wiki-links]]`.** No surveyed project writes docs with `[[…]]` — that is
   only the Claude *memory* file format. The roadmap's "`[[cross-reference]]`
   graph" would have indexed a syntax that does not occur. The xref graph
   parses `[text](relative.md)` (§ 2.2).
2. **IDs are project-specific** (`ANTS-NNNN`, `[mame-curator-NNNN]`, `P##`,
   `#### Pass N.M`, `M1..M9`, `TC-NN-MM`, `Phase N`, or none). A hardcoded
   `ANTS-NNNN` regex would index one project. v1 derives a doc's id from its
   **filename stem** (`docs/specs/ANTS-1637.md` → `ANTS-1637`; `auth.md` →
   `auth`) — generic across every layout.
3. **`docs/` layout and presence vary** — rich trees (Ants, MAME, RetroDB,
   Music, perch), flat top-level only (rusty-psn, YT-DLP, 3D_Engine), or none
   (Rolodex, MKV_to_MP4). v1 walks generically (top-level `*.md` + the `docs/`
   subtree) with **no hardcoded subdir taxonomy**, and a zero-doc project is an
   `ok:true` empty summary, never a refusal.

The status of a spec (`**Status:**` line) is an Ants/MAME convention, so it is
parsed **best-effort** — surfaced when present, `""` when absent (INV-17).

**Layman:** Ants builds a one-time map of a project's documentation — every
`.md` file, its title, its section headings, and the links between docs —
caches it, and hands it to a Claude session in one call, so the session can
jump straight to the doc that covers what it needs instead of grepping the
whole project. It works the same way on any of your projects, not just Ants.

### 2.1 Index data shape (v1)

The on-disk cache and the in-memory `DocsIndex::Index` share one shape:

```cpp
namespace DocsIndex {

struct Heading {
    int     level = 0;   // 1..6 = ATX '#' count
    QString text;        // heading text, trimmed (trailing run of '#' stripped)
    int     line = 0;    // 1-based
};

struct DocEntry {
    QString          path;       // project-relative ("docs/specs/ANTS-1637.md")
    QString          id;         // filename stem ("ANTS-1637"); never empty (basename minus ".md")
    QString          title;      // first H1 text; "" when the doc has no H1
    QString          status;     // best-effort **Status:** value from the HEADER BLOCK,
                                 // whole (wrapped values joined); "" when absent
                                 // (INV-17, amended by ANTS-3786)
    int              lines = 0;
    qint64           mtimeMs = 0;
    QVector<Heading> headings;   // capped at kMaxHeadingsPerDoc (silent, § 2.2)
    QStringList      links;      // outbound resolved project-relative .md targets, deduped + sorted
};

struct Index {
    int                version = kIndexVersion;   // = 1
    QString            rootCanonical;
    qint64             generatedAtMs = 0;         // injected, not clock-read (testability)
    QVector<DocEntry>  docs;                       // sorted by path: root *.md (sorted) then docs/ (sorted)
    bool               docsTruncated = false;      // INV-12/INV-15 build ceiling hit
};

}  // namespace DocsIndex
```

JSON serialisation (`toJson`/`fromJson`) mirrors this 1:1. There is **no**
stored inverted topic→doc map — `topic=` scores at query time over the
in-memory `docs[]` (§ 2.5), keeping the cache small and the keyword logic in
one place.

### 2.2 Markdown scanner

A small single-pass scanner local to `docsindex.cpp`:

```cpp
struct ScanResult {
    QString          title;       // first H1
    QString          status;      // first **Status:** value, "" if none
    QVector<Heading> headings;
    QStringList      links;       // resolved, deduped, sorted
    int              lines = 0;
};
ScanResult scanDoc(const QString &absPath, const QString &relDir, const Options &opts);
```

Per line (`QFile::readLine`), **skipping any line longer than
`kMaxLineBytes`=1024 bytes** — the catastrophic-backtracking guard `FileOutline`
applies (`fileoutline.cpp:256` — a `continue`, *not* a partial read; an
over-long heading/link line is dropped, never truncated-and-matched) — and
accumulating bytes read so the scan **stops once the cumulative read exceeds
`kMaxDocBytes`** (4 MiB): the doc still gets an entry, with whatever
headings/links were collected before the cutoff (a silent per-doc guard against
a multi-MB generated file; INV-19):

- **Heading** — `^(#{1,6})\s+(.+)$`: `level` = captured-group-1 length, `text`
  = group 2 trimmed with a trailing ` #…` run stripped (ATX closing fence).
  The first `level==1` heading sets `title`. Collect up to
  `kMaxHeadingsPerDoc` (1000) headings, then stop appending (silent per-doc
  cap — far above any real doc; a caller wanting certainty reads the file).
- **Status** — first line matching `^\*\*Status:\*\*\s*(.+)$` sets `status`
  (best-effort; absent in most projects).
- **Links** — every `\[[^\]]*\]\(([^)\s]+)\)` capture whose target, after
  stripping a trailing `#anchor`, ends in `.md`: resolve relative to `relDir`
  (the doc's own directory), normalise (`QDir::cleanPath`), keep
  project-relative. Drop `http(s)://` / `mailto:` / pure-anchor / non-`.md`
  targets and any that `cleanPath`s outside the root. Dedup + sort. Capped at
  `kMaxLinksPerDoc` (500). A kept target is recorded **whether or not it is
  itself indexed** — a link to a not-walked `packaging/x.md` (in-root but
  outside the § 2.4 walk roots) is kept; only the `linked_from` reverse map
  (§ 2.5) is restricted to pairs that are both indexed.

**Why a new scanner, not `FileOutline::compute`.** `FileOutline`'s Markdown
mode emits heading text via `offer("heading", m.captured(2), line)`
(`fileoutline.cpp:323`), but its `offer(kind, name, signature)` sink
(`fileoutline.cpp:263-265`) has **no heading-level slot** — the third arg is
the line *text*, and the line *number* comes from a separate `totalLines`
counter inside `appendSymbol`, so nesting level is never captured — and it
extracts **no links** at all. Capturing level + links would change
`FileOutline`'s symbol schema, which the `file_outline` tool's output depends
on — an orthogonal edit. The heading regex itself is one line (the same
`^(#{1,6})\s+(.+)$` shape as `fileoutline.cpp:84`); the duplication is
deliberate and noted in-code (the roadmap's "else a small heading+link
parser" branch).

### 2.3 Pure helper API

```cpp
namespace DocsIndex {

constexpr int    kIndexVersion      = 1;
constexpr int    kMaxIndexDocs      = 2000;            // INV-12 build doc-count ceiling
constexpr qint64 kMaxCacheBytes     = 8 * 1024 * 1024; // INV-15 hard cache/heap ceiling (8 MiB)
constexpr int    kMaxHeadingsPerDoc = 1000;            // INV-19 silent per-doc cap
constexpr int    kMaxLinksPerDoc    = 500;             // INV-19 silent per-doc cap
constexpr int    kMaxTopicHits      = 50;              // INV-6 topic= response cap
constexpr int    kMaxLinkedFrom     = 200;             // INV-18 doc_path= reverse-edge cap
constexpr int    kMaxLineBytes      = 1024;            // INV-3 fixed regex-skip guard (not Options-overridable; mirrors FileOutline)
constexpr qint64 kMaxDocBytes       = 4 * 1024 * 1024; // INV-19 per-doc read budget (ROADMAP/CHANGELOG can be MB-scale)
constexpr int    kMaxHeaderBlockLines = 256;           // INV-19 silent per-doc cap (ANTS-3786)

struct Options {                       // all overridable for tests
    int    maxIndexDocs      = kMaxIndexDocs;
    qint64 maxCacheBytes     = kMaxCacheBytes;
    int    maxHeadingsPerDoc = kMaxHeadingsPerDoc;
    int    maxLinksPerDoc    = kMaxLinksPerDoc;
    int    maxTopicHits      = kMaxTopicHits;
    int    maxLinkedFrom     = kMaxLinkedFrom;
    qint64 maxDocBytes       = kMaxDocBytes;
    int    maxHeaderBlockLines = kMaxHeaderBlockLines;   // ANTS-3786
};

// Cold build: walk <root>/*.md (non-recursive) then <root>/docs/**/*.md
// (recursive), scanDoc each, sort by path. Stops at maxIndexDocs OR when the
// serialised index would exceed maxCacheBytes (whichever first), setting
// docsTruncated. generatedAtMs passed in (no internal clock read).
Index build(const QString &rootCanonical, qint64 generatedAtMs, const Options &opts = {});

// What changed on disk vs `prev`: docs whose mtime differs (changed), docs on
// disk absent from `prev` (added), `prev` docs gone from disk (removed).
struct StaleSet { QStringList changed, added, removed;
                  bool any() const { return !changed.isEmpty() || !added.isEmpty() || !removed.isEmpty(); } };
StaleSet staleDocs(const Index &prev, const QString &rootCanonical);

// Re-scan only changed+added, drop removed, reuse prev's entries for untouched.
// *refreshedOut = changed+added count.
Index refresh(const Index &prev, const QString &rootCanonical, qint64 generatedAtMs,
              const Options &opts, int *refreshedOut);

// One query's selectors (§ 2.5): at most one member non-empty. The handler
// rejects ≥2 non-empty with bad_args *before* calling query().
struct QueryParams { QString topic; QString docPath; QString id; };

// Build the response body (without the dispatcher-injected etag) for one query.
QJsonObject query(const Index &idx, const QueryParams &params,
                  int refreshedDocs, const QString &cachePath, const Options &opts = {});

QJsonObject toJson(const Index &);
Index       fromJson(const QJsonObject &);

QString     cachePathFor(const QString &rootCanonical);

// Orchestrate load → refresh → write-back → query. Cold-builds when the cache
// is absent / unparseable / version- or root-mismatched. nowMs injected.
// Forwards `refresh`'s out-count + `cachePathFor(root)` into `query()`.
QJsonObject serve(const QString &rootCanonical, qint64 nowMs, const QueryParams &params,
                  const Options &opts = {}, const QString &cachePathOverride = {});

}  // namespace DocsIndex
```

**Walk roots.** v1 admits `<root>/*.md` (the top-level README / CHANGELOG /
ROADMAP / CLAUDE.md … family, non-recursive) plus the entire `<root>/docs/`
subtree recursively (`*.md` only). An absent `docs/` is skipped silently. Other
doc homes (`packaging/`, submodule READMEs, `.github/`) are out of scope (§ 5).

### 2.4 Build & staleness (lazy, on-demand)

There is **no** background timer — the saving is in *serving* a pre-computed
map (the `codebase_index` § 2.3 argument applies verbatim). Each call:

1. Resolve `rootCanonical` from `caller_cwd` (mirrors
   `cmdCodebaseIndex`: `expandGlobalConfigSentinel` → `resolveRootCanonical`).
2. Load the disk cache (§ 2.6). **Cold-build** on any of (INV-14): the file is
   absent; its bytes do not parse as JSON; its `version` ≠ `kIndexVersion`; its
   `rootCanonical` ≠ the resolved root.
3. Otherwise `staleDocs` + `refresh` only the delta. Unlike `codebase_index`
   there is **no external map-source mtime** in staleness — a doc's own mtime
   is the only signal (a doc set has no `subsystems.md` analogue).
4. If anything changed (cold build or non-empty `StaleSet`), write the cache
   back atomically (§ 2.6) honouring `maxCacheBytes`. `refreshed_docs` echoes
   the re-scanned count.
5. Filter + serve (§ 2.5).

The warm path is *one `stat` per indexed doc + one JSON parse + serve* — zero
`scanDoc` passes when nothing changed. A root with no `*.md` at top level and no
`docs/` yields `doc_count:0`, an `ok:true` empty summary (never a refusal).

### 2.5 Query selectors

```json
{ "caller_cwd": "/abs/project",         // required
  "topic":    "cold eyes review loop",   // optional — keyword search
  "doc_path": "docs/standards/specs.md", // optional — one doc's outline
  "id":       "ANTS-1637" }              // optional — docs by filename stem
```

| selector | hit body | miss / refusal |
|---|---|---|
| *(none)* | summary: `{docs:[{path, id, title, status, heading_count}], dirs:[{dir, doc_count}]}` (`doc_count` + `docs_truncated` ride the meta block) | — (zero-doc root → `ok:true` empty summary, not a miss) |
| `topic=` | `{matches:[{path, id, title, score, evidence:[…≤3]}]}` ranked desc, capped at `maxTopicHits` (`topic_truncated` rides the meta block) | no scoring doc → `ok:true, found:false, matches:[]` |
| `doc_path=` | the doc's entry `{path, id, title, status, lines, headings:[{level,text,line}], links:[…], linked_from:[…]}` (`linked_from` = reverse edges from the in-memory index, capped at `maxLinkedFrom`; `linked_from_truncated` rides the meta block) | in-root but unindexed (incl. a directory) → `ok:true, found:false`; outside-root/malformed, **or an in-root symlink canonicalising outside root** → `ok:false, code:"bad_path"` |
| `id=` | `{matches:[{path, title, status}], found:true}` — **all** docs whose filename stem == `id` (e.g. `docs/specs/ANTS-1637.md` + `docs/journal/ANTS-1637.md`), exact case-sensitive (`id` is omitted from each entry — it equals the queried value) | no stem match → `ok:true, found:false, matches:[]` |
| *(≥2 selectors)* | — | `ok:false, code:"bad_args"` |

Caveats:

- **Soft miss, not a code.** A `topic`/`doc_path`-in-root/`id` miss is
  `ok:true, found:false` — querying an index, absence is a valid answer (the
  `codebase_index` § 2.5 split: index-absence ≠ refusal). Only an outside-root
  `doc_path` (`bad_path`) and `≥2 selectors` (`bad_args`) are refusals. `found`
  rides the response **body** (not the meta block), mirroring `codebase_index`.
- **All `*_truncated` flags ride the meta block** (§ 2.7) — `docs_truncated`,
  `topic_truncated`, `linked_from_truncated` — each always `false` for a body
  that cannot set it (`topic_truncated` only `topic=`, `linked_from_truncated`
  only `doc_path=`), mirroring `codebase_index`'s `symbols_truncated` rule.
- **Empty selector = absent.** A member that is the empty string (`{topic:""}`)
  counts as *not provided* — falls through to the summary, not `bad_args`.
- **`dirs[]` rollup** — `dir` is each doc's immediate parent directory,
  project-relative (`docs/specs`, `docs/standards`, …); a root-level doc
  (`README.md`) buckets under `"."`. The buckets therefore partition `docs[]`
  exactly once each (INV-16). `dirs[]` and every summary count are computed from
  the post-truncation in-memory `docs[]`, so they stay consistent when
  `docs_truncated` is set (the counts describe what was *indexed*, not what is
  on disk).
- **`id=` entry shape diverges by design** — only the `id=` `matches[]` omit the
  per-entry `id` (it equals the queried value); `summary` and `topic=` entries
  carry it. An implementer must not "helpfully" re-add `id` to `id=` entries —
  INV-8's test asserts the `{path, title, status}` shape.
- **`heading_count`** is the doc's `headings[].length` (post per-doc cap) — a
  light summary field so a caller sees a doc's outline depth without the full
  `doc_path=` body.
- **`topic=` scoring** — tokenise the topic on whitespace, lowercase; per doc,
  score = Σ over tokens of (title hit ×3 + path hit ×2 + heading-text hit ×1),
  where **each token contributes its weight at most once** (a binary per-token
  presence test, not an occurrence count). `evidence` holds ≤3 human-readable
  hit strings (reusing `find_sources`' `score` + `evidence[]≤3` idea — not its
  exact `FileHit` shape, which also carries `role`). Ties break by `path`
  ascending (deterministic). After ranking, the list is truncated to
  `maxTopicHits` and `topic_truncated` (meta) is set. Scoring sees only the
  doc's **post-cap** `headings[]` (INV-19), so a >`maxHeadingsPerDoc` doc's
  dropped headings do not contribute — consistent with the silent-cap design.
  This is the doc-side of the gap `find_sources` leaves; it indexes headings +
  title + path, **not** full body prose (a future enhancement, § 5).
- **`linked_from` is capped** at `maxLinkedFrom` (200) with
  `linked_from_truncated:true` when cut — a doc referenced by thousands of
  others does not return an unbounded reverse-edge list (the no-unbounded-growth
  rule; INV-18). Reverse edges are computed from the in-memory `docs[]`, so a
  build-ceiling-dropped (`docs_truncated`) linker is silently absent from
  `linked_from`.
- `doc_path=` returns the *indexed outline*, never the doc's source bytes — for
  bytes use `read_region`.

### 2.6 Cache file

`~/.cache/ants-terminal/docs-index/<cwdHash(rootCanonical)>.json`
(`GenericCacheLocation` + `/ants-terminal/docs-index`), reusing
`SessionMemoryEngine::cwdHash` (`src/sessionmemoryengine.h:41`) keyed on the
**canonical resolved root** — the `mcp-caches.md` never-shadow contract (a
relocated project gets a new key; the key never aliases two roots).

- **`kIndexVersion` gates schema *and* scanner format** — bump it whenever the
  § 2.1 shape or the § 2.2 scanner output changes, so an Ants upgrade
  invalidates stale caches via the version-mismatch cold-build trigger (INV-14).
- **Not in-repo.** Like every Ants derived cache it lives under
  `~/.cache/ants-terminal/` — no repo pollution, no `.gitignore` churn.
- **Atomic write** via `QSaveFile` (write-full-or-fail → `commit()`) so a
  concurrent same-root reader never sees a torn file (INV-13).
- **Last-writer-wins is safe** — the index is purely derived; a clobbered cache
  is rebuilt next query with no data loss. No cross-process lock (a lock would
  guard rebuildable bytes). Concurrent cold builds duplicate CPU, accepted as a
  rare one-time cost. **No RcGate** — project read anchored by `caller_cwd`; its
  only write is this `~/.cache` derived file, not a project file.

### 2.7 Output envelope & standard contracts

Every response carries a meta block:

```json
{ "ok": true,
  "generated_at_ms": 1780000000000, // last build/refresh write; preserved on a fully-warm no-write query
  "doc_count": 214,
  "refreshed_docs": 0,         // docs re-scanned on THIS call (0 = fully warm)
  "cache_path": "/home/…/docs-index/<hash>.json",
  "docs_truncated": false,        // INV-12/INV-15 — build ceiling hit
  "topic_truncated": false,       // INV-6 — topic= response cap hit (false for non-topic bodies)
  "linked_from_truncated": false, // INV-18 — doc_path= reverse-edge cap hit (false for non-doc_path bodies)
  "etag": "<payload sha256 — injected by the dispatcher, not the handler>"
  /* + the selector-specific body from § 2.5 */ }
```

Assembled no-selector summary (meta + summary body, § 2.5):

```json
{ "ok": true, "generated_at_ms": 1780000000000, "doc_count": 214,
  "refreshed_docs": 0, "cache_path": "/home/…/docs-index/<hash>.json",
  "docs_truncated": false, "topic_truncated": false, "linked_from_truncated": false, "etag": "…",
  "docs": [ {"path":"README.md","id":"README","title":"Ants Terminal","status":"","heading_count":12},
            {"path":"docs/specs/ANTS-1637.md","id":"ANTS-1637","title":"`codebase_index` MCP tool …","status":"accepted (2026-06-05)","heading_count":31}, … ],
  "dirs": [ {"dir":".","doc_count":11}, {"dir":"docs/specs","doc_count":176}, {"dir":"docs/standards","doc_count":20}, … ] }
```

(`docs[].length == doc_count` and `Σ dirs[].doc_count == doc_count` — INV-16.)

These are the **standard read-tool contracts** (`docs/standards/mcp-tools.md`);
listed here only for the `docs_index` wiring sites:

- **caller_cwd: Required** (`callerCwdContractFor`, `claudeintegration.cpp:8882`
  row). Empty `caller_cwd` → `caller_cwd_required` before the handler runs.
- **Path validation.** A `doc_path` arg routes through
  `PathValidation::validatePath(rawPath, rootCanonical, "docs_index",
  "doc_path")` (`src/pathvalidation.h`; `allowOutsideRoot` defaults `false` —
  the live sibling `cmdCodebaseIndex` omits it, `remotecontrol.cpp:8340-8342`);
  malformed / outside-root / symlink escape → `code:"bad_path"`. The
  trust-boundary defence is the **canonical-form anchor**: `validatePath`
  canonicalises the path (`pathvalidation.cpp:71`) and rejects when it is not
  `anchoredUnder` the root (`pathvalidation.cpp:96-100`), so an in-tree→outside
  symlink escape rejects (INV-7). (`topic`/`id` are not path-typed.)
- **ETag-304 (ANTS-1499).** Add `docs_index` to `isEtagSupportedTool`
  (`claudeintegration.cpp:9051` cluster); the handler emits no `etag` (the
  dispatcher hashes the whole payload). The etag is stable across consecutive
  warm queries and busts on any write — INV-10.
- **fields projection (ANTS-1720).** Add `docs_index` to

## 3. Invariants

- **INV-1** — A cold `build` walks `<root>/*.md` (non-recursive) then
  `<root>/docs/**/*.md` (recursive; absent `docs/` skipped silently), scans
  each, and produces `docs[]` of `{path, id, title, status, lines, mtimeMs,
  headings[], links[]}` sorted by path; a root with no docs → `doc_count:0`,
  `ok:true` empty summary (not a refusal). *Test:* `build` over a fixture tree
  (assert a known doc's entry shape + a known heading) and over a doc-less root
  (`doc_count:0`, `ok:true`).
- **INV-2** — `refresh` re-scans only docs whose mtime changed or that were
  added, drops removed docs from `docs[]`, reuses `prev`'s entries for
  untouched docs; `refreshedOut` == changed+added count. Staleness is
  **mtime-only** — there is no external map-source signal (unlike
  `codebase_index`'s `mapSourceChanged`; a doc set has no `subsystems.md`
  analogue). *Test:* build, then in one `refresh` bump one doc's mtime
  (re-scanned), delete a second (gone), add a third (present) →
  `refreshedOut==2`, untouched docs byte-identical.
- **INV-3** — The scanner recognises ATX headings `^(#{1,6})\s+(.+)$` with
  `level` ∈ 1..6, `line` 1-based, trailing `#` fence stripped; the first
  `level==1` heading is the doc `title` (`""` when none). A line longer than
  `kMaxLineBytes` is skipped, never partial-matched (§ 2.2). *Test:* fixture doc
  with `#`/`##`/`###` headings → levels {1,2,3}, correct lines, title == the H1
  text; a doc opening with `##` → `title==""`; a `#`-heading line padded past
  `kMaxLineBytes` is absent from `headings[]`.
- **INV-4** — Link extraction keeps only relative `.md` targets, resolved
  relative to the doc's directory + `cleanPath`-normalised to project-relative,
  deduped + sorted; `http(s)`/`mailto`/pure-anchor/non-`.md`/escaping targets
  are dropped; a kept target need not itself be an indexed doc (§ 2.2).
  *Test:* a doc **at `docs/specs/d.md`** linking `[a](sib.md)`,
  `[b](../x/y.md#sec)`, `[c](https://e.com)`, `[d](img.png)` →
  `links==["docs/specs/sib.md", "docs/x/y.md"]` (each resolved against
  `docs/specs/`, the `#sec` anchor stripped, the array sorted); the external
  URL, the image, and any anchor-only target dropped. The `docs/x/y.md` target
  is kept even though no such doc is indexed.
- **INV-5** — At most one of `{topic, doc_path, id}`; two or more →
  `code:"bad_args"`. No selector → the summary body (counts + light per-doc
  list + dir rollup), never a per-doc heading dump. An empty-string selector
  counts as absent. *Test:* arg-matrix fixture: two-selector → `bad_args`;
  `{topic:""}` → summary; no selector → summary keys.
- **INV-6** — `topic=` returns docs scored over title (×3) / path (×2) /
  heading (×1), ranked desc with `path`-ascending tie-break, capped at
  `maxTopicHits` with `topic_truncated:true` when cut; no scoring doc →
  `ok:true, found:false, matches:[]`. *Test:* `Options{maxTopicHits:1}` over a
  fixture where 2 docs score → one match, `topic_truncated:true`, and the
  surviving match is the higher-scored (asserts *which*); a no-hit topic →
  `found:false`.
- **INV-7** — `doc_path=` routes through `PathValidation::validatePath` under
  `caller_cwd`: outside-root/malformed, **or an in-root symlink canonicalising
  outside root** (the canonical-form anchor — `pathvalidation.cpp:71` +
  `:96-100`), → `bad_path`; an in-root path absent from the index (incl. a
  directory) →
  `ok:true, found:false`; an indexed path → its entry including a
  `linked_from[]` reverse-edge list. *Test:* `doc_path:"../../etc/passwd"` →
  `bad_path`; an unindexed in-root path → `found:false`; an indexed doc that a
  second fixture doc links to → entry with that second doc in `linked_from`.
- **INV-8** — `id=` returns **every** doc whose filename stem equals `id`
  (exact, case-sensitive) as `{path, title, status}`, so two docs sharing a stem
  across dirs both appear; no stem match → `ok:true, found:false, matches:[]`.
  *Test:* fixture with `docs/specs/ANTS-9.md` + `docs/journal/ANTS-9.md` →
  `id:"ANTS-9"` returns both (sorted by path); `id:"ants-9"` (wrong case) →
  `found:false`.
- **INV-9** — caller_cwd is Required: empty `caller_cwd` →
  `caller_cwd_required` before the handler runs. *Test:* source-scrape
  `callerCwdContractFor` returns `Required` for `docs_index` + a dispatch test.
- **INV-10** — ETag-304: `docs_index` is in `isEtagSupportedTool`, the schema
  carries `etag_match`, the handler emits no `etag`, and a matching `etag_match`
  short-circuits to `{ok:true, unchanged:true, etag}`. The etag is stable across
  consecutive warm queries and busts on any write; the lone non-content miss is
  the first warm query after a build/refresh (`refreshed_docs` N→0). A fully-warm
  no-write query preserves `generated_at_ms` verbatim (a re-read of the clock
  would bust the etag). *Test:* source-scrape (`docs_index` in
  `isEtagSupportedTool`, no handler-side `etag`) + a four-call feature test
  (cold build → first warm re-emit → second warm 304 → touch a doc → bust),
  asserting `generated_at_ms` is byte-identical across the two warm calls.
- **INV-11** — fields projection: `docs_index` honours `fields=` (ANTS-4524: no allowlist)
  and `fields:["docs"]` narrows the summary (and narrows whichever body is
  present for a selector query); list `"etag"` to keep 304. *Test:*
  source-scrape + projection feature test.
- **INV-12** — Build doc-count ceiling: a build over more than `maxIndexDocs`
  docs yields a partial index of the first `maxIndexDocs` in **deterministic
  order** — all root `*.md` (sorted) before any `docs/` (sorted) — with
  `docs_truncated:true`, never an unbounded scan. *Test:* `Options{maxIndexDocs:2}`
  over a fixture of 2 root + 1 `docs/` doc → `docs_truncated:true`, the two root
  docs indexed and the `docs/` doc dropped (exercises cross-root order).
- **INV-13** — Cache write is atomic (`QSaveFile` + `commit()`), keyed by
  `cwdHash(rootCanonical)`; a reload of the written cache equals the in-memory
  index. *Test:* source-scrape `QSaveFile` + build → `toJson` → write → read →
  `fromJson` round-trip equality.
- **INV-14** — A cache whose bytes do not parse, whose `version` ≠
  `kIndexVersion`, or whose `rootCanonical` ≠ the resolved root is discarded and
  rebuilt (never served stale/corrupt/cross-root). *Test:* seed (a) `version:0`,
  (b) foreign-`rootCanonical`, (c) truncated-garbage cache files at the right
  key; each query rebuilds (`version:1`, correct root, valid body).
- **INV-15** — Build byte ceiling (the binding RAM bound): a build stops adding
  docs once the serialised index would exceed `maxCacheBytes`, setting
  `docs_truncated:true`, using the **same deterministic order as INV-12**, so
  neither the on-disk cache nor the per-query parse exceeds the ceiling and
  *which* docs survive a byte-cut is reproducible. The ceiling is enforced
  against a **running serialised-size estimate** accumulated as each doc is
  appended (not an O(n²) re-serialise per doc), so the cut point is
  deterministic for a given fixture. `maxIndexDocs` (INV-12) and
  `maxCacheBytes` are **independent guards**: whichever binds first stops the
  build (both set `docs_truncated`). *Test:* a tiny-`maxCacheBytes` `Options`
  over an ordered multi-doc fixture → `docs_truncated:true`, the serialised
  cache ≤ the cap, surviving docs == the deterministic-order prefix.
- **INV-16** — Summary count integrity: `docs[].length == doc_count`,
  `Σ dirs[].doc_count == doc_count` (every indexed doc is in exactly one dir
  bucket), and each summary row's `heading_count == headings[].length` (the
  stored post-cap count). All summary counts derive from the post-truncation
  in-memory `docs[]`, so they stay self-consistent under `docs_truncated`.
  *Test:* a multi-dir fixture asserts all three equalities; a doc exceeding
  `maxHeadingsPerDoc` has `heading_count == maxHeadingsPerDoc`.
- **INV-17** — Status is best-effort + project-agnostic: a `**Status:**` line
  **in the header block** — the lines before the first `^## ` — sets `status`,
  to its whole logical value (continuations joined) rather than its first
  physical line; a `**Status:**` appearing only below that bound is body prose
  and leaves `status==""`. Absence likewise leaves `status==""` and is never an
  error (the scanner assumes no project layout or id scheme). *Test:* a doc with
  a header-block `**Status:**` line → that value; a doc without one → `""`,
  still indexed. *(INV-17 amended by ANTS-3786 — position and extent were both
  unstated, and the reader took the first match anywhere in the file, truncated
  to one line. Extent rule + position tests: ANTS-3786 INV-1/INV-3.)*
- **INV-18** — `doc_path=` reverse-edge cap: `linked_from[]` returns at most
  `maxLinkedFrom` linkers in deterministic (`path`-ascending) order, with
  `linked_from_truncated:true` when cut — no unbounded reverse-edge list.
  *Test:*
  `Options{maxLinkedFrom:1}` over a fixture where 2 docs link the same target →
  `linked_from.length==1`, `linked_from_truncated:true`, and the surviving
  linker is the `path`-first one (asserts *which*).
- **INV-19** — Silent per-doc caps: a doc with more than `maxHeadingsPerDoc`
  headings keeps the first N; more than `maxLinksPerDoc` links keeps the first
  N (post-sort); a header block longer than `maxHeaderBlockLines` yields
  whatever status was found within the cap and `""` otherwise; a doc whose
  cumulative read exceeds `maxDocBytes` stops
  scanning at the budget and is still emitted with its partial
  headings/links — each cap is silent (no per-doc flag, mirroring
  `codebase_index`'s per-file symbol cap) and verified via `Options`
  overrides. *Test:* `Options{maxHeadingsPerDoc:1}` over a 3-heading doc →
  one heading kept; `Options{maxDocBytes:<small>}` over a doc whose headings
  straddle the budget → the entry exists with only the pre-budget headings.
  *(`maxHeaderBlockLines` added by ANTS-3786 — a LINE cap, distinct from
  `maxDocBytes`'s READ budget: it bounds the `QStringList` held, not the bytes
  streamed. Its test surface is ANTS-3786 INV-4; the budget's interaction with
  it is ANTS-3786 INV-5.)*

## 4. RAM / build cost

No persistent in-process state and no in-process MRU cache (v1 loads the disk
cache per query, refreshes, serves, frees) — no eviction policy to maintain.
Peak heap during a query ≈ the parsed cache plus one doc's `scanDoc` at a time
(bounded by `kMaxLineBytes`=1024 / `kMaxDocBytes`=4 MiB / `kMaxHeadingsPerDoc`).
The disk cache **and** the per-query parse share one hard ceiling,
`kMaxCacheBytes` = 8 MiB: the build stops adding docs once the serialised index
would exceed it (`docs_truncated`, INV-15) — the binding RAM bound, satisfying
the no-unbounded-growth rule. `kMaxIndexDocs`=2000 is the secondary guard on the
*number* of `scanDoc` passes. At Ants Terminal's scale (≈214 docs × ~40
headings/doc × ~80 B/serialised heading ≈ 0.7 MB for the heading arrays;
the per-doc `path`/`title`/`status` strings + `links[]` add a small constant,
keeping the whole index well under 1 MB) the index is an order below the 8 MiB
ceiling. A single doc's serialised entry is itself bounded —
`kMaxHeadingsPerDoc`×~80 B + `kMaxLinksPerDoc`×~path-length ≈ <120 KB — so no
single pathological doc can alone breach `kMaxCacheBytes`. No new external
library. Helper in `ants_core_lib`
(`src/docsindex.{h,cpp}`); schema in the existing `ants_claude_lib`.

Cost model (derived, not wall-clock-asserted): a cold build runs one `scanDoc`
(line-by-line regex) per doc, bounded by `kMaxIndexDocs` passes and `kMaxDocBytes`
per doc — one-time, reused from the disk cache across Ants restarts. A warm
query (no doc change) is one `stat` per indexed doc + one JSON parse + serve —
zero scan passes; an ETag-304 match additionally skips re-emitting the body.

## 5. Out of scope

- **Full-body topic search** — `topic=` scores over title/path/headings, not
  full prose. A deeper content scan (the doc analogue of `find_sources`' byte
  budget) is deferred to a follow-up id if a session wants it.
- **`[[wiki-link]]` parsing** — no surveyed project writes docs that way (§ 1);
  only relative `[text](path.md)` links are graphed. If a project adopts
  wiki-links later, a follow-up adds the second link syntax.
- **Doc homes outside `*.md` + `docs/`** — `packaging/`, `.github/`, submodule
  READMEs (e.g. RetroArch's scattered layout) are not walked in v1.
- **Non-markdown docs** — `.txt`/`.rst`/`.adoc` (e.g. Lens's plain-text
  `CHANGELOG`, aic8800's `release_note.txt`) are not indexed; v1 is `.md`-only.
- **Project-specific id/status schemes** — v1 derives ids from filename stems
  and parses only the `**Status:**` line. Mining `#### Pass N.M` / `M1..M9` /
  `[mame-curator-NNNN]` ids out of body text is deferred.
- **In-process MRU index cache** — a latency optimisation (skips the JSON
  parse on a repeat query); deferred until a measured need.
- **Background warm-keeping / git-HEAD watcher** — lazy build chosen (§ 2.4);
  per-doc mtime already catches a checkout's changed docs.
- **`current_state` aggregator slot** — composes later; not built here.
- **`session_orient` eager-refresh** — ANTS-2140 made `session_orient` eagerly
  refresh `codebase_index` at session start; folding `docs_index` in the same
  way is a natural follow-up but is **not** v1 (it would add a cold-build cost
  to every first call; gate it behind a measured need / its own id).

## 8. Open questions

1. **Summary doc-list size on a 200+-doc project** — the no-selector summary
   returns one light `{path,id,title,status,heading_count}` row per doc
   (≈80 B). At Ants's ~214 docs that is ~17 KB — the *map* the tool exists to
   provide, bounded by `docs_truncated` + `fields` projection (drop `docs` via
   `fields:["dirs"]`). *Tentative: keep the full light list; revisit a separate
   summary cap only if a real project exceeds a comfortable envelope.*
2. **`topic=` vs a future `find_docs`** — `topic=` is folded into `docs_index`
   (one verb, headings-level search) rather than a sibling of `find_sources`,
   because the index is already in memory. A future full-body doc search may
   warrant its own verb; not v1.
