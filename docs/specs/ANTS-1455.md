# ANTS-1455 — `test_audit_*` MCP usability gaps (RetroDB cross-session report)

**Status:** draft → implementation
**Kind:** enhancement
**Source:** cross-session-report-2026-05-17 (RetroDB CC instance running `/test-audit` on a Flask app, full write-up at `/mnt/Games/Scripts/Linux/RetroDB/.test-audit-reports/ANTS_MCP_FEEDBACK.md`).
**Reuses:** ANTS-1295 PathValidation, ANTS-1353 error-code taxonomy, roadmap_query pagination pattern.

## 1. Problem

A real cross-project use of the `test_audit_*` trio against a 65-test
pytest project surfaced three friction points that make the tools
unusable on the happy path:

- **(a) `test_audit_partition` ignores `test_globs` by default.**
  `walkTestFiles` parses `tests/**/*.py` by extracting the basename
  pattern (`*.py`) and walking the entire scopeRoot — silently
  matching every `.py` in the project, including `app.py`,
  `routes/*.py`, `services/*.py`. Pre-pass findings then flag
  `datetime.now()` in production code as "test determinism" smells.
  60-70 % of subagent work is wasted on app source.

- **(b) `test_audit_synthesis_prompt` rejects `reports_dir` outside
  project root.** The natural place for ephemeral reports is `/tmp`
  (the test-audit skill itself says "Capture to `/tmp/test-audit-…`"),
  but the engine refuses with the misleading error code
  `reports_dir_missing` — the dir is not missing, it's *rejected*.
  Forces users to `cp` reports under the project root, where they
  collide with `.gitignore` semantics.

- **(c) `test_audit_synthesis_prompt` returns a 112 KB single-line
  blob that exceeds the orchestrator's tool-result limit.** A 7-chunk
  project on the happy path. The orchestrator falls back to reading
  the per-chunk markdown directly, defeating the synthesis tool.

## 2. Surface

### 2.1 `walkTestFiles` — honour test_globs

Replace the basename-extraction approach at
`testauditengine.cpp:182-209` with a glob-prefix-aware walk +
manual glob→regex conversion (Qt's
`QRegularExpression::wildcardToRegularExpression` does NOT
implement globstar — `tests/**/*.py` would not match
`tests/test_a.py` directly because it requires ≥1 intermediate
path segment; see Lane A + E cold-eyes verification).

Algorithm:

1. **Per glob, derive path prefix.** Strip the leading directory
   component(s) up to the first `**` (or to the last `/` if no
   `**` present):
   - `tests/**/*.py` → prefix `tests/`
   - `tests/integration/test_*.py` → prefix `tests/integration/`
   - `**/test_*.py` → prefix `""` (leading `**` ⇒ fall through
     to bare-basename branch — INV-3a)
   - `test_*.py` → prefix `""` (no `/`)
   - `*_test.py` → prefix `""` (no `/`)
2. **Run `QDirIterator` rooted at `<scopeRoot>/<prefix>`.** Empty
   prefix ⇒ root at `scopeRoot` itself. Recursive flag stays on
   for `**`-containing globs; otherwise non-recursive (a glob
   without `**` matches at a fixed depth).
3. **Per emitted path, compute the candidate-relative path**
   (`path.mid(scopeRoot.size() + 1)`) and run a custom
   `globToRegex` against it:
   - `**/` → `(?:[^/]+/)*` (zero-or-more directory segments)
   - `**`  (no trailing `/`) → `.*`
   - `*`   → `[^/]*` (intra-segment wildcard)
   - `?`   → `[^/]` (intra-segment single char)
   - `[abc]` and `[a-z]` character classes passed through to
     `QRegularExpression` directly (Qt supports them natively).
   - Other regex metachars are `QRegularExpression::escape`'d.
   - Anchored `\A…\z`.
4. **For globs without `/`** (INV-3 / INV-3a), the regex matches
   against the candidate's *basename*, so `test_*.py` matches
   `tests/test_a.py`, `tests/unit/test_b.py`, and root-level
   `test_root.py` alike. Globs WITH `/` match against the
   candidate-relative path.

The path-prefix optimisation is a strict throughput win (full-tree
walk for `tests/**/*.py` reduces to `tests/`-subtree walk); the
re-filter step guarantees correctness against the full glob shape.

### 2.2 `synthesize()` — `reports_dir` opt-in escape hatch

Add new fields on `SynthRequest`:

```c++
struct SynthRequest {
    QString     callerCwd;
    QString     partitionToken;
    QString     reportsDir;          // project-relative OR absolute
    QJsonObject calibrationAnchor;
    bool        allowOutsideProject = false;  // ANTS-1455
    QString     mode;                          // ANTS-1455 (§ 2.3)
    int         offset = 0;                    // ANTS-1455 (§ 2.3)
    int         limit = -1;                    // ANTS-1455 (§ 2.3)
};
```

Route ALL `reports_dir` validation through
`PathValidation::validatePath` rather than re-implementing the
NFC + control-char + `\\` + canonicalise pipeline locally (per
ANTS-1295 INV-1 "one helper"). The helper gains a new
optional `allowOutsideRoot` parameter:

```c++
namespace PathValidation {
struct Check { /* unchanged */ };
Check validatePath(const QString &rawPath,
                   const QString &rootCanonical,
                   const QString &toolName,
                   const QString &paramName,
                   bool allowOutsideRoot = false);  // ANTS-1455
}
```

When `allowOutsideRoot:true`, the helper still applies NFC +
control-char + `\\` reject + canonicalise, but skips the
project-root prefix check. Existing callers (~10 sites) get
the new arg defaulted to `false` and remain byte-for-byte
identical.

Behaviour:

- `allow_outside_project: false` (default) — current behaviour
  preserved byte-for-byte except the refusal code rename below.
  `reports_dir` MUST resolve under `callerCwd`.
- `allow_outside_project: true` — accept absolute paths anywhere
  on the filesystem the calling user can read.
  `allow_outside_project:true` with a dir that happens to fall
  under `callerCwd` succeeds identically to `false` mode (the
  flag relaxes, doesn't redirect).

Refusal envelopes:

- **`reports_dir_outside_root`** (≤ 24 chars, replaces old
  `reports_dir_missing`) — § 1 input validation. Fires when
  `allow_outside_project:false` AND the resolved dir is outside
  `callerCwd`.
- **`reports_dir_unreadable`** — § 2 resource state. Fires when
  the resolved dir doesn't exist, isn't a directory, or the
  calling user lacks read permission.
- **`reports_dir_empty`** — § 2 resource state. Fires when the
  resolved dir is readable but contains zero `*.md` files at
  top level. Current behaviour silently produces an empty
  prompt — explicit refusal saves the "looks like it worked
  but didn't" debug round-trip.
- **`bad_path`** — NFC / control-char / `\\` violations
  (existing behaviour preserved; emitted by
  `PathValidation::validatePath`).

The chunk-report fence wrapper at `testauditengine.cpp:584-587`
(`&lt;chunk_report file="…"&gt;…&lt;/chunk_report&gt;` with
nested-fence entity escaping) is preserved across BOTH
`allow_outside_project` modes — the trust boundary on `*.md`
content is unchanged. Per ADR-0004 the same-UID model means
read access to `/tmp` doesn't extend attack surface beyond
what the user can already do.

### 2.3 `synthesize()` — `mode` argument + pagination

New `mode` arg, default `"summary"`. **Breaking change ack:** the
default flip is intentional — v1's full-fenced-bundle default
exceeded tool-result caps on real projects (RetroDB's 7-chunk
112 KB blob). Callers wanting prior behaviour pass `mode:"full"`.

Two valid values:

- **`"summary"` (default)** — per-dimension counts + top-N
  dimensions + most-cited files + multi-line markdown prompt.
  Output target ≤ 16 KiB.
- **`"full"`** — the existing fenced-bundle behaviour, with
  `offset` + `limit` pagination across chunk reports.
  **Default `limit:5`** (NOT -1) so v1 callers transitioning
  to `mode:"full"` don't re-create the 112 KB bug. Explicit
  `limit:-1` opts into "return all chunks" (caller accepts
  the size risk).

`mode:"full"` envelope additions:

- `chunks_total` — total report count.
- `chunks_returned` — count in this response.
- `next_offset` — cursor for follow-up call (-1 when exhausted).
- `truncated_by_limit:bool` — explicit signal when more chunks
  remain.

`mode:"summary"` envelope additions:

- `per_dimension_counts: {<dim>: int}` — count of dimension-name
  keyword hits per chunk (the existing `perDimensionCount`
  heuristic; promote to a structured envelope field).
- `top_dimensions: [{dimension, count}]` — sorted descending by
  count, capped at 10 entries.
- `file_index: [{file, dimension_hits_total}]` — most-frequently
  referenced source files (parsed from existing `file:line`
  patterns inside chunk markdown via a bounded regex
  `[\w./-]+\.(py|cpp|h|js|ts|go|rs):\d+`), capped at 30 entries.
- `truncated:bool` — true when either list was clipped by its cap.

The chunk-report markdown is NOT parsed for per-finding
severity / file / line as structured records — the engine has
no contract on the report shape. `top_dimensions` and
`file_index` use bounded, regex-driven heuristics over the
markdown text; they're useful pointers, not authoritative
records. A future ANTS-NNNN may introduce a structured-JSON
trailer convention for chunk reports if richer fields become
worth the protocol cost (lane C HIGH-3 / lane E HIGH-5
deferred to follow-up).

The bundled prompt string itself is markdown-shaped with
literal `\n` line breaks in the string. The JSON transport
will encode each `\n` as the escape sequence `\n` on the wire
(per `QJsonDocument::Compact`) — when the caller decodes the
JSON, the prompt renders as multi-line in saved files / displays.
INV-12 below clarifies this is the intended behaviour (the v1
"single-line blob" complaint described the JSON-encoded
appearance of a 112 KB string in tool-result diagnostics —
unavoidable for ANY JSON-shaped MCP response).

Unknown `mode` values refuse with `bad_mode` (reused from the
existing taxonomy — `mcp-error-codes.md` § 1, no new row needed).

## 3. Invariants

### Partition walk
- **INV-1** — `walkTestFiles` with default scope (`""` / `"auto"`)
  MUST only return paths matching at least one entry in
  `testGlobs` under FULL-glob match (custom `globToRegex` helper
  per § 2.1, NOT Qt's `wildcardToRegularExpression` — which
  doesn't implement globstar).
- **INV-2** — Path-prefix optimisation: a glob containing
  `<dir>/**/<pat>` MUST limit the `QDirIterator` to
  `scopeRoot/<dir>/` rather than walking the full scopeRoot.
- **INV-2a** — Empty path prefix (e.g. leading `**/` or no
  `/` at all) ⇒ walk `scopeRoot` itself; the re-filter step
  handles the match decision.
- **INV-2b** — Walks do NOT follow symlinks (`QDirIterator`
  default). Symlinked test directories require explicit
  `scope="path:<link>"`.
- **INV-3** — Bare-basename globs (`test_*.py`, `*_test.py`,
  `conftest.py`) retain full-tree walk so basename matches at
  any depth.
- **INV-3a** — For globs without `/`, the re-filter regex matches
  against the candidate's BASENAME. For globs with `/`, the
  regex matches against the candidate-relative path
  (`path.mid(scopeRoot.size() + 1)`, forward-slash normalised).
- **INV-4** — Exclusion regex (`build[^/]*`, `node_modules`,
  `__pycache__`, etc.) still applied after glob filtering.
- **INV-5** — `scope="path:<sub>"` and `scope="files:<csv>"`
  branches are unchanged — they take precedence over glob walks.

### reports_dir
- **INV-6** — Default `allow_outside_project:false` preserves
  current behaviour byte-for-byte except the refusal code rename
  and the routing through `PathValidation::validatePath`.
- **INV-6a** — `synthesize()` invokes
  `PathValidation::validatePath(reportsDir, callerCwdCanonical,
   "test_audit_synthesis_prompt", "reports_dir",
   /*allowOutsideRoot=*/req.allowOutsideProject)` — single source
  of truth for NFC + control-char + `\\` + canonicalisation
  (ANTS-1295 INV-1).
- **INV-7** — `allow_outside_project:true` accepts absolute paths;
  the same `validatePath` call applies NFC + control + `\\` checks
  but skips the project-root prefix anchor. The chunk-report
  fence wrapper at `testauditengine.cpp:584-587` is preserved
  identically across both modes.
- **INV-8** — `reports_dir_unreadable` fires when the canonicalised
  dir doesn't exist OR isn't a directory OR the user lacks read
  permission. Categorised in `mcp-error-codes.md` § 2 (resource
  state).
- **INV-8a** — `reports_dir_empty` fires when the canonicalised
  dir is a readable directory but contains zero `*.md` files at
  top level. § 2 (resource state). Saves the silent-success
  failure mode the v1 engine had.
- **INV-9** — Mcp-error-codes.md gains:
  - § 1: `reports_dir_outside_root` (replaces / renames the
    code emitted at `testauditengine.cpp:562` from the
    pre-fix `reports_dir_missing`).
  - § 2: `reports_dir_unreadable`, `reports_dir_empty`.
  ANTS-1397 § 4's table reference to `reports_dir_missing` is
  amended in the same commit (cross-spec consistency, lane D).

### mode
- **INV-10** — `mode=""` or omitted ⇒ `mode:"summary"` default
  (BREAKING change vs. v1 — explicit in § 2.3). Unknown values
  refuse with `bad_mode` (reuses existing taxonomy row;
  mcp-error-codes.md § 1).
- **INV-11** — `mode:"summary"` output total bounded to
  ≤ 16 KiB. Achieved via:
  - `top_dimensions` capped at 10 entries.
  - `file_index` capped at 30 entries.
  - `truncated:bool` set when either cap fires.
- **INV-12** — `mode:"summary"` prompt string contains literal
  `\n` line breaks. The JSON transport encodes each as the
  escape sequence `\n` on the wire; consumer decoding produces
  multi-line markdown. The v1 "single-line blob" complaint
  described the JSON-encoded *appearance* of a 112 KB string
  in tool-result diagnostics — unavoidable for any JSON-shaped
  MCP response. INV-11's 16 KiB cap addresses the underlying
  size problem; the encoding shape is per the transport spec.
- **INV-13** — `mode:"full"` with default `limit:5` returns up
  to 5 chunk reports starting at `offset` (default 0). Explicit
  `limit:N` returns at most N. Explicit `limit:-1` returns all
  chunks (caller opts into the size risk). `next_offset`
  populated when more remain (-1 when exhausted);
  `truncated_by_limit:true` when a cap fired.
- **INV-13a** — Defaulting `mode:"full"` to `limit:5` rather
  than `limit:-1` prevents v1 callers transitioning to
  `mode:"full"` from re-creating the 112 KB-blob bug.
- **INV-14** — `mode:"full"` envelope additions
  (`chunks_total`, `chunks_returned`, `next_offset`,
  `truncated_by_limit`) are additive on the v1 fields; existing
  consumers that don't read them are unaffected.
- **INV-14a** — `top_dimensions` and `file_index` derive from
  the existing `perDimensionCount` heuristic + a bounded regex
  over chunk markdown. The engine does NOT claim authoritative
  per-finding parse (no severity / per-line records); these
  fields are pointers, not records. A future ANTS-NNNN may
  introduce a structured-JSON-trailer convention.

- **INV-16** — Only the `test_audit_synthesis_prompt` tool

## 4. RAM budget

- Partition walk: bounded by project file count × ~200 bytes/
  entry. No change to peak — the fix only DROPS files from the
  walk (the bug was including too many).
- Synthesis `mode:"summary"`: ≤ 16 KiB string buffer + ≤ ~5 KB
  for `top_findings` array (20 entries × ~250 bytes JSON
  each). Strictly less than the current 112 KB blob.
- Synthesis `mode:"full"` with pagination: ≤ ~80 KiB per page
  at default `limit:5` (5 × 16 KiB chunk reports), comfortably
  under the orchestrator's tool-result cap.
