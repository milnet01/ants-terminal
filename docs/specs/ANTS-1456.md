# ANTS-1456 — `audit_run` flat-layout v1 usability fixes + ANTS-1464 fold-in

**Status:** in flight (Bundle E follow-up, 2026-05-17).
**Kind:** enhancement.
**Lanes:** `auditrunner` (toolArgv + runAudit + writeSarif),
`claudeintegration` (audit_run descriptor), tests under
`tests/features/mcp_audit_run/`.
**Source:** cross-session-report-2026-05-17 (RetroArch CC instance
on `/mnt/Games/Scripts/Linux/RetroArch`).

## Problem

`audit_run` v1 (ANTS-1351) ships hardcoded argv defaults oriented at
the Ants Terminal layout — `cppcheck -I src/ src/`, `bandit -r src`.
A RetroArch session running against a flat-layout C project (source
under `gfx/`, `audio/`, `network/`, … at repo root, no `src/`
subdir) hit three friction points:

1. **Hardcoded `-I src/` against missing directory.** cppcheck
   silently exits 0 on `-I` paths that don't resolve, so the wrapper
   reports `raw_count:0` + `executionSuccessful:true` and the audit
   reads as "all clean" when in fact the parser never engaged.

2. **`scope:"auto"` falls back to "changed since fork-point"
   silently.** A fresh tree with no diff against `master` returns
   `total_raw:0` — correct in isolation but counterintuitive without
   the descriptor saying so.

3. **`executionSuccessful:true` is misleading when findings count
   came from `toolExecutionNotifications` rather than real results.**
   SARIF spec keeps the flag `true` for any clean exit; the wrapper
   should expose a separate signal for "ran cleanly but emitted
   config-load warnings that suppressed all findings."

The roadmap entry also notes a fourth gap surfaced in a second
RetroArch batch (logged as ANTS-1464):

4. **No per-tool args passthrough.** A caller needing project-
   specific flags (`--max-configs=1` for cppcheck on a heavy C
   codebase, etc.) has to bypass `audit_run` and shell out via
   Bash.

## Fix

Four landing-together changes:

- **(a) `toolArgv()` auto-detects `src/`.** Existing `src/` dir →
  unchanged behaviour. Missing `src/` → falls back to `.` for
  cppcheck's `-I` + scan-root and for bandit's `-r`. Single source
  of truth: `QFileInfo(projectRoot + "/src").isDir()` evaluated
  once per `toolArgv()` call.

- **(b) `audit_run` descriptor surfaces `scope:"auto"` semantics.**
  The MCP tool descriptor's `scope` field gains a sentence
  documenting the fork-point fallback and recommends explicit
  `since-tag:<earliest-tag>` for deterministic full sweeps. No
  runtime change — discoverability only.

- **(c) SARIF emit exposes `executionSuccessfulWithConfigWarnings`.**
  When `tr.status == "ok"` AND `tr.rawCount == 0` AND raw output
  is non-empty (i.e. the tool emitted notifications but no
  findings), the invocation gets `properties.executionSuccessfulWithConfigWarnings: true`.
  `executionSuccessful` itself stays at `true` (SARIF spec
  compliance) — a caller wanting to detect the "looks clean but
  isn't" case reads the property.

- **(d) ANTS-1464 fold-in — project-side audit-config.json.**
  New `loadProjectAuditConfig()` probes two locations (first wins):
  `<root>/.audit-config.json` (canonical dotfile), then
  `<root>/docs/private/audit/audit-config.json` (RetroArch-style).
  Schema: `{"<tool>": {"args": ["...", "..."]}}`. When matched,
  `toolArgv()` returns the override array wholesale. Malformed
  JSON / missing file → empty config (defaults used, no error).
  Loaded once per `runAudit()` invocation; not cached across runs
  (config is project-grain, runs are session-grain — re-read is
  cheap).

No schema change to the wire envelope (`top_findings_count`,
`scope`, `tools[]` stay the same). The new
`properties.executionSuccessfulWithConfigWarnings` field is
SARIF-spec compliant (invocation properties are an open extension
point per § 3.20.16 of the SARIF 2.1.0 spec).

## Invariants

- **AR-1.** `toolArgv("cppcheck", root)` returns
  `["-I", "src", "src"]` when `<root>/src` is a directory and
  `["-I", ".", "."]` otherwise (last two args).
- **AR-2.** `toolArgv("bandit", root)` returns `["-r", "src", ...]`
  when `src/` exists and `["-r", ".", ...]` otherwise.
- **AR-3.** `loadProjectAuditConfig(root)` returns the parsed JSON
  object when `<root>/.audit-config.json` is present and parses;
  it falls back to `<root>/docs/private/audit/audit-config.json`
  if the dotfile is absent; otherwise empty object.
- **AR-4.** When `projectConfig` contains a `{"<tool>":
  {"args": [...]}}` entry, `toolArgv(<tool>, root, projectConfig)`
  returns the override array verbatim (bypasses the src-detection
  branch entirely).
- **AR-5.** SARIF emit: when a tool exits `ok` with `rawCount == 0`
  but non-empty raw output, the invocation carries
  `properties.executionSuccessfulWithConfigWarnings: true`.
- **AR-6.** `audit_run` MCP descriptor's `scope` property
  description contains the phrase "deterministic full sweep" so a
  caller reading `tools/list` sees the recommended override
  (`since-tag:<tag>`) for the "audit truly clean" case.

## Out of scope

- Per-tool argv merging (the override is wholesale, not additive).
  A future enhancement could support `{"args": [...], "extra_args":
  [...]}` to append.
- Caching parsed `audit-config.json` across runs. Per-run reload
  keeps things simple; if the file is large enough to matter the
  fix is to shrink it, not cache it.
- SARIF property naming bikeshed —
  `executionSuccessfulWithConfigWarnings` is verbose but
  self-describing; rename is wire-breaking and out of scope.
- Tool-specific `--max-configs`-style flag defaults. Project-side
  audit-config.json is the override surface; the default argv
  stays minimal.
