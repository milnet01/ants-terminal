# ANTS-1237 — RoadmapDialog: "Updated N days ago" on 🚧 cards

- **Status:** 💭 designing 2026-05-11. Flips to ✅ on ship.
- **Source:** roadmap-v2 research synthesis 2026-05-11 (GitHub
  Projects, Linear, Jira — all surface a "last activity" line on
  in-progress items by default).
- **Lanes:** roadmapdialog (one new helper + render hook + cache
  field; mirrors the existing `parseShippedDates` pattern).
- **Kind:** implement.

## 1. Problem

A 🚧 bullet on the Roadmap dialog renders identically whether it
was flipped 📋 → 🚧 yesterday or six months ago. The two failure
modes this creates:

1. **Stall blindness.** A bullet that's been "in progress" for
   months looks the same as one moved this week. The user has to
   open `git log -- ROADMAP.md` (terminal context-switch) to find
   what's been sitting.
2. **No freshness signal on the live list.** GitHub Projects,
   Linear, Jira and Notion all show a "last activity / updated"
   timestamp on in-progress items by default — the user expects
   one here too.

User-impact: scannable signal for "what's been sitting too long",
zero extra clicks. The shipped date on ✅ cards (`rec.status == ✅`
branch at `roadmapdialog.cpp:1241-1247`) already proves the
inline-meta pattern works; this entry extends it to 🚧 with a
different data source (git blame on the bullet block, not a
CHANGELOG lookup).

## 2. Mechanism — what was investigated, what was chosen

**Population note.** At spec-write time the ROADMAP has ~5-15
🚧 bullets at any moment (verified by `grep -c "^- 🚧" ROADMAP.md`).
Perf comparisons below use this realistic count; mentions of
larger populations (50, 200) are stress-test envelopes.

### 2.a Rejected — status-emoji "stalled" lane (🛌)

A fifth status emoji to flag bullets that have stalled. Rejected
because:

- Requires manual curation. The user has to remember to flip
  🚧 → 🛌 when a bullet stalls, which is the same problem the
  feature is meant to solve.
- Multiplies parser state (every status check grows from 4 to 5
  branches; `BulletKind` enum gains an entry).
- The ROADMAP bullet at L8679 already specifies "Updated N days
  ago" as a derived signal — automatic, no manual curation.

### 2.b Rejected — "Started" date (date of first 🚧 flip)

Conceptually attractive: "in progress for 47 days" is more
actionable than "last touched 3 days ago" for stall detection.
Rejected because:

- Requires walking git log per bullet to find the commit that
  transitioned the status emoji from `📋`/`💭` to `🚧`. That's
  N `git log --follow -L /^- 🚧 \[ANTS-NNNN\]/,+1` calls, plus a
  regex on each commit's diff, for every 🚧 bullet on every
  ROADMAP.md mtime change. Even at the realistic 5-15 🚧 count
  that's 5-15 subprocess spawns vs. one — but the cosmetic-edit
  defeat below is the load-bearing rejection argument either way.
- Easy to defeat: any cosmetic edit to the bullet line (typo fix
  on the headline) changes blame to the typo-fix commit, masking
  the original flip. Distinguishing "real" from "cosmetic" edits
  requires reading the diff for status-emoji changes, which is
  the heavy walker above.
- The ROADMAP bullet at L8679 explicitly specifies "Updated" not
  "Started"; "Started" is recorded here as a future follow-on
  (see § 9).

### 2.c Rejected — synchronous per-card git blame

`git blame -L <bullet-line>,+1 ROADMAP.md` per 🚧 card. N
subprocesses for N cards. At a stress-test 200-bullet ROADMAP
× ~50 ms process startup = 10 s of UI-thread block; even at the
current 5-15 count it's 0.25-0.75 s, well over the 200 ms
"feels responsive" threshold. Rejected for obvious perf reasons.

### 2.d Rejected — file system mtime fallback

When the directory is not a git checkout (installed system copy
in `/usr/share/ants-terminal/`), fall back to ROADMAP.md mtime.
Rejected because mtime is whole-file: every bullet would show the
same "updated" date, which is worse than no signal.

### 2.e Rejected — manual `Updated:` field in the bullet

Roadmap-format extension: add `Updated: 2026-05-08` to each bullet,
the author maintains it on every touch. Pros: zero git dependency
(works on installed system copies where blame returns empty), no
QProcess at all. Rejected because it inherits the same manual-
curation failure mode that killed § 2.a — the author has to
remember to touch the field, defeating the freshness signal
exactly when stalls are most likely. If/when the installed-copy
case (no git) becomes a priority complaint, this is the natural
fallback to layer in: blame first, then field, then no signal.

### 2.f Chosen — one blame call + MAX(author-time) per bullet block

Key decisions:

1. **One `git blame --line-porcelain` per ROADMAP.md mtime
   change.** Measured ~175 ms for the current 8723-line ROADMAP
   on a 2026 desktop (`git blame --line-porcelain ROADMAP.md |
   wc -l = 113238`). Cached by file mtime (mirrors
   `refreshShippedDatesIfStale`), so the cost is paid once per
   session for most users.

2. **Parse author-time per source line.** Walk the porcelain
   output, build a `QVector<qint64> lineAuthorTime` indexed 1-based
   so it lines up with markdown line numbers. Memory: 8 bytes × N
   source lines = ~70 KiB for the current ROADMAP. Bounded; tied
   to ROADMAP size.

3. **Per-bullet aggregate = MAX over the bullet's block.** Walk
   the markdown, identify each `- 🚧 [ANTS-NNNN]` bullet line,
   then walk forward through indented continuation lines (start
   with `  `) until the **first blank line** OR a top-level
   bullet (`- ` / `* ` at column 0) OR EOF. Take
   `MAX(lineAuthorTime[lineNo])` over the range.

   **Single-paragraph contract:** the walker terminates at the
   first blank line. ROADMAP cards are de-facto single-paragraph
   by current convention — `docs/standards/roadmap-format.md`
   § 3.5 documents bullet structure (status emoji + ID + headline +
   continuation lines + optional Layman/Lanes/Source/Kind), with
   the canonical example implying single-paragraph form via
   absence rather than explicit prohibition. A future card with
   internal blank-line paragraph breaks would lose later
   paragraphs from MAX — accepted as a tradeoff. If/when this
   bites, either tighten the format spec to forbid blank-line
   breaks, or loosen the walker to allow them (re-open § 8.6).

   **Encoding contract:** ROADMAP.md is UTF-8 by project convention
   (`docs/standards/roadmap-format.md`). Both git's blame output and
   the file re-read use `QString::fromUtf8`. A non-UTF-8 ROADMAP.md
   would break the `🚧` byte match in the regex; treat as a format
   violation, not a feature bug.

   **MAX semantics:**

   - Any edit to the bullet (status flip, headline tweak, Layman
     update, body paragraph added) updates "Updated" — which is
     the user-facing contract.
   - A pure reorder (the bullet's lines moved as a block) shows
     the reorder commit's date, which is correct: the file was
     touched at that bullet on that date.

4. **Graceful degradation.** Five failure paths return an empty
   hash (no error dialog, no log spam — 🚧 cards just don't render
   the "Updated" line, mirroring the ✅-card path when shipped
   date is absent). Enumerated to match INV-6:
   - Directory not under git → `git` exits non-zero, stderr
     contains "not a git repository". Empty hash.
   - File not tracked by git → blame exits non-zero with
     "fatal: no such path '…' in HEAD". Empty hash.
   - `git` binary not on PATH → `QProcess::start` fails.
     Empty hash.
   - File does not exist → early-return at `!fi.exists()` check.
     Empty hash.
   - Blame stdout empty (empty file at HEAD, or git output
     missing `author-time` headers on extremely old git
     versions) → walker produces no entries, `out` stays empty.
     Falls through the `maxTime > 0` filter.

5. **Render-time string formatting (not cache-time).** Store
   Unix timestamps in `m_lastTouchDates`; format the human-
   readable string at render time. Why: a dialog left open
   across midnight stays correct on the next render (filter
   toggle, scroll, search). The format ladder:

   | Age (seconds) | String |
   |---------------|--------|
   | `< 86_400`                | `today` |
   | `< 2 * 86_400`            | `yesterday` |
   | `2 * 86_400` … `< 14 * 86_400`  | `Nd ago` (N = age/86_400, N ∈ [2, 13]) |
   | `< 60 * 86_400`           | `Nw ago` (N = age/(7*86_400), N ∈ [2, 8]) |
   | `< 365 * 86_400`          | `Nmo ago` (N = age/(30*86_400), N ∈ [2, 12]) |
   | otherwise                 | `Ny ago` (N = age/(365*86_400), N ≥ 1) |

   Note: `1d ago` is **never** emitted — day 1 is intercepted by
   the `yesterday` arm. Day-strings start at `2d ago`. Similarly
   `1w ago` / `1mo ago` are unreachable (day 7 = `7d ago`, day 30
   = `4w ago`). Only `1y ago` is reachable in its band.

   Threshold choices: under 2 weeks shows days (most-actionable
   granularity for "is this fresh"); 2-8 weeks shows weeks
   (stall lane); 2-12 months shows months (drifting); >1y shows
   years (write it off or rescope).

   **Discontinuities are intentional.** Three boundary jumps
   produce label-number drops in a single day's tick:
   - day 13 → day 14: `13d ago` → `2w ago` (largest jump — 13 → 2)
   - day 59 → day 60: `8w ago` → `2mo ago` (8 → 2)
   - day 364 → day 365: `12mo ago` → `1y ago` (12 → 1)

   Integer-division semantics; do not interpolate between bands.
   Tests pin every boundary (INV-4).

6. **Render emission.** In `renderCardsHtml::emitCard`, after the
   chevron toggle, branch on `rec.status == "🚧"`. If the bullet
   has an entry in `opts.lastTouchDates`, emit:

   ```html
   <span class="rm-date">· Updated 4d ago</span>
   ```

   Inline with the meta row, same position as the `<span
   class="rm-date">` on ✅ cards. Reuses the existing `.rm-date`
   CSS class so no new style rule is needed — visual consistency
   with shipped dates. (Class name `rm-date` is shared with the
   ✅ branch; the leading "Updated " prefix carries the semantic
   distinction.)

### 3.b Source changes — `src/roadmapdialog.cpp`

**Four discrete edits + one new free helper.**

1. **File-scope helper `humanAge`.** Must live **outside the
   anonymous namespace** (which closes at `roadmapdialog.cpp:343`)

   ```cpp
   // ANTS-1237 — render an age in seconds as one of the ladder
   // strings documented in spec § 2.f.5. External linkage so the
   // feature test reaches it; NOT inside the anonymous namespace.
   // Guard against negative ages (clock skew where a freshly-
   // committed bullet's author-time exceeds now by a few seconds).
   QString humanAge(qint64 ageSeconds) {
       if (ageSeconds < 0) ageSeconds = 0;
       const qint64 d = ageSeconds / 86400;
       if (d < 1)   return RoadmapDialog::tr("today");
       if (d < 2)   return RoadmapDialog::tr("yesterday");
       if (d < 14)  return RoadmapDialog::tr("%1d ago").arg(d);
       if (d < 60)  return RoadmapDialog::tr("%1w ago").arg(d / 7);
       if (d < 365) return RoadmapDialog::tr("%1mo ago").arg(d / 30);
       return RoadmapDialog::tr("%1y ago").arg(d / 365);
   }
   ```

2. **Implement `parseLastTouchDates`.** Place adjacent to
   `parseShippedDates` (around `:1413`).

   **Precondition:** `roadmapPath` is absolute. The dialog's
   `m_roadmapPath` is set absolute at construction; no codepath
   flips it relative. If a relative path is passed, behaviour is
   governed by the process CWD — no explicit guard.

   ```cpp
   QHash<QString, qint64>
   RoadmapDialog::parseLastTouchDates(const QString &roadmapPath) {
       QHash<QString, qint64> out;
       const QFileInfo fi(roadmapPath);
       if (!fi.exists()) return out;

       // One blame call. --line-porcelain repeats header fields
       // (incl. author-time) for every source line — easy to
       // index by line number. QProcess pipes already suppress
       // git's stderr progress, so no --no-progress needed.
       QProcess git;
       git.setWorkingDirectory(fi.absolutePath());
       git.start(QStringLiteral("git"),
                 {QStringLiteral("blame"),
                  QStringLiteral("--line-porcelain"),
                  QStringLiteral("--"),
                  fi.fileName()});
       if (!git.waitForStarted(2000)) return out;
       if (!git.waitForFinished(30000)) {
           git.kill();
           return out;
       }
       if (git.exitStatus() != QProcess::NormalExit
           || git.exitCode() != 0) {
           // Not a git repo, file not tracked, etc. — graceful.
           return out;
       }
       const QByteArray blameOut = git.readAllStandardOutput();

       // Build a 1-indexed vector of author-times per source line.
       QVector<qint64> lineAuthorTime;
       lineAuthorTime.append(0);  // placeholder so index 1 == line 1
       qint64 currentAuthorTime = 0;
       int currentSourceLine = 0;
       // Porcelain format: lines starting with a 40-char hex hash
       // begin a record. Header lines `author-time NNNN` follow.
       // Content line begins with TAB.
       for (const QByteArray &raw : blameOut.split('\n')) {
           if (raw.startsWith('\t')) {
               // Content line — assign the current author-time to
               // the recorded final-line number.
               while (lineAuthorTime.size() <= currentSourceLine)
                   lineAuthorTime.append(0);
               lineAuthorTime[currentSourceLine] = currentAuthorTime;
               continue;
           }
           if (raw.size() >= 41 && raw.at(40) == ' ') {
               // Hash header: "<hash> <orig> <final> [count]"
               const QList<QByteArray> parts = raw.split(' ');
               if (parts.size() >= 3) {
                   currentSourceLine = parts.at(2).toInt();
               }
               continue;
           }
           if (raw.startsWith("author-time ")) {
               currentAuthorTime = raw.mid(12).trimmed().toLongLong();
           }
       }

       // Walk the markdown, identify each `- 🚧 [ANTS-NNNN]`
       // bullet, take MAX over its block.
       QFile f(roadmapPath);
       if (!f.open(QIODevice::ReadOnly | QIODevice::Text)) return out;
       const QByteArray body = f.readAll();
       f.close();
       const QList<QByteArray> mdLines = body.split('\n');
       static const QRegularExpression rxInProgress(
           QStringLiteral("^- 🚧 \\[(ANTS-\\d+)\\]"));
       for (int i = 0; i < mdLines.size(); ++i) {
           const QString line = QString::fromUtf8(mdLines.at(i));
           const auto m = rxInProgress.match(line);
           if (!m.hasMatch()) continue;
           const QString id = m.captured(1);
           qint64 maxTime = 0;
           // Block range: this line (i+1 1-indexed) + continuation
           // lines (start with "  ") until blank or next bullet.
           int j = i;
           while (j < mdLines.size()) {
               const QString cont = QString::fromUtf8(mdLines.at(j));
               if (j > i) {
                   if (cont.trimmed().isEmpty()) break;
                   if (cont.startsWith(QStringLiteral("- "))
                       || cont.startsWith(QStringLiteral("* "))) break;
                   if (!cont.startsWith(QStringLiteral("  "))) break;
               }
               const int lineNo = j + 1;  // 1-indexed
               if (lineNo < lineAuthorTime.size()) {
                   const qint64 t = lineAuthorTime.at(lineNo);
                   if (t > maxTime) maxTime = t;
               }
               ++j;
           }
           if (maxTime > 0) out.insert(id, maxTime);
       }
       return out;
   }
   ```

3. **Implement `refreshLastTouchDatesIfStale`.** Adjacent to
   `refreshShippedDatesIfStale` (around `:2067`). Mirror the
   cited function's **millisecond** precision (`toMSecsSinceEpoch`)
   so both caches read mtime the same way — diverging would
   silently change repeat-render behaviour on sub-second mtime
   bumps.

   ```cpp
   void RoadmapDialog::refreshLastTouchDatesIfStale() {
       if (m_roadmapPath.isEmpty()) return;
       const qint64 mtime = QFileInfo(m_roadmapPath).lastModified()
                                .toMSecsSinceEpoch();
       if (mtime == m_lastTouchDatesMtime
           && !m_lastTouchDates.isEmpty()) return;
       m_lastTouchDates = parseLastTouchDates(m_roadmapPath);
       m_lastTouchDatesMtime = mtime;
   }
   ```

   **Synchronous cost:** ~175 ms blocking on first dialog open
   per session. The existing `refreshShippedDatesIfStale` is also
   sync-blocking with much smaller cost (~10 ms — bounded I/O on
   CHANGELOG.md). § 8.2 covers the threading move if/when ROADMAP
   growth makes 175 ms perceptible.

   **Blame-vs-read race (accepted).** `parseLastTouchDates` reads
   ROADMAP.md twice: once via `git blame` (which blames the
   working-tree copy) and once via `QFile::readAll()` for the
   markdown walk. If the file is edited between the two reads
   (a sub-millisecond window in practice), line numbers in
   `lineAuthorTime` (indexed by blame's "final-line" number)
   may not align with line numbers in `mdLines`. The mtime cache
   invalidates on the next refresh, so a stale render lasts at
   most one filter toggle. Accepted as a single-user-editing
   tradeoff; tighten only if reports of mis-attributed dates
   appear in practice.

test was added — see `CMakeLists.txt:849-866` `test_dialogs`
SOURCES list).

The renderer-layer tests use the static `renderCardsHtml` with a
synthetic `lastTouchDates` hash — no dialog instance, no git. The
parser-layer tests for INV-5 / INV-6 / INV-7 / INV-8 use a
`QTemporaryDir` with `git init` + a hand-crafted markdown,
exercised via the public static `parseLastTouchDates`.

**Git availability gate:** the parser-layer tests early-skip with
a `qWarning` and `GTEST_SKIP()` if
`QStandardPaths::findExecutable("git").isEmpty()`. On a minimal
CI image without `git`, the renderer-layer tests still run and
INV-1..INV-4 stay locked.

1. **INV-1 — `🚧` card renders "Updated …".** Render a markdown
   fixture with `- 🚧 [ANTS-9999]`. `opts.lastTouchDates[ANTS-9999]
   = now - 3*86400`. Assert the rendered HTML contains
   `· Updated 3d ago` inside a `<span class="rm-date">` (substring
   match on the literal `>· Updated 3d ago<`).
2. **INV-2 — `✅` card does NOT render "Updated".** Same fixture
   with status `✅`. Same `lastTouchDates` entry. Assert the
   rendered HTML does NOT contain the literal `· Updated `
   (with the bullet separator + space — tightened from a bare
   "Updated" match so the test isn't fooled by a card whose body
   prose legitimately contains the word "Updated"). The ✅
   shipped-date span MAY be present; assertion is on the absence
   of `· Updated ` specifically.
3. **INV-3 — empty `lastTouchDates` → no span.** Same `🚧`
   fixture, but `opts.lastTouchDates` empty. Assert the rendered
   HTML does NOT contain `· Updated `.
4. **INV-4 — `humanAge` ladder + boundaries.** Direct call on the
   helper (declared at file scope outside the anonymous namespace
   so the test can forward-declare and link against it; see
   § 3.b.1). Boundary assertions pin every lower-side label:

   | Input (seconds)   | Expected output |
   |-------------------|-----------------|
   | `0`               | `today` |
   | `86399`           | `today` |
   | `86400`           | `yesterday` |
   | `2*86400`         | `2d ago` |
   | `7*86400`         | `7d ago` |
   | `13*86400`        | `13d ago` |
   | `14*86400 - 1`    | `13d ago` |
   | `14*86400`        | `2w ago` |
   | `59*86400`        | `8w ago` |
   | `60*86400 - 1`    | `8w ago` |
   | `60*86400`        | `2mo ago` |
   | `364*86400`       | `12mo ago` |
   | `365*86400 - 1`   | `12mo ago` |
   | `365*86400`       | `1y ago` |

   Each row gets a discrete assertion. The day-vs-week regime

5. **INV-5 — mtime cache.** Construct a `RoadmapDialog` against a

   touching the file. Assert `lastTouchDatesMtime()` returns the
   same value and the dialog's internal hash size is unchanged.
   Touch the file with `utime` to bump mtime; call once more,
   assert `lastTouchDatesMtime()` strictly increased.
6. **INV-6 — non-git directory → empty hash.** Call
   `parseLastTouchDates` on a path in a `QTemporaryDir` with no
   `.git`. Assert the returned hash is empty. No git PATH

   even on a host without git installed `QProcess::start` fails
   to start and the function returns empty — covered by the

7. **INV-7 + INV-8 — bullet-block MAX, audit-trail exclusion.**
   Set up a `QTemporaryDir`, `git init`, configure
   `user.name="test" user.email="test@example.com"`. Author a
   roadmap with two bullets:
   - `- 🚧 [ANTS-9999]` line + 3 continuation lines (the bullet
     block).
   - A separate `- ✅ [ANTS-9998]` bullet later in the file with
     `[ANTS-9999]` mentioned in its body's audit-trail line.

   Make **two distinct commits** (not `--amend`) with pinned
   timestamps via `GIT_AUTHOR_DATE` + `GIT_COMMITTER_DATE`
   environment variables. Concrete invocation:

   ```sh
   GIT_AUTHOR_DATE="2026-01-01T00:00:00Z" \
   GIT_COMMITTER_DATE="2026-01-01T00:00:00Z" \
       git commit -m "add 9999"
   # yields author-time = 1767225600 == T_A
   # (verify: `date -u -d "2026-01-01T00:00:00Z" +%s` → 1767225600)

   GIT_AUTHOR_DATE="2026-02-01T00:00:00Z" \
   GIT_COMMITTER_DATE="2026-02-01T00:00:00Z" \
       git commit -m "add 9998 audit-trail"
   # yields author-time = 1769904000 == T_B
   ```

   - Commit 1: write the file with the ANTS-9999 bullet only.
     Timestamp T_A.
   - Commit 2: edit the file to add the ANTS-9998 bullet + its
     audit-trail line.

   Run `parseLastTouchDates`. Compute the expected epoch in C++
   with `QDateTime::fromString(QStringLiteral("2026-01-01T00:00:00Z"),
   Qt::ISODate).toSecsSinceEpoch()` (== 1767225600). Assert
   `out["ANTS-9999"] == 1767225600` (T_A, NOT T_B). The
   ANTS-9999 bullet block's lines are blamed to commit 1, while
   the audit-trail mention's line is blamed to commit 2 — MAX
   over the block yields T_A, locking both INV-7 (block-only)
   and INV-8 (no audit-trail contribution).

## 6. Memory budget

**Persistent state added per dialog instance:**

- `m_lastTouchDates: QHash<QString, qint64>` — one entry per 🚧
  bullet. Key: `"ANTS-NNNN"` ≈ 30 bytes (QString small-string-
  optimised header + 9-char body). Value: 8 bytes (qint64). Hash
  bucket overhead: ~32 bytes. Total ≈ 70 bytes per 🚧 bullet.
- `m_lastTouchDatesMtime: qint64` — 8 bytes flat.

**Worst-case scaling.** Realistic 5-15 🚧 bullets → ~1 KiB.
Stress-test 500 bullets (well past any realistic project) →
35 KiB. Negligible.

**Transient cost per `parseLastTouchDates` call:**

- One `QProcess` (git blame) — RSS bounded by git's own resident
  set, ~3-10 MiB, released when `QProcess` is destroyed at end
  of function.
- `QByteArray blameOut` — verified at ~4.2 MB total on the
  current ROADMAP (`git blame --line-porcelain ROADMAP.md | wc -c
  = 4_220_024`; 113_238 porcelain lines × ~37 bytes/line average).
  Freed at function return; peak transient ~4 MB for ~175 ms
  during the parse. Invisible on any modern host. Stress-test
  scaling (50K-line ROADMAP) projects to ~25 MB transient —
  still fine.
- `QVector<qint64> lineAuthorTime` — 8 bytes × 8723 lines = ~70 KiB.
  Released at function return.

**Total persistent footprint:** ~1 KiB per dialog instance at
realistic 🚧 counts.
**Total transient peak:** ~4 MB for ~175 ms once per ROADMAP.md
mtime change.

## 8. Re-open conditions

1. **Squash-merge confusion.** If users report "this bullet says
   updated yesterday but the actual work was weeks ago", that's a
   squash merge moving the author-time to the merge date.
   Mitigation: switch to `--first-parent` blame walking, or
   document the convention in `docs/standards/roadmap-format.md`.
2. **Perf on much larger ROADMAP.md.** If the file grows to 50K
   lines (~5 s blame on the same hardware), move the
   `parseLastTouchDates` call to a worker thread via
   `QtConcurrent::run` + a signal back to the dialog. First-render
   shows no "Updated" line; refresh in place on completion.
3. **"Started" semantic requested.** A separate ROADMAP entry
   would land "Started 47d ago" (immutable from first 🚧 flip).
   Would need a deeper git-log walker (see § 2.b rejection).
4. **Stall-color highlight.** A future entry could colour the
   `rm-date` span red when age > 30d. CSS-only change; defer until
   the "Updated" line proves load-bearing.
5. **Locale / pluralisation.** The `1d ago` / `2d ago` shorthand
   is locale-fragile (no plural form for `d`/`w`/`mo`/`y`). If
   translations expose this, switch to Qt's `tr("%n day(s) ago",
   "", n)` plural-form syntax.
6. **Multi-paragraph card bodies.** If a future bullet gains
   blank-line paragraph breaks within its body, the walker
   terminates at the first blank line and MAX loses later
   paragraphs. Re-open by either tightening the format spec
   (`docs/standards/roadmap-format.md` § 3.5) to forbid internal
   blank lines, or by loosening the walker to continue across
   blank lines that are followed by 2-space-indented prose.

## 9. Out of scope

The ROADMAP bullet at L8679 implies the bare semantic. This spec
deliberately defers:

- **"Started X days ago"** — immutable date of first 🚧 flip.
  Requires git-log walking per bullet, not blame; see § 2.b.
- **Tooltip with commit hash / author.** Hover the date span to
  see who touched it and when in full. Defer; the inline
  shorthand is enough signal for v1.
- **Stall colour-highlight** (red after 30d, etc.). CSS-only,
  separable feature.
- **Click-through to `git log -- ROADMAP.md`** opens a viewer of
  the commit history filtered to that bullet. Useful, but
  cross-cuts the dialog → terminal coordination story; defer.
- **Cross-section "stalled" rollup** ("3 bullets stalled > 30d
  under 🎨 UX"). Useful management-view; defer until the inline
  signal lands.

If any of these become priority, file a follow-on ROADMAP entry
(suggested IDs ANTS-1247 / 1248 / 1249).
