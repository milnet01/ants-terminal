# ANTS-1635 — test_audit_fold_in narrative_mode

**Status:** shipped 2026-05-19 (pull 29 + pull 30 — combined commit)
**Kind:** enhancement
**Source:** cross-session report 2026-05-18 (Music Production
`/test-audit` second sweep, Issue #3)
**Composes with:** [[ANTS-1615]] (empty `**.**` bullets — same root
class), [[ANTS-1634]] (cold_eyes_brief loop-2 ergonomics — sibling
MCP fold-in tool), [[ANTS-1581]] (skill wiring — narrative-vs-
structured choice becomes per-call once /audit /cold-eyes /
indie-review /test-audit skills call fold_in natively)

## 1. Problem

`test_audit_fold_in`'s contract is shaped for per-finding fold-in:

```json
{
  "actionable": [
    {"file": "...", "line": N, "severity": "...",
     "dimension": "...", "headline": "...", "fix": "..."},
    ...
  ],
  "framework": "...",
  "files_scanned": N,
  "dimensions": [...],
  "raw_findings": N
}
```

The engine renders one `- 📋 [ANTS-NNNN] **<headline>.**` bullet per
entry under a `### 🧪 Test Audit YYYY-MM-DD` section heading, and
allocates one new roadmap ID per actionable item.

This shape is right for machine-driven audits. It's wrong for the
common human workflow:

> *"I ran /test-audit, triaged 32 findings myself, and now I want to
> fold in one narrative ROADMAP subsection grouped by **Closed
> inline (X) / Deferred (Y) / False-positives (Z)** with paragraph
> prose. Coercing 32 records through `actionable[]` produces 32
> bullets the reviewer doesn't want, allocates 32 IDs that get
> immediately wasted, and loses the per-group framing."*

Music Production /test-audit second sweep (2026-05-18) hit this
exactly. Workaround: hand-wrote the markdown subsection rather than
calling the MCP verb at all. The /test-audit skill's discoverability
took the loss.

Same friction class affects `cold_eyes_fold_in` and
`indie_review_fold_in`. This spec scopes the fix to
`test_audit_fold_in`; the other two carry as follow-ups (see § 5).

## 2. Fix

### 2.1 Schema

Two new optional fields on the `test_audit_fold_in` MCP descriptor:

```jsonc
"narrative_mode": { "type": "boolean" },
"narrative_md":   { "type": "string"  }
```

`actionable` is dropped from the schema's `required` array — the
engine still refuses with `missing_field` when both
`narrative_mode==false` AND `actionable[]` is empty, so the
backward-compat contract is preserved at the handler. Only
`caller_cwd` remains in `required`.

### 2.2 Engine path (testauditengine.cpp)

`TestAuditEngine::FoldInRequest` gains two fields:

```c++
bool    narrativeMode = false;
QString narrativeMd;
```

`TestAuditEngine::foldIn` short-circuits when `narrativeMode`:

1. Refuse with `narrative_md_required` if `narrativeMd.trimmed()` is
   empty (loud + dedicated code so orchestrators distinguish "forgot
   the body" from "forgot the actionable list").
2. Emit the same `### 🧪 Test Audit YYYY-MM-DD` heading as
   structured mode.
3. Omit the structured-mode metadata line
   (`Framework: … · Files scanned: …`) — the narrative carries its
   own framing.
4. Insert `narrativeMd` verbatim under the heading.
5. Call `RoadmapFoldIn::insertBlock(canon, releaseHeading, block)`.
6. Skip ID allocation entirely — no `.roadmap-counter` touch.
7. Return `writtenCount=0` (engine can't count caller bullets), no
   `allocatedIds`, `releaseBlockHeading` echoed.

`missing_field` (the non-narrative empty-actionable error) now names
the narrative escape hatch in its message so callers discover it:

> `"test_audit_fold_in: actionable[] is required (or pass
> narrative_mode=true + narrative_md=\"…\" — ANTS-1635)"`

### 2.3 Provider lambda (mainwindow.cpp)

Two more `args.value()` lookups before calling `foldIn`:

```c++
req.narrativeMode = args.value("narrative_mode").toBool();
req.narrativeMd   = args.value("narrative_md").toString();
```

## 3. Invariants

- **INV-1** (verbatim insert). `narrative_mode=true` + non-empty
  `narrative_md` emits the section heading followed by the
  caller-supplied markdown verbatim. No per-finding bullet shape
  (`- 📋 [ANTS-...]`); no structured-mode metadata line; no
  allocated IDs in the response.
- **INV-2** (empty body refuses). `narrative_mode=true` with empty
  or whitespace-only `narrative_md` returns
  `{ok:false, code:"narrative_md_required"}`.
- **INV-3** (back-compat). `narrative_mode=false` (or absent) with
  empty `actionable[]` still returns `{ok:false, code:"missing_field"}`.
  The error string names `narrative_mode` so callers discover the
  escape hatch from the refusal alone.
- **INV-4** (insert site). Narrative mode writes through the same
  `RoadmapFoldIn::insertBlock` path as structured mode — same
  release-heading resolution, same atomic-write guarantees.
- **INV-5** (counter untouched). Narrative mode does not touch
  `.roadmap-counter` — the byte content is identical before / after.

## 5. Out of scope

- **`cold_eyes_fold_in` / `indie_review_fold_in` narrative mode.**
  Same shape gap, tracked as separate follow-up bullets so each
  engine's render path can be reasoned about independently. The
  schema + handler pattern in this spec is the template for the
  follow-ups.
- **Mode-conflict refusal.** Passing BOTH `narrative_mode=true`
  AND a non-empty `actionable[]` currently silently ignores
  `actionable[]` (narrative wins). The engine could refuse with
  `mode_conflict` to surface the orchestrator bug, but in the
  observed misuse pattern callers either set narrative_mode XOR
  pass actionable, not both. Defer to a follow-up if reports
  surface the confusion.
- **Caller-supplied section heading.** Today the heading is fixed
  at `### 🧪 Test Audit YYYY-MM-DD`. Custom headings would help
  callers writing project-specific labels but break the existing
  release-block heuristics that find the test-audit block by name.
  Out of scope; defer.

## 6. RAM / build budget

- Engine: one short-circuit branch (~30 LOC) before the existing
  structured-mode path. No new state, no new helpers.
- Schema: two extra `QJsonObject` declarations.
- Handler: two extra `args.value()` lookups.
- Tests: ~120 LOC, four new TEST blocks in an existing GUI-bundled
  fixture (no new build target).
