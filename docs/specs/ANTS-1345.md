# ANTS-1345 — cold-eyes `derivePartition` mtime tiebreak

## Problem

`src/coldeyesengine.cpp` previously sorted `mtimes` (a list of
`(lastModifiedMs, relPath)` pairs from `listSpecLaneCandidates`)
purely by `lastModified` descending:

```cpp
std::sort(mtimes.begin(), mtimes.end(),
          [](const auto &a, const auto &b) { return a.first > b.first; });
```

Entries with the same `lastModified` retain their original
filesystem-enumeration order, which depends on directory iteration
order — non-deterministic across runs, OS upgrades, or `git
checkout` re-touches.

Concrete failure: `touch docs/specs/ANTS-1234.md` rearranges the
top-`kMaxSpecLanes` (12) cut, even when the touched file's mtime
matches another within the same second. A future CI workflow that
runs `touch` (e.g. to bust caches) would deterministically rearrange
the partition.

Source: indie-review-2026-05-14 lane-5 ME-5.

## Fix

Bucket `lastModified` into 1-second windows and tiebreak inside a
bucket on path-lexicographic ascending order:

```cpp
std::sort(mtimes.begin(), mtimes.end(),
          [](const auto &a, const auto &b) {
              const qint64 aBucket = a.first / 1000;
              const qint64 bBucket = b.first / 1000;
              if (aBucket != bBucket) return aBucket > bBucket;
              return a.second < b.second;
          });
```

Why bucketing rather than a tolerance window: a `|a − b| ≤ 1000`
predicate is not transitive (a∼b, b∼c does not imply a∼c when the
chain spans > 1000 ms), so `std::sort` invokes UB when the
comparator drifts between equivalence and inequality across triples.
Bucketing is total and transitive — same 1 s bucket ⇒ equivalent,
different bucket ⇒ strictly ordered.

## Invariants

The post-truncation presentation order is path-lex ascending — this
fix doesn't change that. It tightens the *selection cutoff* so the
`mtimes.mid(0, kMaxSpecLanes)` slice is deterministic when there are
more candidates than the cap allows.

- **INV-1** Same-bucket cluster + truncation cutoff: the kept set is
  the lex-smallest names; lex-largest surplus is dropped.
- **INV-2** Mixed buckets + truncation cutoff: newer-bucket files
  always survive; the older-bucket cut drops the lex-largest names.
- **INV-3** Same fixture, repeated calls → byte-identical partition
  (idempotency).

## Tests

`tests/features/cold_eyes_partition_deterministic/`:

- Materialise a tmp project with N synthetic specs under
  `docs/specs/`, set explicit mtimes via `QFile::setFileTime`, call
  `ColdEyesEngine::derivePartition` twice, assert the two runs
  produce byte-identical lane orderings.
- Pre-fix on the same fixture: the order depends on directory
  enumeration; the fix locks it.

## Out of scope

- `listSpecLaneCandidates`' active-spec filter (`activeAntsIds`) is
  unchanged. Determinism applies after the filter has run.
- The bucket width (1000 ms) is a heuristic — finer buckets would
  treat sub-second filesystem mtime resolution as significant.
  Future tuning would require evidence that within-second edits
  carry real signal, which they typically do not.
