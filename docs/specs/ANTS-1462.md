# ANTS-1462 — `roadmap_query` header-inventory fallback for non-bullet roadmaps

**Status:** in flight (Bundle E follow-up, 2026-05-17).
**Kind:** enhancement.
**Lanes:** `remotecontrol` (cmdRoadmapQuery, both bullets-mode +
section_index-mode emission paths).
**Source:** cross-session-report-2026-05-17 (RetroArch CC instance,
second batch — also Vestige and any project that ships a
markdown-table or section-only roadmap).

## Problem

After ANTS-1459's path-widening, `roadmap_query` finds
`docs/private/ROADMAP.md` on RetroArch. But the file still
refuses with `code:"unrecognised_format"` because RetroArch's
roadmap uses a markdown-table-plus-sections shape (✅/📋/🚧/🔄
markers in a bundle progress table + ## headings) rather than
the GFM-task-list or Ants-v1 emoji-bullet formats the parser
recognises. Same shape as the silent-empty failure mode that
ANTS-1429 already fixed for the parser-engages-but-emits-zero
case; this is a level further out — the parser doesn't engage
at all.

The refusal surfaces ANTS-1429's typed envelope (`path`,
`bytes`, `hint`), which is helpful for diagnostics but
unhelpful for the *primary use case*: the caller wanted to
know what's in the roadmap. A section-headline inventory is
still actionable data — slugs are usable as section anchors
for downstream tools (e.g. roadmap_log refusals could quote
which heading to insert under), and a caller can fall back
to `Read` against the file with confidence that the data
exists.

## Fix

Add a header-inventory fallback to `cmdRoadmapQuery`. When the
existing `unrecognised_format` gate fires (parser yielded zero
bullets) BUT `RoadmapIndex::buildIndex` finds at least one
`##`/`###` heading, fall through to a header-only emission
instead of the typed-error envelope:

```json
{
  "ok": true,
  "mode": "header_inventory_fallback",
  "sections": [
    {"slug": "bundle-progress", "headline": "Bundle progress",
     "level": 2},
    {"slug": "audit-2026-04",   "headline": "Audit 2026-04",
     "level": 3},
    ...
  ],
  "path": "/abs/path/ROADMAP.md",
  "bytes": 12345,
  "count": 17,
  "hint": "no GFM/Ants-v1 bullets parsed; section inventory
           emitted instead — use Read for the full markdown."
}
```

Slug derivation matches the bullet-mode convention
(`RoadmapIndex::buildIndex` → headline→slug mapping with
kebab-case + duplicate disambiguation). Total inventory is
capped at **200 headings** (defensive ceiling — no relation to
pagination defaults, just a sanity bound for a malformed file
with thousands of headings); past the cap, drop the tail and
emit `truncated:true`.

If the file has zero bullets AND zero headings, the existing
`unrecognised_format` refusal still fires (truly opaque content;
nothing actionable to return).

**Sites (anchor for grep):**
- `cmdRoadmapQuery` section_index mode at `remotecontrol.cpp:~1413-1430`.
- `cmdRoadmapQuery` bullets mode at `remotecontrol.cpp:~1664-1687`.

Section_index mode already calls `RoadmapIndex::buildIndex`
upstream of the gate (`:1410`) so the fallback reuses
`m_roadmapIndex` cheaply. Bullets mode does NOT call buildIndex
upstream — so the fallback path in bullets mode performs a
**lazy `buildIndex` call** on first hit (the result is dropped
since we don't need to populate `m_roadmapIndex` for the
non-section_index emission convention; per-call cost is
acceptable for the refusal-only path). Both modes converge on
the same `mode:"header_inventory_fallback"` envelope shape so
callers can branch on a single field.

**Backwards compat:** existing callers that branch on
`code:"unrecognised_format"` for header-only files now see
`ok:true, mode:"header_inventory_fallback"` instead. This is
the intended discoverability win — opaque-file refusal is
preserved for the truly-empty case. The `hint` field telegraphs
the change. No callers in the Ants Terminal codebase rely on
the prior refusal for header-only files (verified by grep on
`unrecognised_format` callers).

## Invariants

- **HI-1.** `cmdRoadmapQuery`'s bullets-mode fallback calls
  `RoadmapIndex::buildIndex(markdown)` on first hit (refusal-
  path lazy call); section_index mode reuses the upstream
  `m_roadmapIndex` already populated at line ~1410.
- **HI-2.** Header-inventory fallback fires when the bullet
  parser yields zero entries AND the resulting index has at
  least one section. Otherwise the existing ANTS-1429
  `unrecognised_format` refusal fires.
- **HI-3.** The envelope carries `mode:"header_inventory_fallback"`.
  Slugs are kebab-case; duplicate headlines disambiguate with
  `-2`, `-3`, … (same convention as bullet-mode section_index).
- **HI-4.** Inventory is capped at 200 entries; overflow drops
  the tail and the envelope carries `truncated:true`.
- **HI-5.** Zero bullets + zero headings → existing
  `unrecognised_format` refusal (ANTS-1429 behaviour preserved
  for genuinely opaque files).
- **HI-6.** Only `##` (level 2) and `###` (level 3) headings
  contribute to the inventory — matches the bullet-mode
  section_index emitter and `RoadmapIndex::buildIndex`
  convention. Deeper headings (`####`/`#####`) are skipped.

## Out of scope

- Re-rendering the roadmap into bullet form (a converter).
- Walking nested `####` / deeper headings (cap at `##` and `###`
  matches the existing slug-emitter convention).
- Emitting partial bullet shapes when *some* bullets parse but
  the file also has tables — the existing ANTS-1429 gate
  predicate is "bullets is empty" (binary), and ANTS-1462
  keeps that binary semantics. A mixed-mode emit would need
  its own design.
- ANTS-1463 (roadmap_log refusal envelope improvements) —
  separate item; the two land in the same commit but are
  scoped independently.
