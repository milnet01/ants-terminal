# ANTS-1319 — `/cold-eyes` MCP fold-in

**Status:** 📋 → 🚧 (this spec)
**Kind:** implement
**Source:** roadmap (mirror to ANTS-1112 / ANTS-1113 fold-in pattern)
**Date:** 2026-05-14

## 1. Problem

`superpowers:cold-eyes` (`~/.claude/skills/cold-eyes/SKILL.md`, 142 lines)
drives Claude through a 6-phase doc-review loop: discover docs, partition
into lanes, dispatch N parallel reviewer-subagents, verify each finding
against current files, fix verified findings, loop until clean, fold the
trail into ROADMAP.

The skill markdown alone is 142 lines. The actual orchestration also has
Claude **load the entire doc trail through the parent context** every
pass: `CLAUDE.md` (~700 lines), `ROADMAP.md` (~9 K lines), per-spec
`docs/specs/*.md` (~50 files), `docs/standards/*.md`, `docs/decisions/*.md`,
contract docs (`README.md`, `PLUGINS.md`, `CHANGELOG.md`). Per pass.

Mechanical pieces that don't need Claude's judgment:

- **Discovery** — regex/glob over `*.md`/`*.rst`/`*.txt` in scope dirs.
- **Lane partition** — directory-based heuristic; one spec per lane,
  contract-trio as cross-cutting lane, standards/decisions as bundle
  lanes.
- **Brief assembly** — per-lane manifest (paths, not bodies) mirroring
  the ANTS-1281 shape — the subagent reads the doc files itself.
- **Cross-doc claim aggregation** — disk-based, mirroring the
  ANTS-1282 shape (`reports_dir` parameter; truncate each report at
  64 KiB; corroborate by `(file, line)` cited across ≥ minLanes lanes).
- **Fold-in markdown render** — `### 📝 Cold-eyes <YYYY-MM-DD>`
  subsection per skill spec § Phase 6, using the existing
  `RoadmapFoldIn::allocateIds` (flock + QSaveFile) and
  `RoadmapFoldIn::insertBlock` atomic insert.

Per the ANTS-1289/1290 displacement criterion: a skill phase whose core
loop is "run X, parse Y, return Z" is movable. These five phases all
qualify. The judgment phases (per-finding verify; fix-vs-don't-fix
decisions; loop-vs-stop convergence; synthesis prose) stay Claude-side.

Expected token savings per `/cold-eyes` run: **~50–100 K orchestrator
tokens** (the parent currently shoulders the full doc-trail load across
N agent dispatches; under fold-in it shoulders only tool args + compact
results).

#### 2.1.2 `cold_eyes_brief`

**Returns:**

```json
{

  "lane": "spec/ANTS-1287",
  "brief": "<header + Read-each-doc instruction sentinel + cross-ref hints>",
  "doc_paths": ["docs/specs/ANTS-1287.md"],
  "cross_reference_docs": ["CLAUDE.md", "ROADMAP.md",
                           "docs/standards/coding.md"],
  "cited_code_paths": ["src/roadmapindex.h", "src/roadmapindex.cpp"],
  "review_dimensions": ["dedup","accuracy","cross-ref","consistency",
                        "completeness","clarity","conflicts","currency",
                        "perf-discipline","quality-discipline",
                        "token-efficiency","structure","examples",
                        "audience","testability"],
  "byte_count": 1842
```

#### 2.1.3 `cold_eyes_cross_doc_diff`

**Args:** `reports_dir` (string, required, project-relative path under
`<project>/.cold-eyes/reports-loop-N/` by convention). Optional
`min_lanes` (default 2). Mirrors `indie_review_corroborate` with the
disk-input path (ANTS-1282 INV-1 contract — no inline-reports
alternative for cold-eyes v1; the whole point is to avoid the
parent-context pile-up).

**Returns:**

```json
{
  "ok": true,
  "findings": [
    {"file": "docs/specs/ANTS-1281.md", "line": 42,
     "citing_lanes": ["contracts", "spec/ANTS-1281"],
     "contexts": ["…claim text ±40 chars…", "…second context…"]}
  ],
  "reports_read": 7,
  "total_findings": 14,
  "reports_dir": ".cold-eyes/reports-loop-1"
}
```

#### 2.1.4 `cold_eyes_fold_in`

**Args:** `actionable` (array, required — each entry
`{file, line, citing_lanes}`). Optional `date_iso` (ISO date string,
default = today), `release_block_heading` (string, default = auto via
`RoadmapFoldIn::findActiveReleaseHeading`).

**Returns:**

```json
{
  "ok": true,
  "block": "### 📝 Cold-eyes 2026-05-14\n\n- 📋 [ANTS-NNNN] …",
  "allocated_ids": [1335, 1336, 1337],
  "written": true,
  "release_block_heading": "## 0.7.92 (target: 2026-W21)"
}
```

`written:false` + present `block` is the dry-run path: the heading
wasn't recognised; Claude can hand-place the block.

### 2.2 New engine module — `src/coldeyesengine.{h,cpp}`

Pure-function library, `Qt6::Core` only (mirrors `IndieReviewEngine`).
Added to `ants_core_lib` so the new tests can link without
`Qt6::Widgets`.

Surface (header excerpt; full body in implementation):

```cpp
namespace ColdEyesEngine {

struct Lane {
    QString     name;
    QString     summary;
    QStringList docPaths;            // project-relative
};

struct BriefManifest {
    QString     brief;               // header + Read-each-doc instruction
    QStringList docPaths;            // INV-3: == lane.docPaths
    QStringList crossReferenceDocs;  // INV-4 fixed list
    QStringList citedCodePaths;      // extracted via regex from doc bodies
};

enum class Scope { Default, DocsOnly, ContractsOnly };

QList<Lane>     derivePartition(const QString &projectPath, Scope scope = Scope::Default);
BriefManifest   assembleBriefManifest(const QString &projectPath, const Lane &lane);
QStringList     extractCitedCodePaths(const QString &projectPath, const QStringList &docPaths);

// Cross-doc-diff (mirrors IndieReviewEngine::corroboratedFindingsFromDir).
QList<IndieReviewEngine::CorroboratedFinding>
                crossDocDiffFromDir(const QString &projectPath,
                                    const QString &reportsDirRelative,
                                    int minLanes = 2,
                                    int *reportsRead = nullptr);

QString         templateColdEyesFoldInBlock(
                    const QList<IndieReviewEngine::CorroboratedFinding> &actionable,
                    const QList<int> &allocatedIds,
                    const QString &dateIso);

}  // namespace ColdEyesEngine
```

`crossDocDiffFromDir` and the `CorroboratedFinding` type are intentionally
shared with `IndieReviewEngine`: same algorithm, same regex, same 64 KiB
truncate, same `(file, -1) != (file, 42)` keying. Re-using the type
avoids a parallel `ColdEyesEngine::CorroboratedFinding` that would force
the cross-doc-diff MCP and the indie-review-corroborate MCP to diverge
later if either side adds a field.

## 3. Invariants

- **INV-1: discovery scope is bounded.** `derivePartition` walks
  `<root>`, `<root>/docs/`, with maxdepth 3. Excludes
  `_archive/`, `build*/`, `tests/audit_fixtures/`, `node_modules/`,
  `.git/`. Matches `*.md`/`*.rst`/`*.txt`.
- **INV-2: spec-lane cap = 12.** If the active-spec set exceeds 12,
  return the 12 most-recently-modified by mtime and a `truncated:true`
  field plus `scoped_count` reflecting the cap-hit. Keeps fan-out
  tractable per `/cold-eyes` skill § Budget.
- **INV-3: brief manifest is paths-only.** `brief` body never inlines
  doc bodies — mirrors ANTS-1281 INV-5. Saves N×~5 K-token inlining
  cost per lane dispatch.
- **INV-4: cross-reference docs are the fixed contract trio.**
  Authored order: `CLAUDE.md`, `README.md`, `ROADMAP.md`,
  `CHANGELOG.md`. Always emitted even if the per-lane scope already
  contains them — they're always-cross-referenced for drift detection.
  De-duped only against the lane's own `docPaths`.
- **INV-5: `cold_eyes_cross_doc_diff` mirrors ANTS-1282 exactly.**
  Same disk-read path, same `kMaxScanBytes` (64 KiB), same
  `(file, line)` keying, same `min_lanes` default = 2, same
  `reports_read` accounting. Re-uses
  `IndieReviewEngine::corroboratedFindingsFromDir` under the hood; the
  cold-eyes wrapper exists only to provide a topical entry-point in
  the MCP namespace (per ANTS-1296 future namespacing).
- **INV-6: fold-in uses `RoadmapFoldIn::allocateIds` + `insertBlock`.**
  Same atomic guarantees as indie-review fold-in: `flock(LOCK_EX|LOCK_NB)`
  on `.roadmap-counter`, `QSaveFile` for the counter write, atomic-rename
  insert on `ROADMAP.md`. `kill -9` between read and write leaves both
  files intact.
- **INV-7: heading is `### 📝 Cold-eyes <YYYY-MM-DD>`.** Matches the
  skill spec § Phase 6 verbatim (the emoji marker; the date format).
  Theme line: `Docs reviewed: <N>. Loops to clean: <L>. Findings
  fixed: <F>.` — but those counts are Claude-side judgment; the
  engine emits the heading + bullets only and the caller may prepend
  the theme line in `actionable[0]` if desired (out of v1 scope —
  see § 9).
- **INV-8: error codes mirror indie-review verbatim.** `no_window`,
  `no_project`, `bad_args`, `not_found`, `counter_failed`. Adds one
  cold-eyes-specific code: `bad_scope` for invalid `scope` arg.
- **INV-9: provider lambdas forward all args via `req[…]`.** No silent
  drops, no hard-coded defaults. The schema declares optional fields
  with explicit defaults; the engine applies them.
- **INV-10: schema required-array parity with indie-review.**
  `cold_eyes_partition` (scope optional) emits no `required` array;
  `cold_eyes_brief` requires `["lane"]`, `cold_eyes_cross_doc_diff`
  requires `["reports_dir"]`, `cold_eyes_fold_in` requires
  `["actionable"]` — matches indie-review's per-tool pattern.
- **INV-11: unknown-lane echo sanitised.** `bad_args` / `not_found`
  responses that echo the user-supplied lane name MUST cap at 64
  bytes and substitute `< 0x20 → '?'` per the ANTS-1287 INV-11
  hygiene pattern. Same regex/treatment as `cmdRoadmapQuery`'s
  `verbatim.truncate(64)` block.
- **INV-12: mtime-cached discovery (5 s TTL).** Repeat `partition` or
  `brief` calls within 5 s reuse the cached lane list. Single-call
  dispatch (Phase 2's parallel batch hits partition once + N briefs
  in sequence) benefits — N+1 queries → 1 stat, N+1 lookups.
- **INV-13: path-rule defence.** `derivePartition` /
  `extractCitedCodePaths` reject any path whose canonical form
  escapes `<projectPath>`. Same `QFileInfo::canonicalFilePath` +
  `startsWith` check as
  `IndieReviewEngine::corroboratedFindingsFromDir`.

## 4. Failure modes

| Mode | Code | Treatment |
|---|---|---|
| No focused project | `no_project` | Per indie-review precedent |
| No MainWindow (test) | `no_window` | Per indie-review precedent |
| Lane name empty | `bad_args` | "lane required" |
| Lane name not in partition | `not_found` | "no such lane" + sanitised echo (INV-11) |
| `reports_dir` empty / absolute / escapes project | `bad_args` | Matches `indie_review_corroborate` wording |
| `actionable[]` empty after filter | `bad_args` | Matches `indie_review_fold_in` |
| `.roadmap-counter` flock fails (5 s budget) | `counter_failed` | Per indie-review fold-in |
| `release_block_heading` not found in ROADMAP | `ok:true, written:false` | Block emitted for hand-placement |
| `.cold-eyes/partition.json` malformed | falls back to heuristic | No error; `path` echo reports `"<default>"` |
| `scope` arg not in enum | `bad_scope` | Cold-eyes-specific |

## 5. Lane partition heuristic (v1 default)

Walk order:

1. **`contracts` lane** — `CLAUDE.md`, `README.md`, `ROADMAP.md`,
   `CHANGELOG.md` (those that exist).
2. **`standards` lane** — every `docs/standards/*.md` bundled together.
3. **`decisions` lane** — every `docs/decisions/*.md` bundled together.
4. **`plugins` lane** — `PLUGINS.md` if it exists.
5. **One lane per active spec** — every `docs/specs/ANTS-NNNN.md`
   whose corresponding ROADMAP entry status is 📋 or 🚧.
   Sort by ID ascending (deterministic); cap at 12 per INV-2.

Skipped from default scope (Claude can opt them in with `scope=docs_only`
+ explicit `partition.json`):

- `docs/journal/*.md` — retrospective, post-ship; not contract docs
- `docs/plans/*.md` — deprecated location; superseded by specs+journal
- `docs/screenshots/` — binary
- `docs/AUTOMATED_AUDIT_REPORT_*` — generated; reviewed by `/audit`
- `tests/features/*/spec.md` — covered by their spec's own lane

Status of a spec's ROADMAP entry is determined by:

- Parse ROADMAP.md once (re-use the `RoadmapIndex` engine from
  ANTS-1287 if its slug heuristic recognises ID headings; else
  fall back to a simple regex pass for `[ANTS-NNNN] **…**` +
  the preceding-line status emoji).
- The cheap fallback: regex
  `^- (📋|🚧|✅|💭)\s+\[ANTS-(\d+)\]` over ROADMAP.md, build
  `QHash<int, QChar> idToStatus`.
- Spec lanes are only emitted for IDs whose status ∈ {📋, 🚧}.

## 7. Performance / RAM

### 7.1 Build cost

Engine adds ~250 LoC across `coldeyesengine.{h,cpp}`. Linkage:
`ants_core_lib` already pulls `IndieReviewEngine`, `RoadmapFoldIn`,
and `RoadmapIndex` — cold-eyes adds zero new external deps. Each new
test bundle adds one compile unit. Conservative build-time delta:
+8–12 s on the workstation preset (within JOB_POOLS budget).

### 7.2 RAM bound

- `derivePartition` output: ≤ 16 lanes × (~64-byte name + ~120-byte
  summary + ≤ 20 paths × ~64 bytes) ≈ **24 KiB** per call.
- `BriefManifest`: ≤ 2 KiB body text + ≤ 30 paths × ~64 bytes ≈
  **4 KiB** per lane.
- Mtime cache (INV-12): single `QString path` + `qint64 mtimeMs` +
  `QList<Lane>` snapshot ≈ **24 KiB**. Bounded; one entry; cleared
  on TTL.
- Cross-doc-diff: delegates to `IndieReviewEngine`; same 64 KiB
  per-report truncate, same O(citations) RAM. No new bound.

### 7.3 Per-call overhead

- `cmdColdEyesPartition` cold path: directory walk over `docs/`
  (~50 files) + ROADMAP.md status regex pass. Order: tens of ms.
- `cmdColdEyesBrief` cold path: re-uses partition cache; per-lane
  manifest assembly is a few QString concatenations. Sub-ms.
- `cmdColdEyesCrossDocDiff`: dominated by report-file IO + regex
  cost (already characterised under ANTS-1282).
- `cmdColdEyesFoldIn`: dominated by `allocateIds` flock budget
  (≤ 5 s ceiling; typical < 10 ms).

## 8. Workflow integration

Under fold-in, the skill's Phase 1 becomes a single `cold_eyes_partition`
call; Phase 2 becomes N `cold_eyes_brief` calls (one per lane, served
from the mtime cache); Phase 3 stays Claude-side (per-finding verify
against current files); Phase 4 stays Claude-side (Edit calls); Phase 5
loop control stays Claude-side; Phase 6 fold-in becomes one
`cold_eyes_cross_doc_diff` (against `<root>/.cold-eyes/reports-loop-N/`)
plus one `cold_eyes_fold_in`.

The skill markdown can shrink to ~30 lines (orchestration script:
"call these four tools in this order, do the per-finding verify in
between"). That trim is **not in this spec's scope** — it's a follow-up
PR against `~/.claude/skills/cold-eyes/SKILL.md` once the tools are
live and proven.

## 9. Out of scope

- Per-finding verify automation. The engine emits citations; Claude
  reads the file and judges.
- Synthesis-prose generation (skill Phase 6 message 1/2). Claude
  drafts.
- Theme-line prepend on fold-in block (counts are Claude-side
  judgment). The engine emits the heading + bullets only; the
  orchestrator may inject a theme line via Edit if desired.
- Loop control. Claude decides when convergence is reached.
- Skill-markdown trim. Follow-up against the skill repo, not this
  spec.
- `cold_eyes_orchestrate` end-to-end wrapper. Roadmapped under
  ANTS-1279 / ANTS-1280 (general "orchestrate" pattern) and
  intentionally deferred — the four-tool surface is the right
  primitive for Phase 1.
