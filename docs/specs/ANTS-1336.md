# ANTS-1336 — `session_memory` `cwd` arg cross-project tenancy bypass

## Problem

`cmdSessionMemory`'s read path (`remotecontrol.cpp:3565` post-fix) used
to accept a user-supplied `cwd` argument:

```cpp
} else {
    // get/list: read-only — keep the legacy default-to-focused
    // resolution. The optional `cwd` arg still works for cross-
    // project READS, which is the legitimate "survey project B
    // from project A" use case (see ANTS-1372 spec INV-7).
    cwd = req.value(QStringLiteral("cwd")).toString();
    if (cwd.isEmpty()) cwd = resolveRootCanonical(m_main, req);
    if (cwd.isEmpty()) return ... no_project;
    cwd = QFileInfo(cwd).canonicalFilePath();
    ...
}
```

The stored payload lives at
`~/.cache/ants-terminal/mcp-state/<sha256(cwd)>.json`. The hash is the
attacker-chosen identity (no provenance check) — a Claude session in
project A can read project B's `session_memory` bucket by passing
`cwd="/path/to/B"`. ANTS-1372 closed this off for **set/delete**
(mutating ops require caller_cwd via RcGate) but explicitly preserved
the cross-project read pattern under INV-7, treating "survey project B
from project A" as a legitimate use case.

The 2026-05-14 indie review (lane-5 HI-1) reclassified the same
capability as a tenancy bypass: any session that touches Ants's MCP
socket can read any other project's session-memory bucket on the same
machine, with no audit trail and no key-by-key access control. The
storage shape (per-project, hashed at the project root) is per-tenant
data; the read path was the missing tenant check.

## Goal

Drop the `cwd` argument entirely from `session_memory`'s surface.
`caller_cwd` becomes the only project-scope source for **every** op
(get / list / set / delete), routed through the same `RcGate` the
mutating ops already use. The "survey project B from A" capability
goes away — a user who wants project B's session memory opens a
Claude session inside project B and reads from there.

## Design

### Code change

In `cmdSessionMemory(req)`, the `if (mutates)` / `else` split goes
away. RcGate applies to all ops:

```cpp
QJsonDocument RemoteControl::cmdSessionMemory(const QJsonObject &req) {
    if (!m_main) return ... no_window;

    const QString opRaw = req.value("op").toString();
    SessionMemoryEngine::Op op;
    if (!SessionMemoryEngine::parseOp(opRaw, &op)) return ... bad_op;

    // ANTS-1336 — caller_cwd is the only project-scope source for
    // every op. The pre-fix read path accepted a user-supplied `cwd`
    // arg, which let a session in project A address project B's
    // bucket. (ANTS-1372 INV-7 preserved this for reads as the
    // "survey from outside" use case; the 2026-05-14 indie review
    // reclassified the same capability as a tenancy bypass.)
    const auto gate = RcGate::checkCallerCwd(
        resolveRootCanonical(m_main), req,
        QStringLiteral("session_memory"));
    if (!gate.ok) {
        return QJsonDocument(smErr(gate.errorCode, gate.error,
                                   opRaw, QString()));
    }
    const QString cwd = gate.focused;

    // remainder unchanged: key/value validation, engine dispatch,
    // envelope shaping.
    ...
}
```

The read-path branch (`cwd = req.value("cwd")...`) and the
`no_project` envelope it raised are deleted. `cwd_missing` /
`cwd_mismatch` / `cwd_bad` are now the read-side refusal codes
(same shape RcGate already emits for writes).

### Schema change

Tool-list descriptor for `session_memory` adds `caller_cwd` to
`required` (it was schema-required already per ANTS-1372 for
mutating ops; promoting to "always required" matches the new
handler behaviour). The legacy `cwd` field stays in the schema
description as a deprecated alias with a one-release sunset
note — but the handler ignores it. Two-release window:

- **0.7.92 (this release):** schema marks `cwd` as
  `"deprecated — pass caller_cwd instead; this field is ignored"`.
  Handler ignores `cwd` and only routes via caller_cwd.
- **0.7.93:** `cwd` removed from the schema entirely.

(The handler ignoring `cwd` from the moment ANTS-1336 ships is the
security fix — keeping it in the schema description for one release
is a courtesy to legacy callers so the migration error message
points them at the new field.)

## Invariants (post-fix)

- **INV-1.** Every op (`get`, `list`, `set`, `delete`) routes through
  `RcGate::checkCallerCwd` before any disk operation. `cwd_missing`,
  `cwd_mismatch`, `cwd_bad` refusals fire before any cache file is
  read or written.

- **INV-2.** `req.value("cwd")` is no longer extracted in the
  handler. (Grep: `git grep -n 'req.value.*"cwd"' src/remotecontrol.cpp`
  returns zero hits inside `cmdSessionMemory`'s body. Other handlers
  may still read their own `cwd` fields; this is per-handler.)

- **INV-3.** `session_memory` get/list returns the same payload to a
  caller who passes `caller_cwd` matching the focused tab as the
  pre-fix path returned for a caller who passed `cwd` matching the
  focused tab. No data is lost or reshaped for compliant callers.

- **INV-4.** A `session_memory` request with `caller_cwd` absent or
  empty refuses with `cwd_missing` — for **every** op. Matches the
  ANTS-1372 mutating-op refusal shape.

- **INV-5.** A `session_memory` request whose canonical `caller_cwd`
  differs from `resolveRootCanonical(m_main)` (focused-tab project
  root) refuses with `cwd_mismatch`. Matches ANTS-1372 INV-3.

- **INV-6.** No new state. The cache directory layout is unchanged
  (`~/.cache/ants-terminal/mcp-state/<sha256(cwd)>.json`); only the
  routing into that directory is tenant-checked.

- **INV-7 (ANTS-1372 amendment).** ANTS-1372 spec § 4 INV-7 is
  amended: `session_memory` (get/list) is **no longer** in the
  read-only-unaffected set. Other read-only verbs
  (`indie_review_corroborate`, `debt_sweep_scan`,
  `cold_eyes_partition`, `cold_eyes_brief`, `cold_eyes_cross_doc_diff`,
  `roadmap_query`, `git_state`, …) remain unaffected — they read
  from filesystem locations the caller already has access to via
  the project they're surveying. `session_memory` is unique in
  reading from a hash-derived path inside Ants's own cache, which
  is what creates the cross-tenant exposure.

## Test

`tests/features/session_memory_caller_cwd_gate/`:

1. **Schema-side (source-scrape).** Modified
   `tests/features/mcp_session_memory/test_mcp_session_memory.cpp`
   REG-3 inverts: `req.value(QStringLiteral("cwd"))` MUST NOT appear
   in `cmdSessionMemory`'s body (regression-lock that the cwd arg
   stays dropped).

2. **Behaviour-side (runtime).** Tests written under a real
   `RcGate` invocation:
   - **get** with `caller_cwd` matching `resolveRootCanonical` ⇒
     `ok=true`, payload matches what a `set` from the same caller
     stored.
   - **get** with `caller_cwd` empty ⇒
     `{ok:false, code:"cwd_missing"}`.
   - **get** with `caller_cwd` mismatching focused tab ⇒
     `{ok:false, code:"cwd_mismatch"}`.
   - **list** with `caller_cwd` empty ⇒
     `{ok:false, code:"cwd_missing"}`. (List was previously the
     least-gated op; this is the highest-leverage refusal.)
   - **cross-tenant attempt** — `set` from caller_cwd=A,
     followed by `get` from caller_cwd=B (still passes the gate
     because the *focused tab* is B's root in the test fixture):
     `get` returns `{ok:true, found:false}`. The B-side store
     does NOT see A's keys; A's keys remain readable from a
     caller_cwd=A session. Locks in tenant isolation.

3. **Regression — pre-ANTS-1372 callers** — request with
   `cwd="/path/to/B"` but no `caller_cwd` ⇒
   `{ok:false, code:"cwd_missing"}`. The deprecated `cwd` field
   is ignored, not silently honoured.

Label `features;fast`. The runtime tests use `RcGate` directly
plus a stub `MainWindow::resolveRootCanonical` (the test bundle
already has the `terminal_for_caller_isolation` stubbing pattern
to follow).

## Migration

No live callers in the project tree use `session_memory`'s `cwd`
arg (`grep -rn "session_memory" .claude/ docs/ tools/`). The
`/audit` and `/release` skills do not invoke session_memory. The
risk surface for breakage is: external skill authors who built on
the ANTS-1283 surface before ANTS-1372 / ANTS-1336 landed. Such
callers see `cwd_missing` on their first request and the error
message names `caller_cwd` as the new arg — mechanical migration.

CHANGELOG `Security` entry lists the change; the deprecation note
on the `cwd` field is removed in 0.7.93.

## Out of scope

- The `caller_cwd_handling` per-tool contract enum
  (ANTS-1404 — Phase 3 work). ANTS-1336 hard-wires
  `session_memory` to cwd-required because the contract framework
  doesn't exist yet; once ANTS-1404 lands, `session_memory` would
  be declared `Contract::Required` and the per-handler RcGate call
  becomes redundant. The framework migration is in scope for
  ANTS-1404, not here.
- Removing `cwd` from the JSON-schema. Tracked for 0.7.93 — keeping
  it as `deprecated` in 0.7.92 buys one release for migration error
  messages.
- session_memory's storage shape (size cap, hash function, on-disk
  format) — all unchanged.

## RAM budget

Zero — the change deletes a code path, doesn't add one.

## Build cost

Trivial — one if/else collapse in `cmdSessionMemory`. No new TUs.
