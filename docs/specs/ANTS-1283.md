# ANTS-1283 — `session_memory` MCP key-value store

**Status:** spec draft, pre cold-eyes (2026-05-14). Loop log at end (§ 11).
**Source:** ROADMAP.md ANTS-1283 (line in `🔌 MCP ergonomics — caller polish`
block).
**Blocked by:** none — pure file I/O, no other engines required.
**Pairs with:** ANTS-1286 (audit tool-detection cache — this spec is the
persistence backend it can opt into), ANTS-1284 (`token_usage` —
distinct: that one counts dispatch bytes, this one persists arbitrary
caller-supplied state), ANTS-1289 (`verify_changes` — both write to
machine-local locations; `verify_changes` reads `.ants/verify.json`
*inside the repo*, this spec writes `~/.cache/ants-terminal/mcp-state/`
*outside the repo*).

## 1. Problem

After ANTS-1284/1287/1289/1290/1319 shipped, the MCP surface displaces
significant skill-markdown loading per session. But every Claude Code
session starts cold: previous audit timestamps, partition snapshots,
"files we already know are zombie-free", and similar cached facts get
recomputed from scratch each time.

Three concrete examples already on the roadmap:

- **ANTS-1286** wants to cache `command -v cppcheck` etc. across audit
  runs; the natural backing store is a per-machine, per-cwd file but
  every consumer rolling its own is wasteful.
- **ANTS-1289**'s "did anything change since last verify?" caching is
  explicitly deferred to this spec.
- **ANTS-1287**'s `RoadmapIndex` is in-process today; a future
  "persist the index across MCP-server restarts" optimisation pairs
  with this spec.

Today the assistant has no way to persist a small "I learned X about
this project last session" fact across MCP-server restarts. Each
session re-derives the same facts — modest per-call cost, but
multiplied across N sessions and M cached items, real token spend.

The fix is a small key-value store the MCP server backs to
`~/.cache/ants-terminal/mcp-state/<cwd-hash>.json`, addressable by a
single `session_memory` MCP tool with `op = get / set / delete / list`.
Bounded 100 KiB per cwd to keep this from drifting into a
privacy/disk-quota concern.

## 2. Surface

### 2.1 Tool signature

```
mcp__ants__session_memory
  required: op    enum "get" | "set" | "delete" | "list"
  optional: key   string, ≤ 64 chars, [A-Za-z0-9._-]+
                  required when op ∈ {get, set, delete}
  optional: value any JSON value
                  required when op == set
                  size ≤ 16 KiB after JSON-compact serialisation
  optional: cwd   string override; default = focused project root
                  (mirrors verify_changes / cold_eyes_* resolution).
```

Op semantics:

| op | reads | writes | response carries |
|---|---|---|---|
| `get`    | store     | —              | `found:bool, value?` |
| `set`    | store     | store          | `bytes_written, total_bytes` |
| `delete` | store     | store          | `found:bool` |
| `list`   | store     | —              | `keys:[{key, bytes}], total_bytes` |

### 2.2 Response shape

```json
// get (found)
{
  "ok": true, "op": "get", "key": "last_audit_ts",
  "found": true, "value": 1715789000,
  "path": "/home/me/.cache/ants-terminal/mcp-state/9f3c2a8b1d4e5f60.json"
}

// get (missing)
{"ok": true, "op": "get", "key": "last_audit_ts", "found": false, "path": "..."}

// set
{"ok": true, "op": "set", "key": "last_audit_ts",
 "bytes_written": 13, "total_bytes": 412, "path": "..."}

// delete (existed)
{"ok": true, "op": "delete", "key": "last_audit_ts", "found": true,
 "total_bytes": 399, "path": "..."}

// list (no values — see INV-5)
{"ok": true, "op": "list",
 "keys": [
   {"key": "last_audit_ts", "bytes": 13},
   {"key": "tool_detect", "bytes": 124}
 ],
 "total_bytes": 137,
 "path": "..."}

// error
{"ok": false, "op": "set", "code": "cap_exceeded",
 "error": "session_memory: store would exceed 100 KiB cap (would be 102456 bytes)"}
```

### 2.3 Error codes

| code | when |
|---|---|
| `bad_op`         | `op` missing or not in {get,set,delete,list} |
| `bad_key`        | `key` missing for get/set/delete, or fails regex `^[A-Za-z0-9._\-]{1,64}$` |
| `bad_value`      | `value` missing for set, or serialises to > 16 KiB |
| `cap_exceeded`   | post-write store would exceed 100 KiB |
| `no_project`     | cwd resolution returned empty path |
| `io_error`       | filesystem failure (mkdir / save / read) |

Every error envelope includes `echo` for any user-supplied string args,
sanitised per INV-12 (64-char cap + control-char substitution).

## 3. Engine

### 3.1 Layering

Pure-function namespace in `ants_core_lib` (Qt6::Core only):

```cpp
namespace SessionMemoryEngine {

constexpr qint64 kMaxStoreBytes = 100 * 1024;  // 100 KiB cap per cwd (INV-2)
constexpr qint64 kMaxValueBytes =  16 * 1024;  // 16 KiB per value (INV-8)
constexpr int    kMaxKeyLength  = 64;          // INV-7

enum class Op { Get, Set, Delete, List };

struct OpResult {
    bool        ok    = false;
    QString     code;            // empty when ok; otherwise see § 2.3
    QString     error;
    QString     op;              // echo of the op for the caller
    QString     key;
    bool        found = false;   // for get / delete
    QJsonValue  value;           // for get
    qint64      bytesWritten = 0;
    qint64      totalBytes  = 0;
    QJsonArray  keys;            // for list — [{key, bytes}, ...]
    QString     path;            // absolute path to the store file
};

QString cwdHash(const QString &absoluteCwd);   // SHA-256(cwd) → first 16 hex
QString defaultBaseDir();                       // ~/.cache/ants-terminal/mcp-state
QString storePathFor(const QString &cwd, const QString &baseDir = {});

bool       parseOp(const QString &raw, Op *out);
bool       isValidKey(const QString &key);
QJsonObject loadStore(const QString &path, bool *corruptOut = nullptr);
QString    saveStore(const QString &path, const QJsonObject &store);
                                                 // returns "" on success,
                                                 // error message on failure
qint64     serializedSize(const QJsonObject &store);

OpResult   execute(const QString &cwd, Op op,
                   const QString &key, const QJsonValue &value,
                   const QString &baseDirOverride = {});

}  // namespace SessionMemoryEngine
```

`execute` is the high-level entry point: it resolves the path,
load–modify–saves under the cap, and returns a complete `OpResult`.
RemoteControl + tests both call into `execute`.

### 3.2 File layout

```
~/.cache/ants-terminal/mcp-state/
├── 9f3c2a8b1d4e5f60.json    # cwd /home/me/projects/foo
├── 4a2d8e7c0f9b1320.json    # cwd /home/me/projects/bar
└── ...
```

- Directory created lazily on first `set`, mode `0700`.
- Files created with mode `0600` (matches `config.json` convention).
- File body is a single flat JSON object: `{"key1": value1, "key2": value2, ...}`.
  Values can be any JSON type (string, number, bool, object, array, null).
  Flat schema — no nesting of namespaces; callers are expected to use
  `.` / `_` in keys for grouping (e.g. `audit.last_ts`, `audit.tool_detect`).

### 3.3 Atomicity

Write path uses `QSaveFile` (temp file + `rename(2)` at `commit()`).
Concurrent writers within the same MCP process are not expected (single
process, single thread for `RemoteControl::cmd*`).

ANTS-1823 — concurrent writers *across processes* (two Ants Terminal
instances, or two Claude Code sessions sharing a cwd) previously got
last-writer-wins, which could silently drop a key when each session set a
different key at the same time. The read-modify-write now runs under a
`QLockFile` advisory lock spanning load → mutate → save, via the
`mutateLocked` primitive that all mutating ops (`set`/`delete`, and
`workflow_state`) route through. The lock is best-effort: a 5 s
acquisition budget and a 30 s stale window mean a crashed holder is
reclaimed and a timeout degrades to the old last-writer-wins rather than
wedging the tool. See INV-14.

Corrupt JSON on load (truncated, hand-edited mistake) is treated as an
empty store — the next `set` will overwrite with a clean state. INV-11.

## 4. Invariants

**INV-1 — store path.** Store file lives at
`<baseDir>/<cwdHash>.json` where `baseDir` defaults to
`~/.cache/ants-terminal/mcp-state/`. Base dir overridable via the
`ANTS_SESSION_MEMORY_DIR` env var (for tests).

**INV-2 — 100 KiB total cap.** `set` is rejected with `cap_exceeded`
when the JSON-compact serialised post-write store would exceed 100 KiB.
The cap is measured against the *post-write* serialised size, not the
running in-memory representation, so users get exact accounting.

**INV-3 — atomic save.** All writes use `QSaveFile::commit()` — no
partial writes survive a crash mid-save. The previous valid store
remains readable until rename succeeds.

**INV-4 — deterministic cwd hash.** `cwdHash(cwd)` returns the same
string for the same canonical absolute path on every invocation:
`QCryptographicHash::Sha256` of the UTF-8 canonical path, hex-encoded,
first 16 chars. 16 hex = 64 bits, collision probability negligible at
the scale of one user's project tabs.

**INV-5 — list returns keys-only.** `op=list` returns
`[{key, bytes}, ...]` with no inline values. Avoids the case where
"give me a listing" accidentally returns 100 KiB of caller-supplied
content on the wire.

**INV-6 — missing key is not an error.** `op=get` / `op=delete` on a
key that's absent returns `ok:true, found:false` rather than
`ok:false`. Lets callers use `get` as a probe without exception
handling.

**INV-7 — key validation.** Keys must match `^[A-Za-z0-9._\-]{1,64}$`.
Rejects path-traversal attempts, control characters, whitespace, and
unbounded length up front. `bad_key` error includes sanitised echo.

**INV-8 — per-value cap.** A single value's JSON-compact serialised
size must be ≤ 16 KiB. Prevents one giant value monopolising the
100 KiB total. `bad_value` error on overflow.

**INV-9 — schema required-arrays.** Tool schema requires `op`; the
handler additionally requires `key` for get/set/delete and `value` for
set. Schema-level `required: ["op"]` only; handler returns `bad_key` /
`bad_value` for the conditional cases (mirrors `cold_eyes_brief` which
also relies on handler-side enforcement past the schema's single
required field).

**INV-10 — filesystem permissions.** Base directory created with mode
`0700`; store file with mode `0600`. Per-user, not per-group / world
readable. Matches the existing `config.json` convention.

**INV-11 — corrupt-store recovery.** A corrupt or unparseable store
file is treated as empty on load (no exception). The next `set`
overwrites with valid content. Logged once via `qWarning()` to stderr
so a user grep-debugging this can see it happened.

**INV-12 — echo hygiene.** Any user-supplied string echoed back in an
error response is first truncated to 64 chars and has control
characters (`< 0x20`) replaced with `?`. Mirrors the ANTS-1319
`ceSanitiseEcho` helper.

**INV-13 — cwd override path validation.** When `cwd` is provided as
an argument, it must canonicalise (i.e. `QFileInfo(cwd).canonicalFilePath()`
non-empty) — empty / non-canonical → `no_project` error. Does NOT
require the cwd to be inside any specific tree; the store is keyed by
hash, not by path-prefix membership, so the override is a hash input,
not a permission check.

**INV-14 — locked read-modify-write (ANTS-1823).** Mutating ops
(`set`/`delete`, and `workflow_state` which routes through it) perform
their load → mutate → save under a `QLockFile` advisory lock keyed on
`<store>.lock`, so two processes mutating different keys on the same cwd
cannot last-writer-wins-drop each other. The lock is best-effort: a 5 s
acquisition budget and 30 s stale-reclaim window mean a crashed holder is
recovered and an acquisition timeout falls back to last-writer-wins
rather than failing the op. Read ops (`get`/`list`) take no lock — the
INV-3 atomic rename gives them a whole-or-nothing snapshot. Implemented
by `SessionMemoryEngine::mutateLocked`.

## 6. Token math

Per-session savings depend on use-case adoption. Lower bound (one
audit-tool-detect cache hit per session): saves 9 × `command -v` round
trips × ~50 B = ~450 B → ~110 tokens. Realistic mid-bound (audit + a
partition snapshot + a verify-cached file-set): ~2–4 KiB → ~500–1000
tokens/session.

The tool itself is small: response ≤ 200 B for `set`/`get`/`delete`,
~50 B per listed key for `list` (caller-controlled scale). Net
positive at any plausible adoption.

## 7. Memory + disk budget

**In-memory:** zero persistent state. Each `execute` call does
load-modify-save and lets the QJsonObject go out of scope. Peak: one
serialised store in memory at a time = ≤ 100 KiB.

**On-disk:** ≤ 100 KiB per cwd × N cwds the user has ever interacted
with. Realistically a few projects × 100 KiB = ≤ 1 MiB lifetime, more
likely ≤ 50 KiB across all projects combined. No GC needed at this
scale; future spec could add an "expire entries older than N days"
mode if file count grows past a few dozen.

**Build cost:** +1 engine file (~180 LoC compiled), +1 RemoteControl
method (~70 LoC), +1 provider lambda (~7 LoC), +1 schema block
(~50 LoC), +2 test bundles. Estimated +6-10s incremental build under
JOB_POOLS cap.

## 8. Migration

- New tool — no existing API to deprecate.
- No project-committed files. State lives entirely under
  `~/.cache/ants-terminal/mcp-state/` (machine-local).
- No menu / UI surface.
- Distinct from `.ants/verify.json` (ANTS-1289) which is *repo-local*;
  this spec is *machine-local*.
- Distinct from `~/.config/ants-terminal/config.json` (user
  preferences) which is hand-editable; this directory is engine-managed.

## 9. Out of scope

- **TTL / expiry.** v1 has no per-key expiry. Caller-side
  responsibility: store `last_ts` alongside the cached value and
  check freshness on read. A v2 could add `set ttl_seconds=...` with
  background sweep.
- **Encryption at rest.** Mode `0600` is the security perimeter. Users
  storing secrets in session memory get the same protection as their
  `~/.ssh/id_rsa`.
- **Watch / change notifications.** No `QFileSystemWatcher`; the
  store is poll-on-demand. A subscribing consumer would need a v2.
- **Cross-cwd queries.** v1 is per-cwd only — no "list all stores".
  A future maintenance tool could enumerate the base dir, but the
  per-cwd hash is intentional isolation.
- **Concurrent writer locking.** ~~No `flock(2)`; last-writer-wins.~~
  Superseded by ANTS-1823 (§3.3, INV-14): cross-process RMW now runs
  under a best-effort `QLockFile` advisory lock via `mutateLocked`. The
  lock degrades to last-writer-wins only on acquisition timeout.
- **Schema validation per key.** Keys are free-form strings; values
  are free-form JSON. Caller is responsible for matching reads to its
  own expected shapes.
- **Backups / migration on schema bumps.** v1 is single-version. If a
  future change needs migration, the engine can ship a `version` key
  and migrate on load — not needed now.
