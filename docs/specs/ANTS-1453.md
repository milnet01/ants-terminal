# ANTS-1453 — per-tool `selection_hint` on every MCP descriptor

**Status:** in flight (Bundle E follow-up, 2026-05-17).
**Kind:** enhancement.
**Lanes:** `claudeintegration` (`tools/list` block, `tool_info`
inline handler), `mcp_selection_hint` feature test.
**Source:** cross-session-report-2026-05-17 (other CC instance on
RetroDB project), roadmap entry under
`ROADMAP.md § Ants-MCP discoverability — tool-selection guidance`.

## Problem

`tools/list` descriptors document *what* each MCP tool does, not
*when to prefer it over a plain `Grep` / `Read` round*. A first-
time-user assistant scanning the descriptor surface has no signal
that, say, `subsystem` is the right opening move on a "where does
X live?" question vs. a `grep -rln`, or that `workspace_search`
collapses 6–10 grep+read rounds at the cost of one subagent dispatch.

The cross-session report quoted in `ROADMAP.md` shows a CC session
that took 10 vanilla tool calls to do work `mcp__ants__subsystem`
plus `mcp__ants__workspace_search` could have done in two — the
calling assistant never reached for the Ants MCP because the
descriptor didn't telegraph the cost/benefit trade-off.

## Fix

Inject one new descriptor field per registered tool —
`selection_hint` — at the same point we set `name` /
`description` / `inputSchema`. One sentence per tool, surfacing
the form-factor cue:

- "Use this when …" / "Prefer Grep when …" (terminal-state,
  project-layout, code-search tools).
- "Run this before …" / "Pairs with …" (orchestration verbs).
- "Read-only — bypass for write-side checks" (control-plane).

Hint copy stays under ~200 chars so a 42-tool dump adds ~8 KB to
`tools/list`. Default is non-empty for every tool (no opt-in /
opt-out — the spec invariant is that the field is set everywhere).

`tool_info` already returns a descriptor slice
(`name` + `description` + `inputSchema`); extend its envelope to
pass `selection_hint` through unchanged so a caller can fetch one
hint for ~80 B instead of paying for the full `tools/list` snapshot.
The cache-population path at `m_lastToolsList` already captures the
full descriptor object — no new state.

No behavioural change for any tool. The MCP-spec required fields
(`name`, `description`, `inputSchema`) are preserved untouched; this
adds a project-namespaced field that conformant clients will ignore
if they don't recognise it.

## Invariants

- **HINT-1.** Every entry appended to the `tools` array inside the
  `tools/list` handler in `claudeintegration.cpp` sets
  `[X]Tool["selection_hint"]` (or `t["selection_hint"]`) to a
  non-empty `QStringLiteral`. Source-grep: scan the file for
  `Tool["name"] = ` and `t["name"] = ` declarations; every block
  must contain a `selection_hint` assignment before the matching
  `tools.append(...)`.
- **HINT-2.** `tool_info`'s success envelope (`env["ok"] = true`
  branch around `claudeintegration.cpp:3708-3713`) sets
  `env["selection_hint"]` from the matched descriptor — no
  defaulting / no falling back to description copy.
- **HINT-3.** `selection_hint` strings are ≤ 240 chars (roughly 60
  tokens) so a 42-tool descriptor dump grows by < 10 KB.

## Test

`tests/features/mcp_selection_hint/test_mcp_selection_hint.cpp` —
source-scrape regression. For every `Tool["name"] = "..."` (and
`t["name"] = "..."`) site, assert the matching block also sets
`selection_hint` to a `QStringLiteral` literal. Also assert
`tool_info`'s success envelope contains
`env["selection_hint"] = match.value(QStringLiteral("selection_hint"))`.

## Out of scope

- Restructuring `tools/list` into a data-table (separate ANTS-1049
  / ANTS-1444 refactor lane). HINT-1 stays a source-grep invariant
  for now.
- Hint copy revisions per-tool — ship a first-pass set, iterate
  in follow-ups when callers report misleading hints.
- Adding a `version` field on descriptors (ANTS-1354 — separate
  MCP-API-hygiene lane).
- Localisation. English-only hints; matches the rest of the MCP
  surface.
