## 1. Problem

The ANTS-3572 pill is entirely project-blind:

- **Face** = `m_tokenUsage.buildReport(false).totalSaved` — the whole in-process
  session's saved estimate, summed across **every** project whose Claude Code
  session made MCP calls into this Ants window (`claudestatuswidgets.cpp:488`,
  driven by `tokensSavedUpdated`, `claudeintegration.cpp:1469`).
- **Tooltip** month / YTD / all-time = the single global config aggregate
  `claude.tokens_saved_monthly` + `claude.tokens_saved_lifetime`
  (`claudestatuswidgets.cpp:495-506`) — accumulated across all projects and all
  past sessions.

The root cause is that `TokenUsageEngine`'s counters are keyed by **tool name
only** (`QHash<QString, ToolCounter> m_counters`, `tokenusageengine.h:89`); no
`caller_cwd` / project dimension flows into `recordCall`, the counters, the
`tokensSavedUpdated` payload, or the config aggregate. So a user who works across
several projects sees one lump total and cannot tell how much a given project's
MCP usage actually saved.

**Layman:** The "tokens saved" badge adds up every project you've ever used it in.
You want it to show just the project you're looking at right now — with the old
grand total kept as one extra line so nothing disappears.

## 2. Surface / design

### 2.1 Attribution (in-process, live)

`ClaudeIntegration` gains a bounded per-project session accumulator:

```cpp
QHash<QString /*canonicalRoot*/, qint64 /*savedBytesThisSession*/>
    m_sessionSavedBytesByProject;   // ANTS-3579
```

In `recordDispatch`, after the existing `m_tokenUsage.recordCall(...)`:

- Resolve the call's canonical root: `root = resolveCallerCwdRoot(mainWindow(),
  argsObj.value("caller_cwd").toString()).cwd`. (`ClaudeIntegration` reaches the
  `MainWindow` for the focused-terminal fallback; if no `MainWindow` is available
  — headless tests — fall back to `QFileInfo(callerCwd).canonicalFilePath()`.)
- If `root` is empty (unresolvable **and** no focused terminal), attribute to
  **no** project — drop the delta (it is still counted in the global
  `m_tokenUsage`, so the "all projects" line stays whole). *Never* create an
  empty-string bucket.
- On **success only** (`result == "ok"`), add the per-call saved estimate in
  **bytes**: `savedBytes = max(0, TokenUsageEngine::baselineFor(toolName) -
  outBytes)`; `m_sessionSavedBytesByProject[root] += savedBytes`. Failed calls
  add 0 (mirrors `buildReport`, which routes failed bytes to the failed-* fields,
  not `totalSaved`).
- Cap the in-memory map at `kMaxTokenProjects` (64) roots; on inserting a new
  root beyond the cap, evict the smallest-total root (a live map is transient;
  exact LRU is unnecessary — the persisted map, § 2.3, is the durable one).

The map stays **bytes**, not tokens, so the display divides by the same
`kCharsPerToken` the aggregate uses (one rounding point, § 2.5 INV-8).

### 2.2 Which project the pill shows

The pill always reflects the **focused tab's** project, not the last call's:

- Focused root: `focusedTerminal() ? QFileInfo(focusedTerminal()->shellCwd())
  .canonicalFilePath() : QString()` — the same canonical form as § 2.1 keys.
- The pill re-renders on **two** triggers: (a) `tokensSavedUpdated` (any MCP
  call — the existing connection), and (b) the current-tab-changed signal the
  status bar already listens to for its per-tab chips (INV-7). On both, the
  widget recomputes the focused root and reads that project's numbers.
- `tokensSavedUpdated`'s `qint64` payload is now only a *change nudge*; the
  widget pulls the focused project's live total from a new
  `ClaudeIntegration::sessionSavedBytesForProject(const QString &root) const`
  getter (returns 0 for an unknown root).

### 2.3 Persistence (per-project, bounded)

New store-only config field, sibling to the global ones:

```jsonc
"claude.tokens_saved_by_project": {
  "<canonicalRoot>": {
    "monthly":  { "YYYY-MM": <int> },   // ≤ 24 keys, foldMonthlyBucket-pruned
    "lifetime": <int>,                  // exact all-time for THIS project
    "since":    "<ISO date>",           // first fold for this project
    "updated":  "<ISO date>"            // last fold — the LRU key
  }
}
```

`Config` getter/setter `claudeTokensSavedByProject()` /
`setClaudeTokensSavedByProject(const QJsonObject &)` — store-only (no `save()`,
matching ANTS-3572 INV-7). `foldTokenSavingsIntoConfig()` (the existing single
persist point) is extended: after the global fold (unchanged), it iterates
`m_sessionSavedBytesByProject`, converts each root's bytes → tokens, and folds
each into `claude.tokens_saved_by_project[root]` (bump `lifetime`, `monthly` via
`foldMonthlyBucket(..., 24)`, stamp `since` if empty, set `updated` = today),
then evicts to `kMaxTokenProjects` (64) roots by **oldest `updated`**. One
`config.save()` still covers global + per-project (INV-7 preserved). The live
map is cleared alongside `m_tokenUsage.reset()`.

### 2.4 Display

- **Face:** `↓ <humanize(focusedProjectSessionTokens)> saved`. Hidden when the
  feature is off (`claudeTokensSavedChipEnabled()` — unchanged toggle) **or** the
  focused project's session saved is `≤ 0` (same live-indicator semantics as
  ANTS-3572, now per focused project).
- **Tooltip** (vertical, magnifier-friendly — ANTS-3572 layout kept):
  ```
  This session: <focused project session>
  This month:   <focused project month + session>
  This year:    <focused project YTD + session>
  All-time:     <focused project lifetime + session> saved   (this project)
  ──────────────
  All projects: <global lifetime + global session>
  ```
  "This project" numbers read `claude.tokens_saved_by_project[focusedRoot]` +
  the live focused-project session; "All projects" reads the untouched global
  aggregate + global session (INV-4). When the focused root has no persisted
  bucket yet, its month/year/all-time are just the live session value.

### 2.5 Pure helper (unit-testable, Qt6::Core)

Add to `TokenUsageEngine` (no Widgets, testable without a `MainWindow`):

```cpp
// Fold one project's delta into byProject[root] (lifetime += addTokens,
// monthly via foldMonthlyBucket(...,keepMonths), stamp since/updated), then
// retain only the `keepProjects` roots with the newest `updated` (evict oldest).
QJsonObject foldProjectBucket(QJsonObject byProject, const QString &root,
                              qint64 addTokens, const QString &monthKey,
                              const QString &todayIso, int keepMonths,
                              int keepProjects);
```

## 3. Invariants

- **INV-1** — Attribution. Every **successful** MCP dispatch adds
  `max(0, baselineFor(tool) − outBytes)` bytes to
  `m_sessionSavedBytesByProject[resolveCallerCwdRoot(caller_cwd).cwd]`. An
  unresolvable root (empty, no focused terminal) is dropped, never bucketed under
  `""`. Failed calls add 0. *Test:* source-scrape `recordDispatch` for the
  resolve + `+=` + `succeeded` gate; pure test of the byte math.
- **INV-2** — Face scope. The face humanizes the **focused project's** session
  saved, and is hidden iff the feature is off OR that value ≤ 0. *Test:*
  source-scrape the chip lambda reads the focused-project getter, not
  `buildReport().totalSaved`.
- **INV-3** — Tooltip shape. Tooltip carries the four focused-project periods
  tagged "(this project)" and a separated "All projects:" line. *Test:*
  source-scrape the tooltip builder for both the per-project reads and the
  "All projects" literal.
- **INV-4** — Global untouched. `claude.tokens_saved_monthly` /
  `_lifetime` / `_since` semantics are byte-for-byte unchanged (still the true
  all-projects total); the global fold in `foldTokenSavingsIntoConfig` runs
  first and identically to ANTS-3572. *Test:* the ANTS-3572 `tokens_saved_chip`
  suite stays green; source-scrape shows the global fold block unmodified.
- **INV-5** — Persisted store bounded. `claude.tokens_saved_by_project` holds
  ≤ `kMaxTokenProjects` (64) roots (evict oldest `updated` on overflow) and each
  root's `monthly` holds ≤ 24 keys (`foldMonthlyBucket`). *Test:*
  `foldProjectBucket` pure test — 65th root evicts the oldest; 25th month prunes.
- **INV-6** — Single persist. `foldTokenSavingsIntoConfig` writes global +
  per-project buckets under **one** `config.save()` (store-only setters before
  it). *Test:* source-scrape: exactly one `save()` in the method; per-project
  fold sits after the global fold, before `save()`.
- **INV-7** — Focus-change refresh. Switching to a tab in a different project
  re-renders the pill for that project with **no** new MCP call. *Test:*
  source-scrape the widget connects its render to the current-tab-changed signal
  as well as `tokensSavedUpdated`.
- **INV-8** — Rounding. Per-project totals accumulate **saved bytes** and divide
  by `kCharsPerToken` once at display, so `Σ(per-project session tokens)` equals
  the global session tokens up to per-tool floor-at-0 rounding (a single call
  over its baseline lowers only its own project, never another's). Documented,
  not a bug. *Test:* pure test asserting a mixed two-project set sums within the
  documented ±(#tools) token tolerance of the global figure.
- **INV-9** — Migration. `claude.tokens_saved_by_project` starts absent and
  accrues from the first post-ship fold; pre-feature global history is **not**
  retroactively split. A focused project with no bucket shows only its live
  session until its first fold. The "All projects" line always carries the full
  history. *Test:* pure test — empty `byProject` + a session fold yields exactly
  one root at that session's total; global lifetime includes prior history.
- **INV-10** — Toggle + a11y unchanged. `claudeTokensSavedChipEnabled()` still
  hides the whole pill; the accessible name updates to name the project scope.
  *Test:* source-scrape the toggle gate is intact; accessible-name literal present.

## 5. RAM / storage budget

- **In-memory:** `m_sessionSavedBytesByProject` ≤ 64 roots × (`QString` key +
  `qint64`) — a few KB, capped, cleared every session reset.
- **On-disk (config.json):** ≤ 64 roots × (≤24 `"YYYY-MM":int` + 3 scalars) ≈
  a few KB of JSON — same order as the existing 24-month global map, bounded by
  the same 24-month prune plus the 64-root cap. No unbounded growth.

## 6. Non-goals

- The `token_usage` MCP verb stays global (no per-project breakdown this pass;
  a follow-up may add a `by_project` view if asked).
- No retroactive attribution of pre-ship savings (INV-9).
- No new user-facing setting; the existing enable toggle governs the whole pill.
