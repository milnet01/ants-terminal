## 1. Problem

The ANTS-3572 pill is entirely project-blind:

- **Face** = `m_tokenUsage.buildReport(false).totalSaved` — the whole in-process
  session's saved estimate, summed across **every** project whose Claude Code
  session made MCP calls into this Ants window (`claudestatuswidgets.cpp:488`,
  driven by `tokensSavedUpdated`, `claudeintegration.cpp:1469`).
- **Tooltip** month / YTD / all-time = the single global config aggregate
  `claude.tokens_saved_monthly` + `claude.tokens_saved_lifetime`
  (`claudestatuswidgets.cpp:495-506`) — accumulated across all projects and all
  past sessions.

The root cause is that `TokenUsageEngine`'s counters are keyed by **tool name
only** (`QHash<QString, ToolCounter> m_counters`, `tokenusageengine.h:89`); no
`caller_cwd` / project dimension flows into `recordCall`, the counters, the
`tokensSavedUpdated` payload, or the config aggregate. So a user who works across
several projects sees one lump total and cannot tell how much a given project's
MCP usage actually saved.

**Layman:** The "tokens saved" badge adds up every project you've ever used it in.
You want it to show just the project you're looking at right now — with the old
grand total kept as one extra line so nothing disappears.

## 2. Surface / design

### 2.1 Attribution (in-process, live)

`ClaudeIntegration` gains a bounded per-project session accumulator plus a
single-entry canonicalisation memo (the perf mitigation of § 6):

```cpp
QHash<QString /*canonicalRoot*/, qint64 /*savedBytesThisSession*/>
    m_sessionSavedBytesByProject;                 // ANTS-3579
QHash<QString /*canonicalRoot*/, quint64 /*lastTouchSeq*/>
    m_projectTouchSeq;                            // live-map LRU key
QHash<QString /*caller_cwd*/, QString /*canonicalRoot*/>
    m_callerCwdRootMemo;                          // bounded caller_cwd→root memo (§ 6)
quint64 m_projectTouchCounter = 0;
```

`kMaxTokenProjects` (64) is declared in `claudeintegration.h` beside the other
in-process caps (I-A).

In `recordDispatch`, after the existing `m_tokenUsage.recordCall(...)`:

- **Derive the canonical root from `caller_cwd` alone — no `MainWindow`.**
  `recordDispatch` has no `MainWindow` handle (`claudeintegration.h` holds none,
  by ANTS-3572's decoupling), so it does NOT call `resolveCallerCwdRoot` (which
  requires one). Instead: `cwd = argsObj.value("caller_cwd").toString()`; look up
  `cwd` in `m_callerCwdRootMemo`; on a miss, `root = QFileInfo(cwd)
  .canonicalFilePath()` (a `static` call) and insert `cwd → root`. The memo is a
  **bounded map** capped at `kMaxTokenProjects` (cleared wholesale on overflow) —
  it holds one entry per distinct `caller_cwd`, so N interleaved projects all hit
  it after their first stat (§ 6); it is not a single slot that N projects would
  thrash. Cleared with the live map at session reset (INV-12).
- If `cwd` is empty, or `canonicalFilePath()` returns empty (the dir does not
  exist — e.g. a deleted project), attribute to **no** project: drop the delta.
  It is still counted in the global `m_tokenUsage`, so the "all projects" line
  stays whole. *Never* create an empty-string bucket.
- On **success only** (`result == "ok"`), add the per-call saved estimate in
  **bytes**, mirroring the engine's `baseline − (in+out)` term (`argBytes` is the
  call's input bytes, `outBytes` the response bytes):
  `savedBytes = max(0, TokenUsageEngine::Tracker::baselineFor(toolName)
  − (argBytes + outBytes))`; then `m_sessionSavedBytesByProject[root] +=
  savedBytes` and `m_projectTouchSeq[root] = ++m_projectTouchCounter`. Failed
  calls add 0 (mirrors `buildReport`, which routes failed bytes to the failed-*
  fields, not `totalSaved`).
- Cap the live map at `kMaxTokenProjects` (64) roots; on inserting a 65th root,
  evict the **least-recently-touched** root (smallest `m_projectTouchSeq`) — the
  same "oldest wins" policy the persisted store uses (§ 2.3, INV-5b), so the two
  caps agree. A focused project that is actively receiving calls always holds the
  newest seq, so it is never the eviction victim; a project evicted while idle
  **loses its accumulated live-session bytes** and restarts from 0 on its next
  attributed call (§ 4) — an accepted approximation only reachable at > 64
  concurrently-active projects in one session.

The map stays **bytes**, not tokens, so the byte→token division (`/kCharsPerToken`)
happens exactly once, at display (INV-8).

### 2.2 Which project the pill shows

The pill reflects the **focused tab's** project:

- Focused root: `focusedTerminal() ? QFileInfo(focusedTerminal()->shellCwd())
  .canonicalFilePath() : QString()` — the **same** static `QFileInfo::
  canonicalFilePath()` derivation § 2.1 keys the live map on (INV-11), so a call's
  attribution key and the pill's display key are byte-identical **when the MCP
  call's `caller_cwd` equals the focused shell's cwd** — the normal case (Claude
  Code's `caller_cwd` is the project dir it was launched in, which is that tab's
  shell cwd). **Accepted divergence:** if `caller_cwd` is a *subdir* of the shell
  cwd (or the shell has `cd`'d away from where Claude Code launched), the call is
  bucketed under one canonical dir and the pill reads another, so the pill can
  show a project's savings under the "wrong" (still-canonical) key. This is
  accepted: `caller_cwd` is stable per Claude Code session, both keys are real
  canonical dirs, and there is no marker-walk to a common root (matching how the
  rest of MCP dispatch keys). § 4 records the deleted-dir case.
- The pill re-renders on **two** triggers: (a) `tokensSavedUpdated` (any MCP
  call — the existing connection); and (b) the tab-change refresh
  `ClaudeStatusBarController` already runs from its `onTabChanged` entry-point for
  the per-tab chips — **whose body already reads `focusedTerminal()`**. This spec
  **adds the tokens-saved render into that existing `onTabChanged` method body**
  (it is a method call from `MainWindow`'s tab plumbing, NOT a Qt signal the
  widget `connect()`s to — INV-7). ANTS-3572 §2.1 deliberately kept this chip
  integration-signal-only (off `onTabChanged`) because it had no per-tab
  dimension; scoping it per-project gives it one, so it now joins that refresh.
- `tokensSavedUpdated`'s `qint64` payload is now only a *change nudge*; the widget
  pulls the focused project's live total from a new
  `ClaudeIntegration::sessionSavedBytesForProject(const QString &root) const`
  getter (returns 0 for an unknown root).
- **Accepted staleness:** an intra-tab change that alters `focusedTerminal()
  ->shellCwd()` without either trigger firing — a shell `cd` (the accepted
  divergence above) or a split-pane focus change with no intervening MCP call or
  tab switch — leaves the pill on the prior project until the next
  `tokensSavedUpdated` / `onTabChanged`. Accepted: the pill is a live indicator,
  not a ledger, and the next MCP call refreshes it (L-a).

**Supersession note (M-b):** ANTS-3572 § 2.1 states this chip is driven by
`tokensSavedUpdated` "not `onTabChanged`". That is superseded here — scoping the
pill per-project requires the `onTabChanged` refresh above. A one-line forward
reference is added to ANTS-3572 § 2.1 pointing at this spec.

### 2.3 Persistence (per-project, bounded)

New store-only config field, sibling to the global ones:

```jsonc
"claude.tokens_saved_by_project": {
  "<canonicalRoot>": {
    "monthly":  { "YYYY-MM": <int> },   // ≤ 24 keys, foldMonthlyBucket-pruned
    "lifetime": <int>,                  // exact all-time for THIS project
    "since":    "<ISO date>",           // first fold for this project (display)
    "updated":  "<ISO 8601 datetime>"   // last fold — the LRU key (§ 2.5)
  }
}
```

`Config` getter/setter `claudeTokensSavedByProject()` /
`setClaudeTokensSavedByProject(const QJsonObject &)` — store-only (no `save()`,
matching ANTS-3572 INV-7).

`foldTokenSavingsIntoConfig()` (the existing single persist point) is extended.
Because it lives on `MainWindow` and the live map is private to `ClaudeIntegration`,
`ClaudeIntegration` exposes a **whole-map snapshot getter**
`QHash<QString,qint64> sessionSavedBytesByProject() const` (H3). The fold, after
the unchanged global fold, iterates that snapshot, converts each root's bytes →
tokens (`/kCharsPerToken`), and folds each into `claude.tokens_saved_by_project`
via the pure `foldProjectBucket` helper (§ 2.5). One `config.save()` still covers
global + per-project (INV-6).

The live map (+ its touch-seq + memo) is cleared **after** the fold, inside
`endTokenSession()` — never before the `tokenSessionEnding` emit, which runs the
fold synchronously and snapshots the map (INV-12, the per-project analogue of
ANTS-3572 INV-3's fold-before-reset hazard). The modified body:

```cpp
void ClaudeIntegration::endTokenSession() {     // ANTS-3579 additions marked
    emit tokenSessionEnding();          // MainWindow folds global + per-project NOW (sync)
    m_tokenUsage.reset();
    m_sessionSavedBytesByProject.clear();   // ANTS-3579 — AFTER the fold snapshot
    m_projectTouchSeq.clear();
    m_callerCwdRootMemo.clear();
    m_projectTouchCounter = 0;
    emit tokensSavedUpdated(0);          // chip → hidden until next dispatch
}
```

### 2.4 Display

- **Face:** `↓ <TokenUsageEngine::humanizeCount(focusedProjectSessionTokens)>
  saved`. Hidden when the feature is off (`claudeTokensSavedChipEnabled()` —
  unchanged toggle) **or** the focused project's session saved is `≤ 0` (same
  live-indicator semantics as ANTS-3572, now per focused project).
- **Tooltip** (vertical, magnifier-friendly — ANTS-3572 layout kept):
  ```
  This session: <focused project session>
  This month:   <focused project month + session>
  This year:    <focused project YTD + session>
  All-time:     <focused project lifetime + session> saved   (this project, since <date>)
  ──────────────
  All projects: <global lifetime + global session>
  ```
  "This project" numbers read `claude.tokens_saved_by_project[focusedRoot]`
  (`lifetime`/`monthly` + the per-project `since`) plus the live focused-project
  session (`sessionSavedBytesForProject` → tokens). "All projects" reads the
  untouched global aggregate (`claudeTokensSavedLifetime()` + folded `monthly`)
  **plus the global live session** via `m_integration->tokenUsageReport(false)
  .totalSaved` — the same global getter ANTS-3572 uses, NOT the demoted
  `tokensSavedUpdated` nudge payload (M-c) — so it stays whole even though the
  face now shows only the focused project (INV-4). When the focused root has no
  persisted bucket yet, its month/year/all-time are just the live session value
  and the `(since …)` clause is omitted.

### 2.5 Pure helper (unit-testable, Qt6::Core)

Add to `TokenUsageEngine` (no Widgets, testable without a `MainWindow`):

```cpp
// Fold one project's delta into byProject[root]: lifetime += addTokens, monthly
// via foldMonthlyBucket(...,keepMonths), stamp `since` if absent, set `updated`
// = nowIso. Then retain only the `keepProjects` roots with the newest `updated`
// (evict oldest); ties broken by root string DESC so eviction is deterministic.
QJsonObject foldProjectBucket(QJsonObject byProject, const QString &root,
                              qint64 addTokens, const QString &monthKey,
                              const QString &nowIso, int keepMonths,
                              int keepProjects);
```

`nowIso` is an ISO 8601 **datetime** (`QDateTime::toString(Qt::ISODate)`), so
same-day folds still order; the root-string tie-break removes the last ambiguity
(INV-5b).

The byte→token conversion (live-session bytes → displayed tokens in § 2.4, and
each root's fold-time bytes → stored tokens in § 2.3) divides by the engine's
`kCharsPerToken`. That constant is today a file-local `constexpr` in the
`tokenusageengine.cpp` anonymous namespace (`:49`), unreachable from the widget TU
— which is why the ANTS-3572 chip wrote the bare `/ 4` literal
(`claudestatuswidgets.cpp:525`). ANTS-3579 **promotes `kCharsPerToken` to a public
`constexpr` in `tokenusageengine.h`** so both the new display path and the tests
reference it by symbol (the existing `:525` literal may adopt it later — out of
scope). INV-8's display-division scrape keys on `kCharsPerToken` (M-A).

- **INV-1** — Attribution. Every **successful** MCP dispatch adds

  empty `caller_cwd` or an empty canonical path (nonexistent dir) is dropped,
  never bucketed under `""`. Failed calls add 0. *Test:* source-scrape

  subtraction + `+=` under the `succeeded` gate. (The floor math is inline in
  `recordDispatch`, no pure helper, so it is pinned by scraping the exact
  `max(0, … − (argBytes + outBytes))` expression — a separate "pure" test could
  only re-derive the arithmetic tautologically; M-B.)
- **INV-2** — Face scope. The face humanizes (`humanizeCount`) the **focused
  project's** session saved, hidden iff the feature is off OR that value ≤ 0.
  *Test:* source-scrape the chip slot reads `sessionSavedBytesForProject(...)`,
  not `buildReport().totalSaved`.
- **INV-3** — Tooltip shape. The tooltip's first block is the four focused-project

  "(this project, since <date>)"; then a separator; then a single "All projects:"

- **INV-4** — Global untouched. `claude.tokens_saved_monthly` / `_lifetime` /

## 4. Failure modes

- **Corrupt / missing `claude.tokens_saved_by_project`** (hand-edited to a
  non-object, or absent on first run) → getter returns an empty `QJsonObject`;
  the fold starts a fresh map. No crash, no refusal (mirrors ANTS-3572 § 4).
- **A per-root value that is not an object** (hand-edited) → treated as an empty
  bucket in `foldProjectBucket`; overwritten on that root's next fold. Self-heals.
- **Missing `updated` / `since`** on a bucket → `updated` sorts as oldest (so it
  is evicted first, acceptable); `since` is stamped on the next fold; the tooltip
  omits the `(since …)` clause when absent.
- **Project dir deleted between sessions** → attribution: `canonicalFilePath()`
  returns empty for the gone dir, so live calls under it are dropped (INV-1); the
  persisted bucket lingers (harmless — `lifetime` is historical) until the 64-cap
  LRU-evicts it. The pill only shows it while that project is the focused tab
  (impossible once its terminal is gone).
- **Clock moved backwards / timezone change** → a fold may write an earlier
  `updated` than a prior fold and/or a bucket under an earlier `YYYY-MM`; it
  simply adds into that bucket, and eviction still runs on the (now-nonmonotonic)
  datetime — a wrong project could be evicted, but only among > 64 projects.
  Acceptable for a motivational estimate (mirrors ANTS-3572 § 4).
- **Crash / OOM-kill before a fold** → the in-flight session's per-project
  savings are lost, exactly as the global session is (ANTS-3572 § 4). Estimate,
  not accounting.
- **> 64 projects touched in one live session** → the least-recently-touched
  roots are evicted from the live map (§ 2.1); each re-populates on its next
  attributed call. The focused project (actively called) is never the victim.

## 6. Performance / RAM budget

- **Per MCP call (hot path):** the existing `buildReport(false)` (unchanged) plus
  **one** `QFileInfo::canonicalFilePath(caller_cwd)`. That call may `stat` the
  path — ANTS-3572 § 6 promised "no disk I/O on this path", so this is a new,
  bounded cost. **Mitigation (§ 2.1 memo):** `caller_cwd` is stable within a
  Claude Code session, so the single-entry `m_lastCallerCwd → m_lastCallerRoot`
  memo makes the `stat` run ~once per session (per distinct `caller_cwd`), not per
  call; steady-state cost is a `QHash` insert + a `qint64` add. No config write on
  this path (INV-6).
- **Per fold (rare):** the existing 24-month global prune + one `foldProjectBucket`
  per touched root (each a 24-month prune + a 64-root sort) + one `config.save()`.
- **RAM:** live `m_sessionSavedBytesByProject` + `m_projectTouchSeq` ≤ 64 roots ×
  (`QString` key + `qint64`/`quint64`) — a few KB, capped, cleared each session
  reset. On-disk `tokens_saved_by_project` ≤ 64 roots × (≤ 24 `"YYYY-MM":int` + 2
  scalars + 2 short strings) ≈ a few KB of JSON — same order as the global 24-month
  map, bounded by the 24-month prune plus the 64-root cap. No unbounded growth,
  no new thread / watcher / timer.
