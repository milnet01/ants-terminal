## 1. Problem

The ANTS-3572 pill is entirely project-blind:

- **Face** = `m_tokenUsage.buildReport(false).totalSaved` — the whole in-process
  session's saved estimate, summed across **every** project whose Claude Code
  session made MCP calls into this Ants window (`claudestatuswidgets.cpp:488`,
  driven by `tokensSavedUpdated`, `claudeintegration.cpp:1469`).
- **Tooltip** month / YTD / all-time = the single global config aggregate
  `claude.tokens_saved_monthly` + `claude.tokens_saved_lifetime`
  (`claudestatuswidgets.cpp:495-506`) — accumulated across all projects and all
  past sessions.

The root cause is that `TokenUsageEngine`'s counters are keyed by **tool name
only** (`QHash<QString, ToolCounter> m_counters`, `tokenusageengine.h:89`); no
`caller_cwd` / project dimension flows into `recordCall`, the counters, the
`tokensSavedUpdated` payload, or the config aggregate. So a user who works across
several projects sees one lump total and cannot tell how much a given project's
MCP usage actually saved.

**Layman:** The "tokens saved" badge adds up every project you've ever used it in.
You want it to show just the project you're looking at right now — with the old
grand total kept as one extra line so nothing disappears.

## 2. Surface / design

### 2.1 Attribution (in-process, live)

`ClaudeIntegration` gains a bounded per-project session accumulator plus a
bounded `caller_cwd`→root canonicalisation memo (the perf mitigation of § 6):

```cpp
QHash<QString /*canonicalRoot*/, qint64 /*savedBytesThisSession*/>
    m_sessionSavedBytesByProject;                 // ANTS-3579
QHash<QString /*canonicalRoot*/, quint64 /*lastTouchSeq*/>
    m_projectTouchSeq;                            // live-map LRU key
QHash<QString /*caller_cwd*/, QString /*canonicalRoot*/>
    m_callerCwdRootMemo;                          // bounded caller_cwd→root memo (§ 6)
quint64 m_projectTouchCounter = 0;
```

`kMaxTokenProjects` (64) is declared in `claudeintegration.h` beside the other
in-process caps (I-A).

In `recordDispatch`, after the existing `m_tokenUsage.recordCall(...)`:

- **Derive the canonical root from `caller_cwd` alone — no `MainWindow`.**
  `recordDispatch` has no `MainWindow` handle (`claudeintegration.h` holds none,
  by ANTS-3572's decoupling), so it does NOT call `resolveCallerCwdRoot` (which
  requires one). Instead: `cwd = argsObj.value("caller_cwd").toString()`; look up
  `cwd` in `m_callerCwdRootMemo`; on a miss, `root = QFileInfo(cwd)
  .canonicalFilePath()` (a `static` call) and insert `cwd → root`. The memo is a
  **bounded map** capped at `kMaxTokenProjects` (cleared wholesale on overflow) —
  it holds one entry per distinct `caller_cwd`, so N interleaved projects all hit
  it after their first stat (§ 6); it is not a single slot that N projects would
  thrash. Cleared with the live map at session reset (INV-12).
- If `cwd` is empty, or `canonicalFilePath()` returns empty (the dir does not
  exist — e.g. a deleted project), attribute to **no** project: drop the delta.
  It is still counted in the global `m_tokenUsage`, so the "all projects" line
  stays whole. *Never* create an empty-string bucket.
- On **success only** — reuse the existing `succeeded` local
  (`const bool succeeded = (result == QLatin1String("ok"))`, `claudeintegration.cpp:1449`),
  not a fresh compare (LA1 — distinct from INV-10's L1) — add the per-call saved
  estimate in
  **bytes**, mirroring the engine's `baseline − (in+out)` term (`argBytes` is the
  call's input bytes, `outBytes` the response bytes):
  `savedBytes = max(0, TokenUsageEngine::Tracker::baselineFor(toolName)
  − (argBytes + outBytes))`; then `m_sessionSavedBytesByProject[root] +=
  savedBytes` and `m_projectTouchSeq[root] = ++m_projectTouchCounter`. Failed
  calls add 0 (mirrors `buildReport`, which routes failed bytes to the failed-*
  fields, not `totalSaved`).
- Cap the live map at `kMaxTokenProjects` (64) roots; on inserting a 65th root,
  evict the **least-recently-touched** root (smallest `m_projectTouchSeq`) — the
  same "least-recently-active wins" spirit as the persisted store (§ 2.3, INV-5b —
  though the live key is last-attributed-call and the persisted key is last-fold
  datetime, so the two are analogous, not an identical signal, L2). A focused
  project that is actively receiving calls always holds the
  newest seq, so it is never the eviction victim; a project evicted while idle
  **loses its accumulated live-session bytes** and restarts from 0 on its next
  attributed call (§ 4) — an accepted approximation only reachable at > 64
  concurrently-active projects in one session. Eviction removes the victim root
  from **both** `m_sessionSavedBytesByProject` and `m_projectTouchSeq` (L-2), so
  the touch-seq map stays ≤ 64 too.

The map stays **bytes**, not tokens; the byte→token division (`/kCharsPerToken`)
happens once **per data-path** — at display for live-session bytes (§ 2.4) and at
fold time for stored bytes (§ 2.3) — never twice on the same value (INV-8, M-1).

### 2.2 Which project the pill shows

The pill reflects the **focused tab's** project:

- Focused root (computed in the controller): `auto *t = m_focusedTerminalProvider();
  root = t ? QFileInfo(t->shellCwd()).canonicalFilePath() : QString()`. The
  controller reaches the focused tab through its `m_focusedTerminalProvider`
  (`std::function<TerminalWidget*()>`, `claudestatuswidgets.h:515`, set via
  `setFocusedTerminalProvider`), **not** a direct `focusedTerminal()` call (that is
  a `MainWindow` method — M2). It is the **same** static `QFileInfo::
  canonicalFilePath()` derivation § 2.1 keys the live map on (INV-11), so a call's
  attribution key and the pill's display key are byte-identical **when the MCP
  call's `caller_cwd` equals the focused shell's cwd** — the normal case (Claude
  Code's `caller_cwd` is the project dir it was launched in, which is that tab's
  shell cwd). **Accepted divergence:** if `caller_cwd` is a *subdir* of the shell
  cwd (or the shell has `cd`'d away from where Claude Code launched), the call is
  bucketed under one canonical dir and the pill reads another, so the pill can
  show a project's savings under the "wrong" (still-canonical) key. This is
  accepted: `caller_cwd` is stable per Claude Code session, both keys are real
  canonical dirs, and there is no marker-walk to a common root (matching how the
  rest of MCP dispatch keys). § 4 records the deleted-dir case.
- The pill re-renders on **two** triggers: (a) `tokensSavedUpdated` (any MCP
  call — the existing connection); and (b) a **tab switch**, via
  `MainWindow::refreshStatusBarForActiveTab()` (`mainwindow.cpp:5844`) — which
  `MainWindow::onTabChanged` (`:2966`) already calls to refresh the per-tab
  surfaces through named controller methods (`refreshRoadmapButton`,
  `refreshRepoVisibility`, … at `mainwindow.cpp:5942-5943`). The tokens-saved
  render is today a **lambda** in the `tokensSavedUpdated` `connect()`
  (`claudestatuswidgets.cpp:488`); this spec **extracts it into a named controller
  method `ClaudeStatusBarController::refreshTokensSavedChip()`** that both the
  signal slot AND `refreshStatusBarForActiveTab()` call — so a tab switch
  re-renders the pill for the newly-focused project with no MCP call (INV-7). (Do
  NOT model it on `refreshModelStateChip`, which is driven by the status *timer*
  `m_statusTimer::timeout` at `mainwindow.cpp:800`, not the tab switch — Lane-A M1.)
  `onTabChanged` is a
  `MainWindow` method, NOT a controller one; the render is not a mere signal
  `connect`. ANTS-3572 §2.1 deliberately kept this chip integration-signal-only
  (off the tab refresh) because it had no per-tab dimension; scoping it
  per-project gives it one, so it now joins that refresh.
- `tokensSavedUpdated`'s `qint64` payload is now only a *change nudge*; the widget
  pulls the focused project's live total from a new
  `ClaudeIntegration::sessionSavedBytesForProject(const QString &root) const`
  getter (returns 0 for an unknown root).
- **Accepted staleness:** an intra-tab change that alters `focusedTerminal()
  ->shellCwd()` without either trigger firing — a shell `cd` (the accepted
  divergence above) or a split-pane focus change with no intervening MCP call or
  tab switch — leaves the pill on the prior project until the next
  `tokensSavedUpdated` / `onTabChanged`. Accepted: the pill is a live indicator,
  not a ledger, and the next MCP call refreshes it (L-a).

**Supersession note (M-b):** ANTS-3572 § 2.1 states this chip is driven by
`tokensSavedUpdated` "not `onTabChanged`". That is superseded here — scoping the
pill per-project requires the `onTabChanged` refresh above. A one-line forward
reference is added to ANTS-3572 § 2.1 pointing at this spec.

### 2.3 Persistence (per-project, bounded)

New store-only config field, sibling to the global ones:

```jsonc
"claude.tokens_saved_by_project": {
  "<canonicalRoot>": {
    "monthly":  { "YYYY-MM": <int> },   // ≤ 24 keys, foldMonthlyBucket-pruned
    "lifetime": <int>,                  // exact all-time for THIS project
    "since":    "<ISO date>",           // first fold for this project (display)
    "updated":  "<ISO 8601 datetime>"   // last fold — the LRU key (§ 2.5)
  }
}
```

`Config` getter/setter `claudeTokensSavedByProject()` /
`setClaudeTokensSavedByProject(const QJsonObject &)` — store-only (no `save()`,
matching ANTS-3572 INV-7).

`foldTokenSavingsIntoConfig()` (the existing single persist point) is extended.
Because it lives on `MainWindow` and the live map is private to `ClaudeIntegration`,
`ClaudeIntegration` exposes a **whole-map snapshot getter**
`QHash<QString,qint64> sessionSavedBytesByProject() const` (H3). The fold, after
the unchanged global fold, iterates that snapshot, converts each root's bytes →
tokens (`/kCharsPerToken`), and folds each into the by-project object **threading
the accumulator** (`byProject = foldProjectBucket(byProject, root, tokens,
monthKey, nowIso, /*keepMonths=*/24)`, L-1/L3) —
passing the **same** `monthKey = QDate::currentDate().toString("yyyy-MM")` the
global fold computes and `nowIso = QDateTime::currentDateTime().toString(
Qt::ISODate)` (L-3). `foldProjectBucket` folds ONE root and does **not** evict
(M-2); after the loop a single `pruneProjectBuckets(byProject, kMaxTokenProjects)`
evicts to the cap **once over the union**, so eviction is independent of fold
order — a not-yet-folded root can never be dropped and re-added at lifetime 0.
One `config.save()` still covers global + per-project (INV-6).

The live map (+ its touch-seq + memo) is cleared **after** the fold, inside
`endTokenSession()` — never before the `tokenSessionEnding` emit, which runs the
fold synchronously and snapshots the map (INV-12, the per-project analogue of
ANTS-3572 INV-3's fold-before-reset hazard). The modified body:

```cpp
void ClaudeIntegration::endTokenSession() {     // ANTS-3579 additions marked
    emit tokenSessionEnding();          // MainWindow folds global + per-project NOW (sync)
    m_tokenUsage.reset();
    m_sessionSavedBytesByProject.clear();   // ANTS-3579 — AFTER the fold snapshot
    m_projectTouchSeq.clear();
    m_callerCwdRootMemo.clear();
    m_projectTouchCounter = 0;
    emit tokensSavedUpdated(0);          // re-render: focused project's all-time
                                         // (INV-2 fallback), or hidden if it has none
}
```

### 2.4 Display

- **Face:** `↓ <TokenUsageEngine::humanizeCount(faceTokens)> saved`. `faceTokens`
  is the focused project's live **session** saved when > 0 (bytes from
  `sessionSavedBytesForProject` divided by `kCharsPerToken` **once** before
  `humanizeCount`, L2); when the session is 0 but the project has stored history,
  `faceTokens` falls back to its **all-time** (stored lifetime) so the pill never
  reads "↓ 0 saved". **Visibility:** shown iff the feature is on
  (`claudeTokensSavedChipEnabled()`) **AND** `(stored lifetime + live session) > 0`
  for the focused project — both terms in **tokens** (the live session is the
  bytes getter divided by `kCharsPerToken`, L1). Gating on **stored + session** —
  not the live session
  alone — is the deliberate change from ANTS-3572's global pill: a tab switch to a
  project with recorded history must SHOW it, else the pill would hide exactly the
  history the user switched to read (H-1). A project with no history and no
  session stays hidden (clean bar). *(H-1 is a UX decision — flagged for sign-off:
  confirm the session-else-all-time face + stored-or-session visibility.)*
- **Tooltip** (vertical, magnifier-friendly — ANTS-3572 layout kept):
  ```
  This session: <focused project session>
  This month:   <focused project month + session>
  This year:    <focused project YTD + session>
  All-time:     <focused project lifetime + session> saved   (this project, since <date>)
  ──────────────
  All projects: <global lifetime + global session>
  ```
  "This project" numbers read `claude.tokens_saved_by_project[focusedRoot]`:
  all-time = `lifetime`, this-month = `monthly[currentMonthKey]`, this-year =
  `TokenUsageEngine::sumYear(bucket.monthly, currentYear)` — **reusing the exact
  helpers ANTS-3572 uses for the global map** (`sumYear`, § 2.5; no new year-sum
  code, M2) — each plus the live focused-project session. That live term is
  `sessionSavedBytesForProject(focusedRoot)`, which returns **bytes**, divided by
  `kCharsPerToken` **once** here at display; the persisted `lifetime`/`monthly`
  are already tokens and are NOT re-divided (no double-count — Lane-A open q).
  The all-time line also shows the per-project `since`. "All projects" reads the
  untouched global aggregate (`claudeTokensSavedLifetime()` + folded `monthly`)
  **plus the global live session** via `m_integration->tokenUsageReport(false)
  .totalSaved` — the same global getter ANTS-3572 uses, NOT the demoted
  `tokensSavedUpdated` nudge payload (M-c) — so it stays whole even though the
  face now shows only the focused project (INV-4). When the focused root has no
  persisted bucket yet, its month/year/all-time are just the live session value
  and the `(since …)` clause is omitted.

### 2.5 Pure helper (unit-testable, Qt6::Core)

Add to `TokenUsageEngine` (no Widgets, testable without a `MainWindow`):

```cpp
// Fold ONE project's delta into byProject[root]: lifetime += addTokens, monthly
// via foldMonthlyBucket(...,keepMonths), stamp `since` = nowIso.left(10) (date
// portion) if absent, set `updated` = nowIso. Does NOT evict (M-2) — a per-root
// evict would be fold-order-dependent; pruning is a separate single pass below.
QJsonObject foldProjectBucket(QJsonObject byProject, const QString &root,
                              qint64 addTokens, const QString &monthKey,
                              const QString &nowIso, int keepMonths);

// Retain only the `keepProjects` roots with the newest `updated`; ties broken by
// root string DESC so the result is a pure function of the whole map, independent
// of the order roots were folded. Called ONCE after the fold loop (§ 2.3).
QJsonObject pruneProjectBuckets(QJsonObject byProject, int keepProjects);
```

`nowIso` is an ISO 8601 **datetime** (`QDateTime::toString(Qt::ISODate)`), so
same-day folds still order; the root-string tie-break removes the last ambiguity
(INV-5b). Splitting fold from prune (M-2) makes eviction order-independent: all
roots are folded first, then one `pruneProjectBuckets` pass evicts over the union,
so a not-yet-folded root can never be dropped mid-loop and re-seeded at lifetime 0.

The byte→token conversion (live-session bytes → displayed tokens in § 2.4, and
each root's fold-time bytes → stored tokens in § 2.3) divides by the engine's
`kCharsPerToken`. That constant is today a file-local `constexpr` in the
`tokenusageengine.cpp` anonymous namespace (`:49`), unreachable from the widget TU
— which is why the ANTS-3572 chip wrote the bare `/ 4` literal
(`claudestatuswidgets.cpp:525`). ANTS-3579 **promotes `kCharsPerToken` to a public
`constexpr` in `tokenusageengine.h`** so both the new display path and the tests
reference it by symbol (the existing `:525` literal may adopt it later — out of
scope). INV-8's display-division scrape keys on `kCharsPerToken` (M-A).

## 3. Invariants

- **INV-1** — Attribution. Every **successful** MCP dispatch adds
  `max(0, Tracker::baselineFor(tool) − (argBytes + outBytes))` bytes to
  `m_sessionSavedBytesByProject[QFileInfo(caller_cwd).canonicalFilePath()]`. An
  empty `caller_cwd` or an empty canonical path (nonexistent dir) is dropped,
  never bucketed under `""`. Failed calls add 0. *Test:* source-scrape
  `recordDispatch` for the `canonicalFilePath` derive + the `argBytes`/`outBytes`
  subtraction + `+=` under the `succeeded` gate — keyed on those tolerant symbols
  (`baselineFor`, `argBytes`, `outBytes`, `succeeded`, `+=`), NOT a literal
  `max(0, …)` string (the engine idiom is `std::max<qint64>(0, …)`; Lane-A M1). The
  floor math is inline in `recordDispatch` (no pure helper), so this scrape IS its
  test; a separate "pure" test could only re-derive the arithmetic tautologically
  (M-B).
- **INV-2** — Face scope + visibility. The face humanizes (`humanizeCount`) the
  focused project's **session** saved, falling back to its stored **all-time** when
  the session is 0 but history exists (never "↓ 0 saved"). The pill is shown iff
  the feature is on AND `(stored lifetime + live session) > 0` for the focused
  project — so a tab switch to a project with only stored history keeps it visible
  (H-1). *Test:* source-scrape the chip method reads `sessionSavedBytesForProject
  (...)` for the face (positive check — the pre-3579 lambda instead consumed the
  `sessionSaved` signal arg, so this is falsifiable; L2) and that the visibility
  guard reads the per-project **stored-lifetime** getter, not the session alone.
- **INV-3** — Tooltip shape. The tooltip's first block is the four focused-project
  periods (session / month / year / all-time), with the all-time line tagged
  "(this project, since <date>)"; then a separator; then a single "All projects:"
  line (§ 2.4). *Test:* source-scrape the tooltip builder for the per-project
  period reads, the "(this project" tag on the all-time line, and the
  "All projects" literal.
- **INV-4** — Global untouched. `claude.tokens_saved_monthly` / `_lifetime` /
  `_since` semantics are byte-for-byte unchanged (still the true all-projects
  total); the global fold in `foldTokenSavingsIntoConfig` runs first and
  identically to ANTS-3572. The "All projects" tooltip line reads that global
  aggregate — **never** a sum of the per-project buckets (which use a different
  flooring, INV-8). *Test:* the ANTS-3572 `tokens_saved_chip` suite stays green;
  source-scrape shows the global fold block unmodified and the "All projects"
  line sourced from the global getters.
- **INV-5** — Persisted store bounded. `claude.tokens_saved_by_project` holds
  ≤ `kMaxTokenProjects` (64) roots and each root's `monthly` ≤ 24 keys
  (`foldMonthlyBucket`). **INV-5b — deterministic eviction:** eviction to
  `kMaxTokenProjects` runs **once** in `pruneProjectBuckets(byProject, keep)` after
  all roots are folded (NOT inside per-root `foldProjectBucket`, M-2), dropping the
  roots with the oldest `updated` datetime, ties broken by root string — a pure
  function of the union, independent of fold order. *Test:* `pruneProjectBuckets`
  pure test — a 65-root union keeps the 64 newest; a same-`updated` tie evicts the
  deterministic one; `foldProjectBucket` alone never evicts; 25th month prunes.
- **INV-6** — Single persist. `foldTokenSavingsIntoConfig` writes global +
  per-project buckets under **one** `config.save()` (store-only setters before
  it), per-project fold after the global fold. *Test:* source-scrape: exactly one
  `save()` in the method; the per-project block sits after the global block.
- **INV-7** — Focus-change refresh. Switching to a tab in a different project
  re-renders the pill for that project with **no** new MCP call, via the render
  being a named controller method `refreshTokensSavedChip()` that
  `MainWindow::refreshStatusBarForActiveTab()` (itself called by `onTabChanged`)
  invokes alongside the other per-tab chips. *Test:* source-scrape `mainwindow.cpp`
  that `refreshStatusBarForActiveTab` calls `refreshTokensSavedChip()`, AND
  `claudestatuswidgets.{h,cpp}` that the method exists and reads the
  focused-project getter (the render is no longer only a `tokensSavedUpdated`
  lambda).
- **INV-8** — Per-project is an independent per-call estimate, NOT an identity
  with the engine aggregate. It accumulates saved **bytes** per successful call
  (`baseline − (argBytes+outBytes)`, floored **per call**) and divides by
  `kCharsPerToken` once per data-path (display for live bytes, fold for stored —
  never twice on one value, M-1). This deliberately differs from the
  engine's per-**tool** figure (floored **once** over `baseline·nCalls − Σbytes`,
  `tokenusageengine.cpp:131-134`), so `Σ(per-project) ≠ global` in general. The
  authoritative all-projects number is the **global aggregate** (the "All
  projects" line, INV-4), never the per-project sum. *Test:* source-scrape that
  the byte→token `kCharsPerToken` division appears on the display path (not in
  `recordDispatch`) — `kCharsPerToken` is public per § 2.5 — and that the "All
  projects" line reads the global getters (paired with INV-4).
  *(Accepted artifact, I-a: a single-project user may see "(this project)"
  all-time differ slightly from "All projects" all-time for identical activity —
  per-call vs per-tool flooring — a display consequence of the two models, not a
  discrepancy to reconcile.)*
- **INV-9** — Migration. `claude.tokens_saved_by_project` starts absent and
  accrues from the first post-ship fold; pre-feature global history is **not**

## 4. Failure modes

- **Corrupt / missing `claude.tokens_saved_by_project`** (hand-edited to a
  non-object, or absent on first run) → getter returns an empty `QJsonObject`;
  the fold starts a fresh map. No crash, no refusal (mirrors ANTS-3572 § 4).
- **A per-root value that is not an object** (hand-edited) → treated as an empty
  bucket in `foldProjectBucket`; overwritten on that root's next fold. Self-heals.
- **Missing `updated` / `since`** on a bucket → `updated` sorts as oldest (so it
  is evicted first, acceptable); `since` is stamped on the next fold; the tooltip
  omits the `(since …)` clause when absent.
- **Project dir deleted between sessions** → attribution: `canonicalFilePath()`
  returns empty for the gone dir, so live calls under it are dropped (INV-1); the
  persisted bucket lingers (harmless — `lifetime` is historical) until the 64-cap
  LRU-evicts it. The pill only shows it while that project is the focused tab
  (impossible once its terminal is gone).
- **Clock moved backwards / timezone change** → a fold may write an earlier
  `updated` than a prior fold and/or a bucket under an earlier `YYYY-MM`; it
  simply adds into that bucket, and eviction still runs on the (now-nonmonotonic)
  datetime — a wrong project could be evicted, but only among > 64 projects.
  Acceptable for a motivational estimate (mirrors ANTS-3572 § 4).
- **Crash / OOM-kill before a fold** → the in-flight session's per-project
  savings are lost, exactly as the global session is (ANTS-3572 § 4). Estimate,
  not accounting.
- **> 64 projects touched in one live session** → the least-recently-touched
  roots are evicted from the live map (§ 2.1); each re-populates on its next
  attributed call. The focused project (actively called) is never the victim.

## 6. Performance / RAM budget

- **Per MCP call (hot path):** the existing `buildReport(false)` (unchanged) plus
  **one** `QFileInfo::canonicalFilePath(caller_cwd)`. That call may `stat` the
  path — ANTS-3572 § 6 promised "no disk I/O on this path", so this is a new,
  bounded cost. **Mitigation (§ 2.1 memo):** `caller_cwd` is stable within a
  Claude Code session, so the bounded `m_callerCwdRootMemo` map (≤ `kMaxTokenProjects`
  entries, one per distinct `caller_cwd`, cleared wholesale on overflow) makes the
  `stat` run once per distinct `caller_cwd` — not per call — even with several
  projects interleaved; steady state is a `QHash` lookup + a `qint64` add. (The
  memo is `caller_cwd`-keyed while the cap counts on the root-keyed map's size;
  since many `caller_cwd`s can share one root, a pathological session with > 64
  distinct `caller_cwd`s but ≤ 64 roots would clear + re-`stat` occasionally —
  bounded, I1.) No config write on this path (INV-6).
- **Per fold (rare):** the existing 24-month global prune + one `foldProjectBucket`
  per touched root (each a 24-month prune + a 64-root sort) + one `config.save()`.
- **RAM:** the three live maps — `m_sessionSavedBytesByProject`,
  `m_projectTouchSeq`, and `m_callerCwdRootMemo` — are each ≤ `kMaxTokenProjects`
  (64) entries of short `QString`s + a scalar; a few KB total, capped, all cleared
  each session reset. On-disk `tokens_saved_by_project` ≤ 64 roots × (≤ 24 `"YYYY-MM":int` + 2
  scalars + 2 short strings) ≈ a few KB of JSON — same order as the global 24-month
  map, bounded by the 24-month prune plus the 64-root cap. No unbounded growth,
  no new thread / watcher / timer.

## 7. Migration / integration boundary

- New config key `claude.tokens_saved_by_project` only; no existing key changes;
  no schema migration (absent → empty object, § 4). The global keys and their
  meaning are untouched (INV-4).
- `ClaudeIntegration` gains the live map + touch-seq + memo members, the two
  getters, and the `recordDispatch` accumulation — **no** `Config` or `MainWindow`
  dependency (INV-11). `MainWindow::foldTokenSavingsIntoConfig` gains the
  per-project fold loop. `TokenUsageEngine` gains `foldProjectBucket`. `Config`
  gains one accessor pair. `ClaudeStatusBarController` reads the per-project getter
  + config and joins the `onTabChanged` refresh.
- Reuses ANTS-1245's boundary note transitively via ANTS-3572 § 8: saved tokens
  live in `config.json`, not a future consumed-tokens SQLite store.
