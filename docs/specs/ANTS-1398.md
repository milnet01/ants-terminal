# ANTS-1398 — `roadmap_query` filters out section-rollup bullets

## Problem

`roadmap_query` returns `bullets[]` as a flat structured list of
roadmap items. But `RoadmapDialog::parseBullets()` also emits
**section-rollup bullets** for the "N shipped / M planned"
summary cards that appear under each `##` / `###` heading. These
rollups have empty `id`, `headline`, `kind`, and `lanes`, but
carry a `status` emoji. From a 2026-05-16 live response with
`status=active`:

```json
{"bullets":[
  {"headline":"","id":"","kind":"","lanes":[],"status":"🚧"},
  {"headline":"","id":"","kind":"","lanes":[],"status":"📋"},
  {"headline":"Floating prompt-jump button...","id":"ANTS-1330",...},
  ...
]}
```

The two leading entries are rollups; the third is a real item.
A client building an "actionable items" list has to filter the
rollups out client-side. On a 161-bullet active-filter response
~10 rollups appear → ~700 B of token weight per call carrying
no actionable data.

## Goal

Filter rollup bullets out of `bullets[]` server-side. Add a new
optional `include_section_headers` boolean for callers that
want the legacy shape (back-compat). Adjust the `count` and
`filter` echo accordingly.

## Design

### Predicate

A bullet is a **rollup** iff its `id` is empty AND its `headline`
is empty. The two conditions co-occur exactly when
`parseBullets` emits a section-rollup card (the parser uses an
empty headline+id to represent a non-item line that carries
only a status emoji). The `lanes` and `kind` fields are also
typically empty for rollups, but the id+headline pair is the
unambiguous signature.

### Schema change

Add to the `roadmap_query` tool's `inputSchema.properties`:

```jsonc
"include_section_headers": {
  "type": "boolean",
  "default": false,
  "description": "If true, retain section-rollup bullets in
                  `bullets[]` (empty id/headline, status emoji
                  only). Default false — clients that want
                  actionable items get only real bullets.
                  Opt-in for back-compat callers."
}
```

### Behaviour matrix

| `include_section_headers` | `status` | Rollups in `bullets[]`? |
|---|---|---|
| `false` (default) | any (all/active/shipped) | dropped |
| `true` | any | retained verbatim |

The filter applies **after** the status filter, in both the
full-file path (line 974) and the section path (line 923).

### Envelope

`count` reflects post-filter bullets length (matches today's
INV-10 semantics). New optional echo field
`include_section_headers` mirrors the request arg so callers can
verify what they got — only emitted when the request set it
(omitted for the default false case to keep the wire trim).

## Invariants

- **INV-1.** Default behaviour (no `include_section_headers`):
  `bullets[]` contains zero entries where `id` is empty and
  `headline` is empty.

- **INV-2.** With `include_section_headers:true`: response
  shape is identical to the pre-1398 behaviour (rollups
  retained verbatim).

- **INV-3.** The rollup filter runs **after** the status
  filter. A rollup with `status:"🚧"` is dropped under
  `status=active` (without 1398: would be retained, mixed in
  with real in-progress items).

- **INV-4.** `count` reflects post-filter `bullets.size()` —
  the field semantics from ANTS-1247 INV-10 remain intact.

- **INV-5.** `include_section_headers` echo is present in the
  envelope only when the request set the arg. Absent for
  default-false to keep token weight down.

- **INV-6.** The section-mode path (`section` arg present)
  also applies the rollup filter. Section responses have
  their own rollup cards (the per-section `N shipped` cards)
  and should be filtered the same way.

- **INV-7.** Caching invariants from ANTS-1287 / ANTS-1346
  remain valid. The filter runs **post-cache** on the raw
  cached array; the cache itself stores the unfiltered
  bullets (so a follow-up call with
  `include_section_headers:true` doesn't pay a re-parse).

## Test

`tests/features/roadmap_query_filter_section_headers/`:

1. **INV-1 (live call).** Build a markdown fixture with one
   rollup line + one real item. Call `cmdRoadmapQuery` with
   no `include_section_headers`. Assert the response has
   exactly one bullet (the real item), and that bullet has a
   non-empty `id`.

2. **INV-2 (live call).** Same fixture, with
   `include_section_headers:true`. Assert two bullets — the
   rollup (empty id+headline) and the real item.

3. **INV-3 (live call).** Build a fixture with a 🚧 rollup +
   a 🚧 real item. Call with `status:"active"`. Assert one
   bullet (the real item) — the rollup status emoji must not
   leak through.

4. **INV-4 (live call).** Same fixture as INV-1. Assert
   `count` equals `bullets.size()` (post-filter).

5. **INV-5a (live call).** Default call (no
   `include_section_headers`). Assert the envelope does NOT
   carry an `include_section_headers` key.

6. **INV-5b (live call).** Call with
   `include_section_headers:true`. Assert the envelope carries
   `include_section_headers:true`.

7. **INV-6 (live call).** Section-mode fixture with rollup +
   real item under a `## heading`. Call with `section:<slug>`.
   Assert the rollup is dropped.

Label `features;fast`. Live behavioural test — exercises
`cmdRoadmapQuery` directly via a `RemoteControl` instance plus
a fixture markdown file written to a tempdir.

## Out of scope

- Moving rollups to a separate `sections[]` envelope.
  Considered, deferred — adds a second envelope shape clients
  must handle, no clear win over the filter-by-default
  approach. If a future caller wants section-by-section
  summary counts they can be added then.
- Restructuring `parseBullets` to not emit rollups in the
  first place. The dialog UI uses rollups; ripping them out
  of the parser would break the chrome.
- Filtering rollups out of `bullets[]` for `status=all`
  unconditionally without a back-compat door. The opt-in
  flag is the safer migration.

## RAM budget

Zero. Filter runs in O(N) over the cached bullets array;
no new allocations beyond the filtered output array (same
shape as the existing status-filter pass).

## Build cost

~20 LoC added in `cmdRoadmapQuery` (predicate helper +
filter pass at the two emission sites). One new test file
~150 LoC. Schema property addition ~6 LoC in
`claudeintegration.cpp`'s `tools/list` block.
