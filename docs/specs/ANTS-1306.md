# ANTS-1306 — `task_priors` MCP — bundled context for a task description

**Status:** spec draft (2026-05-20).
**Kind:** implement.
**Source:** indie-review-2026-05-13 (roadmap bundle plan pull 37).

One new read-only MCP tool that, given a free-text task description,
returns the project context a session would otherwise gather in 6–8
exploration round-trips at task start: matching spec files, matching
ROADMAP cards, recent commits touching the named files, and related
ADRs. A **pure composer** — it reuses `cmdRoadmapQuery` and
`cmdGitState` and the `parseSpecBody` helper already in
`remotecontrol.cpp`; no new lib, no IPC verb, no persistent state.

## 1. Problem

When a task starts ("add a `foo_bar` MCP tool that reads scrollback"),
the session today does, in sequence:

1. `grep -l` / `Glob` over `docs/specs/` to find related specs, then
   `Read` each candidate.
2. `roadmap_query` to find related cards.
3. `git log` (often `-- <path>`) to see what recently changed in the
   files the task names.
4. `Glob`/`Read` over `docs/decisions/` for related ADRs.

That is 6–8 tool calls and ~10–30 K of mostly-discarded tokens before
the session even proposes an approach. Worse, when the session skips
that legwork it proposes the wrong approach and rewrites — the
expensive failure mode. `task_priors` collapses the legwork into one
call so the right priors land **before** the approach is chosen.

## 2. Goal

One tool, `{description, caller_cwd, max_specs?, max_cards?,
max_commits?, max_adrs?}` in, returning four ranked context buckets:

- **specs** — `docs/specs/ANTS-*.md` files whose body matches the
  description's terms, with a one-line excerpt each.
- **roadmap_cards** — ROADMAP bullets whose headline/body match,
  via the existing `cmdRoadmapQuery`.
- **commits** — recent commits touching the file paths named in the
  description (or, absent any path, recent commits whose subject
  matches a term), via the existing `cmdGitState(op:log)`.
- **adrs** — `docs/decisions/*.md` files whose body matches.

No new persistent state, no index — each call is a fresh streamed
scan plus two internal composer calls. Pairs with the shipped
`spec_query` and `invariant_check` MCP tools for drilling into a
single matched spec after `task_priors` surfaces it.

## 3. Surface

### 3.1 No new lib

`task_priors` is implemented entirely as
`RemoteControl::cmdTaskPriors(const QJsonObject&)` in
`remotecontrol.cpp`, declared public in `remotecontrol.h` next to
`cmdCurrentState` (the existing composer it most resembles). It
reuses, in-process:

- `resolveRootCanonical(m_main, req)` — root resolution + anchor.
- `parseSpecBody(...)` — the existing anonymous-namespace spec parser
  in `remotecontrol.cpp` (shared by `cmdSpecQuery` /
  `cmdInvariantCheck`), used here for spec titles.
- `cmdRoadmapQuery(...)` — for the roadmap-card bucket.
- `cmdGitState(...)` — for the commit bucket.

MCP-only: registered via `registerToolProvider` like `spec_query`;
**not** added to the IPC `dispatch()` switch.

### 3.2 Term extraction

The `description` string is parsed once into three deterministic,
case-folded token sets (extraction order fixed for testability):

1. **ids** — every match of `ANTS-[0-9]+` (case-insensitive),
   upper-cased and de-duplicated. (e.g. `ants-1306` → `ANTS-1306`.)
2. **paths** — every match of
   `[\w./-]+\.(?:cpp|cc|cxx|c|h|hpp|hh|hxx|py|lua|sh|md|json|cmake|txt)`
   (case-sensitive extension), de-duplicated, with any leading `./`
   stripped. (e.g. `src/remotecontrol.cpp`.) A bare basename like
   `remotecontrol.cpp` is kept verbatim — substring matching (§ 3.3)
   still finds it inside a longer path in a spec body.
3. **terms** — every match of `[A-Za-z_][A-Za-z0-9_]{3,}` (≥ 4 chars),
   lower-cased, with the § 3.2.1 stopword set removed, de-duplicated,
   then capped at 25 entries (extraction order preserved) to bound
   per-call work. Tokens already captured as part of an id or path
   still appear here if they independently match the term regex —
   harmless (a term hit and an id hit on the same spec both raise its
   score; § 3.3 counts distinct needles, so no double-count within a
   set).

If after extraction `ids`, `paths`, and `terms` are **all** empty,
the call refuses with `bad_args` (§ 3.6) — a description of pure
stopwords gives nothing to rank against.

#### 3.2.1 Stopword set

A fixed, lower-case set compiled once (process-static
`QSet<QString>`). v1 contents (English function words + generic
task verbs that carry no ranking signal):

```
the a an and or but for nor so yet of to in on at by with from into
this that these those there here when where which while what who whom
will would should could can may might must shall not nor are was were
been being have has had does did doing your you our their its it is be
as if then than also more most some any all each every both
add fix make use new run get set let put via per
```

(the block above is the v1 set; the exact list is the test fixture
for this spec's INV-3 — distinct from the `mcp_tool_prefix_tags`
INV-3 cited under INV-15. Words ≤ 3 chars never reach the stopword
filter — the `{3,}` quantifier already drops them, so `is`/`be`/`an`
etc. are redundant-but-harmless entries.)

### 3.3 Matching & scoring

All matching is **case-insensitive substring** against file bodies /
card text. "distinct-needle count" means: how many distinct entries
of (`ids ∪ paths ∪ terms`) appear at least once in the haystack.

- **specs** — `QDir(docs/specs).entryList("ANTS-*.md")`. For each
  file body: `score = distinctNeedleCount + 5 × (stem ∈ ids ? 1 : 0)`.
  The `× 5` boost makes an explicit `ANTS-NNNN` mention in the
  description float that exact spec to the top. Keep files with
  `score > 0`; sort `score` desc, then filename asc; take `max_specs`.
  Each entry: `{id (filename stem), path ("docs/specs/<file>"),
  title (parseSpecBody.title, may be ""), excerpt, score}`. `excerpt`
  is the first body line containing any needle, trimmed and capped to
  200 chars (UTF-8-safe chop); falls back to the title line when the
  only signal was the id-in-filename boost.
- **roadmap_cards** — one internal `cmdRoadmapQuery({caller_cwd,
  status:"all", limit:500, include_body:true})`. For each returned
  bullet: `haystack = id + " " + headline_oneline + " " + body`,
  where `body` is the `cmdRoadmapQuery`-truncated body (capped at its
  `kRoadmapQueryBodyCap` ~2000 chars) — a needle past that cap in a
  long card is not matched, an accepted v1 bound;
  `score = distinctNeedleCount + 5 × (id ∈ ids ? 1 : 0)`. Keep
  `score > 0`; sort `score` desc, then preserve `cmdRoadmapQuery`
  order (which is document order = priority); take `max_cards`. Each
  entry: `{id, status, headline (the bullet's headline_oneline),
  score}`. If the internal query is non-ok, the bucket collapses to
  `[]` (ok preserved — INV-9).
- **commits** — if `paths` is non-empty: for each path (first 5),
  `cmdGitState({caller_cwd, op:"log", path:<path>, n:max_commits})`,
  merge the returned `commits[]` de-duplicated by `sha` (the
  abbreviated `%h` hash `cmdGitState` emits — same key
  `cmdCurrentState`'s git path uses; abbreviated-hash collisions
  across one repo's history are vanishingly rare and accepted in
  v1). Else (no
  paths): `cmdGitState({caller_cwd, op:"log", n:50})` and keep
  commits whose lower-cased `subject` contains any needle. Either
  way: sort by `date` desc (string compare on the `%cs`
  `YYYY-MM-DD` form is chronological), stable; take `max_commits`.
  Each entry: `{sha, subject, date}`. Any non-ok / not-a-repo
  internal result collapses the bucket to `[]` (ok preserved —
  INV-9), mirroring `cmdCurrentState`'s git fallback.
- **adrs** — `QDir(docs/decisions).entryList("*.md")` minus
  `README.md`. For each body: `score = distinctNeedleCount`. Keep
  `score > 0`; sort `score` desc, then filename asc; take `max_adrs`.
  Each entry: `{path ("docs/decisions/<file>"), title (first
  `# ` heading line, trimmed; "" if none), score}`.

Every candidate `ANTS-*.md` / ADR body is read once, whole, via
`QFile::readAll()` (spec/ADR files are small — ≤ tens of KiB) for
distinct-needle scoring; the extra **line-by-line** excerpt scan
runs only on the ≤ `max_specs` already-selected spec files, not on
every candidate.

### 3.4 Caps & defaults

| Arg | Default | Clamp |
|-----|---------|-------|
| `max_specs`   | 5 | [1, 20] |
| `max_cards`   | 5 | [1, 20] |
| `max_commits` | 5 | [1, 20] |
| `max_adrs`    | 3 | [1, 20] |

A present-but-out-of-range value is clamped (not refused); a
present-but-non-integer value is ignored (default used). Each
`*_count` field reflects the **pre-cap** number of matches so the
caller can tell "5 of 23 specs matched" from "5 of 5".

### 3.5 Envelope

```json
{ "ok": true,
  "terms": ["scrollback","reads","tool"],
  "ids": ["ANTS-1306"],
  "paths": ["src/remotecontrol.cpp"],
  "specs": [
    {"id":"ANTS-1301","path":"docs/specs/ANTS-1301.md",
     "title":"recent_errors MCP — scrollback error extraction",
     "excerpt":"New tool reads the focused tab's scrollback ...",
     "score":4} ],
  "specs_count": 1,
  "roadmap_cards": [
    {"id":"ANTS-1301","status":"✅",
     "headline":"recent_errors MCP — scrollback error extraction.",
     "score":3} ],
  "cards_count": 1,
  "commits": [
    {"sha":"622830b","subject":"ANTS-1301: recent_errors MCP — scrollback error extraction — pull 36.","date":"2026-05-20"} ],
  "commits_count": 1,
  "adrs": [],
  "adrs_count": 0 }
```

`*_count` is the pre-cap total; the arrays are post-cap. An all-empty
result (`description` had needles but nothing matched) is `ok:true`
with four empty arrays and four `0` counts — a valid answer, not an
error.

### 3.6 Refusal codes

| code | when |
|------|------|
| `bad_args` | `description` missing, empty, or yields zero ids **and** zero paths **and** zero terms after extraction. (Reuses the input-validation code per `mcp-error-codes.md` § 1.) |
| `no_project` | root unresolved (no `caller_cwd`, no focused tab). (`mcp-error-codes.md` § 2.) |

(`caller_cwd_required` is emitted upstream by the dispatcher per
ANTS-1404 before the handler runs, when `caller_cwd` is absent.)

### 3.7 Edge cases

| Input | Behaviour |
|-------|-----------|
| `description` of pure stopwords / punctuation | `bad_args` — nothing to rank. |
| `docs/specs/` absent | `specs:[]`, `specs_count:0` (not an error). |
| `docs/decisions/` absent | `adrs:[]`, `adrs_count:0`. |
| Not a git repo / git missing | `commits:[]`, `commits_count:0`, `ok:true`. |
| `cmdRoadmapQuery` non-ok (no ROADMAP.md) | `roadmap_cards:[]`, `cards_count:0`, `ok:true`. |
| ROADMAP has > 500 bullets | ranking is over the first 500 returned (the high-priority head of the document); documented limitation, not an error. |
| Same path named twice in `description` | de-duplicated before the git scan. |
| Spec matched only by `ANTS-NNNN` in its filename | included (id boost), `excerpt` falls back to the title line. |
| > `max_specs` specs match | array capped, `specs_count` = full pre-cap total, same for the other three buckets. |

## 5. Memory & cost budget

- Per call: one `QDirIterator`-free `QDir::entryList` of `docs/specs/`
  (≤ ~200 entries here) + `docs/decisions/` (≤ ~10), one whole-file
  `readAll` at a time (spec/ADR files ≤ tens of KiB), one
  `cmdRoadmapQuery` (caps its own response at 500 bullets), and up
  to 5 `cmdGitState(op:log)` spawns — one per named path, capped at
  5 (or a single spawn in the no-path subject-filter branch). Each
  git call carries its own 5 s wall budget, so the aggregate git
  wall time is ≤ 25 s worst case. No persistent state, no cache,
  no index.
- Worst-case heap: the four capped result arrays (≤ 20 entries each ×
  ≤ ~1 KiB) + one whole spec/ADR file in flight (≤ tens of KiB) + the
  ≤ 500-bullet roadmap response held transiently ≈ well under 1 MiB.
- Time: dominated by the spec/ADR file reads (sub-100 ms on this
  repo) and the git log (its own 5 s wall budget bounds pathological
  histories). The roadmap query is mtime-TTL-cached (ANTS-1117).
- Deliberately NO cache: a task-start bundle is read once per task;
  caching would need invalidation on every spec/commit/ROADMAP edit
  for no reuse benefit.

## 6. Out of scope

- Semantic / embedding similarity. Ranking is distinct-needle-count
  substring matching; that is the cheap 90 % (Karpathy § 2). Fuzzy /
  vector ranking is a later concern (overlaps the planned ROADMAP
  items ANTS-1305 `similar_code` and ANTS-1637 codebase index).
- Returning full spec / ADR bodies. `task_priors` returns pointers +
  one-line excerpts; the caller drills in with `spec_query` /
  `Read` on the specific hit it cares about.
- Ranking ROADMAP cards beyond the first 500 bullets (the
  `cmdRoadmapQuery` `limit:500` head). The high-priority head of the
  document is what a task-start query needs.
- A persistent index of specs / ADRs / commits — see the planned
  ROADMAP item ANTS-1637.
- Cross-project scope: `task_priors` reads only the caller's resolved
  project root.
