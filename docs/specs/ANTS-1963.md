# ANTS-1963 — `spec_log` MCP tool (write Status / cold-eyes loop / INV entries into `docs/specs/*.md`)

**Status:** accepted (2026-06-03) — implemented on main, feature tests green (cold-eyes loops 1–2 folded).
**Kind:** implement.
**Source:** ROADMAP.md ANTS-1963 (in-session-2026-06-03 — the ANTS-1961/1962
session spent ~30 `Edit` calls maintaining two specs by hand).
**Pairs with:** `spec_query` (the read counterpart, `cmdSpecQuery` — shares
the `isValidSpecId` + per-shape routing); `changelog_log` / `roadmap_log`
(the structured-markdown writers whose caller_cwd + atomic-write + op
design this mirrors).
**Contract:** [`docs/standards/specs.md`](../standards/specs.md) (the spec
shape `spec_log` edits — Status lifecycle § 5.6, INV bullet form § 3.5,
cold-eyes loop log § 5.7).

## 1. Problem

`spec_query` reads a spec; nothing **writes** one. So the three recurring
spec mutations all fall back to `Edit`/`Write`:

1. **Flip the `Status:` line** as a spec moves `spec draft → accepted →
   shipped X.Y.Z`, or records `cold-eyes loops 1–N folded`.
2. **Append a cold-eyes loop-log entry** each loop.
3. **Append a new `INV-N`** without renumbering the others.

The ANTS-1961/1962 session did all three by hand across two specs — ~30
`Edit` round-trips, each re-emitting surrounding context. `roadmap_log`
and `changelog_log` already removed exactly this tax for their files;
`spec_log` is the missing third sibling.

**Layman:** lets Claude update a spec's status line and review log through
a cheap Ants command instead of expensive hand-edits to the markdown.

### 2.1 Target resolution (reused from `spec_query`)

- `id` (string) — `ANTS-NNNN` → `docs/specs/<id>.md`; `phase_<NN>_<topic>`
  → `docs/phases/<id>.md`. Validated by the existing `isValidSpecId`; a
  malformed id → `bad_id`.
- `path` (string) — project-relative escape hatch. Unlike the read-only
  `cmdSpecQuery` (which uses an inline `no leading /, no ..` check), this
  **write** verb routes the `path` arg through
  `PathValidation::validatePath(path, rootCanonical, "spec_log", "path")`
  (`allowOutsideRoot=false` — specs live in-root) per the ANTS-1295
  mandate, so it also gets NFC / control-char / canonicalisation
  hardening; a malformed or root-escaping `path` → `bad_path`. Exactly one
  of `id` / `path` is required (neither → `bad_id`, matching the reused
  `cmdSpecQuery` refusal at `src/remotecontrol.cpp:8217-8220`; `path` wins
  when both are set, as in `spec_query`).
- Resolved under `resolveRootCanonical`; unresolved root → `no_project`.
  The target **file** must already exist (`spec_log` edits a spec, it does
  not scaffold one) — absent → `not_found`. (A file that exists but is
  missing the section/line an op needs is a distinct refusal —
  `unrecognised_format`, § 2.2 — so a caller can tell "no such spec" from
  "spec present, wrong shape".)
- `caller_cwd` Required (empty → `caller_cwd_required`).

### 2.2 Ops

`op` (string, required) — one of `set_status` | `append_loop` |
`append_inv`; unknown or absent → `bad_mode`. The pure transforms live in
`SpecLog`. **Refusal split (mirrors ANTS-1962):** the *handler* owns the
arg/cwd/path refusals (`bad_id`, `bad_path`, `bad_mode`, arg-shape
`bad_args`, `no_project`, `caller_cwd_required`, file-absent `not_found`,
`write_failed`) — the pure layer has no filesystem or cwd; the
`EditResult.code` carries only the *structural* refusals computed from the
content string (`unrecognised_format` for a missing section/line,
`bad_args` for a duplicate `INV-N`), which the handler surfaces verbatim.

```cpp
namespace SpecLog {
struct EditResult { bool ok = false; QString content; QString code; QString error; };

// op:"set_status" — replace the text after the first `**Status:**` line.
EditResult setStatus(const QString &content, const QString &newStatus);

// op:"append_loop" — append a `- **<label>** — <body>` bullet at the end
// of the `## … Cold-eyes loop log` section (creating the section at EOF
// when absent).
EditResult appendLoop(const QString &content, const QString &label,
                      const QString &body);

// op:"append_inv" — append a `- **INV-N** — <body>. *Test:* <test>.`
// bullet at the end of the `## … Invariants` section (never renumbers).
EditResult appendInv(const QString &content, const QString &invId,
                     const QString &body, const QString &test);
}
```

- **`set_status`** — arg `status` (required, non-empty, else `bad_args`):
  the literal text that follows `**Status:** ` (e.g. `accepted (2026-06-03)`
  or `spec draft, cold-eyes loops 1–4 folded (2026-06-03)`). The verb
  rewrites the first line matching `^\*\*Status:\*\*` and refuses
  `unrecognised_format` (with a hint) if the spec has no Status line. No
  lifecycle-enum validation — the caller owns the wording (specs.md § 5.6
  lists several valid forms); the verb only requires it non-empty.
- **`append_loop`** — args `loop_label` (required, e.g. `Loop 3
  (2026-06-03)`) + `body` (required prose). Renders
  `- **<loop_label>** — <body>` and appends it at the end of the **first**
  `^## ` section whose heading text contains `Cold-eyes loop log`
  (case-insensitive substring). When no such section exists, the verb
  appends a new `## Cold-eyes loop log` heading + the bullet at EOF (so a
  spec missing the section is repaired, not refused).
- **`append_inv`** — args `inv_id` (required, must match `^INV-[0-9]+$`
  else `bad_args`), `body` (required), `test` (optional — the `*Test:*`
  clause). Renders `- **<inv_id>** — <body>.` plus ` *Test:* <test>.` when
  `test` is supplied, and appends at the end of the **first** `^## `
  section whose heading text contains `Invariants` (case-insensitive
  substring). Refuses `bad_args` if `inv_id` already appears as an `INV-N`
  bullet (no silent duplicate / renumber — specs.md § 3.5 / § 5.5 "never
  renumber"); refuses `unrecognised_format` if the spec has no Invariants
  section.

### 2.3 Section append semantics

"Append at the end of a section" = insert after the section's last
non-blank content line and before the next `^## ` heading (or EOF). The
inserted bullet is separated from prior content by exactly the existing
inter-bullet spacing (no double blank line). Fenced regions inside a
section are skipped when scanning for the next `^## ` boundary (a pasted
`## ` inside a fence is not a section break — the same fence behaviour the
`mcp-feedback-files.md` parser contract defines: `^\s{0,3}(```|~~~)`,
closed on the same fence char). `###`+ headings never end a `## ` section.

### 2.4 Write + response

- Atomic via `QSaveFile` (the `changelog_log` / `roadmap_log` pattern); a
  failed commit leaves the original byte-for-byte untouched →
  `write_failed`. A test-only failure seam
  (`setForceSpecWriteFailForTest`, mirroring `g_forceCounterCommitFail`,
  `src/remotecontrol.cpp:3202`) forces the commit to fail for the
  atomicity test.
- Success response: `{ok:true, op, id?, path, line, bytes_written}` —
  `line` is the 1-based line the edit landed on (the rewritten Status line,
  or the appended bullet). When `append_loop` creates the section, `line`
  is the appended **bullet** line, not the new heading line.

## 3. Invariants

- **INV-1** — `spec_log` edits an existing spec only; it never scaffolds a
  new file (absent target → `not_found`) and only mutates within the
  routed `docs/specs|phases/<id>.md` (or project-relative `path`).
  *Test:* T6.
- **INV-2** — Target routing reuses `isValidSpecId`: `ANTS-NNNN` →
  `docs/specs/`, `phase_*` → `docs/phases/`; malformed `id` → `bad_id`;
  `path` with leading `/` or `..` → `bad_path`; neither `id` nor `path` →
  `bad_id` (matching `cmdSpecQuery`). *Test:* T6.
- **INV-3** — `caller_cwd` Required (empty → `caller_cwd_required`);
  unresolved root → `no_project`. *Test:* T6.
- **INV-4** — `op` ∈ {`set_status`, `append_loop`, `append_inv`}; unknown
  or absent → `bad_mode`. *Test:* T6.
- **INV-5** — `set_status` rewrites the first `^\*\*Status:\*\*` line's
  trailing text to the supplied `status` (required, non-empty else
  `bad_args`) and changes nothing else; a spec with no Status line →
  `unrecognised_format`. *Test:* T1.
- **INV-6** — `append_loop` appends `- **<loop_label>** — <body>` at the
  end of the `Cold-eyes loop log` section; when that section is absent it
  appends a new `## Cold-eyes loop log` heading + the bullet at EOF.
  *Test:* T2, T5.
- **INV-7** — `append_inv` appends `- **<inv_id>** — <body>.` (plus
  ` *Test:* <test>.` when `test` given) at the end of the `Invariants`
  section, never renumbering existing INVs; `inv_id` not matching
  `^INV-[0-9]+$` → `bad_args`; an `inv_id` already present → `bad_args`
  (no duplicate); no Invariants section → `unrecognised_format`. *Test:*
  T3, T4.
- **INV-8** — Section append inserts before the next `^## ` boundary (or
  EOF), skipping fenced regions and `###`+ headings when locating that
  boundary. *Test:* T2, T3, T8.
- **INV-9** — Writes are atomic (`QSaveFile`); a failed write leaves the
  original untouched and returns `write_failed`. *Test:* T7.
- **INV-10** — Success returns `{ok, op, id?, path, line, bytes_written,
  file_bytes}` (`file_bytes` added by ANTS-3724, which this bullet had not
  recorded), plus `previous_status` on `set_status` (INV-12).
  *Test:* T1, T2, T3, T12, T13.
- **INV-11** — `SpecLog::setStatus` / `appendLoop` / `appendInv` are pure
  string transforms in `ants_core_lib`, unit-testable without the MCP
  layer. *Test:* T1–T5 drive them directly.

## 4. RAM / build cost

- The `SpecLog` transforms are pure in-memory string edits; the only
  buffer is the spec file read to mutate (specs are a few KB–tens of KB).
  No cache, no retained state.
- New sources `src/speclog.{h,cpp}` join the existing `ants_core_lib` —
  **no new build target**. The feature-conformance test joins an existing
  `tests/features/*` bundle. External libs: none beyond Qt6 Core.

## 5. Out of scope

- Scaffolding a new spec from the specs.md template — that is a distinct
  `op:"create"`; deferred (the dominant cost is the three edit ops above).
- Editing arbitrary prose sections (Problem / Surface) — `spec_log` owns
  only the three structured mutations; freeform body edits stay on `Edit`.
- Lifecycle-enum validation of the Status string — caller owns the wording.
- `phase_*` → `docs/phases/` routing is inherited from `isValidSpecId` for
  parity with `spec_query`, but this repo has no `docs/phases/` dir, so the
  feature tests exercise only `ANTS-NNNN` routing; phase routing is
  untested surface here (covered by `spec_query`'s own tests).
