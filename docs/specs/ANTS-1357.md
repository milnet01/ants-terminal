# ANTS-1357 — MCP idempotent-read response cache

**Status:** spec, ship-ready after cold-eyes pass.
**Source:** indie-review-2026-05-14 (self-observed).
**Predecessor:** ANTS-1247's per-call `roadmap_query` cache established
the 100 ms TTL pattern; this spec generalises it across the four
cheapest idempotent reads.

## 1. Problem

Four MCP read verbs return values that are stable on the timescale of
a single assistant turn:

| Tool                  | Source                              | Stability |
|-----------------------|-------------------------------------|-----------|
| `get_cwd`             | focused-tab `shellCwd()` or echo    | ms-stable: terminals don't `cd` between back-to-back calls |
| `get_environment`     | `/proc/<shellPid>/environ` snapshot | ms-stable for interactive shells; a sourced script or `claude --env-set` between back-to-back calls would mask within the 100 ms TTL — acceptable bound |
| `tab_list`            | RemoteControl tab enumeration       | ms-stable: tab create/close is a UI event |
| `last_audit_summary`  | last `.audit-summary.json` on disk  | ms-stable: file mtime granularity is 1 s |

When an assistant chains multiple subagents or retries a tool, the
same `(tool, args)` pair fires repeatedly. Today every call re-walks
the tab list / re-reads `/proc` / re-parses the audit summary file
and re-serialises a fresh response, paying both compute on the
Ants side and token cost on the Claude side (the same JSON is
re-quoted in the transcript).

**Token impact, measured 2026-05-15:**

- `tab_list` over a 3-tab session: ~340 bytes / call → ~85 tokens.
- `get_environment` after `keys` filter: ~420 bytes / call → ~105 tokens.
- `get_cwd` (no `caller_cwd`): ~80 bytes / call → ~20 tokens.
- `last_audit_summary` (no cached audit): ~140 bytes / call → ~35 tokens.

A subagent fan-out that hits all four twice burns ~490 tokens of
redundant payload; with five subagents in flight that's ~2 450 tokens
of pure cache-miss noise per turn.

## 2. Design

### 2.1 Where the cache lives

`ClaudeIntegration` owns the cache. Lookup happens in `processTools`
**before** the registry dispatch at `claudeintegration.cpp:2482`. The
cache short-circuits straight to `responseText` so the existing
`wrapMcpData` + `m_tokenUsage.recordCall` paths stay in their current
positions — the cache transparent to telemetry and the data-wrap.

Rationale: two of the four cached tools (`get_cwd`, `get_environment`)
live as MainWindow lambdas, not `RemoteControl::cmd*` methods. A
cache at the dispatch layer covers both cases with one wrapper.

### 2.1.1 `kRcUnavailable` constant move

The `kRcUnavailable` literal is currently a `static constexpr` inside
`MainWindow::setupClaudeIntegration()` (`mainwindow.cpp:3721-3723`),
not visible from `claudeintegration.cpp`. INV-5(b) requires the cache
insert path to compare against this literal.

Promote it to an `inline constexpr` in `claudeintegration.h` (next to
the `ToolHandler` typedef at `claudeintegration.h:187`):

```cpp
// ANTS-1357 — shared with the idempotent-read cache, which must
// reject this transient startup-window envelope.
inline constexpr const char *kMcpRcUnavailable =
    "{\"ok\":false,\"error\":\"remote-control unavailable\","
    "\"code\":\"no_remote_control\"}";
```

`mainwindow.cpp` then references `ClaudeIntegration::kMcpRcUnavailable`
(or a free constant — placement detail) and the old local `constexpr`
deletes. Byte-identity preserved.

### 2.2 Cache structure

```cpp
struct CachedResponse {
    qint64  stampMs;     // QDateTime::currentMSecsSinceEpoch
    QString response;    // unwrapped responseText
};
QHash<QString, CachedResponse>  m_idempotentReadCache;
QList<QString>                  m_idempotentReadLru;
static constexpr int            kIdempotentReadCacheCap = 32;
static constexpr qint64         kIdempotentReadTtlMs    = 100;
```

Key = SHA256 hex (16 chars, ANTS-1283 INV-4 precedent) of:
`toolName + '\0' + QJsonDocument(argsObj, Compact).toJson()`.

LRU policy: `QList` of keys in MRU-first order; on hit, move-to-front;
on insert, push-front + evict back if `size() > kCap`. Avoids a
separate `Q_HASH_LRU_CACHE` template — the access pattern is dominated
by hits (cache is small + TTL is short).

### 2.3 Allowlist

Hardcoded set of four tool names:

```cpp
static const QSet<QString> kIdempotentReadTools = {
    QStringLiteral("get_cwd"),
    QStringLiteral("get_environment"),
    QStringLiteral("tab_list"),
    QStringLiteral("last_audit_summary"),
};
```

**No other tool is cached.** Tools with side effects
(`debt_sweep_apply_fix`, `verify_changes`, `session_memory` set/delete),
tools that mutate UI (`send-text`, `launch`), and tools with
unbounded args (`workspace_search`, `file_outline`) are out by
construction.

### 2.4 Control flow

```
processTools::tools/call:
  cacheable = (toolName in kIdempotentReadTools)
  cacheKey  = sha256_hex_16(toolName + '\0' + compactArgs)
  cachedHit = false
  if (cacheable) {
    if (cached = m_idempotentReadCache.find(cacheKey);
        cached != end &&
        nowMs - cached->stampMs <= kIdempotentReadTtlMs) {
      responseText = cached->response;
      moveToFront(cacheKey);
      toolHandled = true;
      cachedHit   = true;
    }
  }
  if (!toolHandled) {
    // existing get_session_info inline path / m_toolProviders dispatch ...
  }
  if (toolHandled && cacheable && !cachedHit
      && !responseText.isEmpty()
      && responseText != QString::fromUtf8(kRcUnavailable)) {
    insertCache(cacheKey, {nowMs, responseText});  // INV-5 enforced
  }
  // wrapMcpData + recordCall + content emit — unchanged from today
```

`get_session_info` lands first in the existing chain
(`claudeintegration.cpp:2472-2481`); it is not in the allowlist so
`cacheable=false` and the inline path runs unchanged. The cache short-
circuit applies only to allowlisted tools.

`recordCall` continues to fire on every hit so `token_usage` accounts
for the wire bytes the assistant actually paid (the cache saves
Ants-side compute and Claude-side input tokens, not transcript bytes
— those are identical to a non-cached response). See INV-8.

### 2.5 Invariants

- **INV-1** Hit response is byte-identical to the response a miss
  would have produced at `stampMs`. (No transform, no re-wrap.)
- **INV-2** TTL ≤ 100 ms wall-clock. Entries older than 100 ms are
  treated as miss and overwritten.
- **INV-3** Cache size ≤ 32 entries. Insert past cap evicts the
  least-recently-used entry.
- **INV-4** Allowlist is enforced at lookup AND insert. No path
  inserts a non-allowlisted tool.
- **INV-5** Two responses are **never** inserted into the cache:
  (a) an empty `QString` (the lambda-side idiom for
  `!terminalForCaller` / `pid <= 0` / `/proc` read failure used by
  `get_cwd` and `get_environment`), and
  (b) the `kRcUnavailable` literal at `mainwindow.cpp:3721`
  (`tab_list` / `last_audit_summary` return this when
  `RemoteControl` is missing — a transient startup window, not an
  idempotent answer).
  Rationale: these signal "I couldn't answer this call," not "the
  answer is X." Both are recoverable within a single ms.
  Cold-eyes 2026-05-15 verification: the four providers' other
  failure modes (`cmdLastAuditSummary` returning
  `{"ok":false,"code":"not_audited"}`; `cmdTabList` always returning
  `{"ok":true,…}`) are **valid idempotent answers** — same input,
  same state, same response — and ARE cached. The 100 ms TTL bounds
  staleness on those error envelopes to a single ms.
- **INV-6** Cache is per-`ClaudeIntegration` instance — never shared
  across processes. (Implicit from in-memory storage; spelled out
  here so a future refactor doesn't drift to a global.)
- **INV-7** `wrapMcpData` runs on the cached response on every hit
  (same as miss). The cache stores the *pre-wrap* text.
  Depends on `wrapMcpData` being pure (verified
  `claudeintegration.cpp:2543-2577`) — sentinel sub is the only
  transform and is deterministic in `payload`.
- **INV-8** `m_tokenUsage.recordCall` runs on every hit. The cache
  is invisible to wire-level telemetry — a hit looks identical to a
  miss in byte counts. Rationale: `token_usage` reports the bytes
  the wire actually carried, not the work skipped on the server
  side. The token savings this spec captures live in the **assistant's
  context window** (where the cached response replaces the alternative
  of re-issuing the tool call from a subagent and paying input tokens
  on the re-quoted response), not in `token_usage` numbers.
  A future `cache_hit` annotation on the report is out of scope.
- **INV-9** Cache key includes the full `argsObj` (compact JSON).
  Tools whose provider semantics ignore parts of `args` will miss on
  no-op arg variation. Verified 2026-05-15:
  - `tab_list` (`mainwindow.cpp:3841-3846`) — ignores `args` entirely.
  - `get_cwd` (`mainwindow.cpp:3736-3751`) — uses `caller_cwd` only.
  - `get_environment` (`mainwindow.cpp:3791-3813`) — uses `caller_cwd`
    only (forwards to `terminalForCaller`).
  - `last_audit_summary` (`remotecontrol.cpp:2059-2137`) — uses
    `caller_cwd` + an optional `severity_floor` arg.
  This is by design — consistent in-session callers (subagents
  threading the same `caller_cwd`) hit; callers that randomise
  non-semantic args pay miss cost (no worse than today).

### 2.6 RAM budget

Worst-case entry: `last_audit_summary` at ~512 B response + 16-byte key +
QHash overhead ≈ 600 B. 32-entry cap → **~19 KB ceiling**, comfortably
inside the 32 GiB host budget and below the existing `m_roadmapCacheBullets`
allocation order.

## 3. Test surface

The MCP dispatch core today lives inside a `QLocalSocket::readyRead`
lambda in `onMcpConnection` (`claudeintegration.cpp:1187-2538`) — it
is not a standalone callable. Extracting a `processToolsCall(name,
args) → QJsonObject` method from the lambda is a real refactor and
out of scope for this token-reduction bundle. Instead, the cache
itself is the test surface — its put/get/TTL/LRU semantics are
exercisable through a direct cache API on `ClaudeIntegration`:

```cpp
// claudeintegration.h — test-only seam
QString  tryGetIdempotentReadCacheForTest(
    const QString &toolName, const QJsonObject &args) const;
void     putIdempotentReadCacheForTest(
    const QString &toolName, const QJsonObject &args,
    const QString &response);
int      idempotentReadCacheSizeForTest() const;
QStringList idempotentReadCacheLruForTest() const;
```

These call the **same** private helpers (`tryGetCached`,
`maybeInsertCached`) that the in-lambda cache check + insert uses.
The integration with `processTools` rides on code review of the ~40
LOC diff at the dispatch site — same trade as ANTS-1364.

`tests/features/mcp_idempotent_read_cache/`:

1. **HitWithinTtl** — `put(tab_list, args, "RESP")`; `tryGet(tab_list,
   args)` within 50 ms returns `"RESP"`. Provider not driven.
2. **MissAfterTtl** — same, `QTest::qWait(120)` between put and get.
   `tryGet` returns `QString()`.
3. **MissOnDifferentArgs** — `put(tab_list, args_a, "RESP_A")`;
   `tryGet(tab_list, args_b)` returns `QString()`.
4. **NonAllowlistedNotInserted** — `put(workspace_search, args, "X")`
   ; `cacheSizeForTest()` stays zero. Verifies INV-4 at insert.
5. **LruEviction** — `put` 33 distinct `(tool, args)` pairs across
   allowlisted tool names. `cacheSizeForTest() == 32` after; first-
   inserted key absent from `cacheLruForTest()`.
6. **EmptyResponseNotInserted** — `put(tab_list, args, "")` ;
   `cacheSizeForTest()` stays zero. Verifies INV-5(a).
7. **RcUnavailableNotInserted** — `put(tab_list, args,
   QString::fromUtf8(kMcpRcUnavailable))`; `cacheSizeForTest()` stays
   zero. Verifies INV-5(b).
8. **ArgsAreKeyMaterial** — `put(tab_list, {"caller_cwd":"/a"},
   "RESP_A")`; `put(tab_list, {"caller_cwd":"/b"}, "RESP_B")`;
   both retrievable; `cacheSizeForTest() == 2`. Documents INV-9.

The end-to-end integration tests (cache transparently interposes on
real `processTools` traffic) live in the existing
`tests/features/mcp_tools_list_schema/` and `mcp_*` lanes — those
will pass unchanged because INV-1 (hit byte-identical to miss) holds.
A regression that broke wire bytes would fail those without needing
a new integration test.

## 4. Build cost

- ~120 LOC added to `claudeintegration.cpp` (cache struct + ~40 LOC
  at the dispatch site).
- ~25 LOC added to `claudeintegration.h` (members + 4 test
  inspectors + 2 constants + `kMcpRcUnavailable` constant move).
- ~3 LOC change in `mainwindow.cpp` (remove local `kRcUnavailable`,
  re-point references at the shared constant).
- New test target: ~120 LOC C++ + ~25 LOC CMake (no UDS, no
  dispatch-refactor).

## 5. Out of scope

- **`roadmap_query` is NOT in the allowlist.** It has its own cache
  inside `RemoteControl` keyed on `(path, mtime)`. Adding it to the
  idempotent-read cache would double-cache without saving cycles.
- **`get_session_info` / `token_usage` are NOT in the allowlist.**
  They're control-plane (mutate `m_tokenUsage` snapshots, read
  live state). Caching would defeat their purpose.
- **CLI surface unchanged.** Cache is invisible to `--remote-*` flags;
  IPC verbs continue to call `cmd*` directly.
- **No persistence.** Cache is in-memory only; restart wipes it.
  Matches the spec's "ms-stable" framing — a restart is far past TTL.

## 6. Migration

None. New behaviour layers on top of existing dispatch with no
schema or contract changes.
