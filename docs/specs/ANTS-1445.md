# ANTS-1445 — prompt-injection fence sweep across `*_synthesis_prompt` MCP verbs

Source: deferred from cold-eyes loop 3 security H-A (2026-05-17),
generalises ANTS-1397 INV-8's `<chunk_report>` fence to all
synthesis-prompt verbs. ANTS-1448 documents the same-uid trust model
the fence sits inside.

## 1. Goal

When an MCP synth-prompt verb splices third-party content (per-lane
reports, threat-model extras, dep reports) into a prompt handed to a
subagent, that content must be wrapped in a structural fence so the
subagent treats it as quoted data rather than operator instructions.
Without the fence, a hostile reviewer report (or a hostile
contributor's CLAUDE.md / SECURITY.md / .semgrep.yml) can pass
instructions that the synth model would obey.

Precedent: ANTS-1397 INV-8 ships
`<chunk_report file="…">…</chunk_report>` for
`test_audit_synthesis_prompt`. This spec extends the precedent to
`indie_review_synthesis_prompt`.

## 2. Surface audit

| Verb                                | Status pre-1445       | Status post-1445 |
|-------------------------------------|-----------------------|------------------|
| `test_audit_synthesis_prompt`       | Fenced (ANTS-1397)    | Unchanged        |
| `indie_review_synthesis_prompt`     | **No fence**          | Fenced           |
| `cold_eyes_brief`                   | Paths-only, no body   | Unchanged        |
| `cold_eyes_cross_doc_diff`          | Returns findings only | Unchanged        |
| `cold_eyes_fold_in` / `single_doc`  | Returns findings only | Unchanged        |

The `cold_eyes_*` verbs never splice third-party doc bodies into a
prompt (the brief tells the subagent which doc paths to Read; the
subagent fetches them itself). No fence is required there. False-pos
ledger entries spliced into briefs by `falsepos::formatForBrief`
already wrap with 4-backtick data fences + sentinels (precedent).

## 3. Implementation

`IndieReviewEngine::synthesisPrompt`
(`src/indiereviewengine.cpp:613`) now wraps each per-lane report in
`<lane_report lane="…">…</lane_report>`. Both the open marker
(`<lane_report`) and the close marker (`</lane_report>`) are
escaped to `&lt;lane_report` / `&lt;/lane_report&gt;` inside the
content so the outer fence pair stays unique. The `## Lane: <name>`
markdown heading is retained outside the fence for human-readable
sectioning.

When the optional `threat_model_extras` argument is non-empty the
helper applies the same fence pair (`<threat_model>…</threat_model>`)
with both open and close tags escaped. Even though today's extras
come from project-controlled docs (CLAUDE.md / SECURITY.md /
.semgrep.yml), the uniform "quote, don't narrate" contract keeps the
prompt model from drifting if a future contributor adds a
user-controlled extras source.

## 4. Invariants

- INV-1: per-lane content is wrapped in
  `<lane_report lane="<name>">…</lane_report>`.
- INV-2: inner `<lane_report` and `</lane_report>` runs in the
  body are HTML-escaped to `&lt;lane_report` /
  `&lt;/lane_report&gt;` so each fence pair stays balanced
  (exactly one open + one close).
- INV-3: threat-model extras (when non-empty) wrap in
  `<threat_model>…</threat_model>`; inner open/close markers are
  similarly escaped.
- INV-4: the `## Lane: <name>` markdown heading remains outside
  the fence for backwards compatibility with existing INV-7.
- INV-5: the preamble explains "quote, don't obey" without itself
  containing literal fence tags (so the open/close counts stay at
  one per lane / per threat-model block).

## 5. Test coverage

`tests/features/indie_review_engine/test_indie_review_engine.cpp`
adds three INVs:

- `Inv9SynthesisPromptFencesLaneContent` — open/close tag count
  equals lane count + threat-model presence.
- `Inv10SynthesisPromptEscapesHostileCloseTag` — a report
  containing literal `<lane_report>` / `</lane_report>` markers
  cannot escape the outer fence.
- `Inv11SynthesisPromptEscapesThreatModelCloseTag` — same for the
  threat-model fence.

The existing `Inv7SynthesisPromptListsAllLanes` continues to pass
(the `## Lane: <name>` heading is preserved).

## 6. Trust model

Inside ANTS-1448's same-uid boundary. The fence is defence-in-depth
against an attacker who controls a lane report file but cannot
reach the synthesis prompt directly — they would need a Claude
session to invoke `indie_review_synthesis_prompt` with the hostile
reports. The fence ensures the resulting synth output is data, not
executed instructions.

## 7. Out of scope

- Stripping injection content from the fenced body. The fence
  preserves attacker text as visible quoted data (so the assistant
  reviewing the synth output can see what the attacker tried) but
  prevents the open/close markup from escaping the wrapper.
- Adding fences to cold_eyes briefs (paths-only by design).
- Auto-detecting third-party content sources beyond the explicit
  function arguments — out-of-band sources would compose with the
  caller's own fencing.
