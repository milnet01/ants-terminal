# ANTS-3659 — an examples region the doc scanners honour

**Status:** spec draft (2026-07-27).
**Kind:** enhancement.
**Source:** ROADMAP.md ANTS-3659 (in-session-2026-07-27, first real-doc run of
`doc_citations`).
**Blocked by:** none — `MarkdownScan::fenceMask` (`src/markdownscan.h:77`) and
`DocCitations::scan` (`src/doccitations.h:120`) both already ship.
**Blocker for:** ANTS-3661 (`doc_symbols`), which meets the identical problem
one layer over: a document teaching symbol resolution names symbols that do
not resolve, on purpose.
**Composes with:** ANTS-3653 (the citation scan, whose fence rule this
parallels) and ANTS-3636 (the read path, whose antecedent tracker § 2.4 this
resets).

**Layman:** Documents that *teach* how file references work have to write
made-up ones like "see `src/foo.cpp`, line 12". The checker reads those as
broken links. This gives an author a way to mark a passage as "these are
illustrations, not real", so the checker stays quiet there — and stays loud
everywhere else.

---

## 1. Problem

`doc_citations` shipped 2026-07-27 and was pointed at the corpus the same day.
On `docs/specs/ANTS-3636.md` — the spec that *defines* the citation grammar —
it reports **37 citations and 22 `unparsed[]` entries, of which 53 are
illustrations the document authors deliberately**. Six citations are real. The
signal is 6 of 59.

That number is the whole problem, and it is not a complaint about correctness.
The verb is right: `src/foo.cpp` genuinely does not exist. Three consequences,
in the order they bite:

1. **The consumer drowns.** `/cold-eyes` § 1e runs `doc_citations` per in-scope
   doc and feeds its output to a reviewer as pre-verified mechanical findings.
   A lane handed 53 findings of which 0 are real does not learn that this
   document is fine; it learns that this check is noise. A deterministic gate
   that reviewers discount is worse than no gate, because it still costs the
   run.
2. **The affected set is exactly the docs that matter most here.** It is the
   `ANTS-3636` / `3653` / `3654` family — the documents *about* the citation
   grammar. Every future spec in this lane joins it, including this one, which
   cannot state its own fixtures without writing citation-shaped text.
3. **One illustration is already borrowing a real file's identity.** At
   `ANTS-3636.md:1829` a bare `` `:1-9999999` `` is written to illustrate the
   range-clamp bound. It is a continuation, so ANTS-3636 § 2.4's sticky rule
   hands it the antecedent from `ANTS-3636.md:1805` — a genuine
   `claudeintegration.cpp:10181` twenty-four lines earlier — and it resolves
   `ok`, returning that file's line 1 with `range_truncated:true`. An
   illustration is currently able to inherit a real path and report a healthy
   status against it. That is not noise; it is a wrong answer.

**Why the obvious cheap fix does not work.** The tempting opt-out is a
declaration of the fictional path names a doc uses — `src/foo.cpp`,
`src/a.cpp`, `src/gone.cpp` — checked against each citation's path. It fails on
measurement: **three of the six `ok` citations in `ANTS-3636.md` are
illustrations that cite real files.** `CMakeLists.txt:148` at `:581` illustrates
which resolution step catches a repo-root file; `CMakeLists.txt:1` at `:1067` is
a literal inside INV-5's `*Test:*` clause; and `:1829` is the inheriting
continuation above. None of the three names a fictional path, so a
name-keyed rule leaves all three in place while claiming to have solved the
problem.

**Why a per-citation opt-out does not work either.** The 53 tokens sit in more
than a dozen separate passages spread across a 1,873-line document. A marker
per citation is 53 edits and reads worse than the noise.

What is actually true of all 53 is positional: they sit in passages *whose
subject is the notation*. A region is the shape of the thing.

## 2. Surface

### 2.1 The marker

An HTML comment, alone on its line:

```
<!-- doc-examples: begin -->
...prose whose file references are illustrations...
<!-- doc-examples: end -->
```

Recognised by `^ {0,3}<!--[ \t]*doc-examples:[ \t]*(begin|end)[ \t]*-->[ \t]*$`.
Four spelling rules, each with a reason rather than a preference:

- **Alone on its line.** A marker sharing a line with prose would need the scan
  to decide whether the prose before it is inside or outside the region. There
  is no reading of that which is not arbitrary.
- **Up to three leading spaces, spaces only.** The same indent rule
  `MarkdownScan::fenceRe` uses, and space-only for the same reason a tab never
  opens a fence (ANTS-3598): a `\s` class admits `\r` and would let a stray
  carriage return open a region.
- **Lowercase keyword.** `doc-examples`, `begin`, `end`. One spelling to grep
  for. Case-insensitivity buys an author nothing and costs every consumer a
  second pattern.
- **Verb-neutral name, not `doc-citations`.** ANTS-3661's `doc_symbols` needs
  precisely this region over precisely this prose — a doc teaching symbol
  lookup names fictional symbols in the same passages. A verb-scoped marker
  would put two comments on one paragraph. Which verbs *honour* the region is
  each verb's own policy, exactly as ANTS-3653 § 3 already has `codeSpans`
  shared while its masking policy inverts between `doc_integrity` and
  `doc_citations`.

### 2.2 The mask

A new primitive beside the other two in `src/markdownscan.{h,cpp}`:

```cpp
// ANTS-3659 — per-line "inside a doc-examples region" mask, one bool per input
// line. The marker lines are themselves masked true (they are region syntax,
// not prose). An unterminated region masks true to end-of-input, matching
// fenceMask's CommonMark leniency, and reports its opener in
// *unterminatedOpenerLine (-1 when balanced; nullptr accepted).
//
// `fence` is required, not optional: a marker inside a fenced block is sample
// text, and this spec is a document that shows the marker inside a fence.
QVector<bool> exampleMask(const QStringList &lines, const QVector<bool> &fence,
                          int *unterminatedOpenerLine = nullptr);
```

It lives in `MarkdownScan` rather than in `doccitations.cpp` because ANTS-3661
is a named second consumer, and because the ANTS-3649 hoist established that a
primitive two doc verbs both need must not exist twice.

Two degenerate inputs, decided rather than left to the implementation:

- **A `begin` inside an open region is ignored.** Regions do not nest. Nesting
  would need a depth counter to express something no author has a use for.
- **An `end` with no open region is ignored.** It is an authoring slip, but
  reporting it needs a second response field for a case that cannot suppress
  anything — a stray `end` masks nothing, so the failure is already visible as
  "my markers did nothing".

### 2.3 What the region suppresses

Inside a masked line, `DocCitations::scan` emits **neither a `citations[]`
entry nor an `unparsed[]` entry**. Both halves are load-bearing: of the 53
noise tokens in `ANTS-3636.md`, 31 are citations and 22 are `unparsed[]`, and
suppressing only the first leaves 42% of the noise in place.

Two new fields on `ScanResult`, echoed by `DocCitations::check`:

| Field | Meaning | Omitted when |
|---|---|---|
| `unterminated_examples` | 1-based line of an unclosed `begin` | every region closes |
| `examples_suppressed` | count of tokens the mask dropped | zero |

`examples_suppressed` exists because `unterminated_examples` only catches the
*runaway* case. A region that is correctly closed but drawn too wide silently
blanks real citations, and without a count the response is indistinguishable
from a document that cites nothing. Both follow ANTS-3636 INV-28's
omit-when-false discipline.

### 2.4 The antecedent reset

A region boundary resets the sticky antecedent, on the same rule and for the
same reason a fenced block does (ANTS-3636 INV-8).

Without it, a bare `` `:45` `` after a region inherits whichever real path was
last cited before the region — the § 1 consequence 3 defect, merely displaced
past the marker instead of fixed. The reset fails safe: the continuation
becomes `unresolved`, which is a citation the author can see and correct,
rather than `ok` against a file they never named.

## 3. Invariants

Ids continue the ANTS-3636 family's sequence, whose highest live id is INV-48.

- **INV-49** — Inside a `doc-examples` region, no `citations[]` entry and no
  `unparsed[]` entry is emitted; outside one, nothing changes. *Test:* a
  fixture with `src/a.cpp:1` before the region, `src/foo.cpp:12` and a
  path-shaped-but-unresolvable `6.2:1` inside it, and `src/a.cpp:2` after →
  exactly two citations, zero `unparsed[]`. The inside pair must be one of each
  array: a fixture whose region holds only citations passes an implementation
  that masks `citations[]` alone and leaves 42% of the measured noise standing.
- **INV-50** — A marker line inside a fenced block is not a marker. *Test:* a
  fixture whose ```` ```markdown ```` sample contains a `begin` marker, followed
  by `src/foo.cpp:12` in live prose → the citation is emitted and
  `examples_suppressed` is absent. Breaks when `exampleMask` is computed
  without the fence mask — which is the state this spec's own § 2.1 would put
  the corpus in, since it shows the marker inside a fence.
- **INV-51** — An unterminated region masks to end-of-input and sets
  `unterminated_examples` to the 1-based line of the unclosed `begin`; the
  field is absent when every region closes; a stray `end` and a nested `begin`
  are both ignored. *Test:* four fixtures — an unclosed `begin` at line 3 with
  a citation at line 9 → `unterminated_examples:3`, `count:0`; the same closed
  → field absent, `count:1`; a lone `end` before a citation → field absent,
  `count:1`; a `begin`/`begin`/`end` sequence wrapping one citation followed by
  a second citation → `count:1`, field absent, proving the inner `begin` neither
  nested nor re-opened.
- **INV-52** — `examples_suppressed` is the count of tokens the mask dropped,
  summed across both arrays, and is omitted when zero. *Test:* INV-49's fixture
  → `examples_suppressed:2`; a fixture with no marker at all → key absent.
  Breaks when the count is taken from `citations[]` alone, which INV-49's
  fixture distinguishes because its region holds one of each.
- **INV-53** — A region boundary resets the sticky antecedent, as a fence does.
  *Test:* `src/a.cpp:1`, then a closed region, then a bare `` `:45` `` →
  `unresolved`, not `ok` against `src/a.cpp`. The antecedent must be *real* and
  the continuation *outside* the region: an antecedent inside the region is
  suppressed anyway and the fixture would pass without any reset rule.

## 4. RAM / build cost

The mask is one `bool` per scanned line, allocated and discarded inside
`DocCitations::scan`, bounded by `Options::maxDocLines` exactly as `fenceMask`
is. At the 50,000-line ceiling that is a single ~50 KB `QVector<bool>` —
`QVector<bool>` is not bit-packed, so this is one byte per line, and it is
transient for the duration of one call. No cache, no cross-call state, nothing
to evict.

No new translation unit: `exampleMask` joins `src/markdownscan.cpp`, already in
`ants_core_lib`. No new external dependency. One new feature-test source file
into an existing bundle's `SOURCES`, per `tests/features/README.md` — not an
`add_executable`.

## 5. Out of scope

- **Whether `doc_dedup` honours the region** — ANTS-3660's call, and plausibly
  no: two identical teaching examples in two specs may be a genuine
  duplication worth surfacing. The mask is shared; the policy is per verb.
- **Retro-fitting markers across the corpus** — this spec applies them to the
  three docs that measurably need them (`ANTS-3636.md`, `ANTS-3653.md`,
  `ANTS-3654.md`) and stops. A corpus sweep is speculative until another doc
  reports noise.
- **A verb-scoped variant** (`<!-- doc-examples: begin symbols -->`) — no
  measured need for a passage that is illustrative for one verb and literal for
  another. Add it when one appears, not before.
- **Inferring "this is an example" from placeholder-looking names** — refused
  outright, per the ROADMAP bullet: this repo has real files with generic
  names, and a heuristic that guesses would suppress real rot silently.

## 6. Tests

with `spec.md` naming this document as its contract. Label `features;fast`.
Wired into the same bundle as `tests/features/doc_citations_scan/`
(`test_core`), and sharing that directory's fixture helper rather than copying
it.

Every fixture is a string literal and an expected token list — no filesystem
access, matching ANTS-3653 § 5's rule, except INV-53's, which needs

## 7. Cross-doc impact

- **ANTS-3653 § 3** gains a fourth scrape-rule bullet pointing here, beside the
  fence and inline-span rules it already carries. Its invariants are untouched.
- **ANTS-3636 INV-8** (fence resets the antecedent) gains a fixture row for the
  region boundary, and its § 2.4 sticky rule gains a sentence naming the second
  reset trigger. The invariant's claim is widened, not renumbered.
- **`docs/specs/ANTS-3636.md`, `ANTS-3653.md`, `ANTS-3654.md`** get markers
  applied around their example passages — the change that closes the ROADMAP
  bullet. Verified by re-running the verb: `ANTS-3636.md` drops from 31 stale
  citations and 22 `unparsed[]` to the six real citations.
- **`docs/standards/documentation.md`** gains a short authoring note: how to
  write a teaching example that does not read as rot.
- **`/cold-eyes` § 1e** — no change required. The skill is global and this verb
  is not (ANTS-1581), so § 1e names `doc_citations` alongside a hand-rolled
  fallback already; the marker changes what the verb reports, not whether the
  skill can call it.
- **`docs/subsystems.md`** — no change: `exampleMask` joins `MarkdownScan` in
  `ants_core_lib`, which that catalogue already covers.
