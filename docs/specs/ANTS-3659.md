# ANTS-3659 — an examples region the doc scanners honour

**Status:** accepted (2026-07-27), user sign-off — cold-eyes loops 1 + 2 + 3
folded. Deliberately **not** driven to a formally clean pass: the design has
been stable since loop 1, and loops 2 and 3 converged on *fixture-adequacy*
findings ("does this fixture defeat the implementation it names?") rather than
design ones. That class is verified empirically by § 6.1's mutation matrix at
implementation time, which is cheaper and stronger evidence than a review lane
reasoning about it — and is how ANTS-3654 was verified. The loop log records
what each pass found.
**Kind:** enhancement.
**Source:** ROADMAP.md ANTS-3659 (in-session-2026-07-27, first real-doc run of
`doc_citations`).
**Blocked by:** none — `MarkdownScan::fenceMask` (`src/markdownscan.h:77`) and
`DocCitations::scan` (`src/doccitations.h:120`) both already ship.
**Pairs with:** ANTS-3661 (`doc_symbols`), the second plausible consumer of the
same region. Deliberately *not* a blocker: that verb is report-only by design
and expects unresolved symbols, so it can ship without this and simply reports
more candidates.
**Composes with:** ANTS-3653 (the citation scan, whose fence rule this
parallels), ANTS-3636 (the read path, whose antecedent tracker this resets), and
ANTS-3654 (the anchor check, which owns the failure class § 1 explicitly leaves
alone).

**Layman:** Documents that *teach* how file references work have to write
made-up ones like "see `src/foo.cpp`, line 12". The checker reads those as
broken file references. This gives an author a way to mark a passage as
"illustrations, not real", so the checker stays quiet there — and stays loud
everywhere else.

---

## 1. Problem

`doc_citations` shipped 2026-07-27 and was pointed at the corpus the same day.
On `docs/specs/ANTS-3636.md` — the spec that *defines* the citation grammar — it
reports 37 citations and 22 `unparsed[]` entries. **Fifty-eight of those 59
tokens are illustrations the document writes deliberately.** Exactly one is a
claim about this repository: `docs/specs/ANTS-3636.md:1805`, citing
`src/claudeintegration.cpp` as evidence for the description-prefixing loop.

Fifty-three of the 58 surface as problems (31 non-`ok` citations plus all 22
`unparsed[]` entries); the other five resolve `ok` and are discussed below.
Three consequences, in the order they bite:

1. **The consumer drowns.** `/cold-eyes` § 1e runs `doc_citations` per in-scope
   doc and feeds its output to a reviewer as pre-verified mechanical findings. A
   lane handed 53 findings of which 0 are real does not learn that this document
   is fine; it learns that this check is noise. A deterministic gate that
   reviewers discount is worse than no gate, because it still costs the run.
2. **The affected set is exactly the docs that matter most here.** It is the
   `ANTS-3636` / `3653` / `3654` family — the documents *about* the citation
   grammar. Every future spec in this lane joins it, including this one, which
   cannot state its own fixtures without writing citation-shaped text.
3. **One illustration is already borrowing a real file's identity.** At
   `docs/specs/ANTS-3636.md:1829` a bare `` `:1-9999999` `` is written to
   illustrate the range-clamp bound. It is a continuation, so ANTS-3636 § 2.4's
   sticky rule hands it the antecedent from the genuine
   `src/claudeintegration.cpp` citation twenty-four lines earlier, and it
   resolves `ok`, returning that file's line 1 with `range_truncated:true`. An
   illustration is currently able to inherit a real path and report a healthy
   status against it. That is not noise; it is a wrong answer.

**Why the obvious cheap fix does not work.** The tempting opt-out is a
declaration of the fictional path names a doc uses — `src/foo.cpp`,
`src/a.cpp`, `src/gone.cpp` — checked against each citation's path. Measurement
kills it three ways:

- **Four of the five illustrations that resolve `ok` cite real files.**
  `docs/specs/ANTS-3636.md:581` cites `CMakeLists.txt:148` to show which
  resolution step catches a repo-root file; `:1067` uses `CMakeLists.txt:1` as a
  literal inside INV-5's `*Test:*` clause; `:131` and `:163` quote the bare
  basename `mcpprojection.cpp:28` (resolving to `src/mcpprojection.cpp`) as a
  *specimen of a rotted citation*, that spec's own § 1 noting the line "is today
  blank".
- **Three illustrations name no path at all.** `docs/specs/ANTS-3636.md:1829` is
  the inheriting continuation above, and `:966` carries a `:1-9999999` / `:1-3`
  pair with no antecedent. A name list cannot describe a token that has no name.
- **Some "fictional" names are real files.** `mcp-tools.md`, `safe-build.sh`,
  `spec.md` and `run.sh` all exist in this repo; they report `unresolvable` only
  because they are written as bare basenames outside the index roots. An author
  declaring them fictional would be wrong, and would suppress real rot the day
  one of them is cited properly.

**Why a per-citation opt-out does not work either.** The 58 tokens sit in more
than a dozen separate passages spread across a 1,873-line document. A marker per
citation is 58 edits and reads worse than the noise.

What is actually true of all 58 is positional: they sit in passages *whose
subject is the notation* — including `*Test:*` clauses, whose fixture literals
are illustrations in exactly this sense. A region is the shape of the thing.

**What this marker is not for, and § 7's acceptance says so.** Two other
populations look similar and are out of its scope. **Grammar false-positives** —
`6.2:1` (a Qt version) and `counts.missing_file:3` (a JSON field path, whose
last segment carries a dot and so satisfies ANTS-3653 § 2's path production) —
are not illustrations of anything; they are prose the grammar over-recognises.
They already land in `unparsed[]`/`unresolvable`, which is ANTS-3653's designed
containment ("no unauthored token reaches `ok`"), so they are *contained* noise
rather than wrong answers, and a region drawn to silence them would be a region
drawn around live invariant prose. And **the mis-pointing at
`docs/specs/ANTS-3636.md:1805`** —
it names `src/claudeintegration.cpp:10181`, a row inside the `kindForName`
lambda, when the prefixing conditional it describes is at `:10256`. It resolves
`ok` purely because line 10181 exists. Suppression cannot help and must not:
that is a claim, it is wrong, and catching it is ANTS-3654's anchor check. § 7
repairs the line.

## 2. Surface

### 2.1 The marker

An HTML comment, alone on its line:

```
<!-- doc-examples: begin -->
...prose whose file references are illustrations...
<!-- doc-examples: end -->
```

Recognised by `^ {0,3}<!--[ \t]*doc-examples:[ \t]*(begin|end)[ \t]*-->[ \t]*$`.
Three mechanical rules, each with a reason rather than a preference, plus one
naming decision:

- **Alone on its line.** A marker sharing a line with prose would need the scan
  to decide whether the prose before it is inside or outside the region. There
  is no reading of that which is not arbitrary.
- **Up to three leading spaces, spaces only.** The same indent rule
  `MarkdownScan::fenceRe` uses, and space-only for the same reason a tab never
  opens a fence (ANTS-3598): a `\s` class admits `\r` and would let a stray
  carriage return open a region.
- **Lowercase keyword.** `doc-examples`, `begin`, `end`. One spelling to grep
  for. Case-insensitivity buys an author nothing and costs every consumer a
  second pattern.
- **Naming decision — verb-neutral, not `doc-citations`.** The concept ("the
  code-ish things here are illustrations") is verb-neutral, and ANTS-3661's
  `doc_symbols` is a plausible second consumer over the same prose. A
  verb-scoped marker would put two comments on one paragraph. Which verbs
  *honour* the region stays each verb's own policy, exactly as ANTS-3653 § 3
  already has `codeSpans` shared while its masking policy inverts between
  `doc_integrity` and `doc_citations`.

**Input precondition: lines arrive `\r`-stripped.** The trailing `[ \t]*$`
matches neither `\r` nor `\n`, so a CRLF document whose lines still carry `\r`
would silently never open a region — the exact failure the space-only indent
rule above exists to avoid. `DocCitations` already satisfies this
(`src/doccitations.cpp:299` chops a trailing `\r` in `splitLines`), but
`exampleMask` is a shared primitive whose other `MarkdownScan` callers split
their own input, so the precondition is stated rather than assumed. It is a
caller precondition, deliberately untested: the primitive cannot detect a
violation it was handed.

### 2.2 The mask

A new primitive beside the other two in `src/markdownscan.{h,cpp}`:

```cpp
// ANTS-3659 — per-line "inside a doc-examples region" mask, one bool per input
// line, 0-based like fenceMask. Every line of a recognised region is masked,
// its two delimiters included (they are region syntax, not prose). An
// unterminated region masks true to the end of the INPUT — which for a
// truncated scan is the prefix, not the document — and reports its opener in
// *unterminatedOpenerLine as a 1-BASED line (-1 when balanced; nullptr
// accepted), matching fenceMask's overload.
//
// `fence` is required, not optional: a marker inside a fenced block is sample
// text, and this spec is a document that shows the marker inside a fence. It
// must be the mask for THESE lines: a size mismatch is a programming error
// (Q_ASSERT), and in release a short mask reads as unfenced via fence.value(i).
//
// Lines must arrive with any trailing \r removed (§ 2.1).
QVector<bool> exampleMask(const QStringList &lines, const QVector<bool> &fence,
                          int *unterminatedOpenerLine = nullptr);
```

It lives in `MarkdownScan` rather than in `doccitations.cpp` because ANTS-3661
is a plausible second consumer, and because the ANTS-3649 hoist established that
a primitive two doc verbs both need must not exist twice.

Four degenerate inputs, decided rather than left to the implementation:

- **A `begin` inside an open region is ignored.** Regions do not nest, and the
  region keeps its **first** opener's line — that is the line an unterminated
  doubled `begin` reports. Nesting would need a depth counter to express
  something no author has a use for.
- **An `end` with no open region is ignored**, and its line is not masked.
  Reporting it needs a second response field for a case that cannot suppress
  anything, so the failure is already visible as "my markers did nothing".
- **A marker line inside a multi-line inline code span is still a marker.**
  `MarkdownScan::codeSpans` may cross a newline (ANTS-3653 INV-33), so a span
  opening on one line and closing on a later one can contain a whole line that
  looks exactly like a marker. Honouring it is the accepted behaviour: making
  `exampleMask` consume `codeSpans` would have the lighter primitive depend on
  the heavier one, and on a document shape with no instance in this corpus.
  Fences, which *are* how samples are written here, are excluded above.
- **An unclosed fence swallows any later `end`.** `fenceMask` masks an
  unterminated fence true to end-of-input, so an `end` below it is fenced, is
  therefore not a marker, and `unterminatedExamples` fires for a region the
  author did close. `unterminatedFence` fires too, and it is the cause: a
  consumer seeing both should report the fence.

**`unterminatedExamples` is relative to the scanned prefix.** `check` scans at
most `Options::maxDocLines` lines (`src/doccitations.cpp:657`), so a region
whose `begin` is inside the prefix and whose `end` is past it reports as
unterminated and blanks the rest of the prefix. `scanned_lines < doc_lines`
(ANTS-3636 INV-30) is the field that says so, and INV-31 owns that seam's
non-resumability; when it is set, `unterminated_examples` is not evidence the
document is unbalanced.

### 2.3 What the region suppresses

`DocCitations::scan` emits **neither a `citations[]` entry nor an `unparsed[]`
entry** whose `docLine` falls on a masked line. `docLine` — not the enclosing
span's opening line — is the test, per ANTS-3653 INV-33: a citation inside a
span that crosses a newline takes the line its own text begins on. `docLine` is
1-based and the mask is 0-based, so the guard indexes `mask.value(docLine - 1)`,
the same shape as the existing fence guard at `src/doccitations.cpp:207`.

**The two arrays are not the two halves of the measurement, and the layering
matters.** `ScanResult::unparsed` carries only `bad_locus` entries (ANTS-3653
INV-24 / INV-40). The 22 `unparsed[]` entries in the § 1 measurement are
`unresolvable` (20) and `out_of_root` (2) — classifications the *read* path
assigns in `DocCitations::check`, and at scan time all 22 are still `citations[]`
entries. Suppressing in `scan` therefore removes them too: a token the scan
never emits is a token `check` never resolves. `ScanResult::unparsed` is masked
for completeness, not because it carries any of the 58.

Two new members on `ScanResult`, following `unterminatedFence`'s existing
sentinel convention, each echoed by `DocCitations::check` under the JSON key
beside it:

| `ScanResult` member | JSON key | Meaning | Omitted from JSON when |
|---|---|---|---|
| `int unterminatedExamples = -1` | `unterminated_examples` | 1-based line of an unclosed `begin` | `-1` (every region closes) |
| `int examplesSuppressed = 0` | `examples_suppressed` | count of tokens the mask dropped | `0` |

`examples_suppressed` is **whole-doc and invariant across `offset`**, like
`count` and `counts` (ANTS-3636 INV-42): the emission caps trim what is
returned, never what was suppressed. It exists because `unterminated_examples`
only catches the *runaway* case — a region that is correctly closed but drawn
too wide silently blanks real citations, and without a count the response is
indistinguishable from a document that cites nothing. Both keys join ANTS-3636
§ 2.1's omit-when-false list (§ 7), which is what puts them under that spec's
INV-28.

**Suppressed tokens are invisible to every tally.** They are absent from
`count`, from every bucket of `counts`, and from `unparsed_total` — a suppressed
token was never a citation, so ANTS-3636 INV-26's three tally identities hold
unchanged over what survives. `examples_suppressed` is the only field that
counts them, which is why it is not derivable from the others.

### 2.4 The antecedent reset

**Any line the example mask marks resets the sticky antecedent, exactly as any
fenced line does** (ANTS-3636 INV-8: "A fenced block resets the antecedent
tracker"). That is the rule the existing mask-driven reset at
`src/doccitations.cpp:676` already gives for free; phrasing it as "the two
marker lines" would invite a second regex pass to re-identify them. A stray
`end` masks nothing (§ 2.2), so it resets nothing.

Without this, a bare `` `:45` `` after a region inherits whichever real path was
last cited before the region — the § 1 consequence 3 defect, merely displaced
past the marker instead of fixed. The reset fails safe: the continuation becomes
`unresolved`, which is a citation the author can see and correct, rather than
`ok` against a file they never named.

**This is a second computation site, not a field on `ScanResult`.** The
antecedent tracker lives in `DocCitations::check`, which already computes its
own `MarkdownScan::fenceMask` and `codeSpans` over the scanned prefix
(`src/doccitations.cpp:661-662`) independently of `scan`'s at
`src/doccitations.cpp:199`. `check` computes `exampleMask` there too, beside
them, passing `nullptr` for the out-param: `scan` is the single authoritative
source of `unterminatedExamples`, exactly as it already is for
`unterminatedFence`.

## 4. RAM / build cost

Two masks per `check` call, not one: `scan` computes `exampleMask` over the
scanned prefix, and `check` computes it again for the antecedent reset (§ 2.4) —
the same duplication the fence mask already pays at `src/doccitations.cpp:199`
and `:661`. Each is one `bool` per scanned line, allocated and discarded within
its own call, bounded by `Options::maxDocLines`. `QVector<bool>` is not
bit-packed, so at the 50,000-line ceiling that is ~50 KB per mask, ~100 KB
transient for both. No cache, no cross-call state, nothing to evict.

Time is one regex match per line — the same shape as `fenceMask`, linear in the
line count, with no backtracking risk: the pattern is anchored at both ends and
its only repetitions are bounded runs of spaces or tabs, each separated by a
literal. A `line.contains(QLatin1String("<!--"))` prefilter before the regex is
permitted and expected, since the marker-free document is the common case; it is
an optimisation, not a contract, and no invariant depends on it.

No new translation unit: `exampleMask` joins `src/markdownscan.cpp`, already in
`ants_core_lib`. No new external dependency. One new feature-test source file
into an existing bundle's `SOURCES`, per `tests/features/README.md` — not an
`add_executable`.

## 5. Out of scope

- **Grammar false-positives** — `6.2:1`, `counts.missing_file:3` and their kind
  (§ 1). They are contained by ANTS-3653's design, landing in
  `unparsed[]`/`unresolvable` rather than reaching `ok`, and silencing them with
  an examples region would mislabel the class and force a region around live
  invariant prose. If the residue proves annoying, the fix is a grammar
  refinement against ANTS-3653 § 2, filed separately.
- **Whether `doc_dedup` honours the region** — ANTS-3660's call, and plausibly
  no: two identical teaching examples in two specs may be a genuine duplication
  worth surfacing. Likewise **whether `doc_symbols` honours it is ANTS-3661's
  call**. The mask is shared; the policy is per verb.
- **`doc_integrity` is unchanged.** Its findings are dead anchors, broken links
  and TOC gaps — none of which a teaching example produces, because its scrape
  already masks code spans *out*. Stated so its stance is declared rather than
  merely unmentioned.
- **Retro-fitting markers across the corpus** — this spec applies them to the
  four docs that measurably need them (`ANTS-3636.md`, `ANTS-3653.md`,
  `ANTS-3654.md` and itself, § 7) and stops.
- **A verb-scoped variant** (`<!-- doc-examples: begin symbols -->`) — no
  measured need for a passage that is illustrative for one verb and literal for
  another. Add it when one appears, not before.
- **Inferring "this is an example" from placeholder-looking names** — refused
  outright, per the ROADMAP bullet: this repo has real files with generic names,
  and a heuristic that guesses would suppress real rot silently.

### 6.1 What each fixture must defeat

A fixture that cannot fail against a plausible wrong implementation is a test
that certifies nothing. This table is the contract on fixture *adequacy*; it is
stated once here rather than restated inside each invariant.

| Fixture | Wrong implementation it must defeat |
|---|---|
| INV-49's in-region `bad_locus` token | one that masks `citations[]` only — a merely-unresolvable token like `6.2:1` is a *citation* at scan, so it would leave `unparsed[]` empty either way and assert nothing |
| INV-50(a), `begin` with no `end` | a fence-blind mask. With a `begin`/`end` **pair** in the fence it opens *and closes* inside the fence, the post-fence citation survives, and the wrong implementation passes |
| INV-50(b) | one that consumes `codeSpans` and skips spans |
| INV-50(c)/(d) | one indexing the mask by the span's opening line instead of `docLine` |
| INV-51's `begin`/`begin`/`end` | a depth counter (0 citations, not 1) |
| INV-51's unclosed doubled `begin` | one where a second `begin` re-opens — byte-identical to correct on the row above, so this is the only row that separates them |
| INV-54's three-space accept row | one matching `^<!--` with no indent allowance, which passes every reject row |
| INV-55's in-region `6.2:1` | one that suppresses the entry but still counts it in `unparsed_total` |
| INV-55's `unterminated_examples` call | one computing the member correctly but never writing the JSON key |

**Verified RED against feature-absent code before the implementation lands**,
per the project convention. *Feature-absent* means precisely: the two
`ScanResult` members exist at their sentinels and `exampleMask` returns an
all-false vector — without that definition the file does not compile and nothing
fails RED at all.

Under it, every row asserting **suppression** fails RED: INV-49's counts,
INV-50(b)/(c), INV-51's `unterminatedExamples` rows, INV-52's `== 2`, INV-53's
`unresolved`, INV-54's three-space accept row, and INV-55's tallies. The rows
asserting **non-suppression** — INV-50(a) and (d), INV-54's four reject rows,
INV-52's and INV-55's marker-free rows, INV-51's closed-region rows — pass
trivially, because an all-false mask suppresses nothing and a negative assertion
cannot tell "correctly declined to mask" from "the mask does nothing yet". Those
earn their keep only under mutation: build each wrong implementation named in
§ 6.1 and confirm each row goes red under its own mutation and no other — the
