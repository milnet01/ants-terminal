# ANTS-1366 — Sixel raster-header pre-budget

## Problem

The Sixel decoder at `terminalgrid.cpp:2818–2872` runs a full
first-pass walk over the entire payload to derive `imgWidth` and
`imgHeight`, then rejects out-of-bound images at `:2874`:

```cpp
if (imgWidth <= 0 || imgHeight <= 0 ||
    imgWidth > MAX_IMAGE_DIM || imgHeight > MAX_IMAGE_DIM) return;
```

`MAX_IMAGE_DIM = 4096`. The payload-size cap is
`kMaxSixelBytes = 4 MiB`. A 4 MiB payload that happens to declare a
huge image walks all 4 M bytes once before reject. The cost is
linear (~4 M sixel-byte iterations); it pins the parse thread but
isn't catastrophic. Still, when the Sixel raster header
`"Pan;Pad;Ph;Pv` is present at the start (which it almost always
is in real Sixel streams — it appears right after the `q`
introducer), we can read the declared dimensions BEFORE walking
the body and reject early.

## Invariants (post-fix)

- **INV-1.** When the Sixel payload's first non-whitespace
  control after `q` is `"` (raster attributes), parse the four
  raster params and reject early if `Ph > MAX_IMAGE_DIM` or
  `Pv > MAX_IMAGE_DIM`. Emit the same inline-error label the
  full-pass reject path emits (so the user sees the SAME message
  whether the reject fired early or late).
- **INV-2.** Same pre-budget check against `m_imageBudget`:
  `Ph * Pv * 4 > budget` ⇒ early reject + inline error.
- **INV-3.** When the raster header is absent or malformed, fall
  through to the existing first-pass walk — no regression.
- **INV-4.** Early-reject path does NOT call the first-pass
  loop, the QImage allocation, or the second-pass render. The
  function returns immediately after writing the inline error.

## Test

`tests/features/sixel_raster_header_prebudget/`:

1. Craft a Sixel payload with raster header declaring an
   over-cap image: `DCS q "1;1;9999;1$<body>ST`. Submit via
   `handleDcs`. Assert no image is added to `inlineImages()` AND
   an inline error label was emitted matching "exceeds" / "MB" /
   "dim".
2. Same payload with `Pv = 9999` instead of `Ph`. Same assertion.
3. Sanity — small valid Sixel without an over-cap raster
   header reaches the renderer (image count grows by 1).

Label `features;fast`. GUI-free.

## Implementation

Helper `parseSixelRasterHeader(payload, dataStart) → optional<{Ph,Pv}>`
reads `"<digits>;<digits>;<digits>;<digits>` if present. Called
right after the `qpos` find at `:2806`. On hit + over-cap → write
inline error + return. Otherwise fall through to existing
first-pass walk (which still parses the raster header inside its
loop — leave that intact for the case where the parser later
discovers different effective dimensions via repeat counts).

## Out of scope

- Other DCS payloads (DECRQSS at `:2770` — unchanged).
- The Sixel renderer's QImage allocation cap (already correct
  per `m_imageBudget.canFit`).
- Pre-budgeting payloads without a raster header — the
  first-pass loop is the only signal we have for those.
