# ANTS-1405 — `roadmap_query` parser handles non-Ants project stable IDs

**Status:** shipped (0.7.92, 2026-05-20).
**Kind:** fix.
**Lanes:** `roadmapdialog` (`parseBullets`), `claudeintegration`
(`roadmap_query` MCP descriptor text).
**Source:** cross-session-report-2026-05-15 (other Claude Code instance
running on the MAME Curator project).
**Pairs with:** `docs/standards/roadmap-format.md` § 3.5.1 (`[PROJ-NNNN]`
shape); ANTS-1428 (GFM-adapter `boldId` path, used as fallback when no
bracketed ID exists); ANTS-1438 (GFM-adapter multi-token bold extraction).

## Problem

`RoadmapDialog::parseBullets` (`roadmapdialog.cpp:799`) hardcodes the
stable-ID regex to `\[ANTS-(\d+)\]`. The shareable
`docs/standards/roadmap-format.md` § 3.5.1 spec mandates the
`[PROJ-NNNN]` shape for any project — `ANTS`, `MYPRJ`, `OBS`, `R5`, …
— but the parser only recognises the literal `ANTS-` prefix.

Cross-session report 2026-05-15: a Claude Code instance running on the
MAME Curator project, which uses `[mame-curator-NNNN]` inline in
headlines, observed every bullet returning `"id": ""` from
`mcp__ants__roadmap_query`. The caller had to fall back to reading
`ROADMAP.md` over the wire to recover stable IDs — exactly the cost
the MCP verb was added to avoid.

The shareable format standard already exists and is byte-identical
across compliant projects via the App-Build template at
`~/.claude/skills/app-workflow/templates/docs/standards/roadmap-format.md`.
Only the parser was project-locked.

## Goal

Generalise the stable-ID extraction in `parseBullets` so any
`[PROJ-NNNN]` token recognised by `roadmap-format.md` § 3.5.1
populates `BulletRecord::id` with the literal token. Preserve full
byte-for-byte back-compat for `[ANTS-NNNN]` callers. No envelope-shape
or schema change; this is a parser-internal regex widening plus one
descriptor sentence.

Out of scope:

- Other ANTS-hardcoded write paths (`debtsweepengine.cpp:466`,
  `roadmapdialog.cpp:1657/1978`). Those are Ants-internal allocator
  and headline-stripping callsites; generalising them is a separate
  concern with no cross-project user evidence yet.
- The `cmdRoadmapLog` flip-op locator. `remotecontrol.cpp:557`
  (`rxAntsV1IdBracket`) already accepts uppercase `[A-Z][A-Z0-9_-]*-\d{1,8}`
  for that path; it covers the standard-conforming uppercase case
  today. The lowercase observed in MAME Curator is a read concern
  (parser surface), not a write concern (no external project flips
  Ants bullets).
- MCP descriptor versioning. ANTS-1354 already shipped the descriptor
  `version` field; this spec only adds a sentence to the
  `roadmap_query` description text, no version bump required.

## Design

### Regex change

`parseBullets` becomes:

```cpp
static const QRegularExpression rxId(
    QStringLiteral("\\[([A-Za-z][A-Za-z0-9_-]*-\\d+)\\]"));
```

Match shape: `[` + `(letter)(letter|digit|`_`|`-`)*` + `-` + `\d+` +
`]`. Captures the full token. Permits both standard-compliant
uppercase (`ANTS`, `MAME-CURATOR`, `MYPRJ`) and observed-in-the-wild
lowercase (`mame-curator`) — § 3.5.1 says "all caps" as a convention,
but real-world projects diverge and the parser should be tolerant on
the read path.

### `rec.id` assignment

Today (`roadmapdialog.cpp:1005`):

```cpp
rec.id = QStringLiteral("ANTS-%1").arg(idMatch.captured(1));
```

becomes:

```cpp
rec.id = idMatch.captured(1);
```

The captured group is now the full token. For `[ANTS-1234]` the
value is byte-identical (`"ANTS-1234"`) — no callsite change.

### Tool description

`src/claudeintegration.cpp:1734` `roadmap_query` `description`
gains one sentence at the end:

> `bullets[].id` follows the shareable `docs/standards/roadmap-format.md`
> § 3.5.1 spec — any `[PROJ-NNNN]` token (4–6 letter project prefix,
> 4+ digits, e.g. `[ANTS-1234]`, `[MAME-CURATOR-42]`) is recognised.

## Invariants

- **INV-1 / `[ANTS-NNNN]` back-compat.** Bullet body containing
  `[ANTS-1234]` yields `rec.id == "ANTS-1234"`. Byte-identical to
  pre-fix behaviour. Every existing Ants bullet in `ROADMAP.md`
  continues to parse to its existing `id`.
- **INV-2 / uppercase external project.** Bullet body containing
  `[MAME-CURATOR-42]` yields `rec.id == "MAME-CURATOR-42"`. The
  full token is captured verbatim.
- **INV-3 / lowercase external project.** Bullet body containing
  `[mame-curator-7]` yields `rec.id == "mame-curator-7"`. Matches
  the MAME Curator observed convention.
- **INV-4 / reject digit-leading.** `[42-bad-1]` does not match
  (first character must be a letter per § 3.5.1). `rec.id` stays
  empty; the `boldId` fallback path runs unchanged.
- **INV-5 / reject no-dash-before-digits.** `[FOO123]` does not
  match (a `-` separator before the digit run is required). `rec.id`
  stays empty.
- **INV-6 / single-letter prefix permitted.** `[R-5]` matches and
  yields `rec.id == "R-5"`. The standard's "4–6 letters" convention
  is documentary, not enforced by the regex; we tolerate shorter
  prefixes on the read path.
- **INV-7 / underscore inside prefix permitted.** `[my_proj-9]`
  matches and yields `rec.id == "my_proj-9"`. Mirrors the existing
  `rxAntsV1IdBracket` charset.
- **INV-8 / boldId fallback preserved.** A bullet with no bracketed
  token but a `**Sh4**` bold-ID still resolves `rec.id` via the
  ANTS-1428 `boldId` path. Unaffected by this change.
- **INV-9 / multiple brackets in body — first wins.** A body with
  both `[ANTS-1234]` and `[mame-curator-7]` resolves to the first
  matched token. `parseBullets` uses `rxId.match(body)` (not
  globalMatch); this is the existing behaviour.

  - INV-5: no-dash reject. `- 📋 [FOO123] **X.**` → id `""`.
  - INV-6: single-letter. `- 📋 [R-5] **X.**` → id `R-5`.

Label `features;fast`. GUI-free — links only the parsing TUs
(`roadmapdialog.cpp`'s parser is already exercised pure-function
style by other feature tests; reuse the same harness shape).

## RAM / build cost

Net-neutral. Same single static `QRegularExpression`, same
per-bullet call cadence. Capture-group widens from `(\d+)` to
`([A-Za-z][A-Za-z0-9_-]*-\d+)` — captured string is longer on
non-Ants projects, but `rec.id` was previously empty in that case
(net positive: zero bytes → a few bytes per bullet).

Code addition: ~3 LoC in `roadmapdialog.cpp` (one regex change,
one `arg(...)` removal), ~1 LoC sentence in `claudeintegration.cpp`,
~180 LoC test scaffold + 9 fixtures.

## Migration

None. The `id` field now populates with project-specific tokens
where it was previously empty. Consumers that already handled
`id == ""` as "non-actionable / narrator" still see empty for
genuine non-bracketed bullets (rejected by INV-4/5) and for
section-rollup bullets. No envelope-shape change; no schema bump.
