# ANTS-1941 — Behaviour-epoch boundary for the model-switch trust signal

**Status:** ready for implementation (cold-eyes clean 2026-06-02).
**Kind:** implement.
**Source:** ROADMAP.md ANTS-1941 (in-session-2026-06-01 — ANTS-1935 re-baseline blocked by stale records; ANTS-1936 age-window proved insufficient).
**Pairs with:** ANTS-1936 (age window), ANTS-1940 (regret-driven conservatism).
**Blocker for:** ANTS-1935 (re-baseline), ANTS-1923 (close-out), ANTS-1735 §8 OQ-3 (the auto-switch default-ON gate).

## 1. Problem

The model-switch trust signal (`model_switch_stats`) is poisoned by pre-fix
records and the existing age-window cannot clear them.

1. **Age can't distinguish valid-recent from pre-fix-recent.** ANTS-1936 added
   `StatsConfig::windowDays` (default 30) and the filter block at
   `src/modelswitchledger.cpp:539-545` drops records older than the window (the
   `++excludedStaleCount; continue;` drop is at `:542-543`). But the
   contaminating thrash is from 2026-05-29 — ~3 days old today — so
   `excluded_stale_count` stays **0** and the stale records pass the filter.
   Measured live this session via the `model_switch_stats` MCP verb (2026-06-01,
   project scope: `measured_downgrades` 8, `regret_count` 5 → `regret_rate`
   **62.5 %**), built almost entirely from
   the 28 pre-ANTS-1916 thrash records (one switch per ~90 s dwell on
   2026-05-29). The single clean post-fix record is drowned out. (Sibling notes
   quote 67–100 % at different times — all the same stale contamination read at
   different points as pre-fix records settle from `pending`; the percentage
   drifts with the denominator, the cause does not. These figures are evidence,
   not contract — the only checkable post-fix post-condition is the
   `regret_rate = 0.0` of an empty current-epoch set, per §2.4.)

2. **The poisoned ratio feeds back into the live controller.** It is not only a
   display number. `ClaudeStatusBarController::conservatismMultiplierFor`
   (`src/claudestatuswidgets.cpp:1792`; the `StatsConfig sc` it builds sits at
   `:1813-1817`) re-reads `regret_rate` from `statsForScope` and uses it to widen
   the auto-switcher's dwell window (ANTS-1940). A regret rate inflated by stale
   2026-05-29 thrash therefore makes the *current* switcher artificially
   conservative — a robustness regression, not just a reporting one.

3. **The re-baseline (ANTS-1935) cannot resolve.** Its own note records the
   blocker: `statsForScope` aggregates across an age window that can't evict
   records only days old, so the 256 KiB drop-oldest eviction is the only thing
   that would clear them — effectively never at ~11 KB current usage.

The records are not distinguishable by *age*; they are distinguishable by the
*behaviour that wrote them*. The fix is a behaviour-epoch boundary — a
"fixed-from-here" line — so aggregation counts only records written by the
current switcher logic.

**Layman:** The auto-switcher scorecard still reads a high regret number
(60–100 % across recent snapshots), but that's leftover noise from the buggy
May-29 sessions, not how the fixed code behaves.
The 30-day window can't filter it because the bad records are only days old.
We stamp every switch with a "version of the switcher logic that made it" and
count only the current version — so the scorecard, and the switcher's own
caution dial, both reflect the code as it is now.

## 2. Surface

### 2.1 The epoch constant

A single hand-maintained integer declared inside `namespace ModelSwitchLedger`
in `src/modelswitchledger.h` (referenced as `ModelSwitchLedger::kSwitcherEpoch`
from outside the namespace), bumped in any commit that changes auto-switcher
*behaviour* (recommender scoring, the `decide()` gate, the actuator, or the
outcome-fill logic):

```cpp
// ANTS-1941 — behaviour epoch. Bump by 1 in any commit that changes a
// behaviour the trust signal measures (recommender scoring, decide() gate,
// actuator, outcome fill-in). Records written before this feature shipped
// carry no `epoch` field and read as 0 (pre-epoch). Epoch 1 == the first
// switch written *after ANTS-1941 ships* — a point that is ≥ every prior
// behaviour fix (ANTS-1916/1930/…), so a safe "fixed-from-here" lower bound
// (NOT "first post-1916/1930 switch": clean records written between those
// fixes and this ship are unstamped epoch-0 — see § 5). NEVER decrement;
// NEVER reuse a value.
constexpr int kSwitcherEpoch = 1;
static_assert(kSwitcherEpoch >= 1,
              "epoch is a positive behaviour-generation counter");   // INV-7
```

A hand-bumped int, not `ANTS_VERSION`: the app version bumps every weekly
release whether or not switcher behaviour changed, which would over-segment the
ledger into per-release epochs and re-start calibration after unrelated bumps.
The epoch tracks *behaviour generations*, which are rare.

### 2.2 Record field + serialization

`ModelSwitchLedger::Record` (`src/modelswitchledger.h:39`) gains one field:

```cpp
struct Record {
    ...                    // ts, sessionId, project, fromTier, toTier, scoreReason
    QString trigger;       // "auto"
    int     epoch = 0;     // ANTS-1941 — behaviour epoch; 0 = pre-epoch record
    Outcome outcome;
};
```

The new field is inserted between the existing `trigger` and `outcome` members
(the `...` elides the six members above `trigger`). In the definitions in
`src/modelswitchledger.cpp`: `toJson` gains `o["epoch"] = r.epoch;` (next to the
`trigger` write at `:80`, before the `outcome` write at `:81`, mirroring the
struct member order — placement is cosmetic, since `fromJson` looks the key up by
name); `fromJson` gains `r.epoch =
o.value("epoch").toInt(0);` inserted after the `trigger` read at `:93` and
before the `outcome` object read at `:94` — **a missing key defaults to 0** (an
absent key is an Undefined `QJsonValue`, so `toInt(0)` → 0), so every record
written before this ships is pre-epoch with no migration step. The explicit
`.toInt(0)` default follows the same explicit-default idiom the ANTS-1891 field
uses (`oc.value(...).toBool(false)` at `modelswitchledger.cpp:101-102`).

Because `toJson`/`fromJson` carry the field, the outcome fill-in read-modify-
write (`ModelSwitchLedger::writeRecords` at `claudestatuswidgets.cpp:2204`, which
re-serializes every record when a pending outcome settles) round-trips `epoch`
untouched — a settled epoch-1 record stays epoch-1 (covered by INV-1/INV-2). The
"sole *append* site" framing in §2.3 / §4 is about new-record creation; this
re-write path is the only other writer and it preserves the field by
construction.

### 2.3 Stamping at the write site

The one append site — the auto-switch fire path
(`src/claudestatuswidgets.cpp:1601-1612`, where `rec_.trigger` is set at
`:1609`) — sets the current epoch alongside the existing fields:

```cpp
rec_.trigger   = QStringLiteral("auto");
rec_.epoch     = ModelSwitchLedger::kSwitcherEpoch;   // ANTS-1941
```

No other code path appends to this ledger (the chip-click + Undo paths send
`/model` but do not append — confirmed at `claudestatuswidgets.cpp` and the
ANTS-1934 comment at `modelswitchledger.cpp:352-360`; the `(§2.5)` in that
write-site comment refers to ANTS-1735's record section, not this spec's §2.5).
This "sole append site" is a **process/review rule** — like INV-7's
monotonicity clause, not a runtime oracle: INV-1 tests that the fire path stamps
`kSwitcherEpoch`, but nothing automatically proves no *other* path appends an
unstamped record; that holds by the ANTS-1934 single-writer design and is
re-verified at review.

### 2.4 Filtering in `statsForScope`

`StatsConfig` (`src/modelswitchledger.h:152`) gains one field, appended after
the ANTS-1936 `windowDays` field (`:165`) — not inserted into the ANTS-1909
near-miss group:

```cpp
// ANTS-1941 — minimum behaviour epoch. Records with epoch < minEpoch are
// excluded from the aggregation (counted in excluded_pre_epoch_count).
// A record with epoch >= minEpoch is in-scope: a newer behaviour generation
// is trusted, so the predicate is a strict `<`, NEVER `!=` (epoch 2 must pass
// a minEpoch=1 filter). 0 = no epoch filter (all-time / forensic path). Live
// dispatch sites set this to kSwitcherEpoch.
int minEpoch = 0;
```

`statsForScope` (`src/modelswitchledger.cpp:525`) gains the epoch filter,
inserted **between** the existing project-scope `continue` (`:537`) and the
age-window block (`:539`) — i.e. **before** the age filter, so a pre-epoch record
is never also counted as stale (INV-4):

```cpp
int excludedPreEpochCount = 0;
...
for (const Record &r : readRecords(ledgerPath)) {
    if (!global && r.project != projectRoot) continue;
    if (cfg.minEpoch > 0 && r.epoch < cfg.minEpoch) {   // ANTS-1941 — epoch first
        ++excludedPreEpochCount;
        continue;
    }
    if (cfg.windowDays > 0 && nowMs > 0) {              // ANTS-1936 — then age
        ... // unchanged ANTS-1936 body: ++excludedStaleCount; continue;
    }
    scoped.append(r);
}
...
if (cfg.minEpoch > 0) {
    env["min_epoch"]                = cfg.minEpoch;
    env["excluded_pre_epoch_count"] = excludedPreEpochCount;
}
```

Both keys are emitted whenever `minEpoch > 0`, **even when
`excluded_pre_epoch_count` is `0`** — mirroring the ANTS-1936
`window_days`/`excluded_stale_count` pair (`:550-552`). A test asserts the keys
are *present with value 0*, never *absent*, in that case.

`statsEnvelope` is unchanged — it stays pure over whatever record list it is
handed; all epoch logic lives in `statsForScope`.

### 2.5 Dispatch sites set `minEpoch = kSwitcherEpoch`

Both live readers opt in so the human scorecard and the controller's caution
dial agree:

- `src/remotecontrol.cpp:7767` — the `model_switch_stats` MCP verb's `sc`.
- `src/claudestatuswidgets.cpp:1813` — the `sc` inside
  `ClaudeStatusBarController::conservatismMultiplierFor`.

Both sites set `sc.minEpoch = kSwitcherEpoch` **explicitly** — the `StatsConfig`
struct default is `0` (filter off), so the contamination filter applies only
where a reader opts in. Do **not** rely on the struct default for the live
filter. (Pre-existing, out of scope to change here: the MCP site at `:7767`
already leaves `windowDays` at the struct default `30` while the controller sets
it explicitly at `:1815` — they coincide today only by that default. Flag, don't
fix, under this item (tracked as **ANTS-1942**); the new `minEpoch` is set
explicitly at both, so it does not inherit that latent asymmetry.)

**Effect on the controller's caution dial.** Once the filter is live, the
`measured_downgrades` / `regret_rate` that `conservatismMultiplierFor` reads
(`:1819-1822`) reflect current-epoch records only. With the contamination
filtered out (and, until the first post-ship downgrade settles, an empty
current-epoch measured set), `statsEnvelope` yields `regret_rate = 0.0` (it
guards `measured_downgrades > 0` at `modelswitchledger.cpp:425-426`), so
`ModelAutoSwitch::conservatismDwellMultiplier`
returns `1.0`: with the current-epoch measured set empty, `measuredDowngrades`
(0) is below `headlineFloor`, so the floor branch (`:159`) is skipped and the
`regretRatePct <= kRegretConservatismPct` branch (`:161`) returns `1.0`. The
dwell stops being stretched by *stale* regret; the dial reads neutral **until a
current-epoch downgrade settles and supplies a real regret signal** (at which
point the dial correctly responds again) — that is the robustness half of this
fix, not an unconditional neutralisation. The neutralisation is not
instantaneous: `conservatismMultiplierFor` caches its multiplier per project for
`kConservatismTtlMs` (60 s, `claudestatuswidgets.h:375`), so a stale pre-filter
multiplier can persist until the next post-TTL ledger read re-derives it under
`minEpoch`.

`minEpoch` defaults to `0` in the `StatsConfig` struct, and `statsEnvelope`
(the pure aggregator) never inspects `epoch` — filtering lives only in
`statsForScope`. So adding the field changes no existing behaviour *by
construction*: the back-compat wrapper `statsForProject`
(`modelswitchledger.cpp:558`) and every default-config `statsForScope` /
`statsEnvelope` unit test count all epochs unchanged, and the all-time forensic
view stays reachable. (As part of this item's diff, refresh the wrapper's stale
comments at `modelswitchledger.cpp:557` (`// …no config surfaced…`) and `:559`
(`// defaults: disabled, project scope`) — to name the real defaults
`windowDays = 30`, `minEpoch = 0`; both are already wrong w.r.t. the ANTS-1936
window.)

## 3. Invariants

- **INV-1** — A record appended by the auto-switch fire path carries
  `epoch == kSwitcherEpoch`. *Test:* `test_model_switch_ledger.cpp` round-trips a
  `Record{epoch=kSwitcherEpoch}` through `toJson`/`fromJson` and asserts equality.
- **INV-2** — `fromJson` on an object with no `epoch` key yields `epoch == 0`;
  `toJson`→`fromJson` preserves a non-zero epoch. *Test:* same test, two cases
  (legacy line without the key; round-trip of `epoch=2`).
- **INV-3** — `statsForScope` with `minEpoch > 0` excludes every record whose
  `epoch < minEpoch` from the aggregation and counts each in
  `excluded_pre_epoch_count`. *Test:* feature test with a mixed ledger (epoch-0
  + epoch-1 + epoch-2 records, `minEpoch = 1`); assert `switches` counts **both**
  epoch-1 and epoch-2 (a record with `epoch > minEpoch` is in-scope — guards the
  strict-`<` predicate against a `!=` regression) and `excluded_pre_epoch_count`
  equals the epoch-0 count. Make one surviving epoch-1 record a **settled
  downgrade** and assert it contributes to `measured_downgrades` (the positive
  path — a current-epoch downgrade is counted, not just the exclusion of stale
  ones).
- **INV-4** — A record excluded by the epoch filter is **not** also counted in
  `excluded_stale_count` (epoch check precedes the age-window check). *Test:* a
  record both pre-epoch and older than `windowDays`; assert it lands only in
  `excluded_pre_epoch_count`.
- **INV-5** — `minEpoch == 0` (struct default / `statsForProject`) counts records
  of every epoch and emits **neither** `min_epoch` nor
  `excluded_pre_epoch_count`. *Test:* feature test asserts the all-time envelope
  has the same `switches` as the unfiltered record count and omits both keys.
- **INV-6** — `min_epoch` and `excluded_pre_epoch_count` are additive: they
  appear only when `minEpoch > 0`, leaving every pre-1941 envelope field byte-
  identical otherwise. *Test:* feature test diffs the envelope key set of a
  `minEpoch>0` call against a `minEpoch=0` call (only the two keys differ).
- **INV-7** — `kSwitcherEpoch` is a positive compile-time constant
  (`static_assert(kSwitcherEpoch >= 1, ...)` beside its definition in
  `namespace ModelSwitchLedger` in `modelswitchledger.h`). The write path stamps
  the current `kSwitcherEpoch`. *Checkable half:* the `static_assert`
  (compile-time oracle) plus INV-1's round-trip, which reads the stamped epoch
  back as `kSwitcherEpoch` — together these prove the positive direction (the
  fire path stamps *the* constant). *Process half:* that no other path stamps a
  *different* value (§2.3 sole-append-site rule) and that the constant only ever
  increments and is never reused (monotonicity — a behaviour-changing switcher
  fix bumps it) are review rules, documented in the `kSwitcherEpoch` header
  comment, **not** runtime oracles (this checkable/process boundary is
  single-sourced with §7).
- **INV-8** — `statsForScope` over an all-pre-epoch ledger (`minEpoch = 1`, every
  record `epoch = 0`) yields `measured_downgrades == 0` and `regret_rate == 0.0`
  — the empty current-epoch set §2.4's caution-dial chain relies on (the one
  checkable post-fix post-condition §1 names). *Test:* feature test with an
  all-epoch-0 ledger; assert both values, plus `excluded_pre_epoch_count` equals
  the record count.

## 4. RAM / build cost

One `int` per `Record` (4 bytes; records are already ~300 bytes each, ledger
capped at 256 KiB by the `kMaxLedgerBytes` drop-oldest cap — INV-10 of the
ANTS-1735 ledger spec — → ≤ ~900 records → < 4 KiB total added, well inside the
existing cap). One `int` per `StatsConfig` (stack). The filter is one extra
integer compare per record inside the existing read loop — no new allocation, no
new pass. No new build target, no new external library. The single append site
(§2.3) is unchanged, so the field adds no new concurrency surface (the ledger's
`QSaveFile` atomic-replace contract — INV-10 — is untouched).

## 5. Migration / compatibility

- **Old records** (every line written before this ships) have no `epoch` key →
  `fromJson` reads 0 → excluded by the live `minEpoch = 1` filter. No rewrite,
  no archive op, no destructive ledger mutation: the contamination is filtered
  transparently and the raw records remain on disk for the all-time forensic
  path (`minEpoch = 0`). This supersedes the "archive pre-fix records" interim
  the ROADMAP bullet floated.
- **Accepted cost — the lost clean record.** Records written *after* the
  ANTS-1916/1930 behaviour fixes but *before* this feature ships are unstamped
  (epoch 0) and so are excluded even though they were behaviourally clean. Per
  ANTS-1935 that is exactly **one** record (2026-06-01, opus→sonnet, clean).
  Re-stamping by date is fragile and out of scope; the trust signal simply
  re-accumulates from the first post-ship switch. "Fixed-from-here" means
  "stamped-from-here"; the ship point is ≥ all behaviour fixes, a safe lower
  bound.
- **Forward `epoch` bumps** evict the prior generation the same way: after a
  bump to 2, `minEpoch = kSwitcherEpoch = 2` drops epoch-1 records. Process
  rule (INV-7) ties a bump to an actual behaviour change so calibration only
  resets when measurement semantics actually changed.
