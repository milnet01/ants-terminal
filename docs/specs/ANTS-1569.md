# ANTS-1569 — `current_state` MCP aggregator (one-call session-start state recovery)

## Problem

Every session that picks up project work starts with the same 3-4
read cascade to learn "where was I":

1. `roadmap_query(caller_cwd, status:"active")` → identify the
   active 🚧 bullet (the most likely "what am I working on").
2. `git_state(caller_cwd, op:"status")` → branch name, ahead/behind,
   working-tree diff.
3. `last_audit_summary(caller_cwd)` → audit findings outstanding
   from the prior sweep.
4. Optional: `Read .claude/workflow.md` (App-Build projects) for
   the explicitly-marked active item.
5. Optional: `Read docs/specs/<active-bullet-id>.md` for the spec
   the next edit must satisfy.

Per cross-session feedback fold-in (logged in ROADMAP §
`ants-mcp-follow-ups-from-ants-1356-retrodb-cross-session-reports-2026-05-17`
entry ANTS-1569): "every session-start dance is currently a 3-4
read cascade — three separate MCP calls plus an optional Read or
two." The data is already cached on disk on the server; the parent
assistant pays the network round-trip + the response framing N
times to reassemble state it could ask for in one call.

ANTS-1569 ships `current_state` — a single MCP verb that aggregates
all four sources into one envelope. Etag covers the union of
upstreams; on a no-change hit the body short-circuits to ~50 bytes
instead of three full envelopes.

## Goal

`current_state(caller_cwd)` returns one envelope carrying:

- the active roadmap bullet (first 🚧 in ROADMAP.md, or first 📋 if
  no 🚧 exists);
- the workflow status line (first non-blank line under the
  `## Status` heading of `.claude/workflow.md`, when that file
  exists);
- the git branch state (branch name, ahead/behind, files-changed
  count);
- the open audit findings count (error + warning + note summed
  from the most recent SARIF under `.audit_cache/`);
- the spec path for the active bullet ID, when
  `docs/specs/<ID>.md` exists on disk.

## Design

### Tool wiring

- **Name:** `current_state`.
- **Caller-cwd contract:** Required (refuses with
  `caller_cwd_required` when absent — joins the project-scoped read
  group in `callerCwdContractFor`). The ANTS-1520 fall-through
  default is already Required, so omitting an explicit branch fails
  closed; the explicit branch is still added for declaration parity
  with sibling tools.
- **Etag:** opt-in via the ANTS-1499 shared pattern. The verb
  declares `current_state` in `isEtagSupportedTool` and exposes
  `etag_match` in its schema (built via the shared
  `makeEtagMatchProp()` helper from `claudeintegration.cpp`,
  matching every other ANTS-1499-enabled tool). The server-issued
  etag is sha256-hex16 of the response body so any of the upstreams
  changing invalidates.
- **Rate-limit class:** Cheap. The verb is a structural composition
  of three already-cheap reads; the on-disk fan-out is bounded by
  the existing per-upstream caches.
- **Surface:** MCP-only. Mirrors `last_audit_summary` —
  `current_state` is registered via `registerToolProvider` in
  `MainWindow::setupClaudeMcpProviders` and does NOT add an IPC
  `cmd ==` branch in `RemoteControl::dispatch`. Rationale: the
  callers are Claude sessions speaking MCP; non-MCP `--remote`
  callers (rare) can compose the three upstreams manually.

### Response envelope

```json
{
  "ok": true,
  "etag": "<sha256-hex16 of the body below, minus etag>",
  "active_bullet": {
    "id": "ANTS-NNNN",
    "headline": "first-line headline",
    "section_slug": "...",
    "kind": "implement",
    "lanes": [],
    "status": "🚧"
  },
  "workflow_status_line": "",
  "git_branch_state": {
    "branch": "main",
    "ahead": 0,
    "behind": 0,
    "files_changed_count": 0
  },
  "open_audit_findings_count": 0,
  "open_audit_findings_count_stale": false,
  "spec_path": "docs/specs/ANTS-NNNN.md"
}
```

Field guarantees:

- `active_bullet`: present iff at least one bullet in ROADMAP.md
  carries status `🚧` or `📋`. Selection rule: scan
  `cmdRoadmapQuery({"status":"active"})`'s `bullets[]` in document
  order; pick the first whose `status` field equals `🚧`. If none
  match, pick `bullets[0]` (which `roadmap_query`'s active filter
  guarantees is the first 📋 in document order — both states share
  the `active` filter). Field is **omitted** (not `null`, not `{}`)
  when the upstream returns an empty `bullets[]` OR fails with any
  non-`ok` envelope.
- `workflow_status_line`: present iff `.claude/workflow.md` exists
  on disk. Empty string when the file exists but has no
  `## Status` heading or the body under it is blank. Trim trailing
  newline; truncate the emitted string to its first line (everything
  before the first `\n`) — a one-line headline by construction. No
  byte cap is imposed; the file's own line-length conventions govern.
- `git_branch_state`: always present. Built from
  `cmdGitState({"op":"status", "caller_cwd": …})`. If the upstream
  returns non-`ok` (e.g. not a git repo), the field is emitted as
  `{"branch":"", "ahead":0, "behind":0, "files_changed_count":0}` —
  preserves the always-present guarantee for callers iterating the
  envelope. An empty `branch` therefore conflates two distinct
  upstream states (not-a-repo and detached-HEAD). Callers that need
  to distinguish these MUST fall back to a direct
  `git_state(op:"status")` call; the aggregator is deliberately
  lossy on this corner case in exchange for the always-present
  shape.
- `open_audit_findings_count`: integer.
  `cmdLastAuditSummary` may return `{ok:false, code:"not_audited"}`
  (no `.audit_cache`, no recognised report) — counted as 0.
  Any other non-`ok` envelope from the upstream (e.g. `read_failed`,
  `bad_path`) — counted as 0. On `ok:true`, the value is
  `counts.error + counts.warning + counts.note` (per
  `last_audit_summary`'s documented envelope). Suppressed findings
  (`counts.suppressed`) are excluded by definition. No new error
  codes propagate from this upstream to the `current_state`
  envelope.
- `open_audit_findings_count_stale` (ANTS-3370): boolean,
  always present. Mirrors `last_audit_summary`'s always-on `stale`
  signal (ANTS-2056: the cached audit artifact's mtime predates the
  current HEAD commit's date, so the count describes a PAST tree
  where already-fixed findings masquerade as live). Read from the
  upstream `stale` field — not recomputed — so there is one source of
  truth and no extra git probe. `false` when the upstream omitted
  `stale` (HEAD date unreadable) or returned non-`ok` (count 0 ⇒ not
  stale). When the upstream also carried a `stale_reason`, it is
  echoed as `open_audit_findings_count_stale_reason` (present only
  while stale).
- `spec_path`: present iff `active_bullet` is present AND
  `<project-root>/docs/specs/<active_bullet.id>.md` exists on disk
  (a single `QFileInfo::exists()` probe; no parsing). Returned as a
  project-relative path.

### Implementation

`cmdCurrentState(req)` lives in `remotecontrol.cpp` next to
`cmdGitState` / `cmdLastAuditSummary`. The body:

1. Resolves `rootCanonical` via `resolveRootCanonical(m_main, req)`
   (same as the other Required tools). Empty result → standard
   `{ok:false, code:"no_project"}` envelope.
2. Calls
   `cmdRoadmapQuery({"caller_cwd": …, "status": "active"})` —
   single call, no `limit`. The active filter returns 🚧 + 📋 in
   document order. Iterates `bullets[]`: picks the first whose
   `status` field equals `🚧`. If none, picks `bullets[0]` (first
   📋). If `bullets[]` is empty OR the upstream is non-`ok`, leaves
   `active_bullet` unset.
3. Reads `<root>/.claude/workflow.md` if present, walks for a
   `## Status` heading, takes the first non-blank line under it
   (or empty string). Skips the field entirely when the file is
   absent.
4. Calls `cmdGitState({"caller_cwd": …, "op": "status"})` and
   forwards `branch`, `ahead`, `behind`, `files.size()` as
   `files_changed_count`. On upstream failure, fills with the
   empty/zero fallback (per Response envelope).
5. Calls `cmdLastAuditSummary({"caller_cwd": …})`. Any non-`ok`
   envelope → `open_audit_findings_count: 0`. On `ok:true`, sums
   the `counts.{error,warning,note}` fields.
6. If `active_bullet.id` is present, stats
   `<root>/docs/specs/<id>.md` and includes `spec_path` on hit.
7. Returns the JSON envelope WITHOUT an `etag` field. The dispatcher
   layer in `claudeintegration.cpp` runs `applyEtagPattern(toolName,
   responseText, etagMatch)` on the result — that helper calls
   `etagFor(responseText)` (sha256-hex16 of the full body),
   injects the resulting `etag` field into the JSON object, and
   short-circuits to `{ok:true, unchanged:true, etag:"<same>"}`
   when the caller's `etag_match` equals the freshly-computed
   value. `current_state` opts into this path by appearing in
   `isEtagSupportedTool`. No `current_state`-local hashing.

The implementation is **purely a composer** — no new file reads
that the upstream verbs aren't already doing, no new cache layer.
The token saving is in the response framing (one envelope vs
three) and the eliminated round-trips.

### Schema (tools/list)

```json
{
  "name": "current_state",
  "description": "One-call session-start state — active roadmap
   bullet + workflow status line + git branch state + open audit
   findings count + spec path. Bundles roadmap_query +
   git_state(status) + last_audit_summary + .claude/workflow.md
   into one envelope. Etag-able: pass etag_match to short-circuit
   when nothing has changed.",
  "inputSchema": {
    "type": "object",
    "properties": {
      "caller_cwd": <makeCallerCwdReadProp()>,
      "etag_match": <makeEtagMatchProp()>
    },
    "required": ["caller_cwd"]
  }
}
```

The snippet above is **illustrative**. The `caller_cwd` and
`etag_match` property objects are emitted by the shared
`makeCallerCwdReadProp()` and `makeEtagMatchProp()` helpers in
`claudeintegration.cpp` — the descriptions they produce live in
one place and are reused across every project-scoped read tool.
Do NOT hand-write the description strings in the registration
block.

The MCP descriptor is registered in the same block as
`last_audit_summary` in `claudeintegration.cpp` (alphabetical
neighbour). Selection hint: "Call once at session start instead of
chaining roadmap_query + git_state + last_audit_summary."

## Memory & cost budget

The handler holds at most:

- one `QJsonDocument` per upstream call (3 docs);
- one composed response envelope.

Peak memory ≤ 256 KiB in normal cases — sum of the three upstream
payloads, dominated by `roadmap_query`'s active bullet list (≤ ~120
bullets × ~1 KiB each = ~120 KiB), plus `git_state`'s status output
(~kBs typical, ~10–50 KiB on a heavy working tree), plus
`last_audit_summary`'s compact envelope (~2–5 KiB). On a worst-case
project with ~500 active bullets the upstream's own response cap
(~20 KiB roadmap_query envelope before pagination kicks in) keeps
the total well under 512 KiB.

Wall-clock ≈ the slowest single upstream (typically
`last_audit_summary` reading a SARIF). The composer adds < 1 ms.

The `.audit_cache/` SARIF stat alone bounds the audit upstream's
work — the file is path-keyed and read once. No new RAM tax beyond
the existing upstream caches.

## Out of scope

- A streaming-progress variant (no upstream is slow enough to
  warrant it).
- A `branch_diff_count` field beyond `files_changed_count`. The
  caller can drill in via `git_state(op:"diff")` when they need it.
- Walking ROADMAP.md beyond the first matching bullet — the verb
  surfaces "what am I likely working on", not a backlog dump.
- A formal `.claude/workflow.md` schema. The parser is
  best-effort: locate the first `## Status` line, return the first
  non-blank line below it. Nested headings (`### Status`), multiple
  `## Status` blocks, or alternative shapes are out of scope. When
  App-Build's spec evolves the file shape, this verb's parser
  evolves with it.
- Per-Tab routing. `current_state` is project-scoped (Required, not
  TabSpecific) — its data lives on disk under the caller's project
  root, not in a tab's transient state.
