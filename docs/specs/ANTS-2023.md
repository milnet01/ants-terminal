# ANTS-2023 — soft-warn a `cat`/`head`/`tail`-of-source dump into a non-blocking `file_outline`/`read_region` nudge

**Status:** accepted (2026-06-16) — cold-eyes loops 1–5 folded clean (CRITICAL/HIGH zero from loop 3; loops 4–5 cosmetic only; both reviewers concurred "unusually clean"); implementation pending.
**Kind:** feature.
**Source:** ROADMAP.md ANTS-2023 (in-session-2026-06-04) — "PreToolUse prefer-MCP advisory guardrail (the enforcement half of MCP discoverability)."
**Composes with:** ANTS-2141 (the grep/find soft-warn) and ANTS-1252 (the `ants_hooks_pack_v1` token-saving pack). **Pairs with:** `file_outline` / `read_region` (the verbs the nudge points at).

## 1. Problem

ANTS-2141 closed the **search** half of "use the index, don't shell out": a raw
`grep -r` / `rg` / `find … src/` now draws a non-blocking nudge toward
`workspace_search` / `find_definition`. The **read** half is still open. When a
session runs `cat src/terminalgrid.cpp`, the *entire file* streams back as Bash
tool output and lands in the model's context — for a 2000-line source file that
is thousands of tokens, most of them never read. The cheaper moves already
exist:

- `mcp__ants__file_outline` — a file's symbol/structure map without its body.
- `mcp__ants__read_region` — a specific line range of a file.

Both cost a fraction of a full `cat`. There is no nudge steering the session to
them; ANTS-2023 adds one, in the **same soft-warn shape** the user chose on
2026-06-15 (let the command run, just remind) — no new block.

**Layman:** When the assistant dumps a whole code file to the screen with `cat`,
Ants now gently reminds it that asking for just the file's outline or a specific
line range is far cheaper — without stopping the command.

## 2. Surface

All changes live in the existing pack (bash + jq, no C++). No new MCP verb. In
`hooks/ants-bash-veto.sh` a **second** non-blocking warn branch is added,
evaluated *after* the ANTS-2141 source-search branch and *before* the git/roadmap
block branches. It calls a new pure predicate `ants_is_source_read "$cmd"`
(`_common.sh`) and, on a match, runs the **same** throttle → record → emit dance
as the source-search branch (§2.3).

Branch order in the veto becomes:

1. `# ants-bypass` short-circuit (unchanged).
2. `ants_is_source_search` → grep/find warn (ANTS-2141, unchanged).
3. `ants_is_source_read` → **new** read-dump warn (this spec).
4. git-status / `cat ROADMAP.md | grep` → block (unchanged).

A command matches **at most one** branch (first match wins); §2.2 keeps the
read-class predicate disjoint from the grep-class and from the `cat ROADMAP.md`
block (it excludes piped commands, so `cat ROADMAP.md | grep` never reaches the
read branch).

### 2.1 The warn envelope (non-blocking, model-visible)

Identical structure to ANTS-2141 §2.1 — `hookSpecificOutput.additionalContext`,
**no** `permissionDecision`, **no** top-level `decision`, so the command still
runs through the normal permission flow. Only the text differs:

```json
{
  "hookSpecificOutput": {
    "hookEventName": "PreToolUse",
    "additionalContext": "Ants tip: that dumped a whole source file. Prefer mcp__ants__file_outline (symbols/structure) or mcp__ants__read_region (a line range) — far fewer tokens than cat-ing the entire file back. Append `# ants-bypass` to silence."
  }
}
```

The throttle-suppressed path emits **empty stdout** (command runs untouched),
exactly as ANTS-2141 §2.3.

### 2.2 Match algorithm — what counts as a "source read-dump"

Matching runs on the **jq-decoded** `$cmd` (ANTS-1252 INV-7). The predicate is
the pure helper `ants_is_source_read "$cmd"` in `_common.sh` — it **`return`s 0
(match) / 1 (no match), never `exit`s** (so it is in-process unit-testable, like
`ants_is_source_search`), and on a match sets `ANTS_NUDGE_TOOL` to the matched
leading token (the §2.3 tally bucket). It **reuses** ANTS-2141's `pre`-stripping
and EXEMPT-scan shape, but the operand-finding step (skip leading `-`-flags to
reach the first file operand) is **new logic** — `ants_is_source_search` only
reads `first`/`second` (`_common.sh:99-100`) and never needs an operand walk.

```
pre = $cmd up to (not including) the first unquoted '|'      # a pipe = processing, not a read-for-context
strip from pre: leading `VAR=val ` assignments and a single leading `cd … &&`
                (mirrors ants_is_source_search)

READ_DUMP = pre's leading command token ∈ {cat, head, tail, bat}
    AND pre has a "first operand" — the first whitespace-separated token after the
        leading command that does NOT begin with `-` (so `head -50 foo.cpp` →
        first operand is `foo.cpp`, not the `-50` flag) — that is a CODE SOURCE FILE:
        - a path under `src/` / `tests/` / `include/` (with or without `./`), OR
        - an operand ending in a code extension:
          .cpp .cc .cxx .c .h .hpp .hh .lua
    AND $cmd contains NO redirect (`>`), heredoc/herestring (`<<`), or pipe (`|`)
        — all three disqualify, because a `>`/`<<` means the command is writing or
        feeding input and a `|` means the read is a *processing* pipeline
        (`cat src/x.cpp | grep …`), not a context dump. Unlike the grep class
        (where a leading `grep` with a trailing pipe still warns — the pipe only
         caps output), the read class treats *any* `|` as disqualifying: the
        useful nudge is for a bare file dump, not a cat feeding a downstream
        filter. The `>`/`<<`/`|` scan is `$cmd`-wide (not `pre`-scoped, unlike
        ANTS-2141's path/flag scans) — intentional: it only ever narrows toward
        no-warn (e.g. `2>&1`, `>>`, `||`, or a quoted `>`/`|` in an operand all
        suppress), consistent with the fewer-false-positives posture.

eligible = READ_DUMP and not EXEMPT
```

The `EXEMPT` scan (below) runs on `pre` **before** the leading-command-token
dispatch — mirroring `ants_is_source_search`'s ordering (`_common.sh:88-96`
runs the flag/path exemptions ahead of the `case "$first"` token switch at
`_common.sh:101`) — so an exempt path short-circuits regardless of the leading
tool. Interactive pagers `less`/`more` are intentionally **not** in the tool set
(they require a TTY and would not appear as plain dumps in agentic non-TTY Bash);
they join the §5 blind spots. `bat` **is** included: unlike `less`/`more` it auto-
disables its pager when stdout is not a TTY, so in agentic Bash it streams the
file content (rather than blocking on an interactive pager) — enough to make the
dump a token sink worth nudging, even if its non-TTY output still carries a
line-number gutter.

`EXEMPT` reuses **ANTS-2141's exemption set verbatim** (no warn — command runs
untouched) when:

- the **whole `$cmd`** contains `# ants-bypass`; OR
- `pre` contains `--help`, `--version`, `-h`, or `-V`; OR
- `pre` contains a non-source-root token: `/tmp`, `/var`, `/etc`, `/usr`,
  `/proc`, `/sys`, `build/`, `build-`, `.git/`, `node_modules`, or a token
  ending in `.log`.

The code-extension / source-dir requirement is **deliberately narrower** than
"any file `cat` reads": it targets exactly the files `file_outline` /
`read_region` serve best (code), and it keeps the read class clear of
markdown/config reads (those are §5 out of scope — `ROADMAP.md` already has its
own `roadmap_query` routing). The read class never collides with the existing
`cat ROADMAP.md` block branch: the **piped** `cat ROADMAP.md | grep` is excluded
by the pipe rule and falls to that block branch, while a **bare** `cat ROADMAP.md`
is a markdown read that matches *no* branch at all. (The block `case` at
`ants-bash-veto.sh:59` keys on a `grep` token appearing alongside `ROADMAP.md`
— `*"cat ROADMAP.md"*"grep"*` or the reversed `*"grep "*"ROADMAP.md"*` — not on a
literal pipe; a bare `cat ROADMAP.md` has no `grep` token, so it hits nothing.)

Worked cases (→ test table, INV-5):

| Command | Result | Why |
|---|---|---|
| `cat src/terminalgrid.cpp` | warn | code file under `src/` |
| `cat include/foo.h` | warn | code file under `include/` |
| `head -50 vtparser.cpp` | warn | code extension, `head` |
| `tail -100 tests/test_x.cpp` | warn | code file under `tests/` |
| `bat src/foo.lua` | warn | `.lua` is a code extension |
| `cat build-fast/moc_x.cpp` | no warn | `build-` non-source-root token exempt (the project's live `build-fast/` tree — most likely false positive) |
| `cat README.md` | no warn | markdown — out of scope (§5) |
| `cat ROADMAP.md \| grep foo` | no warn (here) | piped → not a read-for-context; the **block** branch (keys on `grep`+`ROADMAP.md`) catches it instead |
| `cat ROADMAP.md` (bare) | no warn | markdown, not a code file, no `grep` token → matches **no** branch; use `roadmap_query` |
| `cat src/foo.cpp \| grep bar` | no warn | piped → processing, not a context dump |
| `cat foo.cpp > bar.cpp` | no warn | redirect → writing, not reading |
| `cat /etc/hosts` | no warn | non-source-root `/etc` exempt |
| `cat notes.txt` | no warn | not a code extension, not under a source dir |
| `cat << EOF` | no warn | heredoc (`<<`) → feeding input |
| `head --help` | no warn | `--help` exempt |

**Accepted blind spots** (documented, not bugs, consistent with the
fewer-false-positives posture): (a) a read not at the head of a `&&`/`;` chain
after the first `cd` strip is not warned (e.g. `make && cat src/foo.cpp`); (b) a
code file dumped via a non-listed tool (`less`, `more`, `xxd`, `od`, `nl`) is not
warned; (c) markdown/JSON/shell/text reads are intentionally not warned (§5);
(d) a **separated option-argument** mis-reads as the first operand —
`head -n 50 src/foo.cpp` takes `50` (the arg to `-n`) as the first non-`-` token,
so it is not a code path → **no warn** (the attached form `head -n50 src/foo.cpp`
and `head -50 src/foo.cpp` do warn; `bat --line-range 5:20 src/foo.lua` is the same
case — `5:20` is read as the operand). A missed nudge is harmless; baking
per-tool option-arity into the predicate is over-engineering for a heuristic.
(e) a **leading-token wrapper** — `command cat src/foo.cpp`, `\cat …`, or an
alias prefix — sets `first` to the wrapper, not `cat`, so it is not warned. Both
predicates share this (`ants_is_source_search` has the same `read -r first`
limitation); unwrapping is not worth the complexity for a heuristic.

### 2.3 Shared throttle + counter (reuses ANTS-2141 unchanged)

The read-class warn reuses ANTS-2141's helpers **as-is** — `ants_grep_nudge_dir`,
`ants_grep_nudge_throttled`, `ants_grep_nudge_record` — and the **same** cache
tree `~/.cache/ants-terminal/grep-nudge/` (stamp + `count.jsonl`). Consequences,
all intentional:

- **One shared anti-nag window.** The throttle stamp is per-`$PPID`, not
  per-class, so at most **one** prefer-MCP nudge (grep *or* read) fires per
  `ANTS_GREP_NUDGE_THROTTLE_SEC` window. A session that was just nudged about a
  grep will not also be nudged about a `cat` 30 s later — the meta-message ("use
  the cheaper MCP verb") is the same, and a second reminder is pure nag. This is
  the simplest correct anti-nag posture; per-class windows are §5 out of scope.
- **Counter vocabulary widens.** `ants_grep_nudge_record` writes the matched
  token as `tool`; the read class adds `cat` / `head` / `tail` / `bat` to the
  existing `grep`/`rg`/`ag`/`ack`/`git-grep`/`find` vocabulary. The matched token
  comes from `ANTS_NUDGE_TOOL`, which `ants_is_source_read` sets on a match; the
  read-branch call site supplies `cat` as the fallback (`${ANTS_NUDGE_TOOL:-cat}`,
  vs. the source-search branch's `:-grep` at `ants-bash-veto.sh:41`) so a matched
  read never mis-buckets as `grep`. `tools/grep-vs-index.sh` buckets on `tool` and
  skips malformed lines, so the new buckets surface with no change to the readout.
- **Same fail-open guarantees** (ANTS-2141 §2.3 / INV-9): a broken/unwritable
  cache never silences the nudge and never changes the exit code; all
  bookkeeping runs only after `ants_in_project_or_exit` returns 0 (ANTS-2141
  INV-11).

## 3. Invariants

*All `INV-N` here are ANTS-2023's.*

- **INV-1** — A read-dump-eligible command produces
  `{"hookSpecificOutput":{"hookEventName":"PreToolUse","additionalContext":<non-empty>}}`
  with **no** `permissionDecision` and **no** top-level `decision`. *Test:* feed
  `{"tool_input":{"command":"cat src/terminalgrid.cpp"}}`; assert with one jq
  program (mirrors ANTS-2141 INV-1).
- **INV-2** — The read warn is non-blocking and the command runs: the branch
  never emits `{}`, a `decision`, or `exit 2`. The git/roadmap **block** branches
  are unaffected: a read-class match emits the warn envelope and exits before
  them; a non-match `return`s 1 and the script **falls through** to the block
  `case` unchanged. *Test:* `cat ROADMAP.md | grep foo` — the read predicate
  `return`s 1 (markdown, not a code file; piped), so the input reaches the
  unchanged block branch and still produces `.decision=="block"`. (This is a
  regression guard on the block branch this spec does not touch — proof the read
  branch's insertion did not shadow it.)
- **INV-3** — The warn `additionalContext` is ≤ 400 bytes — the **same 400 B cap
  and same field** as ANTS-2141 INV-3 (the byte *count* differs: ANTS-2141's body
  is 237 B, this one's is 225 B — both under the shared cap). The §2.1 body
  measures **225 B** (223 chars; the one `—` em-dash is 3 UTF-8 bytes; verified
  via `printf '%s' '<body>' | wc -c`) — headroom under the cap; the test still
  measures the actual field bytes so a future edit past 400 B is caught. *Test:*
  extract via `jq -r`, assert byte length 1..400.
- **INV-4** — Non-eligible read commands produce empty stdout (command runs
  untouched). Two distinct no-warn mechanisms, mirroring ANTS-2141's EXEMPT-vs-
  guard split: **EXEMPT** (the §2.2 scan short-circuits) — `# ants-bypass`;
  `--help`; non-source-root `cat /etc/hosts`; `build-` token
  `cat build-fast/moc_x.cpp`; `.log`-suffix. **Non-eligible (fails READ_DUMP)** —
  not-a-code-file (`cat README.md`, `cat notes.txt`); redirect/heredoc
  (`cat foo.cpp > bar`, `cat << EOF` — the `>`/`<<` clause of READ_DUMP, *not* an
  exemption); piped (`cat src/foo.cpp | grep bar` — excluded by the `pre` split).
  *Test:* one harness case per item asserts empty stdout (the `build-`/`build/`
  exemption included — the project's live `build-fast/` tree makes it the most
  likely real false positive).
- **INV-5** — `ants_is_source_read` is a pure predicate in `_common.sh`,
  source-able and unit-testable, returning 0 (match) / 1 (no match), never
  `exit`. *Test:* harness sources `_common.sh` and table-tests the §2.2 worked
  cases (positive / negative / exempt), mirroring ANTS-2141 INV-6. It also asserts
  `ants_is_source_read` and `ants_is_source_search` never both return 0 for the
  same `$cmd`. The guarantee is structural, in two parts. (1) A command caught by
  *either* predicate's EXEMPT scan `return`s 1 there before `first` is even read
  (the EXEMPT scan precedes the `case`, `_common.sh:88-96` ahead of `:101`), so it
  can match at most the other predicate — never both. (2) For a command that
  survives both EXEMPT scans, both classify on `pre`'s **leading command token**
  (`read -r first`, `_common.sh:99-100`), and the two leading-token sets — read
  `{cat,head,tail,bat}` vs search `{grep,egrep,fgrep,rg,ag,ack,ack-grep,git,find}`
  — are disjoint, so its `first` token lands in at most one set. (`git grep`
  reads a `second` token too, `_common.sh:110-111`, but its *leading* token `git`
  is still in the search set and disjoint from the read set, so the two-token
  dispatch does not weaken the proof.) The read class's
  pipe/redirect exclusion is an *additional* narrowing, not the disjointness
  proof — the EXEMPT-first short-circuit plus disjoint leading tokens are
  sufficient.
- **INV-6** — The read warn shares ANTS-2141's per-`$PPID` throttle: with a fixed
  `PPID` and writable temp `HOME`, a grep nudge immediately followed by a
  read-eligible command emits **empty stdout** for the read (suppressed by the
  shared window); after the window expires the read nudge fires. The read branch
  calls `ants_grep_nudge_record` on **both** the throttle-suppressed and emitted
  paths — mirroring the source-search branch's record calls (`ants-bash-veto.sh:43`
  `warned=false` on suppress, `:46` `warned=true` on emit; the new read branch
  copies that shape), record running *before* the throttle decision — so every
  eligible match is tallied regardless of suppression (ANTS-2141 INV-8). *Test:* fire grep (warn) → fire `cat src/x.cpp` immediately
  (empty) → expire the stamp → fire `cat src/x.cpp` (warn); assert `count.jsonl`
  holds exactly **3** lines with `warned` flags `true` / `false` / `true` in order.
- **INV-7** — `ants-bash-veto.sh` still exits 0 on every path (warn, block,
  exempt, no-op, error) — ANTS-1252 INV-1 / ANTS-2141 INV-12 preserved. *Test:*
  each new case asserts exit 0.

## 4. RAM / build cost

- **Disk:** none beyond ANTS-2141 — the read class writes into the **same**
  `grep-nudge/` stamp + capped `count.jsonl`. No new file.
- **Token cost:** a read nudge injects its body (225 B ≈ ~55 tokens; ≤ 400 B cap,
  INV-3), and shares
  ANTS-2141's once-per-window throttle, so it adds **no new un-throttled token
  class** — at most it changes *which* nudge fills the single per-window slot.
- **Memory / latency:** one extra pure predicate call per Bash PreToolUse,
  evaluated only when the source-search predicate did not match; on a match the
  same `mkdir -p` / `stat` / append as ANTS-2141. Within the ANTS-1252 §4 budget
  (≤ 20 ms p99). The predicate is parameter-expansion + a small `case`/glob — no
  fork.
- **No new build target** (runs under the existing `hook_pack` ctest); **no new
  external libs** (jq already required).

## 5. Out of scope

- **Nudging the Read *tool*** (a full-file `Read` without a line range) — the
  Read tool is the harness-native, recommended way to read a file, and a
  PreToolUse matcher on it would fire on nearly every read, exactly the
  false-positive friction the soft-warn posture exists to avoid. The expensive
  pattern this item targets is `cat`-into-terminal-output, not Read. If a
  measured signal later shows full-file Reads dominating, a separate ROADMAP id
  carries it.
- **Markdown / JSON / shell / plain-text read-dumps** — `file_outline` /
  `read_region` add the most value on code; markdown reads overlap the existing
  `cat ROADMAP.md` routing (`roadmap_query`). Narrowing to code files keeps the
  predicate disjoint and low-false-positive. Revisit if the readout shows
  doc/config dumps are a real sink.
- **Per-class throttle windows** — the shared per-`$PPID` window is the simpler
  anti-nag posture (§2.3); split only if the readout shows one class is starving
  the other of nudges.
- **`&&`-chained / non-`cat` dump tools (`xxd`, `od`, `nl`)** — accepted blind
  spots (§2.2), favour fewer false positives.
- **Strict-deny escalation** — inherits ANTS-2141 §5: deferred per the
  2026-06-15 soft-warn posture.

ANTS-2023 inherits ANTS-2141 §6's manual end-to-end smoke rather than restating
it — no new manual step.
