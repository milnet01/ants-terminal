# ANTS-1883 — `session_orient` bundle verb

**Status:** spec draft, cold-eyes loops 1 + 2 folded (2026-05-26).
**Kind:** enhancement.
**Source:** ROADMAP.md ANTS-1883 (vestige-feedback-2026-05-26
Wishlist #3).

**Layman:** Every fresh session opens by asking three things:
"what state is this project in?" + "where do things live?" + "what
active sections does the roadmap have?". Today that's three MCP
calls + three ETag round-trips. A single bundle verb returning all
three saves the latency + token tax on every session start.

## 1. Problem

Sessions cold-start by composing `current_state` (ANTS-1569,
ETag-eligible) + `project_layout` (ETag-eligible) + `roadmap_query
mode:section_index status:"active"` (ETag-eligible) to orient
themselves. Each call costs a round-trip and (when state hasn't
changed) a 304 negotiation. Three separate ETags mean three
separate "did anything change?" checks, each potentially missing
the cache.

## 2. Surface

### 2.1 New verb

`session_orient` — a new MCP tool that composes the three
on-disk reads into one envelope. Behaviour:

```cpp
QJsonObject result;
result["ok"]   = true;
result["current_state"]   = <body of cmdCurrentState>;
result["project_layout"]  = <body of cmdProjectLayout>;
result["sections_index"]  = <body of cmdRoadmapQuery with
                             mode:"section_index" status:"active">;
```

Each upstream call is made with the same `caller_cwd` the caller
passed. The bundled ETag is computed at the dispatch layer over
the serialized envelope bytes, same as every other ETag-supported
tool.

Note on `mode:"section_index" + status:"active"`: per ANTS-1437
INV-7 as amended by ANTS-1848, the `status:"active"` filter is
NOT a no-op for section_index mode — it drops sections whose
`active_count_id_only` is 0 (the lean planning slice — exactly
what session-orientation needs). Without the filter the index
would include every shipped release block.

**Partial-failure contract.** When any upstream call returns
`ok:false`, the bundle's top-level `ok` is `false` AND the
failing upstream's verbatim refusal envelope is embedded at its
respective key. Succeeding upstreams still emit their bodies at
their keys; the caller can use those even on a partial failure.
The bundle's top-level `ok` is `true` IF AND ONLY IF all three
upstreams succeeded — the caller never has to merge partial data.

### 2.2 Dispatch + descriptor

Implementer touchpoints (four files, named explicitly so a
partial implementation can't ship):

- `src/remotecontrol.cpp` + `src/remotecontrol.h` —
  `RemoteControl::cmdSessionOrient` new method, same shape as
  `cmdSessionBrief`.
- `src/mainwindow.cpp` (the dispatch table at line ~4805) — add
  `rcDelegate(&RemoteControl::cmdSessionOrient)`.
- `src/claudeintegration.cpp` — register in FOUR places:
  1. `tools/list` descriptor (new `sessionOrientTool` block,
     placed alongside the `sessionBriefTool` block).
  2. `isEtagSupportedTool` allowlist: add
     `"session_orient"`.
  3. `callerCwdContractFor`: add an explicit row mapping
     `"session_orient"` → `Required` (matches `session_brief`
     precedent).
  4. `tokenCostFor` table: add `{"session_orient", {2500, 15000}}`
     — composer of three large reads, so the typical / worst-case
     bucket is the sum of the constituents.

### 2.3 No new caches

Composer-only. Each upstream call uses its existing cache; no
new cache shape is introduced. The bundle's ETag is one
sha256(payload) hash that flips when any of the three upstreams'
payloads flips — naturally combining the three independent
freshness signals into one.

**Trade-off.** The combined ETag flips MORE often than any
individual ETag would (any change to project state ⇒ bundle
miss). On a busy repo where only one component changes at a
time, three separate calls would 304 more frequently than the
bundle does. Cold-start orientation (Vestige's actual use case)
benefits from the bundle's one round-trip; warm-cache mid-session
polling is better served by the individual verbs.

## 3. Invariants

- **INV-1** — `session_orient` envelope on success carries
  `ok:true` plus the three keys
  `current_state`, `project_layout`, `sections_index`. Each
  key's value is the verbatim body of the upstream call (no
  re-shaping, no key renaming). *Test:*
  `tests/features/session_orient_bundle/test_session_orient_bundle.cpp::Inv1EnvelopeShape`.
- **INV-2** — `session_orient`'s `sections_index` upstream call
  uses `mode:"section_index"` AND `status:"active"`. Per
  ANTS-1437 INV-7 as amended by ANTS-1848, `status:"active"` is
  meaningful for section_index mode (drops sections with
  `active_count_id_only:0` — the lean planning slice). *Test:*
  `…::Inv2SectionsIndexModeAndStatus`.
- **INV-3** — `session_orient` is in `isEtagSupportedTool`. The
  dispatch-layer `applyEtagPattern` wraps the response, computing
  one sha256 over the serialized bundle bytes. *Test:*
  `…::Inv3EtagAllowlistMembership`.
- **INV-4** — `CallerCwdContract` for `session_orient` is
  `Required` (matches `session_brief`'s precedent). *Test:*
  `…::Inv4CallerCwdRequired`.
- **INV-5** — `tools/list` schema declares the new tool with a
  description naming all three composed verbs. *Test:*
  `…::Inv5ToolsListDescribesBundle`.
- **INV-6** — Top-level `ok` is `true` iff ALL three upstreams
  succeeded. On any upstream `ok:false`, the bundle's top-level
  `ok` is `false` AND the failing upstream's verbatim refusal
  envelope is embedded at its respective key. *Test:*
  `…::Inv6PartialUpstreamFailure`.
- **INV-7** — `tokenCostFor` table carries
  `{"session_orient", {2500, 15000}}` (or a similar bucket
  matching the bundled sum of the three constituents). *Test:*
  `…::Inv7TokenCostBucketRegistered`.

## 5. RAM / build cost

Zero new state. ~70 LoC composer in `cmdSessionOrient`, ~25 LoC
descriptor entry, ~15 LoC `isEtagSupportedTool` +
`callerCwdContractFor` + dispatch registration, ~120 LoC test →
**~230 LoC** total.

## 6. Migration

None. Additive verb. Existing `current_state`, `project_layout`,
`roadmap_query` calls byte-identical.

## 7. Tool-descriptor update

New `sessionOrientTool` block registered alongside
`sessionBriefTool` in `claudeintegration.cpp`'s `tools/list`
builder. Description: *"Single-call session-orientation bundle:
composes current_state (project / git / audit state) +
project_layout (where docs/specs/roadmap live) + roadmap_query
mode:section_index status:\"active\" (active roadmap sections)
into one envelope. Use as the first read on a fresh /clear
session — saves three MCP round-trips and three ETag misses vs
the per-verb-call orientation pattern (ANTS-1883)."*
