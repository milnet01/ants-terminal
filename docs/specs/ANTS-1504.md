## 1. Problem

`audit_run` re-scans the whole tree on every invocation. In the default
fix-then-verify loop (edit a file, re-audit, repeat), running cppcheck /
clazy / clang-tidy across the entire project when only one file changed
is wasted wall-clock — the per-tool caps bound it, but the work is real
and the iteration is slow.

The `scope` arg *looks* like it already solves this — the tool descriptor
advertises `"files"` = "changed-since-fork-point only", `"since-tag:<t>"`
= "git diff vs tag", `"branch-diff"` = "main..HEAD". **It does not.**
`scope` is consumed in exactly two places in `src/auditrunner.cpp`:
since-tag string sanitisation (`:1101`) and recording the scope label
into the manifest (`:1452`). Nothing turns `scope` into a narrowed file
set — `toolArgv` (`:238`) only narrows when the separate `paths` request
arg (`scopedPaths`, ANTS-1512) is non-empty, and only cppcheck (`:285`)
and clang-tidy (`:305`) consume it. So `scope:"files"` / `"branch-diff"`
/ `"since-tag:X"` all run the identical full scan today.

This item adds `scope:"since-last-run"` — anchored to the prior cached
run's commit — and, since the narrowing plumbing must be built anyway,
wires it through `scope:"files"` / `"branch-diff"` / `"since-tag:<t>"` so
those stop being no-ops, and extends the scoped-argv mechanism from 2
tools to every file-oriented tool.

**Layman:** when you re-run the code checker after editing one file, only
re-check the files you actually changed instead of the whole project —
much faster on a tight edit/check loop.

## 2. Surface

### 2.1 New scope value + the shared resolver

`RunRequest.scope` (`src/auditrunner.h:36`) gains `"since-last-run"`
alongside the existing `auto` / `files` / `since-tag:<t>` / `branch-diff`.

A new module `src/auditscope.{h,cpp}` (namespace `AuditScope`) owns
changed-file resolution, split pure/impure so the parsing/filtering is
unit-testable without spawning git (mirrors `ReadLog::filter` and the
`AuditEngine` pure-function pattern, INV-9):

- **Impure** `resolveChangedFiles(canonProject, scope, anchorCommit) →
  Resolution` — runs the git commands (reusing the `runGit` QProcess
  pattern from `auditcache.cpp:39`, `SeparateChannels`, `kGitTimeoutMs`
  applied to *both* start and finish → ~3 s worst case per call)
  and calls the pure helpers. Returns the narrowed project-relative file
  list plus a `demoted` reason (empty when not demoted).
- **Pure** `parseChangedFiles(diffNameOnly, statusPorcelain, includeWorkingTree)
  → QStringList` — parses `git diff --name-only` output ∪
  `git status --porcelain` (when `includeWorkingTree`), dropping deleted
  entries (`D ` / ` D` status, and paths absent from the diff target).
- **Pure** `filterForTool(files, tool) → QStringList` — keeps only files
  whose extension matches the tool's language set (§ 2.3).
- **Pure** `isFileScopedTool(tool) → bool` — false for `gitleaks` /
  `trivy` (§ 2.4).

### 2.2 Anchor per scope

The narrowing scopes share one resolver, differing only in the git range
and whether uncommitted work is included. They follow
**`docs/specs/ANTS-1351.md:52`**: `branch-diff` (`main..HEAD`) and
`since-tag` (`<t>..HEAD`) verbatim, and `files` wraps that row's
`git merge-base HEAD origin/<default-branch>` base (with its `HEAD~1` →
full fallback) in the same `<base>..HEAD` diff form. ANTS-1351 is the
canonical `audit_run` runner spec; those rows were never implemented
(§ 1), so this is their first wiring, not a redefinition:

| scope | git range | working tree? |
|---|---|---|
| `since-last-run` | `git diff --name-only <prior.commit>..HEAD` | yes (`status --porcelain`) |
| `files` | `git diff --name-only <merge-base>..HEAD`, `<merge-base>` = `git merge-base HEAD origin/<default-branch>` (falls back `HEAD~1`, then full scan) | yes |
| `branch-diff` | `git diff --name-only main..HEAD` | no |
| `since-tag:<t>` | `git diff --name-only <t>..HEAD` (tag sanitised per ANTS-1351 INV-15) | yes |
| `auto` / empty | — (full scan, unchanged) | — |

`<prior.commit>` is the short sha (or the literal `"nogit"`) written into
the manifest at `auditrunner.cpp:1447` (`lastRunJson["commit"] =
gitI.shortSha`) and read back via
`AuditCache::loadManifest(canonProject).lastRun.value("commit")`
(a `QJsonObject` lookup — `auditcache.cpp:137` reads `last_run`). The
two-dot `<base>..HEAD` form compares endpoint trees, so it is correct
across branch switches.

Untracked files (`??`) are **included** (a new source file is a change to
re-check); deleted files (`D`) are **excluded** (nothing to scan).

### 2.3 Per-tool language filter

Only files matching a tool's languages are passed to it:

| tool | extensions |
|---|---|
| cppcheck, clazy, clang-tidy | `.c .cc .cpp .cxx .c++ .h .hh .hpp .hxx` |
| ruff, bandit, mypy | `.py .pyi` |
| shellcheck | `.sh .bash` |
| semgrep | all changed files (semgrep self-selects by rule language) |

A file-scoped tool whose filtered set is **empty** is not spawned; it is
recorded in `tools_skipped` with reason `no_changed_files_for_languages`.
This is the common fast-loop outcome (edit one `.cpp` → only the C/C++
tools run).

### 2.4 Repo-global tools

`gitleaks` (secret scan) and `trivy` (dependency/vuln scan) are
repo-global — a secret or a vulnerable dependency is not tied to the
files you just edited. Under **any** narrowing scope they are skipped and
recorded in `tools_skipped` with reason `not_file_scoped`. A full
`scope:"auto"` run still covers them. (Per § 8 sign-off.)

### 2.5 Extending `toolArgv` to the file-oriented tools

`toolArgv` (`src/auditrunner.cpp:238`) currently appends `scopedPaths`
only for cppcheck and clang-tidy. Extend the remaining file-oriented
tools so the narrowed list replaces their default whole-tree target when
non-empty (default behaviour unchanged when empty):

- `ruff` — `check <files…> --output-format=json` (replaces `check .`)
- `bandit` — `<files…> -f json -ll` (explicit files; drop the `-r` dir
  recursion that targets `srcRoot`)
- `mypy` — `--no-color-output <files…>` (replaces `.`)
- `shellcheck` — `-f json -S warning <files…>` (replaces `scripts`)
- `clazy` — append the files to the existing argv:
  `clazy -checks=level1 -p …/build/compile_commands.json <files…>`
  (keep `-checks=level1`; the tool key is `clazy`, `auditrunner.cpp:289`).
  Confirm at wiring that the resolved clazy binary honours source-file
  positionals alongside `-p`; if it does not, clazy stays full-tree under
  narrowing (skip it like a repo-global tool, § 2.4).
- `semgrep` — `--json … --config p/security-audit <files…>` (replaces
  the trailing `.`)

The scoped list is plumbed as a per-tool argument (the run loop at
`:1275`-`1327` issues the `proc->start(…, toolArgv(tool, …, req.paths,
req.checks))` call at `:1324`-`1326` — the narrowing scopes substitute the per-tool filtered set
for `req.paths`).

### 2.6 Path safety

Every git-derived path is re-validated through `isAuditArgSafe`
(`auditrunner.cpp:208`) before reaching argv — the same gate
caller-supplied `paths` pass (`:1119`-`1126`). A path failing the gate is
**dropped** from that tool's set (not a whole-call refusal — git-derived
paths are not caller-supplied, and a single odd filename must not abort
the run). If dropping empties a tool's set, it is skipped as in § 2.3.

### 2.7 Stale-cache fallback

`since-last-run` needs a usable prior commit. When it is unavailable the
run **demotes to a full scan** (behaves as `scope:"auto"`) and the
envelope carries `scope_demoted:"full"` + `scope_demoted_reason`:

- `no_prior_run` — manifest `last_run` empty (project's first sweep).
- `no_prior_commit` — `last_run.commit` empty or `"nogit"`.
- `prior_commit_unreachable` — the commit is gone from history
  (rebase / force-push); verified with
  `git cat-file -e <commit>^{commit}` (non-zero exit → unreachable). An
  ambiguous short-sha prefix also fails this check, so it demotes here
  rather than diffing the wrong commit.
- `not_git` — project root is not a git work tree.
- `no_merge_base` — `files` only: neither `git merge-base HEAD
  origin/<default-branch>` nor `HEAD~1` resolves (shallow clone, root
  commit, detached CI with no remote), so the `files` fallback chain
  (§ 2.2) exhausts to a full scan.

A demoted run records normally (it *is* a full scan). `branch-diff` /
`since-tag` demote only on `not_git`; `files` also demotes on
`no_merge_base`; `since-last-run` demotes on any of the prior-commit
reasons above.

### 2.8 Empty-changeset short-circuit

When a narrowing scope resolves to **zero** changed files (clean tree,
HEAD == anchor — the "re-audited 30 s later, nothing changed" case), the
run returns early:

- No tools are spawned.
- Envelope carries `no_changes:true` + `scope_anchor_commit`.
- `recordRun` is **skipped** — recording an empty scan would migrate the
  real `last_run` into history and reset `last_run.commit` to HEAD,
  destroying the anchor the *next* `since-last-run` needs. (A demoted
  full scan is not empty and records normally.) The early return must sit
  **before** the SARIF write + cache-record block (the
  `if (!r.cachePath.isEmpty())` gate at `auditrunner.cpp:1444`, through the
  `recordRun` call `:1481`), so no `.audit_cache/` file is written either.
- `ok:true`, `total_raw:0`, `by_tool:{}`, `scope_resolved:"since-last-run"`
  (or the requested narrowing scope), `changed_files_count:0` — the
  always-on envelope fields of INV-8 still appear.

### 2.9 Recording semantics

A non-empty `since-last-run` records a run normally
(`AuditCache::recordRun`, `auditrunner.cpp:1481`), advancing
`last_run.commit` to HEAD so the next loop iteration diffs from here. The
recorded SARIF is **partial** (only the changed-set tools ran) — the
`last_run.scope` label (`"since-last-run"`) flags this so a consumer
(`last_audit_summary`) can tell it is not a whole-tree picture. This
partial-SARIF caveat is documented, not solved, in this pass (§ 5).

### 2.10 Envelope additions

Added to the `audit_run` reply built in the envelope block at
`src/mainwindow.cpp:4211`+ (beside the existing `tools_skipped` at
`:4246` / `prior_run` at `:4260`):

```json
{
  "scope_resolved": "since-last-run",   // effective scope; "full" when demoted
  "scope_anchor_commit": "<short-sha>", // when a narrowing scope ran
  "changed_files_count": 3,             // files in the resolved set
  "scope_demoted": "full",              // present only when demoted
  "scope_demoted_reason": "prior_commit_unreachable",  // with scope_demoted
  "no_changes": true                    // present only on the empty short-circuit
}
```

New `RunResult` fields (appended after the ANTS-1555 `cachePath` /
`priorRun` members, `auditrunner.h:84`): `scopeResolved`,
`scopeAnchorCommit`, `changedFilesCount`, `scopeDemoted`,
`scopeDemotedReason`, `noChanges`.

## 4. RAM / build cost

No persistent state and no new cache: the changed-file set is a transient
`QStringList` bounded by the number of files changed since the prior run
(tens, not thousands, in the target loop) and freed when the run
returns. One new small translation unit (`auditscope.cpp`, est.
~150-200 lines) joins `ants_audit_lib`; no new external dependency. The
git calls reuse the existing `runGit` pattern (`kGitTimeoutMs` on both
start and finish → ~3 s worst case per call, then SIGKILL), so a hung git
cannot stall the audit pool beyond that. Net effect on a fix-verify loop
is **less** work (fewer tool invocations, smaller file sets), not more.

## 5. Out of scope

- **Precise `delta:{added, removed, carried_forward}`** (the roadmap
  bonus). The v1 SARIF is a per-tool raw-output blob, not per-finding
  result entries (`auditrunner.cpp:18-28` "v2 will parse the SARIF result
  entries"), so prior-vs-current finding attribution per file is
  impossible without that parser. Computing a coarse count delta across
  mismatched scopes (prior full vs current subset) would be misleading,
  so no delta is emitted. Filed as a follow-up tied to the SARIF-parser
  work (§ 7). The envelope's `changed_files_count` + changed-set counts
  are the honest at-a-glance signal for this pass. **This re-scopes** the
  ROADMAP "Update (2026-05-25)" items (a) carry-forward merge + (b) delta
  envelope to that follow-up; `ANTS-1555.md` § 4 already points the
  SARIF-merge work here, and is updated to defer it likewise. The v1 blob
  SARIF is the blocker, not effort. Item (c) — the stale-cache fallback —
  *is* delivered here (§ 2.7).
- **Carry-forward SARIF merge** (prior findings on untouched files folded
  into the new SARIF) — same blocker as the delta; same follow-up.
- **Making the recorded `since-last-run` SARIF whole-tree** — it is
  partial by design (§ 2.9); the `scope` label flags it.

## 8. Resolved decisions (2026-05-25 sign-off)

1. **Faithful scope.** Build the changed-files→scoped-argv plumbing once;
   extend it to every file-oriented tool and wire it through the
   currently-no-op `files`/`branch-diff`/`since-tag` scopes — not just a
   2-tool `since-last-run`.
2. **Repo-global tools skipped.** `gitleaks` + `trivy` are skipped under
   narrowing scopes with `not_file_scoped`; a full `auto` run covers them
   (§ 2.4).
3. **Precise delta deferred.** No `delta` field this pass; deferred to the
   v2 per-finding SARIF parser rather than shipping a misleading coarse
   count (§ 5, § 7).
