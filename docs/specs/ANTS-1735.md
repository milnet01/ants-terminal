# ANTS-1735 — Autonomous Claude Code model switcher + effectiveness ledger

**Status:** spec draft — cold-eyes loops 1-3 converged (clean pass), awaiting sign-off (2026-05-25).
**Kind:** implement.
**Source:** ROADMAP.md ANTS-1735 (Shape B of ANTS-1226; user-request 2026-05-21, expanded 2026-05-25: fully autonomous, vibe-coder-friendly, must measure its own effectiveness; cooperative-session-pause idea 2026-05-25 — researched, infeasible today, § 2.2).
**Pairs with:** ANTS-1226 (Shape A — passive recommender chip, shipped 0.7.92).
**Blocker for:** ANTS-1872 (auto thinking-level control — § 5).
**Blocked by (preconditions):** § 8 spike S1 (injected `/model` switch vs picker) and S2 (idle-window empty-composer proxy) must pass before implementation commits.
**Relates to:** ANTS-1871 — upstream ask, Claude Code "pause-for-switch" handshake (§ 5) — the only path that fully removes the residual injection race.

## 1. Problem

ANTS-1226 shipped Shape A: a passive status-bar chip that scores session
complexity (`src/modelrecommender.cpp`) and, when the recommended tier differs
from the running model, shows `→ Opus` / `→ Haiku`; clicking it injects
`/model <tier>\n` into the focused terminal
(`src/claudestatuswidgets.cpp:147-148`).

The user reports (2026-05-25) Shape A does not serve them:

1. **The manual click is barely used** — it interrupts flow; the user must
   notice the chip, decide, and click mid-task.
2. **The switch is not seamless** — clicking surfaces `/model` as a command
   at whatever moment the click lands.
3. **The target user is a vibe coder** who does not know Haiku from Opus and
   should never have to. They want the right model chosen for them, zero input.
4. **There is no way to know if routing helps.** The user does not click, so
   Shape A's premise — "graduate to auto-switch once the chip earns trust" —
   has no trust signal to read.

So the value ANTS-1226 targeted (conserve the scarce Opus quota on a Max(5)
subscription for the turns that need it; give Opus to the hard turns) is
unrealised because the human-in-the-loop step is the bottleneck.

A research pass (claude-code-guide, 2026-05-25) pinned the mechanism
constraints this design must live within:

- **Hooks cannot set the model.** No Claude Code hook event (`UserPromptSubmit`
  included) exposes a `model`/`modelOverride` field. ANTS-1226's "auto-switch
  via hook" option (b) is **not feasible** and is abandoned.
- **`/model <alias>` is the only live mid-session switch.** `settings.json`
  `"model"`, `ANTHROPIC_MODEL`, and `--model` take effect at session start
  only. So the switch mechanism *must* remain PTY injection of `/model`, as
  Shape A does — the work is *when* and *whether* to inject, not a new
  mechanism. Two facts about that injection are **unproven and gate the design
  (§ 8 spikes), not assumed**: whether an injected `/model <alias>` switches
  directly or raises an interactive picker, and whether we can reliably tell
  Claude's input composer is empty before injecting.
- **Each switch costs one cache rebuild.** The first turn after a switch
  re-reads context uncached. Cache TTL is 5 min on the metered API but **1 hour
  on Claude subscription plans** (the user's case), so thrash is less punishing
  here, but a switch is never free — switching is damped to task boundaries.
- **`message.model` in the transcript JSONL is canonical** for the running
  model (already what `ModelRecommender::score` reads).

## 2. Surface

### 2.1 Reuse, don't rebuild, the scorer

`ModelRecommender::score(transcriptPath)` →
`{Tier tier, QString reason, QString currentModel}`
(`src/modelrecommender.h:10-14`) stays the single source of the
recommendation. `currentModel` is a **raw model-id string**, not a `Tier`
(`src/modelrecommender.cpp:82-85`); the running tier is derived with
`ModelRecommender::tierFromModelId(rec.currentModel)`, exactly as the chip does
(`src/claudestatuswidgets.cpp:1168-1169`). Shape B adds an *actuator* and a
*ledger* around the scorer; it does not change the heuristic. (Heuristic
breadth is ANTS-1226 scoring work, § 5.)

### 2.2 The two unproven mechanism facts (resolve in § 8 before building)

The whole "seamless, never mid-turn" promise rests on two capabilities the
project does **not** have today:

- **Direct switch (spike S1).** If `/model opus\n` injected at the prompt
  switches the model directly, autonomy is viable. If it raises Claude's
  interactive picker/confirmation, autonomous injection drops a modal into the
  session with no one to dismiss it — *worse* than Shape A and a direct
  violation of the zero-input goal. **Go/no-go.**
- **Empty-composer detection (spike S2).** Claude Code is a full-screen TUI
  that redraws its own composer; OSC 133 marks the *shell* prompt
  (`terminalgrid.h:105-114`, `commandStartCol`), **not** Claude's input box,
  and `TerminalWidget` exposes no current-edit-line accessor (only
  `lineText(globalLine)` at `terminalwidget.h:366`, which includes prompt
  text). So "is the user mid-compose?" cannot be read from the grid reliably.
  The design's answer (§ 2.4) is a *keystroke-timing* proxy that sidesteps grid
  parsing; S2 validates that proxy on a live session.

**Cooperative session-pause: researched, infeasible today.** The cleanest fix
to the timing problem would be for the Claude Code session to cooperate —
*pause at a safe boundary, let Ants switch, then resume*. A research pass
(claude-code-guide, 2026-05-25) found this is **not achievable on the
interactive `claude` CLI**: (a) no hook event (`Stop`, `UserPromptSubmit`,
`SessionStart`, …) carries a `model` field — none can change the model; (b) a
hook can block at a turn boundary (exit 2) but the input-queue ordering of a
`/model` injected *during* that block is undocumented, so a "pause → inject →
resume" handshake has no reliable-execution guarantee; (c) the Claude *Agent
SDK* (Managed Agents) does expose `user.interrupt` + a `session.update` that can
change the model on resume — the capability exists — but the interactive CLI
harness does not surface it. Two findings are nonetheless usable: a `Stop` hook
fires reliably once per turn-end and can give Ants a *precise* idle signal
(tighter than the 2 s state poll — § 2.4); and `/model <alias>` placed ahead of
a prompt in the same input stream executes *before* the prompt, so the switched
model is active for that turn. **The proper fix — a Claude Code "pause-for-
switch" handshake — is filed as an upstream ask (§ 5).** Until it exists, the
design lives with the documented residual race (OQ-1).

### 2.3 The autonomous controller

A controller in `ClaudeStatusBarController` (`src/claudestatuswidgets.{h,cpp}`)
runs on the existing 2 s status timer (interval set at `src/mainwindow.cpp:749`;
`refreshModelChip` wired at `:783-784` — the controller wires alongside it).
The gate decision is a pure helper, unit-testable without a live terminal:

```cpp
// src/modelautoswitch.h — pure decision helper (Qt::Core only).
namespace ModelAutoSwitch {

struct Gate {
    bool enabled            = false;  // config: claude.auto_model_switch
    ClaudeState focusedState = ClaudeState::NotRunning; // focused tab's
                                       // per-shell state (see below)
    bool composerEmpty      = true;   // keystroke-timing proxy (§ 2.4)
    ModelRecommender::Tier current;       // tierFromModelId(rec.currentModel)
    ModelRecommender::Tier recommended;   // rec.tier
    ModelRecommender::Tier floor;         // config: claude.auto_model_floor
    int    ticksTargetStable = 0;     // consecutive ticks clampedTarget != current
    qint64 msSinceLastSwitch = 0;     // dwell since this tab last switched
};

struct Decision {
    bool    act = false;
    QString tierArg;   // "haiku"|"sonnet"|"opus" — clamped target alias
};
// The ledger's `score_reason` comes from the scorer's `rec.reason`, not from
// the Decision — `decide` carries no reason of its own (kept minimal).

// clampToFloor(rec, floor): a recommendation below the floor returns the
// floor; floor never constrains an upgrade (Opus is always allowed through).
ModelRecommender::Tier clampToFloor(ModelRecommender::Tier rec,
                                    ModelRecommender::Tier floor);

// decide(): acts only when ALL hold:
//   enabled
//   focusedState == Idle              (focused tab's per-shell state, not the
//                                      global m_state — C1)
//   composerEmpty                     (keystroke proxy — § 2.4)
//   clampToFloor(recommended,floor) != current   (hysteresis is computed on
//                                                  the CLAMPED target, so a
//                                                  clamped-to-current rec never
//                                                  accumulates — no livelock)
//   ticksTargetStable >= kStableTicks (default 2 → ~4 s)
//   msSinceLastSwitch >= kMinDwellMs  (default 90 s)
// On act: tierArg = tierName(clampToFloor(recommended,floor)).
Decision decide(const Gate &g);

constexpr int    kStableTicks = 2;
constexpr qint64 kMinDwellMs  = 90'000;

}  // namespace ModelAutoSwitch
```

**Per-tab state (resolves C1).** `ClaudeIntegration::currentState()` is a single
process-global `m_state` (`claudeintegration.h:89,483`; the `:1112`/`:1139`
comments document the singleton + sibling-tab contention guards). Building the
gate from it would let the controller inject into focused tab A while A's Claude
is mid-turn because `m_state` reflects tab B. Instead the controller reads the
**focused tab's own per-shell state**:
`m_tracker->shellState(focused->shellPid()).state` — the controller already
holds `m_tracker` and uses exactly this call elsewhere
(`claudestatuswidgets.cpp:205-207`). Because the score (focused transcript) and
the state (focused shell pid) are both read from the *same* focused terminal,
they are consistent by construction — no global `currentState()`, and no
`isFocusedTabSession` cross-check needed (that method is private anyway,
`claudeintegration.h:480`). `focusedState == Idle` then means *this* tab's
Claude finished its turn.

On `act`, the controller injects with the **same** call Shape A uses:
`focused->sendToPty((u"/model " + dec.tierArg + u"\n").toUtf8())`, records a
ledger entry (§ 2.5), resets `ticksTargetStable`, stamps the last-switch time.

### 2.4 The injection window — when the composer is provably empty

Rather than parse Claude's TUI for composer contents (S2 shows this is
unreliable), the controller injects only in the window where the composer is
*provably* empty: **between the moment the focused tab's Claude state transitions
into `Idle` (turn finished) and the user's first keystroke of the next
message.** In that window the user has not yet typed, so the composer is empty by
construction.

The signal is `ClaudeState::Idle` — the turn-finished resting state — **not** the
`ShellState::awaitingInput` overlay, which the tracker sets only on a
PermissionRequest hook / scrollback scan (`claudetabtracker.cpp:59-89`,
`mainwindow.cpp:2256,2332`), i.e. "blocked on an Allow/Deny prompt," not "turn
done." (Loop-2 finding: keying the window on `awaitingInput` would make the
switcher never fire on the normal path.)

Two timestamps drive `composerEmpty`:

- `idleSinceMs` — epoch-ms when the focused shell's per-tab state last
  *transitioned into* `Idle`. **This timestamp does not exist today** —
  `ShellState` records only the current state, not when it was entered. New work:
  stamp it in `ClaudeTabTracker` where the per-shell state is updated (the
  `maybeEmit`/state-write path, `claudetabtracker.cpp`) whenever the new state
  is `Idle`; re-stamped on *every* entry to `Idle` (not just the first), so each
  turn boundary reopens the window. (The static `lastEventTimestampMs(path)`
  helper at `claudeintegration.h:148` is a viable alternative source — pick one
  in implementation.) Initial value `0`.
- `lastUserKeystrokeMs` — epoch-ms updated in `TerminalWidget::keyPressEvent`
  (`terminalwidget.cpp:1575`, confirmed the user-keystroke interception point)
  *before* the key is forwarded to the PTY. New member. Initial value `-1`, so a
  never-typed post-turn composer reads empty.

`composerEmpty == (lastUserKeystrokeMs < idleSinceMs)` — no keystroke since the
turn ended. With the `-1`/`0` initials, a fresh post-turn composer reads empty
(`-1 < 0`); once the user types, `lastUserKeystrokeMs` advances past
`idleSinceMs` → non-empty until the next `Idle` entry re-stamps `idleSinceMs`
above it. So a half-typed prompt is never clobbered.

**Optional precision (from the cooperative-handshake research).** A `Stop` hook
fires once per turn-end and could write the focused session's idle signal at the
exact boundary, giving a crisper trigger than the 2 s poll. This is an
implementation refinement of the *same* idle gate, not a different mechanism; it
narrows but does not close OQ-1.

**Residual race (OQ-1).** A keystroke in the same tick as the PTY write is still
possible; the window is one tick and the failure is benign (a `/model` line
precedes their text). It cannot be fully closed without the upstream
pause-for-switch handshake (§ 5), which the research found does not exist today.
Documented, not hidden.

### 2.5 Effectiveness ledger — the trust signal (and its blind spots)

Because the user will not click, **measured outcomes replace click-acceptance**
as the evidence the feature works. Every auto-switch appends one record;
outcomes are filled by a later tick once the next turns have run.

Storage: `~/.cache/ants-terminal/model-switch-ledger.jsonl` (JSONL, mode 0600
via `setOwnerOnlyPerms()` — `src/secureio.h:33,37`). A **256 KiB** drop-oldest
byte cap evicting whole oldest lines — the *pattern* mirrors `read_log`'s
whole-line drop (`src/readlog.cpp:126-128`, partial lines held back), but the
append + on-disk eviction + pending-pinning is **new code**, not a call into
`ReadLog::filter` (which is a read-path filter). A record whose outcome is still
pending is **pinned** (never evicted) until filled, so the dwell/outcome
lifecycle can never lose an in-flight measurement (resolves M7/MEDIUM-3).

```json
{
  "ts": "2026-05-25T14:02:11Z", "session_id": "abc123",
  "project": "/mnt/.../Ants_Terminal",
  "from_tier": "opus", "to_tier": "haiku",
  "score_reason": "mechanical", "trigger": "auto",
  "outcome": {
    "turns_on_to_tier": 6,
    "user_override_within_5_turns": false,
    "correction_signal_within_5_turns": false,
    "under_route_signal_within_5_turns": false,
    "pending": false
  }
}
```

Outcome fields and their honest limits:

- **`turns_on_to_tier`** — assistant turns on the new tier before the next
  switch (the dwell actually achieved). Pending records (switch near session
  end, no later turns) keep `pending:true` and are reported separately by
  `model_switch_stats`, never silently counted as success.
- **`user_override_within_5_turns`** — a `/model` change in the transcript
  within 5 turns that the ledger did **not** itself log as `trigger:auto`
  (resolves H3: the controller's own injection is indistinguishable in
  `message.model`, so authorship is decided by correlating against the ledger's
  own auto records). **Correlation key:** a transcript `/model X` is treated as
  *auto-authored* iff an auto ledger record exists with `to_tier == X` and
  `|ts_transcript − ts_ledger| ≤ kAuthorWindowMs` (default 10 s); otherwise it
  is a user override. This disambiguates two auto-switches inside one 5-turn
  window (each transcript `/model` matches its own record by tier+time), so
  switch-A never counts switch-B as an override. *Weak signal by construction* —
  the user rarely types `/model`, so a low override count must NOT be read as
  success on its own.
- **`correction_signal_within_5_turns`** — set only on a *downgrade*, only on
  the **first** user turn after the switch, matching
  `/\b(no|wrong|that's not|undo|revert|try again)\b/i` over transcript text.
  The regex is linear (no ReDoS) but false-fires on prose ("no problem", "undo
  stack"); treated as a **soft** indicator, never ground truth (MEDIUM-2).
- **`under_route_signal_within_5_turns`** — the counter-metric the product-fit
  review demanded: set when, within 5 turns of a *downgrade*, the scorer
  re-recommends a *higher* tier (a "should have stayed up" signal). This is the
  only signal for the silent-failure mode where a cheap tier under-serves and
  the user just lives with worse output.

`model_switch_stats` (new MCP read verb, **`caller_cwd` Required** — matching
`roadmap_query`/`audit_run` at `mainwindow.cpp:4048,4137`, not Optional;
ETag/`fields` opt-in) aggregates for the caller's project:
`{ok, switches, downgrades, upgrades, opus_turns_avoided, opus_turns_routed_in,
regret_count, regret_rate, under_route_count, pending_count, by_tier:{…}}`.
The headline is reported **as a ratio**, never the flattering numerator alone:
"avoided N Opus turns, M regretted (regret R%)" — so a too-aggressive scorer
that downgrades everything cannot score well on volume while doing harm
(MEDIUM-1). The same line feeds the chip tooltip.

**Why these metrics, not dollars.** A Max(5) subscription has no per-token
bill; the scarce resources are the **Opus weekly quota** and turn latency. So
effectiveness is *Opus turns avoided* vs *regret/under-route rate*. A low
combined regret+under-route rate with meaningful `opus_turns_avoided` is the
green light to trust the autonomy (and later extend it — § 5). The spec
explicitly acknowledges low regret may reflect user *passivity*, which is why
the under-route signal carries the weight the override signal cannot.

### 2.6 Chip coherence under autonomy

When `claude.auto_model_switch` is **on**, the Shape A chip is **suppressed
entirely** (hidden, not merely "hides when rec==current"). Otherwise, during the
90 s dwell a fresh recommendation would re-show a clickable `→ Opus`,
reintroducing exactly the manual-decision surface the user wants gone
(product-fit MEDIUM). With auto on, the user is never shown a button. When auto
is off, the chip behaves exactly as today (zero change to Shape A).

### 2.7 Config

Typed accessors on `Config` (`src/config.h` uses dedicated getters, not a
generic `value(key)`; a `claudeAutoModel()` QJsonObject accessor mirrors the
existing `roadmapStatusFilters()` shape — LOW-1):

- `claude.auto_model_switch` (bool, default **false** for the introducing
  release; § 8 defines the gate to flip default-on).
- `claude.auto_model_min_dwell_sec` (int, default 90, clamp [30, 1800]).
- `claude.auto_model_floor` (`haiku|sonnet`, default `haiku`) — cheapest tier
  the switcher may drop to.

A single prominent Settings toggle ("Let Ants pick the Claude model for me")
flips `auto_model_switch`; the two tuning keys are config-file only.

## 3. Invariants

- **INV-1** — `decide` returns `act=false` when `enabled` is false, regardless
  of other fields. *Test:* `tests/features/model_auto_switch/`.
- **INV-2** — `decide` returns `act=false` when `focusedState != Idle`, where
  `focusedState` is the focused tab's *per-shell* state
  (`m_tracker->shellState(focused->shellPid()).state`), never the process-global
  `currentState()`. *Test:* `tests/features/model_auto_switch/` — one case per
  non-Idle `ClaudeState` value (`claudeintegration.h:47-53`: NotRunning,
  Thinking, ToolUse, Compacting).
- **INV-3** — `decide` returns `act=false` when `composerEmpty` is false, where
  `composerEmpty == (lastUserKeystrokeMs < idleSinceMs)`, `idleSinceMs` is
  re-stamped on every transition into `Idle`, and the initial stamps
  (`idleSinceMs=0`, `lastUserKeystrokeMs=-1`) make a never-typed post-turn
  composer read empty. *Test:* `tests/features/model_auto_switch/` drives the two
  timestamps across the turn-end → type → next-turn sequence; live behaviour
  validated by spike S2.
- **INV-4** — `decide` acts only when `clampToFloor(recommended,floor) !=
  current`. *Test:* same.
- **INV-5** — `decide` requires `ticksTargetStable >= kStableTicks`, where
  stability is counted against the **clamped** target (a clamped-to-current
  recommendation never accumulates → no livelock). *Test:* same — floor=sonnet
  + persistent Haiku rec must NOT churn.
- **INV-6** — `decide` requires `msSinceLastSwitch >= kMinDwellMs`. *Test:* same.
- **INV-7** — when `decide` acts, `tierArg` is the lowercase alias
  (`haiku`/`sonnet`/`opus`) of the clamped target, never a full model id.
  *Test:* same.
- **INV-8** — `clampToFloor` truth table: rec<floor → floor; rec==floor → rec;
  rec>floor → rec (Opus never clamped). With floor=sonnet and current=Haiku, a
  Haiku rec clamps to Sonnet and (since Sonnet != Haiku) acts as an *upgrade to
  floor*; with current already Sonnet it is a no-op via INV-4. *Test:* same —
  full rec×floor×current matrix.
- **INV-9** — security boundary: `tierArg` is derived only from
  `tierName(Tier)` over the fixed three-value enum (`modelrecommender.h:22-24`),
  never from transcript text, so PTY injection cannot be transcript-influenced.
  *Test:* source-grep + a test asserting non-enum input cannot reach `sendToPty`.
- **INV-10** — the ledger file is mode 0600, never exceeds 256 KiB; eviction
  drops whole oldest lines and never a pending-outcome record nor a partial
  line. *Test:* `tests/features/model_switch_ledger/` — write past cap with a
  pending record present; assert size ≤ cap, pending survives, newest intact.
- **INV-11** — `user_override_within_5_turns` is true iff a transcript `/model X`
  appears within 5 assistant turns for which **no** auto ledger record matches by
  `to_tier == X` and `|ts_transcript − ts_ledger| ≤ kAuthorWindowMs` (default
  10 s) — i.e. the controller's own injections (and a second auto-switch in the
  same window) never count as overrides. *Test:* ledger test with auto-then-auto
  (no override) and auto-then-user (override) transcripts.
- **INV-12** — `under_route_signal_within_5_turns` is true iff, within 5 turns
  of a downgrade, the scorer re-recommends a higher tier than the one switched
  to; a downgrade at the last turn of a session (zero following turns) stays
  `pending` and is never counted as not-under-routed. *Test:* ledger test with a
  downgrade-then-Opus-rec transcript and a last-turn-downgrade (pending) case.
- **INV-13** — `model_switch_stats` is read-only (never writes ledger/config),
  returns `{ok:true, switches:0, …}` on an absent ledger, reports the headline
  as an avoided/regret ratio, and counts `pending` records separately from
  outcomes. The envelope also carries the live switcher configuration
  (`auto_model_switch_enabled:bool`, `floor_tier:"haiku"|"sonnet"`,
  `min_dwell_sec:int`) and the `scope:"project"|"global"` echo so a caller
  can distinguish "auto-switch OFF" / "ON but no switches yet" / "ON with
  measured outcomes" — the dormant-vs-quiet ambiguity that ANTS-1889 closes.
  Optional `scope:"global"` arg (default `"project"`) aggregates across all
  ledger entries regardless of project. The headline reads `"auto-switch
  OFF"` when `auto_model_switch_enabled` is false; `"auto-switch ON in this
  project (no switches yet)"` (or `"auto-switch ON globally (…)"`) when
  enabled with zero records in scope; the avoided/regret ratio otherwise.
  The config triple is part of the response body, so the dispatch-layer
  ETag flips automatically on any Settings toggle change. *Test:*
  `tests/features/mcp_model_switch_stats/`.
- **INV-14** — with `auto_model_switch=false` the controller performs no PTY
  injection on any tick **and** the Shape A chip behaves as today; with it true
  the chip is suppressed. *Test:* controller test — disabled → `sendToPty` never
  called; enabled → chip hidden.

## 4. RAM / build cost

- **Per tab:** four scalars total across the existing per-tab structures —
  `ticksTargetStable` (int) + last-switch timestamp (qint64) on the controller,
  `idleSinceMs` (qint64) added to `ClaudeTabTracker::ShellState`, and
  `lastUserKeystrokeMs` (qint64) added to `TerminalWidget`. Single-digit
  bytes/tab; no growth with session length.
- **Ledger:** disk-bounded 256 KiB drop-oldest with pending-record pinning. In
  memory: the controller holds only the most recent pending record awaiting
  fill-in (one struct), plus a transient ledger parse on a `model_switch_stats`
  call, freed on return. No persistent in-memory ledger.
- **Build:** one new pure unit `src/modelautoswitch.{h,cpp}` into
  `ants_core_lib`; `model_switch_stats` registers in the existing MCP dispatch.
  Named new work in existing files: `idleSinceMs` stamped on the Idle transition
  in `ClaudeTabTracker` (`claudetabtracker.cpp` state-write path);
  `lastUserKeystrokeMs` stamped in `TerminalWidget::keyPressEvent`
  (`terminalwidget.cpp:1575`); the ledger append/evict/pin logic. No
  `isFocusedTabSession` change needed (the focused-shell read makes it
  unnecessary). No new external libraries (Qt6 Core/JSON only).

## 5. Out of scope (future, gated on this proving out)

- **Auto thinking-level control** (user-request 2026-05-25): once the ledger
  shows a low regret+under-route rate, extend the controller to also tune the
  *thinking budget* (think / think-hard / ultrathink) for the turn's
  complexity. Caveat: thinking level is a *per-turn* decision, but this
  controller is debounced to *task boundaries* (90 s dwell) — the extension
  needs a separate, finer cadence and its own mechanism+cache research, so
  "extend the same controller" undersells the work. **Tracked by ANTS-1872;
  blocked by this item.**
- **Heuristic breadth** — adding scenarios to `ModelRecommender::score`
  (error/retry rate, debugging loops, large-context reads) is ANTS-1226 scoring
  work, folded there.
- **Dollar accounting** — excluded; the subscription has no per-token bill.
- **Upstream ask: Claude Code "pause-for-switch" handshake.** The cooperative
  session-pause (§ 2.2) is the only mechanism that fully removes OQ-1's race, and
  it does not exist on the interactive CLI today (no hook sets the model; no
  pause/resume; the SDK has `interrupt`+`session.update(model)` but the CLI does
  not surface it). File a feature request to Claude Code for an explicit
  turn-boundary handshake (block → external model change → resume, with defined
  input-queue ordering). **Tracked by ANTS-1871; this spec adopts the handshake
  as the primary mechanism if/when it lands, demoting the idle-window to
  fallback.**

## 8. Preconditions — blocking spikes (resolve before implementation commits)

- **S1 (go/no-go)** — Empirically confirm an injected `/model opus\n` switches
  the model *directly* with no interactive picker/confirmation modal. If it
  raises a modal, autonomous injection is unacceptable (a modal with no one to
  dismiss it); the feature pauses pending a Claude Code surface that switches
  non-interactively (and we file that as an upstream ask). Verify on the user's
  Claude Code version.
- **S2** — Validate the keystroke-timing `composerEmpty` proxy (§ 2.4) on a live
  Claude TUI session: confirm the focused shell's per-tab state reaches `Idle` at
  turn-end (and `idleSinceMs` stamps there); typing into the composer after a
  turn must flip `composerEmpty` false; a fresh post-turn composer must read
  true. If the proxy is unreliable, INV-3 degrades to best-effort and the
  residual race (OQ-1) widens — the spec would then recommend default-off until a
  better signal exists.

The cooperative session-pause was investigated as the way to remove OQ-1
entirely; the research (§ 2.2) found it infeasible on the interactive CLI today,
so it is recorded as the upstream ask (§ 5), not a precondition of this spec.
- **OQ-3 (default-on gate)** — Ship default-OFF in the introducing release with
  a *prominent* toggle (a first-run nudge for the vibe-coder goal). Commit to
  default-on in a later release once the ledger shows **regret_rate +
  under_route_rate < 15% over ≥ 50 switches across ≥ 10 sessions** AND S1
  passed. This makes the chicken-and-egg explicit (the ledger needs opt-in users
  to bootstrap) rather than leaving it open.
