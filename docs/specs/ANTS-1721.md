# ANTS-1721 — `ColdEyesDialog`: native in-app documentation review

**Status:** shipped 2026-05-21 (TDD; `tests/features/cold_eyes_dialog/` INV-1..8 green). Accepted via cold-eyes loop 1 + user sign-off (2026-05-21). Loop log § end.
**Kind:** implement.
**Source:** ROADMAP.md ANTS-1721 (user-request-2026-05-21).
**Blocked by:** ANTS-1727 (review-dialog foundation — `ReviewDialogBase`,
`LlmDispatcher`, `BriefDispatch`).
**Pairs with:** ANTS-1722 (`TestAuditDialog`, the sibling subclass).

## 1. Problem

The cold-eyes MCP engine is fully shipped — `ColdEyesEngine` exposes
`derivePartition`, `assembleBriefManifest`, `crossDocDiffFromReports`,
and `templateColdEyesFoldInBlock` (`src/coldeyesengine.h:128-190`). What
is missing is a way to run a cold-eyes documentation review **inside
Ants, without Claude orchestrating it** — the user's standing goal of
off-loading review work off the token budget (project focus: Ants ×
Claude integration, reduce token usage).

The mechanical halves (partition the doc tree, assemble per-lane briefs,
corroborate reports, fold findings into ROADMAP) are exactly what the
engine already does without an LLM. Only the per-lane *judgment* needs a
model. `ColdEyesDialog` wraps the engine in the `ReviewDialogBase`
scaffold (ANTS-1727) and dispatches each lane's brief to the user's
configured LLM endpoint in parallel.

This also realises the user's requirement that spec / doc cold-eyes
review loops run **until clean**: the review → fix → re-review loop runs
inside the dialog, and each re-review re-dispatches only the lanes that
had findings — cheaper than a full Claude round because Ants assembles
the briefs locally.

## 2. Surface

`ColdEyesDialog : ReviewDialogBase` (`src/coldeyesdialog.{h,cpp}`,
ants_dialogs_lib). It implements the four `ReviewDialogBase` hooks
(§ 2.4 of ANTS-1727) plus a scope selector and the re-review loop.

### 2.1 Partition (`derivePartition`)

Calls `ColdEyesEngine::derivePartition(projectCwd(), scope)` where
`scope` comes from a combo box (Default / DocsOnly / ContractsOnly →
`ColdEyesEngine::Scope`). Each `ColdEyesEngine::Lane` maps to a
`ReviewLane{ id = lane.name, title = lane.name, summary = lane.summary }`.
The partition panel lists the lanes (name + doc-path count); the user
can deselect lanes before dispatch. `PartitionResult.truncated`
(INV-2 spec-lane cap of 12, `src/coldeyesengine.h:61`) and
`overrideWarning` are surfaced as a status line.

### 2.2 Brief composition (`composeBrief`)

For lane *L*:

1. `BriefManifest m = ColdEyesEngine::assembleBriefManifest(projectCwd, L, priorLoopFixes)`
   — paths-only manifest + `crossReferenceDocs` + `citedCodePaths` +
   `staleCitations` (`src/coldeyesengine.h:108-126`).
2. **System prompt** — the cold-eyes reviewer role (consistency,
   accuracy, drift between doc and cited code), pinned, instructing the
   model to emit findings in the standard `- [SEV] file:line — …` shape
   so `crossDocDiffFromReports` can key them.
3. **User prompt** — `m.brief` (the assembled header / instructions) +
   `BriefDispatch::inlineBodies(projectCwd, L.docPaths, 64 KiB)` for the
   lane's own docs (the subject — inlined whole, per-file capped) +
   `BriefDispatch::inlineRelevantSections(projectCwd,
   m.crossReferenceDocs, keywords, 32 KiB)` for the contract anchors —
   only the sections of each contract doc relevant to lane *L*, where
   `keywords` = tokens from `L.name`, the lane's spec ID (for spec
   lanes), and significant words from `m.summary`; so a huge
   `ROADMAP.md` / `CHANGELOG.md` contributes only its relevant slices,
   not a blind 32 KiB head-truncation — + the prior-false-positive block
   `ants::falsepos::formatForBrief(filter(loadEntries(projectCwd),
   "cold-eyes", L.name))` (`src/falseposledger.h`, the prose-grain
   `.ants_review_falsepos.jsonl` ledger) so the model does not re-raise
   previously-rejected findings.
4. `staleCitations` are appended verbatim as a pre-found accuracy
   finding (the engine already resolved them off-disk — no model needed).

Token budget: lane docs are inlined whole (`inlineBodies`, 64 KiB
per-file cap); cross-reference contracts are pre-narrowed to relevant
sections (`inlineRelevantSections`, 32 KiB per-doc cap) so the large-doc
case is bounded *before* the sum gate rather than head-truncated. The
**200 KiB** (≈ 50 K token) cap is the *sum* gate backstop over all
inlined text: if a doc-heavy lane still exceeds it, the sliced
cross-reference bodies are dropped first (lane docs are the subject;
contracts are context), then a `[brief truncated — N docs omitted]`
marker is appended. This is INV-4.

### 2.3 Reports + corroboration (`onAllReportsCollected`)

On `allFinished`, the base hands `reportsById` (lane → verbatim report)
to the subclass. `ColdEyesDialog` calls
`ColdEyesEngine::crossDocDiffFromReports(projectCwd, reports, minLanes = 2)`
→ `QList<CorroboratedFinding>` (`src/coldeyesengine.h:172-175`), rendered
in a results tab: each row is `file:line`, the citing lanes, and the
per-lane context. Single-lane findings (below `minLanes`) are shown in a
secondary "uncorroborated" list so nothing is silently dropped.

### 2.4 Review → fix → re-review loop

A **Re-review** button re-dispatches only the lanes that produced
findings (`ReviewDialogBase::redispatch(laneIds)`). Before re-dispatch,
the user marks which findings were fixed; those become
`ColdEyesEngine::PriorLoopFix` entries (`src/coldeyesengine.h:103-106`)
threaded into `assembleBriefManifest` on the next `composeBrief`, so the
reviewer does not re-raise a closed item. Each loop appends to an
in-dialog **loop log** (loop N: lanes dispatched, findings, fixed). The
loop ends when a re-review returns no corroborated findings (a clean
pass) — matching the "run until clean" requirement.

### 2.5 Fold into ROADMAP (`performFoldIn`)

The `performFoldIn` override (the ANTS-1727 § 2.4 hook) offers two
user-selected modes, both built from the base helpers:

- **Per-finding** — `allocateFoldInIds(N)` for the N corroborated
  actionable findings → `ColdEyesEngine::templateColdEyesFoldInBlock(
  actionable, allocatedIds, dateIso)` (`src/coldeyesengine.h:177-180`)
  → `insertFoldInBlock(activeReleaseHeading(), block)`.
- **Narrative** — a free-text prose block the user writes (grouped
  Closed-inline / Deferred / False-positives), rendered via
  `templateColdEyesFoldInBlockFreeform` (`src/coldeyesengine.h:188-190`)
  and `insertFoldInBlock`'d under `activeReleaseHeading()` with **no**
  ID allocation.

## 3. Invariants

- **INV-1** — `derivePartition` lanes come from
  `ColdEyesEngine::derivePartition` with the selected `Scope`;
  deselected lanes are not dispatched. *Test:* `cold_eyes_dialog` —
  stub a doc tree, assert lane set matches the engine and a deselected
  lane yields no job.
- **INV-2** — `composeBrief` inlines the lane's doc bodies whole via
  `BriefDispatch::inlineBodies` and the cross-reference contracts via
  `BriefDispatch::inlineRelevantSections` with lane-derived keywords
  (both fence-hardened, no raw 4-backtick break-out), and includes the
  `ants::falsepos` prior-FP block when the ledger is non-empty. *Test:*
  compose against a fixture lane + a seeded ledger → lane bodies fenced
  whole, only keyword-matching cross-ref sections present, prior-FP text
  present.
- **INV-3** — `staleCitations` from the manifest are surfaced as
  accuracy findings without a model round-trip. *Test:* fixture doc
  citing a missing `src/x.cpp:10` → finding present even with an empty
  report.
- **INV-4** — cross-reference contracts are narrowed to relevant
  sections before the budget check; the composed user prompt is then
  sum-capped at 200 KiB, dropping sliced cross-reference bodies before
  lane bodies, with a truncation marker. *Test:* oversize fixture →
  prompt ≤ cap, lane bodies retained, only relevant cross-ref sections
  present, marker present.
- **INV-5** — corroboration uses `crossDocDiffFromReports` with
  `minLanes = 2`; uncorroborated findings are shown, not dropped.
  *Test:* two reports citing the same `file:line` → corroborated row;
  a single-lane cite → uncorroborated list.
- **INV-6** — Re-review dispatches only lanes with findings and threads
  fixed items as `PriorLoopFix`. *Test:* `cold_eyes_dialog` — two-lane
  fixture, one with findings → redispatch covers only that lane and the
  next brief carries the prior-fix.
- **INV-7** — narrative fold-in allocates no IDs; per-finding fold-in
  allocates exactly one ID per actionable finding. *Test:* narrative →
  `.roadmap-counter` unchanged; per-finding with N findings → counter
  advances by N.
- **INV-8** — Dispatch is disabled when `ai_endpoint` is unset/invalid
  (inherited `ReviewDialogBase::endpointDispatchable`). *Test:* covered
  by ANTS-1727 INV-12; dialog smoke asserts the disabled state.

## 4. RAM / build cost

- **Prompt budget** — 200 KiB per composed lane prompt (INV-4). With
  the ANTS-1727 default concurrency of 2, peak inlined-body memory is
  ≈ 2 × 200 KiB plus the `LlmClient` stream buffers (bounded by
  ANTS-1727 § 4).
- **Stored reports** — ≤ 17 lanes (`coldeyesengine.h:61` cap) × verbatim
  report (≤ the 10 MiB `LlmClient` cap, realistically KB-scale). Reports
  are cleared on re-partition. Low single-digit MiB typical.
- **Build** — 1 new `.cpp` (`coldeyesdialog`) in `ants_dialogs_lib` + a
  MainWindow menu entry. No new external libraries. ~300–400 LoC + ~120
  test LoC.

## 5. Out of scope

- **Live token streaming** into the per-lane tab — deferred with
  ANTS-1727 § 5; reports render on completion.
- **`.cold-eyes/partition.json` editing UI** — the override file is
  honoured (engine reads it) but not edited in-dialog in v1.
- **Single-doc mode** (`assembleSingleDocBrief`) — a future
  lightweight entry; v1 is the full multi-lane partition.

- **Loop 1 (2026-05-21, independent cold reviewer + author self-review).**

  precise (`loadEntries`/`filter`/`formatForBrief`, `src/falseposledger.h`);

  (c) `performFoldIn` override built from the base helpers
  (`allocateFoldInIds`/`insertFoldInBlock`), aligning with ANTS-1727's
  subclass-owns-fold-in model. Clean pass.
- **Shipped note (2026-05-21).** § 2.2.3 lists `m.brief` as a user-prompt
  component, but `ColdEyesEngine::assembleBriefManifest` already embeds
  the FP block + prior-fix block AND carries "read each doc via your Read
  tool" instructions — both wrong for a raw inlined-bodies endpoint (no
  Read tool; duplicate FP block). The implementation therefore composes
  its own prompt from the manifest's *structured* fields (`summary`,
  `crossReferenceDocs`, `staleCitations`) rather than reusing `m.brief`
  verbatim, calling `formatForBrief` once and rendering prior fixes
  itself. Net effect matches § 2.2's component list with no duplication.
