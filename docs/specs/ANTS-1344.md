# ANTS-1344 — indie_review_corroborate truncation flag

## Problem

`src/indiereviewengine.cpp:444–446` and `:593–604` cap every per-lane
review report at 64 KiB (`kMaxScanBytes`). Subagents that emit
larger reports (200 KiB review summaries are not unusual) lose 70 %
of their citations silently — `extractFileLineCitations` returns
fewer hits than the report actually carried.

The MCP envelope shape currently surfaces no signal that the engine
clipped the input, so the caller cannot decide to fetch the rest /
paginate / re-run with the trimmed-down report.

Source: indie-review-2026-05-14 lane-5 ME-4.

## Fix

Surface truncation in the MCP envelope. The engine's pure-function
signatures stay untouched — detection runs at the `RemoteControl`
layer where the report sizes are visible.

1. **Constant exposure.** `IndieReviewEngine::kMaxScanBytes`
   (= 64 KiB) becomes a public `constexpr` so callers know the
   threshold. The two file-local copies inside the .cpp stay; INV-1
   source-grep guards the pairing.

2. **MCP-layer detection.**
   - Inline `reports` map: for each entry, compare
     `r.size()` (UTF-16 codepoint count — matches `extractFileLine-
     Citations`' truncation) against `kMaxScanBytes`.
   - `reports_dir` path: enumerate top-level `*.md` files in the
     validated directory, compare `QFileInfo::size()` (UTF-8 byte
     count — matches `corroboratedFindingsFromDir`'s `f.read(N)`)
     against `kMaxScanBytes`.

3. **Envelope shape.** Add three fields on truncation:
   - `truncated: true` — headline boolean.
   - `truncated_lanes: ["laneA", "laneB", …]` — sorted-by-discovery
     list of clipped lane names.
   - `truncated_at_bytes: 65536` — echoes the cap so callers can
     decide on a sizing strategy.

   The envelope stays byte-identical to v1 when no truncation
   occurs (no `truncated` key, no `truncated_lanes`,
   no `truncated_at_bytes`).

4. **Parity for `cross_doc_diff`.** The lane-source-agnostic alias
   shares the same engine path; same truncation surface applied.

## Invariants

- **INV-1** `IndieReviewEngine::kMaxScanBytes` is declared as a
  `constexpr int` in `indiereviewengine.h` and equals 64 * 1024.
- **INV-2** Inline-reports path: a `reports` map containing one
  entry whose value has `size()` > `kMaxScanBytes` results in
  envelope `truncated == true` AND
  `truncated_lanes == ["<that_lane_name>"]`.
- **INV-3** Inline-reports path with all entries ≤ `kMaxScanBytes`:
  envelope does NOT carry the `truncated` key (byte-identical v1
  shape).
- **INV-4** Envelope `truncated_at_bytes` echoes `kMaxScanBytes`
  exactly when truncation fires.
- **INV-5** `cross_doc_diff` envelope carries the same three fields
  on the same condition (parity).

## Tests

`tests/features/indie_review_truncation_flag/`:

- INV-1 source-grep against `indiereviewengine.h`.
- INV-2/3/4 driven by `RemoteControl::cmdIndieReviewCorroborate`
  with synthetic large/small reports. Tests run with a `MainWindow`
  via the chrome test bundle — see existing
  `mcp_indie_review_tools` for the pattern.
- INV-5 same shape, `cmdCrossDocDiff` target.

## Out of scope

- No engine-side change to truncation policy. The 64 KiB cap stays
  — only the signal surfaces. A larger cap is a separate scaling
  decision.
- No retry / pagination — the caller decides what to do with the
  signal.
- `extractCitedCodePaths` in `coldeyesengine.cpp` reads via
  `slurpUtf8` without truncation; not affected.
