# ANTS-2161 — Auto-detect non-standard layout + `project_settings` verb

**Status:** accepted (2026-06-24) — cold-eyes loops 1–6 folded, loop 6 zero CRITICAL/HIGH. Flips to `shipped X.Y.Z` at the next release.
**Kind:** feature.
**Source:** user-request-2026-06-24 (follow-on to ANTS-2160), prompted by DOOM `file_count:0` (non-`src` layout) and the cross-session "I keep drifting back to grep" theme.
**Composes with:** ANTS-2160 (ships the `.ants/project.json` *reader* this extends with detection + a write path).

**Layman:** Ants now notices when a project's code isn't where it expects, and offers to write the little settings file for you — and gives Ants a way to create or update that file for you in one step.

## 1. Problem

ANTS-2160 shipped the *reader*: `<root>/.ants/project.json` lets a
project declare where its code / docs / roadmap / changelog / specs
live, and every consumer honours it. But nothing *creates* the file:

1. **Discovery gap.** A session in a non-`src/` project (DOOM keeps 65
   `.c` files under `linuxdoom-1.10/`) still gets `file_count:0` from
   `session_orient` / `codebase_index` and has no signal that a settings
   file would fix it. The fix exists but is invisible.
2. **No write path.** Authoring the JSON by hand is the only way to
   create or change the file — a session has no one-call verb to do it,
   and hand-writing risks a malformed file or the wrong permissions.

This spec adds three pieces, all opt-in and all additive over ANTS-2160:

- a **detector** that flags when the default `src/`+`tests/` walk would
  miss most of a project's source and proposes `source_roots`;
- a **`session_orient` nudge** that surfaces that proposal — but only
  for a project that needs it (no nag for standard or already-configured
  projects);
- a **`project_settings` MCP verb** (`detect` / `init` / `set`) that
  creates and updates the file in one call.

**Decided scope (user, 2026-06-24):** persistence is *explicit only* —
query verbs (`codebase_index`, …) gain no auto-persist side-effect. A
path passed to a query verb would be ambiguous (one-off vs. permanent)
and silently writing a committable file is a footgun; declaring a path
is always a deliberate `project_settings op:"set"` call (§ 6).

## 2. Surface

### 2.1 The detector — `ProjectSettings::detect`

Added to the existing pure helper `src/projectsettings.{h,cpp}`
(Qt6::Core-only; ANTS-2160):

```cpp
namespace ProjectSettings {
    struct Suggestion {
        bool                       present = false;  // .ants/project.json already on disk
        std::optional<QStringList> sourceRoots;      // suggested dirs, when layout looks misplaced
        QString                    reason;           // human string incl. counts; empty ⟺ no suggestion
        int                        defaultSourceCount = 0;  // admitted files under the literal src/+tests/
        int                        totalSourceCount   = 0;  // admitted files repo-wide (bounded)
    };

    // Bounded shallow analysis of <rootCanonical>. If .ants/project.json
    // already exists, returns {present:true} immediately — NO walk, NO
    // suggestion (an already-configured project is never second-guessed).
    // Otherwise counts source files (CodebaseIndex::isIndexableSuffix — the
    // same suffix predicate codebase_index admits by, so per-file admission
    // cannot diverge; note detect walks repo-wide top-level dirs whereas
    // codebase_index's walk descends only src/+tests/, so the COUNTS are
    // not interchangeable — they share the admit rule, not the traversal)
    // per top-level directory, skipping noise dirs (any dot-dir, plus
    // build*/ node_modules/ dist/ target/ vendor/ out/), capped at
    // kDetectFileCeiling files total. Suggests sourceRoots = the
    // top-level dirs (excluding the tests default + noise) that together
    // hold >= kDominanceRatio of total source, sorted by count desc,
    // ONLY when the default src/+tests/ walk would index fewer than
    // kMissRatio of the repo's source AND at least one qualifying subdir
    // exists. Suggests subdirectories only — never "." / the repo root
    // (INV-12). Empty `reason` + nullopt sourceRoots ⟺ no suggestion.
    Suggestion detect(const QString &rootCanonical);
}
```

Tuning constants (file-local in `projectsettings.cpp`, named not magic):
`kDetectFileCeiling = 20000` (walk cap), `kMissRatio = 0.5` (default walk
must miss more than half before we suggest), `kDominanceRatio = 0.9`
(suggested dirs must cover ≥90 % of source). The detector reads only
under `rootCanonical` and retains nothing.

`CodebaseIndex::isIndexableSuffix(const QString &suffixLower)` *will be*
exported from `codebaseindex.h` by moving the **anonymous-namespace**
file-static `admittedSuffix` (`src/codebaseindex.cpp:28`, not exported
today) out into the `CodebaseIndex` namespace proper, renaming it
`isIndexableSuffix`, and declaring it in `codebaseindex.h`. Its in-file caller — the `walkSubtree` suffix
gate at `src/codebaseindex.cpp:113` — calls the renamed function; the two
comment references that also name the old symbol
(`src/fileoutline.cpp:165` and `src/symbolquery.cpp:54`) are updated in
the same rename. Result: one definition, callers `walkSubtree` + `detect`.

### 2.2 The `session_orient` nudge

`cmdSessionOrient` (`src/remotecontrol.cpp:11566`; the embedded
`codebase_index` summary block is at `:11668`) already embeds a trimmed
`codebase_index` summary carrying `file_count`. After that block, add a
conditional `project_settings_suggestion` block, gated so a healthy or
configured project pays nothing:

- **Gate:** emit the block only when `<root>/.ants/project.json` is
  ABSENT **and** the embedded `codebase_index.file_count` is below
  `kSuggestLowWaterMark` (= 5). The cheap existence + integer test runs
  every call; the `detect()` walk runs ONLY when both gates pass — so a
  standard project (healthy `file_count`) never triggers the walk.
- **Content** (when `detect()` returns a suggestion):
  ```json
  "project_settings_suggestion": {
    "reason": "default src/+tests/ walk indexed 0 of 47 source files; 'linuxdoom-1.10' holds 41",
    "suggested": { "source_roots": ["linuxdoom-1.10"] },
    "write_via": "project_settings op:\"init\"",
    "default_source_count": 0,
    "total_source_count": 47
  }
  ```
  (Wire keys are `snake_case` per MCP convention, mapped 1:1 from the
  `camelCase` `Suggestion` struct fields in § 2.1 — `source_roots` ⟷
  `sourceRoots`, `default_source_count` ⟷ `defaultSourceCount`, etc. —
  the same mechanical mapping ANTS-2160 uses for its file keys.)
- Mirrors the `feedback_pending` precedent (`:11690`): deterministic for
  a given tree (same ETag while the tree is unchanged — the embedded
  counts move with the source set, exactly as `file_count` itself does),
  omitted entirely when not applicable (so the response — and its ETag —
  is unchanged for standard projects), and does NOT contribute to `allOk`
  (an absent/odd layout must never fail orient).

### 2.3 The `project_settings` verb

A new MCP verb in `remotecontrol.cpp` (thin glue over the pure helpers),
`caller_cwd`-required, root-validated. Three ops:

| op | reads | writes | refusals |
|---|---|---|---|
| `detect` | yes | no | — |
| `init` | yes (detect) | creates only (or `written:false` no-op, INV-6) | `settings_exists`, `bad_args`, `bad_path` |
| `set` | yes (existing file) | creates or updates | `bad_args`, `bad_path`, `unrecognised_format` |

*(Table note — applies to every row above: each op also emits
`caller_cwd_required` when `caller_cwd` is absent, INV-13; the per-op
column lists only the op-specific refusals.)* Refusal codes are drawn
from
`docs/standards/mcp-error-codes.md`: `settings_exists` is a NEW code
(Category 2 — resource state, sibling of `plan_exists`; its envelope
carries `path`), registered in that taxonomy in the implementing commit;
`unrecognised_format` (Cat. 2) and `bad_args` (Cat. 1) are REUSED, not
new. The "no recognised key supplied" guard on `set` uses `bad_args`
(not `missing_field`) per the taxonomy's combination-guard rule — no
single field is required; the guard is "at least one of N optional keys
must be present," which is the `bad_args` "one guard covers
absent-and-malformed" case, not a single wholly-absent required field.

- **`op:"detect"`** — runs `ProjectSettings::detect(root)`; returns
  `{ok:true, present, suggestion:{source_roots?, reason,
  default_source_count, total_source_count}}`. Read-only preview; the
  same data the nudge carries, on demand.
- **`op:"init"`** — accept the detector's proposal (the nudge's
  "one call to lock it in"). If `<root>/.ants/project.json` exists →
  `{ok:false, code:"settings_exists", path}` (no clobber). Else the keys
  to write are the explicit declared keys if any are supplied (the same
  flat keys as `set`, below) — explicit keys SUPPRESS the detector
  entirely (they are not merged with the suggestion) — otherwise
  `detect().sourceRoots` (in the explicit-keys path the detector is NOT
  run). If neither yields a key → `{ok:true, written:false, reason}`
  (nothing to do is not an error; `reason` is the detector's — empty when
  explicit keys were the only input). Whichever set of keys is chosen
  (explicit OR detector-derived) is then run through `applyWrite`
  validation (§ 2.4 — an invalid path → `bad_path`; a malformed explicit
  key, e.g. a non-array `source_roots`, → `bad_args`) before writing →
  `{ok:true, written:true, path, settings}`.
- **`op:"set"`** — create-or-update explicitly. Load the existing file
  (if present); if present but not parseable as a JSON object →
  `{ok:false, code:"unrecognised_format", expected_format:["json-object"],
  hint}` (the `expected_format[]` + `hint` envelope the ANTS-1463 contract
  mandates for that code — no fields added beyond it; never clobber a
  hand-edited file). Validate (§ 2.4 — an invalid declared path
  → `bad_path`), merge the provided recognised keys (raw-JSON merge,
  § 2.4) and write → `{ok:true, written:true, path, settings}`. A call
  providing no recognised key at all → `{ok:false, code:"bad_args"}`. A
  recognised key with an explicit `null` value COUNTS as provided (it
  removes the key, INV-8; idempotent if the key was already absent →
  `written:true`), so a `null`-only call is a valid no-op write, not
  `bad_args`.

Input args: `op` (required), and for `init`/`set` the optional declared
keys as FLAT top-level args — `source_roots` / `test_roots` (string
arrays), `docs_dir` / `specs_dir` / `roadmap` / `changelog` (strings)
(there is no nested `settings:{}` wrapper); for `set`, an explicit JSON
`null` on a key removes it from the file (clear semantics, INV-8). An
absent or unrecognised `op` value → `bad_args` (the op-enum guard, common
to all three).

### 2.4 The writer + write-time validation

A pure helper does the merge + validation so it is unit-testable without
`RemoteControl`:

```cpp
// Returns the merged object to write, or nullopt + *errKey/*errVal set
// when a declared path fails write-time validation. `changes` carries
// only the keys the caller supplied (a JSON-null value means "remove").
std::optional<QJsonObject> applyWrite(const QJsonObject &existing,
                                      const QJsonObject &changes,
                                      const QString &rootCanonical,
                                      QString *errKey, QString *errVal);
```

- **Write-time validation is STRICT** (deliberately unlike `load()`'s
  lenient read-time drop, ANTS-2160): each declared path must resolve
  under the canonical root via `PathValidation::isInsideProject` AND have
  the right type — `source_roots`/`test_roots`/`docs_dir`/`specs_dir`
  entries must be existing **directories**, `roadmap`/`changelog` must be
  existing **files**. Any failure → `bad_path` (carrying the offending
  key + value); the file is NOT modified. (Rationale: a deliberate
  declaration deserves immediate feedback, vs. a silent later no-op.)
  This write-time check **complements, not replaces** ANTS-2160's
  consumer-side read-time check (`candidates()`'s `QDir(...).exists()`
  dir-gate, which already drops a file-typed `source_root`; the
  doc-finders' file check). Note `bad_path` here keys on
  `isInsideProject` (the disk-derived anchor), not the `validatePath`
  MCP-arg validator the taxonomy's `bad_path` row names — the code is
  shared, the entry point differs.
  For the *type-mismatch* case it is primarily a UX upgrade (immediate
  feedback vs. ANTS-2160's silent read-time drop — the reader would catch
  a wrong-typed path at consume-time anyway, and a path's type can change
  after the write, so the reader's check still stands). The escape /
  non-existence bound is meaningful at write-time too (it stops a bad
  declaration landing in the committed file in the first place).
- **Merge preserves unrecognised keys.** Operating on the raw
  `QJsonObject` (not round-tripping through `Settings`) keeps any key the
  current schema doesn't know — forward-compatible (INV-7).
- **The on-disk write** (in the verb, reusing the project's atomic-write
  idiom — `QSaveFile` + parent-dir fsync via `secureio.h`'s
  `fsyncParentDir`, as `cmdApplyEdits`'s write does, `remotecontrol.cpp`
  ~`:8900`):
  `mkpath <root>/.ants/`, write pretty JSON (`QJsonDocument::Indented`)
  + trailing newline, then set permissions to **0644 — world-readable by
  design** (NOT `setOwnerOnlyPerms()`; the file holds only non-secret
  path declarations and is committed to the repo, contrast the 0600
  global config — ANTS-2160 § 7).

## 3. Invariants

- **INV-1** — A standard project (populated `src/`, no settings file)
  emits NO `project_settings_suggestion` from `session_orient`, and
  `detect()` returns `present:false` with no suggestion (the default
  walk covers ≥ `kMissRatio` of source). Zero nag, ETag unchanged vs.
  pre-ANTS-2161. *Test:* `src/`-populated `QTemporaryDir` → `detect()`
  `sourceRoots == nullopt`, `reason` empty.
- **INV-2** — A project with `.ants/project.json` present makes
  `detect()` return `present:true` with no suggestion and **no directory
  walk** (early return); `session_orient` emits no block. *Test:* fixture
  with an existing settings file + a misplaced layout → `detect()`
  `present:true`, `sourceRoots == nullopt`.
- **INV-3** — A misplaced layout (source under `engine/`, no `src/`, no
  settings file) makes `detect()` suggest `source_roots:["engine"]`, with
  `reason` carrying the counts (`defaultSourceCount` 0,
  `totalSourceCount` = the repo-wide admitted count). *Test:* fixture
  with `engine/a.c`, `engine/b.c` and **no other source files** (so the
  repo-wide `totalSourceCount` == 2 == the `engine/` count) →
  `sourceRoots == ["engine"]`, `defaultSourceCount == 0`,
  `totalSourceCount == 2`.
- **INV-4** — `op:"init"` on a project with no settings file and a
  detected suggestion writes `<root>/.ants/project.json` that is valid
  JSON, **0644** (world-readable), and whose `source_roots` a subsequent
  `ProjectSettings::load` returns. *Test:* drive `applyWrite` + a write
  into a `QTemporaryDir`, then `load()` returns the written roots; assert
  the file mode is 0644.
- **INV-5** — `op:"init"` refuses `settings_exists` when the file is
  present; the existing file is byte-identical afterwards (no clobber).
  *Test:* pre-write a settings file, call the init path → refusal, file
  bytes unchanged.
- **INV-6** — `op:"init"` with neither a detected suggestion nor any
  explicit declared key writes nothing and returns `written:false`
  (success, not an error). *Test:* standard-`src/` fixture (no
  suggestion), no explicit keys → `written == false`, no file created.
- **INV-7** — `op:"set"` creates the file when absent and merges into it
  when present, preserving every key it did not touch — **including keys
  the current schema does not recognise** (forward-compat). *Test:*
  pre-existing `{ "docs_dir":"docs", "future_key":1 }`, set
  `source_roots:["a"]` → resulting object has `source_roots`, `docs_dir`,
  AND `future_key`.
- **INV-8** — `op:"set"` with an explicit JSON `null` for a key removes
  that key from the file; a `null`-only call (even for an already-absent
  key) is a valid no-op write (`written:true`), never `bad_args` (the
  key was provided — `bad_args` fires only when NO recognised key
  appears). *Test:* (a) pre-existing `{ "docs_dir":"docs" }`, set
  `docs_dir:null` → resulting object lacks `docs_dir`; (b) empty file (no
  `docs_dir`), set `docs_dir:null` → `written:true`, NOT `bad_args`.
- **INV-9** — `op:"set"` / `op:"init"`(explicit) validate each declared
  path at write-time under the canonical root: a path that escapes root,
  does not exist, or has the wrong type (a file where a dir is expected,
  or vice-versa) → `bad_path` refusal AND the on-disk file is NOT
  modified. *Test:* the escape/absent bound — `applyWrite` with
  `source_roots:["nope"]` (absent) → nullopt + `errKey=="source_roots"`;
  the type-mismatch (UX-tier) check — `roadmap:"src"` (a dir, not a file,
  against a fixture that populates `src/`) → nullopt. The no-clobber
  guarantee follows by construction (the verb skips the write whenever
  `applyWrite` returns nullopt — `applyWrite` itself never writes); a verb-
  layer assertion that the pre-existing file is byte-untouched on refusal
  is the belt-and-braces check.
- **INV-10** — `op:"set"` on a present-but-malformed
  `.ants/project.json` refuses `unrecognised_format` rather than
  overwriting a hand-edited file. The malformed-file detection is in the
  verb's *load/parse* step (it runs before `applyWrite`, which receives an
  already-parsed `QJsonObject` — § 2.4 — and so never sees raw bytes).
  *Test:* drive the verb's parse-then-refuse step (or the shared parse
  helper) against a pre-written `{` (truncated) → `unrecognised_format`,
  bytes unchanged; NOT driven through `applyWrite`, which cannot observe
  a truncated file.
- **INV-11** — `detect()`'s walk is bounded and root-confined: it skips
  noise dirs (any dot-dir + `build*`/`node_modules`/`dist`/`target`/
  `vendor`/`out`), caps at `kDetectFileCeiling`, and never reads outside
  `rootCanonical`. *Test:* a fixture with a populated `node_modules/`
  (more files than `engine/`) → `node_modules` is NOT suggested and does
  NOT inflate `totalSourceCount`.
- **INV-12** — `detect()` suggests subdirectories only, never `"."` /
  the repo root: a project whose source sits directly at the repo root
  (no subdir) yields NO suggestion (documented limitation — the user can
  `op:"set"` manually). *Test:* fixture with `a.c`, `b.c` at root, no
  subdir → `sourceRoots == nullopt`.
- **INV-13** — All three ops require `caller_cwd` (else
  `caller_cwd_required`) and write only to `<root>/.ants/project.json`
  under the canonical root. *Test:* a source-grep that `project_settings`
  is registered `CallerCwdContract::Required` in
  `src/claudeintegration.cpp`'s `callerCwdContractFor()` table (the
  `if (toolName == …) return C::Required;` chain at `:9232`+, where
  `codebase_index`/`apply_edits`/`spec_log` already sit — the handler glue
  is in `remotecontrol.cpp`, but the contract table is here), and that the
  verb's write target is the literal join `"/.ants/project.json"` (the
  same source-grep shape the ANTS-2160 feature suite used for its wiring
  check).
- **INV-14** — The dominance gate is honoured: `detect()` suggests a
  subdir set only when one exists that covers ≥ `kDominanceRatio` of total
  source; a miss (default walk < `kMissRatio`) where no subdir set reaches
  that bar — because a large share of source sits directly at the repo
  root (not a suggestable subdir, INV-12) — yields NO suggestion rather
  than a partial one. *Test:* fixture with `a.c` at the repo root and
  `engine/b.c` (each ≈ 50 % of source); `defaultSourceCount == 0` (a
  miss) but `engine/` alone is 50 % < `kDominanceRatio` and the root files
  are not suggestable → `sourceRoots == nullopt`. (Contrast INV-3, where
  `engine/` holds 100 % ≥ `kDominanceRatio` → suggested.)

## 5. RAM / build cost

**Memory:** none retained. `detect()` builds a short-lived per-top-level
count map (a handful of `int`s keyed by dir name) and a `Suggestion`
(< 1 KiB) the caller consumes and discards. The walk is bounded by
`kDetectFileCeiling` (= 20000) — a safety cap, not a typical cost: the
`session_orient` gate (`file_count < kSuggestLowWaterMark`) means the
walk fires only on a project whose default `src/`+`tests/` index already
came back near-empty, so a healthy repo never pays for it. `applyWrite`
operates on one small `QJsonObject`. No cache, no growth, no eviction
policy.

**Build:** no new TU — `detect`/`applyWrite` extend the existing
`projectsettings.cpp`; the verb glue is localised in `remotecontrol.cpp`;
one new exported one-liner in `codebaseindex.h`. No new third-party
dependency. The `session_orient` change is one gated block.

## 6. Out of scope

- **Auto-persist on query verbs** — explicitly rejected (§ 1): a path
  given to `codebase_index` (or any query verb) stays a one-off and never
  writes `.ants/project.json`. Persisting is always a deliberate
  `project_settings op:"set"`.
- **One-off path override on query verbs** — deferred. `op:"set"` + the
  file cover the real need; a transient different-scope index would fight
  the `codebase_index` cache for a rare benefit.
- **Auto-detection of `docs_dir` / `roadmap` / `changelog` / `specs_dir`**
  — `detect()` suggests only `source_roots` in v1 (the one place the
  heuristic is genuinely brittle — every other consumer already probes
  candidate locations and finds the file without a settings file). A
  session can still declare those keys explicitly via `op:"set"`.
- **Repo-root (`"."`) source layout** — `detect()` suggests subdirs only
  (INV-12); a flat repo-root layout is declared manually.
- **A `force` clobber on `init`** — not in v1; `op:"set"` is the
  update path.
- **Auto-nudge above the low-water mark** — the `session_orient` nudge
  fires only when `codebase_index.file_count < kSuggestLowWaterMark`
  (= 5), a deliberate cheap gate that keeps healthy projects from paying
  for the walk. A non-standard layout that still leaves ≥ 5 files under
  the default `src/`+`tests/` walk (e.g. a stray `src/version.h`) will
  not auto-suggest; the session can always run `op:"detect"` explicitly
  to get the analysis on demand.

## 8. Security boundaries

The work crosses the **filesystem** trust boundary in two directions:

- **Read (detector):** `detect()` walks only under `rootCanonical`,
  skips noise dirs, and is capped at `kDetectFileCeiling`; it surfaces
  only directory names + counts, no file contents. It cannot read or
  report anything outside the project root.
- **Write (verb):** the only write target is `<root>/.ants/project.json`;
  the parent `.ants/` is created under root. Every declared path is
  validated under the canonical root via `PathValidation::isInsideProject`
  before any write (INV-9), so a `set`/`init` can never point a consumer
  at a path outside the project (the same bound ANTS-2160's reader
  enforces, applied at write-time). The file is written 0644 by design
  (non-secret path declarations); no secret ever flows into it.
