# ANTS-1644 — cold_eyes_fold_in + indie_review_fold_in narrative_mode

**Status:** in flight 2026-05-19 (pull 30)
**Kind:** enhancement
**Source:** ANTS-1635 fold-in note — "sibling-tool gap, port the
narrative_mode pattern to cold_eyes_fold_in and indie_review_fold_in".
**Composes with:** [[ANTS-1635]] (test_audit_fold_in narrative_mode —
shipped 2026-05-19, the template this spec ports), [[ANTS-1615]]
(empty `**.**` bullets — sibling structured-shape mismatch),
[[ANTS-1581]] (skill wiring — downstream consumer of the
narrative-vs-structured choice across all four review verbs).

## 1. Problem

`cold_eyes_fold_in` and `indie_review_fold_in` carry the same
structured-shape mismatch ANTS-1635 closed for `test_audit_fold_in`.

The contract for both verbs requires `actionable[]` of structured
findings (`{file, line, citing_lanes[]}`). The handler renders one
`- 📋 [ANTS-NNNN] **<headline>.**` bullet per entry under the
verb-specific section heading (`### 📝 Cold-eyes <DATE>` /
`### 🔍 Indie-review fold-in (<DATE>)`) and allocates one new roadmap
ID per actionable item.

This shape is right for machine-driven per-finding fold-ins. It's
wrong for the workflow that surfaced ANTS-1635 in the first place:

> *"I ran /cold-eyes (or /indie-review), triaged the findings myself,
> and now I want to fold in one narrative subsection grouped by
> **Closed inline (X) / Deferred (Y) / False-positives (Z)** with
> paragraph prose. Coercing N records through `actionable[]` produces
> N bullets the reviewer doesn't want, allocates N IDs that get
> immediately wasted, and loses the per-group framing."*

Same friction class, two sibling tools. ANTS-1635 wrote the template;
this spec just applies it.

## 2. Fix

### 2.1 Schema (claudeintegration.cpp)

Two new optional fields on **each** descriptor (`cold_eyes_fold_in`
and `indie_review_fold_in`):

```jsonc
"narrative_mode": { "type": "boolean" },
"narrative_md":   { "type": "string"  }
```

`actionable` is dropped from each schema's `required` array — the
handler still refuses with `bad_args` when both
`narrative_mode==false` AND `actionable[]` is empty, so the
backward-compat contract is preserved at the handler. Only
`caller_cwd` remains in `required`.

Descriptor description text gains a one-line callout for the new
narrative escape hatch so callers discover the path from `tools/list`
alone.

### 2.2 Handler path (remotecontrol.cpp)

Both `RemoteControl::cmdColdEyesFoldIn` and
`RemoteControl::cmdIndieReviewFoldIn` short-circuit when
`narrative_mode==true`, **after** the `RcGate` caller-cwd gate
(security must not be bypassed) and **before** the `actionable[]`
validation (the escape-hatch branch).

Sequence:

1. Refuse with `narrative_md_required` if `narrative_md.trimmed()` is
   empty (loud + dedicated code so orchestrators distinguish "forgot
   the body" from "forgot the actionable list"). Error message names
   the `narrative_mode` knob.
2. Emit the same verb-specific section heading as structured mode:
   - cold_eyes: `### 📝 Cold-eyes <DATE>`
   - indie_review: `### 🔍 Indie-review fold-in (<DATE>)`
3. Omit the structured-mode preamble (none exists for these two
   verbs today — they go straight to bullets — so this step is a
   no-op compared to test_audit_fold_in).
4. Insert `narrative_md` verbatim under the heading.
5. Call `RoadmapFoldIn::insertBlock(root, heading, block)` via the
   existing path. Atomic-write semantics inherited unchanged.
6. **Skip ID allocation entirely** — no `.roadmap-counter` touch,
   `allocated_ids` echoed as the empty array `[]`.
7. Return envelope:
   ```json
   {ok:true, block:"<heading + narrative>",
    allocated_ids:[], written:<bool>,
    release_block_heading:"<heading from disk>"}
   ```

The `actionable[]` refusal message also names the narrative escape
hatch so callers discover it without re-reading the descriptor:

> `"cold_eyes_fold_in: actionable[] required (or pass
> narrative_mode=true + narrative_md=\"…\" — ANTS-1644)"`
>
> `"indie_review_fold_in: actionable[] required (or pass
> narrative_mode=true + narrative_md=\"…\" — ANTS-1644)"`

### 2.3 No engine plumbing

Unlike test_audit_fold_in which has a `TestAuditEngine::foldIn` entry
point gating the actual write, both cold-eyes and indie-review
fold-ins assemble the block in `RemoteControl::cmd*` directly (the
engines only expose pure template-builder functions). The
narrative-mode short-circuit therefore lives entirely in
`remotecontrol.cpp`; no engine API churn.

This is a smaller surface than ANTS-1635 (which threaded the new
fields through `FoldInRequest`/`foldIn()`). The template-builder
functions in `coldeyesengine.cpp` and `indiereviewengine.cpp` are
not touched.

## 3. Invariants

- **INV-1** (verbatim insert, cold-eyes). With `narrative_mode=true` +
  non-empty `narrative_md`, `cmdColdEyesFoldIn` emits
  `### 📝 Cold-eyes <DATE>` followed by the caller's markdown
  verbatim. No per-finding bullet shape; `allocated_ids:[]`.
- **INV-2** (verbatim insert, indie-review). Same as INV-1 with
  `### 🔍 Indie-review fold-in (<DATE>)` heading via
  `cmdIndieReviewFoldIn`.
- **INV-3** (empty body refuses, both verbs). `narrative_mode=true`
  with empty or whitespace-only `narrative_md` returns
  `{ok:false, code:"narrative_md_required"}`. Symmetric to ANTS-1635
  INV-2.
- **INV-4** (back-compat, both verbs). `narrative_mode=false`
  (or absent) with empty `actionable[]` still returns
  `{ok:false, code:"bad_args"}`. The error string names
  `narrative_mode` so callers discover the escape hatch from the
  refusal alone.
- **INV-5** (gate intact). The `RcGate::checkCallerCwd` cross-project
  write gate runs unchanged before the narrative-mode branch — a
  hostile `caller_cwd` is still refused with `cwd_mismatch` /
  `bad_caller_cwd` before any disk activity.
- **INV-6** (counter untouched). Narrative mode does not call
  `RoadmapFoldIn::allocateIds` for either verb. `.roadmap-counter`
  byte content is identical before / after.
- **INV-7** (insert site, both verbs). Narrative mode writes through
  the same `RoadmapFoldIn::insertBlock` path as structured mode —
  same release-heading resolution, same atomic-write guarantees.
- **INV-8** (schema, cold-eyes). The cold_eyes_fold_in descriptor
  declares `narrative_mode` and `narrative_md` schema properties.
  `actionable` is NOT in the `required` array; `caller_cwd` is.
- **INV-9** (schema, indie-review). Same as INV-8 for the
  indie_review_fold_in descriptor.

`cold_eyes_fold_in_freeform` test pattern — no engine link needed,

`SRC_CLAUDE_INTEGRATION_CPP_PATH` + `SRC_REMOTECONTROL_CPP_PATH`):

    `cmdColdEyesFoldIn` body contains the narrative-mode branch
    after the gate and before `actionable.isEmpty()`; the branch
    reads `narrative_mode`, reads `narrative_md`, calls
    `RoadmapFoldIn::insertBlock`, and does NOT call
    `RoadmapFoldIn::allocateIds`.

  - `HandlerNamesEscapeHatchOnActionableMissing` (INV-4) —

- `indie_review_fold_in_narrative/test_indie_review_fold_in_narrative.cpp`
  - Same four tests against `cmdIndieReviewFoldIn` and the

    `### 🔍 Indie-review fold-in (`.

Total: 8 new tests. Full suite remains green.

## 5. Out of scope

- **Mode-conflict refusal.** Passing BOTH `narrative_mode=true` AND a
  non-empty `actionable[]` silently ignores `actionable[]` (narrative
  wins, matching ANTS-1635 behaviour). Deferred until reports
  surface the confusion.
- **Caller-supplied section heading.** The heading remains fixed at
  `### 📝 Cold-eyes <DATE>` / `### 🔍 Indie-review fold-in (<DATE>)`.
  Custom headings break the existing release-block heuristics. Out
  of scope; defer.
- **`debt_sweep_apply_fix` narrative mode.** Same shape class but
  the verb writes a different artefact (per-file diff queue, not a
  ROADMAP block). Tracked separately if reports surface the need.

## 6. RAM / build budget

- Schema: 4 extra `QJsonObject` declarations (2 per descriptor).
- Handler: ~30 LOC per verb (one short-circuit branch each,
  totalling ~60 LOC across the two `RemoteControl::cmd*` methods).
  No new state, no new helpers.
- Engine: zero — the template-builder functions are not touched.
- Tests: ~150 LOC across two new GUI-bundled fixtures (no new build
  targets; both added to the existing `test_claude` bundle).
