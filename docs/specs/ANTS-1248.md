# ANTS-1248 — `workspace_search` MCP tool (ripgrep wrapper)

**Status:** spec, ship-ready after cold-eyes pass.
**Source:** user-2026-05-12 (token-reduction priority).
**Sibling specs:** ANTS-1247 (status filter), 1249 (file_outline),
1250 (git-state tools), 1251 (subsystem_map), 1252 (hook pack).

## 1. Problem

Today's Claude sessions hit `Bash grep -rn 'foo' src/`,
`grep -nE 'pattern' --include='*.cpp' -r .`, `find . -name '*.h' |
xargs grep`, etc. dozens of times per session. Two costs:

- **Output size.** A typical project-wide grep returns 50-500 matched
  lines (~5-50 KiB; ~1.2-12 K tokens). Most are noise the assistant
  filters out client-side.
- **Round-trips.** Without a structured ranking, the assistant
  repeats the search with different flags 2-3× before it finds the
  right slice.

Measured against this repo (`rg --no-heading -nF 'parseBullets' src/`
→ 11 matches, 1 218 bytes ≈ 305 tokens; an unbounded `grep -rn` over
`src/` for the same term returns the same 11 matches but Bash output
adds ~80 bytes of wrapper formatting per session).

## 2. Surface

| Field | Type | Default | Notes |
|-------|------|---------|-------|
| `pattern`     | string  | (required) | Literal or regex; mode picked by `regex`. |
| `regex`       | bool    | `false`    | When `true`, pattern is treated as Rust regex (ripgrep default). |
| `lane`        | string  | `""`       | Subdir under repo root (e.g. `"src"`, `"docs"`, `"tests/features"`). Empty = whole repo. **Path-escape guard**: resolved via `QFileInfo::canonicalFilePath()` (resolves symlinks, unlike lexical `cleanPath`); rejected if the canonical result doesn't startsWith the project root. NFC-normalised before compare; bytes < 0x20 rejected; `\` reserved (Linux-only, no Windows-style path semantics). |
| `glob`        | string  | `""`       | Passed as ripgrep `--glob`. Capped at 256 bytes; rejected if it contains `..` segments. |
| `max_results` | int     | `50`       | Cap (server clamps to ≤ 500). |
| `context`     | int     | `0`        | Lines of context above+below each hit (ripgrep `-C`). |
| `case`        | string  | `"smart"`  | `"smart"` / `"sensitive"` / `"insensitive"`. |

Response:

```jsonc
{
  "ok": true,
  "pattern": "parseBullets",
  "matches": [
    {"file":"src/roadmapdialog.cpp", "line":528, "text":"RoadmapDialog::parseBullets(...) {"},
    ...
  ],
  "truncated": false,   // true if max_results capped the response
  "elapsed_ms": 12
}
```

Error shape (mirrors existing IPC verbs):

```jsonc
{ "ok": false, "error": "<message>", "code": "<bad_pattern|bad_lane|rg_failed|...>" }
```

## 3. Implementation

- Shell to `rg --json --no-heading --line-number --max-columns 500
  --threads <kWorkspaceSearchThreads>` via `QProcess`. **Shell-less argv list**
  (`QProcess::start("rg", args)`) — no shell interpolation, no command
  injection. INV asserts argv form, not the `command` overload.
- Parse `rg`'s NDJSON output incrementally via
  `QProcess::readyReadStandardOutput` — buffer a line, parse with
  `QJsonDocument::fromJson()`, append to results, repeat. Stop at
  `max_results` matches and `terminate()` the child.
- **Two-tier kill timer**: `QTimer::singleShot(2000, …)` per call;
  on fire send `terminate()` (SIGTERM); after a further 200 ms grace
  send `kill()` (SIGKILL). The 2 s hard wall is independent of
  `max_results` — guards against catastrophic regex / no-match-ever
  paths the result cap can't reach.
- **Stderr capture capped at 4 KiB**, returned only in the error
  branch — never echoed on `ok:true`. Mirrors ANTS-1250 INV-7.
  Closes the path-enumeration info-leak vector.
- Cite location: new `cmdWorkspaceSearch(const QJsonObject &req)` in
  `remotecontrol.cpp`; public-promoted (same pattern as ANTS-1244)
  so the MCP server in `claudeintegration.cpp` can delegate.
- Provider lambda: same shape as the ANTS-1247 widened provider
  (passes the full request `QJsonObject` through).
- **Shared helper**: the canonical-path-startswith check
  (`pathInRepoRoot(userPath) → std::optional<QString>`) lives near
  `cmdGetText` in `remotecontrol.cpp` and is reused by ANTS-1249 and
  ANTS-1250's `path` arg. This spec introduces the helper.

## 4. Invariants

- **INV-1.** Empty `pattern` → `{ok:false, code:"bad_pattern"}`. No
  rg fork happens.
- **INV-2.** `lane` is resolved with `QFileInfo::canonicalFilePath()`
  (resolves symlinks) then checked with `startsWith(projectRootCanonical)`.
  Pre-resolve: NFC-normalise; reject any byte < 0x20 or `\` with
  `code:"bad_lane"`. Note acceptable residual TOCTOU window between
  resolve and fork (documented in §8); ripgrep is invoked without
  `-L` so post-fork symlink follow is bounded.
- **INV-3.** `rg` is invoked with shell-less argv
  (`QProcess::start("rg", QStringList args)`, not the single-string
  overload). The test asserts this by source-grep — no `bash -c`,
  no `system(`, no `/bin/sh` surface.
- **INV-4.** `max_results` is clamped server-side: requested 1000 →
  cap returns at 500. `truncated: true` iff there exists a match
  beyond `max_results` that we did not return (rg emitted more, or
  the result-cap fired). Returning exactly `max_results` matches
  with no more available → `truncated: false`.
- **INV-5.** Wall-clock budget. Soft target (perf canary in tests):
  `elapsed_ms ≤ 200 ms` p50 on this repo. **Hard kill**: 2 s
  `QTimer::singleShot` fires `terminate()`; 200 ms grace then
  `kill()`. The hard kill is independent of `max_results` and
  catches the catastrophic-regex / no-match-ever case.
- **INV-6.** No persistent state — `cmdWorkspaceSearch` is stateless;
  no cache, no warm-up. Simpler is correct.
- **INV-7.** MCP tools/list entry declares `pattern`, `regex`, `lane`,
  `glob`, `max_results`, `context`, `case` in `inputSchema.properties`
  with `pattern` required.
- **INV-8.** Stderr capture is capped at 4 KiB; populated only in
  the `ok:false` branch.
- **INV-9.** `glob` is NFC-normalised before validation, then
  capped at 256 bytes and rejected if it contains `..` substrings
  (`code:"bad_glob"`). NFC mirrors `lane`'s normalisation (INV-2)
  for consistency.
- **INV-10.** Reachability gate: `cmdWorkspaceSearch` is reachable
  only through the existing UDS + MCP socket — both enforce
  `SO_PEERCRED` UID match + 0700 dir + `lstat` `S_ISSOCK`. No new
  auth surface (per ANTS-1132).

## 5. Memory & perf

- **Memory:** O(max_results × max_line_length). With `--max-columns
  500`: default 50 × 500 B ≈ 25 KiB peak per call. Released after
  response sent.
- **CPU latency budget:** ripgrep does the work; our overhead is
  per-line `QJsonDocument::fromJson` (~15 µs/line at 50 results ≈
  0.75 ms) + result-array build. Target: ≤ 10 ms in our process;
  rg itself ≤ 200 ms p50 on this repo (perf canary). Hard kill at
  2 s + 200 ms (INV-5).
- **No cache (V1).** Search results are pattern-dependent; the
  measured pattern-repetition rate in sampled sessions is < 5%, so
  caching adds invalidation complexity without payoff. A 30-second
  LRU is a candidate follow-up if measurement shows higher repeat
  rates post-launch.

## 6. Token math (the point of this spec)

Measured against current Claude usage patterns:

| Pattern | Bash today | MCP `workspace_search` | Saving |
|---------|-----------:|-----------------------:|-------:|
| `grep -rn parseBullets src/` (11 hits, 1 file) | ~330 tokens | ~80 tokens | ~250 |
| `grep -rn "QFileSystemWatcher" src/` (32 hits, 9 files) | ~800 tokens | ~250 tokens | ~550 |
| `grep -rn "OSC" src/` (~250 hits, 12 files) | ~6 200 tokens | ~1 800 tokens (capped) | ~4 400 |
| `find . -name '*.md' \| xargs grep -l 'INV-'` (~70 files) | ~1 800 tokens | ~700 tokens | ~1 100 |

Estimated per-session saving on a typical "investigate a bug" run
(8-12 greps): **~6-15 K tokens.** Compounds across sessions.

## 8. Risks / mitigations

| Risk | Mitigation |
|------|-----------|
| `rg` not installed on user's host | Probe at server start; if absent, `tools/list` omits this tool. Document the dep in README. |
| Massive pattern matches OOM | `max_results` server-clamp + 4 KiB stderr cap + hard kill 2 s + 200 ms grace (INV-5/8). |
| Path-traversal via `lane` | Canonical-path startswith check + NFC + byte-class reject (INV-2). |
| Symlink TOCTOU between resolve and fork | rg invoked without `-L` (no follow), bounding the post-resolve window. Residual race is sub-ms and same-UID by socket gate (INV-10). |
| Pattern injection (regex DoS) | rg's Rust regex engine is linear-time; `--max-columns 500` caps per-line work and the wall budget (INV-1) caps total work; 2-tier kill (INV-5) catches a hostile rg-replacement on PATH that ignores SIGTERM. (`--threads` was listed here originally, but capping worker threads bounds neither per-line nor total work — it only serialises I/O. ANTS-3732 measured the cost and moved it 1 → 4.) |
| Stderr info-leak (path enumeration) | 4 KiB cap; never echoed in `ok:true` (INV-8). |
| Stale results during edits | None — every call re-runs rg. Cache-free by design (§5). |

## 9. Out of scope (V1)

- **Multi-pattern OR queries.** Defer: callers compose two calls
  cheaply; first-class union doubles schema-arg surface.
- **File-content replacement.** This tool is read-only by design;
  write-side belongs to a separate edit-tool spec with its own
  audit surface.
- **Symbol-aware search.** Would need clangd / LSP integration; an
  order of magnitude more work for a ~30% quality bump. Separate
  spec when needed.
- **Result-LRU cache.** Sampled pattern-repetition rate is < 5%;
  cache invalidation overhead exceeds the saving. Re-evaluate
  post-ship.

Error codes follow the families in
`docs/standards/mcp-errors.md`:
`bad_pattern`, `bad_lane`, `bad_glob` (input validation);
`rg_failed` (external-tool error).
