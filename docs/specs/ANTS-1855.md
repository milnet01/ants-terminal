# ANTS-1855 — `read_log` MCP tool (filter a log file, return only matching lines)

**Status:** accepted (2026-05-25) — design forks signed off (§ 8); 6
cold-eyes loops, converged (loop 6: 0 CRITICAL / 0 HIGH).
**Kind:** feature.
**Source:** ROADMAP.md ANTS-1855 (user-request-2026-05-25, motivated by
the ANTS-1853 session where reviewing the 5.7 MB Claude debug log meant
shelling out to `grep`/`tail` repeatedly).
**Pairs with:** ANTS-1860 (hook logging — more to read), ANTS-1500
(`get_scrollback` since-cursor — the incremental pattern reused here).

## 1. Problem

When a bug needs the Ants debug log
(`~/.local/share/ants-terminal/debug.log`, resolved by
`DebugLog::logFilePath()` — `src/debuglog.cpp:135`), Claude Code has no
MCP way to read it. The two existing readers don't fit:

1. `recent_errors` (`cmdRecentErrors`, `src/remotecontrol.cpp:1259`)
   scans **terminal scrollback**, not a log file on disk.
2. `get_scrollback` reads the live grid, not an arbitrary file.

So a CC session falls back to `Bash` (`grep`/`tail` on the file), which
(a) re-reads a multi-MB file repeatedly across a session and (b) pulls
whole matched blocks into the model context. For a 5.7 MB log this is
the exact token sink the MCP layer exists to remove. The same gap
applies to any log under the project root (build logs, app logs).

**Layman:** give Claude a tool to ask for *just the relevant lines* of a
log file, instead of reading the whole multi-megabyte file itself and
burning tokens.

## 2. Surface

New MCP read tool `read_log`, wired across the three standard sites:
handler `RemoteControl::cmdReadLog` (`src/remotecontrol.cpp`, joining the
existing `ants_core_lib`), a JSON inputSchema built **inside** the `tools/list` builder block of
`src/claudeintegration.cpp` (the same scope where the block-local lambda
`makeFieldsProp` is defined, `:1578`, and reused by the sibling read
tools — there is no `registerBuiltinTools` function, so the schema must
be added in that block), and
a `registerToolProvider("read_log", CallerCwdContract::Required,
rcDelegate(&RemoteControl::cmdReadLog))` dispatch in `MainWindow`,
following the **Required**-contract registration at
`src/mainwindow.cpp:3989` (`get_git_status`) — NOT the `recent_errors`
site at `:3851`, which is `TabSpecific`.

### 2.1 Target resolution

- `path` (string, optional). **Omitted →** the Ants debug log
  (`DebugLog::logFilePath()`), a known internal path read directly (no
  PathValidation — it is not caller-supplied).
- **Present →** resolved under `caller_cwd` and validated with
  `PathValidation::validatePath(rawPath, rootCanonical, "read_log",
  "path")` (`src/pathvalidation.h:46`, call-site pattern
  `src/remotecontrol.cpp:4224`). `allowOutsideRoot=false`: a path that is
  malformed or canonicalises outside the project root sets `check.bad` →
  return `check.err` (code `bad_path`). An in-root path that simply does
  not exist is NOT `check.bad`; `validatePath` returns `check.bad=false`
  with an empty `check.resolved` (`src/pathvalidation.h:20-21` — "empty
  if it does not exist") → the handler returns `{ok:false,
  code:"not_found"}`. Read from `check.resolved` otherwise.

### 2.2 Filters (applied per line, in this order)

- `include` (string, optional) — `QRegularExpression`; line kept iff it
  matches.
- `exclude` (string, optional) — `QRegularExpression`; line dropped if
  it matches.
- `contains` (string, optional) — plain substring the line must contain
  (cheap convenience; e.g. `contains:"claude"` for the debug-log
  category column). Applied before the regexes.
- `since` (string, optional) — lexical lower bound on each line's
  leading `[<timestamp>]` prefix: a line is kept iff `prefix >= since`.
  The debug-log line shape is local-time `[yyyy-MM-ddTHH:mm:ss.zzz]`
  with **no timezone offset** (`src/debuglog.cpp:162-163`), so it sorts
  lexically within a single offset; `since` is a raw-byte compare against
  that exact prefix (no timezone or sub-second normalisation — a `since`
  of different precision than `.zzz` compares as raw bytes). E.g.
  `since:"2026-05-25T17:40"` keeps a line beginning
  `[2026-05-25T17:40:03.221] …`. Caveat: across a DST fall-back two
  wall-clock-equal lines can mis-order (acceptable for v1). Lines with no
  `[...]` prefix are dropped when `since` is set.
- `tail` (int, optional) — after all filters, keep only the last N
  (most-recent) lines. **Clamped, not refused** (matching the `lines`
  arg at `src/remotecontrol.cpp:1227`): `N > 10000` clamps to 10000;
  `N <= 0` or omitted means no tail limit (all survivors, subject to the
  byte cap). `matched` still reports the full pre-tail count.

An invalid `include`/`exclude` pattern → `{ok:false, code:"bad_args"}`
(named which arg).

### 2.3 Output envelope

```json
{
  "ok": true,
  "path": "/home/<you>/.local/share/ants-terminal/debug.log",  // absolute
  "lines": ["[..] claude  hook recv: ...", "..."],
  "matched": 42,             // survived filters (pre-tail, pre-cap)
  "scanned": 13104,          // lines read this call (full file, or the
                             //   since_cursor delta — see 2.6)
  "returned": 20,            // lines.length after tail + byte-cap
  "truncated": false,        // true when the byte-cap dropped lines
  "lines_dropped": 0,        // present iff truncated
  "bytes_cap_clamped": false,// present iff max_bytes exceeded the 4 MiB ceiling
  "cursor": "1184022"        // opaque byte offset after last read (see 2.5)
  // since_cursor mode may also add: "cursor_stale": true,
  //   "stale_reason": "rotated" | "malformed_cursor"
}
```

The echoed `path` is the **absolute** resolved path
(`DebugLog::logFilePath()` for the default — an absolute
`QStandardPaths::GenericDataLocation` path, never tilde-collapsed — or
`check.resolved` for a supplied path).

`max_bytes` (int, optional; default `RemoteControl::kReadToolDefaultBytesCap`
= 512 KiB, clamped to the read-tool ceiling
`RemoteControl::kReadToolMaxBytesCeiling` = 4 MiB,
`src/remotecontrol.h:233-234` — the read-tool family `file_outline` uses,
NOT the `get_text` 16 MiB *ceiling*; `kGetTextDefaultBytesCap` is 1 MiB,
`remotecontrol.h:162`). A requested cap above the ceiling sets
`bytes_cap_clamped:true`. read_log keeps survivors in a **streaming
drop-oldest deque**: as lines stream in (oldest→newest) it tracks a
running **serialised** byte total — each line's JSON-encoded
contribution (quotes + comma + escapes), so `max_bytes` bounds the
emitted `lines[]` array, not just raw text (consistent with how
`capJsonArrayToBytes` measures) — and pops the **front** (oldest)
whenever the total exceeds `max_bytes` (or the deque exceeds `tail` N),
so peak heap is bounded by `max_bytes` regardless of file size or
whether `tail` is set (INV-12). Any drop sets `truncated:true` + `lines_dropped:<n>`.
It reuses neither existing capper: `trimScrollbackForGetText`
(`remotecontrol.h:191`) trims a single text blob + sentinel (wrong
shape), and `capJsonArrayToBytes` (`remotecontrol.h:246`) keeps the
**front** / drops the newest and runs post-hoc on the full array — the
wrong end for a log, and it would not bound the accumulation peak.

### 2.4 Standard contracts

- **caller_cwd: Required** (`callerCwdContractFor`,
  `src/claudeintegration.cpp:6879`). The tool resolves project-relative
  paths and anchors tenancy; empty `caller_cwd` → code
  `caller_cwd_required` (`src/claudeintegration.cpp:6411`). The debug-log
  default still requires it so the contract is uniform and the tool can't
  be used as an unscoped file reader. A non-empty but non-resolving
  `caller_cwd` is handled upstream by the dispatcher's
  `resolveCallerCwdRoot` (ANTS-1401/1404) before the handler runs — the
  handler can assume a resolved root.
- **fields projection (ANTS-1720)** — add `read_log` to
  `mcp::projectFields` (`src/mcpprojection.cpp`; ANTS-4524 removed the `fields=` allowlist; every verb honours it) and register
  `props["fields"] = makeFieldsProp()`. Lets a caller narrow to
  `["lines"]` or `["matched","scanned"]`.
- **No ETag.** A live-appending log changes on almost every call, so an
  mtime/size etag would never 304. The incremental path is `since_cursor`
  (§ 2.5) instead. (`isEtagSupportedTool` is left untouched.)

### 2.5 Incremental tailing (`since_cursor`, optional)

Mirrors the *protocol shape* of `get_scrollback`'s since-cursor
(`src/mainwindow.cpp:3865`) — opaque token in, fresh token +
`cursor_stale` out — but read_log's `cursor` is an opaque decimal **byte
offset**, NOT get_scrollback's monotonic push counter; do not copy the
counter encoding. read_log emits the literal reason `"malformed_cursor"`
to match get_scrollback byte-for-byte.

- `since_cursor` (string, optional) — a byte offset from a prior call's
  `cursor`. The handler `seek()`s to it and reads only appended bytes,
  applies the filters to the new lines, and returns a fresh `cursor`
  (the post-read offset).
- Soft-fallback — the *posture* (not the strings) mirrors
  `get_scrollback`: a bad cursor returns the full window, never `bad_args`,
  so a polling loop self-heals instead of erroring. read_log defines its
  own file-offset `stale_reason` values: `"rotated"` (`since_cursor >
  fileSize` — file shrank/rotated) and `"malformed_cursor"` (non-numeric
  cursor); both → `cursor_stale:true` + a full re-read from offset 0.
  (get_scrollback's own reasons — `malformed_cursor` / `counter_regressed`
  / `ring_wrapped`, `src/mainwindow.cpp:3897-3908` — are ring-buffer
  specific and don't all map to a file offset, so only `malformed_cursor`
  is shared by name.)
- A polling caller (e.g. watching for a new `hook recv:` line) thus
  transfers only new matching lines — the 80-95 % saving ANTS-1500
  cites.
- Partial trailing line: if the delta read does not end in `\n`, the
  final partial line is held (not emitted) and `cursor` is set to the
  offset before it, so the next call completes it.

### 2.6 Pipeline order + count semantics

A single call applies these stages in this exact order:

1. **Read slice.** Without `since_cursor`: stream the whole file
   (`QFile::readLine` loop, INV-12). With `since_cursor`: `seek()` to the
   offset and read only appended bytes (§ 2.5).
2. **Per-line filters** (§ 2.2), tested in order `contains` → `include`
   → `exclude` → `since`. A line survives only if it passes every set
   filter.
3. **`tail`** — keep the last N survivors (under `since_cursor`, the last
   N of the delta's survivors).
4. **Byte cap** (§ 2.3) — applied streaming via the drop-oldest deque, so
   steps 3-4 are one pass: each survivor is appended and the front popped
   when the deque exceeds `tail` N or `max_bytes`.
5. **Counts**, computed against this call's slice:
   - `scanned` = lines read in step 1 (whole file, or only the delta
     under `since_cursor`).
   - `matched` = survivors of step 2 (pre-tail, pre-cap).
   - `tail_selected` (intermediate, **not** an emitted field) =
     `min(matched, N)` when `tail:N` is set, else `matched`.
   - `returned` = `lines.length` after steps 3-4.
   - `lines_dropped` = `tail_selected − returned` — the count the byte
     cap removed; present iff `truncated`.

Edge cases: an empty file or zero survivors returns `ok:true,
lines:[], matched:0` with `cursor` at the file size (`0` for an empty
file). Filters (including `since`) apply to whatever the read slice is,
so `since` + `since_cursor` together filter the delta. A held partial
trailing line (§ 2.5) is not counted in this call's `scanned`. `tail:N`
is per-call (the last N survivors of *this* read slice), not a cumulative
window across `since_cursor` polls.

- **INV-4** — `include`/`exclude` are `QRegularExpression`; a line is
  emitted iff it matches `include` (when set) and does not match
  `exclude` (when set); an invalid pattern refuses with `bad_args`.
  *Test:* fixture log + good/bad patterns.
- **INV-5** — `contains:S` keeps only lines whose text contains the
  literal substring S. *Test:* fixture.
- **INV-6** — `since:T` keeps only lines whose leading local-time
  `[yyyy-MM-ddTHH:mm:ss.zzz]` prefix (no offset) is lexically `>= T`,
  compared as raw bytes; lines with no bracket prefix are dropped when
  `since` is set. *Test:* fixture with mixed timestamps.
- **INV-7** — `tail:N` is clamped (not refused): `N > 10000` → 10000,
  `N <= 0`/omitted → no tail limit; when applied it returns the last N
  post-filter lines and `matched` reports the full pre-tail count.
  *Test:* fixture with `matched > N` + an out-of-range value (asserts
  clamp, not `bad_args`).
- **INV-8** — Byte cap is a streaming drop-oldest deque (read_log's own
  accounting — reuses neither `trimScrollbackForGetText` nor
  `capJsonArrayToBytes`, which keep the wrong end / run post-hoc):
  `max_bytes` defaults to `kReadToolDefaultBytesCap` (512 KiB), clamps to
  `kReadToolMaxBytesCeiling` (4 MiB) with `bytes_cap_clamped:true` when
  over; the **oldest** survivors are dropped (deque front) until under
  cap, setting `truncated:true` + `lines_dropped`. *Test:* small
  `max_bytes` fixture asserting newest-kept/oldest-dropped + over-ceiling
  fixture.
- **INV-9** — Counts: the envelope always carries `matched` (post-filter
  pre-tail/cap) and `scanned` (lines read). *Test:* fixture asserts both.
- **INV-10** — `since_cursor` incremental: a prior `cursor` reads only
  appended bytes and returns a fresh `cursor`; a `since_cursor >
  fileSize` (rotation) **or** a non-numeric cursor soft-falls-back to
  `cursor_stale:true` + `stale_reason` + a full re-read (matching
  `get_scrollback` — never a refusal). *Test:* temp file appended-to
  across two calls + a shrink + a garbage cursor.
- **INV-11** — fields projection: `read_log` honours `fields=` (ANTS-4524: no allowlist)
  and `fields:["lines"]` narrows the envelope (ANTS-1720). *Test:*
  source-scrape + projection feature test.
- **INV-12** — Streaming read + bounded peak: the file is read once
  line-by-line (`QFile::readLine`, no `readAll` slurp) and survivors go
  into the drop-oldest deque (INV-8), so peak heap is bounded by
  `max_bytes` (≤ 4 MiB) **regardless of `tail` or file size** — a
  match-everything filter on a 5.7 MB log does not hold the whole match
  set. *Test:* source-scrape (`readLine` loop, no `readAll`) + a
  large-fixture smoke test asserting bounded growth.

## 4. RAM / build cost

No persistent state, no cache, no new build target (handler lands in
`ants_core_lib` via `remotecontrol.cpp`; schema in `ants_claude_lib`).
No new external library. The file is streamed line-by-line and survivors
go into a drop-oldest deque bounded by `max_bytes` (≤ 4 MiB read-tool
ceiling), so peak heap is ≤ `max_bytes` regardless of `tail` or file
size — a 5.7 MB (or larger) log never loads whole into memory, and even a
match-everything filter cannot balloon the deque. `max_bytes` (with the
4 MiB ceiling) is the named cap satisfying the no-unbounded-growth rule;
`tail` is an additional caller-facing bound, not the memory bound.

## 5. Out of scope

- Multi-file / glob log reading (one `path` per call) — revisit if asked.
- Structured (JSON-line) field extraction — `include` regex covers it
  for v1.
- Following a log in real time (the caller polls with `since_cursor`).

## 8. Resolved decisions (2026-05-25 sign-off)

1. **`contains` kept.** Literal-substring filter retained — it is the
   ergonomic path for the "filter by category/lane" case (e.g.
   `contains:"claude"`) without regex-escaping, and is cheap. (INV-5.)
2. **caller_cwd Required always.** Uniform with the path-tool family;
   the debug-log default still requires `caller_cwd` for tenancy so the
   tool can't be used as an unscoped file reader. (INV-3, § 2.4.)
3. **`since_cursor` ships in v1.** It is the core token-saver (poll a
   growing log, get only new matching lines); the rotation guard is
   part of v1. (INV-10, § 2.5.)
