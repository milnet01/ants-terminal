# ANTS-1372 — Caller-cwd gate on mutating MCP fold-in verbs (+ ANTS-1342 counter-path canonicalisation)

**Status:** spec draft → review → implement
**Kind:** security
**Source:** incident-2026-05-14 (ANTS-1372) + indie-review-2026-05-14 lane-5 ME-3 (ANTS-1342)
**Pairs with:** ANTS-1295 (per-tool path-anchor enforcement — same defense-in-depth
philosophy applied to project-root resolution).

---

## 1. Summary

Every mutating MCP verb whose effect is **scoped to a project root**
(`indie_review_fold_in`, `debt_sweep_apply_fix`, `debt_sweep_defer`,
`cold_eyes_fold_in`, `session_memory` set/delete, `verify_changes`)
must verify that the **calling Claude Code session's cwd** matches the
focused tab's cwd before it allocates an ID, writes to
`.roadmap-counter` / `ROADMAP.md` / `CHANGELOG.md`, mutates session-
memory state, or kicks off a verify run. If they disagree, the verb
refuses with `{ok:false, error:"<verb>: calling session cwd
\"<caller>\" does not match focused tab cwd \"<focused>\"",
code:"cwd_mismatch"}` (key order matches ANTS-1295 § 4.1).

Concurrently, `RoadmapFoldIn::allocateIds` canonicalises the counter
path before flock — closing the symlinked-counter aliasing case
(ANTS-1342 / indie-review-2026-05-14 lane-5 ME-3).

The two changes ship as one commit because they touch the same code
surface (mutating fold-in path) and defend the same invariant from
different angles: "project A's writes never escape project A."

## 2. Problem statement (threat model)

The Ants Terminal MCP server runs as a single in-process service on a
**shared Unix-domain socket** at
`$XDG_RUNTIME_DIR/ants-terminal/control.sock`. Every Claude Code
session anywhere on the machine — regardless of which project it was
launched in — routes its `mcp__ants__*` calls through that one socket.

The server resolves "project root" via `resolveRootCanonical(m_main)`
(`remotecontrol.cpp:1192–1199`), which returns the **focused tab's
shellCwd**. There is currently **no check** that the focused tab
belongs to the same project as the calling Claude Code session.

### 2.1 Observed incident (2026-05-14)

1. User had Ants Terminal open with a tab focused on the Ants Terminal
   repo (`/mnt/Games/Scripts/Linux/Ants_Terminal`).
2. A Claude Code session running **inside a different terminal** with
   `cwd = /mnt/Emulators/Scripts/python/mame_curator/MAME_curator/`
   invoked `mcp__ants__indie_review_fold_in` and related debt-sweep
   verbs intending to write to the MAME Curator repo.
3. The MCP server resolved "project root" from the focused tab (Ants
   Terminal) rather than the caller (MAME Curator).
4. The verb bumped `.roadmap-counter` 1371 → 1436 in the **Ants
   Terminal** repo and appended 65 ROADMAP bullets referencing
   `src/mame_curator/...` paths under § 0.7.65.
5. Recovery required `git checkout -- .roadmap-counter ROADMAP.md` in
   the Ants Terminal repo + re-running the verb manually pointed at
   MAME Curator.

### 2.2 Generalised threat

- **Cross-project write contamination** — every fold-in verb mutates
  whatever project the focused tab points at, regardless of where the
  caller is. A user with multiple Claude Code sessions in parallel
  cannot trust that a verb writes where the caller expects.
- **Session-disambiguation impossible at server level** — the UDS
  socket is shared; the server cannot distinguish callers by socket
  identity. The only handle is whatever the caller voluntarily
  declares in the request body.
- **Sibling case (ANTS-1342):** even with a correctly-anchored caller,
  if `.roadmap-counter` is a symlink that resolves outside the project
  root (or the project root itself is a symlink to a directory shared
  by two projects), `flock` + write happens against an aliased file.
  Two projects allocate from the same ID space.

## 3. Design

Two independent changes, one commit.

### 3.1 Caller-cwd gate (ANTS-1372) — `remotecontrol.cpp`

**New required argument** on the four mutating fold-in verbs:
`caller_cwd` (string, absolute path or `~`-expandable). Caller passes
their own `$PWD`. The server canonicalises it and compares against
`resolveRootCanonical(m_main)`. Refuse on mismatch.

Helper in `namespace RemoteControl::detail`, declared in
`src/remotecontrolgate.h` and defined in `src/remotecontrolgate.cpp`
(see § 3.1 helper-placement paragraph below):

```cpp
struct CallerCwdGate {
    bool ok = false;
    QString focused;   // canonical
    QString caller;    // canonical (or empty on missing/bad arg)
    QString errorCode; // e.g. "cwd_missing", "cwd_bad", "cwd_mismatch"
    QString error;     // human-readable
};

CallerCwdGate checkCallerCwd(MainWindow *main,
                             const QJsonObject &req,
                             const QString &verb) {
    CallerCwdGate g;
    g.focused = resolveRootCanonical(main);

    const QString rawCaller =
        req.value(QStringLiteral("caller_cwd")).toString();
    if (rawCaller.isEmpty()) {
        g.errorCode = QStringLiteral("cwd_missing");
        g.error = QStringLiteral("%1: caller_cwd argument required "
            "(pass your $PWD; refuses on mismatch with focused tab)")
            .arg(verb);
        return g;
    }
    g.caller = QFileInfo(rawCaller).canonicalFilePath();
    if (g.caller.isEmpty()) {
        g.errorCode = QStringLiteral("cwd_bad");
        g.error = QStringLiteral("%1: caller_cwd \"%2\" does not exist")
            .arg(verb, rawCaller);
        return g;
    }
    if (g.focused.isEmpty()) {
        g.errorCode = QStringLiteral("no_project");
        g.error = QStringLiteral("%1: no focused project").arg(verb);
        return g;
    }
    if (g.caller != g.focused) {
        g.errorCode = QStringLiteral("cwd_mismatch");
        g.error = QStringLiteral("%1: calling session cwd \"%2\" does "
            "not match focused tab cwd \"%3\"")
            .arg(verb, g.caller, g.focused);
        return g;
    }
    g.ok = true;
    return g;
}
```

Each gated verb replaces its current `resolveRootCanonical` + `no_project`
preamble with:

```cpp
const auto gate = checkCallerCwd(m_main, req, "indie_review_fold_in");
if (!gate.ok) {
    QJsonObject err;
    err["ok"]    = false;
    err["code"]  = gate.errorCode;
    err["error"] = gate.error;
    return QJsonDocument(err);
}
const QString root = gate.focused;
```

**Gated verbs (everything that writes, spawns a build, or allocates a
project-scoped ID):**

| Verb | Effect | Handler line |
|---|---|---|
| `indie_review_fold_in` | `.roadmap-counter` + `ROADMAP.md` | `remotecontrol.cpp:2185` |
| `debt_sweep_apply_fix` | source file under project root | `remotecontrol.cpp:2343` |
| `debt_sweep_defer` | `.roadmap-counter` + `ROADMAP.md` | `remotecontrol.cpp:2408` |
| `cold_eyes_fold_in` | `.roadmap-counter` + `ROADMAP.md` | `remotecontrol.cpp:2942` |
| `session_memory` (set/delete only) | `~/.config/.../session-memory/<project>.json` | `remotecontrol.cpp:3045` |
| `verify_changes` | spawns `cmake --build` + `ctest` in project root | `remotecontrol.cpp:2532` |
| `plan_template` | always — even in dry-run mode reads `.roadmap-counter` to derive a project-scoped ANTS-NNNN id (and writes `docs/plans/<id>.md` when `save=true`) | `remotecontrol.cpp:2622` |

**`session_memory` deprecates its `cwd` argument.** The pre-fix
handler accepted an arbitrary optional `cwd` arg (`remotecontrol.cpp:3052`,
comment-marker "INV-13" — that's an inline-handler note, not a
project-level invariant; this spec supersedes it). Two failure modes
were possible:
  (a) caller omits `cwd` → handler defaults to focused tab → cross-
      project write when focused tab is on a different project.
  (b) caller passes `cwd` explicitly → handler trusts the caller-
      supplied path with no anchor check at all.
The fix removes the `cwd` arg entirely for **set/delete** ops;
`caller_cwd` is the only project-scope source, and it must match the
focused tab. **get/list** ops are read-only and unchanged. Migration:
every existing caller (whether it passed `cwd` or omitted it) sees
`cwd_missing` until updated to pass `caller_cwd`. The error message
names the new arg explicitly so the migration is mechanical.

**`verify_changes` is gated even though it doesn't write source files.**
It spawns a multi-minute build + test pipeline; a caller in project A
who triggers it for project B gets a confusing green/red signal back
that doesn't correspond to their actual change. Same threat shape
(cross-project effect from a single shared socket), so same gate.
Note: the gate fires before the existing `cwd_unreachable` check
(`remotecontrol.cpp:2540`); a caller hitting both conditions
(mismatched caller_cwd AND non-directory focused root) sees
`cwd_mismatch` first, not `cwd_unreachable`. This is the intended
order — refuse on cross-project intent before any state probe.

**Read-only verbs are NOT gated.** `indie_review_corroborate`,
`debt_sweep_scan`, `cold_eyes_partition`, `cold_eyes_brief`,
`cold_eyes_cross_doc_diff`, `session_memory` (get/list),
`roadmap_query`, `git_state`, etc. only read — `validatePath`
(ANTS-1295) already anchors them. Adding a caller-cwd gate would break
the expected use case where a caller in project A wants to *survey*
project B from outside.

**Downstream uses `gate.focused` exclusively.** After a successful
gate, the verb body must use the `root = gate.focused` binding for
every subsequent operation — never re-call `resolveRootCanonical`
inside the same handler. Re-resolving would reintroduce a TOCTOU
window: the focused tab can switch (or its `shellCwd` update via OSC 7)
between the gate and the write, breaking the invariant the gate was
meant to enforce. This is a contract on the handler body, not a
helper-level enforcement — there is no greppable test for INV-10;
reviewers enforce it during code review of new mutating handlers.

**Helper lives in `namespace RemoteControl::detail`** (matching the
prior-art convention at `src/secretredact.h:29`'s `namespace detail`).
Declared in a new private header `src/remotecontrolgate.h` and
defined in `src/remotecontrolgate.cpp`; both `remotecontrol.cpp` and
the test bundle include the header. This replaces the anonymous-
namespace placement in the v1 spec, which would have blocked the
G1–G5 runtime tests.

**Audit logging — single refusal code logs.** Only `cwd_mismatch`
refusals emit `qWarning()` (per INV-11). The other refusal codes
(`cwd_missing`, `cwd_bad`, `no_project`) are caller-side bugs that
existed in v1 callers too; logging them would spam the log on the
first refused call from every legacy skill during the migration
window. The 2026-05-14 incident took ~30 minutes of RCA to identify
which session triggered the contamination; one log line on
`cwd_mismatch` shortens that to seconds.

### 3.2 Counter-path canonicalisation (ANTS-1342) — `roadmapfoldin.cpp`

```cpp
// Returns true iff resolving counterPath (or, if non-existent, its
// parent dir) stays inside projectPath's canonical form. Catches:
//   - .roadmap-counter is itself a symlink pointing outside the project
//   - the project root or any path component is a symlink to a
//     directory shared with another project
bool counterStaysInProject(const QString &projectPath,
                           const QString &counterPath) {
    const QString canonProject =
        QFileInfo(projectPath).canonicalFilePath();
    if (canonProject.isEmpty()) return false;

    QString canonCounter = QFileInfo(counterPath).canonicalFilePath();
    if (canonCounter.isEmpty()) {
        // File doesn't exist yet — canonicalise its parent dir and
        // synthesise the canonical form it WOULD take.
        QFileInfo cfi(counterPath);
        const QString parentCanon =
            QFileInfo(cfi.absolutePath()).canonicalFilePath();
        if (parentCanon.isEmpty()) return false;
        // FS-root edge case: if parentCanon == "/", we'd get
        // "//.roadmap-counter". Normalise by stripping a trailing
        // slash before the join.
        const QString joinable = parentCanon.endsWith(QChar('/'))
            ? parentCanon.left(parentCanon.size() - 1)
            : parentCanon;
        canonCounter = joinable + QChar('/') + cfi.fileName();
    }
    return canonCounter ==
        canonProject + QStringLiteral("/.roadmap-counter");
}
```

In `allocateIds`, between `if (n <= 0) return {};` and the path
construction:

```cpp
const QString path = counterPath(projectPath);
if (!counterStaysInProject(projectPath, path)) return {};

int fd = lockExclusive(path);
```

Same guard inside `insertBlock` for `ROADMAP.md`:

```cpp
bool roadmapStaysInProject(const QString &projectPath,
                           const QString &roadmapPath_) {
    const QString canonProject =
        QFileInfo(projectPath).canonicalFilePath();
    if (canonProject.isEmpty()) return false;
    QString canon = QFileInfo(roadmapPath_).canonicalFilePath();
    if (canon.isEmpty()) return false;  // ROADMAP.md must exist
    return canon == canonProject + QStringLiteral("/ROADMAP.md");
}
```

## 4. Invariants

INV-1: **All seven mutating verbs refuse without `caller_cwd`.**
`indie_review_fold_in`, `debt_sweep_apply_fix`, `debt_sweep_defer`,
`cold_eyes_fold_in`, `session_memory` (set/delete only),
`verify_changes`, and `plan_template` return `{ok:false,
error:"...", code:"cwd_missing"}` if the `caller_cwd` argument is
absent or empty.

INV-2: **`caller_cwd` is canonicalised before comparison.**
`/symlink/to/project` and `/real/project` (where the former resolves
to the latter) are treated as equal.

INV-3: **Mismatched cwds refuse with `cwd_mismatch`.** When the
canonicalised caller cwd differs from `resolveRootCanonical(m_main)`,
the verb returns `{ok:false, error:"...", code:"cwd_mismatch"}`
*before* allocating an ID, writing the counter, mutating session-
memory, spawning a verify run, or touching any target source file.

INV-4: **Non-existent `caller_cwd` refuses with `cwd_bad`.**
When the supplied `caller_cwd` doesn't canonicalise (path doesn't
exist), the verb returns `{ok:false, error:"...", code:"cwd_bad"}`.

INV-5: **Empty focused tab refuses with `no_project`.**
When no terminal is focused or its shellCwd doesn't canonicalise,
the verb returns `{ok:false, error:"...", code:"no_project"}` —
matching the pre-fix behaviour when there was no project to write to.

INV-6: **`allocateIds` refuses if the counter path escapes the project
root.** A `.roadmap-counter` symlink whose target sits outside the
canonical project root returns `{}` from `allocateIds`. Same guard
for `ROADMAP.md` in `insertBlock`.

INV-7: **Read-only verbs are unaffected.** `indie_review_corroborate`,
`debt_sweep_scan`, `cold_eyes_partition`, `cold_eyes_brief`,
`cold_eyes_cross_doc_diff`, `session_memory` (get/list),
and every read-only `mcp__ants__*` tool do not require `caller_cwd`.

INV-8: **Existing behaviour preserved for well-formed callers.** When
caller cwd matches focused tab cwd and the counter / ROADMAP files
sit at their expected canonical locations, the verbs behave exactly
as before — same ID allocation, same block emission, same insertion.

INV-9: **No new state.** The gate is stateless — it reads
`resolveRootCanonical` and the request body, returns a verdict. No
persisted "trusted callers" list; no cross-verb memory.

INV-10: **Single `resolveRootCanonical` call per handler.** After
the gate captures `focused`, the handler body uses `gate.focused` for
every subsequent operation. The TOCTOU window where the focused tab
could switch between gate-check and write is closed by this
discipline; re-calling `resolveRootCanonical` in the same handler is
a bug.

INV-11: **`cwd_mismatch` refusals log one `qWarning()` line.** Format:
`[ANTS-1372] cwd_mismatch refused: verb=<v> caller=<c> focused=<f>`.
Other refusal codes (`cwd_missing`, `cwd_bad`, `no_project`) do NOT
log — they're caller-side bugs, not cross-project incidents.

## 5. Test strategy

### 5.1 Runtime tests for ANTS-1342 (extend `tests/features/roadmap_fold_in/`)

R1. **Symlinked counter escape** — create two `QTemporaryDir`s
    `A` and `B`, each with a `.roadmap-counter` file containing `0\n`.
    Replace `A/.roadmap-counter` with a symlink → `B/.roadmap-counter`.
    Call `allocateIds(A, 3)`. Assert empty list returned.
    Assert `B/.roadmap-counter` still reads `0\n` (no allocation).

R2. **Counter file does not exist yet** — create empty dir `A`, no
    `.roadmap-counter`, no symlinks. `allocateIds(A, 1)` falls through
    the original "open returns empty" path and returns empty (existing
    behaviour preserved per test
    `RoadmapFoldIn.AllocateMissingCounterFails`). Asserts the guard
    doesn't reject the legitimate first-allocation path.

R3. **Well-formed call still allocates** — single `QTemporaryDir` with
    `.roadmap-counter` = `0\n`. `allocateIds(A, 2)` returns `{1, 2}`.
    Asserts the new guard doesn't break the happy path.

### 5.2 Runtime tests for ANTS-1372 — `checkCallerCwd` helper

For testability, `checkCallerCwd` is exposed as a free function in
`namespace RemoteControl::detail` (declared in a new private header
`src/remotecontrolgate.h`). The helper takes a pre-resolved focused
canonical path so the test doesn't need a MainWindow.

G1. **Missing `caller_cwd`** — `checkCallerCwd("/proj", QJsonObject{},
    "test_verb")` returns `{ok=false, errorCode="cwd_missing"}`.

G2. **Mismatch** — given focused=`/tmp/A`, caller=`/tmp/B` (both
    real dirs), returns `{ok=false, errorCode="cwd_mismatch"}`.

G3. **Canonical match** — both paths real and identical (or one is a
    symlink to the other), returns `{ok=true}` and `caller == focused`.

G4. **Non-existent caller_cwd** — caller=`/tmp/does/not/exist`,
    returns `{ok=false, errorCode="cwd_bad"}`.

G5. **Empty focused tab** — focused=`""`, caller=`/tmp/A` (real),
    returns `{ok=false, errorCode="no_project"}`.

## 6. Rollout

- **No config flag.** The gate is a hardcoded refusal; there's no
  legitimate use case for a caller in project A to mutate project B
  via Ants's MCP.
- **Caller-side update needed.** Every skill / agent that invokes a
  mutating fold-in verb must pass `caller_cwd: $PWD`. The shipped
  Claude Code skills under `~/.claude/skills/` already have access to
  `$PWD`; the change is one new line in each skill's MCP-call
  templates.
- **Error handling on caller side.** A skill receiving
  `code:"cwd_missing"` knows it shipped without the new arg; one
  receiving `code:"cwd_mismatch"` knows the focused tab is on the
  wrong project — the skill surfaces this to the user verbatim. The
  error envelope is stable contract.

## 7. RAM / build budget

Per [[feedback-consider-ram-in-feature-design]]: zero new heap
state. `checkCallerCwd` is stack-allocated; canonicalFilePath is one
syscall per check. `counterStaysInProject` / `roadmapStaysInProject`
add two `QFileInfo` objects per allocation — bounded by the verb's
own QFile usage. No memoisation, no cache.

Build cost: one new helper function in each of two TUs (estimated
≤ 60 lines of code total). PCH already includes the headers used
(`QFileInfo`, `QJsonObject`). Expect ≤ 1s additional compile on
`remotecontrol.cpp.o` + `roadmapfoldin.cpp.o`.

## 8. Migration / compatibility

Pre-fix callers passing the old (no-`caller_cwd`) argument shape
will receive `{ok:false, code:"cwd_missing"}` and fail loudly. There
is no "soft" rollout — the incident shows the bug is destructive,
so a hard fail is preferable to a silent foot-gun. The error
message tells the caller exactly which arg to add.
