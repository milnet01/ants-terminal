# ANTS-1459 — `roadmap_query` / `last_audit_summary` discovery widening + status-bar button parity

**Status:** in flight (Bundle E follow-up, 2026-05-17).
**Kind:** enhancement.
**Lanes:** `remotecontrol` (roadmap_query + roadmap_log + last_audit_summary),
`auditengine` (summariseCppcheckXml), `mainwindow`
(refreshRoadmapButton), tests under
`tests/features/mcp_last_audit_summary/` and
`tests/features/mcp_roadmap_unrecognised_format/`.
**Source:** cross-session-report-2026-05-17 (RetroArch CC instance
on `/mnt/Games/Scripts/Linux/RetroArch`).

## Problem

Two MCP discovery paths assumed project files live at the repo root.
RetroArch keeps its roadmap under `docs/private/ROADMAP.md` and its
audit cache in cppcheck's native XML format under `.audit_cache/`;
both tools quietly reported nothing-found when the data was right
there.

1. **`roadmap_query` returned `no_roadmap_loaded`** despite the
   project actively maintaining 362 lines of roadmap at
   `docs/private/ROADMAP.md`. Pre-fix discovery only searched the
   repo root with the three case variants
   (`ROADMAP.md` / `roadmap.md` / `Roadmap.md`).

2. **`last_audit_summary` returned `not_audited`** despite
   `.audit_cache/cppcheck-*.xml` files being present (12 of them,
   the format the project's own
   `docs/private/audit/aggregate.py --from-cppcheck` consumes).
   Pre-fix discovery only listed `audit-*.sarif` and failed without
   pointing at the cppcheck XML it could have parsed.

Same shape as ANTS-1429 (silent-empty roadmap_query against
GFM format): Claude believes the absence; the data is one
directory or one format away.

Follow-up surfaced mid-fix: the status-bar Roadmap button also
hides on RetroArch because `MainWindow::refreshRoadmapButton`
shares the same "repo-root only" search shape — fix it for parity
with the MCP-side widening.

## Fix

Four landing-together changes:

- **(a) `findRoadmapUnder(canonicalRoot)` shared helper.** Probes
  the canonical bullet locations:
  `./` (× three case variants: `ROADMAP.md` / `roadmap.md` /
  `Roadmap.md`), then `docs/`, `docs/private/`, `docs/internal/`,
  `.github/` (× two case variants each: `ROADMAP.md` /
  `roadmap.md` — the rare `Roadmap.md` titlecase is omitted in
  subdirs since no observed project uses it outside the repo
  root). Total **11** candidates. Returns the first
  `QFileInfo::exists()` hit; root wins on conflict (a project with
  both `ROADMAP.md` and `docs/ROADMAP.md` resolves to the root
  file). Lives at file scope in `remotecontrol.cpp`'s anonymous
  namespace so both `cmdRoadmapQuery` and `cmdRoadmapLog` consume
  the same path-list — also keeps per-function body under the
  32 KB regression-guard bound enforced by
  `tests/features/mcp_roadmap_unrecognised_format/`'s
  `boundedBetween` helper.

- **(b) Status-bar button parity.** `MainWindow::refreshRoadmapButton`
  carries the same widened candidate list (cannot share the helper
  directly without spinning out a separate include, and the dual
  inlines stay byte-equal under the new shared spec). The button
  surfaces on any project that ships a roadmap in one of the
  recognised paths.

- **(c) `last_audit_summary` recognises cppcheck-native XML.** When
  no `audit-*.sarif` is found, the handler now also probes
  `cppcheck-*.xml`. On hit it dispatches to
  `AuditEngine::summariseCppcheckXml` (new) which parses
  `<results version="2">`'s `<error>` entries via
  `QXmlStreamReader` and populates the same `AuditSummary` struct
  the SARIF path uses. Envelope gains a new `source_format` field
  echoing `"sarif"` or `"cppcheck-xml"` so callers can branch
  without sniffing the path's extension.

- **(d) AuditSummary.sourceFormat.** The engine struct gains a
  `sourceFormat` field set by both parsers. `buildLasEnvelope` echoes
  it as `source_format` on every response (default `"sarif"` when
  blank for back-compat).

No wire breaks: existing callers that ignore `source_format` keep
working. The `not_audited` refusal text gains an explicit hint
naming both probed shapes and pointing at `audit_run` /
`cppcheck --xml --xml-version=2` as the bootstrap path.

## Invariants

- **RQ-1.** `findRoadmapUnder` returns empty when the canonical
  root is empty (defensive guard; verified by source-grep on the
  early-return clause).
- **RQ-2.** `findRoadmapUnder(<canonical>)` probes **11 candidates**
  in first-hit order: root (3 case variants) → `docs/` → `docs/private/`
  → `docs/internal/` → `.github/` (2 case variants each).
  Returns the first `QFileInfo::exists()` hit, so root wins over
  subdirs on conflict.
- **RQ-3.** `cmdRoadmapQuery` and `cmdRoadmapLog` both call
  `findRoadmapUnder` for the caller_cwd branch; neither maintains
  its own inline path list. This dedup also keeps each function
  body under the 32 KB bound the regression-guard at
  `tests/features/mcp_roadmap_unrecognised_format/test_*.cpp`
  enforces via `boundedBetween`.
- **RQ-4.** `MainWindow::refreshRoadmapButton`'s candidate list
  carries the same 11 entries (verified by a source-grep test).
  Cannot share `findRoadmapUnder` directly without exposing it
  through a new header — deferred; the dual inlines stay
  byte-equal under this spec.
- **LAS-1.** `last_audit_summary` discovery probes `audit-*.sarif`
  first, then `cppcheck-*.xml` second; resolves `reportPath` to
  the lex-max name in whichever set matched.
- **LAS-2.** `summariseCppcheckXml(path, topN, floor)` returns
  `nullopt` on missing root `<results>` element and on
  `QXmlStreamReader` errors; otherwise an `AuditSummary` with
  `sourceFormat == "cppcheck-xml"`.
- **LAS-3.** `buildLasEnvelope` emits `source_format` on every
  response. Default `"sarif"` when the cached summary's field is
  blank (back-compat for any caller hitting an old cached entry).

## Test

Extend `tests/features/mcp_last_audit_summary/` with:

- A `fixture_cppcheck.xml` (4 entries: one error, two style/perf,
  one information) and a `Ants1459CppcheckXmlParsesCounts` runtime
  test that calls `AuditEngine::summariseCppcheckXml` and asserts
  counts + `sourceFormat == "cppcheck-xml"` + top finding shape.
  Covers LAS-2.
- `Ants1459SourceFormatInEnvelope` — source-grep for the
  `ok["source_format"]` emission + both literal source-format
  strings in `remotecontrol.cpp`. Covers LAS-1 and LAS-3.
- `Ants1459FindRoadmapUnderWidens` — source-grep for the
  helper declaration + four representative subdir paths. Covers
  RQ-2 (probe set) and RQ-3 (single source of truth).
- `Ants1459StatusBarRoadmapButtonWidened` — source-grep on
  `mainwindow.cpp` for the same subdir paths. Covers RQ-4.

RQ-1 (empty-root defensive) is covered by source-grep on the
`if (canonicalRoot.isEmpty()) return {};` early-return — folding
into `Ants1459FindRoadmapUnderWidens` rather than a separate test.

## Out of scope

- clang-tidy YAML / semgrep JSON parsers — logged as separate
  follow-ups under the same ANTS-1459-shape umbrella.
- ANTS-1462 header-inventory fallback (when the bullet parser
  yields zero entries) — separate planned item, requires its
  own response-mode design.
- `ROADMAP.adoc` / `docs/ROADMAP.rst` / non-markdown roadmap
  formats. The widening keeps the markdown filename invariant;
  alternate filetypes need a richer detector.
- Refactoring `MainWindow::refreshRoadmapButton` to call
  `findRoadmapUnder`. Cross-TU dependency between the GUI lib
  and the remotecontrol helper would introduce header coupling
  for one inline list; deferred.
- Roadmap_log refusal envelope explaining unrecognised_format
  (ANTS-1463) — already logged separately.
