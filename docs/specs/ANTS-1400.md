# ANTS-1400 — `caller_cwd_info` MCP diagnostic verb

## Problem

ANTS-1396's silent-fallback leak in `terminalForCaller` was easy
to miss because the resolution path was opaque to the caller —
you couldn't ask Ants "which tab would this call resolve to?"
without invoking the actual tool. Same shape for the 2026-05-15
cross-session report behind ANTS-1404: the only way a CC session
could detect that it was reading from the wrong project's MCP
data was to compare the response against its own expectations,
after the data already arrived.

ANTS-1401 introduced `ants::ResolvedRoot` as the tagged variant
behind every `caller_cwd` resolution. The `Source` enum already
encodes the four outcomes (`ExplicitMatch`, `EmptyFallback`,
`NoMatch`, `Unresolvable`); surfacing it through a dedicated MCP
verb gives callers a cheap way to diagnose resolution without
side effects.

## Goal

A new MCP verb `caller_cwd_info` that takes the same `caller_cwd`
argument every tab-anchored tool already accepts, runs it through
`ants::resolveCallerCwdRoot`, and returns the envelope verbatim.
Zero side effects (no scrollback read, no git invocation, no
file IO beyond the canonicalisations the helper already performs).

## Design

### Response envelope

```json
{
  "ok": true,
  "source": "ExplicitMatch"   // | "EmptyFallback" | "NoMatch" | "Unresolvable",
  "resolved_cwd": "/canonical/path",   // empty string for Unresolvable
                                       //   and for EmptyFallback with
                                       //   no focused tab
  "tab_index": 0                       // omitted when nullopt
}
```

No `ok:false` path — every input maps to one of the four `Source`
values. The MCP-level refusal codes (`caller_cwd_required`,
`tab_specific`) do not apply: this tool's whole job is to inspect
the caller_cwd argument, so it must accept the call regardless
of whether the arg is empty.

### Tool schema (tools/list)

```jsonc
{
  "name": "caller_cwd_info",
  "description": "Diagnose how Ants would resolve your caller_cwd ...",
  "inputSchema": {
    "type": "object",
    "properties": {
      "caller_cwd": {
        "type": "string",
        "description": "Your $PWD, or an arbitrary path you want
                        to test. Empty/absent → EmptyFallback
                        (returns focused-tab info)."
      }
    },
    "required": [],
    "additionalProperties": false
  }
}
```

`caller_cwd` is **not** required in the schema — the empty case is
the legitimate "what would happen if I omitted it?" question. This
distinguishes the verb from the `Required` group's "you must pass
caller_cwd to use this tool" semantics.

### Implementation

In `mainwindow.cpp`'s registry block (alongside the existing
`registerToolProvider` calls):

```cpp
m_claudeIntegration->registerToolProvider("caller_cwd_info",
    [this](const QJsonObject &args) -> QString {
        const QString callerCwd =
            args.value(QStringLiteral("caller_cwd")).toString();
        const ants::ResolvedRoot rr =
            ants::resolveCallerCwdRoot(this, callerCwd);
        QJsonObject env;
        env["ok"] = true;
        env["source"] = sourceToString(rr.source);
        env["resolved_cwd"] = rr.cwd;
        if (rr.tabIndex) env["tab_index"] = *rr.tabIndex;
        return QString::fromUtf8(
            QJsonDocument(env).toJson(QJsonDocument::Compact));
    });
```

The `sourceToString` helper is a free function in
`mainwindow.cpp`'s anonymous namespace; it switches over the four
`Source` values and returns the `PascalCase` literal. Defined
once, used here.

`caller_cwd_info` is classified `CallerCwdContract::Optional` in
`callerCwdContractFor` — caller_cwd is the input, not an anchor,
so neither `Required` nor `ProcessGlobal` is the right fit.

## Invariants

- **INV-1.** `caller_cwd_info` is registered as an MCP tool with
  the schema above. Empty `caller_cwd` arg is accepted (no
  refusal); the response carries `source: "EmptyFallback"`.

- **INV-2.** The handler is a pure delegation to
  `ants::resolveCallerCwdRoot` plus envelope serialisation. No
  filesystem operations beyond the canonicalisations the helper
  performs; no shell, no process, no cache writes.

- **INV-3.** The `source` field maps the `ResolvedRoot::Source`
  enum to a PascalCase string. The four values are
  `"ExplicitMatch"`, `"EmptyFallback"`, `"NoMatch"`,
  `"Unresolvable"`. New enum values added in the future require
  a matching `sourceToString` case (-Wswitch enforces this at
  compile time inside the helper).

- **INV-4.** `resolved_cwd` is the canonical FS path returned by
  the helper. Empty string for `Unresolvable` and for
  `EmptyFallback` with no focused terminal — these two cases
  are observable via `source` so callers can dispatch on it.

- **INV-5.** `tab_index` is present in the envelope iff
  `ResolvedRoot::tabIndex` is set (i.e. for `ExplicitMatch` and
  for `EmptyFallback` with a focused tab). Absent otherwise.

- **INV-6.** The verb is classified `Optional` in
  `callerCwdContractFor` so the ANTS-1404 dispatcher doesn't
  refuse empty-`caller_cwd` calls before the handler runs.

- **INV-7.** The response is wrapped via `wrapMcpData` like every
  other non-control-plane tool — the envelope is data, not
  structural metadata.

## Test

`tests/features/caller_cwd_info_verb/`:

1. **Registration (source-scrape).** Verify
   `registerToolProvider("caller_cwd_info"` appears in
   `mainwindow.cpp`.

2. **Schema (source-scrape).** Verify the schema block in
   `claudeintegration.cpp` lists `caller_cwd_info` as a tool name
   with the `caller_cwd` property (not required), exactly mirroring
   the schema described in § Design.

3. **Classification (source-scrape).** Verify
   `callerCwdContractFor` classifies `caller_cwd_info` as `Optional`
   (NOT Required — refusing empty caller_cwd would defeat the
   diagnostic purpose).

4. **Handler delegation (source-scrape).** Verify the provider
   lambda calls `ants::resolveCallerCwdRoot` and includes
   `source`, `resolved_cwd`, and `tab_index` in the envelope.

5. **Source string mapping (source-scrape).** Verify
   `sourceToString` covers all four `Source` enum values
   (`ExplicitMatch`, `EmptyFallback`, `NoMatch`, `Unresolvable`).

Label `features;fast`. Source-scrape only — the helper is
behaviourally tested via the wrappers in
`tests/features/terminal_for_caller_isolation/` already.

## Out of scope

- Mutation. The verb is read-only by design.
- A wider diagnostic API (e.g. `dispatch_trace`, `cache_state`).
  Each is its own ticket if needed.
- Schema-level deprecation of cwd args on other tools. Tracked
  in ANTS-1336 / ANTS-1404.

## RAM budget

Zero. Stack-allocated `ResolvedRoot` per call; no caching.

## Build cost

Trivial. One new lambda (~10 lines) plus one schema block (~15
lines) plus one `sourceToString` helper (~10 lines). No new TUs.
