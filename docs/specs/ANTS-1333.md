# ANTS-1333 — Scrollback hyperlink lockstep on width reflow

## Problem

`TerminalGrid::resize()` rebuilds `m_scrollback` during width-change
reflow at `terminalgrid.cpp:2458–2528` but never updates the parallel
`m_scrollbackHyperlinks` deque. After any width-change resize:

- The two deques are length-mismatched (reflow can split rows on the
  slow `joinLogical → rewrap` path).
- Every previously-clickable URL in scrollback maps to a different
  (or non-existent) row.
- The defensive bounds check at `terminalgrid.cpp:227–228`
  (`if (idx >= 0 && idx < m_scrollbackHyperlinks.size())`) prevents
  OOB read but returns spans for the WRONG row.

Second leak path: the screen-reflow overflow at
`terminalgrid.cpp:2548–2553` pushes excess lines into `m_scrollback`
without a matching push to `m_scrollbackHyperlinks`.

The lockstep contract is already documented at
`tests/features/osc8_insert_delete_lines/spec.md`: every mutation
that touches `m_screenLines[r]` or `m_scrollback[N]` must touch the
matching hyperlink container at the same index. `scrollUp()`
(`terminalgrid.cpp:1971–1976`) and `insertLines` / `deleteLines`
(ANTS-1027) honour this; `resize()` does not.

## Invariants (post-fix)

- **INV-1.** `m_scrollbackHyperlinks.size() == m_scrollback.size()`
  on every exit of `resize()`.
- **INV-2.** For scrollback rows taking the in-place fast path
  (`inPlaceResize`, content width fits new `cols`), the row's
  hyperlink span list carries over. Spans with `endCol >= cols`
  are clipped to `cols-1`; spans with `startCol >= cols` are
  dropped.
- **INV-3.** For scrollback rows taking the slow
  `joinLogical → rewrap` path, the corresponding hyperlink span
  lists are replaced with empty vectors (one per reflowed row).
  Acceptable loss — same path that already trims combining-char
  state and trailing spaces.
- **INV-4.** Screen-reflow overflow push at `:2548–2553` emits an
  empty `vector<HyperlinkSpan>{}` per push to `m_scrollback`. The
  `reflowed` lines come from `joinLogical(m_screenLines) → rewrap`,
  so their indices don't map back to `m_screenHyperlinks` —
  conservative-drop matches the slow-path semantics of INV-3.
- **INV-5.** Trim-to-`m_maxScrollback` operates on both deques in
  lockstep.

## Out of scope

- Screen-side hyperlink reflow across width change
  (`m_screenHyperlinks.resize(m_rows)` at `:2688` is unchanged).
  That's a separate concern — existing behaviour drops spans on
  trailing rows that disappear, which is acceptable for the screen
  buffer because OSC 8 spans rarely outlive their cells there.
- Reflowing column indices within a span when the row's
  `joinLogical → rewrap` reshapes content (would require parsing
  the OSC 8 anchor span structure). Empty-span output for
  slow-path rows is the conservative choice.

## Test

`tests/features/scrollback_hyperlinks_reflow_lockstep/`:

1. Seed grid 80×24; push 10 scrollback rows each carrying one
   hyperlink span at cols 5–15 (via `scrollUp` from screen-side
   OSC 8 spans).
2. **In-place narrow** — `resize(80, 60)`. Assert
   `m_scrollbackHyperlinks.size() == m_scrollback.size()`; assert
   row N's span is present at the same idx with `endCol` clipped
   to 15 (still fits) or to `cols-1` (if it didn't).
3. **In-place grow** — `resize(80, 100)`. Assert lockstep; assert
   span survives unmodified.
4. **Slow rewrap** — `resize(80, 10)`. Assert lockstep; assert
   spans are empty vectors (per INV-3).
5. **Overflow push** — seed full screen with a hyperlink on
   `m_screenLines[0]`, then resize to fewer rows so row 0
   overflows to scrollback. Assert lockstep;
   `m_scrollbackHyperlinks.back()` is an empty vector per
   INV-4 (post-rewrap rows have no source mapping).

Label `features;fast`. GUI-free C++ test linking
`src/terminalgrid.cpp` + dependencies only.

## Implementation

Parallel-iterate `m_scrollback` and `m_scrollbackHyperlinks` in the
reflow loop. Build `newScrollbackHyperlinks` alongside
`newScrollback`. For `inPlaceResize`, clip spans to `cols`; for
slow path, push empty. Move-assign both at end. Cap trim pops from
both. Overflow push at `:2548–2553` mirrors to
`m_scrollbackHyperlinks`.
