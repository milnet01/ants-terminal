# ANTS-1882 — `roadmap_query` per-section ETag

**Status:** spec draft, cold-eyes loop 1 folded (2026-05-26).
**Kind:** fix (close the per-section ETag invariance gap).
**Source:** ROADMAP.md ANTS-1882 (vestige-feedback-2026-05-26
Wishlist #4).

**Layman:** Vestige asked for a per-section "nothing changed"
short-circuit so calling `roadmap_query{section:"foo"}` returns
`unchanged:true` when only OTHER sections changed. Investigation
found the existing payload-based ETag *almost* delivers this —
except `duplicate_ids[]` was emitted as a full-file diagnostic on
section-mode responses, breaking the invariance whenever an
unrelated section's duplicates changed. The fix: section-scope the
`duplicate_ids` filter so foo's response only carries duplicates
that involve foo's bullets.

## 1. Problem

The ETag wiring in `ClaudeIntegration::applyEtagPattern`
(`src/claudeintegration.cpp`) hashes the **response payload bytes**:

```cpp
QString ClaudeIntegration::etagFor(const QString &payload) {
    return QString::fromUtf8(QCryptographicHash::hash(
        payload.toUtf8(), QCryptographicHash::Sha256).toHex().left(16));
}
```

For `roadmap_query{section:"foo"}`, the response built by
`cmdRoadmapQuery`'s section branch is *almost* section-bound: every
emitted field — `ok`, `path`, `count`, `filter`, `section`,
`bullets[]`, optional `warning` / `format` echoes / pagination
fields — derives from foo's bullets only.

**The exception:** `duplicate_ids[]` (ANTS-1646) is computed over
the full-file bullet set (`rcComputeDuplicateIds(m_roadmapCacheBullets)`)
and emitted on every emission branch, including the section path.
Result: an edit to section B that introduces or removes a duplicate
ID — even one that involves only B's bullets — shifts foo's
response payload, defeating the per-section ETag short-circuit.

## 2. Surface

### 2.1 The fix

A new helper `rcFilterDuplicateIdsForSection(const QJsonArray &dupes,
const QString &sectionSlug)` that walks the full-file
`duplicate_ids[]` array and returns only entries whose `occurrences[]`
includes at least one bullet inside the named section. The section
emission branch of `cmdRoadmapQuery` calls this helper instead of
emitting `m_roadmapCacheDuplicateIds` verbatim:

```cpp
const QJsonArray scoped = rcFilterDuplicateIdsForSection(
    m_roadmapCacheDuplicateIds, sec->slug);
if (!scoped.isEmpty()) {
    out["duplicate_ids"] = scoped;
}
```

When no duplicates involve the section, the field is omitted
entirely (the existing emptiness-gate is preserved).

### 2.2 Behavioural envelope

For `roadmap_query{section:"foo"}`:

| Edit scenario                              | Per-section 304? |
|--------------------------------------------|------------------|
| File untouched                             | Yes (file-mtime cache hit) |
| Section B edited, no duplicates involved   | Yes (response byte-identical) |
| Section B duplicate added, no foo overlap  | **Yes** (post-fix; was No pre-fix) |
| Foo's bullets edited                       | No (response shifts; expected) |
| A duplicate involving foo is changed       | No (foo's `duplicate_ids` shifts; expected) |

### 2.3 Other emission paths

The full-file path (no `section=`) and the `idArg` (single-bullet)
path emit `duplicate_ids` unchanged — those callers asked for a
global view of the roadmap, so the cross-section diagnostic is
appropriate. The `section_index` mode already emits its own
`legacy_format_sections[]` diagnostic at the per-section level; it
does not emit `duplicate_ids` (verified at
`src/remotecontrol.cpp` section_index branch).

### 2.4 Wire-shape change

Section-mode callers that depended on the cross-section
`duplicate_ids` view will see fewer entries (or none) when their
section has no overlapping duplicates. This is the correct
behavioural fix — callers wanting the full-file diagnostic should
call without `section=`. The diagnostic was emitted on a heuristic
basis (no documented contract guaranteed cross-section visibility
in section mode), so this is a quality fix, not a back-compat
breach.

## 3. Invariants

- **INV-1** — `rcFilterDuplicateIdsForSection(dupes, slug)` returns
  only entries whose `occurrences[].section_slug == slug` for at
  least one occurrence. Empty input or empty slug yields an empty
  array. *Test:*
  `tests/features/roadmap_query_per_section_etag/test_roadmap_query_per_section_etag.cpp::Inv1FilterContract`.
- **INV-2** — `cmdRoadmapQuery`'s section branch calls
  `rcFilterDuplicateIdsForSection` (not the bare cache field) when
  emitting `duplicate_ids`. *Test:* `…::Inv2SectionPathFilters`.
- **INV-3** — For a fixture where section B contains a duplicate
  not involving section foo, a `roadmap_query{section:"foo"}`
  response payload is byte-identical to one taken before B was
  edited — confirming per-section ETag invariance. *Test:*
  `…::Inv3SectionResponseInvariantUnderUnrelatedEdit` (source-grep
  guard locking the filter call site).
- **INV-4** — The full-file path and the `idArg` path emit
  `duplicate_ids` unchanged (full cross-section view). The
  per-section filter applies ONLY in the section path. *Test:*
  `…::Inv4FullFilePathUnchanged`.

## 4. Tests

`tests/features/roadmap_query_per_section_etag/`:

- **`spec.md`** — mirrors INV-1..INV-4.
- **`test_roadmap_query_per_section_etag.cpp`** — Inv1 calls
  `rcFilterDuplicateIdsForSection` directly with synthetic
  descriptors. Inv2/3/4 source-grep `cmdRoadmapQuery` for the
  filter call site in the section branch only.

## 5. RAM / build cost

Zero new state. ~20 LoC helper, ~10 LoC wiring, ~80 LoC test →
**~110 LoC** total.

## 6. Migration

Section-mode `duplicate_ids` view narrows from full-file to
section-scoped. No tracked caller relies on the cross-section view
in section mode (the diagnostic is heuristic, no contract). Stable
back-compat for default `roadmap_query` calls.
