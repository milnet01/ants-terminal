# ANTS-1722 — `TestAuditDialog`: native in-app test-suite review

**Status:** accepted — cold-eyes loop 1 + user sign-off (2026-05-21). Loop log § end.
**Kind:** implement.
**Source:** ROADMAP.md ANTS-1722 (user-request-2026-05-21).
**Blocked by:** ANTS-1727 (review-dialog foundation — `ReviewDialogBase`,
`LlmDispatcher`, `BriefDispatch`).
**Pairs with:** ANTS-1721 (`ColdEyesDialog`, the sibling subclass).
**Composes with:** ANTS-1580 (`partition_token` save-and-resume recipe).

## 1. Problem

The test-audit MCP engine is fully shipped — `TestAuditEngine` exposes
`partition`, `brief`, `synthesize`, and `foldIn`
(`src/testauditengine.h:219-222`). As with cold-eyes (ANTS-1721), the
mechanical halves (framework detect, file-tree walk, chunk packing,
pre-pass grep, synthesis, ROADMAP fold-in) run with no LLM; only the
per-chunk *judgment* needs a model. `TestAuditDialog` lets the user run
a test-suite audit inside Ants without spending Claude tokens on the
orchestration.

It mirrors `ColdEyesDialog` on the same `ReviewDialogBase` scaffold
(ANTS-1727), with three test-audit-specific differences: chunks instead
of doc lanes, a two-stage flow (per-chunk dispatch → one synthesis
dispatch), and a `partition_token` that supports closing and reopening
the dialog mid-audit (ANTS-1580).

## 2. Surface

`TestAuditDialog : ReviewDialogBase` (`src/testauditdialog.{h,cpp}`,
ants_dialogs_lib).

### 2.1 Partition (`derivePartition`)

Calls `TestAuditEngine::partition(PartitionRequest{ callerCwd =
projectCwd(), scope = "auto", dimensions = "auto", chunkSize = 12 })`
(`src/testauditengine.h:80-88`). Stores `PartitionResult.partitionToken`
(`src/testauditengine.h:113`) and `dimensionsActive`. Each
`Chunk` (`src/testauditengine.h:69-78`) maps to a `ReviewLane{ id =
chunk.id, title = chunk.id, summary = paths joined }`. The partition
panel renders framework + chunk count + the active/skipped dimension
sets; the user can edit the dimension set (re-partitions with
`dimensions = "csv:<…>"`) before dispatch.

### 2.2 Brief composition (`composeBrief`)

For chunk *C*:

1. `BriefResult b = TestAuditEngine::brief(BriefRequest{ callerCwd,
   chunkId = C.id, partitionToken })` — structured fields only
   (`src/testauditengine.h:129-140`): `sourcePaths`, `dimensions`,
   `frameworkContext`, `prePassFindings`, `priorFalsePositives`.
2. **System prompt** — the test-audit reviewer role seeded with the full
   `dimensionsActive` list (not just the pre-pass hits — per the
   `prePassDimensions` note at `src/testauditengine.h:74-77`), asking
   for findings in the standard `- [SEV] file:line — …` shape under
   `## <Dim>` sections so `synthesize`'s severity-histogram parser
   (`src/testauditengine.h:171-177`) can read them.
3. **User prompt** — the structured brief (dimensions, framework
   context, `prePassFindings`, `priorFalsePositives`) +
   `BriefDispatch::inlineBodies(callerCwd, b.sourcePaths, 64 KiB)`.

Token budget: as in ANTS-1721, `BriefDispatch::inlineBodies` bounds each
test-file body at 64 KiB, but 12 chunk files × 64 KiB can exceed
200 KiB, so the **200 KiB** *sum* gate + a `[brief truncated]` marker —
not the per-file cap — is the real bound. When exceeded, the
lowest-priority pre-pass context is trimmed first, then the marker is
appended (INV-4).

### 2.3 Synthesis (`onAllReportsCollected`)

On `allFinished`, `TestAuditDialog` writes each verbatim chunk report to
a temp reports dir under `.audit_cache/test_audit_<token>/` and calls
`TestAuditEngine::synthesize(SynthRequest{ callerCwd, partitionToken,
reportsDir, mode = "summary" })` (`src/testauditengine.h:142-151`). The
returned `SynthResult.prompt` is dispatched via the base
`dispatchOne(job, cb)` (ANTS-1727 § 2.4) — a single follow-up job that
does **not** re-enter `onAllReportsCollected` — for the cross-chunk
narrative summary. The `dimensionSummaries`, `topDimensions`, and
`severityHistograms` (`src/testauditengine.h:155-177`) render in a
results tab alongside the model's returned summary text.

### 2.4 Fold into ROADMAP (`performFoldIn`)

Unlike cold-eyes, the `performFoldIn` override here calls
`TestAuditEngine::foldIn` directly — that engine entry **owns ID
allocation + insert internally** (`src/testauditengine.h:21`,
"`fold_in` delegates to `RoadmapFoldIn::*` engine entries directly"), so
the dialog must **not** also call the base `allocateFoldInIds` /
`insertFoldInBlock` helpers (doing so would double-allocate).

Primary mode is **narrative** (ANTS-1635): the user edits the grouped
summary (Closed-inline / Deferred / False-positives) and
`TestAuditEngine::foldIn(FoldInRequest{ …, narrativeMode = true,
narrativeMd })` (`src/testauditengine.h:180-198`) inserts it verbatim
under the `### 🧪 Test Audit YYYY-MM-DD` heading with **no** ID
allocation. A per-finding mode (`actionable[]`, IDs allocated by the
engine) remains available for users who want individual bullets.

### 2.5 Resume (`partition_token` via `session_memory`)

On partition, the dialog persists `{ partition_token, dimensions,
collected_chunk_ids }` keyed on the project cwd via
`SessionMemoryEngine` (`src/sessionmemoryengine.h`, the in-process
backing store the `session_memory` MCP tool also writes — so the dialog
needs **no** MCP socket round-trip and resume interoperates with the
MCP recipe in `docs/standards/test-audit-resume.md`, ANTS-1580).
Reopening the dialog offers **Resume**: it reloads the token and the
already-collected reports, dispatching only the chunks not yet reviewed.

Staleness handshake (ANTS-1580 caveat): the engine's partition cache is
in-process and LRU-bounded (`src/testauditengine.h:224-228`), so after
an Ants restart `brief` may return `code:"stale_token"`. The dialog
detects this and re-runs `partition` (a fresh token), preserving any
collected reports it can re-key by chunk path set. This is INV-6.

## 3. Invariants

- **INV-1** — `derivePartition` chunks come from
  `TestAuditEngine::partition`; the stored `partitionToken` is the one
  passed to every `brief` call. *Test:* `test_audit_dialog` — stub a
  suite, assert chunk set matches the engine and brief requests carry
  the token.
- **INV-2** — `composeBrief` seeds the prompt with the full
  `dimensionsActive` list (not only `prePassDimensions`) and inlines
  `sourcePaths` fenced via `BriefDispatch`. *Test:* compose against a
  fixture chunk → all active dimensions present, fenced bodies present.
- **INV-3** — chunk reports are written under
  `.audit_cache/test_audit_<token>/` and `synthesize` is called with
  that `reportsDir`. *Test:* fixture reports → files written under the
  token dir, `SynthResult.reportsRead` matches the chunk count.
- **INV-4** — composed prompt capped at 200 KiB with a truncation
  marker. *Test:* oversize chunk → prompt ≤ cap, marker present.
- **INV-5** — narrative fold-in allocates no IDs and inserts under the
  `### 🧪 Test Audit` heading; per-finding fold-in allocates one ID per
  actionable finding. *Test:* narrative → `.roadmap-counter` unchanged;
  per-finding with N → counter advances by N.
- **INV-6** — a `stale_token` from `brief` (post-restart cache miss)
  triggers a `partition` re-run rather than a hard error; collected
  reports re-key by chunk path set where possible. *Test:* simulate
  `lookupPartition` miss → dialog re-partitions, no crash, no lost
  collected reports.
- **INV-7** — Resume reloads `{ partition_token, collected_chunk_ids }`
  from `session_memory` and dispatches only un-reviewed chunks. *Test:*
  seed `session_memory`, reopen → only missing chunks enqueued.
- **INV-8** — Dispatch disabled when `ai_endpoint` is unset/invalid
  (inherited `ReviewDialogBase::endpointDispatchable`, ANTS-1727
  INV-12). *Test:* smoke assertion of the disabled state.

## 4. RAM / build cost

- **Prompt budget** — 200 KiB per composed chunk prompt (INV-4); peak
  inlined-body memory ≈ 2 × 200 KiB at the ANTS-1727 default concurrency
  of 2, plus the bounded `LlmClient` stream buffers.
- **Stored reports** — chunk-count × verbatim report. Chunk count scales
  with suite size; each report ≤ the 10 MiB `LlmClient` cap
  (realistically KB-scale). Reports also persist to
  `.audit_cache/test_audit_<token>/` (disk, not RAM) for resume —
  bounded by the existing `.audit_cache` retention conventions
  (`docs/standards/mcp-caches.md`). The dialog clears its in-RAM map on
  re-partition.
- **session_memory entry** — `{ token, dimensions, chunk-id list }`,
  well under the 4 KiB per-entry cap (ANTS-1723) and the 72 h lazy TTL.
- **Build** — 1 new `.cpp` (`testauditdialog`) in `ants_dialogs_lib` +
  a MainWindow menu entry. No new external libraries. ~300–400 LoC +
  ~120 test LoC.

## 5. Out of scope

- **Live token streaming** into per-chunk tabs — deferred with
  ANTS-1727 § 5.
- **`full`-mode synthesis pagination** (`src/testauditengine.h:148-150`)
  — v1 uses `summary` mode; full-mode paging is a follow-up.
- **Polyglot fan-out** via `additionalFrameworks`
  (`src/testauditengine.h:95-103`) — surfaced as a hint in the partition
  panel but a second partition call is manual in v1.
