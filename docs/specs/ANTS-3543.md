# ANTS-3543 — Auto-downshift a would-be-truncated list to its lean projection instead of dropping the tail

`RemoteControl::downshiftMatches` (header, socket-free) rewiring

`rc_read_tool_byte_cap` WI-2; full `features` label green (2781/2781).
**Kind:** enhancement.
**Source:** ROADMAP.md ANTS-3543 (`🔌 MCP integration deepening — token + perf`
block); in-session-2026-07-16 token-saving sweep, wave 3.
**Builds on:** `PaginationEngine::pageBullets` (`src/paginationengine.{h,cpp}`,
ANTS-1436 — the auto-truncate helper for `roadmap_query`); `rcProjectHeadlineOnly`
(`rcProjectHeadlineOnly`, `src/remotecontrol.cpp` — roadmap_query's lean row projector);
`rcApplyHeadlineOnly` (defined `src/remotecontrol.cpp:431`, called at `:10736` —
workspace_search's lean match projector); `RemoteControl::capJsonArrayToBytes`
(defined `src/remotecontrol.h:256`, called at `src/remotecontrol.cpp:10870` —
workspace_search's byte-cap tail-trim, which sets **both** `truncated:true` and
the dropped-count key on a trim, and clears neither on a fit).
**Distinct from:** ANTS-3532 (compact drops *empty/false* fields — same row shape;
this keeps every row but drops *bodies*, changing row shape only when it would
otherwise truncate). ANTS-3538 (offload spills the *whole* oversized body to a
handle; this trims in-place and still returns a usable list). ANTS-3547
(workspace_search `offset` cursor — paging the *dropped* tail; this avoids the
drop in the first place). The three are complementary, not overlapping.

## 1. Problem

`roadmap_query` and `workspace_search` cap a large result list at a soft byte
budget by **truncating tail rows** — `PaginationEngine`'s ~20 KB
`kSoftCapBytes` measure-then-cut (`src/paginationengine.cpp`), and
workspace_search's `capJsonArrayToBytes(out, "matches", "results_dropped", …)`
tail-trim (`src/remotecontrol.cpp:10870`). Both report the loss
(`truncated:true` + `next_offset`, or `results_dropped`), but a caller
**scanning for existence or coverage** ("is ANTS-3xxx tracked anywhere?", "how
many call-sites reference `foo`?") silently loses the tail: it gets ~50 *full*
rows and an invisible remainder.

The full rows carry the cost. A roadmap bullet's `body` (multi-line prose) and a
search match's `context_before`/`context_after` + long `text` are what blow the
budget — not the identifying `id`/`headline`/`file:line`. Every one of these
verbs **already has a lean projection**: `roadmap_query`'s `headline_only` mode
(`rcProjectHeadlineOnly` → `{id, status, headline_oneline, section_slug}`) and
workspace_search's `headline_only` mode (`rcApplyHeadlineOnly` → `{file, line,
headline}` + `also_at`, context dropped). But those projections are opt-in: a
caller who did not ask for them, and did not cap the list, gets the fat-then-
truncated default.

The fix: when a list would exceed the soft cap **on the auto path** (caller
passed no explicit page size), first **downshift** the whole list to its
existing lean projection and re-measure. All (or far more) items now fit in the
same budget, so a scanning caller gets *every* `id`/`headline` rather than 50 fat
rows plus an invisible tail — truncating only if even the lean list overflows.

**Layman:** When a list of results is too big to send whole, keep every item but
drop the long descriptions (show just the titles) rather than cutting off the
end — so nothing goes invisibly missing. (If even the titles-only list is too
big it still pages, but every page is titles, never a hidden cut-off.)

## 2. Surface

Two verbs, two distinct truncation mechanisms, so two wirings around **one
shared idea** (project-the-full-set-then-re-measure). No new caller argument: the
downshift is a heuristic on the existing auto-truncate path, and the opt-out is
the intent the caller already expresses (an explicit `limit`, `include_body`, or
an already-lean `mode`).

### 2.1 `PaginationEngine` — optional projector callback

`pageBullets` gains an optional projector. The engine already holds the **full**
`filtered` array and does the measure-then-cut, so it is the right place to
re-page a projected copy (`roadmap_query` wires it now; `changelog_query` shares
the helper and becomes *eligible* via this same hook — deferred, § 5).

```cpp
// src/paginationengine.h
namespace PaginationEngine {

// Mutates a row array in place to its lean shape (same contract as
// rcProjectHeadlineOnly). Qt6::Core-only; std::function from <functional>.
using RowProjector = std::function<void(QJsonArray &)>;

struct PageResult {
    QJsonArray slice;
    int  offset;
    int  limit;
    int  total;
    bool truncated;
    int  nextOffset;
    bool downshifted = false;   // NEW — rows were projected to their lean
                                // shape to fit more items in the budget.
};

// `downshift` default {} → byte-identical to pre-3543 behaviour.
PageResult pageBullets(const QJsonArray &filtered, int offset, int limit,
                       const RowProjector &downshift = {});
}
```

Engine logic (added after the existing measure-then-cut):

1. Run the current measure-then-cut on `filtered` → `(slice, truncated,
   nextOffset)`. Unchanged.
2. **If** `downshift` is set **and** `limit <= 0` (the engine's auto-pick
   branch — `paginationengine.cpp:66` runs measure-then-cut whenever
   `limit <= 0`; an explicit *positive* `limit` is the caller choosing a page
   size and is respected verbatim) **and** `truncated` (the fat set dropped
   ≥1 row):
   - Copy the **full** `filtered`, apply `downshift` to the copy → `leanFull`.
   - Re-run measure-then-cut on `leanFull` from the same `offset`.
   - Return that paging with `downshifted = true`. If `leanFull` fits entirely
     from `offset`: `truncated = false`, `nextOffset = -1`. If it still
     overflows: `truncated = true`, `nextOffset` advances over the *lean* set.
3. **Else** return step 1's result with `downshifted = false`.

The caller's `filtered` array is never mutated — the projector runs on a copy.

### 2.2 `roadmap_query` wiring (`cmdRoadmapQuery`)

`cmdRoadmapQuery` calls `pageBullets` at **two bullet-emitting sites** — the
`section=` branch (`src/remotecontrol_roadmap_query.cpp`) and the full-file branch
(`:5230`). Wire the downshift projector at **both**. The third
`pageBullets` call — the `section_index` `sections[]` branch (ANTS-1729) — pages
*section descriptors*, which have no `headline_only` lean form (like
`find_sources`, § 5), so it is **excluded**: pass it an empty projector. (Adding
a 4th argument does not add or remove call sites, so ANTS-1436 INV-11's
"exactly-5-`pageBullets`-calls" source-scrape still holds.)

At each bullet site, pass `rcProjectHeadlineOnly` as the projector **iff** the
response is not already lean and the caller did not ask for bodies:

```cpp
const bool wantDownshift = (mode != QLatin1String("headline_only")) && !includeBody;
auto page = PaginationEngine::pageBullets(
    filtered, offsetArg, limitArg,
    wantDownshift ? PaginationEngine::RowProjector(&rcProjectHeadlineOnly)
                  : PaginationEngine::RowProjector{});
…
if (page.downshifted) out["downshifted"] = true;   // emit only when true
```

`headline_only` mode already projects the slice — no downshift (already lean).
`include_body=true` is an explicit request for bodies — no downshift (respect
it). When downshift fires, `wantDownshift` was true so `mode != "headline_only"`
— the trailing `mode==headline_only` projection block is therefore **skipped**
(not re-run), and `rcStripBodyFields` is a genuine no-op on the already
headline-shaped rows.

### 2.3 `workspace_search` wiring

workspace_search does **not** use `PaginationEngine`; it caps with
`capJsonArrayToBytes` (called at `src/remotecontrol.cpp:10870`). Add the
cap-plus-downshift step as a **`static inline` member of `RemoteControl` in
`remotecontrol.h`** — the same home as `capJsonArrayToBytes`, which is why the
existing `rc_read_tool_byte_cap` feature test can call `capJsonArrayToBytes`
directly (no socket, no `remotecontrol.cpp` link). It takes the lean projector as
a **callback** (mirroring `PaginationEngine`'s `RowProjector`) so it does not
depend on the TU-local `rcApplyHeadlineOnly` — the handler passes that in, and a
pure test passes a synthetic projector. This is what makes INV-8/9/10 executable
(§ 6):

```cpp
// remotecontrol.h — static inline sibling of capJsonArrayToBytes. Applies the
// byte-cap to out["matches"]; iff it dropped AND the caller isn't already lean,
// downshifts the FULL matches via `leanProjector` and re-caps. Sets downshifted /
// headline_only / results_dropped / bytes_cap_clamped and an HONEST truncated.
// `scanTruncated` is out["truncated"] BEFORE this call (its SCAN-cutoff meaning,
// set at remotecontrol.cpp:10785 — capJsonArrayToBytes overwrites truncated to
// true on a trim and clears nothing on a fit, so recompute the honest value here).
static inline void downshiftMatches(
        QJsonObject &out, bool alreadyLean, bool scanTruncated, int maxBytes,
        const std::function<void(QJsonArray &)> &leanProjector) {
    const QJsonArray fullMatches = out.value("matches").toArray();  // pre-cap
    auto cap = capJsonArrayToBytes(out, "matches", "results_dropped", maxBytes);
    bool capClamped = cap.capClamped;
    if (out.contains("results_dropped") && !alreadyLean) {
        QJsonArray lean = fullMatches;
        leanProjector(lean);                 // handler passes rcApplyHeadlineOnly
        out["matches"] = lean;
        out.remove("results_dropped");       // the fat-cap drop no longer applies
        out["downshifted"]  = true;
        out["headline_only"] = true;         // reflect the shape now emitted
        capJsonArrayToBytes(out, "matches", "results_dropped", maxBytes);
        // (same maxBytes ⇒ capClamped is unchanged from the first cap.)
        // HONEST truncated: scan cutoff OR the lean re-cap still dropped. Without
        // this the stale fat-cap truncated:true would falsely signal "incomplete"
        // on a fully-returned lean list — the exact signal § 1 exists to prevent.
        out["truncated"] = scanTruncated || out.contains("results_dropped");
    }
    if (capClamped) out["bytes_cap_clamped"] = true;   // preserve ANTS-1293 echo
}
```

The projector callback exists for **testability**, not for a second caller
(workspace_search is the only one) — it decouples the header-inline helper from
the `.cpp`-local `rcApplyHeadlineOnly` so the pure test can drive it without
linking `remotecontrol.cpp`.

The handler replaces its inline cap block (`remotecontrol.cpp:10868-10874`) with:

```cpp
const bool scanTruncated = out.value("truncated").toBool();  // pre-cap
RemoteControl::downshiftMatches(out, headlineOnly, scanTruncated,
                                req.value("max_bytes").toInt(0),
                                rcApplyHeadlineOnly);
```

When no downshift fires the helper is byte-identical to the old block (cap once,
echo `bytes_cap_clamped`) — so the non-downshift path is unchanged. `also_at`
(the dedup fan-out) carries no `text` field, so `rcApplyHeadlineOnly` leaves it
intact (its existing ANTS-1876 INV-5b contract). The `count_only` / `files_only`
modes return before this cap step, so they never reach `downshiftMatches` — they
carry no `matches[]` rows to downshift.

### 2.4 Envelope contract

- `downshifted: true` is emitted **only when a downshift fired** (omitted
  otherwise — same truthy-only discipline as `truncated`/`results_dropped`, so
  ANTS-3532 compact and `fields=` leave it alone).
- When `downshifted` is set, the row shape is the verb's lean projection, and a
  residual-overflow signal may still be present if even the lean list overflowed
  — but it is the verb-appropriate signal and it is honest, never stale:
  - `roadmap_query`: `truncated:true` + `next_offset`. `PaginationEngine` returns
    a freshly-computed `PageResult`, so no staleness is possible.
  - `workspace_search`: `truncated` (**recomputed** = scan-cutoff OR lean re-cap
    still dropped, § 2.3) + `results_dropped`. It does **not** emit `next_offset`
    on a byte-cap trim — `next_offset` is the ANTS-3547 match-event cursor
    (`seenMatchEvents`), not a cap signal.
- Optional read-hint (advisory, non-invariant): when `downshifted` fires the
  dispatch read-hint may note "rows shown as titles only to fit N items — pass
  an explicit `limit` (or `include_body`) to page full rows." Nice-to-have; not
  a contract.

## 3. Invariants

### Engine (`PaginationEngine`)

- **INV-1** — `pageBullets` called with the default (absent) projector is
  byte-identical to pre-3543: same `slice`, `truncated`, `nextOffset`, and
  `downshifted == false`. *Test:* the existing `roadmap_query_pagination`
  suite (INV-1..11) passes unchanged; a new case asserts `downshifted == false`
  on a no-projector call.
- **INV-2** — the downshift path fires **iff** the projector is set **and**
  `limit <= 0` **and** the fat set truncated. The `<= 0` matches the engine's
  auto-pick branch (`paginationengine.cpp:66`, the `else` of `limit > 0`); per
  the `pageBullets` header contract (`paginationengine.h:50`) `0` is invalid and
  is rejected upstream with `bad_args`, so in practice only `-1` reaches this
  branch — `< 0` and `<= 0` coincide, and `<= 0` is chosen only to stay
  consistent with the branch the engine actually takes. An explicit *positive*
  `limit` never triggers a downshift (fat paging respected). *Test:*
  `pageBullets(fat, 0, -1, proj)` → `downshifted`; `pageBullets(fat, 0, 50,
  proj)` → not downshifted.
- **INV-3** — a fired downshift projects a **copy of the full `filtered` set**
  (never just the current slice) and re-pages from `offset`. If the lean set
  fits from `offset`: `truncated == false`, `nextOffset == -1`, and every item
  from `offset` is present. If it still overflows: `truncated == true`,
  `nextOffset` advances over the lean set, and the slice holds **no fewer** rows
  than the fat page did — strictly more whenever the projector actually removed
  bytes from each row, equal only in the degenerate case of rows whose lean and
  fat shapes are the same size (e.g. an empty-body rollup bullet).
  *Test:* one fixture that fits-when-lean (all items, not truncated) and one
  whose rows carry bodies and overflow even when lean (truncated, `slice.size()`
  strictly > the fat page's).
- **INV-4** — `PageResult.downshifted` defaults `false`; the input `filtered`
  array is never mutated by a downshift (projector runs on a copy). *Test:*
  struct default + caller's array compared equal before/after a downshift call.

### `roadmap_query`

- **INV-5** — `cmdRoadmapQuery` passes `rcProjectHeadlineOnly` as the projector
  at **both** bullet-emitting `pageBullets` sites (section + full-file) iff
  `mode != "headline_only"` **and** `!include_body`; otherwise (and at the
  `section_index` site) it passes an empty projector. *Test:* source-scrape for
  the gated projector at both sites; the "`include_body=true` → empty projector →
  no downshift" behaviour is the pure INV-1 no-downshift case (an empty projector
  never downshifts), not a socket-level check.
- **INV-6** — when the engine downshifts, `cmdRoadmapQuery` emits `downshifted:
  true` (omitted when false) and the emitted rows are headline-shaped
  (`{id, status, headline_oneline, section_slug}`). *Test:* the engine downshift
  is pure-tested (INV-1..3); the verb's emit-when-fired guard is source-scraped
  (handler needs a live socket — see § 6).
- **INV-7** — an explicit *positive* `limit` on `roadmap_query` never downshifts
  (INV-2 at the verb boundary): the caller gets `limit` fat rows + `truncated`/

  rejects it with `bad_args` before `pageBullets`, per ANTS-1436 INV-8.) *Test:*
  the "positive limit → not downshifted" behaviour is the pure INV-2

  source-scraped.

### `workspace_search`

- **INV-8** — when `capJsonArrayToBytes` drops matches (`results_dropped`
  present) **and** the caller did not pass `mode=headline_only`, the handler
  re-projects the **full** pre-cap matches via `rcApplyHeadlineOnly`, re-caps,
  sets `downshifted: true` + `headline_only: true`, and **recomputes `truncated`
  = (pre-cap scan-cutoff) OR (lean re-cap still dropped)** — never leaving the
  fat cap's `truncated:true` stale. When the lean set fits and there was no scan
  cutoff, both `truncated` and `results_dropped` are falsy/absent (a
  fully-returned lean list reads as complete). *Test:* pure test over
  `RemoteControl::downshiftMatches` (§ 2.3) across all four scan-cutoff ×
  lean-fits/drops cases (enumerated in § 6) — e.g. (a) no scan cutoff + lean fits
  → all matches lean, `downshifted:true`, no `results_dropped`, `truncated`
  falsy; (b) scan cutoff + lean fits → `downshifted:true` **and** `truncated:true`
  preserved; the two lean-drops cases keep `results_dropped` + `truncated:true`.
- **INV-9** — a caller-requested `mode=headline_only` never triggers a downshift
  (already lean): the cap behaves exactly as pre-3543. *Test:* pure test over
  `RemoteControl::downshiftMatches` with `headlineOnly=true` (an over-cap lean set still
  reports `results_dropped`, no `downshifted`) + source-scrape of the gate.
- **INV-10** — a downshift preserves `also_at` (dedup fan-out) and emits only the
  lean shape — the dropped fat tail is never resurrected as fat rows. *Test:*
  pure test over `RemoteControl::downshiftMatches` — a fired-downshift result carries `also_at`
  where present and no `context_before`/`context_after`/full `text`.

### Cross-verb contract

- **INV-11** — `downshifted` is emitted only when `true`; it is additive
  (callers that don't read it are unaffected) and survives the dispatch pipeline
  (`compact` keeps a truthy scalar; `fields=` passes it through when requested).
  *Test:* source-scrape that every emit site (both `roadmap_query` bullet sites +

## 4. RAM / build cost

- **Memory:** the downshift materialises at most one extra copy of the
  already-in-memory row array, and only when it fires: `roadmap_query` projects a
  copy of `filtered` inside the engine; `workspace_search`'s `RemoteControl::downshiftMatches`
  takes a Qt copy-on-write handle to `matches` up front (near-free — the deep
  copy happens only when `rcApplyHeadlineOnly` mutates the lean copy on a fired
  downshift). Bounded by the result set already held; freed when the handler
  returns. No retained state, no cache, no new eviction policy. The engine
  projector is a `std::function` const-ref parameter, empty by default — no
  allocation on the default (empty) path.
- **Build:** add `<functional>` explicitly to `paginationengine.h` and
  `remotecontrol.h` for the two `std::function` projector params (neither header
  includes it today — do not rely on transitive availability). Qt6::Core-only, no
  new build target, no new external library.

## 5. Out of scope

- **`find_sources` downshift** — its rows (`path`/`score`/`role`/`evidence`)
  have no lean form and it caps by `max_results` only (no soft-cap byte path), so
  there is nothing to project. Confirmed absent by design; no follow-up.
- **`roadmap_query` bundles mode** — `buildRoadmapBundlesEnvelope`
  (called from `cmdRoadmapQuery`) bounds `bundles[]` at the soft
  cap by **dropping whole trailing bundles** — a separate truncation path from
  `pageBullets`, with the same silent-tail-loss shape § 1 decries. Not wired
  here: a bundle is a structured group (id + members + counts), not a flat row
  with a `headline_only` lean form, so downshifting it means projecting each
  bundle's *members* — a distinct design. Deferred to **ANTS-3575**; called out
  so the gap is explicit, not silent.
- **`changelog_query` downshift** — `cmdChangelogQuery` shares
  `PaginationEngine::pageBullets` (call sites in `src/remotecontrol_roadmap_query.cpp`,
  `:5805`) and has a `headline_only` mode, so the § 2.1 engine hook makes it
  eligible for a follow-up wiring — cheap *if* its `headline_only` projection is
  a reusable in-place function like `rcProjectHeadlineOnly` (to confirm at
  follow-up time; changelog rows are shaped differently from roadmap bullets, so
  the projector is not literally shared). Deferred to keep this spec's surface to
  the two ROADMAP-named verbs — tracked by **ANTS-3576**.
- **`headline_only` mode measuring the *unprojected* shape** — today
  `roadmap_query`/`workspace_search` in `headline_only` mode measure the fat row
  for the cap, then project the surviving slice, so they drop more rows than the
  lean shape needs. This spec does **not** change that (downshift only fires when
  the caller is *not* already lean); fixing the already-lean measure is a
  separate small optimisation — tracked by **ANTS-3577**.

## 8. Open questions

- **Default-on vs opt-in.** This spec makes downshift a heuristic default on the
  auto path (matches the project's token-saving-default-ON stance), with the
  opt-out being an explicit `limit` / `include_body` / already-lean `mode` — no
  new argument. If a caller is later found to *depend* on fat rows in the
  no-limit case, a `no_downshift` bool is the escape hatch; not added
  pre-emptively (§ CLAUDE.md — no scaffolding for hypothetical futures).
