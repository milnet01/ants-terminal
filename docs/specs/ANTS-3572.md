# ANTS-3572 — MCP tokens-saved status-bar chip + persisted month / YTD / all-time aggregate

**Status:** spec draft, pre cold-eyes (2026-07-18). Loop log at end (§ 10).
**Source:** ROADMAP.md ANTS-3572 (`📊 Claude Code token-usage tracking + reports`
block); user request 2026-07-18 ("a status-bar tokens-saved counter … keep track
of year-to-date totals and monthly totals as well").
**Builds on:** ANTS-1284 (`TokenUsageEngine::Tracker` + `token_usage` MCP verb —
shipped 2026-05-14; the session counter this work surfaces + persists), ANTS-1355
(wrap/latency v2), ANTS-1432 (failed-call metric), ANTS-3361 (read/search
baselines).
**Distinct from:** ANTS-1245 (design-only Tools → Token Usage dialog with
SQLite + QtCharts) which tracks Claude's *consumed* tokens + $ cost. This work
tracks tokens *saved* by the MCP surface (`baseline − actual` displacement) and
stores its period buckets in `config.json`, NOT the ANTS-1245 SQLite DB. The two
period stores are independent; § 8 records the boundary so they don't collide.

## 1. Problem

`TokenUsageEngine::Tracker` (ANTS-1284) already observes every MCP dispatch and
computes a per-session `total_saved` (the `baseline − actual-bytes` displacement,
floored at 0). But it has no face and no memory:

- **No face** — the only way to read the number is for the assistant to call the
  `token_usage` MCP verb. The user never sees "the MCP has saved me tokens" while
  they work. The saving the tooling was built for is invisible.
- **No memory** — the counter resets on every MCP `initialize` handshake
  (`claudeintegration.cpp`, ANTS-1284) and dies with the process. There is no
  "this month" / "this year" / "all-time" figure, so the cumulative payoff — the
  most motivating number — cannot exist.

The fix is two thin layers on the existing engine, no new counter:

1. A **live status-bar chip** ("↓ 1.2M saved") showing the session total, updated
   on each dispatch, matching the existing context-% bar's State-widget pattern.
2. A **persisted aggregate** — a bounded monthly bucket map + an exact all-time
   counter in `config.json` — from which *this-month*, *year-to-date*, and
   *all-time* are derived. Written only at session-reset and app-quit, never per
   call.

## 2. Surface

### 2.1 The chip (`ClaudeStatusBarController`, `src/claudestatuswidgets.{h,cpp}`)

A new **State** widget (per `docs/standards/status-bar.md`): read-only fact, not
an Action. A `QLabel` pill `m_tokensSavedChip`, constructed in the controller ctor
next to the context-% bar (`m_contextBar`) and added via
`m_statusBar->addPermanentWidget(...)` — placed immediately after `m_contextBar`
so the two "session telemetry" readouts sit together, before the model chips.

- **Face text:** `↓ <humanized session-saved> saved`, e.g. `↓ 1.2M saved`.
  Humanization (§ 2.7): `< 1000 → "820"`, `< 1e6 → "12.4K"`, `< 1e9 → "1.2M"`,
  else `"…B"` (one decimal, trailing `.0` trimmed).
- **Visibility:** shown iff `Config::claudeTokensSavedChipEnabled()` (default true)
  AND the live session-saved total `> 0`; hidden otherwise (clean bar at launch;
  the pill appears on the first MCP call that saves anything — typically
  `session_orient`). Mirrors the context bar's `hide()`-when-`<=0` behaviour.
- **Theme:** styled inside the update slot from `Themes::byName(m_currentThemeName)`
  (border `th.border`, background `th.bgSecondary`, text `th.textPrimary`),
  exactly as the context-bar update slot does — no static stylesheet, so a live
  theme switch repaints it.
- **Tooltip** (the fuller story, always present once the pill shows):
  `This session: 1.2M · This month: 12.4M · This year: 47.8M · All-time: 91.2M
  saved (since 14 May 2026)`, with a trailing `· net of <N> wasted on failed
  calls` clause **only when** the session's failed-byte waste (§ 2.2
  `sessionFailedTokens`) is non-zero. `setAccessibleName` / `setAccessibleDescription`
  kept in sync (documentation.md § 7).

Update path is **event-driven, not the `shellCwd()` refresh trio**: the chip is
integration-scoped (like the context bar), so it is driven by a signal
(§ 2.2), not `m_statusTimer` + `singleShot` + `onTabChanged`.

### 2.2 Signal + summary API (`ClaudeIntegration`, `src/claudeintegration.{h,cpp}`)

One new signal, declared next to `contextUpdated(int)`:

```cpp
signals:
    void tokensSavedUpdated(qint64 sessionSaved);   // ANTS-3572
```

Emitted at the **tail of `recordDispatch()`** — the single, unification-tested
MCP dispatch-observation hook (ANTS-1402) that already calls
`m_tokenUsage.recordCall(...)`. One `emit` line, carrying the live session total
(`m_tokenUsage.buildReport(false).totalSaved`). No second dispatch site is
touched (INV-6).

One new read accessor + a small POD, so the widget never reaches into `Config` or
the engine itself:

```cpp
struct TokenSavingsSummary {           // ANTS-3572
    qint64  session       = 0;         // live: buildReport().totalSaved
    qint64  month         = 0;         // storedMonth[curMonth] + session
    qint64  ytd           = 0;         // sum(storedMonth[curYear-*]) + session
    qint64  lifetime      = 0;         // storedLifetime + session
    qint64  sessionFailedTokens = 0;   // buildReport().totalFailedBytes / 4
    QString sinceDisplay;              // e.g. "14 May 2026" ("" until first fold)
};
TokenSavingsSummary tokenSavingsSummary() const;   // pure read, no mutation
```

`tokenSavingsSummary()` reads the persisted map/counter from `Config` and adds the
live session total — it never writes. Because every displayed period is
`stored + session`, and a fold (§ 2.4) moves that exact `session` amount into
`stored`, the numbers are byte-identical across the fold boundary (INV-1).

### 2.3 Persistence schema (`config.json`, via `src/config.{h,cpp}`)

Four keys under the existing `claude.*` namespace (world-readable config; no
secrets — the file's existing 0600 mode is unchanged):

| Key | Type | Meaning |
|---|---|---|
| `claude.tokens_saved_monthly` | object `{"YYYY-MM": number}` | per-month gross saved buckets; pruned to the most-recent 24 keys |
| `claude.tokens_saved_lifetime` | number | exact all-time gross saved; never pruned |
| `claude.tokens_saved_since` | string (ISO date) | date of the first fold; sets the tooltip's "since …" and is written once |
| `claude.tokens_saved_chip_enabled` | bool (default `true`) | show/hide the chip; does NOT gate the ledger (INV-11) |

Config accessor pairs (matching the `config.cpp` `.toBool(true)` default idiom):
`claudeTokensSavedMonthly()`/`setClaudeTokensSavedMonthly(QJsonObject)`,
`claudeTokensSavedLifetime()`/`set…(qint64)`,
`claudeTokensSavedSince()`/`set…(QString)`,
`claudeTokensSavedChipEnabled()`/`set…(bool)`. Values are stored as JSON numbers
(exact integers to 2^53 — INV-9).

### 2.4 Fold logic (`ClaudeIntegration::foldAndResetTokenUsage()`)

Replaces every existing bare `m_tokenUsage.reset()` call with a fold-then-reset:

```cpp
void ClaudeIntegration::foldAndResetTokenUsage() {          // ANTS-3572
    const qint64 s = m_tokenUsage.buildReport(false).totalSaved;
    if (s > 0) {
        const QString month = QDate::currentDate().toString("yyyy-MM"); // local
        QJsonObject m = Config::instance().claudeTokensSavedMonthly();
        m = TokenUsageEngine::foldMonthlyBucket(m, month, s, /*keepMonths=*/24);
        Config::instance().setClaudeTokensSavedMonthly(m);
        Config::instance().setClaudeTokensSavedLifetime(
            Config::instance().claudeTokensSavedLifetime() + s);
        if (Config::instance().claudeTokensSavedSince().isEmpty())
            Config::instance().setClaudeTokensSavedSince(
                QDate::currentDate().toString(Qt::ISODate));
        Config::instance().save();       // one write, fold-time only (INV-7)
    }
    m_tokenUsage.reset();                // clears live counter (no double-count)
}
```

Call sites (each fold is immediately followed by the internal `reset()`, so a live
amount is folded exactly once — INV-2):

1. **MCP `initialize` handler** — replace the ANTS-1284 `m_tokenUsage.reset()`
   with `foldAndResetTokenUsage()`. Folds the *previous* MCP session (same
   process, Claude Code restart) before clearing.
2. **`token_usage` verb, `reset:true`** — the handler snapshots the report first
   (unchanged INV-9 read-before-clear), then routes its clear through
   `foldAndResetTokenUsage()`.
3. **App quit** — `QCoreApplication::aboutToQuit` (or the existing MainWindow
   shutdown path) calls `foldAndResetTokenUsage()` once, capturing the final live
   session (the case initialize can't cover — a new process starts empty).

The tracker's `reset()` also re-stamps `sinceUnixMs` (existing ANTS-1284
behaviour), which is the desired new-session boundary at sites 1–2 and harmless at
quit.

### 2.5 `token_usage` MCP verb additions (`RemoteControl::cmdTokenUsage`)

Four new top-level fields, computed at call time from `ci->tokenSavingsSummary()`
(so they equal `stored + session`, matching the chip):

```json
{
  "…": "existing ANTS-1284/1355/1432 fields unchanged",
  "month_saved":    12400000,
  "ytd_saved":      47800000,
  "lifetime_saved": 91200000,
  "monthly": [ { "month": "2026-07", "saved": 12400000 },
               { "month": "2026-06", "saved":  9100000 } ]
}
```

`monthly[]` is the persisted bucket map (recent-first), capped at the retained 24.
`additionalProperties:false` on the envelope still holds — the four keys are added
to the declared schema (INV-10). On `reset:true` the aggregate fields are computed
BEFORE the fold (so they already include the session about to be folded); the fold
then makes the stored numbers match, so a follow-up call returns the same
lifetime.

### 2.6 Config flag surfacing

`claude.tokens_saved_chip_enabled` defaults true (the project's "token-saving
knobs ship ON, keep an off switch" rule). Exposed in Settings → General next to
the other `claude.*` toggles; catalogued in `docs/standards/mcp-config-keys.md`.

### 2.7 Pure helpers (`TokenUsageEngine`, `src/tokenusageengine.{h,cpp}`)

The fold/prune/sum math lives as pure static functions in the engine (Qt6::Core
only, already unit-tested) so it is testable without a MainWindow — the widget/
Config/verb wiring is source-grep tested, the math is functionally tested:

```cpp
namespace TokenUsageEngine {
// Add `add` to monthly[monthKey], then retain only the `keepMonths`
// lexicographically-greatest keys ("YYYY-MM" sorts chronologically).
QJsonObject foldMonthlyBucket(QJsonObject monthly, const QString &monthKey,
                              qint64 add, int keepMonths);
// Sum of buckets whose key starts with `yearPrefix` (e.g. "2026").
qint64      sumYear(const QJsonObject &monthly, const QString &yearPrefix);
}
```

Humanization is a UI concern → a file-local static in `claudestatuswidgets.cpp`.

## 3. Invariants

- **INV-1 — No jump across a fold.** Every displayed period is
  `stored + liveSession` (§ 2.2). A fold (§ 2.4) adds exactly `liveSession` to
  `stored` and then clears the live counter, so immediately after the fold the
  display is `(stored+liveSession) + 0` — byte-identical to the pre-fold
  `stored + liveSession`. The month/YTD/all-time numbers never jump or flicker at
  a session boundary. *Test: fold-parity unit test.*

- **INV-2 — Fold-once, no double-count.** `foldAndResetTokenUsage()` clears the
  live counter (`reset()`) in the same call that folds it. The three call sites
  (initialize, verb `reset:true`, quit) each fold a live amount that has
  accumulated since the last clear; none folds twice without an intervening
  accumulation. A live amount contributes to `stored` exactly once. *Test:
  source-grep asserts all reset sites route through the helper; unit test folds
  twice with no accumulation between and asserts the second is a no-op.*

- **INV-3 — Bucket key is local-month at fold time.** The bucket is
  `QDate::currentDate().toString("yyyy-MM")` in local time, evaluated when the
  fold runs. A session spanning midnight into a new month attributes its whole
  total to the month it *ended* (folded) in — a deliberate approximation; the
  engine does not timestamp individual calls. *Documented; no per-call bucketing.*

- **INV-4 — Bounded map, exact all-time.** `foldMonthlyBucket` retains only the 24
  lexicographically-greatest keys after each fold; older buckets are dropped.
  `claude.tokens_saved_lifetime` is a separate counter that is never pruned, so
  all-time stays exact even after buckets age out. YTD sums only current-year keys,
  which (≤ 12 months) always fall inside the retained 24-month window, so pruning
  never truncates YTD. *Test: fold 30 distinct months → map size 24, lifetime =
  sum of all 30; YTD across a year boundary.*

- **INV-5 — Chip visibility.** The pill is shown iff
  `claudeTokensSavedChipEnabled()` (default true) AND `liveSession > 0`; hidden
  otherwise. Theme-styled from the active theme in the update slot. *Test:
  source-grep the enabled-guard + `>0` guard + `hide()` path in the slot.*

- **INV-6 — Single emission hook.** `tokensSavedUpdated` is emitted ONLY from
  `recordDispatch()`, preserving the ANTS-1402 single-observation-site contract
  (the same hook that owns the sole `recordCall`). *Test: source-grep asserts
  exactly one `emit tokensSavedUpdated` and that it sits in `recordDispatch`.*

- **INV-7 — Write cadence.** `Config::save()` for these keys happens only inside
  `foldAndResetTokenUsage()` (initialize / verb-reset / quit) — never per MCP
  call. A busy session with thousands of dispatches performs at most a handful of
  config writes. *Test: source-grep asserts no `Config::save`/`setClaudeTokensSaved*`
  inside `recordDispatch`.*

- **INV-8 — RAM / footprint bound.** The monthly map is ≤ 24 entries
  (`"YYYY-MM"` key ~7 chars + a number) held inside the already-resident `Config`
  object; plus one `qint64` lifetime + one date string. The `TokenUsageEngine`
  itself is unchanged (~7 KiB per ANTS-1284 INV-8). No new cache, thread, file
  watcher, or timer. *Documented; no RSS test (flaky in CI).*

- **INV-9 — Storage precision.** Buckets and lifetime are stored as JSON numbers,
  exact-integer to 2^53 (~9.0e15 tokens). At 1 M saved/day that ceiling is ~24
  billion years away, so double storage never loses precision for any real total.
  *Documented.*

- **INV-10 — Verb schema closed.** `month_saved`, `ytd_saved`, `lifetime_saved`,
  and `monthly[]` (with `additionalProperties:false` on each `monthly[i]`) are
  added to the declared `token_usage` schema; the envelope keeps
  `additionalProperties:false`. *Test: source-grep the four keys in the schema
  block + the handler.*

- **INV-11 — Flag gates the chip, not the ledger.** Turning
  `tokens_saved_chip_enabled` off hides the widget but folds still run and the
  aggregate keeps accruing, so re-enabling later shows the true accumulated total
  (no silent gap). *Test: source-grep asserts the enabled-check is in the widget
  update slot, not around `foldAndResetTokenUsage`.*

- **INV-12 — Aggregate is gross saved; failed-waste is session-only.** The
  monthly/YTD/all-time buckets accumulate `buildReport().totalSaved` (gross,
  floored at 0). The failed-call waste (`totalFailedBytes/4`) is surfaced only in
  the live tooltip's "net of …" clause, never persisted — so the stored periods
  are a single consistent gross-saved series. *Documented.*

## 4. Failure modes

- **Corrupt/missing `claude.tokens_saved_monthly`** (hand-edited to a non-object,
  or absent on first run) → `claudeTokensSavedMonthly()` returns an empty
  `QJsonObject`; fold starts a fresh map. No crash, no refusal.
- **A bucket value that is not a number** (hand-edited) → treated as 0 in `sumYear`
  / fold (`QJsonValue::toDouble(0)`), and overwritten on the next fold for that
  month. Self-heals.
- **`tokens_saved_lifetime` < sum of retained buckets** (e.g. buckets hand-edited
  up) → lifetime is authoritative for all-time; the tooltip shows lifetime, not
  the bucket sum, so no contradiction is displayed.
- **Clock moved backwards / timezone change** → a fold may land in an earlier
  `YYYY-MM` key than a prior fold; it simply adds into that bucket. Monotonic
  lifetime is unaffected. Acceptable for a motivational estimate.
- **Crash / OOM-kill before a fold** (earlyoom on this host) → the in-flight
  session's savings are lost from the aggregate (never folded). Accepted: this is
  an estimate, not accounting; § 7 records the rejected per-minute-flush
  alternative.
- **Chip enabled but `tokenSavingsSummary()` reads a stale `Config`** — not
  possible: the summary reads the live in-memory `Config` object, which fold
  updates before `save()`.

## 6. Performance / RAM budget

- **Per MCP call:** one extra `buildReport(false)` (O(distinct tools) ~≤ 80
  entries + a sort) to produce the signal payload, plus one signal emission and
  one label repaint. `buildReport` is already the verb's cost; here it runs per
  dispatch — still ~10 µs, dominated by nothing the user can perceive. No disk I/O
  on this path (INV-7).
- **Per fold (rare):** one 24-key prune + one `Config::save()` (the whole config
  is already rewritten atomically on any settings change; these keys add < 1 KiB).
- **RAM:** ≤ 24 map entries + 2 scalars inside the resident `Config` (INV-8).
- **No new caches, threads, watchers, or timers.**

## 7. Out of scope

- **Per-minute / periodic flush** to bound crash loss. Rejected for v1: adds a
  timer + write-amplification for a motivational estimate; the fold-on-quit +
  fold-on-initialize pair captures every clean session. Revisit only if crash-loss
  proves annoying in practice.
- **Per-project / per-cwd breakdown.** The aggregate is global to the process, as
  the ANTS-1284 session counter already is. A project-keyed view is a later item.
- **Cost ($) estimate / graphs / CSV export.** That is ANTS-1245's surface
  (consumed tokens); this chip is saved-tokens only. No QtCharts dependency.
- **Weekly / daily buckets.** The user asked for monthly + YTD + all-time; day/
  week granularity would need per-call timestamping (out of scope) — the engine
  only knows session totals at fold time.
- **Migrating the aggregate into ANTS-1245's SQLite store** if that ships. Noted
  as the integration seam (§ 8); not built here.
- **Net-of-failure persistence.** Only gross saved is stored (INV-12).

## 8. Migration / integration boundary

- New config keys only; no existing key changes; no schema migration (absent keys
  default cleanly — § 4). First fold seeds `tokens_saved_since`.
- `ClaudeIntegration` gains one signal, one POD, one accessor, one fold method;
  the sole behavioural change to existing paths is routing the two `reset()` sites
  through `foldAndResetTokenUsage()` (semantics preserved — reset still clears +
  re-stamps `since`).
- **ANTS-1245 boundary:** if the consumed-tokens dialog later ships with SQLite,
  it owns *consumed* tokens; this feature owns *saved* tokens in `config.json`.
  They must not share a store. A future unification (one dialog with both series)
  is a design item, not a silent merge.
