# ANTS-1625 — `last_audit_summary` foreign-format picker preference

**Status:** implementing
**Kind:** enhancement
**Source:** cross-session-report-2026-05-18 (RetroArch Bundle 69 — narrow
single-file cppcheck-XML rerun misread as project-wide clean)
**Pull:** 25 (MCP test-audit framework + last_audit_summary picker fold-in)
**Composes with:** [[ANTS-1576]] — scope classifier already lands the
*warning* shape; this spec lands the *re-pick* atop. Spec § 5 ("preferring
broader file on recency tie") explicitly deferred to a follow-up — this is
that follow-up.

## 1. Problem

`cmdLastAuditSummary`'s foreign-format picker at `remotecontrol.cpp:4429-
4458` walks the cache dir with `QDir::entryList(glob, QDir::Files,
QDir::Name | QDir::Reversed)` and picks the first match. For `audit-*.sarif`
files written by `audit_run` this is correct because the ANTS-1555 naming
convention (`audit-<iso-utc>-<sha>.sarif`) sorts lexicographically by
timestamp. For **foreign-format** files (`cppcheck-*.xml`,
`clang-tidy-*.txt`, `semgrep-*.json`) the user names them however they
like; `cppcheck-b68-ozone-postfix.xml` outranks `cppcheck-broad-2026-05-
17.xml` in lex order even though the latter is the actually-broad project
sweep.

RetroArch Bundle 69 hit this exact case:

- `.audit_cache/cppcheck-b68-ozone-postfix.xml` — single-file rerun, 0
  warnings, 0 errors, 68 notes. Picker chose it (lex-max).
- 25 other broader `cppcheck-*.xml` siblings in the same dir, the most
  recent of which had 56 errors + 105 warnings (the real project state).

Caller read `counts: {error: 0, warning: 0, note: 68}` and assumed the
audit was clean. The follow-up was a manual broad cppcheck run that
surfaced the real next-bundle list.

[[ANTS-1576]] already lands a `scope:` tag + `narrow_run_warning` on the
envelope. That tells the caller "this looks narrow" but doesn't re-pick.
The Bundle-69 report explicitly asks for the re-pick: *"Prefer broadest-
scope cache file when multiple exist."*

## 2. Fix

Add a `pickForeignReport` helper next to the existing
`pickLatest` lambda. The SARIF picker keeps lex-max behaviour (audit-
cache naming already sorts correctly); the foreign-format paths route
through the new helper.

### 2.1 Helper signature

```c++
struct ForeignPick {
    QString name;       // basename of the chosen file (empty when none)
    QString pickBasis;  // "sole" | "newest" | "broadest_in_recency_window"
};

ForeignPick pickForeignReport(const QDir &cacheDir, const QString &glob);
```

### 2.2 Algorithm

1. List files in `cacheDir` matching `glob` via `QDir::entryList`.
2. If empty: return `{"", ""}`.
3. If one entry: return `{name, "sole"}`.
4. Otherwise:
   - Build a `Cand { name, mtimeMs, size, narrow }` row for each entry,
     where `narrow == true` iff the lowercase basename contains one of
     `-postfix`, `-single`, `-narrow` (mirrors ANTS-1576's narrow-hint
     suffix set).
   - Compute `newestMs = max(mtimeMs)` across all candidates.
   - Define the recency window as `[newestMs - 24h, newestMs]`.
   - Among files inside the window: pick the **largest non-narrow** if
     any exists; else the **largest narrow** (tiebreak by lex-max name
     when sizes equal). The size tiebreaker is bounded by the SARIF/XML
     payloads being proportional to finding count — broader runs are
     larger.
   - If chosen entry's mtime == `newestMs` AND the chosen entry is the
     unique newest by lex-name AND no broader candidate was skipped:
     `pickBasis = "newest"`. Else `pickBasis = "broadest_in_recency_window"`.
5. Return `{name, pickBasis}`.

### 2.3 Envelope wiring

`buildLasEnvelope` is unchanged — it doesn't see the picker. The
envelope gains `pick_basis` at the `cmdLastAuditSummary` site, alongside
the existing `scope` / `narrow_run_*` fields:

```c++
env["pick_basis"] = pickBasis;  // always emitted
```

For SARIF the picker stays as-is; `pickBasis = "newest"` (the audit-cache
naming convention guarantees this).

The 24-hour window matches the typical multi-bundle workday: a narrow
rerun two hours after a broad sweep should not displace the broad sweep
as the "latest summary". A narrow rerun a week later should — the broad
sweep is stale.

### 2.4 Why `pick_basis` is always emitted

The caller's mental model needs a single field that names *how* the
file was chosen. Three values cover the cases:

- `"sole"` — only one matching file in `.audit_cache/`. Caller treats
  the summary at face value.
- `"newest"` — multiple files; the newest also happens to be the best
  candidate (no narrower-but-newer file displaced a broader one).
- `"broadest_in_recency_window"` — multiple files; the picker chose a
  non-newest file because a narrower file (smaller, narrow-name suffix)
  was lex-max but the broader candidate sits within the 24-hour window.

A caller seeing `"broadest_in_recency_window"` knows the choice was
deliberately not lex-max; they can re-issue against an explicit path
if they actually wanted the most-recent narrow rerun.

### 2.5 Composes with ANTS-1576 scope classifier

The scope classifier (`scope: "broad" | "narrow" | "single_file"`) runs
**after** the picker on the chosen file's `topFindings`. The two
surfaces are independent:

- Picker prevents the obvious wrong file from being chosen.
- Classifier warns when the chosen file still looks narrow (e.g. a
  project where all cached audits happen to be single-file reruns).

A caller seeing `pick_basis: "broadest_in_recency_window"` **AND**
`scope: "broad"` has high confidence the summary is project-wide. A
caller seeing `pick_basis: "sole"` **AND** `scope: "narrow"` has the
honest answer that this project only has a narrow audit cached.

## 5. Out of scope (deferred)

- **Per-tool scope re-pick.** A SARIF that bundles two tools (one
  broad, one narrow) still gets a single envelope. The SARIF picker
  doesn't try to identify intra-tool narrowness — that's the scope
  classifier's job. Acceptable for v1.
- **Manifest-driven picks.** [[ANTS-1555]] writes an audit-cache
  manifest at `.audit_cache/index.json` (v1). The manifest only tracks
  SARIF history today, not foreign formats. A v2 manifest with a
  per-file `scope_hint` would let the picker route on metadata rather
  than file-size heuristic; punt until a cross-session report shows
  the heuristic mis-picking.
- **User-configurable recency window.** 24h is hard-coded. A project
  with sub-hourly audits + project-wide weekly sweeps would want a
  longer window; add a `recency_window_hours` arg only when a real
  caller asks.
- **CLI `last_audit_summary --reason` flag.** The MCP envelope's
  `pick_basis` is the primary surface. The CLI doesn't currently
  surface a comparable diagnostic; out-of-scope here.

## 6. RAM / build budget

- Helper: bounded by `QDir::entryList` returning the file count in
  `.audit_cache/`. Typical project: ≤ 30 entries. Per-entry overhead:
  one `QFileInfo` for mtime + size (already paid for the cache-key
  computation at line 4475). Net new allocation: a `QList<Cand>` of
  the same length. Bounded.
- No new on-disk state. No new fields on `AuditSummary`. No new
  cache slots — the existing `m_auditSummaryPath` / `Mtime` cache key
  already invalidates correctly when the picker chooses a different
  file (the path differs).
- Envelope size: + ~32 bytes for the `pick_basis` field. Bounded.
