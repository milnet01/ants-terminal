# ANTS-1351 — `audit_run` MCP verb: server-side audit runner

**Status:** implemented; cold-eyes loops 1 + 2 + 3 folded (2026-05-17), loop 4 folded (2026-07-24, ANTS-3605 headless in-process lanes). Loop log § 10.
**Kind:** implement
**Source:** ROADMAP.md ANTS-1351, line 5220.
**Blocked by:** none. `AuditEngine` (Qt6::Core-only) shipped in ANTS-1119.
**Pairs with:** `last_audit_summary`. ANTS-1397 follows this spec's
conventions (envelope cap, contract classification, lock pattern,
worker model, namespace).
**Distinct from:** ANTS-1280 (end-to-end orchestrator with subagent
dispatch). ANTS-1351 is the single-call tool-wrapper.

## 1. Problem

`/audit` skill is ~11.5 KiB markdown + N parallel Bash tool
invocations. Each tool's raw output enters parent context for
filter/dedup/rank/triage. 2026-05-14 sweep measurement:

- ~2.9 K input tokens for the skill markdown (loaded once per
  session, not per sweep — clarified loop 3 H1).
- **~80 K input tokens for tool raw output** — measurement source:
  `token_usage` ledger row tagged `audit_v0_2026-05-14` (see
  ANTS-1432). The 80 K figure is **±20 % pending re-measurement
  during impl** — call it an estimate.
- ~5 K output tokens for shell orchestration.

`audit_run` returns a structured envelope + SARIF path instead of N
raw outputs. **Net per-sweep saving: ~60 K tokens** (80 K tool
output − 20 K envelope cap − 60 B wrap; first sweep additionally
saves the 2.9 K skill load).

## 2. Surface

### 2.1 Request shape

```json
{
  "caller_cwd": "/abs/path/to/project",
  "tools":      ["cppcheck", "ruff", "bandit"],
  "scope":      "auto | full | files | since-tag:<tag> | branch-diff | since-last-run",
  "cap_per_tool_seconds": 30,
  "suppressions": "auto | none | path:<file>",
  "formats":    ["sarif"],
  "top_findings_count": 0
}
```

| Field | Required | Default | Notes |
|---|---|---|---|
| `caller_cwd` | yes | — | Canonicalised via `PathValidation::validatePath` (ANTS-1295). ANTS-1404 `Required` contract. |
| `tools` | no | `auto` | Subset of {cppcheck, clazy, clang-tidy, ruff, bandit, semgrep, gitleaks, trivy, shellcheck, mypy} (`kKnownTools`). Unknown → `bad_tool`. Auto-detect (`kAutoDetectTools`) is this set minus `mypy` (deps-less mypy is noise — ANTS-3418). |
| `scope` | no | `auto` | `auto` = full-tree minus exclusions; `full` = deterministic whole-tree sweep (git-independent, ANTS-2015); `files` = `git merge-base HEAD origin/<default-branch>` (falls back HEAD~1 then full); `since-tag:<t>` = `git diff --name-only <t>..HEAD` (sanitised per INV-15); `branch-diff` = `git diff --name-only main..HEAD`; `since-last-run` = changed files since the prior run's anchor commit (ANTS-1870 findings delta). |
| `cap_per_tool_seconds` | no | `30` | Per-tool wall-clock cap, [5, 300] (ANTS-3585). Out of range → `bad_args` (INV-16). |
| `suppressions` | no | `auto` | `auto` = load `.audit_suppress` + `.audit_allowlist.json`; `none` = ignore; `path:<file>` = named file (validated). |
| `formats` | no | `["sarif"]` | Subset of `["sarif", "html"]`. Default drops HTML (~50 KiB disk write skipped — loop 3 opt L12). |
| `top_findings_count` | no | `0` | If > 0, inline first N full findings into envelope (additional `top_findings[]` array, bounded by INV-13's 18 KiB cap). Caller hint: avoids the orchestrator-Reads-SARIF token collapse (loop 3 token H4). Out of [0, 100] → `bad_args` (INV-16). |

### 2.2 Response shape

```json
{
  "ok": true,
  "by_tool": {
    "cppcheck": {
      "status": "ok | timed_out | not_runnable | crashed",
      "elapsed_ms": 1842,
      "raw_count": 27,
      "after_filter_count": 12,
      "samples": [ { "file": "src/foo.cpp", "line": 142, "rule": "uninitvar",
                     "severity": "HIGH", "message": "<≤ 256 B excerpt>" } ]
    }
  },
  "total_raw": 184,
  "total_actionable": 31,
  "noise_rate_pct": 83,
  "sarif_path": "/tmp/audit-<sid>-<seq>.sarif",
  "html_path":  "/tmp/audit-<sid>-<seq>.html",
  "tools_skipped": [ { "tool": "clazy", "reason": "compile_commands.json absent" } ],
  "elapsed_total_ms": 18450,
  "samples_truncated": false,
  "top_findings": []
}
```

| Field | Notes |
|---|---|
| `by_tool[t].status` | `ok` (zero or more findings); `timed_out`; `not_runnable`; `crashed` (stderr in `samples[0].message`). |
| `by_tool[t].samples[]` | First 10 *after-filter* findings. Each `message` ≤ 256 B (INV-13). |
| `noise_rate_pct` | `100 - round(100 * total_actionable / total_raw)`; `0` when `total_raw == 0`. |
| `sarif_path` | Always present if `"sarif" ∈ formats`. Per-call unique (INV-12). |
| `html_path` | Present iff `"html" ∈ formats`. |
| `tools_skipped[]` | JSON objects `{tool, reason}` (engine type: `QVector<ToolSkip>` with explicit field names — not `QPair`, per loop 3 consistency). |
| `samples_truncated` | `true` if any sample hit 256 B cap OR `samples[]` cascade trimmed (INV-13). Distinct semantics from ANTS-1397's pagination `truncated`. |
| `top_findings[]` | Present iff `top_findings_count > 0`. Up to N full SARIF-shaped findings (file, line, ruleId, level, message, regions, snippet) bounded by INV-13. |

### 2.3 Engine API

New `auditrunner.{h,cpp}` in **`ants_audit_lib`** (CMakeLists.txt:315)
— alongside `auditengine.cpp`. Pulls QDialog into the link closure
via the sibling `auditdialog.cpp`; `auditrunner.cpp` doesn't
`#include` any Widgets header so runtime cost is link-only. Future
ADR may split the lib (loop 3 opt M10).

Namespace **`AuditRunner`** (PascalCase, matches `AuditEngine`).

```cpp
namespace AuditRunner {
struct ToolSkip { QString tool; QString reason; };
struct RunRequest {
    QString projectRoot;          // canonical absolute (validated)
    QStringList tools;            // empty == auto-detect
    QString scope;
    int capPerToolSeconds = 30;
    QString suppressionsMode;
    QStringList formats;          // {"sarif"} default
    int topFindingsCount = 0;
};
struct ToolResult {
    QString tool;
    QString status;
    qint64 elapsedMs = 0;
    int rawCount = 0;
    int afterFilterCount = 0;
    QJsonArray samples;
};
struct RunResult {
    bool ok = true;
    QString error;
    QString code;
    QHash<QString, ToolResult> byTool;
    int totalRaw = 0;
    int totalActionable = 0;
    int noiseRatePct = 0;
    QString sarifPath;
    QString htmlPath;
    QVector<ToolSkip> toolsSkipped;
    qint64 elapsedTotalMs = 0;
    bool samplesTruncated = false;
    QJsonArray topFindings;
};
RunResult runAudit(const RunRequest &req);
}  // namespace AuditRunner
```

### 2.4 In-flight gate (inline, not a class)

Per loop 3 opt H3 + M11: with only two consumers (this spec +
ANTS-1397), the abstraction is premature. Both consumers add two
members on `ClaudeIntegration`:

```cpp
// claudeintegration.h additions
QHash<QPair<QString, QString>, qint64> m_verbInFlight;  // {verb, root} -> start ms
QMutex m_verbInFlightMutex;
```

Call-site pattern (4 lines):
```cpp
{
    QMutexLocker lk(&m_verbInFlightMutex);
    const auto key = qMakePair(verb, canonicalProjectRoot);
    if (m_verbInFlight.contains(key))
        return {ok:false, code:"already_running", running_since_ms: now - m_verbInFlight[key]};
    m_verbInFlight.insert(key, now);
}
const auto guard = qScopeGuard([&]{
    QMutexLocker lk(&m_verbInFlightMutex);
    m_verbInFlight.remove(qMakePair(verb, canonicalProjectRoot));
});
```

**Orphan recovery (INV-11):** the guard fires on normal AND
exceptional return; worker death via SIGKILL leaves the slot held.
Stale-slot reaper: a one-shot QTimer per slot (set to the
aggregate cap + 30 s) auto-releases if the guard didn't fire. Logs
DBGLOG warning. Prevents the per-project DoS surfaced by loop 3
security H-B.

### 2.5 QProcess + worker thread model

INV-9 places `runAudit` on a worker. Implementation:

- Worker thread runs a local `QEventLoop`.
- Each tool gets its own `QProcess` (heap-allocated, parented to a
  scope-guard struct) on the worker thread.
- Per-tool wall-clock cap enforced via QTimer::singleShot inside the
  same event loop. Two-phase: `terminate()` at cap; `kill()` 2 s
  later if `state() != NotRunning`. Captures the heap pointer, not
  a stack ref (loop 3 consistency).
- 9 tools multiplex I/O via the one event loop; `loop.exec()` exits
  when all done OR aggregate cap fires.

## 3. Invariants

- **INV-1 / single MCP call, blocking, ≤ 15 min.** Aggregate cap =
  `min(tools.count × cap_per_tool_seconds × 1.5, 900 s)` (ANTS-3585
  raised the ceiling 240 s → 900 s so a high opt-in per-tool cap is not
  immediately re-clamped by the aggregate). Partial results on
  aggregate-cap fire (INV-8).
- **INV-2 / every path validated via `PathValidation::validatePath`.**
  `caller_cwd` validated; canonical becomes `projectRoot`.
  `suppressions:"path:<file>"` validated. `compile_commands.json`
  existence-checked at projectRoot only (loop 3 opt M8 — no
  symlink-follow, no `-I`-arg validation; clazy fails at link time
  if symlinked-out → reported as `not_runnable`).
- **INV-3 / Required contract, refusal BEFORE cache lookup.**
  ANTS-1404. `audit_run` not in the idempotent-read allowlist;
  refusal upstream of `m_idempotentReadCache`.
- **INV-4 / tool isolation.** Tool A crash sets
  `by_tool["A"].status = "crashed"`, stderr excerpt in
  `samples[0].message`, sweep continues. Stderr unredacted under
  same-uid trust (see § 8 decision).
- **INV-5 / per-tool cap is hard.** SIGTERM at cap; SIGKILL 2 s
  later if alive (Linux-only per § 8). Implementation pattern in
  § 2.5. POSIX precedent: `ptyhandler.cpp:29,61,72`.
- **INV-6 / exclusion list + regex-cache.** Exclusion list lives
  in `AuditRunner::kExclusions` (hardcoded — loop 3 opt M5; the
  list is *de facto* static and shipping a JSON sidecar adds two
  writers for no win). Skill markdown documents the same list
  inline. **ANTS-3394 — the set is wired into each find-everything
  tool's whole-tree (non-scoped) invocation via
  `toolExclusionArgs(tool)`: ruff `--extend-exclude`, bandit `-x`,
  semgrep `--exclude` (repeated), trivy `--skip-dirs **/<dir>`
  (repeated), mypy `--exclude <regex>`. A `scope:"full"` sweep no
  longer drowns the real findings in `dist/` / `node_modules/` /
  scraped-media noise. Scoped invocations (an explicit `paths` /
  changed-file set) deliberately omit the exclusions — those files
  were chosen on purpose. cppcheck/clazy/clang-tidy run against
  `src/` or the compile DB (never build output) and gitleaks is
  filtered via its generated `--config` (ANTS-2016), so none take
  exclusion args. ruff + semgrep additionally honour `.gitignore`
  by default; the explicit set covers the gitignore-unaware tools
  (bandit, mypy, trivy).** Project's `.audit_allowlist.json`
  augments; regexes **hardened via `AuditEngine::hardenUserRegex`
  and rejected via `isCatastrophicRegex`** (rejected entries DBGLOG
  + skipped). Compiled `QRegularExpression` objects **cached per
  pattern hash + mtime keyed by allowlist file** (loop 3 perf M6 +
  opt M6). Cache invalidates on stat change.
- **INV-7 / suppressions applied AFTER filter, BEFORE sample
  selection.** Pipeline order matches `auditdialog`'s
  (CLAUDE.md `auditdialog` block). `.audit_suppress` *marks*
  findings (SARIF `result.suppressions[]` § 3.34); samples emit
  only the unsuppressed, post-dedup, post-cap set.
- **INV-8 / SARIF + HTML emit even on partial sweep.** SARIF
  written if `"sarif" ∈ formats`; HTML iff `"html" ∈ formats`
  (formats default `["sarif"]` only — loop 3 opt L12). Failed
  tools appear as SARIF `tool.driver` entries with `notifications[]`.
- **INV-9 / dedicated `m_auditPool` worker, separate from build pool.**
  Spec name: `m_auditPool` (pinned per loop 3 consistency).
  `runAudit` dispatched via this pool's worker that owns a local
  `QEventLoop` (§ 2.5). MCP dispatcher returns
  `{ok:false, code:"server_busy"}` if all slots taken; envelope
  carries `retry_after_ms: 5000` hint (loop 3 token M5). **Pool size:
  `max(2, nproc/8)`** (loop 3 perf H2 — was `max(1, nproc/8)`; bumped
  so the common `/audit && /test-audit` workflow doesn't serialise).
  On nproc=8: 2 slots. **Cross-pool isolation:** audit pool is
  SEPARATE from build/verify pool; build OOM (~3 GiB) + audit
  (~1.7 GiB peak tools, INV-10) can sum to ~5 GiB peak — documented
  in § 6.
- **INV-10 / sandbox: same uid, scrubbed env, absolute-path tools.**
  Tools run as Ants user; no setuid; no `sudo`. Per QProcess:
  stdin closed; signal mask reset; umask preserved. Env
  **allowlist** `{PATH, HOME, USER, LANG, LC_*, TERM, TMPDIR,
  XDG_CACHE_HOME}`; **blocklist** `{SUDO_ASKPASS, SSH_AUTH_SOCK,
  AWS_*, GH_TOKEN, OPENAI_API_KEY, ANTHROPIC_API_KEY}`. **Tools
  resolved via `QStandardPaths::findExecutable` with 60 s TTL cache
  keyed by tool name** (loop 3 opt M7 — was per-call; cache
  invalidates on TTL or PATH change). PATH-tampering window: ≤ 60 s.
- **INV-11 / single in-flight per canonical projectRoot.** Inline
  gate per § 2.4. Key: `("audit_run", canonicalProjectRoot)`.
  Stale-slot reaper at aggregate-cap + 30 s prevents orphan
  permanent DoS (loop 3 security H-B).
- **INV-12 / SARIF path per-call unique.** `/tmp/audit-<sid>-<seq>.
  sarif` where `<sid>` = `PID-startTimeEpoch`, `<seq>` = monotonic
  per-process counter. Cleanup hooked to `MainWindow::aboutToQuit`.
- **INV-13 / response envelope hard-capped.** Each `samples[*].
  message` and each `top_findings[*].message` capped 256 B. Cap
  budget: 18 KiB soft, 20 KiB hard. Cascade trim *bottom-up per
  tool* on `samples[]`: 10 → 5 → 3. `top_findings[]` trimmed last
  (caller asked for it explicitly). `samples_truncated:true`
  whenever any cap fires. Implementation: ~30 LOC inline using
  `QJsonDocument(env).toJson(QJsonDocument::Compact).size()`. SARIF
  capped at `kSarifFindingsMax = 10000` (loop 3 perf L10) — overflow
  reported via SARIF `notifications[]`.
- **INV-14 / explicit-tool refusal.** `tools:[X]` + X not runnable
  → `no_tools_runnable` (caller intent honoured). ANTS-3605 — an
  auto-detect sweep (empty `tools`) with no external tool on PATH is
  **not** refused: it proceeds so the in-process drift lanes (INV-21),
  which need no external binary, still run — matching the GUI Audit
  dialog, which always runs them. The refusal now fires only for an
  explicit named-but-unresolvable tool.
- **INV-15 / `scope:"since-tag:<X>"` argv-safe.** Tag must match
  `^[A-Za-z0-9._/+-]{1,128}$` AND not start with `-`. Rejected →
  `bad_scope`. Passed as a single QStringList argv element.
- **INV-16 / `cap_per_tool_seconds` range-check.** Out of [5, 300]
  or non-int → `bad_args` (ANTS-3585 raised the ceiling 60 → 300; the
  default stays 30 s). (Was implicit in § 2.1 only — pinned per loop 3
  consistency.)
- **INV-17 / JSON-tool output parsed as JSON only; aborts routed
  to `incomplete_tools[]`.** (ANTS-3395.) The JSON-emitting tools
  (`ruff`, `bandit`, `semgrep`, `gitleaks`, `trivy`, `shellcheck`)
  carry a single JSON document, sometimes wrapped in progress-bar /
  log noise on the merged stdout+stderr stream. `parseToolOutput`
  extracts the JSON span (first `{`/`[` → matching last `}`/`]`) and
  parses **only** that; it **never** falls through to the line-based
  parser for these tools — that fallback would mint a phantom finding
  from bandit's Rich progress bar or a trivy timestamped log line.
  The plain-text tools (`cppcheck`, `clazy`, `clang-tidy`, `mypy`)
  stay line-based. A JSON tool that emits no parseable findings doc
  **and** logs a fatal-abort marker (trivy `FATAL` + `run error:`/
  `scan error`) is promoted from `ok` to a `crashed` status, so the
  aborted scan surfaces in `incomplete_tools[]` (INV-4 / ANTS-2032)
  instead of as a misleading clean zero-finding run.
- **INV-21 / in-process drift lanes on a default sweep (ANTS-3605).**
  (Numbering note: the feature test contract
  `tests/features/mcp_audit_run/spec.md` carries invariants not
  back-ported to this canonical spec — INV-10b (absolute-path tool
  resolution), INV-18 (scoped-positional argv guard, ANTS-2185),
  INV-19 (compile-DB resolution, ANTS-2182), INV-20 (transport-cap
  guidance, ANTS-2183) — and reuses INV-17 for a *different* invariant
  there (secret redaction, ANTS-2188) than this spec's INV-17
  (JSON-only parsing, ANTS-3395). That cross-doc collision and the
  missing back-ports are tracked in ROADMAP ANTS-3609; this new
  invariant takes INV-21, the next number free in both docs, to avoid
  minting a fresh collision.)
  The GUI-free `FeatureCoverage` drift lanes — `spec_code_drift`,
  `contract_doc_drift`, `changelog_test_coverage` — run inside
  `runAudit`, *after* the external QProcess tools and *before* the
  tally (so their counts fold into the totals), whenever the caller did
  not name tools explicitly (`tools:[]`) **and** the resolved scope is
  not a narrowed file-diff — i.e. the default `auto`, an explicit
  `full`, or a narrowing scope that demoted to full. The gate in code is
  `req.tools.isEmpty() && !scopeNarrowed`. An explicit `tools:[…]`
  request, or a narrowed scope with changes (`files` / `branch-diff` /
  `since-tag` / `since-last-run`), skips them: they are whole-project
  doc-vs-code checks, meaningless against a changed-file set — the same
  rationale as the repo-global-tool skip under a narrowed scope. Each
  lane emits `file:line: message`, parsed
  by the line-based fallback (the lane ids are not JSON tools, so
  INV-17's JSON-only path never applies); results land in
  `by_tool[<lane-id>]` like any tool. This gives the headless MCP/CI
  workflow the doc-drift coverage that previously fired only when a
  human opened the GUI Audit dialog, which registers all three lanes
  `autoSelect` via `AuditDialog::populateChecks`. The lanes reuse the
  same `finish()` ingestion seam (scrub → `parseToolOutput` →
  `by_tool` / `fullFindingsByTool`) as the external tools, so
  suppression, SARIF, and the delta treat them uniformly.

## 6. Performance / RAM budget

**Wall time:**
- Cold-start overhead (one-time, before first audit): ≤ 250 ms
  (PATH probe × 9 tools × 8 PATH entries ≈ 50-200 ms; exclusion
  list/regex hardening ≈ 30 ms; engine alternation build ≈ 10 ms).
  Runs inside the first call's pool slot — server_busy callers
  should expect first-call latency.
- Aggregate cap: 240 s. Median on Ants Terminal (~60 KSLOC): ~45 s.
- Fold-in (delegated to caller's audit-triage subagent): out of
  scope here; subagent calls `roadmap_log` itself.

**RAM (Ants process):**
- Engine working set: ~200 KiB at N=200 findings.
- SARIF builder peak: ~150 KiB at N=200; ~1.4 MiB at N=2000.
  Capped at N=10000 (~7 MiB) per INV-13.
- Response envelope: ≤ 20 KiB.
- QProcess overhead: ~50 KiB × 9 ≈ 450 KiB.
- Cached compiled regex set: ~10 KiB.

**RAM (per-tool children):** cppcheck ~80 MiB, semgrep ~500 MiB,
trivy ~300 MiB, clazy ~400 MiB, mypy ~250 MiB, four lighter tools
~50 MiB each = ~200 MiB. **Sum: ~1.7 GiB** peak tool-side RSS.

**Cross-pool aggregate (audit + concurrent build):** Audit pool
(INV-9) is independent from build/verify pool. A concurrent build
adds `max(2, nproc/4) × ~1.5 GiB cc1plus` ≈ 3 GiB. **Audit + build
peak ≈ 5 GiB total.** On the 32 GiB workstation: fine. On the
`workstation` preset's lower-spec target (8-16 GiB): user should
not run `/audit` during a build. Documented for user awareness
per the standing "every feature states a memory budget" rule.

**Disk I/O:** SARIF write ~150 KiB; HTML write (opt-in) ~80 KiB.

**FD pressure:** 9 QProcess × 3 pipes + 9 pidfd = 36 fds. Well
within RLIMIT_NOFILE.

**PathValidation cost:** ~5 stat syscalls per path × ~5 paths per
call = ~25 syscalls ≈ 5 ms cold cache. Negligible.

## 7. Skill-side change

`~/.claude/skills/audit/SKILL.md` gains a fast-path block at top:

```
## Fast path (Ants Terminal)

If `mcp__ants__audit_run` is available, prefer it.

Flag mapping:
- `/audit`              → `audit_run{}` (auto-detect, scope:auto)
- `/audit --quick`      → `audit_run{tools:["cppcheck","ruff","bandit","gitleaks","shellcheck"], scope:"files"}`
- `/audit --no-roadmap` → `audit_run{}` then DON'T call roadmap_log
- `/audit cppcheck`     → `audit_run{tools:["cppcheck"]}`

Tip: for routine sweeps where the assistant just needs to see top
findings, set `top_findings_count: 20` to inline the highest-severity
findings into the envelope — saves the SARIF Read round trip.
```

## 8. Decisions

- **Blocking response, 4-min cap.** Async/streaming deferred.
- **Per-call SARIF; HTML opt-in; cleaned at shutdown.**
- **Exclusion list hardcoded in engine.** No new standards file.
- **Fold-in out of scope.** Orchestrator's audit-triage path retains
  `roadmap_log` calls (matches current skill flow). ANTS-1397 has
  a dedicated fold-in verb because test-audit synthesis doesn't go
  through a triage subagent.
- **Stderr excerpts unredacted under same-uid trust.** Callers
  re-publishing envelopes own redaction.
- **Dedicated `m_auditPool`, size `max(2, nproc/8)`.** Separate
  from build/verify pool. Two slots accommodate concurrent
  `/audit && /test-audit`.
- **Namespace `AuditRunner` PascalCase.** Matches in-tree
  convention.
- **In-flight gate inlined (not a class).** Per loop 3 opt H3 —
  two consumers don't warrant the abstraction.
- **`top_findings_count` opt-in.** Lets caller dodge the SARIF Read
  collapse when only ranking matters.
- **Linux-only assumed.** No `WIN32`/`APPLE` blocks (precedent:
  `ptyhandler.cpp`).
