# ANTS-2090 — Tabular (columnar) encoding for homogeneous-array MCP replies

**Status:** implemented (2026-06-29) — `mcp::tabularize` + `encoding:"tabular"` on the 7 list-shaped read verbs; 9 McpTabular feature tests green. Cold-eyes loops 1–3 clean (loop 3 2026-06-25).
(2026-06-25). Awaiting design sign-off before implementation.
**Kind:** implement.
**Source:** ROADMAP.md ANTS-2090 (2026-06-11 token-saving brainstorm; promoted
considered→planned 2026-06-25 as the first phase-2 token-savings design after
the ANTS-2094 offload fast-follow shipped).
**Composes with:** ANTS-1720 (`fields=` projection, `docs/specs/ANTS-1720.md`),
ANTS-2091 (`compact`/`compactEnvelope` — code only, no spec doc), ANTS-2085
(terse default — code only, no spec doc), ANTS-2094 (result offload,
`docs/specs/ANTS-2094.md`). Same dispatch pipeline, same
`src/mcpprojection.cpp` home.

**Layman:** JSON repeats every column name on every row — like a spreadsheet
that reprints the header above each line. This packs a list-shaped reply into
one header row plus value rows, so a big roadmap or search result is 30–60%
smaller. A session asks for it explicitly (`encoding:"tabular"`) because it has
to read the table back; it can never make a reply *bigger*.

## 1. Problem

The largest Ants MCP read replies are **lists of same-shaped objects**, and
JSON re-serialises every key on every element. Concrete shapes verified this
session:

1. `roadmap_query` → `bullets[]` of `{id, status, headline_oneline,
   section_slug, …}` (a full roadmap scan is 1000+ elements; the keys
   `id`/`status`/`headline_oneline`/`section_slug` repeat on each).
2. `workspace_search` → `matches[]` of `{file, line, text, also_at?,
   context_before?, context_after?}` (`mcpprojection.cpp` search above
   returned dozens of matches, each repeating `file`/`line`/`text`).
3. `file_outline` → `symbols[]` of `{line, kind, name, signature}`
   (`mcpprojection.cpp:file_outline` returned 14 symbols, each with the same
   four keys — see the outline call earlier this session).
4. `find_caller` → `callers[]`, `find_sources` → `sources[]`,
   `codebase_index` / `docs_index` → their entry lists.

For an N-element array with K keys, plain JSON pays the K key strings N times.
A columnar form pays them **once** (a header) plus the values. On the dense
list payloads above that is a 30–60% body reduction — the single biggest
remaining structural win after offload (ANTS-2094) masked the *occasional* huge
body and `compact` (ANTS-2091) dropped *dead-weight* fields. Neither touches
the per-row key repetition that dominates list replies.

Why now: phase-2 of the token-savings bundle. The projection pipeline
(`src/mcpprojection.cpp`, chained at `src/claudeintegration.cpp:9127–9216`)
already parses every read body into a `QJsonObject`, transforms it, and
re-serialises — adding one more pure transform to that chain is a small,
well-isolated change with no new build target.

## 2. Surface

### 2.1 New transform in `mcpprojection`

A pure function alongside `projectFields` / `compactEnvelope`, declared in
`src/mcpprojection.h` and defined in `src/mcpprojection.cpp`:

```cpp
// ANTS-2090 — pack each eligible top-level array-of-objects field of a
// response envelope into a columnar {__cols__, __rows__} form. Pure,
// Qt6::Core only; returns responseText unchanged when nothing is eligible
// or the columnar form would not be smaller. Opt-in: only called when the
// caller passed encoding:"tabular".
QString tabularize(const QString &responseText);
```

**No tool-name predicate gates `tabularize`.** Unlike `projectFields` /
`compactEnvelope` (gated on `isFieldProjectionTool`, `mcpprojection.cpp:28`)
and `offloadBody` (gated on `isOffloadEligible`, `:45`), `tabularize` is
**self-guarding per array** (§2.3): on any envelope it transforms only the
arrays that qualify and shrink, and no-ops on everything else. So the only
runtime gate is the per-call `encoding` arg (§2.4) — there is deliberately no
`isTabularEligible` predicate. Reusing either existing predicate set would be
*wrong*, not just unnecessary: their membership diverges from this feature's
target list (`find_caller` is in **neither** set; `find_sources` is in
`isOffloadEligible` but not `isFieldProjectionTool`). The §2.4 verb list is
purely where the schema prop is **advertised** for discoverability, decoupled
from those predicates.

### 2.2 Wire format

**Encoding choice (resolves the ROADMAP fork).** The ROADMAP bullet left the
encoding open ("columnar JSON vs TOON vs NDJSON"). Columnar JSON is chosen
because it keeps the body **one valid JSON document** — the entire dispatch
pipeline parses each response with a single `QJsonDocument::fromJson`
(`mcpprojection.cpp:61`, `:236`), which NDJSON (one object per line) would
break, and because it needs **zero new parser** on either side, whereas a
bespoke TOON grammar would. The win (drop repeated keys) is captured without
leaving JSON.

An eligible array field is replaced, in place, by an object carrying two
synthetic keys:

```json
{
  "ok": true,
  "bullets": {
    "__cols__": ["headline_oneline", "id", "section_slug", "status"],
    "__rows__": [
      ["columnar tabular encoding", "ANTS-2090", "performance-2", "📋"],
      ["server-side compute query", "ANTS-2093", "performance-2", "📋"]
    ]
  }
}
```

Decode (the consuming session): for each object value containing a `__cols__`
key, zip `__cols__` with each element of `__rows__` to rebuild the array of
objects; a `null` cell means that key was absent on that element (an element
with an *explicit* `null` value and one *missing* that key decode identically
— this missing-key⟺null collapse is the defined, lossless-in-practice
semantics; see INV-3).

- The `__`-prefixed keys are the discriminator: only an object value that
  contains `__cols__` is a tabular-encoded array. Real object fields
  (`feedback_pending:{…}`) never use `__`, so there is no collision and a
  decoder needs no out-of-band signal. No real MCP response field begins with
  `__` (grep-verified at authoring time; see §5).
- Scalar and other top-level fields (`ok`, `count`, `etag`, hint keys) are
  left exactly as-is.

### 2.3 Eligibility + the size guard (per array, independent)

For each **top-level** field whose value is a JSON array, `tabularize`:

1. **Skips** the array unless it is non-empty, has **≥2 elements**, and
   **every element is a JSON object** (not a scalar, not a nested array). A
   1-element array never shrinks (header + one row ≈ the original); a
   mixed/scalar array has no well-defined column set.
2. Builds `__cols__` = the union of element keys, **accumulated into a sorted
   container** (a `QSet<QString>` drained into a sorted `QStringList`, or a
   `QMap` keyed by name) so the column order is **lexicographic regardless of
   element order** — not the first-seen order a naive per-element `QStringList`
   append would give. (A single `QJsonObject`'s own keys are already sorted in
   Qt6, but the *union across elements* only inherits that if the accumulator
   sorts; pin it explicitly.) `__rows__` = one value-array per element, each
   value placed at its column index, `null` where the element lacks that key.
3. **Compares serialised sizes**: if the columnar object is **not strictly
   smaller** (UTF-8 bytes, compact JSON) than the original array, the original
   array is kept verbatim. The transform can therefore never cost bytes.

Nested object/array values inside an element (a bullet's `lanes:[…]`, a
match's `also_at:[…]` / `context_before:[…]`) are carried **verbatim** into
their row cell — v1 does **not** recurse into nested arrays. The saving comes
from de-duplicating the element-level keys, which is where the bulk is.

`tabularize` returns the body unchanged when: the body is not a JSON object,
or `ok` is present and `false` (a refusal envelope is never restructured —
mirrors `projectFields`' refusal floor and `appendReadHints`' `!ok` bail).

### 2.4 Dispatch wiring + gating

`encoding` is a per-call arg, resolved at the dispatch site exactly like
`compact` (ANTS-2091): the new transform slots into the existing chain in
`src/claudeintegration.cpp` **after `mcp::appendReadHints` and before
`mcp::offloadBody`** (lines 9178 / 9196 at authoring — the *tests* pin this by
symbol, not line number; see INV-8):

```
applyEtagPattern → projectFields → compactEnvelope → appendReadHints
  → tabularize (NEW, when encoding=="tabular")  → offloadBody → wrapMcpData
```

```cpp
// after appendReadHints, before the offload size-gate:
if (argsObj.value(QStringLiteral("encoding")).toString()
        == QStringLiteral("tabular"))
    responseText = mcp::tabularize(responseText);
```

**Why `encoding`, not `format`.** The arg is named `encoding` (not `format`)
because `roadmap_query` — the #1 target verb — already emits a top-level
*response* field named `format`: `out["format"] = "github-task-list"` at
`remotecontrol.cpp:4423` (in `cmdRoadmapQuery`, ANTS-1428, set when any bullet
parsed as GFM). Request args and response fields are separate namespaces, so
`format` would be functionally safe, but a verb that took `format:"tabular"`
in and returned `format:"github-task-list"` out is a decoder trap; `encoding`
removes the overlap.

Ordering rationale:
- **After `projectFields`/`compactEnvelope`** so it tabularizes only the
  fields that survived projection, with dead-weight keys already dropped
  (fewer/cleaner columns).
- **After `appendReadHints`** so the etag/leaner-mode nudges are computed on
  normal JSON (they touch only top-level scalar keys, which `tabularize`
  leaves untouched — order is correctness-neutral between the two, but this
  keeps all the hint logic operating on un-restructured bodies).
- **Before `offloadBody`** so the smaller tabular body feeds the offload
  size-gate: a body that would have spilled may now fit under
  `mcp_offload_threshold_bytes`, avoiding a spill round-trip; and if it still
  spills, the spill file holds the (valid) tabular JSON.

`encoding` is declared as an enum prop `["json","tabular"]` (default `"json"`)
on the schema of each list-shaped read verb — `roadmap_query`,
`workspace_search`, `file_outline`, `find_sources`, `find_caller`,
`codebase_index`, `docs_index` — so it is discoverable + validated, following
the ANTS-2091 pattern ("each in-scope tool declares the prop"). This advertise
list is independent of the `isFieldProjectionTool` / `isOffloadEligible`
predicates (§2.1) — the dispatcher honours the arg generically; declaring it
per-verb is the discoverability surface, not the enforcement point.

**Composition with `fields=`.** `tabularize` runs *after* `projectFields`
(`:9145`), so it operates only on the arrays that survived projection. Unlike
`appendReadHints` — which bails entirely when `fields=` is present
(`mcpprojection.cpp:138`) — `tabularize` does **not** bail on a narrowed call:
a `fields=["bullets"]` + `encoding:"tabular"` call still gets `bullets`
columnar-encoded, and a `fields=` set that drops the array leaves nothing for
`tabularize` to do (it no-ops). That asymmetry is intentional (the caller asked
for tabular explicitly); §6 covers it with a `fields=`+`encoding` unit case.

There is **no config key and no session default** in v1: tabular changes the
*shape* of a field (unlike `compact`, whose absence is value-identical, and
`offload`, whose envelope is self-describing). A caller opts in **because it
knows how to decode** the columnar form — so it is a per-call tool like
`fields=`, never a global default. (Contrast ANTS-2094, which could default ON
precisely because its envelope is safe to ignore.)

## 3. Invariants

- **INV-1** — Opt-in & inert by default: `tabularize` is invoked only when the
  call passed `encoding:"tabular"`; with `encoding` absent / `"json"` / any
  other value the response is byte-identical to the non-tabular pipeline
  output. *Test:* `tests/features/mcp_projection/` — dispatch scrape asserts an
  `encoding")).toString() == ` ... `"tabular"` guard immediately precedes the
  `mcp::tabularize(` call (matched by symbol/literal, **not** line number).
- **INV-2** — Eligibility: a top-level array is transformed iff it is
  non-empty, has ≥2 elements, and every element is a JSON object. Empty,
  single-element, scalar-bearing, or nested-array-bearing top-level arrays are
  left unchanged. *Test:* unit cases per shape.
- **INV-3** — Round-trip fidelity, length-preserving: `__rows__` has exactly
  one entry per original element (so any sibling `count`/`total` field stays
  consistent with `__rows__.length`), and zipping `__cols__` with each
  `__rows__` entry (null for a missing column) reconstructs an array equal to
  the original parsed array with element order preserved — faithful **up to
  the missing-key⟺explicit-null equivalence** (an element with an explicit
  `null` value and one missing that key decode identically). Acceptable
  because the target verbs do not emit explicit-null fields, and when composed
  after `compactEnvelope` those nulls are pruned first (`mcpprojection.cpp:188`).
  *Test:* unit reconstruct-and-compare, plus a length/`count`-consistency case
  and a documented missing-vs-null case.
- **INV-4** — Never costs bytes: per array, the columnar form is emitted only
  when strictly smaller (compact UTF-8) than the original array; otherwise the
  original array is kept. A sparse/heterogeneous array that does not shrink is
  returned unchanged. *Test:* unit with a 2-element array of disjoint keys
  (columnar larger) → unchanged.
- **INV-5** — Nested-value preservation: object/array values inside an element
  (e.g. `lanes`, `also_at`, `context_before`) are carried verbatim into the
  row cell; v1 does not recurse into nested arrays. *Test:* unit asserting a
  nested-array cell survives byte-equal.
- **INV-6** — Refusal/non-object floor: a non-object body, or an envelope with
  `ok:false`, is returned unchanged (no array restructuring on errors or raw
  text). *Test:* unit (refusal envelope + non-JSON string passthrough).
- **INV-7** — Determinism & column order: identical input yields byte-identical
  output, and `__cols__` is in lexicographic order (the sorted key-union of
  §2.3 step 2), independent of element order. *Test:* a unit asserting two
  calls are byte-equal **and** a unit asserting `__cols__` is lexicographically
  sorted for an array whose first element introduces keys out of alphabetical
  order (so first-seen order would differ from sorted) — call-equality alone
  does not lock the order claim.
- **INV-8** — Dispatch order: `mcp::tabularize` runs after
  `projectFields`/`compactEnvelope`/`appendReadHints` and before
  `offloadBody`/`wrapMcpData`. *Test:* source-scrape of
  `src/claudeintegration.cpp` asserting the order **by symbol** —
  `s.indexOf("mcp::appendReadHints(") < s.indexOf("mcp::tabularize(") <
  s.indexOf("mcp::offloadBody(")` — never by hard-coded line number (adopts the
  ANTS-2094 Loop-5 by-symbol rule, not the pre-Loop-5 literal form; cf. the
  `project_source_scrape_test_windows` drift hazard).
- **INV-9** — Composition with offload: when a tabularized body still exceeds
  the offload threshold it spills via `offloadBody`; the spill file holds the
  tabular JSON and `read_spill` returns it verbatim (the `head` preview may cut
  mid-row and is not required to decode — full body decodes). *Test:* unit /
  source-scrape that tabularize precedes the offload gate (covered by INV-8).

## 4. RAM / build cost

- **Memory:** transient and bounded by the response size, which each verb
  already caps via `max_bytes`. `tabularize` parses one `QJsonDocument`, builds
  one rebuilt object, serialises once; all freed on return. **No retained
  state, no cache, no growth** — it adds nothing to the steady-state footprint
  (consistent with the standing "name your memory budget" rule: budget = O(one
  response), eviction = stack lifetime).
- **Build:** no new translation unit, no new library, no new external dep —
  one function added to the existing `mcpprojection` TU (Qt6::Core only).
  Tests join the existing `mcp_projection` feature bundle (no `add_executable`).

## 5. Out of scope (v1)

- **Recursion into nested arrays** (tabularizing `also_at[]` /
  `context_*[]` inside a match) — deferred; the element-level keys carry the
  bulk. Tracked for a follow-up if profiling shows nested arrays dominate.
- **A session-default / config key** — intentionally omitted (§2.4); revisit
  only if a decode helper is added that makes always-on safe.
- **Ants-side decode** — none; the consuming session decodes inline per the
  documented recipe. No `read_spill`-style companion verb.
- Authoring note: `__cols__`/`__rows__` were verified collision-free — no MCP
  *response field key* begins with `__`. When implementing, grep the
  response-builder key insertions specifically (e.g.
  `insert(QStringLiteral("__` / `["__`), not a bare `"__` (a bare grep also
  matches non-field literals like `__pycache__` in `auditengine.cpp` and the
  `__ants_engine` Lua registry key in `luaengine.cpp` — both benign, neither a
  JSON field). If any real response field ever begins with `__`, rename the
  sentinels before ship.
