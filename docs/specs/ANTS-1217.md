# ANTS-1217 — Hybrid GoogleTest bundle consolidation

**Theme**: 🧪 Build hygiene
**Status**: ✅ All phases shipped (2026-05-10)
**Post-ship reconciliation:** the architectural sections below
discuss `-j6` for the workstation preset and `link_pool=2`. The
shipped values are **`-j3`** (workstation preset jobs cap) and
**`link_pool=1`** (in-tree JOB_POOLS). The Phase 6 retune row
documents the change; readers of the architectural body should
substitute the shipped values rather than the design draft.
**Kind**: refactor
**Source**: build-OOM incident on 2026-05-09 (cc1plus over-parallelism on Tumbleweed 7.0.1; earlyoom reaped 64 processes — including the active ants-terminal session and the linker writing `build/ants-terminal`, which left a missing on-disk binary)

## Problem

`tests/features/` grew from ~37 → 141 standalone `add_executable(test_*)` blocks
in 14 days. Each test binary carries its own Qt MOC `_autogen` step and its
own copy of the `src/*.cpp` files it links against — `src/mainwindow.cpp` is
compiled **42 times** today (once for `ants-terminal`, once for each of the
~41 tests that link it). Every Qt-using `cc1plus` peaks at 200–300 MiB
working set; on a default `cmake --build build -j$(nproc)` (16+ jobs on this
host), peak **compile-time** RSS exceeds RAM+swap and earlyoom intervenes.

The OOM is purely a **build-time** problem driven by `cmake --build`'s
parallelism (Ninja runs ~`nproc` cc1plus jobs concurrently, each holding a
copy of the same Qt-bloated translation unit). Test *runtime* — `ctest -j` —
is comparatively cheap and is not the trigger.

The reference for the cure is the sister project **Vestige**
(`/mnt/Games/Scripts/Linux/3D_Engine`): one consolidated GoogleTest
executable with `gtest_discover_tests` registers ~3,200 individual ctest
entries against a single bundle binary. Ants is too large for one bundle
(it would still OOM at link time and slow incremental builds), so we apply
the same idea sliced by subsystem — a **hybrid** between Vestige's single
bundle and the current per-test sprawl.

Phase 0 (applied in this working tree on 2026-05-09, not yet committed)
flips the `ANTS_TESTS` default to `OFF` and adds a Qt PCH on the main exe.
That stops the *daily* OOM but leaves the *tests-on* path equally
vulnerable — and tests need to run. The durable cure is to consolidate
test binaries.

## Non-goals

- Replacing the audit-rule shell harness (`tests/audit_self_test.sh`) — it's
  not C++ and isn't part of the OOM problem.
- Migrating to QTest. GoogleTest is preferred for cross-project consistency
  (sister project Vestige already uses GoogleTest v1.15.2 successfully).
- Unity builds. Documented Qt MOC + anonymous-namespace clashes; reward not
  worth the risk at this scale.
- Mold linker. Has a Ninja-parallelism gotcha (each mold instance is
  multi-threaded; N concurrent links = N² threads). Once consolidated to
  7–9 link targets (count varies with `LUA_FOUND` and
  `ANTS_ENABLE_HELPER_CLI`) the problem ceases to exist; the default
  linker is fine.
- Splitting tests by class (unit vs integration vs e2e). Out of scope for
  this refactor; the existing `features` ctest label stays.

### Inside each bundle

Each `tests/features/<dir>/test_*.cpp` migrates from a standalone `int main()`
exit-code-based test into one or more `TEST(SubsystemName, FeatureName)`
blocks. Assertions migrate from `if (bad) { fprintf(stderr,…); return 1; }`
to `EXPECT_*` / `ASSERT_*`. Each migrated TEST block stays runnable in
isolation via `ctest -R <Suite\.Name>` so the "run against pre-fix code to
confirm the test would have caught the bug" workflow from
`tests/features/README.md` still applies.

**Bundle assignment is by subject, not by Qt link surface.** A measurement
of the current corpus (2026-05-09) found 77 of the 141 tests link **no**
`src/*.cpp` files — they're pure grep/structural tests (e.g., `audit_*`
tests grep audit-rule fixtures, `remote_control_*` tests spawn a child
process and check IPC behaviour). These tests still bucket by subject:
`audit_*` → `test_audit`, `remote_control_*` → `test_core`,
`session_*` → `test_core`, etc. The remaining 64 tests link src/ files
directly today and are the primary OOM drivers; they get the largest
benefit from STATIC-library dedup.

The exact per-bundle headcount is determined during Phase 2's
pattern-establishing work (the migration commit lists the moved tests
explicitly). The estimates in the migration table below
(test_vt ~29, test_chrome ~50, …) sum to 141 but are approximate; the
final distribution may shift by a handful as edge cases are bucketed.

**Two bundle-main flavours** to match the GUI / non-GUI split:

`tests/bundle_main_gui.cpp` (used by test_vt, test_chrome, test_claude,
test_audit, test_dialogs, test_lua):

```cpp
#include <gtest/gtest.h>
#include <QApplication>

int main(int argc, char* argv[]) {
    qputenv("QT_QPA_PLATFORM", "offscreen");
    QApplication app(argc, argv);
    ::testing::InitGoogleTest(&argc, argv);
    return RUN_ALL_TESTS();
}
```

`tests/bundle_main_core.cpp` (used by test_core — Qt::Core only):

```cpp
#include <gtest/gtest.h>
#include <QCoreApplication>

int main(int argc, char* argv[]) {
    QCoreApplication app(argc, argv);
    ::testing::InitGoogleTest(&argc, argv);
    return RUN_ALL_TESTS();
}
```

`app.exec()` is **not** called — Ants' tests are pure invariant checks; they
don't need an active event loop. (Tests that legitimately need event-loop
processing can call `QCoreApplication::processEvents()` or use `QSignalSpy`
within their TEST block, same pattern as today.) The two flavours exist
because `QApplication` requires `Qt6::Widgets`, which would defeat the
"no GUI dependencies for grep-style tests" goal of the `test_core` bundle.

**ctest selection migration.** Existing names (`test_redraw`,
`test_frozen_view`, …) become Suite.Test pairs (`VtParser.Redraw`,
`VtParser.FrozenView`, …). Existing `ctest -R '^test_redraw$'`
invocations need to migrate to `ctest -R 'VtParser\.Redraw'` (or the
broader `ctest -R 'Redraw'`). The `-L features` label filter is
preserved untouched. The Phase 2 commit will include a
`tests/features/README.md` update with the new ctest filter snippets.

### CMake skeleton

```cmake
# GoogleTest acquisition: system pkg first, FetchContent fallback.
# Floor of 1.13 — we use APIs from that release (DISCOVERY_MODE PRE_TEST
# first reached its current behaviour there).
find_package(GTest 1.13 QUIET)
if(NOT GTest_FOUND)
    include(FetchContent)
    FetchContent_Declare(googletest
        GIT_REPOSITORY https://github.com/google/googletest.git
        GIT_TAG v1.15.2)
    set(BUILD_GMOCK OFF CACHE BOOL "" FORCE)
    set(INSTALL_GTEST OFF CACHE BOOL "" FORCE)
    FetchContent_MakeAvailable(googletest)
endif()
include(GoogleTest)

# Cap concurrent compile + link invocations (Ninja only; harmless under
# Make). Belt-and-suspenders: even after the STATIC-library refactor
# bounds the TU count, the JOB_POOLS cap ensures `cmake --build --parallel`
# (or `ninja -j$(nproc)`) cannot oversubscribe a Qt-bloated cc1plus and
# OOM the host. Sized to leave 2 cores' headroom for the OS.
include(ProcessorCount)
ProcessorCount(_ANTS_NPROC)
if(_ANTS_NPROC LESS 4)
    set(_ANTS_COMPILE_CAP ${_ANTS_NPROC})
else()
    math(EXPR _ANTS_COMPILE_CAP "${_ANTS_NPROC} - 2")
endif()
set_property(GLOBAL APPEND PROPERTY JOB_POOLS
    compile_pool=${_ANTS_COMPILE_CAP}
    link_pool=2)
set(CMAKE_JOB_POOL_COMPILE compile_pool)
set(CMAKE_JOB_POOL_LINK    link_pool)

# Shared INTERFACE target carrying the warning + hardening flag set so
# every consumer (libs + main exe + test bundles) compiles with the
# identical flags that PCH REUSE_FROM requires.
add_library(ants_warnings INTERFACE)
target_compile_options(ants_warnings INTERFACE
    -Wall -Wextra -Wpedantic -Wformat=2 -Wshadow=local -Wnull-dereference)

# Source libraries
add_library(ants_core_lib   STATIC src/config.cpp src/debuglog.cpp …)
target_link_libraries(ants_core_lib
    PUBLIC  Qt6::Core Qt6::Gui Qt6::Widgets
    PRIVATE ants_warnings)
target_include_directories(ants_core_lib PUBLIC src)

# (… 5 more ants_*_lib blocks; ants_lua_lib + ants_helper_lib gated …)

# Main exe
add_executable(ants-terminal src/main.cpp)
target_link_libraries(ants-terminal PRIVATE
    ants_core_lib ants_vt_lib ants_chrome_lib ants_claude_lib
    ants_audit_lib ants_dialogs_lib ants_warnings
    $<$<BOOL:${LUA_FOUND}>:ants_lua_lib>)
target_precompile_headers(ants-terminal PRIVATE
    <QtCore/QtCore> <QtGui/QtGui> <QtWidgets/QtWidgets>)

# Test bundles (only when ANTS_TESTS=ON)
if(ANTS_TESTS)
    # GUI-flavoured bundles share the PCH from ants-terminal because they
    # link Qt6::Widgets and inherit the same INTERFACE flags.
    function(ants_add_gui_bundle name)
        cmake_parse_arguments(B "" "" "LIBS;SOURCES" ${ARGN})
        add_executable(${name} tests/bundle_main_gui.cpp ${B_SOURCES})
        # Qt6::Widgets is reached transitively via PUBLIC link from each
        # ants_*_lib; no need to re-list it here.
        target_link_libraries(${name} PRIVATE
            ${B_LIBS} ants_warnings GTest::gtest)
        target_precompile_headers(${name} REUSE_FROM ants-terminal)
        gtest_discover_tests(${name}
            DISCOVERY_MODE PRE_TEST
            PROPERTIES LABELS "features;fast" TIMEOUT 10)
    endfunction()

    # Core-only bundle (test_core) cannot REUSE_FROM ants-terminal because
    # it does not link Qt6::Widgets and would inherit different INTERFACE
    # flags. It compiles fast enough on its own that an independent PCH
    # (or none) is fine.
    function(ants_add_core_bundle name)
        cmake_parse_arguments(B "" "" "LIBS;SOURCES" ${ARGN})
        add_executable(${name} tests/bundle_main_core.cpp ${B_SOURCES})
        # Qt6::Core is needed even when B_LIBS is empty (test_core with
        # ANTS_ENABLE_HELPER_CLI=OFF), so it is listed explicitly.
        target_link_libraries(${name} PRIVATE
            ${B_LIBS} ants_warnings GTest::gtest Qt6::Core)
        gtest_discover_tests(${name}
            DISCOVERY_MODE PRE_TEST
            PROPERTIES LABELS "features;fast" TIMEOUT 10)
    endfunction()

    ants_add_gui_bundle(test_vt
        LIBS    ants_vt_lib ants_core_lib
        SOURCES tests/features/scrollback_redraw/test_redraw.cpp
                tests/features/scrollback_frozen_view/test_frozen_view.cpp
                # … 27 more)
    # (… test_chrome, test_claude, test_audit, test_dialogs declarations …)

    if(LUA_FOUND)
        ants_add_gui_bundle(test_lua
            LIBS    ants_lua_lib ants_core_lib
            SOURCES tests/features/lua_sandbox_hardening/test_lua_sandbox_hardening.cpp
                    tests/features/plugin_manifest_safety/test_plugin_manifest_safety.cpp)
    endif()

    # test_core: subject = core infrastructure (IPC, session, PTY,
    # threading, audit-shell harness wrappers, helper CLI). Qt::Core only;
    # no GUI symbols. Final test list determined during Phase 6.
    ants_add_core_bundle(test_core
        LIBS    $<$<BOOL:${ANTS_ENABLE_HELPER_CLI}>:ants_helper_lib>
        SOURCES tests/features/remote_control_ls/test_remote_control_ls.cpp
                tests/features/session_persistence_default/test_session_persistence_default.cpp
                tests/features/pty_closefrom/test_pty_closefrom.cpp
                # … remaining core-infra tests …
                $<$<BOOL:${ANTS_ENABLE_HELPER_CLI}>:tests/features/local_subagent_framework/test_local_subagent_framework.cpp>)
endif()
```

`ants_warnings` (an `INTERFACE` library carrying the warning + hardening
flag set) is the single source of truth. Every consumer — libs, main exe,
test bundles — links it `PRIVATE`, so PCH `REUSE_FROM` always sees
identical compile flags between source (ants-terminal) and reusing
targets (the GUI bundles). REUSE_FROM is intentionally not used for
`test_core` because its non-Widgets link interface diverges.

## Build-time guardrails (belt-and-suspenders)

The architectural fix above removes the *cause* of the OOM (too many
concurrent Qt-bloated cc1plus processes). But because the consequences of
a future regression are catastrophic for the user (full system freeze,
lost work, missing binary on disk), we also ship guardrails that bound
the worst case even if the cause re-emerges.

Three layers, ordered from in-tree-automatic to opt-in:

1. **In-tree CMake `JOB_POOLS` cap** (always on; no user action). See
   the `compile_pool` / `link_pool` block in the CMake skeleton above.
   `compile_pool` is sized at `nproc - 2` (or `nproc` on hosts with
   fewer than 4 cores). Effect (Ninja only — Make uses `-j` directly):
   even if a user runs `ninja -C build -j$(nproc)` or `cmake --build
   build --parallel`, the pool caps the actual concurrency. On a
   16-core host: at most 14 concurrent compiles + 2 concurrent links.
   Worst-case RSS on a Qt build with 200–300 MiB per cc1plus stays
   well below 32 GiB. This layer is invisible to the user — no new
   flags to remember.

2. **`CMakePresets.json` workstation preset** (opt-in via `cmake
   --preset=workstation`). Ships a sane default `-j6` for users on
   constrained hardware. Optional; advanced users can still pass `-j`
   explicitly to override.

3. **`tools/safe-build.sh` wrapper** (opt-in last-resort backstop).
   Wraps `cmake --build` in a memory-bounded systemd
   user scope so the kernel kills the build (not the running session)
   if the cap is exceeded:

   ```bash
   #!/usr/bin/env bash
   exec systemd-run --user --scope --quiet \
       -p MemoryMax=24G -p MemorySwapMax=8G \
       cmake --build "${1:-build}" "${@:2}"
   ```

   Use it as `tools/safe-build.sh build -j$(nproc)` when paranoid.
   Documented in CLAUDE.md but not invoked by CI or the build's
   default path; the in-tree pool cap should make it unnecessary.

Layer 1 is mandatory and ships in Phase 1 alongside the STATIC-library
refactor. Layers 2 and 3 ship in Phase 7 with the rest of the
documentation work.

### Additional build optimizations (sign-off 2026-05-10)

Independent of the OOM cure, three further optimizations ship in Phase 1
because they compound the resource savings at near-zero risk:

1. **ccache as `CMAKE_CXX_COMPILER_LAUNCHER`** — `/usr/bin/ccache` is
   already installed on the workstation. With `CCACHE_BASEDIR` set to
   the source root, cache hits cross multiple `build*/` trees. Effect:
   re-configuring or switching branches no longer recompiles
   already-seen translation units; cc1plus is not invoked at all on a
   cache hit, which means **zero RSS** during the cached portion of a
   build. CI runners are stateless so they don't benefit, but the
   workstation rebuild loop does.

   ```cmake
   find_program(CCACHE_PROGRAM ccache)
   if(CCACHE_PROGRAM)
       set(CMAKE_CXX_COMPILER_LAUNCHER ${CCACHE_PROGRAM})
       set(CMAKE_C_COMPILER_LAUNCHER   ${CCACHE_PROGRAM})
   endif()
   ```

2. **`CMAKE_OPTIMIZE_DEPENDENCIES=ON`** — when an internal STATIC
   library's interface (its public headers) didn't change, CMake
   skips re-linking dependents. Requires CMake ≥ 3.19; we mandate
   3.20 already and the workstation is on 4.2.3.

3. **`-gsplit-dwarf` for Debug builds** — writes per-TU debug info to
   `.dwo` files instead of embedding into `.o`. The linker no longer
   has to read+relocate hundreds of MiB of debug strings, cutting
   linker peak RSS by 30–50%. Release builds keep the standard
   format. Pair with `-Wl,--gdb-index` if interactive gdb startup
   speed matters; not required for the OOM cure.

   ```cmake
   target_compile_options(ants_warnings INTERFACE
       $<$<CONFIG:Debug>:-gsplit-dwarf>)
   ```

Phase 2 layers on:

4. **`-O0 -g1` for test bundles** — tests are pure invariant checks;
   optimisation only adds compile cost. cc1plus uses ~50% less RSS at
   `-O0` than `-O2`. `-g1` (line tables only) drops local-variable
   debug info that adds nothing to test failure diagnostics.
5. **gtest header in test-bundle PCH** — `tests/bundle_main_gui.cpp`
   and `bundle_main_core.cpp` already include `<gtest/gtest.h>`;
   adding it to the bundle's PCH means every migrated `test_*.cpp`
   gets it precompiled.
6. **AUTOMOC scoped per-target** — leave `CMAKE_AUTOMOC` off globally
   and enable it only on libs/targets that contain QObject classes
   (the libs do; the test bundle main does not). Saves a few
   per-target `moc` invocations.

Phase 7 documents the AI/CI side:

7. **Token-frugal build invocations** in CLAUDE.md — `cmake --build
   build -j6 --quiet 2>&1 | tail -20` patterns so an AI assistant
   reading build output does not ingest 10k lines on every rebuild.

**Why not just `-j6` everywhere?** Because for users on a 32-thread
EPYC desktop, `-j6` leaves performance on the table. Layer 1's
`nproc - 2` heuristic scales: 6 jobs on a 8-thread laptop, 30 jobs on
a 32-thread workstation. The cap is tight enough to prevent OOM but
loose enough that builds still benefit from parallelism. Users who
*want* `-j6` can use Layer 2's preset.

**Why not `MemoryMax=` only?** Because a kernel-OOM kill mid-link
still loses the on-disk binary (the linker dies between `open()` and
`close()`, leaving a zero-byte file). Layer 1 is preferred because it
prevents the kill from happening at all; Layer 3 is only the
last-resort backstop.

## Migration plan

Incremental per-subsystem migration, every step bisectable. Each phase is
one or more focused commits. The default `ANTS_TESTS=OFF` brake stays in
place until **Phase 7** when it flips back to `ON`.

**Important Phase 1 caveat.** During Phase 1 the standalone tests still
list `src/*.cpp` directly (`add_executable(test_x tests/.../test.cpp
src/foo.cpp src/bar.cpp …)`). The new STATIC libraries also contain those
sources. CMake compiles each .cpp twice — once for the lib, once per
standalone. Phase 1 therefore reduces the *main exe* compile cost (one
TU set, shared with future bundles) but does **not** reduce per-test
compile cost. The OOM danger of `cmake --build build -j$(nproc)` with
`ANTS_TESTS=ON` persists until standalones are migrated in Phases 2–6.
Phase 1's win is structural ("ants-terminal builds via libs") and
prerequisite for all later phases — it is not itself an OOM mitigation.
Daily incremental builds with `ANTS_TESTS=OFF` (Phase 0 default) remain
safe throughout.

## Risks & mitigations

| Risk | Mitigation |
|---|---|
| **Static-init ordering** — tests in a bundle share QApplication. If any test relies on `qApp` being null at TEST entry → that test fails | Wrap in a gtest fixture `class FreshAppFixture : public ::testing::Test { … };` that handles app-state assumptions explicitly. Inventory at migration time; expected count: 0–2 tests. |
| **Source-grep tests with hardcoded paths** — some tests use `SRC_MAINWINDOW_PATH` baked in via `target_compile_definitions` | Move the `target_compile_definitions` from the per-test target to the bundle target. Each affected test_*.cpp keeps its `#ifdef SRC_MAINWINDOW_PATH` guard. |
| **Tests that mutate environment variables** — `qputenv`/`qunsetenv` calls leak across TEST cases in same process | Add a base fixture `EnvIsolationFixture` that snapshots/restores the env on `SetUp`/`TearDown`. Tests opt in via inheritance. |
| **FetchContent network access at configure time** | `find_package(GTest 1.13 QUIET)` is tried first — Tumbleweed's `gtest-devel` and Ubuntu's `libgtest-dev` both satisfy it, no network. FetchContent only fires on hosts without a system GoogleTest, and CMake caches the download in `<build>/_deps/googletest-src/` so re-configure is offline. CI workflow files explicitly install `libgtest-dev` so the FetchContent path is never taken in CI. |
| **GoogleTest version too old on system pkg** — Ubuntu 22.04 ships gtest 1.11; Ubuntu 24.04 ships 1.14. We pin a 1.13 floor for `DISCOVERY_MODE PRE_TEST` semantics | `find_package(GTest 1.13 QUIET)` returns `GTest_FOUND=FALSE` on too-old system pkgs, FetchContent fallback fetches v1.15.2. CI uses `ubuntu-24.04` (gtest 1.14) which satisfies the floor. Workstation users on Tumbleweed get the rolling release (≥1.15 today). |
| **`TEST(Suite, Name)` collisions across files in the same bundle** — two test files inside `test_vt` both writing `TEST(VtParser, BasicCsi)` link cleanly (gtest disambiguates registration symbols by file/line) but produce two ctest entries with identical Suite.Test names, indistinguishable to `ctest -R` and dropped by `gtest_discover_tests`'s set-uniquification | Suite-naming convention in `tests/features/README.md`: each subdir owns a unique Suite name derived from the directory (`scrollback_redraw` → `ScrollbackRedraw`); within a Suite, the Name is the assertion topic. Phase 2's commit establishes the convention; later phases follow it mechanically. CI grep for duplicate `TEST(Suite, Name)` lines per bundle catches drift. |
| **PCH `REUSE_FROM` flag drift** — GUI bundles need identical compile flags to ants-terminal (REUSE_FROM is intentionally not used by `test_core`) | Factor warning + hardening flag set into the `ants_warnings` `add_library(INTERFACE)` target shown in the skeleton and `target_link_libraries(... PRIVATE ants_warnings)` everywhere. Single source of truth; flag drift breaks loudly at PCH-validation time. |
| **A test legitimately needs process isolation** (signal handlers, abort, exit) | gtest convention `_DeathTest` suffix → forks per assertion. If even that fails, demote that test to a single-test bundle (extra add_executable, but only for the genuinely-isolated cases). Audit for these during Phase 2's pattern-establishing work. |
| **A test needs a non-offscreen Qt platform** (e.g. an X11-specific test) | `qputenv("QT_QPA_PLATFORM", "offscreen")` runs *before* `QApplication` construction in `bundle_main_gui.cpp`. Tests that need otherwise can't override post-hoc. Mitigation: any such test stays as a standalone `add_executable` exception (not migrated into a bundle). Sweep for these during Phase 2 — expected count: 0 based on current test corpus (all existing tests pass `QT_QPA_PLATFORM=offscreen` per `tests/features/README.md`). |
| **Phase 1 standalones still OOM during migration** | `ANTS_TESTS=OFF` default means daily `cmake --build build` is safe; tests-on builds during this period are protected by the Phase 1 `compile_pool` cap (Layer 1 of the guardrails — no manual `-j` flag needed). |
| **A migrated test passes when it shouldn't** (false-pass on broken code) | Per-phase verification gate forces re-running the regression-confirmation workflow from `tests/features/README.md` before merging the phase commit. |
