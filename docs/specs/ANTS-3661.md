**Blocked by:** ANTS-3664 — the finding shape this emits.
**Composes with:** ANTS-3601 (`doc_integrity`, whose verb-layer walk this

**Layman:** Check that every function or class name a document mentions actually
exists in the code. It only ever *reports* — deciding whether a missing name is
a mistake or something the document is about to create is a person's call.

---

## 1. Problem

`/cold-eyes` § 1e calls this "the highest-yield check in the pre-pass" and names
its two worst corpus findings: a function documented as returning one thing when
it returned another, under a heading reading *"Verified API basis"*; and a test
seam a later reviewer's notes call *"fictional"*. Both were written from recall.
Both would have died at a symbol lookup. Both instead cost a cold-reader pass to
find and a redesign to fix.

This session produced a third, unprompted: `docs/standards/specs.md:236` states
`spec_query` surfaces a `*Test:*` clause as `test_surface`, and its bullet-form
branch did not (ANTS-3665, fixed 2026-07-28). Nobody noticed until a grounding pass read the
parser. That is the same class — a doc asserting a behaviour of a named symbol
that the symbol does not have.

**The lookup is cheap and nothing does it today.** `find_definition` resolves
C++, Python, Lua, shell, GLSL and a generic family (`SymbolQuery::langForExt`,
`src/symbolquery.cpp::langForExt()`) but has no markdown path at all: it answers "where is
`Foo` defined", never "which names does this document claim exist". Harvesting
the question from prose is the new part; answering it is a call to
`SymbolQuery::findDefinition` (`src/symbolquery.h`).

## 2. Surface

### 2.1 What counts as a candidate

Harvest inline code spans via `MarkdownScan::codeSpans` (fence-aware, so a
```` ```cpp ```` sample is skipped), then keep a span only if its content
matches

```
candidate := ident ( "::" ident )* "()"?
ident     := [A-Za-z_][A-Za-z0-9_]*
```

after CommonMark's one-space strip, and the whole span is consumed by the match.
**Six** exclusions, each removing a population that would otherwise dominate the
output:

- **Anything containing `/` or `.`** — that is a path, and `doc_citations`
  (ANTS-3636) and `doc_integrity` (ANTS-3601) already own paths. A doc's
  `src/foo.cpp` must not be reported by two verbs with two vocabularies.
- **Spans inside a `doc-examples` region** (ANTS-3659) — a doc teaching symbol
  resolution names fictional symbols on purpose, exactly as it writes fictional
  paths. This verb honours the region; that ANTS-3659 § 2.1 left the policy per
  verb is what makes the answer a decision rather than an inheritance.
- **A single lowercase word shorter than `minIdentChars = 5`** — prose backticks
  `ok`, `path`, `kind` constantly, and a short lowercase run is far more often
  emphasis than an identifier. A `::`-bearing, `()`-bearing or mixed-case span is
  exempt from the floor, because those shapes are unambiguous. (A bare lowercase
  word that *clears* the floor is harvested and resolved, but reported only if
  it resolves — that is a reporting rule, not this exclusion. See ANTS-3692
  below.) The floor is a
  real trade: it also drops `emit`, `exec`, `main` and `open`. Accepted, because
  a doc asserting something about one of those almost always writes it with `()`
  or a scope, and the alternative is a list dominated by prose emphasis.
- **The language keyword list** — `if`, `return`, `class`, `struct`, `null`,
  `true`, `false` and the rest. A doc backticks these while explaining code;
  none is a symbol anyone declared.
- **MCP verb names** — `spec_query`, `audit_run`, `roadmap_log` and the rest of
  the ~74-verb catalogue. **This is the largest population in this corpus and
  the one the first draft missed.** Applying § 2.1 by hand to
  `docs/standards/specs.md` § 3 harvests `spec_query`, `audit_run`, `LlmClient`,
  `implement`, `refactor` and `reaper` — and only `LlmClient` is a C++ symbol.
  Verb names are registered by *string* and declared nowhere, so every one of
  them resolves nowhere and would be reported forever; the `Kind:` taxonomy
  values (`implement`, `refactor`) are the same shape. Excluded against the live
  registry, not a static list, so a new verb never becomes a new false positive
  — see § 2.4 for how a Core-only engine gets at it.
- **Schema argument names and refusal codes** — `caller_cwd`, `max_findings`,
  `etag_match`, `bad_path`, `caller_cwd_required`, `mcp_disabled`. Backticked on
  nearly every page of this corpus, declared as JSON keys and string literals
  rather than as symbols, and so unresolvable forever — the same failure mode as
  verb names and, like them, missed by the first draft. Sourced the same way:
  each registered verb's schema property names, plus the taxonomy in
  `docs/standards/mcp-error-codes.md`. Grouped with verb names as one injected
  set (§ 2.4), since both come from the registry and neither is knowable to
  `ants_core_lib`.

**The exclusions are calibrated, not asserted.** The gate is numeric, because
"looks dominated" is not a test: **a population accounting for ≥ 25% of
unresolved occurrences means something is missing.** The harness is
`DocSymbols.DISABLED_CorpusCalibration`
(`tests/features/doc_symbols/test_doc_symbols.cpp`), which sweeps
`docs/specs/` + `docs/standards/` and classifies the unresolved set.

**Measured 2026-07-28, after ANTS-3692** — 240 docs, 12,723 candidate
occurrences emitted, 949 needles actually resolved (589 resolved / 360
unresolved; the rest `not_checked`, see § 4):

| Population | Unresolved | Share |
|---|---|---|
| C++ data members (`m_scrollOffset`, `m_claudeDetectTimer`) | 104 | **28%** |
| Unclassified | 193 | 53% |
| Qt framework symbols (`QTextBoundaryFinder`, `QRect`) | 53 | 14% |
| CMake link targets (`Qt6::Widgets`) | 10 | 2% |

The pre-ANTS-3692 run of the same harness measured 23,153 occurrences and
574 resolved / 442 unresolved. Emitted occurrences fell 45% while *resolved*
rose, which is the ordering rule below doing its work: the same budget now
buys more real lookups because it is no longer spent first on spans that
would be dropped unreported.

**The gate fires, and on the population this section already predicted.** C++
data members clear 25% — the "seventh population" below, named in loop 3 as
known-unresolvable and deliberately not excluded. So the gate's original
wording (*"an exclusion is missing"*) was too narrow: what a dominant
population proves is that **either** an exclusion is missing **or** the
resolver is short a pattern, and here it is the latter. The fix is ANTS-3668
against `find_definition`, not a filter here. Recorded rather than silently
reinterpreted, because a gate that fires and is then explained away is a gate
that never fires again.

Two populations the hand-applied loop-1 pass did not predict, both small enough
to leave alone for now:

- **Qt framework symbols (11%)** — `QRect` and friends are declared outside the
  project tree, so a project-root walk cannot resolve them however good the
  resolver gets. Genuinely unresolvable rather than a gap. Left unexcluded
  because a doc asserting something about `QTextBoundaryFinder` is asserting
  something real, and § 2.3 already makes the reader the judge.
- **CMake link targets (2%)** — `Qt6::Widgets` matches the production by
  accident. Too small to act on; noted so a future sweep recognises it.

The 59% unclassified bucket is not a finding, only the limit of four buckets:
finer classification is worth doing when a sweep is used to justify a change,
not before.

**A seventh population is known unresolvable and is deliberately *not*
excluded.** C++ data members, response-field names and enumerators —
`maxDocsPerRun`, `excludedNames`, `autoFixable`, `sections_checked`, `doc_line`
— pass every exclusion above: mixed-case or ≥ 5 characters, no `/` or `.`, not
keywords, and neither verb names nor schema arguments. They then resolve
nowhere, because `SymbolQuery::buildAnchors`' C++ ladder carries exactly three
definition patterns — a return-type-led form requiring a trailing `(`, an
out-of-line ctor/dtor form, and a `struct|class|union|enum` keyword form — and
none matches a data-member declaration.

They are not excluded because they *cannot* be. Unlike verb names there is no
registry to source them from, and "is this a data member?" is precisely the
question resolution exists to answer. Nor should they be: a doc asserting
something about `autoFixable` is asserting something real, and the honest
reading of a large data-member population in the calibration run is that the
**resolver** is short a pattern. Filed as ANTS-3668 against `find_definition`,
not against this verb. Until it lands these surface as unresolved candidates,
which § 2.3 already defines as a reviewer's call and never the verb's — so the
cost is noise in a list that is advisory by construction, not a false defect.

**Bare lowercase members of that population are the exception, and ANTS-3692
suppresses them.** The paragraph above holds for `autoFixable` and
`maxDocsPerRun`, whose mixed case marks them as somebody's identifier. It does
not hold for `sections_checked` or `doc_line`: those are shaped exactly like
`counts`, `dry_run` and `truncated`, which are JSON response keys no one ever
declared. The engine cannot tell the two apart, and a check that reports the
undecidable case has spent a reviewer's attention to say "this word exists".

So the rule is a *reporting* rule, not a seventh exclusion — the candidate is
still harvested and still looked up:

> An **ambiguous** span — bare lowercase, carrying no `::`, no `()` and no case
> boundary — reaches `symbols[]` only when it **resolves**. Unresolved or
> `not_checked`, it is dropped from both `symbols[]` and `findings[]`.

The discriminator is resolution, deliberately *not* shape. Requiring an
unambiguous shape was the first proposal and measurement refused it: sampling
100 bare lowercase spans from `docs/*.md` returned 7 that resolved, and
`cmd_promote`, `require_clean_main` and `redispatch` were real — two of them
shell functions. Bare lowercase **is** the naming convention in shell, Python
and Lua, so a shape rule would blind this verb to those languages wholesale
while a resolution rule keeps every one of them.

What it costs is rot in a bare lowercase name: a doc still naming a deleted
`render_frame` now goes unreported. Accepted, because that is precisely the
population where the check could not distinguish a defect from a JSON key, and
§ 2.3's constraint says the verb stays silent rather than guess.

Because ambiguous needles are dropped far more often than they are kept, they
are also resolved **last** — see § 2.2's ordering note. Spending the budget in
document order would let prose keys exhaust it before the symbols the check
exists for are reached.

Everything surviving is a *candidate*, not an assertion. § 2.3 is why that word
matters.

### 2.2 Resolution and shape

Each candidate is resolved by `SymbolQuery::findDefinition(rootCanonical,
symbol, opts)` — the same ladder `find_definition` uses, unchanged. Two
reductions turn a candidate into a needle, **in this order**:

1. **A trailing `()` is stripped.** The grammar admits it (§ 2.1) because
   `Foo::bar()` is how this corpus writes a function, and `()` is one of the
   three shapes that earn exemption from the `minIdentChars` floor — so it is
   the main path, not an edge. It must not reach the resolver:
   `SymbolQuery::isValidSymbol` is `^[A-Za-z_][A-Za-z0-9_]{0,127}$`, so `bar()`
   fails the guard and the call refuses `bad_args`. Unstripped, the corpus's
   commonest candidate shape turns into a verb refusal.
2. **The text after the last `::` is taken**, matching the needle rule
   ANTS-3654 § 2 established for anchors, so `Foo::bar` looks for `bar`.

The order is load-bearing: `Foo::bar()` reduces to `bar`, never to `bar()`.

The response carries every **reportable** candidate occurrence, resolved or not
— every unambiguous one, and the ambiguous ones that resolved (§ 2.1):

```
symbols[]:  { symbol, doc_line, doc_col, resolution, definitions[]? }
resolution: "resolved" | "unresolved" | "not_checked"
counts:     { total, resolved, unresolved, not_checked }  // emitted
                                                          // occurrences, not
                                                          // distinct needles
findings[]: DocFinding::Finding   // one per UNRESOLVED occurrence — never for
                                  // not_checked
truncated:  bool                  // true iff any NEEDLE went unlooked-up
```

**`truncated` is counted over needles, not over emitted occurrences.** Before
ANTS-3692 the two were the same thing and the flag was derived from
`counts.not_checked > 0`. They are no longer: an elided ambiguous needle never
reaches `symbols[]`, so that derivation would report a complete run over an
incomplete one — the same class of false claim as calling an unchecked needle
`unresolved`. A run may now legitimately return `counts.not_checked:0` with
`truncated:true`.

**Ordering: unambiguous needles are resolved first.** The budget is a fixed
number of tree walks, and across `docs/*.md` bare lowercase spans outnumber
`::`/`()`/mixed-case ones roughly 17:1 (18,369 against 1,076). In document
order that majority exhausts the allowance on spans most of which are then
dropped unreported, leaving the symbols the check exists for `not_checked`. A
needle reachable by both shapes is claimed by the unambiguous pass.

**`not_checked` is a third state, not a flavour of unresolved, and the
distinction is the one § 2.3 rests on.** A needle elided by `maxSymbolsPerRun`
or by § 4's resolve deadline was never looked up. Reporting it as `unresolved`
would assert that a symbol does not exist on the strength of never having asked
— the exact false claim this verb is built to avoid, and worse than a missing
row because it is indistinguishable from a real one. So a `not_checked`
occurrence produces **no** `DocFinding`, and `truncated:true` accompanies it.
The field is a tri-state string rather than a `resolved` bool plus a flag
because a two-boolean encoding admits a meaningless fourth combination, and the
first consumer to read only the bool would silently reintroduce the defect.

`doc_line` is 1-based and `doc_col` 0-based, converted from
`MarkdownScan::CodeSpan`'s 0-based `startLine`/`startCol` — the same convention
`DocCitations::Citation` uses, so the two doc verbs report positions the same
way.

**De-duplication is a resolution cache, not a filter on the output.** A doc
naming `parse` forty times yields forty `symbols[]` rows and **one** tree walk;
`counts.total` is forty. `maxSymbolsPerRun` caps the **distinct needle** set —
the thing that costs a walk — and sets `truncated:true`, which is why the two
numbers are not comparable and are named differently.

A candidate longer than 128 characters is dropped before resolution rather than
passed on: `SymbolQuery::isValidSymbol` (`src/symbolquery.h`) refuses it with
`bad_args`, and a harvest that fed it one would turn a prose oddity into a verb
refusal.

`definitions[]` is `find_definition`'s own `{file, line, signature, lang, kind}`
shape, present only when `resolution` is `"resolved"`. Unresolved candidates additionally become
`DocFinding::Finding` (ANTS-3664) with `verb:"doc_symbols"`,
`kind:"unresolved_symbol"`, and `autoFixable` left false — so by ANTS-3664 INV-1
the key is **absent** from the JSON, not present-and-false. A test asserting
`auto_fixable:false` on the wire fails against a conforming serialiser.

### 2.3 Report-only, and this is the whole design constraint

**The verb never decides that an unresolved symbol is a defect.** Whether it is
rot or a legitimate forward reference — a doc naming a thing it is about to
create — is a judgement, and the ROADMAP bullet is explicit that the verb must
not make it. ANTS-3659 is the live proof: while it was a draft, `exampleMask`,
`unterminatedExamples` and its whole test directory were unresolved and every
one of them was correct.

So: no severity, no "broken" wording, and `doc_lint` (ANTS-3663) must not
auto-fix any finding this verb emits. What the lookup buys is the *short list* —
the expensive part a reviewer cannot do cheaply — while the cheap part, deciding,
stays with them. § 1e already frames unresolved symbols as candidates for
exactly this reason.

It is also why ANTS-3659 is not a blocker for this verb: one designed to emit
unresolved symbols is not blocked on a suppression region. It ships without one
and simply reports more candidates.

### 2.4 Files and hooks

Engine `src/docsymbols.{h,cpp}` in `ants_core_lib`, Qt6::Core-only, consuming
`MarkdownScan` and `SymbolQuery`. Verb layer mirrors `doc_integrity`
(`src/remotecontrol.cpp::cmdDocIntegrity()`): a `cmdDocSymbols` handler plus
one pure static, `docSymbolsBuildResponse`.

**The `*.md` walk is REUSED, not cloned.** Earlier drafts of this section
specified a `docSymbolsEnumerate` copied from `docIntegrityEnumerate`; the
implementation calls `docIntegrityEnumerate` directly instead. It is already a
public pure static with exactly the required contract, and two enumerations
that must agree forever are two that will eventually disagree — CLAUDE.md § 3
prefers the direct call. The name stays `docIntegrity*` because it is that
verb's helper by origin; renaming it to something neutral is a follow-up worth
doing only if a third caller appears.

Registration is one `registerToolProvider` with `CallerCwdContract::Required` in
`src/mainwindow.cpp`, plus five `src/claudeintegration.cpp` hooks: the
`tools/list` entry, the token-cost row, the `kindForName` bucket
(`"workspace"`), `callerCwdContractFor` and `isEtagSupportedTool`.

**The registry-sourced exclusions are injected, not looked up — the engine
cannot see them.** `ants_core_lib` is Qt6::Core-only and the library dependency
runs core → claude, so `DocSymbols` **cannot** link `ClaudeIntegration`; a draft
that has the engine consult the verb catalogue directly does not build. The
engine therefore takes the set as data:

```cpp
struct Options {
    QSet<QString> excludedNames;   // verb names + schema args + refusal codes
    int maxSymbolsPerRun = 500;    // distinct needles; § 4
    int minIdentChars    = 5;
};

// Text in, candidates out, per the family convention ANTS-3664 § 2.3 fixes:
// the engine never opens the DOCUMENT under review (its text is handed in),
// which is what lets ANTS-3663 read each document once and serve all three
// native checkers from that one read.
//
// It does walk the SOURCE TREE, and that is the § 2.3 exception rather than a
// contradiction of it: resolution calls SymbolQuery::findDefinition, which
// needs the project root, so `rootCanonical` is injected alongside
// `excludedNames`. § 4 costs that walk.
ScanResult scan(const QString &text, const QString &relPath, const Options &opts = {});
```

**`cmdDocSymbols` cannot read the registry either, and that is one layer deeper
than loop 2 found.** `RemoteControl` also lives in `ants_core_lib`, so the verb
handler is as blind to `ClaudeIntegration` as the engine is. The only place that
sees both is `MainWindow`, which is where the injection is installed:
`RemoteControl::setMcpVerbVocabularyProvider` takes a `std::function<QStringList()>`,
`MainWindow` fills it with `ClaudeIntegration::registeredToolNames()` **from its
constructor, immediately after `m_remoteControl` is allocated**, and
`cmdDocSymbols` calls it per run. Reading it lazily rather than snapshotting
means a verb registered after that line is still covered.

**Where the install sits is a contract, not a detail (ANTS-3688).** The obvious
home is `setupClaudeMcpProviders()`, beside the registrations — and it is wrong,
because that function runs from `setupStatusBarChrome()` early in the
constructor, before `m_remoteControl` exists. Every other line in it survives
that ordering: `rcDelegate` captures `this` and dereferences `m_remoteControl`
lazily at call time. This setter needs the object *then*, so a guarded install
there is a silent no-op — the provider is never set, `excludedNames` falls back
to the refusal codes alone, and every MCP verb name becomes an
`unresolved_symbol`. It shipped that way and was found by measurement, not by a
test; `tests/features/doc_symbols_verb/` now asserts the ordering.

`registeredToolNames()` returns `m_toolProviders`' keys (`src/claudeintegration.h`,
a `std::map<QString, RegisteredTool>` populated by every `registerToolProvider`
call) plus the two verbs dispatched inline rather than registered
(`get_session_info`, `tool_info`), which are **not** in it — a registry read
alone would leave `tool_info` a permanent candidate in every doc that names it.
Refusal codes come from `docs/standards/mcp-error-codes.md`, parsed for
backticked snake_case runs; a project without that standard contributes none,
which is correct, since it has no such vocabulary.

**Schema argument names are the one source not yet wired, and this is a stated
gap rather than an oversight.** The `tools/list` payload is built inline inside
`ClaudeIntegration::onMcpConnection`, with no accessor returning it; extracting
one is a refactor of an ~8,000-line handler and its own item. Until then
`caller_cwd`, `etag_match` and their siblings surface as unresolved candidates.
§ 2.1's calibration run is exactly what decides whether that matters — if
schema arguments clear the 25% threshold there, the extraction is justified by
measurement instead of argument.

Because the set is a parameter, the engine's tests pass their own — INV-1's
fixture does not need a live registry to exercise the exclusion.

## 3. Invariants

- **INV-1** — A span is a candidate only if it matches § 2.1's production
  whole-span, with all **six** exclusions applied. *Test:* one fixture carrying
  `` `parseSpecBody` ``, `` `Foo::bar()` ``, `` `src/a.cpp` `` (path),
  `` `ok` `` (under the floor), `` `return` `` (keyword), `` `spec_query` ``
  (a verb name), `` `caller_cwd` `` (a schema argument), a fenced
  `` `Widget` ``, and a `` `Ghost` `` inside a `doc-examples` region → exactly
  the first two are candidates, with `excludedNames` supplied by the fixture per
  § 2.4. The last two rows are the ones a plausible implementation misses, and
  together they are the largest population in the corpus. `caller_cwd` is the
  sharper of the pair: at ten lowercase characters it **clears** the
  `minIdentChars` floor, so no other exclusion catches it.
- **INV-2** — A `::`-bearing candidate resolves on the text after its last
  `::`, and `symbol` echoes the span verbatim. *Test:* `` `Foo::bar` `` with a
  real `bar` → `resolution:"resolved"`, `symbol:"Foo::bar"`. The echo half matters:
  reporting the needle would make the finding un-greppable against the doc.
- **INV-3** — Every **unambiguous** candidate appears in `symbols[]` whether
  resolved or not, and only unresolved ones produce a `DocFinding`. *Test:* one
  resolving and one not → `symbols[]` length 2, `counts.resolved:1`, one
  finding, its `kind` `"unresolved_symbol"` and `autoFixable` false. INV-9 is
  the ambiguous half of the same rule; the fixture here is mixed-case on both
  rows so that the two are independently falsifiable.
- **INV-4** — `doc_symbols` emits no severity and no defect wording, and never
  marks a finding auto-fixable. *Test:* source-scrape `src/docsymbols.cpp` and
  the body of `RemoteControl::docSymbolsBuildResponse` for `severity`,
  `broken`, `invalid` and `autoFixable = true` → zero hits. A behavioural test
  cannot hold a claim about vocabulary, so this one is deliberately a scrape,
  in the `rc_get_text_byte_cap` idiom. The scrape covers the **implementation**
  and the response builder, not `src/docsymbols.h`: the header states the rule
  in prose, and a scrape that forbids naming the rule forbids documenting it.
- **INV-5** — Document order: `symbols[]` ascends by `doc_line` then `doc_col`,
  matching ANTS-3653 INV-33. *Test:* two candidates on one line and one earlier
  → line-then-column, stable across two runs.
- **INV-6** — The verb-contract minimum `mcp-tools.md` § Tests requires: a call
  with no `caller_cwd` refuses `caller_cwd_required`; a root-escaping `path`
  refuses `bad_path`; a well-formed non-existent in-root `path` is `ok:true`
  with empty `symbols[]`, matching ANTS-3601 INV-15. *Test:* three verb calls.
- **INV-7** — A needle the run never looked up is `not_checked`, never
  `unresolved`, and emits no finding. *Test:* two distinct candidates, neither
  resolvable, with `maxSymbolsPerRun` set to 1 → one occurrence `unresolved`
  with a finding, the other `not_checked` with none; `truncated:true`;
  `counts.not_checked:1`. Run the same fixture with the cap at its default →
  both `unresolved`, `truncated:false`, `counts.not_checked:0`. The second half
  is what makes the first falsifiable: without it an engine that reports
  everything `not_checked` passes.
- **INV-8** — Verb-layer row (ANTS-3688): the vocabulary provider is installed
  from `MainWindow`'s constructor, after `m_remoteControl` exists and before
  `setupClaudeMcpProviders()` is defined. *Test:*
  `DocSymbolsVerb.Inv8VocabularyProviderInstalledAfterRemoteControlExists`
  source-scrapes `mainwindow.cpp` for a single install site and asserts it
  against both offsets — the allocation and the registration function's
  definition. Both are needed: that function's definition sits later in the
  file than its call, so "after the allocation" alone is satisfied by the
  broken position. Stated with the rest of the verb-layer rows in
  `tests/features/doc_symbols_verb/spec.md`; listed here so § 3's numbering
  has no gap.
- **INV-9** — An ambiguous span (bare lowercase, no `::`, no `()`, no case
  boundary) reaches `symbols[]` only when it resolves; unresolved or
  `not_checked` it is dropped from `symbols[]` **and** `findings[]` (§ 2.1).
  *Test:* one fixture carrying a resolving bare lowercase name, a
  non-resolving one, and a non-resolving mixed-case one → `symbols[]` is the
  first and third, `counts.total:2`, exactly one finding and it names the
  mixed-case span. The third row is load-bearing: without it the rule is
  satisfied by suppressing every unresolved candidate, and INV-3 dies with it.
  The first is the guard against re-adopting a *shape* rule, which would drop
  shell, Python and Lua symbols wholesale.
- **INV-10** — Ambiguous needles are resolved last, and `truncated` reports an
  elided needle even when nothing about it reaches `symbols[]` (§ 2.2).
  *Test:* an ambiguous span first in document order followed by a
  non-resolving mixed-case one, `maxSymbolsPerRun` at 1 → `symbols[]` holds
  only the mixed-case span, `unresolved`, with `counts.not_checked:0` **and**
  `truncated:true`. Document order alone would have spent the single unit of
  budget on the ambiguous span, so the row falsifies both halves at once.

## 4. RAM / build cost

Per document: the fence mask and example mask (one `bool` per line each), the
span list, and the candidate list — all transient within one call, bounded by
`maxDocsPerRun` documents each capped at `maxDocBytes`, both enforced by the
verb layer's enumerate step, which reuses `DocIntegrity::Options`' values so the
two doc walks cost the same. They are deliberately **not** fields on
`DocSymbols::Options` (§ 2.4): the engine is handed the document text it should
scan and never walks a directory itself.

The real cost is resolution: one `SymbolQuery::findDefinition` per *distinct*
candidate, each a tree walk. Two bounds, both stated because neither is
optional: candidates are **de-duplicated by resolved needle before resolving**,
so a doc naming `parse` forty times pays one walk; and
**`maxSymbolsPerRun = 500`** caps the distinct set, setting `truncated:true`
past it. Without the first, a spec that mentions one symbol on every page would
walk the tree hundreds of times.

**What one walk costs.** `findDefinition` is called with an explicit
`SymbolQuery::Options`: `maxFiles` at its 5000 default and `maxResults` at 50.
The honest worst case is therefore 500 needles × 5000 files — 2.5 M file scans
in a single call — and a cap on needles alone does not bound wall-clock. So the
resolution phase also carries a **10 s deadline**. On expiry it stops resolving,
marks the remaining needles `not_checked`, and sets `truncated:true` — the same
flag `maxSymbolsPerRun` sets, because to a caller both mean the identical thing:
the run stopped asking. § 2.2 is why they are `not_checked` and not
`unresolved`; a cap that silently converted "not looked up" into "does not
exist" would make the honesty guarantee weakest exactly where the run is
largest. A deadline that fires is a calibration
signal, not a normal outcome; if the corpus sweep trips it, the cap is too high.

**The cap was gated at "≤ 250 distinct needles for the whole `docs/specs/` +
`docs/standards/` sweep". Measured, that sweep has 3,683 — fourteen times
over.** The gate did its job: the number it falsified is not the cap but the
sentence beside it, which called the full-corpus sweep "the run this verb is
built for".

It is not. Measured per document — which is how a reviewer actually calls this
verb, over one spec — the distinct-needle count is **median 20, worst 132, and
zero of 240 documents exceed the 500 cap.** So 500 is comfortably right for the
design point and hopeless for a 240-document sweep, and the honest correction
is to state the design point rather than raise the cap:

- **One document, or a handful, is the supported run.** There the cap never
  binds and every needle is looked up.
- **A full-corpus sweep truncates by design, and says so.** 11,774 of 12,723
  occurrences came back `not_checked` in the measured run. That is a
  disappointing answer but not a wrong one, which is the entire point of § 2.2's
  third state: before it existed this sweep would have reported eleven thousand
  symbols as *not existing*.

**Wall-clock is the real constraint, and it is tighter than the cap.** The
measured run resolved 949 needles in ~76 s — **~80 ms per distinct needle**,
each being a full tree walk, and an upper bound because the same 76 s also
covers scanning 240 documents. Against the 10 s deadline that is ~125 needles
per call, so for any document near the worst case the *deadline* governs and
`maxSymbolsPerRun` is never reached. A median document (20 needles) takes ~1.6 s
and completes; the worst (132) is marginal at ~10.6 s. Raising the cap would
therefore change nothing without a resolver that answers many needles in one
walk — filed as **ANTS-3680**, and the prerequisite for any corpus-wide sweep.

*(The per-needle figure previously read "~150 ms", which did not follow from the
1,016-needles-in-77 s measurement beside it — that arithmetic gives ~76 ms.
Recomputed here from the current run rather than carried forward.)*

Build cost is the family default (ANTS-3664 § 4), with no deviation.

## 5. Out of scope

- **Deciding defect vs forward reference** — § 2.3. The whole design constraint.
- **Signature checking.** "Does `foo()` still take two arguments" needs a parse,
  not a lookup, and `find_definition`'s anchors return a signature *string* it
  would have to interpret. The two corpus findings § 1 names were both existence
  failures, so v1 stops there.
- **Config keys, CLI flags, env vars.** `claude.mcp_enabled` and `--e2e` are
  backticked identifiers too, and resolving them means a different index per
  kind. Filed only when one is measured to rot.
- **Markdown outside `docs/`.** The walk matches `doc_integrity`'s: `docs_dir`
  by default, any in-root path on request.
- **A corpus-wide sweep.** § 4 measures it at ~13 minutes; it needs a resolver
  that answers many needles in one walk. Deferred: **ANTS-3680**.
- **Schema argument names as an injected exclusion.** No accessor returns the
  `tools/list` payload. Deferred: **ANTS-3679**.
