# ANTS-3661 — `doc_symbols`: resolve the identifiers a doc asserts something about

**Status:** spec draft, cold-eyes loop 1 folded (2026-07-27).
**Kind:** implement.
**Source:** ROADMAP.md ANTS-3661 (user-request-2026-07-27).
**Blocked by:** ANTS-3664 — the finding shape this emits.
**Composes with:** ANTS-3601 (`doc_integrity`, whose verb-layer walk this
copies), ANTS-3659 (the `doc-examples` region this honours) and ANTS-1303
(`find_definition`, whose resolver this calls rather than reimplements).
**Blocker for:** ANTS-3663 (`doc_lint`), which composes it.

**Layman:** Check that every function or class name a document mentions actually
exists in the code. It only ever *reports* — deciding whether a missing name is
a mistake or something the document is about to create is a person's call.

---

## 1. Problem

`/cold-eyes` § 1e calls this "the highest-yield check in the pre-pass" and names
its two worst corpus findings: a function documented as returning one thing when
it returned another, under a heading reading *"Verified API basis"*; and a test
seam a later reviewer's notes call *"fictional"*. Both were written from recall.
Both would have died at a symbol lookup. Both instead cost a cold-reader pass to
find and a redesign to fix.

This session produced a third, unprompted: `docs/standards/specs.md:236` states
`spec_query` surfaces a `*Test:*` clause as `test_surface`, and its bullet-form
branch does not (ANTS-3665). Nobody noticed until a grounding pass read the
parser. That is the same class — a doc asserting a behaviour of a named symbol
that the symbol does not have.

**The lookup is cheap and nothing does it today.** `find_definition` resolves
C++, Python, Lua, shell, GLSL and a generic family (`SymbolQuery::langForExt`,
`src/symbolquery.cpp::langForExt()`) but has no markdown path at all: it answers "where is
`Foo` defined", never "which names does this document claim exist". Harvesting
the question from prose is the new part; answering it is a call to
`SymbolQuery::findDefinition` (`src/symbolquery.h`).

## 2. Surface

### 2.1 What counts as a candidate

Harvest inline code spans via `MarkdownScan::codeSpans` (fence-aware, so a
```` ```cpp ```` sample is skipped), then keep a span only if its content
matches

```
candidate := ident ( "::" ident )* "()"?
ident     := [A-Za-z_][A-Za-z0-9_]*
```

after CommonMark's one-space strip, and the whole span is consumed by the match.
**Six** exclusions, each removing a population that would otherwise dominate the
output:

- **Anything containing `/` or `.`** — that is a path, and `doc_citations`
  (ANTS-3636) and `doc_integrity` (ANTS-3601) already own paths. A doc's
  `src/foo.cpp` must not be reported by two verbs with two vocabularies.
- **Spans inside a `doc-examples` region** (ANTS-3659) — a doc teaching symbol
  resolution names fictional symbols on purpose, exactly as it writes fictional
  paths. This verb honours the region; that ANTS-3659 § 2.1 left the policy per
  verb is what makes the answer a decision rather than an inheritance.
- **A single lowercase word shorter than `minIdentChars = 5`** — prose backticks
  `ok`, `path`, `kind` constantly, and a short lowercase run is far more often
  emphasis than an identifier. A `::`-bearing, `()`-bearing or mixed-case span is
  exempt from the floor, because those shapes are unambiguous. The floor is a
  real trade: it also drops `emit`, `exec`, `main` and `open`. Accepted, because
  a doc asserting something about one of those almost always writes it with `()`
  or a scope, and the alternative is a list dominated by prose emphasis.
- **The language keyword list** — `if`, `return`, `class`, `struct`, `null`,
  `true`, `false` and the rest. A doc backticks these while explaining code;
  none is a symbol anyone declared.
- **MCP verb names** — `spec_query`, `audit_run`, `roadmap_log` and the rest of
  the ~74-verb catalogue. **This is the largest population in this corpus and
  the one the first draft missed.** Applying § 2.1 by hand to
  `docs/standards/specs.md` § 3 harvests `spec_query`, `audit_run`, `LlmClient`,
  `implement`, `refactor` and `reaper` — and only `LlmClient` is a C++ symbol.
  Verb names are registered by *string* and declared nowhere, so every one of
  them resolves nowhere and would be reported forever; the `Kind:` taxonomy
  values (`implement`, `refactor`) are the same shape. Excluded against the live
  registry, not a static list, so a new verb never becomes a new false positive
  — see § 2.4 for how a Core-only engine gets at it.
- **Schema argument names and refusal codes** — `caller_cwd`, `max_findings`,
  `etag_match`, `bad_path`, `caller_cwd_required`, `mcp_disabled`. Backticked on
  nearly every page of this corpus, declared as JSON keys and string literals
  rather than as symbols, and so unresolvable forever — the same failure mode as
  verb names and, like them, missed by the first draft. Sourced the same way:
  each registered verb's schema property names, plus the taxonomy in
  `docs/standards/mcp-error-codes.md`. Grouped with verb names as one injected
  set (§ 2.4), since both come from the registry and neither is knowable to
  `ants_core_lib`.

**The exclusions are calibrated, not asserted.** Before the verb ships, run it
over `docs/standards/` and `docs/specs/` and record the measured
resolved/unresolved split in this section. A candidate list dominated by any one
population means an exclusion is missing — which is how both registry-sourced
cases were found, and both were found by a reviewer doing this by hand.

Everything surviving is a *candidate*, not an assertion. § 2.3 is why that word
matters.

### 2.2 Resolution and shape

Each candidate is resolved by `SymbolQuery::findDefinition(rootCanonical,
symbol, opts)` — the same ladder `find_definition` uses, unchanged. A candidate
bearing `::` is resolved on the text after its last `::`, matching the needle
rule ANTS-3654 § 2 established for anchors, so `Foo::bar` looks for `bar`.

The response carries every candidate **occurrence**, resolved or not:

```
symbols[]: { symbol, doc_line, doc_col, resolved, definitions[]? }
counts:    { total, resolved, unresolved }   // occurrences, not distinct needles
```

`doc_line` is 1-based and `doc_col` 0-based, converted from
`MarkdownScan::CodeSpan`'s 0-based `startLine`/`startCol` — the same convention
`DocCitations::Citation` uses, so the two doc verbs report positions the same
way.

**De-duplication is a resolution cache, not a filter on the output.** A doc
naming `parse` forty times yields forty `symbols[]` rows and **one** tree walk;
`counts.total` is forty. `maxSymbolsPerRun` caps the **distinct needle** set —
the thing that costs a walk — and sets `truncated:true`, which is why the two
numbers are not comparable and are named differently.

A candidate longer than 128 characters is dropped before resolution rather than
passed on: `SymbolQuery::isValidSymbol` (`src/symbolquery.h`) refuses it with
`bad_args`, and a harvest that fed it one would turn a prose oddity into a verb
refusal.

`definitions[]` is `find_definition`'s own `{file, line, signature, lang, kind}`
shape, present only when `resolved`. Unresolved candidates additionally become
`DocFinding::Finding` (ANTS-3664) with `verb:"doc_symbols"`,
`kind:"unresolved_symbol"`, `autoFixable:false`.

### 2.3 Report-only, and this is the whole design constraint

**The verb never decides that an unresolved symbol is a defect.** Whether it is
rot or a legitimate forward reference — a doc naming a thing it is about to
create — is a judgement, and the ROADMAP bullet is explicit that the verb must
not make it. ANTS-3659 is the live proof: while it was a draft, `exampleMask`,
`unterminatedExamples` and its whole test directory were unresolved and every
one of them was correct.

So: no severity, no "broken" wording, and `doc_lint` (ANTS-3663) must not
auto-fix any finding this verb emits. What the lookup buys is the *short list* —
the expensive part a reviewer cannot do cheaply — while the cheap part, deciding,
stays with them. § 1e already frames unresolved symbols as candidates for
exactly this reason.

It is also why ANTS-3659 is not a blocker for this verb: one designed to emit
unresolved symbols is not blocked on a suppression region. It ships without one
and simply reports more candidates.

### 2.4 Files and hooks

Engine `src/docsymbols.{h,cpp}` in `ants_core_lib`, Qt6::Core-only, consuming
`MarkdownScan` and `SymbolQuery`. Verb layer mirrors `doc_integrity` exactly
(`src/remotecontrol.cpp::cmdDocIntegrity()`): a `cmdDocSymbols` handler plus two pure statics
— `docSymbolsEnumerate` (the `QDirIterator` walk over `*.md`, cloned from
`docIntegrityEnumerate` at `:12317`) and `docSymbolsBuildResponse`. Registration
is one `registerToolProvider` with `CallerCwdContract::Required` in
`src/mainwindow.cpp`, plus five `src/claudeintegration.cpp` hooks: the
`tools/list` entry, the token-cost row, the `kindForName` bucket
(`"workspace"`), `callerCwdContractFor` and `isEtagSupportedTool`.

**The registry-sourced exclusions are injected, not looked up — the engine
cannot see them.** `ants_core_lib` is Qt6::Core-only and the library dependency
runs core → claude, so `DocSymbols` **cannot** link `ClaudeIntegration`; a draft
that has the engine consult the verb catalogue directly does not build. The
engine therefore takes the set as data:

```cpp
struct Options {
    QSet<QString> excludedNames;   // verb names + schema args + refusal codes
    int maxSymbolsPerRun = 500;    // distinct needles; § 4
    int minIdentChars    = 5;
};
```

`cmdDocSymbols` fills `excludedNames` at the verb layer, where the registry is
visible: `ClaudeIntegration::m_toolProviders`
(`src/claudeintegration.h`, a `std::map<QString, RegisteredTool>` populated
by every `registerToolProvider` call) gives the verb names as its keys, each
entry's `tools/list` schema gives the argument names,
and `docs/standards/mcp-error-codes.md` gives the refusal codes. Two consequences
worth stating rather than discovering: the handful of verbs dispatched inline
rather than registered (`get_session_info`, `tool_info`) are **not** in that
registry and must be added explicitly; and because the set is a parameter, the
engine's tests pass their own — INV-1's fixture does not need a live registry to
exercise the exclusion.

## 3. Invariants

- **INV-1** — A span is a candidate only if it matches § 2.1's production
  whole-span, with all **six** exclusions applied. *Test:* one fixture carrying
  `` `parseSpecBody` ``, `` `Foo::bar()` ``, `` `src/a.cpp` `` (path),
  `` `ok` `` (under the floor), `` `return` `` (keyword), `` `spec_query` ``
  (a verb name), `` `caller_cwd` `` (a schema argument), a fenced
  `` `Widget` ``, and a `` `Ghost` `` inside a `doc-examples` region → exactly
  the first two are candidates, with `excludedNames` supplied by the fixture per
  § 2.4. The last two rows are the ones a plausible implementation misses, and
  together they are the largest population in the corpus. `caller_cwd` is the
  sharper of the pair: at ten lowercase characters it **clears** the
  `minIdentChars` floor, so no other exclusion catches it.
- **INV-2** — A `::`-bearing candidate resolves on the text after its last
  `::`, and `symbol` echoes the span verbatim. *Test:* `` `Foo::bar` `` with a
  real `bar` → `resolved:true`, `symbol:"Foo::bar"`. The echo half matters:
  reporting the needle would make the finding un-greppable against the doc.
- **INV-3** — Every candidate appears in `symbols[]` whether resolved or not,
  and only unresolved ones produce a `DocFinding`. *Test:* one resolving and one
  not → `symbols[]` length 2, `counts.resolved:1`, one finding, its `kind`
  `"unresolved_symbol"` and `autoFixable` false.
- **INV-4** — `doc_symbols` emits no severity and no defect wording, and never
  marks a finding auto-fixable. *Test:* source-scrape the engine for
  `severity`, `broken`, `invalid` and `autoFixable = true` → zero hits. A
  behavioural test cannot hold a claim about vocabulary, so this one is
  deliberately a scrape, in the `rc_get_text_byte_cap` idiom.
- **INV-5** — Document order: `symbols[]` ascends by `doc_line` then `doc_col`,
  matching ANTS-3653 INV-33. *Test:* two candidates on one line and one earlier
  → line-then-column, stable across two runs.
- **INV-6** — The verb-contract minimum `mcp-tools.md` § Tests requires: a call
  with no `caller_cwd` refuses `caller_cwd_required`; a root-escaping `path`
  refuses `bad_path`; a well-formed non-existent in-root `path` is `ok:true`
  with empty `symbols[]`, matching ANTS-3601 INV-15. *Test:* three verb calls.

## 4. RAM / build cost

Per document: the fence mask and example mask (one `bool` per line each), the
span list, and the candidate list — all transient within one call, bounded by
`maxDocsPerRun` documents each capped at `maxDocBytes`, both inherited from
`DocIntegrity::Options`' values so the two doc walks cost the same.

The real cost is resolution: one `SymbolQuery::findDefinition` per *distinct*
candidate, each a tree walk. Two bounds, both stated because neither is
optional: candidates are **de-duplicated by resolved needle before resolving**,
so a doc naming `parse` forty times pays one walk; and
**`maxSymbolsPerRun = 500`** caps the distinct set, setting `truncated:true`
past it. Without the first, a spec that mentions one symbol on every page would
walk the tree hundreds of times.

The 500 is a ceiling, not a target, and is calibrated against the same measured
run § 2.1 requires: the largest spec in this corpus is ~1,100 lines, and the
whole `docs/specs/` + `docs/standards/` sweep is the run this verb is built for.
If that sweep's distinct-needle count lands within an order of magnitude of 500,
the cap is wrong and the calibration step is where that surfaces — record the
measured number beside the split.

One new translation unit in `ants_core_lib`; one new feature-test source into an
existing bundle. No new external dependency.

## 5. Out of scope

- **Deciding defect vs forward reference** — § 2.3. The whole design constraint.
- **Signature checking.** "Does `foo()` still take two arguments" needs a parse,
  not a lookup, and `find_definition`'s anchors return a signature *string* it
  would have to interpret. The two corpus findings § 1 names were both existence
  failures, so v1 stops there.
- **Config keys, CLI flags, env vars.** `claude.mcp_enabled` and `--e2e` are
  backticked identifiers too, and resolving them means a different index per
  kind. Filed only when one is measured to rot.
- **Markdown outside `docs/`.** The walk matches `doc_integrity`'s: `docs_dir`
  by default, any in-root path on request.

**Verified RED against feature-absent code before the implementation lands.**
INV-1's exclusions are the rows that pass trivially against an engine that
harvests nothing, so they are re-proven by mutation once the harvest exists —
**six mutations, one per exclusion**: drop the path filter, drop the region
check, drop the length floor, drop the keyword list, and drop each half of the
injected set (empty `excludedNames` covers the verb-name and schema-argument
rows together, so it is run once and expected to turn *two* rows red). Record
what the runs actually produce, including any mutation that turns nothing red,
as `tests/features/doc_citations_examples/spec.md` does — that spec's own run
found three predictions wrong, so the recording is the point, not the ceremony.

## 7. Cross-doc impact

- **ANTS-3664** is a blocker; this verb emits `DocFinding::Finding` natively.
- **ANTS-3663** composes this verb and must respect § 2.3 — no auto-fix of a
  `doc_symbols` finding, ever.
- **`docs/standards/mcp-tools.md`** — no change; this follows the checklist
  rather than altering it.
- **`docs/subsystems.md`** — `src/docsymbols.{h,cpp}` joins `ants_core_lib`.
- **`/cold-eyes` § 1e** already describes this check and already frames
  unresolved symbols as candidates. When the verb ships, § 1e names it beside
  its existing hand-rolled fallback — the skill is global and this verb is not
  (ANTS-1581), so the fallback sentence stays.
