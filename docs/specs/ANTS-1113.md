# ANTS-1113 — Fold `/debt-sweep` into the Project Audit tool

**Status:** shipped (v2, ANTS-1259). Ship-ready after 3-loop
cold-eyes convergence (2026-05-13); § 3.5 later re-synced to the
ANTS-3342 window-scoping in a loop-4 maintenance pass (2026-07-13).
Loop-by-loop fixes documented at end of file (§ 11).
**Source:** ROADMAP.md ANTS-1113; ADR-0002 dec 8 relaxed by
[ADR-0003](../decisions/0003-cc-fold-relax-gate-and-draw-boundary.md).
**Blocked by:** none — RoadmapFoldIn ships in ANTS-1111 v1 (0.7.88),
templated fold-in pattern shipped in ANTS-1112 v1 (0.7.89).
**Boundary:** see ADR-0003 dec 2 (per-surface table). ANTS-1113 owns
the engine + 4 MCP tools; the AuditDialog "Debt Sweep" tab is v2 work
(tracked under ANTS-1259).

## 1. Problem

`/debt-sweep` today (`~/.claude/skills/debt-sweep/SKILL.md`) runs
end-to-end inside the parent Claude Code session: it scopes the diff
range, probes the project layout, dispatches a single subagent with a
~2 K-token brief covering 5 categories, the subagent reads the diff
and project files inline, classifies findings into trivial /
behavioural / out-of-scope buckets, and Claude triages + applies the
trivial bucket. **Per /debt-sweep run cost: ~30-80 K orchestrator
tokens** — most of it is the subagent reading project files (CHANGELOG,
ROADMAP, README, version-bearing packaging files, every spec.md
under `tests/features/`) every single time it runs.

The mechanical halves of this pipeline — scanning for stale type
references, parsing INV-N markers, diffing CHANGELOG against `git
diff`, running the version-drift script, computing
roadmap/commit-mention discrepancies — need no judgment. They're
deterministic file IO and regex. Only the per-finding *judgment*
("is this stale comment merely terse, or actually wrong?") and the
optional cross-cutting *triage* genuinely require an LLM, and only
on the small subset of findings that survive the mechanical filter.

ANTS-1113 v1 lifts the mechanical halves into Ants as **MCP tools**,
following the same pattern as ANTS-1111 v1 (audit fold) and
ANTS-1112 v1 (indie-review fold). The orchestrator (Claude or any
MCP client) calls them; the per-finding triage continues to live in
optional Claude calls. Token saving per run: estimated 15-40 K
orchestrator tokens (subagent never opens 95% of the project files;
findings come back as pre-classified JSON instead of free-form
prose).

A future v2 (tracked under ANTS-1259) adds a "Debt Sweep" tab to
the Project Audit dialog with **Fix inline** / **Defer to ROADMAP** /
**Allow** buttons per finding, plus a "Triage with AI" button that
sends only the LLM-shaped tail through aidialog. v1 ships the engine
+ MCP surface only; the tab follows in a separate release.

### 1.2 v2 shipped (ANTS-1259, 2026-05-21)

The AuditDialog "Debt Sweep" tab landed. The single-pane dialog is now a
two-tab `QTabWidget` (Audit | Debt Sweep). The Debt Sweep tab:

- **🧹 Scan for debt** → `debtScan()` runs `DebtSweepEngine::scanAll`,
  drops entries already in `.audit_allowlist.json` (the engine doesn't
  consult the allowlist, so the dialog filters), and renders the
  survivors grouped by the four canonical categories.
- Per-finding **[fix]** (auto-fixable only) → `debtFixInline` →
  `applyMechanicalFix`, then re-scan.
- Per-finding **[defer]** / **📌 Defer all** → `debtDeferToRoadmap` →
  allocateIds + `templateDebtSweepFoldInBlock` + insertBlock (heading
  pre-flighted so a misclick doesn't burn IDs).
- Per-finding **[allow]** → `debtAllow` → reuses the ANTS-1257
  `appendAllowlistEntry` machinery (rule = detectorId) so the finding
  stays hidden across scans.
- **🧠 Triage with AI** → `debtTriagePrompt` (the non-mechanical tail)
  dispatched one-shot via `LlmClient` (ANTS-1727); the response renders
  in the debt pane. Token-spend gated behind a confirmation.

Tab orchestration is tested by `tests/features/debt_sweep_dialog/`
(INV-D1..D4). The README-CLI-flag-drift detector mentioned in the
ROADMAP bullet is **not** part of this ship — it is unspecced here (the
§1.1 v2 row is the tab only) and needs a binary-execution shim; tracked
separately if pursued.

## 2. Surface

### 2.1 Engine API (`src/debtsweepengine.{h,cpp}`)

```cpp
namespace DebtSweepEngine {

// One detector finding. The `category` field is one of the four
// canonical category strings (see § 3); `id` is a stable detector
// identifier (e.g. "stale_type_comment"); `autoFixable` is true iff
// applyMechanicalFix can land the suggested edit without asking.
struct Finding {
    QString category;     // "code_drift" | "test_coverage" |
                          // "doc_drift" | "packaging_drift"
    QString detectorId;   // e.g. "stale_type_comment", "orphan_q_unused"
    QString file;         // project-relative
    int     line = -1;    // 1-based; -1 for file-level
    QString message;      // one-line human description
    QString suggestedFix; // edit text or "" if no mechanical fix
    bool    autoFixable = false;
};

// Scope: which commit range to inspect for window-scoped detectors
// (added TODOs, CHANGELOG diff, ROADMAP shipped-without-commit). When
// `sinceRef` is empty the engine uses `git describe --tags --abbrev=0`
// (most-recent annotated tag); if no tag exists, falls back to
// `HEAD~10`. Detectors that scan the whole tree (orphan Q_UNUSED)
// ignore sinceRef.
struct ScanOptions {
    QString sinceRef;     // empty → auto-detect
    bool    includeCodeDrift = true;
    bool    includeTestCoverage = true;
    bool    includeDocDrift = true;
    bool    includePackagingDrift = true;
};

// Per-detector pure functions. Each returns the findings it
// produced; they're combined by scanAll() but exposed individually
// for invariant tests + future selective dispatch.

// Code drift (a) — comments that name a type/symbol no longer
// present in the project source blob. Walks `git diff
// <sinceRef>..HEAD --name-only -- '*.cpp' '*.h' '*.py' '*.js'
// '*.ts' '*.tsx'` (extension list MUST match § 3.1 step 2);
// extracts `// …` and `/* … */` comments from those files;
// for each identifier-shaped backtick or quoted token in the
// comment, looks it up in the project source blob (same blob
// builder as featurecoverage.cpp). Reports tokens that don't
// resolve.
QList<Finding> detectStaleTypeComments(
    const QString &projectPath, const ScanOptions &opt);

// Code drift (c) — TODO / FIXME markers added in scope. Diffs
// `<sinceRef>..HEAD` and reports any new line containing
// `\b(TODO|FIXME|XXX|HACK)\b:` that wasn't in the baseline.
// Excludes NOTE: + the file's own copyright block.
QList<Finding> detectAddedTodos(
    const QString &projectPath, const ScanOptions &opt);

// Code drift (d) — `Q_UNUSED(x)` / `(void)x;` / Python `_unused`
// markers wrapping an undeclared variable. Per-file pass: extract
// the marker arg `x`, then check the same file for any
// declaration of `x` (`auto x`, `int x`, `const Foo &x`, function
// param `Foo x`, etc.). Reports markers whose target isn't
// declared anywhere in the file.
QList<Finding> detectOrphanQUnused(
    const QString &projectPath, const ScanOptions &opt);

// Test coverage gap — INV-N markers in `tests/features/*/spec.md`
// without a matching `INV-N` reference in the corresponding
// `test_*.cpp` / `test_*.py`. Per-feature-dir pass: for each
// `<dir>/spec.md`, extract `\bINV-([0-9][0-9a-zA-Z]*)\b` markers
// (numeric leader + optional alphanumeric tail — covers `INV-7` and
// the `INV-8b` shape that ANTS-1111 spec uses); for each, check
// `<dir>/test_*` for a literal `INV-<id>` mention. Reports
// unmatched markers as line-pinned findings on spec.md.
QList<Finding> detectMissingInvariantTests(
    const QString &projectPath, const ScanOptions &opt);

// Doc drift (a) — ROADMAP ✅ items flipped to shipped within the
// `sinceRef..HEAD` window whose stable ID isn't mentioned in any
// commit subject in `git log --all --format=%s`. Diffs ROADMAP.md
// over the window and keeps IDs whose `- ✅ [ANTS-NNNN]` line was
// added-but-not-also-removed (a bare remove+add is a reorder, not a
// fresh flip), then runs the git log and reports those in-window IDs
// with zero subject mentions. Self-disables on non-git checkouts /
// empty windows. See § 3.5.
QList<Finding> detectRoadmapShippedWithoutCommit(
    const QString &projectPath, const ScanOptions &opt);

// Doc drift (b) — CHANGELOG `[Unreleased]` bullets that reference
// a file path not present in `git diff <sinceRef>..HEAD --name-only`.
// Per-bullet: extract backtick-fenced filename tokens (`foo.cpp`,
// `src/bar.h`); flag bullets where none of the cited paths are in
// the diff. Self-disables if CHANGELOG.md has no `[Unreleased]`
// section.
QList<Finding> detectChangelogStaleBullets(
    const QString &projectPath, const ScanOptions &opt);

// Packaging drift — wraps `bash packaging/check-version-drift.sh`
// (the existing audit rule's shell entry-point). Parses the
// `file:line: <label> version <got> drifts from CMakeLists.txt
// <truth>` stdout into Finding structs. Self-disables silently
// when the script is absent or non-executable. NOT marked
// autoFixable — the fix is "re-run /bump", not a single-line
// edit.
QList<Finding> runPackagingDrift(
    const QString &projectPath, const ScanOptions &opt);

// Convenience: run every enabled detector and concatenate. Order
// is the canonical category order (code, test, doc, packaging).
// Within each category, detectors run in declaration order.
QList<Finding> scanAll(
    const QString &projectPath, const ScanOptions &opt);

// Apply ONE mechanical fix in-place. Caller passes the Finding
// (returned from scanAll); engine performs the suggested edit
// via QSaveFile (atomic). Returns a verdict struct so the MCP
// handler can disambiguate "no-op because file changed" from
// "no-op because IO error" without inspecting QFile errno state.
struct ApplyVerdict {
    bool    applied = false;          // true iff the file was mutated
    QString errorCode;                // "" on success or expected no-op;
                                      // "not_fixable" / "file_changed" /
                                      // "io_error" on failure
    QString errorMessage;             // human-readable detail; empty on success
};
ApplyVerdict applyMechanicalFix(
    const QString &projectPath, const Finding &finding);

// Fold-into-roadmap block template. Mirrors
// AuditEngine::templateRoadmapFoldInBlock + IndieReviewEngine::
// templateIndieReviewFoldInBlock. Heading is `### 🧹 Debt-sweep
// fold-in (DATE)` per roadmap-format.md § 3.8 (subsection
// pattern); per-bullet `Kind:` and `Source:` are `chore` and
// `debt-sweep-DATE` respectively per § 3.5.3 (Kind/Source
// taxonomy). Caller pre-allocates IDs via
// RoadmapFoldIn::allocateIds.
QString templateDebtSweepFoldInBlock(
    const QList<Finding> &deferred,
    const QList<int> &allocatedIds,
    const QString &dateIso,
    const QString &idPrefix);

// Pure string templating of an LLM triage prompt. Combines:
//   - the LLM-shaped subset of findings (the ones with no
//     suggestedFix; the engine cannot judge)
//   - per-category guidance (the "judgment column" from the
//     ROADMAP table — e.g. "Is this stale comment actually
//     wrong, or merely terse?")
// Caller dispatches via aidialog (v2) or Claude (v1). Pure
// string concatenation; no LLM call inside the engine.
QString triagePrompt(
    const QList<Finding> &llmShaped);

}  // namespace DebtSweepEngine
```

### 2.2 MCP tools (registered via `registerToolProvider`)

4 new tools added to ClaudeIntegration `tools/list`. Each follows
the ANTS-1253 registry pattern AND the ANTS-1112 dual-surface
convention:

- **Implementation layer:** one `RemoteControl::cmdDebtSweepX`
  method per tool (declared in `remotecontrol.h`, defined in
  `remotecontrol.cpp` — see `mainwindow.cpp:3696-3700` /
  `remotecontrol.cpp:1885+` for the ANTS-1112 precedent).
- **Registration layer:** one `m_claudeIntegration->registerToolProvider(name, lambda)`
  call per tool in `MainWindow::setupClaudeMcpProviders`, where
  the lambda dispatches to the matching `m_remoteControl->cmdDebtSweepX(args)`.

The dual-surface pattern is intentional: the `RemoteControl::cmdX`
method is callable from the legacy Unix-socket IPC path AND from
MCP via the lambda, with no code duplication. Spec § 6's
`+~250 LoC` budget for `remotecontrol.{h,cpp}` covers the four
`cmdDebtSweepX` methods; § 6's `+~100 LoC` budget for
`mainwindow.cpp` covers the four `registerToolProvider` lambdas.

| Tool | Input | Output (envelope) |
|---|---|---|
| `debt_sweep_scan` | `{since?: "<ref>", categories?: ["code_drift", "test_coverage", "doc_drift", "packaging_drift"]}` (omitted = all) | `{ok, findings:[{category, detector_id, file, line, message, suggested_fix, auto_fixable}], total_findings, by_category:{code_drift: N, …}, since_resolved}` |
| `debt_sweep_apply_fix` | `{detector_id, file, line}` (the triple uniquely identifies a Finding from the most recent scan) | `{ok, applied: bool, error_code?, error?}` — `ok` is true even when `applied` is false IF the engine returned a recognised no-op (`error_code == "file_changed"` or `"not_fixable"`); `ok` is false only on `error_code == "io_error"` (with `error` populated). |
| `debt_sweep_defer` | `{deferred:[{category, detector_id, file, line, message}], date_iso?: <today>, release_block_heading?: <auto>}` | `{ok, block, allocated_ids, written: bool}` — `block` and `allocated_ids` are ALWAYS populated when `ok:true` (so a `written:false` caller can fall back to writing the block manually). `written:false` happens when `release_block_heading` is omitted AND `RoadmapFoldIn::findActiveReleaseHeading(projectPath)` returns empty (no recognisable release block) — this is NOT an error, just a not-yet-written state. `written:true` iff a heading was resolved AND `RoadmapFoldIn::insertBlock` succeeded. The standard `{ok:false, error, code}` envelope applies on hard failures (counter allocation IO error, malformed input). **ID-leak note:** `RoadmapFoldIn::allocateIds` bumps `.roadmap-counter` eagerly (before the heading-resolve / insertBlock attempt). When `written:false` the IDs are still reserved (a re-run won't double-allocate). The cost is the reserved-but-never-used slot in the ID space — same trade-off as ANTS-1111 § 2.5 documented for `audit_fold_in`. The handler does NOT roll back the counter on `written:false`; the allocated IDs stay live in the returned `block` so the caller can splice manually. |
| `debt_sweep_triage_prompt` | `{findings:[{category, detector_id, file, line, message}]}` (the LLM-shaped subset, caller-filtered) | `{ok, prompt, byte_count}` |

**Project-path resolution.** All four tools resolve the active
project via `MainWindow::currentTerminal()->shellCwd()` (the focused
TerminalWidget's cwd, accessed via the existing
`resolveRootCanonical(m_main)` helper declared at
`remotecontrol.cpp:1040`)
— same convention as `git_state`, `subsystem`, `last_audit_summary`,
`indie_review_*`. The input objects do not carry an explicit
`projectPath`; if no terminal is focused or its cwd is empty, the
envelope is `{ok: false, error, code: "no_project"}`.

All four envelope `{ok: false, error, code}` on failure (matches
the existing MCP convention from ANTS-1248..1252).

## 3. Algorithm

### 3.1 detectStaleTypeComments

1. Resolve `sinceRef` (auto via `git describe --tags --abbrev=0` if
   empty; `HEAD~10` if no tags).
2. Run `git diff <sinceRef>..HEAD --name-only -- '*.cpp' '*.h'
   '*.py' '*.js' '*.ts' '*.tsx'`. Cap at 500 paths (defensive — a
   massive diff would explode the comment scan).
3. Build the project-wide source blob. **The helpers do not exist
   yet — three new public surfaces in `featurecoverage.h`:**
   (a) lift the inline blob build at `featurecoverage.cpp:269-339`
   into `FeatureCoverage::buildProjectSourceBlob(const QString
   &projectPath)` returning the concatenated UTF-8 blob (extension
   list + skip-dir set carried over verbatim; `spec.md` exclusion
   carried over);
   (b) lift the local `existsInSource` lambda
   (`featurecoverage.cpp:341-368`) into a public free function
   `FeatureCoverage::existsInSource(const QString &blob, const
   QString &token)` retaining the substring-containment check plus
   the `::` and `.` tail-fallbacks unchanged;
   (c) expose the existing internal `stopwords()` helper
   (`featurecoverage.cpp:22-34`) via a public accessor
   `FeatureCoverage::specStopwords()` returning `const QSet<QString> &`
   so debtsweepengine can consume `kSpecStopwords` without copying
   the literal set.
   Update `runSpecDriftCheck` to call (a) + (b) + the existing
   `stopwords()` (which now becomes a thin shim over
   `specStopwords()`). The blob includes config / docs too — same
   rationale as Lane 1 (filename + package-name resolution).
4. For each diff file, read it; extract every `//`-line-comment and
   every `/* … */` block-comment body. Skip the first 12 lines
   (typical license / copyright block — would generate false
   positives on author names, URLs).
5. Within each comment body, extract identifier-shaped tokens via
   a new bare-token regex (NOT `extractSpecTokens`, which only
   matches backtick-fenced tokens — `featurecoverage.cpp:96`):
   `\b([A-Z][A-Za-z0-9_]{3,})\b` (capitalised CamelCase ≥ 4 chars,
   identifier-shaped). The capitalisation requirement is
   deliberate — bare lowercase words in comments are usually prose,
   not type names; restricting to leading-capital cuts false
   positives by ~95% in practice. Drop tokens in
   `FeatureCoverage::kSpecStopwords` (caller exposes the existing
   stop-set via the new helper extraction in step 3).
6. For each surviving token, look it up in the project source blob
   via `FeatureCoverage::existsInSource(blob, token)` (the new
   helper from step 3; substring containment + `::` and `.`
   tail-fallbacks). Tokens that don't resolve → emit a Finding:
   - `category = "code_drift"`, `detectorId = "stale_type_comment"`
   - `file = <relpath>`, `line = <comment line>`
   - `message = "comment references \`<tok>\` but no match in project source"`
   - `suggestedFix = ""` (caller decides — could be edit comment
     or delete comment; engine doesn't judge)
   - `autoFixable = false`

### 3.2 detectAddedTodos

1. `git diff <sinceRef>..HEAD --unified=0 -- '*.cpp' '*.h' '*.py'
   '*.js' '*.ts' '*.tsx' '*.go' '*.rs'`. Cap stdout at 1 MiB
   (defensive).
2. Parse the diff: track current file + line number from
   `+++ b/<path>` and `@@ -A,B +C,D @@` chunks.
3. For each `+` line (added), check for `\b(TODO|FIXME|XXX|HACK)\b:`.
   Hits → Finding:
   - `category = "code_drift"`, `detectorId = "added_todo"`
   - `file`, `line` (post-image line)
   - `message = "<MARKER>: …"` (truncate at 80 chars)
   - `suggestedFix = ""`, `autoFixable = false`

### 3.3 detectOrphanQUnused

1. `git ls-files '*.cpp' '*.h'` (cap 5000). Self-disables for
   non-git checkouts.
2. For each file, scan for these markers:
   - `Q_UNUSED\(\s*([A-Za-z_][A-Za-z0-9_]*)\s*\)`
   - `\(void\)\s*([A-Za-z_][A-Za-z0-9_]*)\s*;`
3. For each marker, extract the variable name. Then check the same
   file for any declaration: any of these regexes matching with
   `<varname>` substituted:
   - `\b(?:auto|int|bool|float|double|char|short|long|size_t|const)\b[^;{=]*\b<varname>\b`
   - `\b[A-Z][A-Za-z_0-9]*\s*[*&]?\s*<varname>\b\s*[;,)=]` (typed
     decl / param)
   - `\b(?:lambda|capture)\s*\[[^\]]*\b<varname>\b` (lambda capture)
4. If no declaration matches → orphan. Emit Finding:
   - `category = "code_drift"`, `detectorId = "orphan_q_unused"`
   - `file`, `line` (marker line)
   - `message = "Q_UNUSED(<var>) — no declaration of <var> in this file"`
   - `suggestedFix = "<delete the marker line>"`
   - `autoFixable = true` (mechanical: delete one line)

### 3.4 detectMissingInvariantTests

1. Walk `<projectPath>/tests/features/*/`.
2. For each subdir with a `spec.md`:
   - Read `spec.md`; extract `\bINV-([0-9][0-9a-zA-Z]*)\b` markers
     (line-pinned). Numeric leader + optional alphanumeric tail
     covers `INV-7` and `INV-8b` (the latter is used in ANTS-1111
     spec § 4 today).
   - List the subdir's other files matching `test_*.cpp` /
     `test_*.py` / `test_*.js` / `test_*.go` / `test_*.rs`.
   - Read those test files; concatenate; for each INV-id from
     spec.md, check the concatenated text for `INV-<id>`.
   - Unmatched INV-id → Finding:
     - `category = "test_coverage"`, `detectorId = "missing_inv_test"`
     - `file = <relpath to spec.md>`, `line = <marker line>`
     - `message = "INV-<id> declared in spec.md but no test_*.cpp/py/js/go/rs in this dir mentions it"`
     - `suggestedFix = ""`, `autoFixable = false`
3. Self-disables silently when `tests/features/` is missing.

### 3.5 detectRoadmapShippedWithoutCommit

1. Window-scope the candidates (ANTS-3342). Resolve `since` (`sinceRef`,
   else the last tag, else `HEAD~10`) and run
   `git diff --unified=0 <since>..HEAD -- ROADMAP.md`. Empty diff →
   return empty (empty window, or not a git checkout). Collect the IDs
   whose `^- ✅ \[(ANTS-\d+)\]` line was **added** but not also **removed**
   in that diff — i.e. items *flipped to ✅ within the window*. A bare
   remove+add of an already-✅ line is a position-is-priority reorder, not
   a fresh flip, so it is excluded. Without this the detector re-checked
   every ✅ item in the whole ROADMAP against the log, re-surfacing ~433
   pre-convention shipped items (IDs that predate the commit-subject
   convention and so never appear in any commit) on every sweep.
2. Scan the live `<projectPath>/ROADMAP.md`. For each line matching
   `^- ✅ \[(ANTS-\d+)\]` whose ID is in the in-window set from step 1,
   capture the ID + line number.
3. Run `git log --all --format=%s`. Cap stdout at 4 MiB (an Ants
   Terminal repo at 0.7.90 has ~600 commits = ~30 KiB).
4. For each captured ID, check the log for any subject containing the
   literal ID string. IDs with zero matches → Finding:
   - `category = "doc_drift"`, `detectorId = "shipped_without_commit"`
   - `file = "ROADMAP.md"`, `line = <captured line>`
   - `message = "<ID> is ✅ in ROADMAP but no commit subject mentions it"`
   - `suggestedFix = ""`, `autoFixable = false` (the fix is either
     an amendment or a status flip — engine can't tell which)

### 3.6 detectChangelogStaleBullets

1. Read `<projectPath>/CHANGELOG.md`. Find the `## [Unreleased]`
   header. If absent, return empty list (silent self-disable —
   matches the existing `runChangelogCoverageCheck` pattern).
2. Within the `[Unreleased]` block (until the next `## ` header),
   collect bullets per `extractTopVersionBullets`
   (`featurecoverage.cpp:137`). **The reuse hinges on
   Keep-a-Changelog convention placing `[Unreleased]` as the
   topmost `## ` block** — `extractTopVersionBullets` always
   selects the FIRST `## ` header it sees and stops at the second.
   If `[Unreleased]` is not the top section, this detector
   self-disables (returns empty list) per § 3.6 step 1.
   Verify the convention holds with a one-liner check: `grep -n
   '^## \[Unreleased\]' CHANGELOG.md | head -1` returns line < the
   line of the first `## [N.N.N]` header.
3. Run `git diff <sinceRef>..HEAD --name-only`. Cap 500 paths.
4. For each bullet, extract backtick-fenced filename-shaped tokens
   via `featurecoverage::extractBacktickTokens`, filtered to those
   matching `^[a-zA-Z0-9_./-]+\.(cpp|h|md|json|yml|yaml|py|sh)$`.
5. If the bullet has at least one such token AND none of the cited
   paths are in the diff → Finding:
   - `category = "doc_drift"`, `detectorId = "stale_changelog_bullet"`
   - `file = "CHANGELOG.md"`, `line = <bullet line>`
   - `message = "[Unreleased] bullet cites \`<token>\` but it's not in git diff <sinceRef>..HEAD"`
   - `suggestedFix = ""`, `autoFixable = false`

### 3.7 runPackagingDrift

1. Check `<projectPath>/packaging/check-version-drift.sh` is
   regular file + executable. If not → return empty (silent
   no-op, matches the existing `packaging_version_drift` audit
   rule's behaviour).
2. Run `bash packaging/check-version-drift.sh` with cwd =
   projectPath. 30 s timeout. Stdout cap 1 MiB.
3. Parse stdout per the script's documented format
   (`<file>:<line>: <label> version <got> drifts from
   CMakeLists.txt <truth>`):
   - `category = "packaging_drift"`, `detectorId = "version_drift"`
   - `file`, `line` from the parse
   - `message` = the part after `<line>: `
   - `suggestedFix = ""`, `autoFixable = false` (fix is to re-run
     /bump; not a single-line edit)

### 3.8 scanAll

1. Initialize empty `QList<Finding> out`.
2. For each enabled category in `opt`, run the detectors in this
   order:
   - **code_drift:** detectStaleTypeComments,
     detectAddedTodos, detectOrphanQUnused
   - **test_coverage:** detectMissingInvariantTests
   - **doc_drift:** detectRoadmapShippedWithoutCommit,
     detectChangelogStaleBullets
   - **packaging_drift:** runPackagingDrift
3. Concatenate findings into `out`. Order is stable: detector
   declaration order, then file ascending, then line ascending.

### 3.9 applyMechanicalFix

Only one detector currently sets `autoFixable = true`:
`orphan_q_unused`. Returns `ApplyVerdict` (§ 2.1):

1. Re-validate: if `finding.autoFixable == false` →
   `{applied:false, errorCode:"not_fixable", errorMessage:"detector did not flag this finding as auto-fixable"}`.
2. Re-validate: if `finding.detectorId != "orphan_q_unused"` →
   `{applied:false, errorCode:"not_fixable", errorMessage:"no fix table entry for detector '<id>'"}` (defensive — engine fix table is detector-keyed).
3. Read `<projectPath>/<finding.file>` via QFile. On open failure →
   `{applied:false, errorCode:"io_error", errorMessage:"<QFile::errorString()>"}`.
4. Confirm the marker is still on `finding.line` (re-grep that
   single line for the exact marker pattern). If absent →
   `{applied:false, errorCode:"file_changed", errorMessage:"marker no longer on line <N>; re-scan required"}`. This is a recognised no-op, NOT an error — the MCP handler maps it to `ok:true, applied:false`.
5. Delete the line via `QSaveFile` (atomic). Preserve original
   permissions via `QFile::setPermissions(path, origPerms)` after
   commit (mirrors the RoadmapFoldIn convention). On commit
   failure → `{applied:false, errorCode:"io_error", errorMessage:"<QSaveFile::errorString()>"}`.
6. On success → `{applied:true, errorCode:"", errorMessage:""}`.

**No batched apply.** Caller applies one finding at a time and
re-runs the build between batches if it wants safety. The MCP
tool returns one applied/not-applied verdict per call.

### 3.10 templateDebtSweepFoldInBlock

Same shape as `IndieReviewEngine::templateIndieReviewFoldInBlock`
from ANTS-1112 v1, but with debt-sweep-specific heading + per-bullet
template. Pinned literals (caller-substituted fields in `<…>`):

`<dateIso>` MUST be `YYYY-MM-DD` (date-only, ISO 8601 calendar
date — no time component, no `T` separator), matching the
`roadmap-format.md` § 3.8 example heading shape exactly.

**Heading line (always first line of output):**

```
### 🧹 Debt-sweep fold-in (<dateIso>)
```

**Per-bullet template (one per Finding in `deferred`, in input
order; each pre-allocated ID from `allocatedIds[i]` consumed in
order):**

```
- 📋 [<idPrefix>-<id>] **<message>** at <file>:<line>.
  Kind: chore.
  Source: debt-sweep-<dateIso>.
```

`<dateIso>` MUST be the exact same string in both the heading and
every bullet's `Source:` line — INV-10 locks this equality.
Implementer should pass `dateIso` through once and use it twice.

`<idPrefix>` is the project's own ID prefix, sniffed by the caller and
passed through as the `idPrefix` parameter; `<id>` is zero-padded to
the ROADMAP append width (ANTS-3497). On a non-`ANTS` project the
bullets carry that project's prefix, not a literal `ANTS-`.

Empty-input contract: if `deferred` is empty, return an empty
QString (no heading, no bullets) — the caller decides whether to
fold an empty result.

### 3.11 triagePrompt

Pure string substitution. Template:

```
You are triaging mechanical findings from a debt-sweep run.
The mechanical scanners flagged <N> potential issues that need
human judgment. For each, decide one of:

  KEEP — finding is real; suggest a fix
  DROP — false positive; explain why
  DEFER — real but not worth fixing now

=== Findings ===

[<category> / <detector_id>] <file>:<line>
<message>

…

=== Per-category guidance ===

- stale_type_comment: is the cited identifier merely a description
  in prose, or genuinely a stale code reference?
- added_todo: TODOs added in this scope — are they tracked elsewhere
  (issue tracker, ROADMAP), or floating?
- missing_inv_test: was the INV intentionally untested (judgment-
  only invariant), or is this a real coverage gap?
- shipped_without_commit: was the commit message truncated, the
  ID renamed, or the ROADMAP item flipped prematurely?
- stale_changelog_bullet: was the bullet for an earlier baseline,
  or does the diff actually not match?

Format: markdown. ≤ 500 words.
```

## 4. Invariants (locked by feature tests)

- **INV-1.** `detectStaleTypeComments` returns at least one Finding
  for a fixture where a `.cpp` file in scope has a
  `// QFakeWidget needs reflow` comment and `QFakeWidget` is
  absent from the project source blob. Returns empty for the
  same comment when `QFakeWidget` exists in any project file.
- **INV-2.** `detectAddedTodos` returns one Finding per
  diff-introduced `TODO:` / `FIXME:` line; pre-existing TODOs
  (in baseline) are not reported.
- **INV-3.** `detectOrphanQUnused` returns a Finding for
  `Q_UNUSED(stale)` in a file that does not declare `stale`.
  Returns empty when the same file declares `int stale = 0;`
  anywhere.
- **INV-4.** `detectMissingInvariantTests` returns a Finding for
  a feature dir whose `spec.md` declares `INV-7` and whose
  `test_*.cpp` does not mention `INV-7`. Returns empty when the
  test file mentions it. Alphanumeric IDs work too: a fixture
  declaring `INV-8b` produces a Finding when the test file
  doesn't mention `INV-8b`.
- **INV-5.** `detectRoadmapShippedWithoutCommit` returns a Finding
  for a fixture ROADMAP where `- ✅ [ANTS-9999]` was flipped to
  shipped within the `sinceRef..HEAD` window and the fixture git log
  has no subject containing `ANTS-9999`. Returns empty when the log
  contains a commit subject like `ANTS-9999: ship the thing`, and also
  when the `✅` line predates the window (never flipped in-range) —
  the ANTS-3342 window scoping.
- **INV-6.** `detectChangelogStaleBullets` returns a Finding for
  a `[Unreleased]` bullet citing `` `src/foo.cpp` `` when
  `src/foo.cpp` is not in the diff list. Returns empty when the
  diff includes `src/foo.cpp`.
- **INV-7.** `runPackagingDrift` returns the same finding count as
  the script's stdout line count. Returns empty when the script
  is missing or non-executable.
- **INV-8.** `scanAll` honours `ScanOptions::includeXxx` flags —
  toggling `includeCodeDrift = false` removes every Finding with
  `category == "code_drift"` from the output.
- **INV-9.** `applyMechanicalFix` deletes the marker line for an
  `orphan_q_unused` Finding; the post-fix file has one fewer line
  and no longer contains the marker on the original line number;
  the returned verdict is `{applied:true, errorCode:"",
  errorMessage:""}`. When called with a non-fixable Finding, the
  verdict is `{applied:false, errorCode:"not_fixable", …}` and
  the file is unchanged.
- **INV-10.** `templateDebtSweepFoldInBlock` first line is
  `### 🧹 Debt-sweep fold-in (<dateIso>)`; first bullet starts
  with `- 📋 [ANTS-<id>]`; bullet contains `Kind: chore.` and
  `Source: debt-sweep-<dateIso>.`. The `<dateIso>` token in the
  heading is byte-identical to the `<dateIso>` token in every
  bullet's `Source:` line — the test extracts both via regex and
  asserts string equality.
- **INV-11.** `triagePrompt` emits a prompt containing one
  `[<category> / <detector_id>] <file>:<line>` block per input
  Finding.
- **INV-12.** All 4 `debt_sweep_*` MCP tools are registered in
  the `m_toolProviders` map and appear in `tools/list` with
  valid inputSchema. Lock asserts:
  (a) the test directly calls `m_toolProviders.count(name)` for
  each of the 4 names and asserts == 1;
  (b) `tools/list` JSON contains a `tools[]` entry for each of
  the 4 names with `inputSchema.type == "object"` and
  `additionalProperties == false`.
- **INV-13.** `debt_sweep_apply_fix` round-trip: scan a fixture
  with one orphan `Q_UNUSED(stale)`, call apply with the returned
  triple, assert the file is mutated AND the response envelope is
  `{ok:true, applied:true}`. Calling apply again (line is now
  wrong) returns `{ok:true, applied:false, error_code:"file_changed"}`
  — the fix is idempotent against re-application by virtue of the
  re-grep step in § 3.9 step 4. A third call with a synthetically
  flipped `auto_fixable=false` finding returns `{ok:true,
  applied:false, error_code:"not_fixable"}`.

## 5. Memory + perf budget

| Item | Cost | Notes |
|---|---|---|
| `detectStaleTypeComments` | One source blob build (~10-50 MiB string for Ants Terminal); per-file comment scan. | Blob is built ONCE per scanAll call and reused across detectors that need it. Transient — released after scanAll returns. |
| `detectAddedTodos` | One `git diff` invocation (~1 MiB cap), linear parse. | Sub-second on Ants-shape repos. |
| `detectOrphanQUnused` | `git ls-files` + per-file regex pass. | O(N · M) where N = file count, M = avg markers/file (~0-3). For Ants Terminal: ~150 files × <1 marker each = ms-scale. |
| `detectMissingInvariantTests` | Walks `tests/features/*/spec.md` (~150 specs); per-spec test-file concat + grep. | Sub-second on the whole Ants Terminal corpus. |
| `detectRoadmapShippedWithoutCommit` | One `git diff --unified=0 ROADMAP.md` over the window + one `git log` invocation (~4 MiB cap); per-ID substring search. | O(I · L) where I = in-window ✅ flips (usually ≤10), L = log size (~30 KiB). Sub-second. |
| `detectChangelogStaleBullets` | One CHANGELOG read (~50 KiB) + one `git diff` invocation. | Sub-second. |
| `runPackagingDrift` | One shell invocation (~30 s timeout, but actual ~ms). | Bounded by the script's runtime. |
| `applyMechanicalFix` | One file read + write per call. | Atomic via QSaveFile. |
| `templateDebtSweepFoldInBlock` / `triagePrompt` | Pure string concatenation. | Sub-ms. |

**RAM cost:** transient only. The 4 MCP tool handlers are stateless
lambdas in `MainWindow::setupClaudeMcpProviders`. The source blob
(largest transient) is built per `scanAll` call and released when
the function returns; ~10-50 MiB peak for Ants Terminal — same
order as `featurecoverage::runSpecDriftCheck` already pays.

No persistent state added to ClaudeIntegration. No caching layer
(deferred to v2 if measured useful — per § 5 the per-invocation
cost is sub-second on Ants-shape repos, so caching adds state for
negligible win).

- **AuditDialog "Debt Sweep" tab.** Deferred to ANTS-1259 (v2).
  v1 surface is MCP-only.
- **Per-finding Allow / `.audit_allowlist.json` integration.**
  v2 only — needs the dialog UI to confirm allow scope.
- **`docs/audit-allowlist.md` writer.** Same ADR-0003 dec 5
  deferral as ANTS-1111 / ANTS-1112.
- **README CLI flag drift.** The original ROADMAP table listed
  "README CLI flag references vs `ants-terminal --help` output"
  as a doc-drift detector. Dropped from v1: it requires running
  the binary (or maintaining a side-channel parser) to extract
  the flag list, which a Qt::Core-only engine can't do without
  shelling out to a built binary that may not exist. Re-add in
  v2 once the dialog can execute the project's main binary
  safely (likely via the existing PtyHandler shim).
- **Per-detector severity / triage shifts.** v1 emits all
  findings at a single notional severity (the engine doesn't
  classify); v2 may add severity annotation in line with the
  AuditEngine's existing severity ladder.
- **C++17 / C++20 declaration shapes for `detectOrphanQUnused`.**
  The § 3.3 step 3 regex set won't match structured bindings
  (`auto [a, b] = …`), `decltype(auto)` returns, brace-init
  declarations (`Foo varname{}`), or template-arg types
  (`std::unique_ptr<Foo> v`). Engine will produce false positives
  for orphan markers wrapping such variables. v1 ships the simpler
  detector; v2 may extend the regex set. Document via the
  `not_fixable` `errorCode` returned by `applyMechanicalFix` if
  the user tries to apply on a false positive (re-grep step
  catches the marker still being there with the variable also
  present — but the engine's per-file declaration scan would have
  flagged it as orphan, so the user gets a Finding and the apply
  removes a line that shouldn't be removed). **Mitigation in v1:**
  the test fixture corpus for INV-3 includes one negative case per
  unsupported shape so future regressions surface.
- **Workflow-panel button.** Per ADR-0003 dec 2, ANTS-1108 owns
  it (button calls into `debt_sweep_*` MCP tools or the future
  dialog).

## 9. Security / lifecycle

- All file IO is constrained to `<projectPath>` via
  `QFileInfo::canonicalFilePath` resolution + projectPath-prefix
  rejection (matches `auditdialog.cpp`'s `resolveProjectPath`
  defense).
- `runPackagingDrift` shells out to a project-tracked script.
  The script path is fixed (`packaging/check-version-drift.sh`)
  and not derived from user input — same trust posture as the
  existing `packaging_version_drift` audit rule. 30 s timeout.
- `applyMechanicalFix` writes via QSaveFile (atomic);
  re-validation step (§ 3.9 step 4) ensures the fix is a no-op
  if the file changed under the engine's feet between scan and
  apply.
- Git invocations (`git diff`, `git log`, `git ls-files`) are
  parameterised — no shell metachar interpolation. All run via
  QProcess with stdout caps.
