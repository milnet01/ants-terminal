# ANTS-1302 — `focused_test` MCP — run only the tests touching the changed files

**Status:** spec draft (2026-05-20).
**Kind:** implement.
**Source:** indie-review-2026-05-13 (roadmap bundle plan pull 38).

A new MCP tool that runs a *subset* of the test suite — the tests that
exercise the files a session just changed — instead of the full
~1200-test suite, then returns the ANTS-1300 `test_results` envelope.
The file→test mapping comes from a project-supplied
`tests/coverage-map.json`; a heuristic and a full-suite fallback keep
it safe when the map is absent or incomplete. A new Qt6::Core-only
`FocusedTest` lib does the pure resolution; the MCP layer runs `ctest`
and parses it with the existing `TestResCache::parseCtestOutput`.

## 1. Problem

A one-file change is verified today by running the entire suite
(`ctest --test-dir build --output-on-failure`, ~40 s wall + a large
output the session must read). For a change that only touches
`src/vtparser.cpp`, only the `Vt*` tests can possibly be affected —
running `test_claude`'s 200 MCP tests is pure waste, in both wall time
and output tokens. `focused_test` runs only the relevant subset, 5×–50×
faster on focused changes, with proportionally smaller output.

The hard part is *which tests are relevant*. This project's tests are
gtest-bundled and ctest-discovered as `Suite.Test` names (e.g.
`McpTaskPriors.WiringAndLogicContract`), so the naive `foo.cpp →
test_foo` heuristic does not hold. The reliable mechanism is a
project-maintained `tests/coverage-map.json`; everything else is a
safety net that degrades to the full suite rather than skip a test that
might cover the change.

## 2. Goal

One tool, `{caller_cwd, changed_files?, timeout_sec?, build_dir?}` in:

- Resolve `changed_files` (or auto-derive from git) to a set of `ctest
  -R` name patterns via `tests/coverage-map.json`, a heuristic, or
  full-suite fallback.
- Run `ctest --test-dir <build> -R "<regex>" --output-on-failure` (no
  `-R` for the full fallback).
- Parse with `TestResCache::parseCtestOutput` and return the ANTS-1300
  envelope shape plus focused-test metadata (which selection was used,
  the filter, the unmapped files).

**Safety invariant:** `focused_test` never reports a green result from a
run that matched *zero* tests — that path falls back to the full suite.
The tool errs toward running *more* tests, never fewer than the change
demands.

## 3. Surface

### 3.1 New lib — `src/focusedtest.{h,cpp}` (Qt6::Core only)

`namespace FocusedTest`. No GUI deps; lives in `ants_core_lib` next to
`testrescache.cpp`. Pure — no process spawning, no filesystem writes;
the only I/O is reading the coverage-map file. Public API:

```cpp
enum class Selection { Map, Heuristic, Full };

struct CoverageMap {
    bool        valid = false;        // parsed OK and schema_version == 1
    QString     error;                // ANTS-2119 L4 — "absent" / "read_failed" /
                                      // "bad_json" / "bad_schema" / "bad_pattern" / ""
    int         schemaVersion = 0;
    QHash<QString, QStringList> entries;  // repo-rel src path -> ctest patterns
    QStringList defaultPatterns;          // optional top-level "default"
    QStringList ignoreGlobs;              // optional top-level "ignore"
};

// Read <root>/tests/coverage-map.json. Missing file -> {valid:false,
// error:"absent"}. Malformed -> {valid:false, error:"bad_json"}.
// schema_version != 1 -> {valid:false, error:"bad_schema"}.
CoverageMap loadCoverageMap(const QString &rootCanonical);

struct Resolution {
    Selection   selection = Selection::Full;
    QStringList patterns;        // ctest -R alternatives (empty == run all)
    QStringList mappedFiles;     // changed files that hit a map entry
    QStringList unmappedFiles;   // changed files with no entry, not ignored
    QStringList ignoredFiles;    // changed files matched by an ignore glob
    QString     reason;          // human-readable selection rationale
};

// Resolve changed files to ctest patterns. `changedFiles` are
// repo-relative (leading "./" stripped by the caller). See § 3.3.
Resolution resolve(const QStringList &changedFiles, const CoverageMap &map);

// foo.cpp / foo.h -> a best-effort ctest-name fragment. Best-effort
// only (bundle suites are CamelCase, not basename-derived); the 0-match
// safety net (§ 3.5) covers a heuristic that matches nothing.
QString heuristicPattern(const QString &changedFile);

// OR-join patterns into one ctest -R ERE: "(p1|p2|p3)". Empty -> "".
QString buildCtestRegex(const QStringList &patterns);
```

### 3.2 `tests/coverage-map.json` schema (v1)

```json
{
  "schema_version": 1,
  "map": {
    "src/vtparser.cpp":     ["^Vt", "^Decstr", "^Csi"],
    "src/remotecontrol.cpp":["^Mcp", "^Roadmap", "^RemoteControl"]
  },
  "default": [],
  "ignore": ["*.md", "docs/", "CHANGELOG.md", "ROADMAP.md", ".roadmap-counter"]
}
```

- **`schema_version`** (required, integer): must be `1`.
- **`map`** (required, object): repo-relative source path → array of
  `ctest -R` regex fragments (ERE, the CMake regex dialect). The
  fragments are OR-joined and passed as a single `-R`.
- **`default`** (optional, array): patterns applied to a changed file
  that has no `map` entry and is not ignored. When absent (or empty),
  an unmapped non-ignored file forces the **full** fallback (§ 3.3).
- **`ignore`** (optional, array of glob/suffix strings): changed files
  matching any entry contribute nothing and do **not** force the full
  fallback. Match rule: a file matches if it ends with the entry
  (suffix match, so `*.md` is stored as `.md`; a leading `*` is
  stripped) or its path starts with the entry (so `docs/` matches
  `docs/specs/x.md`). Lets a `src/foo.cpp` + `CHANGELOG.md` commit
  resolve to the `foo` patterns instead of the full suite.

### 3.3 Resolution rules (`FocusedTest::resolve`)

Applied in order; the first rule that fully decides wins:

1. `changedFiles` empty → `Selection::Full`, reason `"no changed
   files"`.
2. `map.valid == false` → **heuristic mode**: for each changed file,
   `heuristicPattern(f)`; collect non-empty results into `patterns`,
   the contributing files into `mappedFiles`. A file yielding nothing
   (not source-like — no usable basename stem) goes into
   `unmappedFiles`, **not** `ignoredFiles` (ANTS-2119 M1 — heuristic mode
   consults no ignore globs, so it never "ignores" a file; labelling an
   unmappable file as ignored both mislabels observability and masks a
   coverage gap). Then, mirroring map mode's conservatism: if
   `unmappedFiles` non-empty → `Selection::Full` (reason `"no coverage
   map; unmappable file <f> (running full suite)"`) — an unmappable file
   could affect any test, so err toward more tests; else if `patterns`
   non-empty → `Selection::Heuristic`; else → `Selection::Full` (reason
   `"no coverage map; heuristic matched no source files"`).
3. `map.valid == true` → **map mode**, per changed file:
   - matches an `ignore` glob → add to `ignoredFiles`, skip.
   - has a `map` entry → union its patterns, add to `mappedFiles`.
   - else if `map.defaultPatterns` non-empty → union those, add to
     `mappedFiles`.
   - else → add to `unmappedFiles`.
   After the loop:
   - `unmappedFiles` non-empty → `Selection::Full` (reason names the
     first unmapped file). **This is the conservative core: an unmapped
     source file means the map can't prove which tests cover it, so run
     everything.**
   - else `patterns` non-empty → `Selection::Map`.
   - else (every changed file was ignored) → `Selection::Full` (reason
     `"only test-irrelevant files changed; running full suite"`).

Pattern unions are de-duplicated, order-preserved.

### 3.4 MCP orchestration (`RemoteControl::cmdFocusedTest`)

1. `resolveRootCanonical(m_main, req)`; empty → `no_project`.
2. Re-entrancy gate: `m_focusedTestInFlight` (member bool +
   `qScopeGuard` reset, mirrors `m_verifyInFlight`); busy →
   `focused_test_in_flight`.
3. Build dir: `build_dir` arg if present (path-validated under root via
   `PathValidation::validatePath`), else `<root>/build`. Must be an
   existing directory containing `CMakeCache.txt`; else →
   `no_build_dir`. (This is a deliberately tighter gate than
   `verifyengine.cpp`'s `CMakeLists.txt`-exists check: `verify_changes`
   *configures + builds*, whereas `focused_test` only runs `ctest`,
   which requires an already-*configured* build dir — `CMakeCache.txt`
   is that signal. The QProcess mechanics in step 7 still mirror
   verifyengine; only this gate differs, by design.)
4. `changed_files`: if the arg is a non-empty array, use it (each entry
   trimmed, leading `./` stripped, deduped); if the arg is absent,
   auto-derive from `cmdGitState({op:"status"})`'s `files[].path`
   (worktree + staged + untracked); if the arg is present but not an
   array → `bad_args`.
5. `FocusedTest::loadCoverageMap(root)` then
   `FocusedTest::resolve(changedFiles, map)`.
6. Build argv: `ctest --test-dir <buildRel> --output-on-failure`, plus
   `-R <buildCtestRegex(patterns)>` when `selection != Full`.
7. Run via `QProcess` (workingDir = root, `MergedChannels`,
   `waitForFinished(timeoutMs)` with a 2 s kill grace — mirrors
   `verifyengine.cpp`). `timeout_sec` default 300, clamp [10, 1800].
   Capture stdout, capped at 2 MiB (keep the tail on overflow).
   Process failed to start → `ctest_missing`; timed out or crashed →
   `ctest_failed` (with the captured tail).
8. `TestResCache::parseCtestOutput(output)` → `ParsedTests`.
9. **0-match safety net:** if `selection != Full` and
   `parsed.total == 0`, re-run once with the full command (no `-R`),
   set `downgraded_to_full:true` and `downgrade_reason:"selection
   matched 0 tests"`, and use the full run's parse.
10. If the (final) parse has `recognised == false` → `unrecognised_output`.
11. Envelope: start from `TestResCache::toJsonWire(parsed)` (which
    gives `passed, failed, skipped, total, failing_tests[]`,
    `exit_code`, `schema_version`, … but **not** `ok` — `toJsonWire`
    does not set it). `cmdFocusedTest` adds `ok:true` and the § 3.5
    focused-test fields.

### 3.5 Envelope

On success, `ok:true` (set by `cmdFocusedTest`, not `toJsonWire`) plus
the ANTS-1300 wire fields plus the focused-test fields:

```json
{ "ok": true,
  "passed": 12, "failed": 0, "skipped": 0, "total": 12,
  "failing_tests": [],
  "selection": "map",
  "ctest_filter": "(^Vt|^Decstr|^Csi)",
  "changed_files": ["src/vtparser.cpp"],
  "mapped_files": ["src/vtparser.cpp"],
  "unmapped_files": [],
  "ignored_files": [],
  "selection_reason": "1 file mapped to 3 patterns",
  "downgraded_to_full": false,
  "duration_ms": 1840,
  "build_dir": "build" }
```

- `selection` ∈ `map` / `heuristic` / `full`.
- `ctest_filter` is the `-R` regex actually passed (`""` for full).
- `downgraded_to_full` / `downgrade_reason` present only when the
  0-match net fired.
- `failing_tests[]` is the `toJsonWire` form (no `full_excerpt`),
  capped at 50 by `TestResCache`.
- The `toJsonWire` base also carries `exit_code`, `schema_version`,
  `recorded_at_ms`, `output_byte_size`, and `failing_tests_truncated`
  (elided from the example above for brevity).

### 3.6 Refusal codes

| code | when |
|------|------|
| `no_project` | root unresolved. (`mcp-error-codes.md` § 2.) |
| `no_build_dir` | no `build/` (or `build_dir`) directory with `CMakeCache.txt`. (§ 2 resource state.) |
| `focused_test_in_flight` | a previous `focused_test` is still running. (§ 2 resource state — mirrors `verify_in_flight`.) |
| `bad_args` | `changed_files` present but not an array, or `timeout_sec`/`build_dir` malformed. (§ 1.) |
| `bad_path` | `build_dir` escapes the project root (from `PathValidation`). (§ 3 caller-cwd.) |
| `ctest_missing` | the `ctest` binary failed to start. (§ 4 I/O.) |
| `ctest_failed` | ctest crashed or exceeded `timeout_sec`. (§ 4 I/O.) |
| `unrecognised_output` | the (final) ctest output matched neither a summary footer nor any per-test line. (§ 4 I/O.) |

(`caller_cwd_required` is emitted upstream by the dispatcher per
ANTS-1404 when `caller_cwd` is absent.)

A run where tests *failed* (`failed > 0`, ctest exit non-zero) is a
**success** envelope (`ok:true`, `failed:N`), not a refusal — same as
`test_results`.

### 3.7 Edge cases

| Input | Behaviour |
|-------|-----------|
| `changed_files: []` (explicit empty) | treated as absent → auto-derive from git. |
| auto-derive finds no changes (clean tree) | `resolve([])` → Full; runs the whole suite (reason `"no changed files"`). |
| coverage-map.json absent | heuristic mode; near-certain 0-match on this bundled project → 0-match net → full. |
| coverage-map.json malformed / wrong schema | `map.valid=false` → heuristic mode (not a refusal — a stale map must not break testing). |
| changed file not in map, not ignored | full fallback (conservative). |
| only `*.md` / ignored files changed | Full (reason `"only test-irrelevant files changed"`). |
| selected regex matches 0 tests | re-run full, `downgraded_to_full:true`. |
| ctest exits non-zero due to test failures | `ok:true`, `failed > 0` (not a refusal). |
| `timeout_sec` out of range | clamped to [10, 1800]. |

## 5. Memory & cost budget

- `FocusedTest` lib: O(changed_files × patterns) string work; reads one
  JSON file (`coverage-map.json`, ≤ tens of KiB). No process, no cache.
- `cmdFocusedTest`: one (occasionally two — the 0-match net) `ctest`
  subprocess. Captured stdout capped at 2 MiB (tail kept on overflow);
  `TestResCache` caps `failing_tests[]` at 50, per-failure excerpt at
  8000 chars, joined wire excerpt at 4000. Wall bounded by `timeout_sec`
  (default 300 s, max 1800 s) with a 2 s kill grace. Re-entrancy gate
  bounds it to one run at a time.
- Worst-case heap: the 2 MiB capture + the parsed structure (≤ 50
  failures × ≤ 8 KiB) ≈ a few MiB transiently, freed after the call.
  No persistent state — `focused_test` does **not** write the
  `.audit_cache/tests.json` cache (that is `test_results`' job; this
  tool is a runner, not a recorder).
- The win is wall-time + output-token reduction on focused changes; the
  cost ceiling is one full-suite run (the fallback), i.e. never worse
  than running `ctest` directly.

## 6. Out of scope

- **Writing the `tests.json` cache.** `focused_test` runs and reports;
  `test_results` (ANTS-1300) owns the cache. A caller that wants the
  result cached calls `test_results op=record` with the output. (A
  future enhancement could record the focused run, but the partial-run
  semantics would corrupt the "last full run" cache — deliberately
  omitted.)
- **Building before testing.** `focused_test` runs ctest against the
  *existing* build; it does not `cmake --build`. Stale binaries are the
  caller's problem (use `verify_changes` / `build_status` for the
  build step). Documented in the `selection_hint`.
- **Coverage-accurate mapping.** The map is human-maintained and
  approximate; correctness is guaranteed only by the conservative
  full-fallback, not by the map's completeness. A precise map is a
  living doc, not a build artifact.
- **Per-test-executable heuristic** beyond the basename token. The
  bundled-suite naming defeats `foo.cpp → test_foo`; the heuristic is
  retained as a documented best-effort with the 0-match net behind it.
- **Auto-deriving the diff base.** Auto-derive uses working-tree status
  (`cmdGitState op:status`), not an arbitrary `git diff <ref>`; a
  caller wanting a specific base passes `changed_files` explicitly.
