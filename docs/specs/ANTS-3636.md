# ANTS-3636 — `doc_citations`: resolve a doc's `path:line` citations and return the cited text

**Status:** spec draft (2026-07-26).
**Kind:** implement.
**Source:** ROADMAP.md ANTS-3636 (OneUp_Ants_MCP_Feedback.md, 2026-07-26 addendum).
**Composes with:** ANTS-3601 (`doc_integrity` — shares the fence primitives),
ANTS-2021 / ANTS-2219 (`read_region` / `read_regions` — the line-slicing engine),
ANTS-1637 (`codebase_index` — the basename→path map).
**Pairs with:** ANTS-3596 (hand-hardened `~:line` citations in
`docs/specs/ANTS-2161.md` — the manual fix this verb generalises).

**Layman:** Design docs are full of "see `file.cpp`, line 200" pointers. Code
moves; the pointers rot silently. This adds one call that looks up every such
pointer in a document and shows what is actually on those lines today.

---

## 1. Problem

Global rule 13 requires every doc claim naming a file, line, function, or
constant to be checked against live source rather than recalled. `/cold-eyes`
runs that check on every loop, for every reviewer, on every doc. There is no
verb for it, so it is done by hand or skipped — and when it is skipped, the
loop ratifies a stale line number and the next reader is sent to the wrong
place.

The reporting session (OneUp) hit this directly: verifying one spec meant
resolving 33 `updater.py:NNN` citations, and they wrote a throwaway Python
script because no verb existed. `read_regions` is the closest fit but takes a
hand-extracted list of `{path, start_line, end_line}` — and extracting that
list *is* the tedious part.

**The corpus is large enough that hand-verification does not scale.** Measured
this session over `docs/` (ripgrep via `workspace_search`, extension-restricted
scan `[A-Za-z0-9_./-]+\.(cpp|h|py|sh|md|json|lua|cmake|txt):~?\d+`):

| Shape | Count | Share |
|---|---:|---|
| Total `path:line` citations | ~1,872 in 167 docs | — |
| Carry a directory component (`src/foo.cpp:12`) | 537 | ~29% |
| **Bare basename** (`foo.cpp:12`) | remainder | **~71%** |
| Line **ranges** (`:208-228` or en-dash `:208–228`) | 668 | ~36% |
| Bare continuations (`` `:548-549` ``, path inherited) | 547 in 78 files | ~29% |
| Multi-locus / open-ended (`:262/265/286`, `:5669+`) | 39 | ~2% |
| Approximate (`:~197`, ANTS-3596's hand fix) | 10 | <1% |

Densest single doc: `docs/specs/ANTS-1750.md` at 56 citations.

Three consequences follow, and they shape the design:

1. **Existence checking is not enough.** A citation that has drifted 20 lines
   onto an unrelated statement still points at a line that exists. Only the
   cited *text* exposes that, which is why the text is the load-bearing output
   and not an option.
2. **Bare basenames are the common case, not an edge case.** A resolver that
   only handles repo-relative paths would silently skip ~70% of the corpus —
   worse than no verb, because the empty result reads as "all clear".
3. **Citations live inside inline code spans.** Nearly every one in the corpus
   is written `` `remotecontrol.cpp:335` ``. `doc_integrity` deliberately
   *masks inline code out* before harvesting links (`maskInlineCode`,
   `src/docintegrity.cpp:116`) because a link inside a code span is a code
   sample. For citations the rule inverts: the code span is exactly where the
   data is. This is the single most important reason the two checks cannot
   share a scrape pass.

## 2. Surface

### 2.1 Verb shape

New verb `doc_citations`, **not** a mode on `doc_integrity`. The ROADMAP bullet
left this open ("decide at spec time"); the deciding facts are that
`doc_integrity`'s contract is a *defect list* (`findings[]` + `counts{}`
narrowed by `kinds`, ANTS-3601 INV-18) while this verb's primary output is an
*enumeration of every citation with its text* — most of which are healthy.
Folding an enumeration into a findings verb would either break `kinds`/`counts`
or bury the payload. Reuse happens one layer down, at the engine (§ 2.7).

Request:

```jsonc
{
  "caller_cwd":       "<required>",       // CallerCwdContract::Required
  "path":             "docs/specs/ANTS-2161.md",  // required, a FILE
  "only":             "all" | "stale",    // default "all"
  "max_range_lines":  3,                  // per-citation, clamp [1, 20]
  "max_bytes":        131072,             // default 128 KiB, clamped to 4 MiB
  "etag_match":       "<opt>"
}
```

`path` must name a single file. A directory refuses `bad_args` with the reason
in the message — the corpus's ~1,870 citations would blow any sane response
budget, and the per-doc call is the shape the workflow actually needs (§ 5).

Response:

```jsonc
{
  "ok": true,
  "path": "docs/specs/ANTS-2161.md",
  "citations": [
    {
      "doc_line": 214,                       // 1-based line in the doc
      "raw": "projectsettings.cpp:96-112",   // as written, sans backticks
      "status": "ok",
      "path": "src/projectsettings.cpp",     // resolved, project-relative
      "start_line": 96,
      "end_line": 112,
      "file_lines": 486,                     // target's total line count
      "text": ["    if (CodebaseIndex::isIndexableSuffix(...", "..."],
      "range_truncated": true,               // >max_range_lines; text is the head
      "inherited_path": false,               // true → path came from § 2.2's sticky rule
      "approximate": false,                  // true → the `~N` form
      "partial": false,                      // true → trailing loci dropped (`/265`, `+`)
      "anchor_symbol": "countSourceFiles",   // absent when none precedes (§ 2.5)
      "anchor_found": true
    }
  ],
  "counts": { "ok": 31, "missing_file": 1, "out_of_range": 0,
              "ambiguous": 1, "unresolved": 0, "anchor_missing": 2 },
  "count": 33,
  "truncated": false,
  "unparsed": [ { "doc_line": 88, "raw": "Qt 6.2:1" } ]
}
```

`only:"stale"` drops every `status:"ok"` entry whose `anchor_found` is not
`false`, keeping `counts` unfiltered — the re-verification sweep after a
refactor, where the healthy 90% is noise. (Deliberately unlike `doc_integrity`'s
`kinds`, which narrows counts too: there, counts *are* the defect tally; here
the whole-doc tally is the context that makes the filtered list meaningful.)

### 2.2 Citation grammar

Scraped shapes, in the frequency order of § 1:

```
citation   := path ":" locus
continuation := ":" locus                 // path inherited (sticky rule below)
path       := [A-Za-z0-9_.@+-]+ ( "/" [A-Za-z0-9_.@+-]+ )*   // must contain a "."
locus      := "~"? N [ ("-" | "–") "~"? N ]             // hyphen or EN DASH
```

- **En dash is not optional.** The corpus writes both `:208-228` and
  `:208–228`; a hyphen-only regex loses a large minority of the 668 ranges.
- **Trailing loci are dropped, not guessed.** `:262/265/286/300` and `:5669+`
  parse as their first locus with `partial:true` (39 occurrences, ~2%).
  Reporting the first locus is honest and useful; enumerating a `+` open range
  is not well-defined.
- **`~N` sets `approximate:true`.** An approximate citation is never reported
  `out_of_range` for being off by a few lines — that is what the author meant
  by the tilde. It still resolves and still returns text.
- **Sticky path.** A bare `:NNN` continuation inherits the path of the most
  recent successfully-*parsed* citation **earlier in the same document**, and
  carries `inherited_path:true` so a reader can see the path was not stated. No
  preceding citation → `status:"unresolved"`. Attribution can be wrong when the
  author's antecedent was a prose mention rather than a citation; the flag is
  the mitigation, and the alternative (dropping 547 real citations) is worse.
  The sticky path is **cleared by a fenced block**, so a code sample cannot
  become the antecedent of the prose after it.

Anything matching the shape whose path part resolves nowhere (§ 2.4) is a
likely false positive from prose (`Qt 6.2:1`). Those land in `unparsed[]`
rather than `citations[]` — never silently dropped, never inflating the tally.

### 2.3 Scrape rule (masking is inverted vs. `doc_integrity`)

- **Fenced blocks are skipped**, via `MarkdownScan::fenceMask` (`src/markdownscan.h:58`)
  — a `path:line` inside a ```` ```cpp ```` sample is illustrative text, not a
  claim about the repo. This is the one primitive shared with `doc_integrity`,
  including its ANTS-3638 list-container awareness.
- **Inline code spans are scanned, not masked** — the inverse of
  `maskInlineCode`. `doccitations` does not call it.
- The scan runs on the raw line, so a citation in plain prose
  (`ROADMAP.md:19418 was …`) is picked up too.

### 2.4 Path resolution ladder

Applied in order; first hit wins.

1. **Contains `/`** → treat as project-relative from the repo root
   (`PathValidation`). Resolves or `missing_file`.
2. **Bare basename** → look up `basenameIndex` (§ 2.7). Exactly one match →
   resolved. Two or more → `status:"ambiguous"`, with the candidate paths in
   `candidates[]` and **no text**.
3. **Bare basename not in the index** → probe `<root>/<basename>` (this is what
   catches `CMakeLists.txt:148`, `ROADMAP.md:19418`, `README.md:…`, which live
   at the root and outside the src/tests walk).
4. Otherwise → `status:"unresolved"`.

**Ambiguity is reported, never resolved by guessing.** `src/` is flat today so
in-lane collisions are impossible, but the indexed tree holds ~13 `good.cpp`
and ~12 `bad.cpp` under `tests/audit_fixtures/`. `TestAuditEngine` merges such
collisions by picking the longest path (`src/testauditengine.cpp:1568-1591`);
that heuristic is fine for a ranking aid and wrong for a verification tool,
where a confidently-wrong line of text is worse than a flagged unknown.

**Security boundary.** A citation is untrusted text in a file the verb reads.
Absolute (`/etc/passwd:1`) and root-escaping (`../../outside.h:3`) paths are
**skipped without a filesystem probe** — the same posture as
`DocIntegrity::resolveRelative` (`src/docintegrity.cpp:228`, ANTS-3601 INV-6).
They land in `unparsed[]`, so the reader still sees that the doc contains one.

### 2.5 Anchor-symbol check — the `expect` mode, derived instead of supplied

The ROADMAP bullet asks for an `expect` mode ("does the cited line still
contain this substring?"). A request-side `expect` map would need the caller to
already know what it expects — which is what reading the text tells them.

The corpus supplies the expectation for free. Its dominant citation idiom names
the symbol immediately before the location:

```
`RemoteControl::filterControlChars` (`remotecontrol.h:95-113`) strips C0
`uniqueSlug` (`roadmapindex.cpp:72-86`) DOES auto-append `-2`, `-3`
```

So: when the code span preceding a citation on the same line (within 40
characters, content matching `^[A-Za-z_][A-Za-z0-9_:]*$`) is an identifier,
record it as `anchor_symbol` and set `anchor_found` to whether the cited region
contains it — comparing on the final `::` component, since the doc qualifies
names the source often does not. No anchor → both fields absent.

`anchor_found:false` is **advisory, not a `status`**: `status` answers "did the
citation resolve", this answers "does it still say what the doc claims". It is
counted separately (`counts.anchor_missing`) and it is what `only:"stale"`
keeps. This catches precisely the failure the bullet describes — the citation
that drifted onto an unrelated statement — at ~30 lines, and needs nothing
added to any doc.

### 2.6 Status taxonomy

| `status` | Meaning | `text` emitted |
|---|---|---|
| `ok` | Resolved, in range | yes |
| `missing_file` | Path resolved, file absent | no |
| `out_of_range` | File exists, `start_line > file_lines` | no |
| `ambiguous` | Basename matches ≥2 indexed paths | no (`candidates[]` instead) |
| `unresolved` | No resolution path applied | no |

An `approximate` citation past EOF is `out_of_range`; one merely a few lines
off is `ok` (there is nothing to compare against — § 2.2).

### 2.7 Files and reuse

| File | Role | Target |
|---|---|---|
| `src/doccitations.h` / `.cpp` | Engine: scrape → parse → resolve → read | `ants_core_lib` (`CMakeLists.txt:269`, beside `src/docintegrity.cpp:296`) |
| `src/remotecontrol.cpp` | `RemoteControl::cmdDocCitations` — root resolve, `PathValidation`, build `basenameIndex`, call engine | existing |
| `src/claudeintegration.cpp` | Verb registration + `inputSchema` | existing |
| `src/mainwindow.cpp` | Provider wiring | existing |

```cpp
namespace DocCitations {

struct Options {
    // Basename → project-relative paths, built by the CALLER (§ 2.4 step 2).
    // Passing it in keeps the engine Qt6::Core-pure and unit-testable without
    // a CodebaseIndex on disk; empty → steps 1/3/4 only.
    QHash<QString, QStringList> basenameIndex;
    QString onlyMode      = QStringLiteral("all");  // "all" | "stale"
    int     maxRangeLines = 3;        // clamp [1, 20]
    int     maxCitations  = 400;
    int     maxBytes      = 128 * 1024;             // clamp to ReadRegion::kMaxBytesCeiling
};

// Reads `docAbsPath`, resolves every citation under `rootCanonical`, returns
// the § 2.1 envelope. Writes nothing; holds no cross-call state.
QJsonObject check(const QString &rootCanonical, const QString &docAbsPath,
                  const Options &opts = {});

}  // namespace DocCitations
```

Reused rather than rewritten:

- `MarkdownScan::fenceMask` — fence skipping (§ 2.3).
- `ReadRegion::extract` (`src/readregion.h:44`) — line slicing, already
  handling clamping and the byte cap. `readOneRegion` is file-static in
  `readregion.cpp` and stays that way; `extract` is the exported entry point
  and is sufficient here, since this verb does its own path resolution.
- `CodebaseIndex::serve` (called at `src/remotecontrol.cpp:12223`) — the
  handler builds `basenameIndex` in one pass over `Index::files`, keyed on
  `path.section('/', -1)`. No new index, no new cache, no new disk artifact.
  A cold/absent index degrades to steps 1/3/4 rather than failing.

### 2.8 RAM and build cost

- **Target-file line cache**, keyed by resolved path, so a doc citing one file
  30 times opens it once. Bounded at **16 files or 8 MiB, whichever first**;
  past the cap, further reads are uncached rather than evicting (no LRU churn,
  no unbounded growth). Sized against the realistic worst case: 56 citations
  into a handful of files, the largest of which (`src/remotecontrol.cpp`) is
  ~18k lines.
- **Response** bounded by `maxCitations` (400) and `maxBytes` (128 KiB default;
  lower than the read-family 512 KiB because the value here is a compact
  review artifact, not a bulk read). Exceeding either sets `truncated:true`.
- **Build**: one new `.cpp` in an existing static lib; no new external
  dependency, no new target.

## 3. Invariants

- **INV-1** — A `path:line` citation inside a fenced block is not harvested.
  *Test:* fixture doc with `` `foo.cpp:1` `` inside a ```` ```cpp ```` fence and
  another in prose → exactly one citation, the prose one.
- **INV-2** — A citation inside an inline code span **is** harvested (the
  inverse of `doc_integrity`'s link rule). *Test:* fixture whose only citation
  is `` `src/a.cpp:2` `` → one citation, resolved.
- **INV-3** — Both range separators parse: `:10-12` and `:10–12` (en dash)
  yield `start_line:10, end_line:12`. *Test:* fixture with one of each → two
  citations with identical loci.
- **INV-4** — A bare basename resolving to exactly one indexed path resolves;
  one matching ≥2 is `status:"ambiguous"` with `candidates[]` populated and no
  `text`. *Test:* `basenameIndex` seeded with one unique and one duplicated
  basename → one `ok`, one `ambiguous` carrying both candidates.
- **INV-5** — A bare basename absent from `basenameIndex` but present at the
  repo root resolves (step 3). *Test:* fixture citing `CMakeLists.txt:1` with
  an empty `basenameIndex` → `status:"ok"`.
- **INV-6** — An absolute or root-escaping citation path is never resolved and
  never probed on the filesystem; it appears in `unparsed[]`. *Test:* fixture
  citing `/etc/passwd:1` and `../../outside.h:3` → both in `unparsed[]`, zero
  in `citations[]`, and no stat of either path (assert via a probe counter or
  by pointing the escape at a real out-of-root file that would otherwise
  resolve `ok`).
- **INV-7** — A bare `:NNN` continuation inherits the most recent parsed
  citation's path and sets `inherited_path:true`; with no antecedent it is
  `status:"unresolved"`. *Test:* fixture with `src/a.cpp:1` then `` `:2` `` →
  second resolves to `src/a.cpp` with the flag; a fixture whose first citation
  is a bare `:5` → `unresolved`.
- **INV-8** — A fenced block clears the sticky path: a bare `:NNN` after a
  fence whose only preceding citation was before that fence is `unresolved`.
  *Test:* fixture ordering citation → fence → bare `:9` → `unresolved`.
- **INV-9** — `:262/265/286` and `:5669+` parse as their first locus with
  `partial:true`. *Test:* fixture with both forms → `start_line` 262 and 5669,
  both `partial`.
- **INV-10** — `~N` sets `approximate:true`, still resolves and returns text,
  and is not reported `out_of_range` unless it is past EOF. *Test:* fixture
  citing `:~2` in a 10-line file → `ok` + `approximate`; `:~99` → `out_of_range`.
- **INV-11** — A citation whose file is missing is `missing_file`; one past EOF
  is `out_of_range`; neither emits `text`. *Test:* fixture citing `gone.cpp:1`
  and `src/a.cpp:9999` → the two statuses, `text` absent on both.
- **INV-12** — A range longer than `max_range_lines` returns the first
  `max_range_lines` lines with `range_truncated:true`. *Test:* `:1-10` with
  `max_range_lines:3` → 3 lines, flag set, `end_line` still 10.
- **INV-13** — `anchor_symbol` is recorded from the identifier code span
  preceding the citation, compared on its final `::` component, and
  `anchor_found` reflects presence in the cited region. Absent when no
  identifier precedes. *Test:* fixture with `` `alpha` (`src/a.cpp:1`) `` where
  line 1 contains `alpha` → `anchor_found:true`; a second citing a line that
  does not → `false`; a bare citation → both fields absent.
- **INV-14** — `only:"stale"` drops `status:"ok"` entries whose `anchor_found`
  is not `false`, and leaves `counts` unfiltered (the whole-doc tally). *Test:*
  fixture producing 3 ok-and-anchored, 1 ok-but-anchor-missing, 1 missing_file
  → `citations` has 2, `counts.ok` still 4.
- **INV-15** — A shape-matching token whose path resolves nowhere lands in
  `unparsed[]`, not `citations[]`. *Test:* fixture containing `Qt 6.2:1` →
  `citations` empty, `unparsed` has one entry with its `doc_line`.
- **INV-16** — `DocCitations::check` writes nothing to disk and holds no
  cross-call state. *Test:* run twice over an unchanged fixture → byte-identical
  output, no new files.
- **INV-17** — No more than `maxCitations` entries and no more than `maxBytes`
  of text are emitted; exceeding either sets `truncated:true`. *Test:* fixture
  with `maxCitations + 5` citations run at a lowered cap → exactly
  `maxCitations` entries, `truncated:true`.
- **INV-18** — The verb refuses without `caller_cwd` (`caller_cwd_required`),
  refuses a root-escaping `path` with `bad_path`, and refuses a directory
  `path` with `bad_args`. A well-formed but non-existent in-root `path` refuses
  `not_found`. *Test:* four verb-level calls, one per code.
- **INV-19** — The verb is registered with `CallerCwdContract::Required` and is
  ETag-supported. *Test:* source-scrape of `mainwindow.cpp`,
  `claudeintegration.cpp`, `remotecontrol.cpp` (the `rc_get_text_byte_cap`
  pattern used by ANTS-3601 INV-10).

## 5. Out of scope

- **Directory / whole-corpus scans.** `path` is a single file (§ 2.1). A
  `docs/`-wide sweep is ~1,870 citations; it needs a digest response shape
  (counts + `only:"stale"` only, no text), which is a different verb contract.
  Follow-up if the per-doc call proves the value first.
- **Rewriting drifted citations.** A verb that edits line numbers in a doc is
  a different risk class; the drift may mean the *claim* moved, not the line.
- **Non-markdown inputs.** Source-comment citations (`// see foo.cpp:12`) are
  out; the workflow this serves is doc review.
- **`docs_index` integration.** No reverse "which docs cite this file?" index —
  that is a cache with an invalidation contract, and nothing has asked for it.
