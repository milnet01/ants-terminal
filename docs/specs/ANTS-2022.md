# ANTS-2022 — `apply_edits` MCP tool (N old→new edits across M files, atomic per file)

**Status:** shipped (unreleased — landed 2026-06-05) — 5 cold-eyes loops,
converged; implemented + feature-tested (tests/features/mcp_apply_edits/,
955/955 bundle green).
**Kind:** feature.
**Source:** ROADMAP.md ANTS-2022 (in-session-2026-06-04 — bundle/sweep work
costs one native `Edit` round-trip per site).
**Pairs with:** ANTS-2021 (`read_region` — the read half of the
read-slice/edit token-saver bundle).
**Composes with:** the `roadmap_log` `flip_batch` *posture*
(ANTS-1690 — `ok:true` with a populated `skipped[]`, the rest still
applied) and the `auditautofix::applyRepair` atomic write idiom
(`src/auditautofix.cpp:102-149`). The envelope **field names** deliberately
differ from `flip_batch`'s (`flipped`/`flipped_count`/`skipped_count` with
`skipped[]` of `{locator_index, code, error}`) because this is a
file-edit tool, not a roadmap-flip — see § 2.5. "Parity" below means the
soft-skip posture, never field-for-field identity.

## 1. Problem

A multi-site sweep — e.g. ANTS-1988 (`mkpath` → `ensurePrivateDir` across
5 sites), ANTS-2018 (idiom sweep) — costs one native `Edit` round-trip per
site. Each `Edit` re-emits its surrounding context and pays a tool
round-trip; 5 identical edits across 5 files is 5 calls. There is no MCP
verb to apply a batch of `{path, old, new}` edits in one call, even though
the project already has:

1. An atomic single-file old→new write
   (`auditautofix::applyRepair`, `src/auditautofix.cpp:102` —
   read → transform → `QSaveFile` write-full-or-fail → `commit()` →
   `fsyncParentDir`), and
2. A batch-with-`skipped[]` contract on the roadmap side (`roadmap_log`
   `op:"flip_batch"`, ANTS-1690 — an unresolvable locator lands in
   `skipped[]` while the rest apply).

`apply_edits` is the source-tree analogue: it collapses N edits into one
call with the same path-validation and atomic-per-file write guarantees
the rest of the Ants write surface uses.

**Layman:** apply the same small change across several files in one Ants
call — like the batch roadmap-flip already does for the roadmap — instead
of one built-in edit per file.

## 2. Surface

New MCP **write** tool `apply_edits`, backed by a pure, Core-only helper so
the string transform is unit-testable without touching the disk:

- Pure helper `ApplyEdits::applyToContent` in `src/applyedits.{h,cpp}`,
  joining `ants_core_lib`:

  ```cpp
  namespace ApplyEdits {
  struct EditOutcome {
      bool      applied = false;
      QString   newContents;   // valid iff applied
      int       replacements = 0;
      QString   skipReason;    // "" iff applied; else a § 2.3 reason
  };
  // Apply one old→new edit to in-memory contents. Without replaceAll,
  // `oldStr` must occur exactly once (unique) or the edit is skipped
  // ("not_found" for 0, "ambiguous" for > 1) — mirrors native Edit +
  // the applyRepair ambiguity guard (auditautofix.cpp:126).
  EditOutcome applyToContent(const QString &contents,
                             const QString &oldStr,
                             const QString &newStr,
                             bool replaceAll);
  }
  ```

- Handler `RemoteControl::cmdApplyEdits` (`src/remotecontrol.cpp`,
  `ants_core_lib`) — validates every path, groups edits by file, applies
  each file's edits in array order via `ApplyEdits::applyToContent`
  (threading the result of one into the input of the next so two edits to
  one file compose), then writes each touched file atomically with the
  `applyRepair` idiom (`QSaveFile` → write-full-or-fail → `commit()` →
  `fsyncParentDir`; preserve a trailing newline).

  **Layer split (load-bearing — keep it straight):** the pure helper
  `applyToContent` sees only the in-memory `contents`/`oldStr`/`newStr` and
  does the substring transform + occurrence counting. **All filesystem
  concerns live in `cmdApplyEdits`, never the helper:** reading the file,
  the 4 MiB `too_large` size gate (INV-9), and the atomic write (INV-5).
  Trailing-newline preservation (INV-8) needs **no** split/rejoin: the
  helper does a **whole-content** substring replace, so a final `\n`
  outside the matched `old` is untouched. (This is simpler than
  `applyRepair`, which split/rejoined because it edited by line number, not
  substring.)
- inputSchema in the `tools/list` builder block of
  `src/claudeintegration.cpp`.
- Dispatch `registerToolProvider("apply_edits",
  ClaudeIntegration::CallerCwdContract::Required,
  rcDelegate(&RemoteControl::cmdApplyEdits))`
  in `MainWindow`, near the other `Required` write tools
  (`src/mainwindow.cpp`), plus a `callerCwdContractFor → Required` entry
  in `src/claudeintegration.cpp`.

### 2.1 Arguments

```json
{
  "caller_cwd": "/abs/project",     // required
  "edits": [                        // required, non-empty
    { "path": "src/a.cpp", "old": "mkpath(", "new": "ensurePrivateDir(",
      "replace_all": false }        // replace_all optional, default false
  ]
}
```

- `edits` (array, **required**, non-empty). Each entry names `path`
  (string, required) and `new` (string, required — may be empty for a
  deletion), plus **exactly one** selector:
  - **substring** — `old` (string, non-empty), plus `replace_all` (bool,
    optional, default `false`).
  - **line range** (ANTS-3711) — `start_line` and `end_line` (1-based,
    inclusive), plus `expect_first_line` and `expect_last_line`, the
    verbatim text of those two lines. All four are required together.
    The guard is deliberately **not** optional: `old` guards itself by
    having to be unique, whereas a line number guards nothing, so an
    unguarded range would silently rewrite whichever lines had drifted
    into those coordinates — which is the corruption a caller reaches
    for this tool to escape. `read_region` returns both the numbers and
    the line text, so the guard costs the caller nothing.
- Missing `edits`, an empty `edits`, an entry missing `path` / `new`,
  both selectors on one entry, neither selector, or a partial range
  (some but not all four range fields) → `{ok:false, code:"bad_args"}`,
  **nothing written**.

### 2.2 Path validation — fail-closed on escape (security boundary)

Every edit's `path` is resolved under `caller_cwd` and validated with
`PathValidation::validatePath(rawPath, rootCanonical, "apply_edits",
"path", /*allowOutsideRoot=*/false)`. Validation runs for **all** edits
**before any file is written**. If any path is malformed or canonicalises
outside the project root (`check.bad`), the whole call refuses with
`{ok:false, code:"bad_path"}` and nothing is written — a path-escape is a
trust-boundary violation, fail-closed, not a soft per-edit skip
(specs § 5.4). An in-root path whose file does not exist
(`check.resolved` empty) is **not** a refusal; that edit lands in
`skipped[]` with reason `"not_found"` (you cannot edit a file that isn't
there, but it is not a security event).

### 2.3 Per-edit soft outcomes (`skipped[]`, flip_batch soft-skip posture)

After the path gate, each edit is applied to its file's working content:

- `old` occurs **exactly once** (or `replace_all` and ≥ 1 occurrence) →
  applied; `replacements` counts the substitutions.
- `old` occurs **zero** times → `skipped[]` reason `"not_found"` (this
  holds with `replace_all:true` too — zero occurrences is `not_found`,
  never a silent no-op).
- `old` occurs **> 1** time and `replace_all` is false → `skipped[]`
  reason `"ambiguous"`. This is the native-`Edit` **substring**-uniqueness
  rule applied across the whole file. The `applyRepair` guard at
  `auditautofix.cpp:126`
  (`if (r.removeLine && lines.count(r.original) > 1)`) is an *analogous*
  precedent but narrower — it tests whole-**line** uniqueness and only for
  line removals; `apply_edits` tests arbitrary-substring uniqueness for
  every edit. Cited as the design ancestor, not a reusable check.
- the file does not exist → `skipped[]` reason `"not_found"`.
- the file exceeds `RemoteControl::kReadToolMaxBytesCeiling` (4 MiB,
  `src/remotecontrol.h:234`) → `skipped[]` reason `"too_large"` (memory
  bound, § 4).
- a range selector whose `expect_first_line` / `expect_last_line` no
  longer match the file's lines at `start_line` / `end_line` →
  `skipped[]` reason `"range_mismatch"` (ANTS-3711). This is the range's
  analogue of `ambiguous`: the coordinates resolved, but not to the text
  the caller was looking at.
- a range whose coordinates fall outside the file (`start_line < 1`,
  `end_line < start_line`, or `end_line` past the last line) →
  `skipped[]` reason `"range_out_of_bounds"` (ANTS-3711).

The closed set of `skipped[].reason` values is
`{"not_found", "ambiguous", "too_large", "commit_failed",
"range_mismatch", "range_out_of_bounds"}` (§ 2.4 defines
`commit_failed`; ANTS-3711 added the last two). These are **in-envelope field values**, not the top-level
refusal `code` taxonomy — in particular `commit_failed` is deliberately
**not** the taxonomy's top-level `write_failed` code
(`docs/standards/mcp-error-codes.md`), to avoid a caller string-matching a
skip-reason against a refusal code.

**A skip row is EXTENSIBLE: `{index, path, reason}` is its floor, not its
shape.** Two of the reasons carry diagnostic keys beside those three, so a
caller parses the row tolerantly and a strict three-key parser is wrong:

| On | Extra keys | Present when |
|---|---|---|
| `not_found` | `candidates: [{line, text}]`, `near_miss_line`, `hint` | **ANTS-4418** — `old` is single-line and **exactly one** line of the file equals it under whitespace normalisation. `candidates` carries that one line, verbatim as the file has it. |
| `ambiguous` | `candidates: [{line, text}]`, `match_count`, `hint`, and `candidates_truncated` | **ANTS-4473** — always. `match_count` is the TRUE occurrence count, `candidates` the first **10** (`kMaxReported`, `src/applyedits.cpp`), and `candidates_truncated` appears **only** when the list is shorter than the count. |

**The two are mutually exclusive by construction** — a near miss is sought only
on `not_found`, occurrences only on `ambiguous` — so one `candidates` key
carries both and a caller keeps one code path. It is the same key `read_region`
section-mode and `roadmap_log`'s bullet locators already return on a miss.

**Absence is the normal case and is not a defect.** A `not_found` with no
unique whitespace near miss, or with a multi-line `old`, carries the three
fields alone — the finder reports nothing rather than a confident wrong line,
and two candidate lines cannot tell a caller which to retry. The other four
skip sites (an absent file, `too_large`, an open failure, a commit failure)
have no `EditOutcome` to carry and are three-field rows by construction.

**§ 2.1's `EditOutcome` sketch is the ORIGINAL shape and is not maintained
against these:** `src/applyedits.h` is the live one, and it also carries the
range selectors ANTS-3711 added.

A file with **≥ 1** applied edit is rewritten **once**, atomically. A file
all of whose edits were skipped is **not touched**. Edits to the same file
apply in `edits[]` array order: edit *k+1* sees edit *k*'s result, so an
edit can match text that a prior edit produced (document order matters,
mirroring native sequential `Edit`s).

### 2.4 Atomicity

Each touched file is committed independently with the `applyRepair` idiom:
`QSaveFile sf(absPath)` → `write()` the full UTF-8 buffer, **refuse a short
write** (`auditautofix.cpp:140-141`:
`if (sf.write(outBytes) != outBytes.size()) return false;` — rather than
commit a truncated source file) → `commit()` (rename(2)) →
`fsyncParentDir(absPath)`
(`src/secureio.h:51` — durable directory entry, the ANTS-2006 guard). The
batch is atomic **per file**, not cross-file: there is no multi-file
transaction (the filesystem offers none), so a crash between two files'
commits can leave file A written and file B not. This matches how N
sequential native `Edit`s already behave, and the per-file `skipped[]` /
`applied[]` accounting tells the caller exactly which landed. A file whose
`QSaveFile` write/commit fails lands in `skipped[]` with reason
`"commit_failed"` (one entry per edit that targeted that file) and its
edits are reported as not applied. The reason string is `commit_failed`,
**not** the taxonomy's top-level `write_failed` code (§ 2.3) — a
`skipped[].reason` is an in-envelope value, never a refusal `code`.

### 2.5 Output envelope

```json
{
  "ok": true,
  "applied": [ { "path": "src/a.cpp", "replacements": 1 } ], // edit 0 applied
  "skipped": [ { "index": 1, "path": "src/a.cpp", "reason": "not_found" },
               { "index": 2, "path": "src/b.cpp", "reason": "ambiguous",
                 "candidates": [ { "line": 44, "text": "    return ok;" },
                                 { "line": 91, "text": "    return ok;" } ],
                 "match_count": 2,
                 "hint": "`old` occurs 2 time(s) — …" } ],
  "files_written": 1,
  "edits_total": 3,
  "edits_applied": 1,
  "edits_skipped": 2
}
```

`skipped[].index` is the 0-based position in the input `edits[]`.
`applied[]` is one entry per **file** written and carries **no** input
`index` — it is file-scoped, its `replacements` being the sum across that
file's applied edits; recovering which input edit produced a given
replacement is out of scope (a caller that needs it issues one edit per
call). `skipped[]` is one entry per skipped **edit**. § 2.3 owns both the
closed `reason` set and the diagnostic keys two of those reasons add — the
first entry above is the three-field floor, the second an extended row.
Restating either here is how this paragraph came to name four of the six
reasons and none of the extra keys. These field names (`applied`,
`files_written`, `skipped[].reason`) are deliberately **distinct** from
`flip_batch`'s (`flipped`/`flipped_count`, `skipped[].{locator_index, code,
error}`) — this is a file-edit tool, and the shape fits files, not roadmap
locators (see the header note). The counts always balance:
`edits_total == edits_applied + edits_skipped` (INV-11). `ok:true` even
when some/all edits are skipped (the `flip_batch` soft-skip posture);
`ok:false` is reserved for the whole-call refusals, whose emission sites
differ: `caller_cwd_required` is **dispatcher-emitted** before the handler
runs (§ 2.6), while `bad_args` and `bad_path` are **handler-emitted**.

### 2.6 Standard contracts

- **caller_cwd: Required** (`callerCwdContractFor`). Empty → refuse
  `caller_cwd_required` before the handler runs (ANTS-1404). A non-empty
  but non-resolving `caller_cwd` is handled upstream by
  `resolveCallerCwdRoot`.
- **No RcGate.** `apply_edits` writes **project files** anchored by
  `caller_cwd` + PathValidation — the same posture as `roadmap_log` /
  `changelog_log`, **not** the tenant-hashed `session_memory` /
  `workflow_state` storage that routes writes through the focused-tab gate.
  It does not touch `~/.cache/ants-terminal/mcp-state`.
- **Not a read tool** — no ETag, no `fields` projection. The response is
  auto-wrapped in `<ants_mcp_data tool="apply_edits">` by the dispatch site
  (it is not a control-plane tool).

## 3. Invariants

- **INV-1** — Without `replace_all`, an edit applies iff `old` occurs
  exactly once; 0 occurrences → `skipped` reason `"not_found"`, > 1 →
  `skipped` reason `"ambiguous"`. *Test:* pure-`applyToContent` cases for
  unique / absent / duplicate.
- **INV-2** — With `replace_all:true`, every occurrence of `old` is
  replaced and `replacements` reports the count. *Test:* pure helper, 3
  occurrences → 3.
- **INV-3** — Multiple edits to one file apply in `edits[]` order against
  one working content and the file is rewritten exactly **once** (one
  atomic commit). *Test:* feature test, two edits to one fixture file, one
  matching text the first produced; assert single file mtime change +
  combined result.
- **INV-4** — Per-edit failures land in `skipped[]` as
  `{index, path, reason}` (`reason` from the § 2.3 closed set) while other
  edits still apply (the `flip_batch` soft-skip posture, distinct field
  names); `ok:true` with a non-empty `skipped[]`. *Test:* mixed batch (one
  good, one absent-`old`) → one `applied`, one `skipped`, `ok:true`.
- **INV-5** — Atomic write: a touched file is written via `QSaveFile`
  write-full-or-fail + `commit()` + `fsyncParentDir`; a short write does
  not commit partial content (reuses the `applyRepair` idiom). *Test:*
  source-scrape (`QSaveFile`, `fsyncParentDir`, short-write guard) + a
  happy-path content assert.
- **INV-6** — Security fail-closed: if **any** edit's `path` escapes the
  project root or is malformed, the **whole call** refuses with `bad_path`
  and **no file is written**. *Test:* batch of one in-root good edit + one
  `../../etc/passwd` edit → `bad_path`, the good file unchanged.
- **INV-7** — caller_cwd is Required: empty `caller_cwd` →
  `caller_cwd_required`. *Test:* source-scrape `callerCwdContractFor` +
  dispatch test.
- **INV-8** — Trailing newline preserved: a file ending in `\n` still ends
  in exactly one `\n` after an edit; a file with no final newline keeps
  none. Falls out of the whole-content substring replace (no split/rejoin
  needed). *Test:* `applyToContent` on `"foo\nbar\n"` and `"foo\nbar"`.
- **INV-9** — Per-file size cap: a target file larger than
  `kReadToolMaxBytesCeiling` (4 MiB) is skipped with reason `"too_large"`
  and never read whole into memory, bounding peak heap. *Test:*
  source-scrape the size guard + (optional) large-fixture smoke.
- **INV-10** — bad_args: a missing/empty `edits`, or an entry missing
  `path`/`new`, or an entry carrying neither selector, both selectors, or
  a partial range, refuses with `bad_args` and writes nothing. *Test:*
  arg-matrix fixture.
- **INV-11** — Count balance + commit-failure accounting: on an `ok:true`
  response `edits_total == edits_applied + edits_skipped` always, and a
  file whose `QSaveFile` write/commit fails reports **all** of that file's
  in-memory-applied edits in `skipped[]` (reason `"commit_failed"`) and
  **never** in `applied[]` — since `applied[]` is file-scoped, a
  fully-failed file simply produces no `applied[]` entry — so a commit
  failure is counted in `edits_skipped`, never as a silent success.
  *Test:* mixed batch asserts the sum identity; a commit-failure fixture
  (e.g. a read-only target dir, which makes `QSaveFile` open/commit fail)
  asserts the file's edits land in `skipped[]` with `commit_failed` and
  `edits_applied` excludes them.
- **INV-12** — A guarded `start_line`/`end_line` range replaces exactly
  those lines and nothing else, and the file's trailing-newline state is
  unchanged (INV-8 holds for range edits too — the split/rejoin round-trips
  the final empty field). *Test:* range replace over a fixture, assert the
  untouched lines byte-identical and the final `\n` still singular.
- **INV-13** — An empty `new` on a range edit removes those lines
  outright — no blank line is left behind. "Delete these 76 lines" is the
  motivating case, and a caller who wanted a blank line can ask for one.
  *Test:* delete an interior range, assert the neighbours become adjacent.
- **INV-14** — A stale range is a **skip, never a write**: if either
  `expect_*` line mismatches, the edit is skipped `range_mismatch` and the
  file is left byte-identical; coordinates outside the file are skipped
  `range_out_of_bounds`. *Test:* drifted-coordinates fixture asserts the
  file's bytes are unchanged, plus a past-EOF case.
- **INV-15** — Selector-shape errors are **whole-call `bad_args`**, not
  per-edit skips: `old` together with a range, neither of them, a range
  missing `expect_first_line`/`expect_last_line`, or half a range. A
  malformed request is the caller's bug, so it is refused loudly; a
  surprising *file* is what `skipped[]` is for. *Test:* arg matrix, each
  case asserting nothing was written.
- **INV-16** — Ranges resolve against the file **as earlier edits in the
  same call left it** (INV-3's one-working-content rule), so a batch whose
  earlier edit changes the line count shifts a later range — and the
  INV-14 guard turns that into a skip rather than a write to the wrong
  lines. Callers order line-shifting edits last, or send them bottom-up.
  *Test:* two-edit batch where the first deletes a line, assert the second
  skips `range_mismatch` and the first edit still applied.

## 4. RAM / build cost

No persistent state, no cache, no new build target (helper in
`ants_core_lib` via `src/applyedits.{h,cpp}`; schema in `ants_claude_lib`).
No new external library. Each touched file is read fully into memory to
transform (source files are small); the per-file 4 MiB cap (INV-9, reusing
the read-tool family's `kReadToolMaxBytesCeiling` constant —
`cmdApplyEdits` is its first write-side consumer) is the named bound — a
file over it is skipped rather than slurped. Peak heap ≈ the largest single touched file (≤ 4 MiB),
one file at a time. This is the cap satisfying the no-unbounded-growth
rule.

## 5. Out of scope

- **Symbol-scoped** replace — still deferred; if needed it composes with
  ANTS-2021's symbol resolver in a follow-up. (v1 was literal
  `old`→`new` string replace only, native-`Edit` semantics; ANTS-3711
  added the **line-range** selector, so "line-anchored" has since left
  this list. It is anchored by the `expect_*` guard rather than being
  robust against drift on its own — it detects drift and refuses, which
  is the property that made it safe to ship.)
- Cross-file transactional atomicity (all-or-nothing across M files) — the
  filesystem offers no portable multi-file transaction; per-file atomicity
  + `applied[]`/`skipped[]` accounting is the contract (§ 2.4).
- Creating new files — `apply_edits` only edits existing files (a missing
  file is `skipped:"not_found"`). File creation stays with native `Write`.
