# ANTS-2164 — Harden the RC→release→new-RC cadence into one guarded `cut-rc.sh cycle`

**Status:** accepted (2026-06-24) — cold-eyes loops 1–6 folded, converged.
**Kind:** implement.
**Source:** ROADMAP.md ANTS-2164 (user-request-2026-06-24 — recurring RC/release
issues; failure-mode catalogue gathered 2026-06-24).
**Hardens:** ANTS-1318 (the weekly-Wednesday frozen-RC cadence). It adds NEW
hard guards at `promote` / `new-rc` rather than rewriting ANTS-1318's contract.
`ANTS-1318 INV-2` (public bits == the frozen RC tag) is **preserved** by this
spec's INV-6; the empty/placeholder refusal (this spec's INV-2) is a *new* guard
layered on the same `cut-rc.sh:270-272` diff-check site that `ANTS-1318 INV-2`
left as warn-and-continue. `ANTS-1318 INV-4` (the 14-day RC window, today with
"no automated test surface") is made **executable** by this spec's INV-8. All
other ANTS-1318 invariants are unchanged. (Cross-spec invariant references below
are written `ANTS-1318 INV-N`; a bare `INV-N` always means this spec's own.)

## 1. Problem

The release cadence (ANTS-1318) keeps producing the same class of incident:
the multi-step RC→release→new-RC dance has **warn-only guards** and
**manual steps that get skipped or done out of order**, so a broken state
ships or nearly ships. The 2026-06-24 failure-mode catalogue (and the live
0.7.97 cut) isolate three still-unguarded gaps plus one structural flaw:

1. **Empty RC in the degenerate same-tip case (the structural flaw).** The
   intended cadence (ANTS-1318 §1.1; user-confirmed 2026-06-24) is: week 1 cut
   the first RC from `main`; every Wednesday after, **promote the existing
   week-old (frozen) RC to public AND cut a new RC from current `main`**. The
   new RC is non-empty because a full week of work accumulated on `main`
   between the two cuts, and the public release is always the *promoted prior
   RC* — never a fresh `main` cut. The failure occurs only when a **fresh
   public release and the new RC are cut from the same commit the same day**,
   so no week of work separates them: the 2026-06-12 dual-cut tagged public
   `v0.7.96` **and** `v0.7.97-rc1` from the same tip
   (`git log v0.7.96..v0.7.97-rc1` = one chore bump `be66e9a`), so the RC was
   empty; the cadence then stalled 12 days while 82 commits piled on `main`.
   The 2026-06-24 cut reproduced it — `v0.7.98-rc1` tagged from the same tip as
   the `v0.7.97` release (`git log v0.7.97..v0.7.98-rc1` = one chore bump), so
   it too is empty and next Wednesday's promote would ship nothing. **Cutting a
   new RC from a tip with no work accumulated since the last release yields an
   empty frozen RC.**
2. **`promote` never refuses an empty/placeholder release** (FM-8/FM-15). Its
   only check is `git diff --quiet "${rctag}"` (working-tree-vs-tag), which
   *warns and continues* (`packaging/cut-rc.sh:270-272`; ANTS-1318 INV-2
   confirms "warns … and continues — no interactive confirmation"). Nothing
   blocks publishing an RC whose CHANGELOG section is still the
   "_No changes yet … opens the … preview channel_" placeholder.
3. **`promote` never rolls or date-stamps the CHANGELOG** (FM-15). It only
   *reads* the section (`release_notes()`, `packaging/cut-rc.sh:134-150`); the
   `## [Unreleased]` → `## [X.Y.Z] — <date>` roll and the debian-changelog date
   are hand-edited every release (done manually in the 0.7.97 cut). A skipped
   hand-edit ships a placeholder.
4. **The 14-day RC-not-promoted window (ANTS-1318 INV-4) is manual** (FM-11).
   No code computes an RC tag's age; the spec admits "no automated test
   surface" (`docs/specs/ANTS-1318.md:351-356`). The 0.7.97-rc1 stall went
   unflagged for 12 days.

The version-drift family (FM-1..4) is already well-guarded
(`packaging/check-version-drift.sh` + CI + the `CMakeLists.txt`-edit hook); this
spec does **not** re-solve it, but it promotes the drift check to a *hard gate*
at release time (today `cut-rc.sh` does not run it at all — `:106-114`
`build_and_test` only builds + tests).

**Layman:** Releasing today is a fragile checklist where one missed step
publishes an empty or half-finished release. This turns it into one command
that either does the whole release correctly or stops and says exactly what's
wrong.

## 2. Surface

All changes are to `packaging/cut-rc.sh` (the project-local orchestrator) plus
its feature test. No new build target, no new runtime dependency, no change to
the `/release` / `/bump` skills or `bump.json` (ANTS-1318 INV-9 preserved). The
body-drafting step (metainfo / debian release notes) is performed by the
existing `changelog-writer` subagent in the assistant layer — a shell script
cannot invoke a subagent — and the script *guards* its output (§2.4).

### 2.1 New helpers in `cut-rc.sh`

```bash
# True if the CHANGELOG "## [Unreleased]" section has ≥1 real entry. Slice =
# the lines after the "## [Unreleased]" heading up to the next "## [" heading
# (in the live CHANGELOG.md:13 that slice is empty — "## [Unreleased]" is
# immediately followed by "## [0.7.98] — …", so the helper reads FALSE today).
# A "real entry" = a line matching ^[[:space:]]*[-*] (a changelog bullet) or a
# "### Added/Changed/Fixed/…" category header; the italic placeholder prose
# "_No changes yet …_" (which lives under the [X.Y.Z] section, NOT here) does
# NOT count. This is the authoritative "is there a release's worth of work to
# preview?" signal — the project logs every shippable change to [Unreleased]
# via changelog_log, so it beats parsing commit subjects (the bump commits,
# e.g. `162259e chore: bump to 0.7.98 …`).
unreleased_has_content

# True if the <version>'s CHANGELOG section / release body is still the
# channel-opener placeholder. Each predicate FIRST isolates that version's
# slice — in CHANGELOG.md the "## [X.Y.Z]" section (up to the next "## ["); in
# packaging/linux/org.ants.Terminal.metainfo.xml the
# <release version="X.Y.Z"> … </release> element (that start tag to its
# </release>); in packaging/debian/changelog the "ants-terminal (X.Y.Z-1)"
# block (up to the next "ants-terminal (") — THEN matches the single-line
# anchor "opens the .* preview channel" WITHIN that slice (never a bare
# repo-wide match, so a lingering placeholder for a DIFFERENT version can't
# false-positive). The anchor is the substring common to all three files and
# intact on one line in each (verified 2026-06-24: CHANGELOG.md:21,
# org.ants.Terminal.metainfo.xml:108, debian/changelog:3). Do NOT key on the
# "no changes yet" phrasing: the metainfo says "No user-facing changes yet" and
# the debian block wraps "No changes yet" across a line.
changelog_section_is_placeholder <version>     # CHANGELOG.md ## [X.Y.Z]
release_body_is_placeholder <version>           # metainfo <release> + debian block
                                                # (CHANGELOG → changelog_section_is_placeholder)

# Roll the NON-EMPTY "## [Unreleased]" BODY into a "## [X.Y.Z] — unreleased
# (Patron RC preview)" section, leaving the "## [Unreleased]" heading in place
# with an empty body. The live layout is the two headings stacked
# (CHANGELOG.md:13 "## [Unreleased]" then :15 "## [0.7.98] — unreleased …") —
# never collapse them. Precedence when "## [X.Y.Z]" already exists: if its body
# is the channel-opener placeholder, REPLACE it with the [Unreleased] content;
# only no-op when [X.Y.Z] already has real content (idempotent). "Real content"
# reuses the unreleased_has_content predicate (a ^[[:space:]]*[-*] bullet or a
# "### Category" header) applied to the [X.Y.Z] slice — so the "**Theme:**" line
# and the italic placeholder prose correctly read as NOT real content. The
# replace swaps only the BODY beneath the "## [X.Y.Z]" heading; the heading and
# its "— unreleased (Patron RC preview)" suffix are left untouched for
# stamp_release_date to date at promote. Pure awk over CHANGELOG.md (no
# `sed -i` — see §8 test note).
roll_unreleased <version>

# Stamp the public-ship date in THREE release-note carriers, via awk to a temp
# file + atomic rename (NOT `sed -i`, to keep the Inv4BaseReadOnly source-scrape
# green — §8). At RC-cut the carriers hold a PROVISIONAL date: the metainfo
# date= attribute and the debian trailer must be valid dates for the files to
# validate, so `new-rc` writes the RC-cut date there, while the CHANGELOG header
# carries the literal "— unreleased (Patron RC preview)". `promote` rewrites all
# three to the public-ship date:
#   • CHANGELOG.md — "## [X.Y.Z] — unreleased (...)" → "## [X.Y.Z] — <iso-date>".
#   • packaging/linux/org.ants.Terminal.metainfo.xml — the
#     <release version="X.Y.Z" date="YYYY-MM-DD"> attribute → <iso-date>.
#   • packaging/debian/changelog — the RFC-2822 TRAILER line
#     "-- Name <email>  <RFC-2822 date>" of the (X.Y.Z-1) block (NOT the
#     "ants-terminal (X.Y.Z-1)" header, which carries no date); reformat the
#     <iso-date> arg to RFC-2822 via `date -R -d "<iso-date>"` (local tz, e.g.
#     → "Wed, 24 Jun 2026 00:00:00 +0200"). dpkg parses only the date for
#     ordering, so midnight/local-tz is fine.
# Refuses (exit≠0) if any target isn't found. The rewrite + its commit run only
# under --push (rehearsal prints what it would change, mutating nothing), like
# every other promote side effect.
stamp_release_date <version> <iso-date>

# Days since the in-flight RC TAG was created (git for-each-ref
# --format='%(creatordate:unix)' refs/tags/<rctag>), NOT the commit date — the
# 14-day window (ANTS-1318 INV-4) is measured from when the RC was cut, and a
# respin re-tags an older commit, so commit date would understate the age. If
# creatordate is empty (a lightweight tag — should not occur, `new-rc` makes
# annotated tags at cut-rc.sh:195), echo a large sentinel (9999) so the stale
# check fails CLOSED (over-age, never silently young). Echoes an integer.
rc_age_days <rctag>

# The hard drift gate: bash packaging/check-version-drift.sh || exit 1.
require_no_version_drift
```

### 2.2 Hardened `cmd_promote`

Pre-flight (each a HARD refusal, exit≠0, with a named override flag):

1. `require_clean_main` (existing).
2. `require_no_version_drift` — INV-5.
3. An in-flight RC exists (existing `inflight_base`).
4. **Not empty** — `changelog_section_is_placeholder` *and*
   `release_body_is_placeholder` must both be false; else refuse with
   `--promote-empty` escape hatch — INV-2.
5. **Not stale** — `rc_age_days ≥ 15` (strictly past the 14-day window; a
   14-day-old RC still promotes) refuses with `--force-stale` — INV-8.

Actions (in order, `--push`-gated as today):

6. `stamp_release_date <inflight> <today>`; commit the date-stamp on `main`,
   push — INV-3.
7. Tag `v<inflight>` at `"${rctag}^{commit}"` (unchanged; frozen bits) — INV-6.
8. Publish `gh release create` (no `--prerelease`); notes from `release_notes`.

`wednesday_guard` stays a soft warn (ANTS-1318 INV-1 is deliberately soft).

### 2.3 Hardened `cmd_new_rc`

Pre-flight (HARD refusals):

1. `require_clean_main`, `require_no_version_drift`.
2. One-RC-in-flight guard (existing, `:179-185`).
3. **Work to preview** — `unreleased_has_content` is true (the
   `## [Unreleased]` section has ≥1 real entry); else refuse: "nothing new to
   preview — skip the RC this week" (`--allow-empty-rc` override) — INV-1.
   *This is the guard that would have stopped both empty channel-opener cuts.*
4. **Bumped past the last release** — the base version has no public `vX.Y.Z`
   tag yet (the inter-phase `/bump` was done); else refuse: "base X.Y.Z is
   already public — run `/bump` first" — INV-9.

Actions:

5. `roll_unreleased <base>` — move `[Unreleased]` content into the named
   `## [base] — unreleased (Patron RC preview)` section; commit — INV-4.
6. Tag `v<base>-rc<N>` at `main` HEAD; `--prerelease`; publish (unchanged).

### 2.4 New `cmd_cycle` — the one-command Wednesday cadence

```
cut-rc.sh cycle [--push] [--skip-build]
```

`cycle` is the guarded Wednesday procedure: promote the in-flight RC, then cut
the next one. It does NOT bump the base version itself — `cut-rc.sh` never edits
version files (`ANTS-1318 INV-9`). The bump to N+1 between the two phases is an
assistant-orchestrated `/bump` step (same division of labour as §2.5: the
script guards, the assistant supplies content), so the realised flow is
`promote` → `/bump` to N+1 → `new-rc`, and `cycle` chains the two cut-rc.sh
phases around that bump. A skipped/forgotten bump can't cut a wrong RC — INV-9
catches it.

Each phase is independently gated. A phase SKIPS (logged, contributing a clean
status to `cycle`'s aggregate exit) only when there is *nothing to do*; it
HARD-REFUSES (logged loudly) when it finds something *broken*:

- *promote* — `cycle` pre-checks `inflight_base` itself: no in-flight RC → SKIP
  (without invoking `cmd_promote`, whose standalone `exit 1`-on-no-RC,
  `cut-rc.sh:265`, would otherwise fail the cycle on a normal no-RC week). An
  in-flight RC that EXISTS but is empty/placeholder (INV-2) or stale (INV-8) →
  HARD-REFUSE: never silently skipped, so a broken RC can't strand the release
  (the FM-11 failure).
- *new-rc* — SKIPS if `unreleased_has_content` is false (no work to preview);
  HARD-REFUSES if its base version is already a public tag (the bump was
  missed — INV-9).
- `cycle` cuts public(N) + RC(N+1) — exactly the case `ANTS-1318 INV-6`
  permits; never public(N) + RC(N) (INV-9 enforces this).

`cycle` runs `wednesday_guard` once up front and threads `--force-non-wed` to
both phases (one warning, not two). The build+test gate runs ONCE:
`cmd_promote` does not build (it tags the RC's already-built+tested frozen bits,
`cut-rc.sh:260-293` calls no `build_and_test`); only `new-rc` builds `main`
HEAD, and `--skip-build` skips that one build. A promote SKIP does not
short-circuit — `cycle` still runs `new-rc`; `cycle` exits 0 when every phase
succeeded-or-skipped-cleanly, non-zero if EITHER phase hard-refused — INV-7.

### 2.5 Body-drafting (assistant layer, guarded by the script)

When the assistant runs the cycle, before `new-rc` it drafts the metainfo
`<release>` block + debian block from the rolled `## [X.Y.Z]` CHANGELOG section
via the `changelog-writer` subagent (as in the 0.7.97 cut), then writes them.
`release_body_is_placeholder` (§2.4 promote guard) is the backstop: if the
bodies were never drafted, `promote` refuses. The script owns the *guarantee*;
the assistant owns the *content*.

## 3. Invariants

- **INV-1** — `new-rc` refuses to cut an empty RC: it exits non-zero unless
  `unreleased_has_content` is true (the `## [Unreleased]` section has ≥1 real
  entry beyond the channel-opener placeholder), absent `--allow-empty-rc`.
  *Test:* `release_rc_pipeline` fixture run — an empty / placeholder-only
  `[Unreleased]` refuses; one with a real entry passes.
- **INV-2** — `promote` refuses an empty/placeholder release: exits non-zero
  if the CHANGELOG `## [X.Y.Z]` section **or** the metainfo
  `<release version="X.Y.Z">` body **or** the debian `(X.Y.Z-1)` block still
  matches the channel-opener anchor `opens the .* preview channel`, matched
  **within the version's isolated section/block** (§2.1), absent
  `--promote-empty`. This is a *new* guard on the `cut-rc.sh:270-272`
  diff-check site, **not** a change to `ANTS-1318 INV-2`'s bit-identity
  contract (that is preserved by INV-6). *Test:* fixture — placeholder →
  refuse, real → pass, asserted against all three files.
- **INV-3** — `promote` auto-date-stamps the public-ship date in all three
  release-note carriers — `CHANGELOG.md` (`## [X.Y.Z] — unreleased (…)` →
  `## [X.Y.Z] — <today>`), the `packaging/linux/org.ants.Terminal.metainfo.xml`
  `<release … date="…">` attribute, and the `packaging/debian/changelog`
  RFC-2822 trailer (the `(X.Y.Z-1)` header carries no date — §2.1) — via awk +
  atomic rename, not `sed -i` (keeps the `Inv4BaseReadOnly` scrape green, §8).
  The rewrite + its commit run only under `--push` (rehearsal mutates nothing).
  The date-stamp commit lands on `main` HEAD (ahead of the frozen RC commit the
  tag points at — INV-6), so the published `vX.Y.Z` *tag tree* keeps the
  provisional "— unreleased" header while the GitHub release body is dated
  (`release_notes` reads the live working tree at run time); this is
  intentional — preserving the frozen bits (INV-6) matters more than the date
  in the tag's tree. *Test:* fixture asserts all three dates set to the run
  date on `main`; a rehearsal (`--push` absent) leaves the files unchanged.
- **INV-4** — `new-rc` auto-rolls: a non-empty `## [Unreleased]` body is moved
  into a `## [X.Y.Z] — unreleased (Patron RC preview)` section with content
  preserved, leaving the `## [Unreleased]` heading in place with an empty body
  (never collapsing the two headings). Precedence when `## [X.Y.Z]` already
  exists: replace a channel-opener-placeholder body with the `[Unreleased]`
  content; no-op only when `[X.Y.Z]` already has real content. *Test:* fixture
  — roll moves content; a second run is a no-op; a pre-existing placeholder
  section is replaced, not skipped.
- **INV-5** — the drift check is a HARD gate: `cycle`, `promote`, and `new-rc`
  invoke `check-version-drift.sh` and abort non-zero on failure (no
  warn-and-continue). *Test:* source-scrape (`require_no_version_drift` called
  in all three paths; aborts on non-zero) + a drifted-fixture run.
- **INV-6** — `promote` tags the frozen RC commit `"${rctag}^{commit}"`, never
  `main` HEAD; `main` being ahead of the RC is expected and does not block.
  Preserves `ANTS-1318 INV-2` (frozen bits Patrons tested). This is **already
  the behaviour** (`cut-rc.sh:275`) — preserved, no code change, scrape-locked.
  *Test:* source-scrape asserts the `^{commit}` tag target and that no promote
  path tags `main`/`HEAD`.
- **INV-7** — `cut-rc.sh cycle` runs `promote` then `new-rc`, each
  independently gated. A phase SKIPS (logged, contributing a clean status to
  `cycle`'s aggregate exit) only when there is *nothing to do*: no in-flight RC
  for promote, or `unreleased_has_content`
  false for new-rc. A phase that finds something *broken* — an in-flight RC
  that is empty/placeholder (INV-2) or stale (INV-8) — HARD-REFUSES (logged
  loudly, `cycle` exits non-zero), never silently skips, so a broken RC can't
  strand the release. A skipped phase never blocks the other. *Test:* fixture
  across the states (both ready; only-promote; only-new-rc; neither;
  in-flight-but-empty → refuse; in-flight-but-stale → refuse).
- **INV-8** — RC age is executable: `status` prints the in-flight RC's age in
  days; `promote`/`cycle` refuse (override `--force-stale`) when `rc_age_days
  ≥ 15` (day 14 is the last day an RC may still promote — `ANTS-1318 INV-4`'s
  14-day window is inclusive).
  This changes `ANTS-1318 INV-4`'s remedy from "the next `/release` flags it"
  to a hard refusal (override `--force-stale`) and makes its window executable.
  *Test:* source-scrape (`rc_age_days` + the ≥15 refusal) + a back-dated
  *annotated* tag fixture (a lightweight tag has no `creatordate` and falls
  back to commit date; `new-rc` makes annotated tags, `cut-rc.sh:195`)
  asserting the 14-vs-15 boundary.
- **INV-9** — `new-rc` refuses (exit≠0) if its base version (`CMakeLists.txt`)
  already has a public `vX.Y.Z` tag — i.e. the inter-phase `/bump` (§2.4) was
  missed, which would otherwise cut an RC for an already-released version and
  violate `ANTS-1318 INV-6` (no public(N) + RC(N)). (This is ANTS-2164's own
  INV-9 — distinct from `ANTS-1318 INV-9`, the unrelated "bump.json not
  extended" contract.) It is evaluated early in `cmd_new_rc`'s pre-flight,
  before the existing rc-tag-exists computation (`cut-rc.sh:187-190`), and is
  orthogonal to the §4.4 one-RC-in-flight guard (`cut-rc.sh:179-185`): that
  fires for a DIFFERENT base, INV-9 for an already-public SAME base. *Test:*
  fixture — base == an existing public tag refuses; base one ahead passes.

## 6. RAM / build cost

None. All changes are bash/awk in an existing script (no `sed -i`); no state
held, no build target, no external library. The feature test is source-scrape +
`QTemporaryDir` fixture runs (no network, no live `gh`).

## 7. Out of scope

- Fully shell-native markdown→metainfo-XML transform (FM-4 auto-generation):
  the deterministic guard (INV-2 placeholder refusal) plus subagent drafting
  (§2.5) is sufficient; a faithful in-shell transform is deferred unless the
  subagent step proves unreliable — tracked under ANTS-2164 follow-up only if
  it bites.
- Wednesday-cadence *enforcement* (ANTS-1318 INV-1 stays a soft warn).
- Automated Patron notification (ANTS-1318 OQ-5).
- `respin` re-roll: a respin (ANTS-1318 §2.3) re-tags rc(N+1) with
  cherry-picked fixes onto the existing RC; it does NOT re-run
  `roll_unreleased` (the roll is a `new-rc`-only step). A respin's fix gets its
  CHANGELOG entry appended to the already-rolled `## [X.Y.Z]` section by the
  author, as today — unchanged by this spec.
