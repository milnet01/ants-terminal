# ANTS-3669 — `doc_lint --fix`: the write half of the doc-lint composite

**Status:** spec draft, not yet reviewed.
**Kind:** implement.
**Source:** ROADMAP.md ANTS-3669 (cold-eyes-2026-07-28, split from ANTS-3663).
**Blocked by:** ANTS-3663 — the walk, the composition and the envelope this
extends; ANTS-3664 — the `autoFixable` flag this reads.
**Blocker for:** nothing. `/cold-eyes` § 1e consumes the read half and does not
need this.

**Layman:** The part of the document checker that actually repairs a file. It is
kept separate from the part that only looks, because anything that edits your
documents deserves a stricter review than anything that reads them.

---

## 1. Problem

ANTS-3663 composes five deterministic checkers into one findings list. One of
those findings — a table of contents that has drifted from the headings below it
— has exactly one correct repair, and a caller who has just been handed the
finding is one obvious step away from wanting it applied.

That step crosses a boundary the rest of the family never crosses: **this is the
only verb in the doc-lint set that writes to a file.** Everything else reads,
computes and returns. A defect in the read half returns a wrong string and the
caller notices; a defect here silently rewrites a document the user has not
opened.

Three contracts follow from that one fact, and none of them applies to the read
half:

- **A `dry_run` preview.** `docs/standards/mcp-tools.md` requires one of every
  mutating verb, computed by the same code path that performs the write so the
  preview cannot drift from the result.
- **Exclusion from `isEtagSupportedTool`.** ETag-304 is specified for read
  verbs. A matching `etag_match` short-circuits to `{ok, unchanged, etag}` —
  which, on a `fix:true` call, is a **success envelope for a repair that never
  happened**. The read half keeps its ETag support; this half gives it up.
- **`autoFixable` semantics.** What may be touched at all is a per-finding
  decision made by the producer, not a kind list the composer pattern-matches
  (ANTS-3664 § 2.1).

It is split from ANTS-3663 for that risk profile, not for length. The secondary
benefit is ordering: the read half can ship and serve `/cold-eyes` § 1e before
this exists, which is what the caller actually wants — the pre-pass reads far
more often than it repairs.

## 2. Surface

### 2.1 What may be fixed, and what may not

Auto-fixable is **exactly one kind**:

- **`toc_gap`** — a hand-maintained table of contents is regenerable from the
  document's own headings. There is one correct answer and the document already
  contains it.

The ROADMAP bullet behind ANTS-3663 also named a version string disagreeing with
`project(... VERSION X.Y.Z)` in `CMakeLists.txt`. **It is dropped, because no
checker in the composed set produces such a finding**: `DocIntegrity::Kind` is
`{DeadAnchor, BrokenLink, TocGap}`, `doc_citations` emits citation statuses, and
none of ANTS-3660/3661/3662 checks versions. A fix half for a finding nobody
emits is untestable by construction. If version drift is ever wanted it needs a
producer first, filed as its own item at that point — nothing is filed today.

**Everything else is report-only by design, not by omission**, and each refusal
has a reason rather than a shrug:

- deleting one of two duplicated facts needs a decision about which is
  canonical, and the wrong choice destroys the authoritative copy (ANTS-3660
  § 2.5);
- an unresolved symbol may be a forward reference to something the doc is about
  to create, which the verb must not adjudicate (ANTS-3661 § 2.3);
- renumbering an `INV-N` breaks every citation of it, which `specs.md` § 5.5
  forbids and `/cold-eyes` Phase 4 forbids again;
- a missing section needs prose only an author can write.

The gate is the **flag on the finding**, never the kind. An implementation that
tests `kind == "toc_gap"` instead of reading `autoFixable` passes every fixture
here and breaks the moment a native producer marks something else fixable —
which is the whole reason ANTS-3664 carries the flag.

### 2.2 Request and response

Both extend ANTS-3663 § 2.1 rather than replacing it; only the fix-specific keys
are given here.

```jsonc
// request — added to ANTS-3663's
{ "fix": false,       // opt-in, never the default
  "dry_run": false }  // compute the would-be result, write nothing

// response — added to ANTS-3663's, and ABSENT ENTIRELY under fix:false
{ "fixed":         [ { "verb": "doc_integrity", "kind": "toc_gap",
                       "file": "a.md", "line": 12, "emission_index": 0 } ],
  "files_written": 1,
  "fix_errors":    [ { "file": "d.md", "reason": "write_failed" } ] }
```

Absent, not zero. `files_written: 0` on a report-only run reads as "tried and
wrote nothing" when the truth is "never entered the fix path", and a caller
distinguishing those two is a caller checking whether it just modified the
user's tree.

**`fixed[]` is per finding; `files_written` is per file, and they are not the
same number.** Each element is `{verb, kind, file, line, emission_index}` —
enough to identify the finding that was repaired, not a description of the edit.
The emission index is there for the reason ANTS-3663 INV-7 needs it in the sort:
the other four do not uniquely identify a finding, so without it a caller cannot
join `fixed[]` back onto `findings[]`.

One document with three TOC gaps produces three `DocIntegrity::Finding`s
(`toc_gap` is per occurrence — `src/remotecontrol.cpp::docIntegrityBuildResponse()`
tallies it as a count, not a flag), one regenerated table of contents, and
therefore `fixed[]` of length three with `files_written:1`. Both numbers are
reported because a caller asking "did it touch anything it shouldn't" wants the
file count, and a caller reconciling against `findings[]` wants the finding list.

### 2.3 Files and hooks

No new engine and no new verb: this is `fix` and `dry_run` on `cmdDocLint`, plus
the regeneration itself in `src/doclint.{h,cpp}`. Two registration consequences,
both of them the point of the split:

- **`dry_run` is declared through the shared `makeDryRunProp()` factory**, like
  every other mutating verb. It must share the code path that computes the
  write — a preview assembled separately is a preview that drifts.
- **`doc_lint` is deliberately absent from `isEtagSupportedTool`.** § 1 gives
  the reason. This is a *removal* from the set ANTS-3663 § 2.5 inherits from
  ANTS-3661 § 2.4, so it is stated in both places rather than assumed.

Writes go through `QSaveFile` (atomic temp + rename), matching `apply_edits`.
A document is rewritten once per run, not once per finding.

## 3. Invariants

- **INV-1** — `fix:true` changes only `autoFixable` findings; `fixed[]` names
  each finding repaired and `files_written` counts files. *Test:* a tree of
  three documents — one with a TOC missing **two** H2s, one with a
  near-duplicate pair, one with an unresolved symbol → `fixed[]` of length
  **two**, `files_written:1`, and **the other two files byte-identical
  afterwards**. The two-gap TOC is deliberate: it separates the per-finding list
  from the per-file count, and a one-gap fixture makes both numbers 1 and tests
  neither. The byte-identical half is the assertion about restraint — a
  `fixed[]` of the right length proves nothing about what was left alone.
- **INV-2** — Default is report-only: without `fix`, no file is written.
  *Test:* the INV-1 tree run without the flag → every file byte-identical, and
  a source-scrape confirming the write path is reachable only under the flag.
- **INV-3** — `dry_run:true` returns the envelope a real run would return and
  writes nothing. *Test:* the INV-1 tree run with `fix:true, dry_run:true` →
  `fixed[]` and `files_written` **identical to the `dry_run:false` run**, the
  envelope carrying `dry_run:true`, and every file byte-identical. The identity
  half is what catches a separately-assembled preview; asserting only "wrote
  nothing" passes against a `dry_run` that returns an empty envelope.
- **INV-4** — `etag_match` never short-circuits a `fix:true` call. *Test:* run
  `fix:true` once, take the returned `etag`, and run again with that
  `etag_match` and a tree re-seeded with the same gap → the repair happens
  again, and the response is **not** `{ok, unchanged}`. This is the row that
  fails against the obvious registration, which is to add the verb to
  `isEtagSupportedTool` alongside its siblings.
- **INV-5** — A write failure on one document neither stops the run nor is
  silent. *Test:* a three-document tree with two repairable gaps where one
  target is read-only → `fix_errors[]` of length one naming that file with
  `reason:"write_failed"`, the other document repaired, `files_written:1`, and
  `ok:true`. A partial write is still a successful call; the incompleteness is
  in the envelope, not the status.

## 4. RAM / build cost

One document's text and its regenerated table of contents, both transient inside
one call and bounded by ANTS-3663's `maxDocBytes`. Nothing accumulates across
documents: a file is read, rewritten and dropped before the next is opened, so
peak memory is one document rather than the tree.

No new translation unit — the regeneration lands in the existing
`src/doclint.cpp`. No new external dependency.

## 5. Out of scope

- **Any fix beyond `toc_gap`.** The narrowness is the design; § 2.1 gives the
  reason per refused kind. A new fixable kind arrives with its producer, not
  ahead of it.
- **Repairing a document that no checker reported on.** The fix half consumes
  `findings[]`; it never scans independently.
- **A version-string fix.** Needs a producer first (§ 2.1). No follow-up id is
  filed because nothing is deferred — the work does not exist until a checker
  emits the finding.
- **Interactive or partial application** (fix this finding, not that one). If a
  caller needs that granularity it can filter with `checks[]` and re-run; a
  per-finding selector is a bigger surface than the one fixable kind justifies.

**Verified RED against feature-absent code before the implementation lands.**
INV-2 is the row that passes trivially against a verb with no write path at all,
which is the state it first runs in — so it is re-proven by mutation once the
write path exists: make the writer ignore the `fix` flag, and INV-2 must go red.
INV-4 gets the same treatment from the other direction: add `doc_lint` to
`isEtagSupportedTool` and INV-4 must go red. Record what the runs actually
produce, including any mutation that reddens nothing.

## 7. Cross-doc impact

- **ANTS-3663** loses § 2.3 and its INV-5 / INV-6, which are tombstoned in place
  rather than renumbered (`specs.md` § 5.5). Its § 2.1 keeps `fix` in the
  request schema and points here for the semantics.
- **ANTS-3664** § 2.1's `autoFixable` comment and § 5's "ANTS-3663 owns what
  auto-fixable means" both repoint here.
- **ANTS-3660** § 5 and **ANTS-3661** § 7 each say `doc_lint` must never
  auto-fix their findings; both repoint here, since this is now the document
  that could violate it.
- **`docs/standards/mcp-tools.md`** gains `doc_lint` in the `dry_run` supported
  list once this ships, and must NOT gain it in the ETag list.
