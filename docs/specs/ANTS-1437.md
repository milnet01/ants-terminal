# ANTS-1437 — `roadmap_query` section-index mode

**Status:** in flight (Vestige sweep pull 1, 2026-05-16).
**Kind:** implement (cross-session report).
**Lanes:** `remotecontrol` (`cmdRoadmapQuery`).
**Source:** vestige-cc-feedback-2026-05-16.
**Pairs with:** ANTS-1436 (response-cap mitigation — once a caller can
*see* section slugs, they can drill in via `section=` and avoid the
giant full-active payload). ANTS-1287 (introduced section mode +
`RoadmapIndex`). ANTS-1398 (rollup filter — small-end trim; this is
the discoverability companion).

## Problem

Vestige CC session 2026-05-16: there is no way to ask
`roadmap_query` "what sections does this roadmap have?" without
running a full-bullet query and post-processing the response.
Callers end up guessing slug names — Vestige guessed wrong on
several, burning round-trips, and ended up firing **12+ queries**
to drill into individual slices because the cheaper alternative
(one section-index call, then targeted section queries) didn't
exist.

The cost is paid twice: once on the wire (giant response with
bullets the caller doesn't need yet), once on the assistant's
context budget (the full bullets array is held even when only the
slug list was wanted).

## Goal

A new `mode:"section_index"` arg on `roadmap_query` that returns a
compact section index — `{slug, headline, level, active_count,
shipped_count, total_count}[]` — and **no bullets**. Typical
response size: < 5 KB on a 500-bullet roadmap, vs ~100 KB for the
full active payload.

## Design

### Arg

```jsonc
{
  "mode": "bullets" | "section_index",  // default: "bullets"
  // existing args (status, section, include_section_headers,
  // caller_cwd) unchanged.
}
```

Unknown mode → `{ok:false, code:"bad_mode", error:"unknown mode: <verbatim>"}`
with the same 64-byte / control-char hygiene as `bad_status` /
`bad_section`. Mode echo (`out["mode"]`) emitted only when the
caller passed the arg explicitly (matches the ANTS-1398 echo
pattern for `include_section_headers`).

### Mode interactions

- `mode:"section_index"` + `section:"<slug>"` → returns
  `{ok:false, code:"bad_mode_combo", error:"section_index mode does
  not accept section= filter"}`. The two are conceptually
  exclusive — section_index *is* the section-discovery surface.
- `mode:"section_index"` + `status:"<any>"` → counts always emit
  `active_count` / `shipped_count` / `total_count`. The status
  filter is **ignored** for section_index emission (counts are
  pre-categorised; the filter would be a no-op). The filter echo
  remains in the response for caller transparency (`filter:"all"`
  default behaviour).
- `mode:"section_index"` + `include_section_headers:<bool>` →
  ignored. Rollup bullets are not in the section_index emission;
  the field is bullet-mode-only.

### Counting

`parseBullets` already sets `sectionSlug` on every record (per
`roadmapdialog.cpp:745`). One full-file parse yields all the
tally inputs:

```cpp
QHash<QString, QVector<int>> counts;  // slug → {active, shipped, total}
for (const auto &b : bullets) {
    auto &c = counts[b.sectionSlug];
    if (c.isEmpty()) c = {0, 0, 0};
    if (b.status == plannedEmoji || b.status == progressEmoji) c[0]++;
    if (b.status == doneEmoji) c[1]++;
    c[2]++;
}
```

Empty sections (heading exists, no bullets inside) are emitted with
`active_count: 0, shipped_count: 0, total_count: 0`. The full
section list comes from `RoadmapIndex::buildIndex`, not from the
bullet tally — that way callers see *every* section, including
empty ones (discoverability).

Rollup bullets (empty id + empty headline; ANTS-1398) are excluded
from `total_count` regardless of `include_section_headers`. Rollups
are display artefacts of the section's own headline, not bullets
the caller asked about.

### Envelope

```jsonc
{
  "ok": true,
  "mode": "section_index",      // echoed only when caller passed mode arg
  "path": "/abs/path/ROADMAP.md",
  "filter": "all",              // status filter echo (no-op in this mode)
  "sections": [
    {
      "slug": "ants-mcp-improvements-...",
      "headline": "🔌 Ants MCP — improvements from running ...",
      "level": 3,
      "active_count": 21,
      "shipped_count": 7,
      "total_count": 28
    },
    {
      "slug": "tab-ux",
      "headline": "🐜 Tab UX",
      "level": 3,
      "active_count": 0,
      "shipped_count": 0,
      "total_count": 0
    }
  ]
}
```

`headline` is the raw heading text (sans leading `##`/`###`
markdown markers). Markdown formatting (emoji prefixes, embedded
bold/italic) flows through verbatim — the caller is the right
audience to decide whether to strip.

`level` is `2` for `##`, `3` for `###`. The roadmap-format spec
forbids `#` and treats `####+` as out-of-spec; the index ignores
them per ANTS-1287 INV-3.

### Cache reuse

The existing roadmap cache (`m_roadmapCachePath` / `_MtimeMs` /
`_StampMs` / `_Bullets` / `m_roadmapIndex`) is the source of truth.
section_index mode warms both caches if cold:

1. Cache check (path + mtime + 100ms wall-clock TTL): if fresh,
   reuse `m_roadmapCacheBullets` and `m_roadmapIndex`. Build
   either if empty (lazy-fill pattern from ANTS-1287).
2. If neither is populated, do **one** read + one parse + one
   index build, populate both caches, emit envelope.

No new cache fields. The mode arg is read-orthogonal — it doesn't
need its own slot.

### Dispatch

In `cmdRoadmapQuery` (`src/remotecontrol.cpp:960`), after the
status / section / include_section_headers parse and after the
cache check, branch on `mode == "section_index"` to a new helper
that returns the section-index envelope before the existing
bullet-emission paths.

## Invariants

- **INV-1 / default mode is unchanged.** `roadmap_query{}` and
  `roadmap_query{mode:"bullets"}` produce byte-identical envelopes
  (with the exception of the `mode` echo, which is present only
  when the caller passed the arg).
- **INV-2 / unknown mode rejected with hygiene.** `mode:"foo"`
  returns `code:"bad_mode"`; the verbatim echo follows the 64-byte
  + control-char-`?` rules from `bad_status` / `bad_section`.
- **INV-3 / mode + section is bad_mode_combo.**
  `mode:"section_index"` with a non-empty `section` arg returns
  `code:"bad_mode_combo"`. Neither cache is touched.
- **INV-4 / every section in the index is emitted (status:all).**
  Under the default `status:"all"`, sections with zero bullets emit
  with `total_count:0` — discoverability beats output size at the
  bullet-tally level (a section with no bullets is still a section a
  caller might query). **Amended by ANTS-1848:** under
  `status:"active"` / `status:"shipped"` the emission is filtered (see
  INV-7).
- **INV-5 / counts match bullet-mode result.** For any slug `S`,
  `section_index.sections[S].active_count` equals
  `len(roadmap_query{section:S, status:"active",
  include_section_headers:false}.bullets)`. Status filter `all` →
  total_count; `shipped` → shipped_count.
- **INV-6 / rollup bullets excluded from counts.** A rollup
  bullet (empty id + empty headline; ANTS-1398) inside section S
  does NOT contribute to `S.total_count`. Symmetric with bullet-
  mode's default `include_section_headers:false` behaviour.
- **INV-7 / status filter shapes section_index emission (ANTS-1848).**
  Superseded the original "status filter is a no-op" rule. Now:
  `mode:"section_index"` + `status:"active"` emits only sections whose
  `active_count_id_only > 0`; `status:"shipped"` only those whose
  `shipped_count_id_only > 0`; `status:"all"` (the default) emits every
  indexed section unchanged (INV-4). The `*_id_only` tally is the
  predicate — not the emoji-only count — so the kept set matches the
  default `bullets[]` ID-filter: a section retained here returns a
  non-empty bullets-mode query for the same status. All modes still
  echo `filter:"<as supplied>"` for transparency. Rationale: the
  common planning call (`status:"active"`) was returning ~140 sections,
  the large majority `active_count:0` (every shipped release block) —
  pure noise for a query whose purpose is "what's left to do".
- **INV-8 / `unrecognised_format` gate applies.** If the cache
  fill produces zero bullets AND the file exceeds
  `kRoadmapMinParseableSize`, section_index mode emits the same
  `{ok:false, code:"unrecognised_format"}` envelope as bullet mode
  (ANTS-1429 parity — the gate fires before mode dispatch).

## Tests

`tests/features/roadmap_query_section_index/`:

- **`spec.md`** — mirrors the INVs above.
- **`test_roadmap_query_section_index.cpp`** — source-scrape
  + cmdRoadmapQuery-roundtrip tests. Uses `QTemporaryDir` with a
  synthetic ROADMAP.md (3 sections, mix of active/shipped/empty
  bullets):

  ```markdown
  ## A
  - 📋 [ANTS-1] **a-active.**
  - ✅ [ANTS-2] **a-shipped.**

  ## B
  - 📋 [ANTS-3] **b-active.**
  - 📋 [ANTS-4] **b-active-2.**

  ## C
  (no bullets)
  ```

  Eight INV anchors:
  - INV-1: `mode:"bullets"` ⇔ no mode ⇔ byte-identical (modulo
    mode echo).
  - INV-2: `mode:"foo"` → `bad_mode` + verbatim sanitisation.
  - INV-3: `mode:"section_index" + section:"a"` →
    `bad_mode_combo`.
  - INV-4: section C with zero bullets is in the response under
    `status:"all"`.
  - INV-5: counts match bullet-mode-with-filter for A, B.
  - INV-6: a rollup bullet (manually inserted as `- 📋` with no
    id+headline) does NOT contribute to its section's total_count.
  - INV-7 (ANTS-1848): under `status:"active"` the emission loop skips
    sections whose `active_count_id_only` is 0 (source-scrape: the
    `filter == "active" && t.activeWithId == 0` continue guard); the
    `status:"all"` default keeps every section.
  - INV-8: zero-bullets fixture > kRoadmapMinParseableSize triggers
    `unrecognised_format` even under section_index mode.

## RAM / build cost

Zero new state. Reuses the existing roadmap cache (≤ ~50 KB
typical). Code addition: ~50 LoC in `cmdRoadmapQuery` (helper
function + branch) + ~50 LoC of schema updates + ~150 LoC test =
**~250 LoC** including tests.

## Migration

None. Additive arg with a default-back-compat behaviour. Existing
`roadmap_query` calls behave identically.

## Tool-descriptor update

`tools/list` entry for `roadmap_query` adds the `mode` arg to the
schema. Description gains one sentence: *"`mode:"section_index"`
returns a compact `sections[]` index (slug + headline + level +
counts) instead of `bullets[]` — use for slug discovery before
drilling in via `section=`."*

  spec is the discoverability companion: section mode let you
