# ANTS-3600 — Audit lane: contract-doc literal-drift catcher

**Status:** accepted (2026-07-24) — user sign-off; cold-eyes loops 1–7 folded; scope resolved to both dirs (§ Open questions).
**Kind:** enhancement.
**Source:** ROADMAP.md ANTS-3600 (in-session-2026-07-24, ANTS-3598/3599 follow-up).
**Blocked by:** ANTS-3603 (shared fence-aware markdown scanner — its `src/markdownscan.h` interface is defined in ANTS-3601 § 2.2; there is no separate ANTS-3603 spec doc).
**Pairs with:** ANTS-3601 (deterministic doc-integrity check — its sibling; internal-consistency vs doc-vs-code).

## 1. Problem

Contract docs under `docs/standards/` and `docs/specs/` quote code
literals in backticks — regex fragments, file paths, function names,
constants, config keys. When the code they quote is renamed or changed
and the doc is not updated in the same commit, the doc silently drifts
into a lie. The implementer or maintainer who trusts the contract then
builds or calls the wrong thing.

This class of drift escaped review twice on 2026-07-24, caught only by a
human cold-eyes reader, never by a tool:

1. **ANTS-3598** — `docs/standards/mcp-feedback-files.md` described the
   fence-opener indent as space-only, but `src/feedbackfile.cpp` `fenceRe`
   (`feedbackfile.cpp:34`) actually matched `^\s{0,3}(```|~~~)` (which also
   admits a tab). Doc and code had diverged on a literal.
2. **ANTS-3599** — `mcp-feedback-files.md` said an absent id renders
   `archived/unknown`, but `remotecontrol.cpp:12588` emits `unknown`. The
   doc quoted a slash-path string the code no longer produced.

There is an existing audit lane that does exactly this shape of check for
a *different* doc set — `FeatureCoverage::runSpecDriftCheck`
(`featurecoverage.cpp:394`) extracts backtick tokens from each
`tests/features/*/spec.md` and flags any that no longer appear in project
sources. ANTS-3600 generalises that machinery to the contract-doc corpus.

**Scope caveat (read before § 2):** of the two motivating incidents, this lane
fully resolves **case 2** (ANTS-3599 — slash-path / filename literals) but
**not case 1** (ANTS-3598 — regex-fragment literals), which stays a human-only
catch. Freeform regex literals cannot be tokenised deterministically without a
false-positive flood; the deferral is detailed in § 2.4 / § 6. So "this class
of drift" above is only *partly* automated — do not read a shipped ANTS-3600 as
closing the ANTS-3598 shape.

**Consequence:** without this lane, every doc-vs-code literal drift relies
on a human noticing during cold-eyes — an unreliable, expensive gate that
already failed twice in one day.

## 2. Surface

A new in-process audit lane, reusing the `FeatureCoverage` parsers and the
existing `inProcessRunner` escape hatch. No new dialog wiring pattern — it
follows `spec_code_drift` (`auditdialog.cpp:474`) exactly.

### 2.1 Where the code lives

- **`src/featurecoverage.{h,cpp}`** — four additions:
  - `QString buildProjectSourceBlob(const QString &projectPath, const BlobOptions &opts = {})`
    — the existing whole-tree blob builder (`featurecoverage.cpp:265`),
    refactored to take options (see § 2.3). The **default argument is
    load-bearing**: it keeps both current 1-arg call-sites —
    `runSpecDriftCheck` (`featurecoverage.cpp:403`) and
    `DebtSweepEngine` (`debtsweepengine.cpp:156`) — compiling and
    behaviourally unchanged (default `BlobOptions{}` == the current
    behaviour). Neither existing call-site is edited.
  - `QList<SpecToken> extractDocLiteralTokens(const QString &docText)`
    — a fence-aware, path-widened variant of `extractSpecTokens`
    (§ 2.4). Distinct function so the existing `tests/features` lane's
    token shape is untouched (§ 11 stay-in-lane).
  - `QString runContractDocDriftCheck(const QString &projectPath)`
    — the runner (§ 2.5), mirroring `runSpecDriftCheck`.
  - `QSet<QString> loadAllowlist(const QString &projectPath)`
    — reads `<root>/.ants_doc_drift_allow.txt` into the token set (§ 2.6);
    returns empty if absent.
- **`src/auditdialog.cpp`** — register one `AuditCheck` in `populateChecks`
  (next to `spec_code_drift`, whose `id` literal is at `auditdialog.cpp:476`),
  `id = "contract_doc_drift"`,
  `c.inProcessRunner = &AuditDialog::runContractDocDriftCheck`. As with the
  existing lane, `AuditDialog::runContractDocDriftCheck` is a thin static
  forwarder to `FeatureCoverage::runContractDocDriftCheck`. The lane is
  dispatched by `AuditDialog::runNextCheck` (`auditdialog.cpp:4361`), the
  **GUI-dialog** in-process path.
- **Where it runs:** the in-process (`inProcessRunner`) audit lanes are
  dispatched only by the GUI Audit dialog today, exactly like the existing
  `spec_code_drift` / `changelog_test_coverage` lanes. The headless MCP
  `audit_run` path (`AuditRunner::runAudit`, `src/auditrunner.cpp`) has **no**
  `inProcessRunner` dispatch — it runs the hardcoded `kKnownTools()` QProcess
  list — so `contract_doc_drift` does **not** fire via `audit_run` until that
  pre-existing gap is closed (ANTS-3605, § 6). No `auditrunner.cpp` change is
  in this spec's scope.

### 2.2 The `AuditCheck` registration

```cpp
AuditCheck c;
c.id          = "contract_doc_drift";
c.name        = "Contract-Doc ↔ Code Drift";
c.description = "Back-ticked literals in docs/standards + docs/specs that no "
                "longer appear in project sources";
c.category    = "General";
c.type        = CheckType::CodeSmell;
c.severity    = Severity::Minor;   // human-triage finding, never auto-fixed
c.autoSelect  = true;
c.available   = true;
c.filter.maxLines = 0;             // UNCAPPED — see below
c.inProcessRunner = &AuditDialog::runContractDocDriftCheck;
```

**`c.filter.maxLines = 0` is load-bearing.** The `inProcessRunner` output is
post-processed through the **same** `handleCheckOutput` → `applyFilter` path as
the shell-command lanes (`auditdialog.cpp:4361`+), and `OutputFilter::maxLines`
**defaults to 100** (`auditengine.h:60`); `applyFilter` `break`s once
`keptCount >= f.maxLines` (`auditengine.cpp` tail) with **no** truncation
signal. Over the FP-heavier `docs/specs/` corpus (~200 files, § 2.7), a run can
easily exceed 100 findings — the default cap would silently drop everything past
the 100th (and, since § 2.5's walk is `sorted`, always the same
alphabetically-later docs), starving the § 2.7 seed pass and masking drift in
later docs on *every* run. `applyFilter` treats `maxLines <= 0` as uncapped
(the `f.maxLines > 0` guard), so `0` disables the cap. *(The existing
`spec_code_drift` lane leaves the 100 default; its `tests/features/` corpus is
small enough that it never bites — a latent limit this spec must not inherit.)*

### 2.3 The blob — code-only + filename manifest

The existing `buildProjectSourceBlob` concatenates the contents of the
whole tree **including `*.md`** (the `kExts` list at `featurecoverage.cpp:276`,
`"*.md"` entry at `:285`). For contract-doc drift that is wrong: a literal quoted in `docs/standards/foo.md` would match
its own prose in the blob and never flag. But naively excluding all `*.md`
over-corrects — a doc legitimately citing another doc's filename
(`` `roadmap-format.md` ``) would then flag as drift because that filename
lives only in `*.md` files.

Resolution — `BlobOptions`:

```cpp
struct BlobOptions {
    bool includeMarkdownContents = true;   // existing behaviour (default)
    bool appendPathManifest      = false;  // append every walked file's rel-path
};
```

The contract-doc runner passes
`{.includeMarkdownContents = false, .appendPathManifest = true}` (designated
initializers — both fields are `bool`, so positional init would silently swap
semantics if the struct ever gains a field; C++20 idiom per global CLAUDE.md § 5):

- `includeMarkdownContents = false` — `*.md` file **bodies** are excluded, so
  doc prose cannot self-satisfy a quoted literal. All non-`.md` code/config
  extensions (`.cpp .h .py .lua .json .yml .toml .xml .cmake .txt` …) keep
  their existing inclusion, so config-key literals (`` `x-checker-data` ``)
  still resolve.
- `appendPathManifest = true` — the manifest records **every** walked file's
  project-relative path, and the append must happen **first — before any of
  the walk's `continue` gates**. The current walk skips files by **name**
  (`spec.md` at `featurecoverage.cpp:335`; `ROADMAP.md` / `CHANGELOG.md` at
  `:340`) and by **extension** (the `kExts` match, whose list begins at
  `:276`) *before* any content handling. Those gates must apply only to
  **content concatenation**, never to the manifest — otherwise a doc-cited
  filename that is name-excluded (`` `ROADMAP.md` ``, `` `CHANGELOG.md` ``,
  `` `spec.md` ``) or has an off-`kExts` extension (an image, a `.desktop`, an
  extensionless file) never reaches the manifest and false-flags as drift.
  `` `ROADMAP.md` `` / `` `CHANGELOG.md` `` / `` `spec.md` `` are each cited in
  backticks dozens of times across `docs/specs/` — ANTS-3600 §7 cites
  `` `CHANGELOG.md` `` itself — so this ordering is load-bearing, not a corner
  case.

Concretely the walk becomes two phases per file: (1) **unconditionally** append
its rel-path to the manifest; (2) apply the name-based and `kExts` gates plus
the `includeMarkdownContents` flag to decide whether to concatenate its
*content*. A quoted **filename** literal thus resolves against the manifest
without pulling any doc's prose into the blob, while the content exclusions
(`featurecoverage.cpp:335`, `:340`) plus `includeMarkdownContents=false` keep
doc prose out of the content half.

### 2.4 Token extraction — identifier + path shape, fence-aware

`extractDocLiteralTokens` differs from `extractSpecTokens`
(`featurecoverage.cpp:95`) in exactly three ways:

1. **Path-widened charset.** Add `/` to the token body so slash-paths
   (`archived/unknown`, `tools/e2e/cases.sh`) are captured:
   `` `([A-Za-z_][A-Za-z0-9_:\-\./]{3,})` ``. Everything else is reused
   verbatim — the same `stopwords()`, `isPseudoToken()`, min-length-4,
   and dedup guards (`featurecoverage.cpp:95-124`). **URL guard:** because the
   widened charset admits both `:` and `/`, a back-ticked URL
   (`` `https://example.com/x` ``) would otherwise become a token that never
   matches source and floods the lane; `extractDocLiteralTokens` skips any
   token matching a scheme prefix (`^[a-z][a-z0-9+.-]*://`, matched
   **case-insensitively** so `HTTPS://…` is also skipped), the same way
   `isPseudoToken` already skips Qt-API / lint-code shapes. (No corpus doc
   cites a URL in backticks today — this is a forward guard, not a live fix.)
2. **Fence-aware.** Lines inside fenced code blocks are skipped, because a
   fenced example (` ```bash / git commit / ``` `) is an *illustration*, not
   a contract claim, and flagging those would flood the lane. Fence state is
   provided by the shared scanner from ANTS-3603 (`src/markdownscan.h`), NOT a
   third hand-rolled copy. Inline single-backtick spans in prose remain in
   scope — that is where contract literals live.
3. **Citation guard (ANTS-3849).** A token whose head holds a `.` or `/` and
   which ends in `:N` or `:N-M` (`remotecontrol.cpp:2540`,
   `src/vault.py:39-49`) is skipped: the path manifest (§ 2.3) records paths
   with no line suffix, so the shape can never resolve and is false by
   construction. Measured on the Ants corpus 2026-08-13 — 1,146 of the lane's
   2,315 findings, 49.5%, the reason the category was unreadable. A citation's
   staleness has its own owner, the `doc_citations` verb (ANTS-3636), which
   resolves the anchor rather than the literal. The head test keeps a bare
   `symbol:123` and a JSON fragment (`limit:10`) in scope, and INV-5's bare
   slash-path is untouched.

**Out of extraction scope (deferred):** freeform regex fragments and
operator-laden literals such as ANTS-3598's `^\s{0,3}(```|~~~)`. These
contain spaces, backticks, and regex metacharacters that no deterministic
tokenizer extracts without a false-positive flood. Deferring them is why
ANTS-3600 catches ANTS-3599 (slash-path) but not ANTS-3598 (regex). Tracked
as out-of-scope in § 6; a follow-up id carries it if the demand proves real.

### 2.5 The runner

```
runContractDocDriftCheck(projectPath):
    if no docs/standards AND no docs/specs dir → return ""   # silent no-op
    blob = buildProjectSourceBlob(projectPath,
               {.includeMarkdownContents = false, .appendPathManifest = true})
    if blob empty → return ""
    allow = loadAllowlist(projectPath)                        # § 2.6
    out = ""
    for each *.md under docs/standards/ and docs/specs/ (sorted):
        docText = read(file)
        for tok in extractDocLiteralTokens(docText):
            if tok in allow → continue
            if existsInSource(blob, tok) → continue           # reused verbatim
            out += "<relpath>:<line>: doc references `<tok>` but no match "
                   "in project sources\n"
    return out.trimmed()
```

`existsInSource` (`featurecoverage.cpp:362`) is reused unchanged — its
substring-containment plus `::`/`.`-tail fallbacks already handle scoped and
dotted names correctly.

### 2.6 Allowlist

Intentionally-illustrative literals (hypothetical names, examples in prose
that are not contract claims) are suppressed by a project-local allowlist:

- **File:** `<root>/.ants_doc_drift_allow.txt` — one literal token per line.
  Parsing (pin these edges): each line is trimmed of leading/trailing
  whitespace and a trailing `\r` (CRLF tolerated); a line that is empty after
  trimming is ignored; a line whose first non-space character is `#` is a
  **whole-line comment** (there is **no** inline/trailing `#` comment — a
  `token # note` line is taken verbatim as the token `token # note`, so keep
  comments on their own line); every other trimmed line is one allowlist token.
  Absent file → empty allowlist (lane still runs). Read-only; the lane never
  writes it. A token is suppressed by **exact, case-sensitive string equality**
  against the extracted token (not substring, not prefix).
- **The allowlist file is excluded from the blob's content half** — it is a
  hidden `*.txt` at root, so the `QDir::Hidden` walk with `"*.txt"` in `kExts`
  would otherwise concatenate its body into the blob, and `existsInSource`
  (substring containment) would then resolve any token the file *mentions* —
  including inside a `#` comment — for the wrong reason, masking real drift.
  Add `.ants_doc_drift_allow.txt` to the same name-based content exclusion as
  `spec.md` / `ROADMAP.md` / `CHANGELOG.md` (§ 2.3). Its **path** may still
  appear in the manifest (harmless); only its **content** is kept out. The
  allowlist therefore suppresses a token **only** via the explicit
  exact-equality check, never via blob coincidence.
- Rationale for a flat text file over JSON: the existing audit-suppression
  precedents (`.audit_suppress` JSONL, `.audit_allowlist.json`) are keyed by
  finding-location; this is keyed by *token literal*, a simpler shape, and a
  human edits it by hand. Follows the "reuse existing project configs" audit
  posture — a new file only because no existing config is token-keyed.

### 2.7 Illustrative & forward-reference tokens (expected findings)

Contract docs legitimately contain back-ticked tokens that do **not** resolve
in current source, and this lane will surface them. Two classes:

- **Illustrative / hypothetical** — an example name a doc invents to explain a
  rule (`` `nonexistent_symbol_xyz` `` in this very spec's INV-1). This is the
  exact case the ROADMAP anticipated ("needs an allowlist for
  intentionally-illustrative literals — fenced examples, hypothetical names").
  Mitigation: **fence** the example (fenced spans are skipped, § 2.4) or
  **allowlist** it (§ 2.6).
- **Forward-reference** — a spec describing *planned* code cites symbols that
  do not exist **yet** (ANTS-3601 cites `gfmSlug`, `DocIntegrity`,
  `doc_integrity`, `markdownscan` before they are built). These resolve
  naturally once the code lands; until then they are true-but-transient
  findings.

Because of both classes, `contract_doc_drift` is deliberately
`Severity::Minor` + **human-triage** + non-blocking (§ 2.2) — it never gates a
build or a commit. **Rollout:** on first enable, do a one-time triage of the
existing corpus and seed `.ants_doc_drift_allow.txt` with the standing
illustrative/hypothetical tokens; forward-references are left to resolve as
their code ships. The `docs/specs/` corpus is materially FP-heavier than
`docs/standards/` for this reason (specs routinely forward-reference unbuilt
code); scanning both is a deliberate choice (resolved for both dirs,
2026-07-24 — § Open questions), so the first-enable seed pass and the ongoing
allowlist are load-bearing, not optional.

**Fixed paths (intentional divergence from ANTS-3601).** This lane hardcodes
`docs/standards/` + `docs/specs/`, like the sibling `spec_code_drift` hardcodes
`tests/features/`. It does **not** honour the portable `.ants/project.json`
`docs_dir` / `specs_dir` overrides that ANTS-3601's `doc_integrity` engine uses
(via `DocsIndex::walkDocs`) — `contract_doc_drift` is an Ants-Terminal audit
lane over a known layout, not a portable engine. A project with a relocated
docs dir gets no coverage here (acceptable: the lane self-no-ops, § INV-9).

## 3. Invariants

- **INV-1** — A backtick literal in a `docs/standards/` or `docs/specs/`
  `*.md` file that appears in **no** non-`.md` source file **and** matches no
  real file path in the tree is reported as drift. *Test:* fixture doc citing
  `` `nonexistent_symbol_xyz` `` → one finding.
- **INV-2** — A backtick literal that names a real file is **not** reported,
  **including** the name-excluded `ROADMAP.md` / `CHANGELOG.md` / `spec.md` and
  files with off-`kExts` extensions — the manifest append precedes every walk
  gate. *Test:* fixture doc citing `` `ROADMAP.md` ``, `` `CHANGELOG.md` ``,
  and an extensionless `` `LICENSE` `` (all present in the fixture tree) → zero
  findings; deleting them from the fixture tree makes all three flag (proves
  the manifest, not doc prose, is what resolves them).
- **INV-3** — A literal that exists only in another contract doc's **prose**
  (not in code, not a filename) **is** reported. *Test:* fixture where doc A
  cites `` `madeUpToken` `` that appears only inside doc B's prose → one
  finding (`includeMarkdownContents=false` excludes doc B's body).
- **INV-4** — Literals inside fenced code blocks are **not** extracted.
  *Test:* fixture doc with `` `driftedToken` `` inside a ```` ``` ```` fence →
  zero findings; the same token in an inline prose span → one finding.
- **INV-5** — A slash-path literal (`archived/unknown`) absent from sources
  is reported (path-widened charset). *Test:* fixture doc citing
  `` `archived/unknown` `` with no such string in code → one finding.
- **INV-6** — A token listed in `.ants_doc_drift_allow.txt` is never
  reported; `#`-comment lines and blank lines are ignored, and a token with
  surrounding whitespace matches after trimming. *Test:* an allowlist file with
  a `# comment` line, a blank line, and `  someDriftToken  ` (padded) suppresses
  `someDriftToken` → zero findings; delete that entry → one finding (proves the
  allowlist, not blob coincidence, is the reason — the file's content is
  excluded from the blob, § 2.6).
- **INV-7** — The `BlobOptions` refactor is behaviour-preserving for **both**
  existing 1-arg call-sites (`runSpecDriftCheck` at `featurecoverage.cpp:403`,
  `DebtSweepEngine` at `debtsweepengine.cpp:156`) — default `BlobOptions{}`
  reproduces today's whole-tree-including-`.md` blob. *Test:* the existing
  `tests/features/feature_coverage/` spec-drift fixtures and the debt-sweep
  suite still pass unchanged; the default `BlobOptions` is `{true, false}`.
- **INV-8** — `runContractDocDriftCheck` is a pure free function that produces
  the same `file:line: message` output regardless of caller, and is dispatched
  by the GUI Audit dialog's `inProcessRunner` path (`auditdialog.cpp:4361`).
  *Test:* the feature test drives `FeatureCoverage::runContractDocDriftCheck`
  directly (headless, no QtWidgets) and asserts the output shape — proving the
  runner is caller-agnostic. (The runner does **not** fire via MCP `audit_run`
  today — that's the pre-existing ANTS-3605 gap, § 6, not an INV of this spec.)
- **INV-9** — The lane is a silent no-op on a project with neither
  `docs/standards/` nor `docs/specs/`, and processes whichever of the two
  exists when only one is present. *Test:* runner over a tree lacking both dirs
  returns ""; a tree with only `docs/specs/` still scans that dir's docs.
- **INV-10** — The registered check leaves the audit output filter **uncapped**
  (`c.filter.maxLines == 0`), so no finding is silently dropped past the
  default 100-line cap. *Test:* a source-grep fixture over `populateChecks`
  (like the `tests/audit_fixtures/` rule checks) asserts the `contract_doc_drift`
  registration sets `maxLines = 0` — the feature test drives the runner
  directly and so cannot exercise `applyFilter`, making this a registration
  invariant.
- **INV-11** (ANTS-3849) — A `path:line` / `path:line-range` citation is not
  extracted, so it is never reported. *Test:* fixture doc citing
  `` `src/gone.cpp:2540` `` and `` `gone.cpp:39-49` `` (neither in the tree) →
  zero findings, while the bare `` `src/gone.cpp` `` and the non-path
  `` `limit:10` `` each flag once.

## 5. RAM / build cost

- **Memory:** the source blob is the dominant allocation — one `QString` of
  the concatenated non-`.md` tree plus a path manifest (a few KB). This is the
  **same** blob the existing `spec_code_drift` lane already builds per run;
  excluding `*.md` bodies makes it *smaller*, not larger (the path manifest adds
  ~tens of KB of path text for this repo's ~1,500 files — trivial). No persistent state,
  no cache — built per audit run, freed at return. No new eviction policy
  needed (bounded by project size, transient).
- **Latency:** one tree walk to build the blob + manifest, then a
  substring-containment lookup per extracted token — the same O(tree) +
  O(tokens × blob) shape the existing `spec_code_drift` lane already runs. On
  this project's corpus (blob a few MB, a few hundred contract-doc tokens) it
  is well under a second; it runs as one lane inside a full audit, not on any
  interactive hot path.
- **Build:** no new translation unit (additions land in existing
  `featurecoverage.cpp`); no new external library (`markdownscan` from
  ANTS-3603 is first-party Qt6::Core). Net cost ≈ one extra function compile.

## 6. Out of scope

- **Freeform regex / operator literals** (ANTS-3598 shape) — deferred, see
  § 2.4. If demand is real, a follow-up ROADMAP id adds a curated
  regex-literal extractor with its own fence + allowlist guards.
- **Auto-fixing drift** — this lane only *reports* for human triage
  (`Severity::Minor`). It never edits a doc; a flagged literal may be a
  legitimate rename the human resolves either way.
- **Substring false-negatives from the path manifest** — `existsInSource` is
  substring-containment (a deliberate, pre-existing tradeoff in the reused
  code), so a short identifier token could coincidentally match inside some
  file's *path* (e.g. a token `` `parse` `` masked by a `.../roadmapparse.cpp`
  path). Because the manifest records **every** walked file's path (§ 2.3), the
  collision surface is the **whole tree's path text** — on this repo ~1,500
  tracked files — not a small excluded subset. So a "no finding" result means
  "not in any file's content *or* any path." The path half weakens that
  confidence, which a human triaging results should keep in mind. It still only
  ever *misses* real drift
  (false-negative), never invents a false-positive. Left as-is (matching
  `spec_code_drift`'s containment design) rather than adding path-shape gating,
  which would complicate the reused lookup; the miss is rare because a real
  drifted literal rarely coincides with a path substring.
- **Non-`.md` contract docs** — scope is `docs/standards/` + `docs/specs/`.
  README/CLAUDE.md/CHANGELOG drift is covered by other lanes and cold-eyes.
- **Headless `audit_run` dispatch of in-process lanes** — out of scope and
  pre-existing (ANTS-3605). `contract_doc_drift` runs via the GUI Audit dialog
  like its `spec_code_drift` sibling; wiring the `inProcessRunner` registry
  into `AuditRunner::runAudit` so `audit_run` fires it is tracked separately.
