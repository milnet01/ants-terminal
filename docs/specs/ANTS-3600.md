# ANTS-3600 — Audit lane: contract-doc literal-drift catcher

**Status:** spec draft (2026-07-24).
**Kind:** enhancement.
**Source:** ROADMAP.md ANTS-3600 (in-session-2026-07-24, ANTS-3598/3599 follow-up).
**Blocked by:** ANTS-3603 (shared fence-aware markdown scanner).
**Pairs with:** ANTS-3601 (deterministic doc-integrity check — its sibling; internal-consistency vs doc-vs-code).

## 1. Problem

Contract docs under `docs/standards/` and `docs/specs/` quote code
literals in backticks — regex fragments, file paths, function names,
constants, config keys. When the code they quote is renamed or changed
and the doc is not updated in the same commit, the doc silently drifts
into a lie. The implementer or maintainer who trusts the contract then
builds or calls the wrong thing.

This class of drift escaped review twice on 2026-07-24, caught only by a
human cold-eyes reader, never by a tool:

1. **ANTS-3598** — `docs/standards/mcp-feedback-files.md` described the
   fence-opener indent as space-only, but `src/feedbackfile.cpp` `fenceRe`
   (`feedbackfile.cpp:34`) actually matched `^\s{0,3}(```|~~~)` (which also
   admits a tab). Doc and code had diverged on a literal.
2. **ANTS-3599** — `mcp-feedback-files.md` said an absent id renders
   `archived/unknown`, but `remotecontrol.cpp:12588` emits `unknown`. The
   doc quoted a slash-path string the code no longer produced.

There is an existing audit lane that does exactly this shape of check for
a *different* doc set — `FeatureCoverage::runSpecDriftCheck`
(`featurecoverage.cpp:394`) extracts backtick tokens from each
`tests/features/*/spec.md` and flags any that no longer appear in project
sources. ANTS-3600 generalises that machinery to the contract-doc corpus.

**Consequence:** without this lane, every doc-vs-code literal drift relies
on a human noticing during cold-eyes — an unreliable, expensive gate that
already failed twice in one day.

## 2. Surface

A new in-process audit lane, reusing the `FeatureCoverage` parsers and the
existing `inProcessRunner` escape hatch. No new dialog wiring pattern — it
follows `spec_code_drift` (`auditdialog.cpp:474`) exactly.

### 2.1 Where the code lives

- **`src/featurecoverage.{h,cpp}`** — three additions:
  - `QString buildProjectSourceBlob(const QString &projectPath, const BlobOptions &opts)`
    — the existing whole-tree blob builder (`featurecoverage.cpp:265`),
    refactored to take options (see § 2.3). The current no-arg call-site
    (`runSpecDriftCheck`) passes a default-constructed `BlobOptions` and is
    behaviourally unchanged.
  - `QList<SpecToken> extractDocLiteralTokens(const QString &docText)`
    — a fence-aware, path-widened variant of `extractSpecTokens`
    (§ 2.4). Distinct function so the existing `tests/features` lane's
    token shape is untouched (§ 11 stay-in-lane).
  - `QString runContractDocDriftCheck(const QString &projectPath)`
    — the runner (§ 2.5), mirroring `runSpecDriftCheck`.
- **`src/auditdialog.cpp`** — register one `AuditCheck` in `populateChecks`
  (next to `spec_code_drift`), `id = "contract_doc_drift"`,
  `c.inProcessRunner = &AuditDialog::runContractDocDriftCheck`. As with the
  existing lane, `AuditDialog::runContractDocDriftCheck` is a thin static
  forwarder to `FeatureCoverage::runContractDocDriftCheck`.
- **`src/auditrunner.cpp`** — the headless audit path dispatches
  `inProcessRunner` checks generically; no per-lane change needed (verify the
  generic dispatch covers the new id — INV-8).

### 2.2 The `AuditCheck` registration

```cpp
AuditCheck c;
c.id          = "contract_doc_drift";
c.name        = "Contract-Doc ↔ Code Drift";
c.description = "Back-ticked literals in docs/standards + docs/specs that no "
                "longer appear in project sources";
c.category    = "General";
c.type        = CheckType::CodeSmell;
c.severity    = Severity::Minor;   // human-triage finding, never auto-fixed
c.autoSelect  = true;
c.available   = true;
c.inProcessRunner = &AuditDialog::runContractDocDriftCheck;
```

### 2.3 The blob — code-only + filename manifest

The existing `buildProjectSourceBlob` concatenates the contents of the
whole tree **including `*.md`** (`featurecoverage.cpp:276`). For contract-doc
drift that is wrong: a literal quoted in `docs/standards/foo.md` would match
its own prose in the blob and never flag. But naively excluding all `*.md`
over-corrects — a doc legitimately citing another doc's filename
(`` `roadmap-format.md` ``) would then flag as drift because that filename
lives only in `*.md` files.

Resolution — `BlobOptions`:

```cpp
struct BlobOptions {
    bool includeMarkdownContents = true;   // existing behaviour (default)
    bool appendPathManifest      = false;  // append every walked file's rel-path
};
```

The contract-doc runner passes `{false, true}`:

- `includeMarkdownContents = false` — `*.md` file **bodies** are excluded, so
  doc prose cannot self-satisfy a quoted literal. All non-`.md` code/config
  extensions (`.cpp .h .py .lua .json .yml .toml .xml .cmake .txt` …) keep
  their existing inclusion, so config-key literals (`` `x-checker-data` ``)
  still resolve.
- `appendPathManifest = true` — after the walk, append one line per walked
  file with its project-relative path (all extensions, `.md` included). A
  quoted **filename** literal (`` `roadmap-format.md` ``, `` `remotecontrol.cpp` ``)
  resolves against the manifest without pulling any doc's prose into the blob.

The existing `spec.md` / `ROADMAP.md` / `CHANGELOG.md` content exclusions
(`featurecoverage.cpp:334`, `:345`) are preserved. Under
`includeMarkdownContents = false` they are already excluded by extension;
their **paths** still appear in the manifest, which is correct (they are real
files a doc may name).

### 2.4 Token extraction — identifier + path shape, fence-aware

`extractDocLiteralTokens` differs from `extractSpecTokens`
(`featurecoverage.cpp:95`) in exactly two ways:

1. **Path-widened charset.** Add `/` to the token body so slash-paths
   (`archived/unknown`, `tools/e2e/cases.sh`) are captured:
   `` `([A-Za-z_][A-Za-z0-9_:\-\./]{3,})` ``. Everything else is reused
   verbatim — the same `stopwords()`, `isPseudoToken()`, min-length-4,
   and dedup guards (`featurecoverage.cpp:95-124`).
2. **Fence-aware.** Lines inside fenced code blocks are skipped, because a
   fenced example (` ```bash / git commit / ``` `) is an *illustration*, not
   a contract claim, and flagging those would flood the lane. Fence state is
   provided by the shared scanner from ANTS-3603 (`src/markdownscan.h`), NOT a
   third hand-rolled copy. Inline single-backtick spans in prose remain in
   scope — that is where contract literals live.

**Out of extraction scope (deferred):** freeform regex fragments and
operator-laden literals such as ANTS-3598's `^\s{0,3}(```|~~~)`. These
contain spaces, backticks, and regex metacharacters that no deterministic
tokenizer extracts without a false-positive flood. Deferring them is why
ANTS-3600 catches ANTS-3599 (slash-path) but not ANTS-3598 (regex). Tracked
as out-of-scope in § 6; a follow-up id carries it if the demand proves real.

### 2.5 The runner

```
runContractDocDriftCheck(projectPath):
    if no docs/standards AND no docs/specs dir → return ""   # silent no-op
    blob = buildProjectSourceBlob(projectPath, {false, true})
    if blob empty → return ""
    allow = loadAllowlist(projectPath)                        # § 2.6
    out = ""
    for each *.md under docs/standards/ and docs/specs/ (sorted):
        docText = read(file)
        for tok in extractDocLiteralTokens(docText):
            if tok in allow → continue
            if existsInSource(blob, tok) → continue           # reused verbatim
            out += "<relpath>:<line>: doc references `<tok>` but no match "
                   "in project sources\n"
    return out.trimmed()
```

`existsInSource` (`featurecoverage.cpp:362`) is reused unchanged — its
substring-containment plus `::`/`.`-tail fallbacks already handle scoped and
dotted names correctly.

### 2.6 Allowlist

Intentionally-illustrative literals (hypothetical names, examples in prose
that are not contract claims) are suppressed by a project-local allowlist:

- **File:** `<root>/.ants_doc_drift_allow.txt` — one literal token per line,
  `#` line-comments allowed, blank lines ignored. Absent file → empty
  allowlist (lane still runs). Read-only; the lane never writes it.
- Rationale for a flat text file over JSON: the existing audit-suppression
  precedents (`.audit_suppress` JSONL, `.audit_allowlist.json`) are keyed by
  finding-location; this is keyed by *token literal*, a simpler shape, and a
  human edits it by hand. Follows the "reuse existing project configs" audit
  posture — a new file only because no existing config is token-keyed.

## 3. Invariants

- **INV-1** — A backtick literal in a `docs/standards/` or `docs/specs/`
  `*.md` file that appears in **no** non-`.md` source file **and** matches no
  real file path in the tree is reported as drift. *Test:* fixture doc citing
  `` `nonexistent_symbol_xyz` `` → one finding.
- **INV-2** — A backtick literal that names a real file (`` `roadmap-format.md` ``)
  is **not** reported, even though its only textual home is `*.md` files.
  *Test:* fixture doc citing a real doc filename → zero findings (manifest
  path-match).
- **INV-3** — A literal that exists only in another contract doc's **prose**
  (not in code, not a filename) **is** reported. *Test:* fixture where doc A
  cites `` `madeUpToken` `` that appears only inside doc B's prose → one
  finding (`includeMarkdownContents=false` excludes doc B's body).
- **INV-4** — Literals inside fenced code blocks are **not** extracted.
  *Test:* fixture doc with `` `driftedToken` `` inside a ```` ``` ```` fence →
  zero findings; the same token in an inline prose span → one finding.
- **INV-5** — A slash-path literal (`archived/unknown`) absent from sources
  is reported (path-widened charset). *Test:* fixture doc citing
  `` `archived/unknown` `` with no such string in code → one finding.
- **INV-6** — A token listed in `.ants_doc_drift_allow.txt` is never
  reported. *Test:* fixture with allowlisted token → zero findings; remove
  the allowlist entry → one finding (proves the allowlist is the reason).
- **INV-7** — `runSpecDriftCheck`'s existing behaviour is unchanged by the
  `BlobOptions` refactor. *Test:* the existing `tests/features` spec-drift
  fixtures still pass; the default `BlobOptions` is `{true, false}`.
- **INV-8** — The lane runs in both the GUI audit dialog and the headless
  `auditrunner` path via the generic `inProcessRunner` dispatch, producing
  identical `file:line: message` output. *Test:* headless run over a fixture
  tree emits the finding.
- **INV-9** — The lane is a silent no-op on a project with neither
  `docs/standards/` nor `docs/specs/`. *Test:* runner over a tree lacking
  both dirs returns "".

## 4. Tests

Feature-conformance test under `tests/features/contract_doc_drift/`
(`spec.md` + `test_contract_doc_drift.cpp`, added to an existing bundle's
`SOURCES` per `tests/features/README.md` — no standalone `add_executable`),
label `features;fast`. The test builds a small fixture tree in a temp dir
(docs + a `src/` file + an allowlist) and drives
`FeatureCoverage::runContractDocDriftCheck` directly (headless, no QtWidgets),
asserting INV-1 through INV-9.

Per the project test convention, **verify the test fails against pre-fix
code** — before the runner exists, the test must not compile/pass — then
restore. Each INV maps to at least one assertion above.

## 5. RAM / build cost

- **Memory:** the source blob is the dominant allocation — one `QString` of
  the concatenated non-`.md` tree plus a path manifest (a few KB). This is the
  **same** blob the existing `spec_code_drift` lane already builds per run;
  excluding `*.md` bodies makes it *smaller*, not larger. No persistent state,
  no cache — built per audit run, freed at return. No new eviction policy
  needed (bounded by project size, transient).
- **Build:** no new translation unit (additions land in existing
  `featurecoverage.cpp`); no new external library (`markdownscan` from
  ANTS-3603 is first-party Qt6::Core). Net cost ≈ one extra function compile.

## 6. Out of scope

- **Freeform regex / operator literals** (ANTS-3598 shape) — deferred, see
  § 2.4. If demand is real, a follow-up ROADMAP id adds a curated
  regex-literal extractor with its own fence + allowlist guards.
- **Auto-fixing drift** — this lane only *reports* for human triage
  (`Severity::Minor`). It never edits a doc; a flagged literal may be a
  legitimate rename the human resolves either way.
- **Non-`.md` contract docs** — scope is `docs/standards/` + `docs/specs/`.
  README/CLAUDE.md/CHANGELOG drift is covered by other lanes and cold-eyes.

## 7. Cross-doc impact

- `CHANGELOG.md` — new dated entry on ship.
- `docs/subsystems.md` — the audit lane catalogue gains one entry (if it
  enumerates lanes).
- No CLAUDE.md module-map change (no new file).
