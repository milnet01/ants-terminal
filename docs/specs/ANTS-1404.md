# ANTS-1404 — Per-tool `caller_cwd` contracts (Phase 3a)

## Problem

ANTS-1396 fixed the silent cross-project fallback when `caller_cwd`
is *provided but doesn't match* any open tab. The 2026-05-15 cross-
session report flagged the remaining gap: when `caller_cwd` is
*absent entirely*, tab-anchored tools (`get_git_status`,
`get_environment`, `get_last_command`, `get_scrollback`,
`get_text`) still silently anchor to the focused tab, and
path-anchored read tools (`last_audit_summary`, `git_state`) do
the same.

The leak shape: a Claude session inside project B, called by a
skill that forgot to pass caller_cwd, gets project A's git status
back when Ants happens to have an A-tab focused. The wrong-project
data has no marker — the caller can't tell it got cross-tenant
data versus their own.

Today the dispatch site at `claudeintegration.cpp:2628–2748`
treats every tool identically: extract args, route to provider
lambda, wrap output. There is no per-tool contract recorded
anywhere — each lambda decides on its own whether to honour
caller_cwd, ignore it, or treat it as routing data. The decisions
spread across 25-ish lambdas drift over time.

## Goal

Record the `caller_cwd` contract per tool as registry-level data,
then enforce the contract at the dispatch site before the lambda
runs. Phase 3a (this ticket) ships the framework + enforcement for
the `Required` category — the four tools whose silent
focused-fallback is the active leak shape. The other three
categories (`Optional`, `TabSpecific`, `ProcessGlobal`) are
classified and documented; their enforcement is a follow-up.

## Design

### `CallerCwdContract` enum

A new enum in `src/claudeintegration.h`:

```cpp
enum class CallerCwdContract {
    // Anchorable + leaks if absent — refuse with
    // {ok:false, code:"caller_cwd_required"} when caller_cwd is
    // empty/absent. Examples: get_git_status, last_audit_summary,
    // git_state, get_cwd.
    Required,

    // Anchor when caller_cwd is present, focused-tab fallback when
    // absent. Survey-from-outside is a legitimate use case for
    // these (the user wants the current project's roadmap/subsystem
    // map even from a Claude in a different project). Examples:
    // roadmap_query, subsystem, workspace_search, file_outline.
    Optional,

    // Per-tab reads that route on `tab` index *or* `caller_cwd`
    // (whichever resolves to a tab). The two are interchangeable
    // routing keys; refuse only when BOTH are absent. Phase 3a
    // does not enforce this — ANTS-1392 already routes via
    // caller_cwd, and the routing-vs-anchoring semantics overlap
    // enough that the refusal rule needs its own spec pass.
    // Examples: get_scrollback, get_text, get_last_command,
    // get_environment.
    TabSpecific,

    // No per-tab / per-project state; caller_cwd accepted-and-
    // ignored. Examples: mcp_trace, token_usage, tab_list,
    // get_session_info.
    ProcessGlobal,
};
```

### Per-tool classification

A static `std::unordered_map<QString, CallerCwdContract>` built
once at server start in `claudeintegration.cpp` (or
`mainwindow.cpp` alongside the provider registrations — see
"Implementation order" below). One entry per registered MCP tool;
unknown tools default to `Optional` so adding a new tool without
classifying it doesn't accidentally refuse calls.

Classification for the current 29 tools (28 at spec-time plus
ANTS-1400's `caller_cwd_info` added in the same bundle):

| Contract        | Tools |
|-----------------|-------|
| `Required`      | `get_git_status`, `last_audit_summary`, `git_state`, `verify_changes` |
| `Optional`      | `roadmap_query`, `subsystem`, `workspace_search`, `file_outline`, `plan_template`, `cold_eyes_partition`, `cold_eyes_brief`, `cold_eyes_cross_doc_diff`, `cold_eyes_fold_in`, `indie_review_partition`, `indie_review_brief`, `indie_review_corroborate`, `indie_review_synthesis_prompt`, `indie_review_fold_in`, `debt_sweep_scan`, `debt_sweep_apply_fix`, `debt_sweep_defer`, `debt_sweep_triage_prompt`, `session_memory`, `caller_cwd_info` |
| `TabSpecific`   | `get_scrollback`, `get_text`, `get_last_command`, `get_environment`, `get_cwd` |
| `ProcessGlobal` | `mcp_trace`, `token_usage`, `tab_list`, `get_session_info` |

Notes:
- `verify_changes` is in `Required` because it already enforces
  caller_cwd via RcGate (ANTS-1372). Classifying it here is
  documentation; the redundant check is fine (RcGate refuses first
  with `cwd_missing`; the contract check would emit
  `caller_cwd_required` to the same caller).
- `session_memory` is `Optional` here even though ANTS-1336 just
  made it require caller_cwd. The RcGate enforcement inside the
  handler already covers the leak; the classification picks the
  category that documents how the *MCP layer* treats the arg.
  Conceptually session_memory is now Required at the handler
  layer; classifying it `Optional` at the dispatcher means the
  dispatcher passes through (no double-refuse) and the handler
  has the say. A future refactor can hoist the gate up.
- `get_cwd` is `TabSpecific` because it reads a specific tab's
  shellCwd — not a project root. Echoing caller_cwd back is the
  current behaviour (see `mainwindow.cpp:3760`); classifying it
  `Required` would be a contract break for callers that ask
  "what's my Ants-tab's cwd?" before knowing their own.

### Dispatch-site enforcement

In `processTools` (around `claudeintegration.cpp:2628`), before
the idempotent-read cache check at line 2657, look up the
contract for `toolName`:

```cpp
// ANTS-1404 — per-tool caller_cwd contract enforcement. Run
// before the idempotent-read cache so a refused call doesn't
// pollute the cache, and before the get_session_info inline
// branch so the contract applies uniformly.
const CallerCwdContract contract = callerCwdContractFor(toolName);
const QString callerCwd =
    argsObj.value(QStringLiteral("caller_cwd")).toString();
if (contract == CallerCwdContract::Required && callerCwd.isEmpty()) {
    QJsonObject env;
    env["ok"]    = false;
    env["code"]  = QStringLiteral("caller_cwd_required");
    env["error"] = QStringLiteral(
        "%1: caller_cwd is required for this tool (ANTS-1404). "
        "Pass your $PWD as caller_cwd so the tool routes to your "
        "project rather than whichever tab Ants has focused.")
        .arg(toolName);
    responseText = QString::fromUtf8(
        QJsonDocument(env).toJson(QJsonDocument::Compact));
    toolHandled = true;
    // Falls through to the existing wrap + recordCall +
    // recordMcpTrace path — refusals still count as dispatches
    // for token_usage and mcp_trace observability.
}
```

`callerCwdContractFor(QString)` is a small static helper inside
the same TU that looks up the table and returns
`CallerCwdContract::Optional` on miss (graceful default — a tool
typo or a tool added without classification doesn't refuse calls).

### One-release deprecation note

The roadmap entry mentions "a one-release deprecation warning
before refusal." Phase 3a chooses **refuse immediately** rather
than warn-then-allow because:

- The leak the contract closes is a cross-tenant data exposure.
  Warn-then-allow ships the leak for another release.
- The refusal envelope is structurally distinct (`code:
  "caller_cwd_required"`) — callers can dispatch on it and update.
  Migration is mechanical: a single arg to add.
- No known live skill author depends on the focused-fallback path
  (`grep -rn "session_memory\|get_git_status\|git_state\|last_audit_summary" .claude/`
  in the project tree returns zero hits — none of the local
  /audit, /release, /bump, /indie-review skills omit
  caller_cwd).

The CHANGELOG entry under `Security` documents the contract break
and names the four tools affected.

## Invariants (post-fix)

- **INV-1.** `callerCwdContractFor(toolName)` returns the
  classification from a single static table. Every registered
  tool has an entry (kept in sync with `registerToolProvider`
  by the build — a future test asserts the registry sizes match).

- **INV-2.** Tools classified `Required` refuse with
  `{ok:false, code:"caller_cwd_required", error:"..."}` when
  `caller_cwd` is absent or empty, BEFORE the provider lambda
  runs and BEFORE the idempotent-read cache is consulted.

- **INV-3.** Tools classified `Optional`, `TabSpecific`,
  `ProcessGlobal` see no Phase-3a refusal path. Their provider
  lambdas run as before. TabSpecific enforcement deferred to a
  follow-up.

- **INV-4.** Unknown tools (typos, future additions without a
  classification entry) default to `Optional` — gracious degradation
  rather than refuse-by-default. Adding a tool intentionally
  Required-without-classification is a developer bug, not a
  production failure.

- **INV-5.** Refused calls still flow through `recordCall` and
  `recordMcpTrace` so `token_usage` and `mcp_trace` see them.
  Observability is unchanged.

- **INV-6.** The refusal envelope passes through `wrapMcpData`
  unchanged (matching the ANTS-1294 wrap policy for every
  non-control-plane response).

- **INV-7.** Cache layer is bypassed for refused calls — both
  insert and lookup. `maybeInsertIdempotentReadCache` is gated by
  `toolHandled && cacheable && !cachedHit`; refusals set
  `toolHandled = true` and `cacheable` depends on the tool name.
  The four `Required` tools are NOT in the idempotent-read
  allowlist (`isIdempotentReadTool` at `claudeintegration.cpp:2816`
  enumerates `get_cwd`, `get_environment`, `tab_list`,
  `last_audit_summary` — only `last_audit_summary` overlaps with
  `Required`). The refusal envelope for `last_audit_summary` must
  not enter the cache. The fix: order the contract check BEFORE
  the cache lookup (the design above already does this), and add
  an explicit `if (cachedHit) skip contract check` to avoid
  re-refusing cached payloads (cache hits are by definition
  successful prior dispatches that came WITH caller_cwd).

## Test

`tests/features/mcp_caller_cwd_contracts/`:

1. **Classification table sanity (source-scrape).** Verify
   `callerCwdContractFor` exists and the four `Required` tools
   appear in the classification block. Grep for
   `"get_git_status".*Required`, `"git_state".*Required`,
   `"last_audit_summary".*Required`, `"verify_changes".*Required`
   in `claudeintegration.cpp`.

2. **Dispatch-site refusal (source-scrape).** Verify the
   `processTools` body contains `code:"caller_cwd_required"`,
   refuses for `CallerCwdContract::Required + callerCwd.isEmpty()`,
   and runs the contract check BEFORE
   `tryGetIdempotentReadCache`.

3. **Cache-hit bypass (source-scrape).** Verify the contract
   check is gated on `!cachedHit` OR runs after the cache lookup
   in a way that doesn't re-refuse cache hits — assert that
   `last_audit_summary` cache hits don't trigger the contract
   refusal (since the prior successful dispatch carried
   caller_cwd).

4. **Refusal envelope shape (source-scrape).** The envelope
   includes `ok=false`, `code="caller_cwd_required"`, an error
   message that names both the tool and the missing arg, and
   passes through `wrapMcpData` unchanged.

Label `features;fast`. Source-scrape only — runtime testing the
MCP socket dispatch needs the full Qt event loop and isn't
warranted for this scope.

## Out of scope

- **TabSpecific enforcement.** Refusing when both `tab` and
  `caller_cwd` are absent for the 5 tab-specific tools is a
  separate spec pass because the semantics overlap with ANTS-1392's
  routing behaviour. Track as a follow-up ticket.
- **Tool-list schema changes.** The four Required tools' schemas
  already surface `caller_cwd` via `makeCallerCwdReadProp()`. The
  schema marking `caller_cwd` as `required` is a follow-up;
  Phase 3a leaves the schema as-is and enforces at the handler.
- **`session_memory` hoist.** ANTS-1336 enforces caller_cwd inside
  the handler (via RcGate). Hoisting that to the dispatcher's
  contract check would be a no-op behaviourally; refactor for
  Phase 3b.
- **Deprecation warning mode.** Phase 3a refuses immediately;
  no warn-then-allow path.

## Migration

CHANGELOG `Security` entry names the four affected tools and the
new refusal code. Local /audit, /release, /bump, /indie-review
skills don't omit caller_cwd (verified). External skill authors
who omit it see one refusal, read the error message, add the arg.

## RAM budget

Static `unordered_map<QString, CallerCwdContract>` with ~28
entries — ~1.5 KiB once. Constructed once at server start; lookup
is O(1) per dispatch. Zero per-call allocation.

## Build cost

One new enum + one classification map + one helper function + one
dispatch-site if/block. ~80 lines total in `claudeintegration.cpp`.
No new TUs.
