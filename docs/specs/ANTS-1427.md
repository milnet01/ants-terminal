# ANTS-1427 — MCP dispatch debug logging (multi-checkpoint)

## Problem

The 2026-05-16 ANTS-1422 investigation needed two diagnostic
pulls (envelope + production bypass) because no audit trail of
MCP dispatches existed. Every regression hypothesis required
redeploying a fresh diagnostic build with `qWarning()` lines or
JSON `debug` field additions.

The user's classic debugging approach — print relevant variables
at multiple checkpoints, annotated by location, so a variable's
change point can be pinned — wasn't available without code
edits. The next mystery should not need a re-shipped build.

## Goal

One bit-test in production, full per-call audit trail on
`ANTS_DEBUG=claude`. Multi-checkpoint so a variable can be
followed through the dispatch chain — not a single end-of-chain
summary.

## Design

Three log lines per MCP call, all gated on `DebugLog::Claude`:

1. **lambda-enter** (in `ClaudeIntegration::registerToolProvider`
   wrapper). Fires the moment a tool handler is invoked.
   Captures tool name + arg-key count. Single-site change —
   every registered tool inherits the line automatically.

2. **cmd-enter** (in `RemoteControl::cmdTokenUsage`). Fires when
   the handler body enters its `cmd*` function. Captures the
   incoming `ci` pointer. Per-cmd one-liner; added now for
   `cmdTokenUsage` (the historical hot spot); other `cmd*`
   sites add the same one-liner ad-hoc as future debugging
   needs surface.

3. **dispatch-end** (in `ClaudeIntegration::recordDispatch`).
   Fires once per dispatch — the unified observation point from
   ANTS-1402. Captures tool name, success/failure, arg bytes,
   out bytes, wrap bytes, duration µs, cached-hit flag.

Comparison across the three lines for a single call shows the
full pipeline. If a future tool fails the way `token_usage` did,
the audit trail pins the exact hop.

## Invariants

- **INV-1.** `registerToolProvider` wraps every handler with a
  `ANTS_LOG(DebugLog::Claude, "mcp lambda-enter tool=%s
  arg_keys=%lld", ...)` line before invoking the user's handler.
  Single site — covers all current and future MCP tools without
  per-tool edits.
- **INV-2.** `recordDispatch` emits a `ANTS_LOG(DebugLog::Claude,
  "mcp dispatch tool=%s result=%s arg_b=… out_b=… wrap_b=…
  dur_us=… cached=…")` line after both the token-usage record
  and the trace-ring update. Single observation point so the
  log line counts every dispatch exactly once across success
  + failure branches.
- **INV-3.** `cmdTokenUsage` emits a middle-checkpoint
  `ANTS_LOG(DebugLog::Claude, "mcp cmd-enter cmdTokenUsage
  ci=%p", ci)` line on function entry. Pointer value lets future
  debug sessions confirm `ci` captured at lambda-registration
  time matches `ci` here.
- **INV-4.** Zero overhead when `DebugLog::Claude` is off.
  `ANTS_LOG`'s `if (DebugLog::enabled(cat))` bit-test is the
  only cost; arg formatting is short-circuited.
- **INV-5.** Tool name flows through `toUtf8().constData()` —
  safe lifetime (temporary's lifetime extends to end of
  expression).

## Test

`tests/features/mcp_dispatch_debug_log/` — source-scrape pattern
(the log emission itself is gated behind a process-global bit
not safe to flip from a feature-bundle test):

1. **INV-1 (source-scrape).** Wrapper site in
   `registerToolProvider` exists with the `ANTS-1427` anchor,
   the `ANTS_LOG(DebugLog::Claude, ...)` invocation, the
   `mcp lambda-enter tool=%s` format string, and the
   `inner = std::move(handler)` capture.
2. **INV-2 (source-scrape).** `recordDispatch` body contains
   the `ANTS-1427` anchor, the `ANTS_LOG(DebugLog::Claude, ...)`
   invocation, the `mcp dispatch tool=%s` format string, and
   all three byte-count fields (`arg_b=`, `out_b=`, `dur_us=`).
3. **INV-3 (source-scrape).** `cmdTokenUsage` body contains
   the `ANTS-1427` anchor, the `ANTS_LOG(DebugLog::Claude, ...)`
   invocation, and the `mcp cmd-enter cmdTokenUsage ci=%p`
   format string.

Label `features;fast`. Integration path is exercised by every
other MCP test going through the lambda wrapper.

## Migration

None. Production behavior unchanged. The log lines fire only
when `ANTS_DEBUG=claude` is set at launch or `DebugLog::Claude`
is toggled at runtime (Tools → Debug menu).

## RAM budget

Zero in production (bit-test only). When enabled: one
`QFile::write` per dispatch, ~150 B per line × dispatch rate.
For a busy session with ~10 MCP calls/sec, that's ~1.5 KB/sec
of log file growth, capped only by the user toggling the
category off.

## Build cost

~25 LoC added across `claudeintegration.cpp` (wrapper, recordDispatch
log line) + `remotecontrol.cpp` (cmdTokenUsage cmd-enter line) +
the new `tests/features/mcp_dispatch_debug_log/` fixture (~110
LoC test, 3 invariants). Net link cost: nil (`ANTS_LOG` already
present; no new symbol).
