# ANTS-1253 — Consolidate MCP-tool provider registry

**Status:** spec, ship-ready after cold-eyes pass 2 fix-pass (2026-05-13).
**Source:** cold-eyes pass 2 finding on ANTS-1247, surfaced 2026-05-12.
**Blocked by:** ANTS-1247..1252 (all merged on `main`, listed under
CHANGELOG `[Unreleased]`; this refactor consolidates the surface
those tickets each added and lands in the same unreleased window).
**Siblings:** ANTS-1244, 1247, 1248, 1249, 1250, 1251, 1252, 1254.
**Kind:** refactor (no behaviour change). **Lanes:** claudeintegration,
mainwindow.

## 1. Problem

After ANTS-1244..1251 landed, `claudeintegration.{h,cpp}` carries **12
parallel `setXProvider` setters + 12 `m_xProvider` members + 12
provider-gated dispatch branches** in the JSON-RPC `tools/call` handler
— one set per outward-delegate MCP tool. A 13th dispatch branch handles
`get_session_info` inline (it reads `ClaudeIntegration`'s own state and
is not a delegate; see §3.2). The pattern is mechanically duplicated;
Rule of Three was crossed at the third delegate tool (ANTS-1244) and
is now at 12. Each new outward-delegate tool (ANTS-1254 in flight)
requires four edits in lockstep: setter decl, member decl, setter
body, dispatch branch. The dispatch chain at
`claudeintegration.cpp:1554-1646` spans 93 lines (12 outward branches
+ the `get_session_info` inline branch) of
`else if (toolName == "X" && m_XProvider)` boilerplate.

Verified counts (2026-05-13, by `grep -c` against current `main`):
- `m_*Provider` members in `claudeintegration.h`: **12**
  (lines 328-345 — `m_scrollbackProvider`, `m_cwdProvider`,
  `m_lastCommandProvider`, `m_gitStatusProvider`, `m_envProvider`,
  `m_roadmapQueryProvider`, `m_tabListProvider`, `m_getTextProvider`,
  `m_workspaceSearchProvider`, `m_fileOutlineProvider`,
  `m_gitStateProvider`, `m_subsystemProvider`; `get_session_info` has
  no provider — see §3.2).
- `setXProvider` decls in `claudeintegration.h`: **12** (lines 174-208).
- `setXProvider` bodies in `claudeintegration.cpp`: **12** (lines 1089-1143).
- `tools/call` dispatch entries: **13** total within the chain at
  lines 1554-1646 — 12 provider-gated outward-delegate branches + 1
  inline branch for `get_session_info`.
- `MainWindow::setupClaudeMcpProviders` lambda registrations: **12**
  (mainwindow.cpp:3550-3674; `setXProvider` calls span lines 3554-3670;
  `get_session_info` not registered).

Cost of the status quo:
- **Source-file weight.** ~120 LoC of mechanical boilerplate across two
  files. Future audits / cold-eyes / `/indie-review` re-read the
  duplication every time.
- **Add-a-tool friction.** 4 synchronised edits per new tool; if any
  one drifts, the tool silently no-ops in the dispatcher (`m_XProvider`
  null-check fails) without a build error.
- **Signature drift.** Six distinct `std::function<…>` shapes in use
  today: `QString(int)`, `QString()`, `QPair<int,QString>()`,
  `QString(const QString&)`, `QString(int,int)`,
  `QString(const QJsonObject&)` (see §2.1) — adding a seventh shape
  compounds the boilerplate.

## 2. Surface — single registry

### 2.1 Canonical signature

All 12 outward-delegate tools collapse to one shape:

```cpp
using ToolHandler = std::function<QString(const QJsonObject &args)>;
```

Argument: the tool-call's `arguments` object (already extracted from
`params.value("arguments").toObject()` in the dispatcher today).
Return: the tool's response as a JSON-string (wrapped by the
dispatcher into `result.content[].text`).

The 4 tools added in ANTS-1248..1251 (`workspace_search`, `file_outline`,
`git_state`, `subsystem`) already use this shape — their lambda bodies
in `MainWindow::setupClaudeMcpProviders` are unchanged by this refactor;
only the surrounding `setXProvider` → `registerToolProvider` syntax
changes. The 8 older tools are migrated by absorbing their argument
extraction and result formatting into the lambda body. Concretely:

| Tool | Today's shape | New lambda extracts | New lambda formats |
|------|---------------|---------------------|--------------------|
| `get_scrollback` | `QString(int)` | `args.value("lines").toInt(50)` | passthrough |
| `get_cwd` | `QString()` | (ignores args) | passthrough |
| `get_last_command` | `QPair<int,QString>()` | (ignores args) | builds `{exit_code, output, failed}` JSON |
| `get_git_status` | `QString()` | (ignores args) | passthrough |
| `get_environment` | `QString()` | (ignores args) | passthrough |
| `roadmap_query` | `QString(const QString&)` | `args.value("status").toString()` | passthrough |
| `tab_list` | `QString()` | (ignores args) | passthrough |
| `get_text` | `QString(int,int)` | `args.value("tab")` AND `args.value("lines")` — both gated by `isDouble()` | passthrough |
| `workspace_search` | already `QString(const QJsonObject&)` | unchanged | unchanged |
| `file_outline`     | already `QString(const QJsonObject&)` | unchanged | unchanged |
| `git_state`        | already `QString(const QJsonObject&)` | unchanged | unchanged |
| `subsystem`        | already `QString(const QJsonObject&)` | unchanged | unchanged |

The `get_text` extraction must preserve the `isDouble()` gate on **both**
`tab` and `lines`, noted at `claudeintegration.cpp:1609-1612` (ANTS-1244
INV-9 — `tab=0` is a valid index distinct from "tab omitted"). The
dispatcher passes `lines` through verbatim and the `cmdGetText` verb
defaults `lines<=0` to 100; the `isDouble()` gate on `lines` exists to
match the IPC verb's omit-vs-zero semantics symmetrically. Test
asserts this behaviour post-migration (INV-3).

### 2.2 Public API on `ClaudeIntegration`

Replace 12 setters with one registrar:

```cpp
// In the public section, alongside startMcpServer / stopMcpServer:
void registerToolProvider(const QString &name, ToolHandler handler);
```

Replace 12 members with one map:

```cpp
// In the private section:
std::map<QString, ToolHandler> m_toolProviders;
```

`std::map` not `QHash`: tool names are read once on dispatch and
contention is zero (single-threaded MCP socket handler). `std::map`
gives stable iteration order so debug logs / tests are deterministic.

### 2.3 Dispatch chain

The 12 outward-delegate branches (one bare `if` for `get_scrollback`
plus 11 `else if (toolName == "X" && m_XProvider)`) collapse to:

```cpp
} else if (auto it = m_toolProviders.find(toolName);
           it != m_toolProviders.end()) {
    QJsonObject args = params.value("arguments").toObject();
    result["content"] = makeTextContent(it->second(args));
    toolHandled = true;
}
```

The `get_session_info` branch (lines 1563-1572 today) stays inline —
it's the only tool that reads `ClaudeIntegration`'s own private state
(`m_state`, `m_currentTool`, `m_contextPercent`, `m_changedFiles`,
`m_activeSessionId`) rather than delegating outward. Routing it through
the registry would require capturing `this` in a self-referential
lambda registered on itself — adds noise without consolidation gain.
See §3.2 for the carve-out rationale.

## 3. Implementation

### 3.1 Header changes (`claudeintegration.h`)

Delete:
- All 12 `setXProvider(...)` decls (lines 174-208).
- All 12 `std::function<...> m_XProvider;` members (lines 328-345).
- The associated comment blocks documenting per-tool widening
  (ANTS-1244/1247/1248/1249/1250/1251 author notes).

Add (in the public MCP-server block, after `stopMcpServer()`):

```cpp
// ANTS-1253: single tool-provider registry. Each handler receives
// the JSON-RPC `arguments` object and returns the tool's response
// as a JSON string (the dispatcher wraps it into a text content
// block). Absorbs the per-tool setter/member triples that
// ANTS-1244..1251 each added. `get_session_info` stays inline in the
// dispatcher — it reads ClaudeIntegration's own state, not an
// external delegate.
using ToolHandler = std::function<QString(const QJsonObject &args)>;
void registerToolProvider(const QString &name, ToolHandler handler);
```

Add (in the private MCP-server block, replacing all 12 members):

```cpp
std::map<QString, ToolHandler> m_toolProviders;
```

Includes: add an explicit `#include <map>` to `claudeintegration.h`
alongside the existing `#include <QHash>`. Verified 2026-05-13: `<map>`
is **not** transitively pulled in by the current Qt-header set
(`<QObject>`, `<QTimer>`, `<QProcessEnvironment>`, `<QJsonObject>`,
`<QJsonArray>`, `<QFileSystemWatcher>`, `<QHash>`, `<QLocalServer>`,
`<QLocalSocket>`, `<QDateTime>`). The explicit include is mandatory;
no probe step required.

### 3.2 `get_session_info` carve-out

`get_session_info` is the only tool whose data source is
`ClaudeIntegration`'s own private state. Two options were considered:

- **(a) Inline branch (chosen).** Keep the existing `else if
  (toolName == "get_session_info")` branch in the dispatcher. The
  registry serves the 12 outward-delegate tools.
- **(b) Self-referential registration.** Have `ClaudeIntegration`
  register a `get_session_info` handler on itself in a constructor
  / `startMcpServer` step. The lambda captures `this` and reads
  private state.

Option (a) chosen because (b) introduces a hidden ordering dependency
(the self-registration must happen before any `tools/call`) and a
self-referential lambda for the sole purpose of formal uniformity
trades clarity for tidiness. Option (a) honestly names the asymmetry:
12 tools delegate outward (registry); 1 tool reads internal state
(inline). The inline branch is one `else if` block; the cost of the
carve-out is ~10 LoC of dispatcher code preserved.

### 3.3 Source changes (`claudeintegration.cpp`)

Delete:
- All 12 `setXProvider` bodies (lines 1089-1143).

Add (in their place):

```cpp
void ClaudeIntegration::registerToolProvider(
    const QString &name, ToolHandler handler) {
    m_toolProviders[name] = std::move(handler);
}
```

Rewrite the `tools/call` `(else )?if (toolName == ...)` chain at
`claudeintegration.cpp:1554-1646`:
- The 12 outward-delegate branches collapse to a single registry
  lookup (§2.3); the `get_session_info` inline branch (lines 1563-1572
  today) stays as-is. Post-refactor the chain has two `if`-style
  entries: one inline `if`/`else if` for `get_session_info`, one
  `else if (auto it = m_toolProviders.find(toolName); …)` for
  everything else. The surrounding `tools/call` envelope (lines
  1541-1554 method-name dispatch and lines 1647-1659 unknown-tool
  / notification handling) is untouched.
- Net delete inside the chain: ~70 LoC of dispatch boilerplate
  (93 lines today → ~23 lines: 10 for `get_session_info` inline +
  ~13 for the registry lookup branch).

### 3.4 Caller changes (`mainwindow.cpp`)

Rewrite `MainWindow::setupClaudeMcpProviders` (function spans lines
3550-3674; the 12 `setXProvider` calls span 3554-3670). Each of the
12 `setXProvider` calls becomes a `registerToolProvider` call.
Lambda bodies absorb the argument extraction + result formatting
that lived in the dispatcher. Examples:

```cpp
m_claudeIntegration->registerToolProvider("get_scrollback",
    [this](const QJsonObject &args) -> QString {
        const int lines = args.value("lines").toInt(50);
        if (auto *t = focusedTerminal()) return t->recentOutput(lines);
        return {};
    });

m_claudeIntegration->registerToolProvider("get_last_command",
    [this](const QJsonObject &) -> QString {
        auto *t = focusedTerminal();
        const int   exitCode = t ? t->lastExitCode()       : 0;
        const QString output = t ? t->lastCommandOutput()  : QString();
        QJsonObject info;
        info["exit_code"] = exitCode;
        info["output"]    = output;
        info["failed"]    = (exitCode != 0);
        return QString::fromUtf8(
            QJsonDocument(info).toJson(QJsonDocument::Compact));
    });

m_claudeIntegration->registerToolProvider("get_text",
    [this](const QJsonObject &args) -> QString {
        if (!m_remoteControl) return QStringLiteral(
            "{\"ok\":false,\"error\":\"remote-control unavailable\"}");
        // ANTS-1244 INV-9 — tab=0 is a valid index distinct from
        // "tab omitted"; gate via isDouble().
        QJsonObject req;
        if (args.value("tab").isDouble())   req["tab"]   = args.value("tab").toInt();
        if (args.value("lines").isDouble()) req["lines"] = args.value("lines").toInt();
        return QString::fromUtf8(
            m_remoteControl->cmdGetText(req).toJson(QJsonDocument::Compact));
    });
```

Net add in `mainwindow.cpp`: +8 LoC versus the existing 12-lambda
block. Breakdown: 8 older lambdas each gain 1-3 lines of arg
extraction / result formatting (≈ +14 lines); the 4 already-canonical
ones (`workspace_search`, `file_outline`, `git_state`, `subsystem`)
keep their bodies but lose the surrounding ANTS-12NN author-comment
preambles (≈ −6 lines net). The §6 token-math table reflects the +8
figure.

- **INV-7.** Pre-existing per-tool author comments (ANTS-1244 INV-9

  test (cross-grep). Catches schema-side additions that forget the
  caller-side registration.

## 5. Memory & perf

- **Memory (rough order-of-magnitude).** `std::map<QString,
  std::function<…>>` with 12 entries: each node carries a `QString`
  key (8 B implicit-shared header on libstdc++ + a heap-allocated
  payload) plus a `std::function` (≈ 32 B SBO on libstdc++ for a
  capturing lambda; spills to heap above the SBO size) plus 3
  red-black-tree pointers + colour bit. Per-instance footprint is
  on the order of 1-2 KiB resident. Replaces 12 `std::function`
  members at the same ≈ 32 B each + payload. Net delta: a few
  hundred bytes per `ClaudeIntegration` instance (one per process).
  Negligible — sizes here are stdlib-dependent and listed for
  ballpark only.
- **Per-call latency.** `std::map::find` over 12 string keys: O(log n)
  with ~4 string compares average. Today's `if/else` chain is O(n)
  with ~6 string compares average (tools listed in registration
  order; `get_scrollback` first). New shape is faster on average —
  documenting to head off premature `QHash` swap.
- **Build cost.** Verified 2026-05-13: `<map>` is **not** transitively
  pulled in by `claudeintegration.h`'s current Qt-header set; §3.1
  requires an explicit `#include <map>`. No new TU. Recompile scope
  is **header-touching**. Direct `#include` of `claudeintegration.h`:
  5 src `.cpp` TUs (`claudeintegration.cpp`, `claudeprojects.cpp`,
  `claudestatuswidgets.cpp`, `claudetranscript.cpp`,
  `mainwindow.cpp`) + 6 feature-test `.cpp` TUs
  (`claude_plan_mode_detection`, `claude_session_freshness`,
  `claude_status_bar_per_tab`, `claude_status_bar`,
  `claude_tab_status_indicator`, `claude_transcript_robustness`)
  = 11 direct includers. Three project headers also include it
  (`mainwindow.h`, `claudestatuswidgets.h`, `claudetabtracker.h`),
  pulling in 3 additional transitive TUs (`main.cpp`,
  `remotecontrol.cpp` via `mainwindow.h`; `claudetabtracker.cpp`
  via `claudetabtracker.h`). Total recompile fan-out: ~14 TUs. One
  incremental build, not a full clean.

  IPC-socket dispatcher in `RemoteControl` has its own verb table

  separate ROADMAP candidate if `/indie-review` flags it.

  carve-out; revisit only if a second self-state-reading tool
  appears (Rule of Three).
- **Schema-side consolidation** (`tools/list` block at
  `claudeintegration.cpp:1204-1539` — 336 lines of `QJsonObject`
  builder boilerplate). Out of scope; would couple registry to schema
  storage and is a larger refactor.
