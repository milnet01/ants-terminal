# ANTS-1112 — Fold `/indie-review` orchestration into Ants Terminal

**Status:** spec, ship-ready after 2-loop cold-eyes convergence
(2026-05-13). Loop-by-loop fixes documented at end of file (§ 11).
**Source:** ROADMAP.md ANTS-1112; ADR-0002 dec 8 relaxed by
[ADR-0003](../decisions/0003-cc-fold-relax-gate-and-draw-boundary.md).
**Blocked by:** none — RoadmapFoldIn ships in ANTS-1111 v1 (0.7.88).
**Boundary:** see ADR-0003 dec 2 (per-surface table).

## 1. Problem

`/indie-review` today runs entirely inside the parent Claude Code
session: the orchestrator partitions the codebase into lanes, writes
a brief per lane (verbatim text passed to a subagent), dispatches
each subagent, collects the per-lane reports, regex-extracts the
`file:line` mentions, computes the cross-lane corroboration filter
(≥ 2 distinct lanes citing the same site = "gold signal"), and
optionally folds findings into ROADMAP. **Per /indie-review run cost:
~50-150 K orchestrator tokens** — the briefs themselves are 5-15 K
each, the orchestrator holds them all in context to dispatch and
aggregate.

The mechanical halves of this pipeline (partition + brief assembly +
corroboration + fold-in) need no judgment. They're file IO and regex.
Only the per-lane review *judgment* and the optional cross-cutting
*synthesis* genuinely require an LLM.

ANTS-1112 v1 lifts the mechanical halves into Ants as **MCP tools**.
The orchestrator (Claude or any MCP client) calls them; the per-lane
judgment continues to live in subagent calls. Token saving per run:
estimated 20-50 K orchestrator tokens (briefs are no longer assembled
in main context; corroboration runs in one MCP round-trip instead of
N file reads + a custom regex pass).

A future v2 (tracked under ANTS-1258) wraps this engine in a Qt
dialog for users who don't have a Claude Code subscription — they
get the same pipeline with their own LLM credentials via aidialog.

## 2. Surface

### 2.1 Engine API (`src/indiereviewengine.{h,cpp}`)

```cpp
namespace IndieReviewEngine {

// One reviewable lane.
struct Lane {
    QString name;             // CLAUDE.md module-map name (e.g. "vtparser")
    QString summary;          // module-map summary (one-liner, may be multi-line wrapped)
    QStringList sourcePaths;  // src/* files belonging to this lane (relative)
};

// 1. Partition. Default source = CLAUDE.md `## Module map (src/)`
//    parsed via the existing SubsystemMap helper
//    `QVector<SubsystemMap::Lane> SubsystemMap::cachedLanes(const
//    QString &claudeMdPath)` — note the QVector return + path
//    argument; convert to QList<Lane> at the boundary by walking
//    + projecting. For each
//    lane, source paths are derived by basename match:
//    `src/<name>.{h,cpp}` plus `src/<name>*.{h,cpp}` (catches
//    `claudestatuswidgets` → `claudestatuswidgets.{h,cpp}` plus any
//    `*_helper.cpp` siblings).
//
//    Optional override: if `<projectPath>/.indie-review/partition.json`
//    exists, parse + return that instead. Schema:
//      { "version": 1,
//        "lanes": [
//          { "name": "vtparser",
//            "summary": "VT100/xterm state machine.",
//            "sourcePaths": ["src/vtparser.h", "src/vtparser.cpp"] }
//        ] }
QList<Lane> derivePartition(const QString &projectPath);

// 2. Per-lane brief (verbatim text passed to the LLM). Concatenates:
//    (a) header — lane name + summary + cite-list of source paths
//    (b) source bodies — full content of every sourcePath, separated
//        by `=== file: <path> ===` headers
//    (c) ROADMAP slice — every line in ROADMAP.md that mentions the
//        lane name as a `Lanes:` value or basename
//    (d) standards trail — links to docs/standards/coding.md +
//        docs/standards/testing.md + docs/standards/documentation.md
//        (text not inlined; the reviewer can fetch them if needed)
//    Caller passes lane verbatim from derivePartition. Return is the
//    UTF-8 brief text; size is bounded (no recursive doc inlining).
QString assembleBrief(const QString &projectPath, const Lane &lane);

// 3. file:line citation extractor. Pure regex pass over a single
//    report. Recognises:
//      `path/to/file.cpp:123`
//      `\`path/to/file.cpp:123\``  (markdown code-fenced)
//      `path/to/file.cpp` (no line) — included with line=-1
//    Skips citations whose path doesn't resolve under projectPath
//    (defense against fabricated cites).
struct Citation {
    QString file;     // project-relative
    int line = -1;    // -1 if no line cited
    QString context;  // ±40 chars surrounding the citation in the report
};
QList<Citation> extractFileLineCitations(
    const QString &projectPath, const QString &report);

// 4. Cross-lane corroboration. Input: lane → report map. Output: list
//    of findings cited by >= minLanes distinct lanes at the same
//    (file, line). Each finding carries the citing-lane list + the
//    surrounding context from each citing report.
struct CorroboratedFinding {
    QString file;
    int     line;             // -1 ⇒ file-level (no line cited)
    QStringList citingLanes;  // sorted, unique
    QStringList contexts;     // one per citingLane, same order
};
QList<CorroboratedFinding> corroboratedFindings(
    const QString &projectPath,
    const QHash<QString /*lane*/, QString /*report*/> &reports,
    int minLanes = 2);

// 5. Synthesis prompt template. Pure string templating; caller
//    dispatches via aidialog or Claude. Combines:
//      - per-lane reports (with `## Lane: <name>` headers)
//      - threat-model extras (caller passes — typically CLAUDE.md +
//        SECURITY.md + .semgrep.yml content)
//    Prompt asks the LLM for:
//      (a) cross-cutting themes across lanes
//      (b) threat-model calibration of the corroborated set
//      (c) recommended action order for the user
QString synthesisPrompt(
    const QHash<QString, QString> &reports,
    const QString &threatModelExtras);

// 6. Fold-into-roadmap block template. Mirrors
//    AuditEngine::templateRoadmapFoldInBlock from ANTS-1111 (see
//    that spec § 3 for the per-bullet shape). This variant emits a
//    `### 🔍 Indie-review fold-in (DATE)` heading per
//    roadmap-format.md § 3.8 (subsection pattern), with per-bullet
//    `Kind: review-fix.` / `Source: indie-review-DATE.` per § 3.5.3
//    (Kind/Source taxonomy). Caller pre-allocates IDs via
//    RoadmapFoldIn::allocateIds.
QString templateIndieReviewFoldInBlock(
    const QList<CorroboratedFinding> &actionable,
    const QList<int> &allocatedIds,
    const QString &dateIso);

} // namespace IndieReviewEngine
```

### 2.2 MCP tools (registered via `registerToolProvider`)

5 new tools added to ClaudeIntegration `tools/list`. Each follows the
ANTS-1253 registry pattern (one `registerToolProvider("name",
lambda)` call in `MainWindow::setupClaudeMcpProviders`).

| Tool | Input | Output (envelope) |
|---|---|---|
| `indie_review_partition` | `{}` | `{ok, lanes:[{name,summary,sourcePaths}], path}` — `path` is **project-relative** (e.g. `"CLAUDE.md"` or `".indie-review/partition.json"`), matching the convention used by `subsystem` / `git_state` MCP responses. |
| `indie_review_brief` | `{lane: "<name>"}` | `{ok, brief, lane, source_count, byte_count}` |
| `indie_review_corroborate` | `{reports: {"<lane>":"<report text>", …}, min_lanes?: int = 2}` | `{ok, findings:[{file,line,citing_lanes,contexts}], total_input_bytes, total_findings}` |
| `indie_review_synthesis_prompt` | `{reports: {…}, include_threat_model_extras?: bool = true}` | `{ok, prompt, byte_count}` |
| `indie_review_fold_in` | `{actionable:[{file,line,context}], date_iso?: <today>, release_block_heading?: <auto>}` | `{ok, block, allocated_ids, written: bool}` — when `release_block_heading` is omitted, the handler calls `RoadmapFoldIn::findActiveReleaseHeading(projectPath)` and uses the result; if that returns empty (no recognisable release block) the tool returns `written: false` + the rendered block for the caller to write manually. `written: true` iff a heading was found AND `RoadmapFoldIn::insertBlock` succeeded. |

**Project-path resolution.** All five tools resolve the active
project via `MainWindow::focusedTerminal()->shellCwd()` (the
focused TerminalWidget's cwd) — same convention as `git_state`,
`subsystem`, `last_audit_summary` (see e.g.
`remotecontrol.cpp:1041`). The input objects do not carry an
explicit `projectPath`; if no terminal is focused or its cwd is
empty, the envelope is `{ok: false, error, code: "no_project"}`.

All five envelope `{ok: false, error, code}` on failure (matches the
existing MCP convention from ANTS-1248..1252).

## 3. Algorithm

### 3.1 derivePartition

1. Try to read `<projectPath>/.indie-review/partition.json`. If
   present, parse + return its `lanes` array (validated against the
   schema in § 2.1).
2. Otherwise: call
   `SubsystemMap::cachedLanes(projectPath + "/CLAUDE.md")` →
   `QVector<SubsystemMap::Lane>`. Convert each entry to the
   IndieReviewEngine::Lane shape by adopting `name`, `summary`,
   and computing `sourcePaths` per step 3.
3. For each `Lane{name, summary}`, compute `sourcePaths` by walking
   `<projectPath>/src/`:
   - Match `src/<name>.h`, `src/<name>.cpp` if they exist.
   - Match `src/<name>*.{h,cpp}` for the `*_helper.cpp` /
     `*_storage.cpp` sibling pattern.
   - Skip generated files (`moc_*`, `ui_*`, `qrc_*`).
4. Return the assembled `QList<Lane>`. Empty list when CLAUDE.md is
   missing or has no module map.

### 3.2 assembleBrief

For lane L with sourcePaths `[s1, s2, …]`:

```
=== Lane: L.name ===

Summary: L.summary

Source files (N):
- s1
- s2
…

=== file: s1 ===
<contents of s1>

=== file: s2 ===
<contents of s2>

…

=== ROADMAP slice ===
<lines from ROADMAP.md where (L.name) appears as a Lanes: value
 OR as the basename of a sourcePath>

=== Standards reference (not inlined; reviewer fetches if needed) ===
- docs/standards/coding.md
- docs/standards/testing.md
- docs/standards/documentation.md
```

Pure file IO. No LLM call. Bounded by the lane's source-file size
(typically 2-30 KiB combined for an Ants Terminal lane).

### 3.3 extractFileLineCitations

Two regexes applied in order (extension alternation is
longest-first per the project regex convention so `cpp` wins over
`c` and `hpp` wins over `h`):

1. `\b([a-zA-Z0-9_./-]+\.(?:cpp|hpp|cc|yaml|json|yml|md|py|sh|h|c)):(\d+)`
2. `\b([a-zA-Z0-9_./-]+\.(?:cpp|hpp|cc|yaml|json|yml|md|py|sh|h|c))\b`
   (file-level; line=-1)

**Input cap.** Caller (the MCP-tool handler or the engine itself)
truncates each report to 64 KiB before regex dispatch; reports
larger than that are accepted but only the first 64 KiB is scanned
for citations (matches the auditdialog `MAX_TOOL_OUTPUT_BYTES`
defensive convention). The two regexes have no nested quantifiers
or alternation under quantifier — `AuditEngine::isCatastrophicRegex`
returns false for both, so no PCRE2 LIMIT_MATCH wrap is needed.

For each match, resolve against `projectPath` via
`QFileInfo::canonicalFilePath`. Drop matches that escape projectPath
or don't exist on disk (defense against fabricated cites). Capture
±40 chars of surrounding text as `context`.

### 3.4 corroboratedFindings

1. For each `(lane, report)` in input map: call
   `extractFileLineCitations(projectPath, report)` → `QList<Citation>`.
2. Build `(file, line) → set<lane>` coverage map. `(file, -1)`
   (file-level) and `(file, 42)` (line-level) are **distinct keys**;
   both can independently produce CorroboratedFinding entries in
   the same call. Implementation: a `QHash<QPair<QString,int>,
   QSet<QString>>` where `int == -1` is a sentinel for file-level
   cites — never collapsed into the line-level entry.
3. For each entry where `set<lane>.size() >= minLanes`: emit a
   `CorroboratedFinding` with:
   - `file`, `line` (the key)
   - `citingLanes` (sorted)
   - `contexts` (one per citing lane, in the same order)
4. Return sorted by citingLanes.size() descending, then by file
   ascending, then by line descending.

### 3.5 synthesisPrompt

**Threat-model assembly (MCP-handler responsibility).** When the
`indie_review_synthesis_prompt` MCP tool is called with
`include_threat_model_extras: true` (default), the handler reads
three files under `projectPath` and concatenates them with separator
markers, in this order:

```
=== CLAUDE.md ===
<contents of <projectPath>/CLAUDE.md, or "" if missing>

=== SECURITY.md ===
<contents of <projectPath>/SECURITY.md, or "" if missing>

=== .semgrep.yml ===
<contents of <projectPath>/.semgrep.yml, or "" if missing>
```

Missing files contribute their header line + an empty body — the
LLM still sees the structure, just empty for that source. The
combined string is passed verbatim as `threatModelExtras` to
`IndieReviewEngine::synthesisPrompt`. When
`include_threat_model_extras: false`, the handler passes an empty
string. Direct callers of the engine API (not via MCP) must
assemble the string themselves with the same convention.

Single template:

```
You are reviewing an Ants Terminal codebase that has just been
audited by N independent reviewers. Each reviewer was given one
subsystem in isolation. Your job: cross-cutting synthesis.

=== Per-lane reports ===

## Lane: lane1
<report1>

## Lane: lane2
<report2>

…

=== Threat model extras ===

<threatModelExtras (CLAUDE.md + SECURITY.md + .semgrep.yml content
 concatenated by caller)>

=== Your tasks ===

1. Cross-cutting themes: which findings appear in 2+ lane reports?
   Group them and explain.
2. Threat-model calibration: which corroborated findings are
   genuinely high-impact given the project's threat model
   (above)? Which are noise that the project has explicitly
   accepted?
3. Recommended action order: rank the actionable findings by
   (impact × effort^-1). Top 5 only.
4. Anti-rec: anything you would NOT do based on these reports
   (cases where two lanes recommend opposite changes).

Format: markdown. No code generation. ≤ 800 words.
```

Pure string substitution. Caller dispatches via aidialog or Claude.

### 3.6 templateIndieReviewFoldInBlock

Same shape as `AuditEngine::templateRoadmapFoldInBlock` from
ANTS-1111 v1, but heading is `### 🔍 Indie-review fold-in (DATE)`
and bullet `Kind:` / `Source:` are `review-fix` and
`indie-review-DATE` respectively. Caller pre-allocates IDs.

## 4. Invariants (locked by feature tests)

- **INV-1.** `derivePartition` returns at least one lane for any
  CLAUDE.md containing `## Module map (src/)` with one or more
  `- name — summary` bullets. Empty list for a CLAUDE.md without
  the section.
- **INV-2.** `derivePartition` honours
  `<projectPath>/.indie-review/partition.json` when present —
  returns the file's lane array verbatim, ignoring CLAUDE.md.
- **INV-3.** `assembleBrief` emits the `=== Lane: NAME ===` header
  on the first line; subsequent file blocks are prefixed with
  `=== file: <path> ===`; final block is `=== ROADMAP slice ===`.
  Never reads files outside projectPath.
- **INV-4.** `extractFileLineCitations` returns at least one
  citation for a report containing `src/foo.cpp:42`, with
  `file == "src/foo.cpp"` and `line == 42`. Returns empty list
  for a report citing only a non-existent file (drop on resolve).
- **INV-5.** `corroboratedFindings` returns a finding with
  `citingLanes == ["A","B"]` for two reports both citing
  `src/foo.cpp:42`. Same finding NOT returned when only lane A
  cites it (default `minLanes=2`).
- **INV-6.** `corroboratedFindings` treats `(file, -1)` and
  `(file, 42)` as distinct keys — file-level cites don't merge
  with line cites. Consequence: if lane A cites
  `src/foo.cpp` (no line) and lane B cites `src/foo.cpp:42`,
  *neither* is corroborated under default `minLanes=2` (each
  has only one citing lane). This is intentional: the LLM
  reviewer is taken at its word about whether a finding is
  file-level or line-specific. Callers wanting laxer matching
  pass a custom `minLanes=1`.
- **INV-7.** `synthesisPrompt` emits a prompt containing every
  `lane` key from the input map as a `## Lane: X` header.
- **INV-8.** `templateIndieReviewFoldInBlock` first line is
  `### 🔍 Indie-review fold-in (<dateIso>)`; first bullet starts
  with `- 📋 [ANTS-<id>]`; bullet contains `Kind: review-fix.`
  and `Source: indie-review-<dateIso>.`.
- **INV-9.** All 5 `indie_review_*` MCP tools are registered in
  the `m_toolProviders` map and appear in `tools/list` with valid
  inputSchema. Lock asserts:
  (a) the test directly calls `m_toolProviders.count(name)` for
  each of the 5 names and asserts == 1 (no global-count assertion);
  (b) `tools/list` JSON contains a `tools[]` entry for each of the
  5 names with `inputSchema.type == "object"`. The existing
  `McpProviderRegistry::Inv7AtLeastTwelveRegisterCalls` test
  (relaxed in 0.7.87 to `>= 12`) continues to pass without
  modification.
- **INV-10.** `indie_review_corroborate` round-trip: feed JSON
  `{lane1: report1, lane2: report2}` where both reports cite
  `src/foo.cpp:42`; the response contains a finding with
  `citing_lanes == ["lane1","lane2"]`.

## 5. Memory + perf budget

| Item | Cost | Notes |
|---|---|---|
| `derivePartition` | One-shot CLAUDE.md read (~24 KiB) + `src/` directory walk (~150 files for Ants Terminal). | Cached per-call by `SubsystemMap::cachedLanes`; the directory walk is O(N) where N = `src/` file count. |
| `assembleBrief` | Reads every `sourcePath` for the lane; ROADMAP grep over ~9000 lines. | A typical Ants lane is 3-15 source files × 1-100 KiB each = ~1-1500 KiB. Bounded; not in any hot path. |
| `extractFileLineCitations` | One regex pass + N file-existence stats per report. | N is typically ≤ 50 cites per report; sub-millisecond. |
| `corroboratedFindings` | O(N · M) where N = reports, M = avg citations per report. Uses a HashMap for the (file, line) → set<lane>. | For ANTS-Terminal-shape input (8-14 lanes × 30-100 cites each), the whole pass is ms-scale. |
| `synthesisPrompt` | Pure string concatenation. Output bounded by `Σ len(reports) + len(threatModelExtras)`. | Caller is responsible for their LLM context-window budget; this fn doesn't truncate. |
| `templateIndieReviewFoldInBlock` | Same shape as ANTS-1111's audit fold template. | Sub-ms. |

**RAM cost:** transient only. The 5 MCP tool handlers are stateless
lambdas in `MainWindow::setupClaudeMcpProviders`. No persistent
state added to ClaudeIntegration.

## 9. Security / lifecycle

- `assembleBrief` reads files only inside `projectPath`; resolves
  symlinks via `QFileInfo::canonicalFilePath` and rejects any
  result that escapes projectPath (matches `auditdialog.cpp`'s
  `resolveProjectPath` defense).
- `extractFileLineCitations` rejects citations whose resolved path
  isn't under projectPath — defense against an LLM hallucinating
  `../../etc/hosts:1` in its report.
- `derivePartition` validates `partition.json` against a strict
  schema (`name` non-empty, `sourcePaths` all under `src/`); rejects
  the file on validation failure and falls back to CLAUDE.md.
- The 5 MCP tools follow the existing UID-scoped + 0700 socket
  trust model from `claudeintegration.cpp` — no new transport.
- `indie_review_fold_in` writes to ROADMAP.md via
  `RoadmapFoldIn::insertBlock` (atomic, preserves perms). The
  `release_block_heading` arg defaults to
  `RoadmapFoldIn::findActiveReleaseHeading()`; if no active block
  exists, the tool returns the rendered block + `written: false`
  for the caller to handle manually.
