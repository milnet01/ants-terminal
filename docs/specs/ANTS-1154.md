## 1. Scope

**Add what is missing. Do not rewrite.**

The existing RoadmapDialog architecture stays in place — the
QTextBrowser body, `renderHtml`, `parseBullets`, `extractToc`,
`Filter`/`Preset` enums, `QFileSystemWatcher`, search debounce,
Kind/status filter checkboxes, tab strip, TOC sidebar, and all
public-static helpers preserved byte-for-byte. Existing test suites
(`roadmap_viewer*`, `roadmap_kind_facets`,
`remote_control_roadmap_query`) keep passing without modification.

What's added are the missing features the user enumerated (§1.6):

- Per-item card visual styling inside the existing QTextBrowser HTML.
- Layman summary field (optional, parsed additively).
- Per-item expand / collapse with persisted state.
- Per-section collapse with persisted state.
- Strict tab-relevance — non-Full tabs hide prose / narration / intros.
- Completed-date row from CHANGELOG.md.
- Scroll-position persistence per tab.
- Refresh + Reset View footer buttons (only Close exists today).
- Lazy loading at scale (current ~400-bullet load is already fast;
  the design names the levers to pull as the roadmap grows).

The renderer mechanism is the dedicated **`renderCardsHtml`** path
(forked from `renderHtml`) — emitting card rows with inline CSS,
expand-anchor links handled via the existing
`QTextBrowser::anchorClicked` signal. ANTS-3392 makes each card a
`<tr class="rm-card">` inside a per-section `<table class="rm-cards">`
(pre-3392 a styled `<div class="rm-card">`). No widget tree replacement.

What's added on the backend (gaps surfaced by the card design):

- `BulletRecord::body` — body prose for the expanded view.
- `BulletRecord::layman` — optional new field, see §3.3.
- `BulletRecord::sectionSlug` — the owning `##` / `###` heading as a
  slug, for grouping cards without a second walk (INV-5).
- `parseShippedDates` — maps `[ANTS-NNNN]` → the shipped-date string
  from `CHANGELOG.md` `## [X.Y.Z] — YYYY-MM-DD` blocks; the dialog
  pre-computes it into `opts.shippedDates` (§3.1), which
  `renderCardsHtml` just looks up.

## 3. Card design (HTML cards inside QTextBrowser)

### 3.1 Card structure (collapsed = default)

Each top-level status-emoji bullet renders as a `<tr class="rm-card">`
row inside a per-section `<table class="rm-cards">` (ANTS-3392;
pre-3392 a styled `<div class="rm-card">`):

```
┌──────────────┬───────────────┬───────────────────────────────┬────────────────────┐
│ ✅ shipped   │ ✨ implement   │ Diff viewer split out of main │  #1145 · 2026-05-02 [▾]│
├──────────────┼───────────────┼───────────────────────────────┼────────────────────┤
│ 🚧 progress  │ 🏗 refactor   │ Grid re-layout pass           │  #9002 · Updated 3d [▾]│
└──────────────┴───────────────┴───────────────────────────────┴────────────────────┘
   col: state       kind            summary (flexible)            meta (right-aligned)
```

**ANTS-3392 layout (2026-06-30).** A section's cards render as one
`<table class="rm-cards">`, one `<tr>` per bullet, so the four fields
line up in aligned columns down the whole section instead of flowing
inline as prose (which fused the badge, headline, and ID together —
`"planned featureA…#CL-0001"`). The change is **container-only**: every
inner span below (`rm-state`, `rm-state-label`, `rm-kind`, `rm-summary`,
`rm-id`, `rm-date`, `rm-toggle`) keeps its class, text, and per-tier CSS
from ANTS-1235/1240/1241/1238 — only the wrapper moves from
`<div class="rm-card">` to `<tr class="rm-card">` split across four
`<td class="rm-col-*">` cells.

The original ANTS-3392 brief also proposed dropping the repeated
state-label word ("planned"). That is **not** done: the word is the
ANTS-1235 screen-reader affordance (QTextBrowser's only accessibility
surface is `QTextDocument::toPlainText()`, and the emoji alone reads as
"white heavy check mark"). The column boundary — not deletion — is what
resolves the fusing the brief complained about.

HTML shape (per-tier CSS lives in the shared `<style>` block, not inline
— per ANTS-1238 §2.e / §3.b, which mandate the per-tier px values be
substituted into the `<style>` CSS literals via `QString::arg`, never emitted
as inline `<td>` attributes (§2.f is the tier-value table); that placement is
also what lets ANTS-1238 INV-6 assert the non-`<style>` HTML is byte-identical
across tiers):

```html
<table class="rm-cards">
  <tr class="rm-card" id="rm-ANTS-1145">
    <td class="rm-col-state"><span class="rm-state">✅</span><span class="rm-state-label">shipped</span></td>
    <td class="rm-col-kind"><span class="rm-kind">✨ implement</span></td>
    <td class="rm-col-summary"><span class="rm-summary">Diff viewer split out of main window.</span></td>
    <td class="rm-col-meta"><span class="rm-id">#1145</span><span class="rm-date">· 2026-05-02</span><a class="rm-toggle" href="ants://expand/ANTS-1145">[▾]</a></td>
  </tr>
</table>
```

- **No cell borders.** `table.rm-cards` + its cells set `border:none`.
  The pre-ANTS-3392 cards `<style>` carried a
  `td,th{border:1px solid …;padding:2px 6px;font-size:%15px}` rule
  (`roadmapdialog.cpp` ~1972): its `font-size` scaled via `codePx`
  (and is scanned by ANTS-1238 INV-8), but it matched **no rendered
  element** — `renderCardsHtml` emits no `<table>`, and bullet-body
  markdown tables are rendered by the legacy `renderHtml`, not here.
  ANTS-3392 repurposes that `td,th` rule into the borderless
  `.rm-cards td` card-cell rules. Column alignment comes from fixed
  cell widths on state/kind/meta; the summary cell takes the remainder.
- **Per-card left accent + backgrounds** (`rm-current`,
  `rm-card-synthetic`) move onto the **first cell** (`rm-col-state`) as
  a `border-left`, because Qt's rich-text engine paints cell — not row —
  backgrounds/borders reliably. Right-alignment of the meta column is via
  `<td align="right">` / cell CSS, **not** CSS `float` (the rich-text
  engine ignores float).

- **State icon:** ✅ done · 🚧 in progress · 📋 planned · 💭 idea /
  far future. From `BulletRecord::status`.
- **Type chip:** Kind emoji + label. The 12 kinds the card renderer
  assigns glyphs to (the `kindGlyph` map in `renderCardsHtml`:
  `implement`, `fix`, `audit-fix`, `review-fix`, `doc`, `doc-fix`,
  `refactor`, `test`, `chore`, `release`, `research`, `ux`). Note the
  broader `roadmap_log` `Kind:` enum (per CLAUDE.md) has more values
  (`security`, `feature`, `enhancement`, `perf`, …) — a Kind with no
  glyph renders its label with no emoji. Bullets with no `Kind:` line
  emit no chip.
- **Summary (col 3):** `BulletRecord::layman` if non-empty, else
  `BulletRecord::headline` with any leading `ANTS-NNNN — ` token
  stripped (since the ID lives in the meta cell).
- **ID chip (meta cell, muted):** `#NNNN` — small / low-contrast /
  monospace, leading the right-aligned meta cell (`rm-col-meta`). The
  full `ANTS-NNNN` form remains in the row's HTML `id` attribute for
  anchoring + copy-paste + accessibility. Keeping the ID in the meta
  cell keeps it visible (it's still an important part of the roadmap
  item — user 2026-05-11) without putting it in the natural reading
  column where out-of-order IDs would feel jarring.
- **Date (meta cell, ✅ or 🚧):** conditional `<span class="rm-date">`
  after the ID, `·`-separated. On ✅ it is the shipped `YYYY-MM-DD`
  from the CHANGELOG resolver (`opts.shippedDates[id]`, built by
  `parseShippedDates` → the date of the release block containing the
  ID; no match → span omitted, never
  `(unknown)`; cache invalidated on CHANGELOG reparse). On 🚧 it is
  `Updated <N>d ago` from the git last-touch map (ANTS-1237), emitted
  only when `lastTouchDates` has an entry (graceful on non-git
  checkouts).
- **Toggle anchor:** `ants://expand/<id>` for collapsed cards,
  `ants://collapse/<id>` for expanded. Handled by an
  `anchorClicked` slot that flips the ID in
  `Config::roadmapExpandedItems` and triggers `scheduleRebuild()`.

### 3.2 Expanded card

When the user clicks `[▾]`, the same summary `<tr>` is emitted (toggle
now `ants://collapse/<id>` with a `[▴]` chevron) **followed by a
full-width body row** in the same `<table class="rm-cards">`:

```html
<table class="rm-cards">
  <tr class="rm-card" id="rm-ANTS-1145">
    <td class="rm-col-state"><span class="rm-state">✅</span><span class="rm-state-label">shipped</span></td>
    <td class="rm-col-kind"><span class="rm-kind">✨ implement</span></td>
    <td class="rm-col-summary"><span class="rm-summary">DiffViewerDialog extracted.</span></td>
    <td class="rm-col-meta"><span class="rm-id">#1145</span><span class="rm-date">· 2026-05-02</span><a class="rm-toggle" href="ants://collapse/ANTS-1145">[▴]</a></td>
  </tr>
  <tr class="rm-card-body">
    <td colspan="4">
      <p class="rm-body-first">Headline / first body line…</p>
      <p class="rm-body-line">Body prose…</p>
    </td>
  </tr>
</table>
```

- Body prose is emitted as direct `<p>` children of the colspan cell —
  `rm-body-first` (dotted divider + top padding) then `rm-body-line`
  (indent only), exactly as ANTS-1240 established. There is **no**
  `<div class="rm-body">` wrapper (it painted a nested `QPalette::Base`
  frame over the card background); the colspan `<td>` inherits the card
  background so the body reads as continuous with its summary row.
- Body markdown rendered to HTML via `applyInline` per line (code +
  bold), the same logic used today.
- Toggle anchor swaps to `ants://collapse/<id>`. Click flips it back.

### 3.3 Layman summary — optional new field in §3.5 of `roadmap-format.md`

The user reviewed the existing headlines and judged that "not all
headlines make sense to a layman." The spec adds an **optional**
`Layman: <one sentence>.` line to the bullet body — same shape as the
existing `Kind:` / `Lanes:` / `Source:` lines, parsed as part of
`BulletRecord`:

```markdown
- 📋 [ANTS-1154] **Tagged-text roadmap format v2 + RoadmapDialog tab
  filtering on tags.** [...body...]
  Layman: Make the roadmap dialog easy to skim at a glance.
  Kind: refactor.
```

**Rules:**

- Optional. If absent, the card shows the bold headline (§3.5
  already guarantees the headline is a one-line summary).
- If present, the card shows the `Layman:` text instead of the
  headline. The headline still appears in the expanded view.
- Single sentence ending in a period, like the headline.
- Added to `BulletRecord` as `QString layman;`.
- No format-version bump. The field is additive on v1 — older parsers
  ignore it gracefully (it's a body line they don't recognise, same
  as today).

**Migration:** none required. Authors add `Layman:` lines opportunistically
as they touch bullets. Headlines that already read well stay as-is.

### 3.4 Section grouping

Each `##` (release/phase) and `###` (theme) heading emits a
collapsible header line:

```html
<h2 class="rm-section">
  <a href="ants://expand-section/0-8-0">▸</a>
  0.8.0 — Claude integration polish
  <span class="rm-section-counts">✅ 4 · 🚧 2 · 📋 5</span>
</h2>
```

- **Default state: collapsed.** A section's bullets are not emitted
  unless its slug is in `Config::roadmapExpandedSections`.
- **Per-section state persists** (§3.5).
- **Count chip:** counts of bullets in the section under the active
  filter mask. Recomputed on every `renderHtml` invocation (cheap —
  already walking the bullet list).

This is the core fix to the "wall of text" problem. Open the dialog
→ see ~17 release headers + ~115 theme headers in a scannable list,
expand only what interests you.

### 3.5 State persistence

Four new `Config` keys:

- `Config::roadmapExpandedItems` — `QSet<QString>` of expanded card IDs.
- `Config::roadmapExpandedSections` — `QSet<QString>` of expanded
  section slugs (heading text → lowercase, non-alnum → `-`).
- `Config::roadmapTableSections` — `QSet<QString>` of section slugs
  toggled to compact-table view (§3.6). **Retained but unused — §3.6
  is superseded by ANTS-3392 (never built).**
- `Config::roadmapScrollAnchor` — `QHash<QString, ScrollAnchor>` keyed
  by tab name; `ScrollAnchor = { sectionSlug, idIfAny, offsetPx }`.
  See §4.5 for restore semantics.

Why ID-keyed sets rather than a tree-shaped state object: ID-keyed
state survives section-heading edits, file moves, and tab-strip
changes — same invariant ANTS-1163 leans on for resolver freshness.

Loaded on dialog open via the existing `Config` accessor pattern;
persisted on close via the existing `closeEvent` path. No new
threads, no new write triggers.

### 3.6 Same-Kind table mode (optional, per section) — SUPERSEDED by ANTS-3392

> **ANTS-3392 (2026-06-30):** superseded. The default card layout is
> now itself a per-section `<table class="rm-cards">` with aligned
> state / kind / summary / meta columns (§3.1), which already delivers
> the columnar alignment this opt-in mode was meant to provide — a
> second table-inside-the-card-table would have no defined semantics.
> This mode was never implemented (no `ants://table/<slug>` path exists
> in `renderCardsHtml`); the `Config::roadmapTableSections` key (§3.5)
> is retained but unused. The paragraphs below are the original
> (unbuilt) design, kept for provenance only.

When a section's filtered card set is "≥ 4 cards all of the same
Kind", the section header offers a `[≣ table]` toggle link. When
enabled, the section's body emits as an HTML table (same renderer
the existing ANTS-1139 path uses) with columns: state · ID · summary
· date. Toggle anchor: `ants://table/<sectionSlug>`.

- Clicking a table row's expand link expands that single card in
  place: the row's `<td>` group is replaced with the expanded-card
  HTML block (§3.2). On collapse, the row returns.
- Toggle state is per-section, persisted via
  `Config::roadmapTableSections` (a `QSet<QString>` of section
  slugs).
- Sections explicitly authored as markdown tables (existing
  ANTS-1139 behaviour) always render as tables and don't show the
  toggle.

Default OFF for all sections — the card stack is the primary view.

## 4. Tabs, filters, and panes

All six tabs (`Full / History / Current / Next / Far Future /
Custom`) and their `(filter, sort)` presets retain current
semantics. The search box, Kind row, and status checkboxes work
identically.

### 4.1 Tab-relevance contract (strict)

Each tab MUST show ONLY items relevant to that tab. The current
`renderHtml` lets section intros, prose paragraphs, and plain
narration bullets render under every tab — that's a major source of
the "wall of text" the user complained about. Cards fix this:

- **Full roadmap:** all cards + all section headers + section intros
  + prose narration. Same surface as today.
- **History (✅):** only ✅ cards. Section headers render iff they
  contain ≥ 1 ✅ card under the active filter. Prose intros and
  plain narration bullets are hidden.
- **Current (🚧 + changelog/commits signal):** only 🚧 + current-signal
  cards. Same heading + prose gating as History.
- **Next (📋):** only 📋 cards.
- **Far Future (💭):** only 💭 cards.
- **Custom:** what the active filter mask + search would show. Same
  heading + prose gating: prose intros and plain narration appear
  only on `Full`.

### 4.2 Two-pane layout

- **Nav pane (left, ~25 %, resizable):** TOC of section headings,
  hierarchical (`##` → `###` → optional `####`). Same shape as today.
- **Content pane (right):** the card list.

### 4.3 Nav scroll-sync

As the content pane scrolls, the topmost visible section's nav entry
is highlighted. Wiring is unchanged from today: each `<h2>` /
`<h3>` emission carries an `<a name="roadmap-toc-N">` anchor;
`QTextBrowser::verticalScrollBar()::valueChanged` triggers a
"find the first visible anchor in the QTextDocument" pass and sets
the TOC list's current row to the matching index. The cards
augmentation does not change this — section-header lines retain
their anchor.

### 4.4 Nav-click jump

Clicking a nav entry:
1. Expands the matching section (if collapsed).
2. Scrolls the content pane so that section's header card is at the top.

The expand is programmatic — it does NOT write to
`Config::roadmapExpandedSections` (INV-10).

### 4.5 Scroll-position persistence

On dialog close, the topmost visible card's `(sectionSlug,
idIfAny, pixelOffsetWithinCard)` is captured per tab and saved to
`Config::roadmapScrollAnchor`. On open:

1. If the saved `(sectionSlug, id)` still exists, scroll so that
   card's top minus `offsetPx` aligns with viewport top.
2. If only `sectionSlug` matches (the ID no longer exists — e.g.
   item was renamed), scroll to the section header.
3. If neither matches, scroll to top.

ID-keyed anchoring (rather than a raw pixel/line offset) survives
content edits between sessions, same principle as §3.5.

### 4.6 Footer buttons

Three buttons at the bottom of the dialog (the current dialog has
only Close):

- **Refresh** — force a re-read of `m_roadmapPath` + archives,
  rebuild the model. Visible safety net; live updates already fire
  on `QFileSystemWatcher` events. Bound to `F5`.
- **Reset View** — clear filters, search, expand state, and scroll
  position for the active tab. Confirms via a small inline prompt
  before clearing. Does NOT change the active tab.
- **Close** — closes the dialog. `Esc` shortcut. State persists per
  §3.5.

## 6. Memory budget

### 6.1 At Ants Terminal's current ROADMAP.md size (~400 bullets, ~115 sections)

The dialog continues to use a single `QTextBrowser` containing a
`QTextDocument`. Memory accounting:

- **Rendered HTML (cold, all sections collapsed):** ~115 section
  header lines × ~200 B = **~23 KiB**. No bullets emitted under
  collapsed sections.
- **Rendered HTML (warm, current section + 5 expanded items):**
  ~115 headers + ~30 cards (in the expanded section) + 5 full-body
  blocks ≈ **~80 KiB**.
- **Rendered HTML (worst case, all sections + all bodies expanded —
  user explicitly opens everything):** ~400 cards + 400 body blocks
  ≈ **~600 KiB**. QTextDocument's internal data structures roughly
  double that at peak: ~1.3 MiB.
- **`BulletRecord` cache** (parse result kept for re-render without
  re-parse): ~400 × ~600 B (5 strings averaging 120 B) ≈ **~240 KiB**.
- **CHANGELOG date cache:** `QHash<QString, QDate>`, one per ✅ ID ≈
  ~50 B × ~250 = **~12 KiB**.
- **Persisted state:** three `QSet<QString>` + one `QHash` ≤ 400
  entries each ≈ **~64 KiB**.

Total resident: **~340 KiB cold**, ~400 KiB typical, ~1.7 MiB
worst-case (all-expanded). Comparable to today's renderer; net delta
on cold is +~100 KiB for the parsed-bullet cache (which today is
re-parsed on every rebuild — this spec memoises it).

### 6.2 Lazy loading strategy (R22)

The user is sized for ~400 bullets today. The design names the
levers to pull as the roadmap grows:

1. **Collapsed-by-default sections** are the primary lever — only
   the ~115 section headers render at cold-open, not the 400 cards.
   Cold-open HTML size drops by ~15× vs eager rendering.
2. **Non-Full tab prose stripping** (INV-11) — narrow tabs (History
   / Current / Next / Far Future) render ONLY status-prefixed
   bullets in matching sections, dropping ~30 % of the document
   weight at parse time.
3. **Archive files loaded only on demand** — `shouldLoadHistory`
   already gates archive parse on History-tab or non-empty search.
   INV-14 preserves this against the cards renderer.
4. **Bullet body parsed lazily** — `BulletRecord::body` is populated
   on first request (when the card's ID enters
   `Config::roadmapExpandedItems`), not eagerly during
   `parseBullets`. Reduces cold-open parse cost.
5. **CHANGELOG date resolver cached** — `parseShippedDates` populates a
   `QHash` once per CHANGELOG file change; subsequent renders hit
   the cache.

### 6.3 Projected at scale

| Bullets | Sections | Resident cold (collapsed) | Cold-open parse | Notes |
|---|---|---|---|---|
| 400 | 115 | ~340 KiB | ~50 ms | Today's size |
| 1 000 | 200 | ~600 KiB | ~120 ms est. | Comfortable |
| 5 000 | 600 | ~2.5 MiB | ~600 ms est. | Archive parse still gated per INV-14 (only History/search loads it). Add a "Loading…" indicator at the parse boundary; consider promoting some of the layered levers to defaults (e.g. cap collapsed-section count chip recomputation to differential update) |

No new threads. No new file watchers. No new `add_executable`.

## 9. Resolved decisions

- **`Layman:` line position.** Sits after the bullet's body prose,
  before `Kind:`. Same trailing-line convention as `Kind:` / `Lanes:`
  / `Source:`. Closed 2026-05-11.
- **Custom-tab semantics.** Unchanged from today — `Custom` is "no
  named preset matches the active filter mask + search". The card
  augmentation does not change the tab's definition, only its
  rendering shape. Closed 2026-05-11.
- **ID visibility.** Visible as a `#NNNN` chip on the card's meta
  row (after the summary), not inline with the summary text. Full
  `ANTS-NNNN` form retained in the HTML `id` attribute for anchoring
  and accessibility. Resolved 2026-05-11 in response to the user's
  chronology concern (user reframed: "let's give it a number but
  show it after the layman summary").

## 10. Re-open conditions

If after shipping the user reports the dialog is still hard to scan:

1. **Specific entries' summaries are too technical** → add `Layman:`
   lines to those bullets in ROADMAP.md. Not a code-side defect.
2. **Too many sections to scan** → revisit §3.4: maybe the default
   should auto-expand the section containing in-progress work
   (top-of-mind section). Defer to a follow-on bullet.
3. **Performance on a 1000-bullet project** → revisit the lazy-loading
   levers in §6.2 (e.g. cap the collapsed-section count-chip
   recompute to a differential update, or split archives more
   aggressively). This spec sized for ~400 bullets.
4. **Vibe coders still finding the layman text unclear** → ROADMAP
   author training, not a code defect. Surface as a docs item.
