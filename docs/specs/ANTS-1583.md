# ANTS-1583 — `roadmap_branch_drift` MCP verb

**Status:** implementing
**Kind:** implement
**Source:** cross-session-report-2026-05-18 (RetroArch Bundle 67)
**Pull:** 14 (MCP audit-surface git/scope-awareness fold-in, 0.7.92)
**Composes with:** [[ANTS-1576]] — both surfaces share the
"audit/roadmap is branch-aware" theme on the same pull.

## 1. Problem

RetroArch runs two long-lived local branches:
`local/audit-2026-04` (docs / roadmap / audit work) and
`local/fixes-2026-04` (fix commits), diverged by 76 / 24 commits.
Bundle-60 through Bundle-65 fix commits live on the `fixes` branch
but the `audit` branch is missing them. The audit branch's
`ROADMAP.md` claims those fixes are ✅ shipped — re-running cppcheck
on that branch surfaces the same warnings the ROADMAP says are gone.

A cheap MCP verb can detect this: parse each ✅ bullet for the
cited commit SHA (typical form: `commit abc1234`, `(abc1234)`, a
trailing `\babc1234\b`), check whether the SHA is reachable from
HEAD, surface a drift list when not.

This isn't strictly an Ants-codebase problem — Ants's `main` doesn't
have a two-branch split — but the verb is generic across any
project that uses a similar workflow. The user mentions other CC
sessions (RetroDB, Vestige, …) treating Ants MCP as a workshop;
this verb gives them a programmatic answer to "did the fix I'm
about to claim shipped actually land on this branch?".

## 2. Fix — new MCP verb `roadmap_branch_drift`

### 2.1 Verb shape

Registered like the other roadmap verbs (`roadmap_query`,
`roadmap_log`) — `caller_cwd` Required contract, idempotent-read
cache eligible, etag-supported.

```json
// Request
{ "caller_cwd": "/path/to/project",
  "max_drift":  20,                       // optional, [1, 100], default 20
  "etag_match": "<prior server etag>" }   // optional, ANTS-1499 304 pattern

// Success envelope
{ "ok":              true,
  "etag":            "<server-issued>",
  "current_branch":  "local/audit-2026-04",
  "current_commit":  "1b400e930a...",
  "scanned_bullets": 73,                 // total ✅ in ROADMAP
  "with_sha":        38,                 // ✅ bullets that cite ≥1 SHA
  "drift_count":     5,
  "drift": [
    { "bullet_id":  "ANTS-1234",
      "cited_sha":  "abc1234",
      "reason":     "sha_not_in_HEAD",
      "headline":   "<one-line headline>" },
    { "bullet_id":  "ANTS-1235",
      "cited_sha":  "deadbee",
      "reason":     "sha_not_in_git",     // SHA doesn't exist at all
      "headline":   "<one-line headline>" }
  ],
  "path":  "ROADMAP.md" }                 // or docs/private/ROADMAP.md etc.

// Refusal envelopes
{ "ok": false, "code": "caller_cwd_required", "error": "..." }
{ "ok": false, "code": "no_roadmap_loaded",   "error": "..." }
{ "ok": false, "code": "no_git_state",        "error": "..." }
```

### 2.2 SHA extraction

The ROADMAP cites SHAs in heterogeneous forms (verified by grep —
see § 8 below):

- `commit 1abf768` (bare-with-prefix)
- `(2faa000)` (parenthesised)
- `Landed in commit aad4f32.`
- `(commit 1abf768, 2026-05-07)`
- `64e67e7,` (trailing comma)

**False-positive baseline.** A bare `\b[0-9a-f]{7,40}\b` regex
on Ants's own `ROADMAP.md` produces 36 distinct hex tokens,
of which ~9 (≈25%) are non-commits: epoch timestamps
(`1735689600`), CVE IDs (`1000117`), Lua instruction caps
(`10000000`), stack addresses (`7fff09517fe0`), session IDs
(`94218f91`), tmp-dir suffixes (`c7ee2911`), and a GitHub
Actions reference SHA (`93cb6efe...bf9bfd`) that isn't on
HEAD. That noise would all surface as `sha_not_in_git`, drowning
the real drift signal.

**Tightening: alpha-required + post-anchor or pre-anchor.**

1. **Require ≥1 alpha character.** Lookahead
   `(?=[0-9a-f]*[a-f])` — eliminates all-digit tokens (epoch
   timestamps, CVE IDs, Lua caps).
2. **Require a context anchor either before OR after.** Match
   when preceded by `commit\s+`, `\(`, `^`, ` ` after
   `merge|via|in|at|Landed in commit|Source:`, **OR** followed by
   one of `[,.\)\s]` — the trailing-comma / period / paren / space
   form, which covers bare `64e67e7,` citations without forcing
   a leading prefix word.

Combined regex:

```c++
// ANTS-1583 — anchored SHA detector for roadmap_branch_drift.
static const QRegularExpression rxCommitSha(
    QStringLiteral(
        "(?:^|commit\\s+|\\(|"
        "(?:\\bmerge\\b|\\bvia\\b|\\bin\\b|\\bat\\b|"
            "\\bLanded in commit\\s+|\\bSource:\\s*)\\s*)"
        "(?=[0-9a-f]*[a-f])"
        "([0-9a-f]{7,40})"
        "(?=[,.\\)\\s]|$)"));
```

The pre-anchor + lookahead post-anchor combination drops the 25%
non-commit noise on the ROADMAP sample while keeping all 6 sample
citation forms above, including the bare trailing-comma form
`64e67e7,`. Residual rate (e.g., a 9-char `94218f91` session ID
that happens to follow `via` in some hypothetical sentence)
surfaces as `sha_not_in_git` — acceptable noise floor (≤ 1 per
100 bullets empirically). The regex literal is marked with a
leading `// ANTS-1583` comment so source-grep tests anchor on
the comment rather than the literal — survives regex evolution.

### 2.3 Reachability check

One batch `git log` rather than N `git branch --contains`, with a
short-SHA prefix index so the per-cited-SHA lookup is O(1):

```c++
// Pseudocode
const QByteArray raw = runGit(root,
    {QStringLiteral("log"), QStringLiteral("--format=%H"),
     QStringLiteral("HEAD"), QStringLiteral("--max-count=200000")});
QSet<QString> reachableFull;                          // full 40-hex
QMultiHash<QString /*7-hex prefix*/, QString /*full*/> reachableByPrefix;
for (const auto &line : raw.split('\n')) {
    if (line.size() < 40) continue;
    const QString full = QString::fromUtf8(line.left(40));
    reachableFull.insert(full);
    reachableByPrefix.insert(full.left(7), full);
}
```

200 000 commit cap — protects against absurd repo sizes; > 200 K
HEAD-reachable commits would also blow the 2 s `runGit` timeout
on most hardware. Excess is surfaced via a `truncated_history: true`
flag in the envelope.

For each cited SHA:

- **Full 40-char match.** `reachableFull.contains(sha)` ⇒ reachable.
- **Short SHA (7-39 char).** Look up `reachableByPrefix.values(sha
  .left(7))` and check `startsWith(sha)` on candidates. With
  ~200 K commits, expected bucket size is ~200000/16^7 ≈ 0.0007,
  i.e., at most ~1 candidate per bucket on a typical repo. O(1)
  amortised. (For pathological hash collisions a bucket might
  hold 2-3 entries — still constant-bounded.)
- **Not in reachable set.** Second probe: `git cat-file -e <sha>`
  (cheap exists check). Object exists ⇒ `sha_not_in_HEAD`.
  Doesn't exist ⇒ `sha_not_in_git`.

`drift_count` is the count of `reason != "reachable"` entries.
If `max_drift` is reached, stop scanning further bullets and set
`drift_truncated: true` in the envelope (separate from
`truncated_history`).

**Helper reuse.** The verb's "what's HEAD?" probe reuses the
existing `collectGitSnapshot` helper at `remotecontrol.cpp:5247`
which already runs `git rev-parse HEAD` and returns
`{head, statusSha, valid}`. Saves one fork per call.

### 2.4 Bullet enumeration

Reuse `findRoadmapUnder(rootCanonical)` from [[ANTS-1459]] for path
discovery (gets us `docs/private/ROADMAP.md` etc.).

**Parser entry point.** Follow the `cmdRoadmapQuery` template
(`src/remotecontrol.cpp` around the dispatch site that runs
`detectRoadmapFormat` + `parseBullets` / `parseGitHubTaskListBullets`
/ `parsePassHeadingBullets`). The verb calls the same dispatch
sequence to get a `QList<RoadmapBullet>` (or the GFM / pass-heading
adapter equivalents), then filters to `bullet.status == "✅"`. For
each, joins the bullet's headline + body (continuation lines until
the next bullet) and runs the SHA regex on the joined text.

`bullet_id` is the bullet's `[PROJ-NNNN]` ID; empty for narrator /
header bullets — those are excluded.

### 2.5 Refusal envelopes

- `caller_cwd_required` — missing or empty `caller_cwd`. Standard
  contract refusal (ANTS-1404).
- `no_roadmap_loaded` — `findRoadmapUnder` returned empty.
- `no_git_state` — the project root has no `.git/` directory or
  `collectGitSnapshot(root).valid == false`. The verb is
  meaningless without git state; refuse rather than emit an
  envelope with zero coverage. **New code in taxonomy** — added
  to `docs/standards/mcp-error-codes.md` § 2 (Resource state)
  in this pull.
- `cwd_bad` — inherited from the dispatch layer's
  `PathValidation::validatePath` / canonical-cwd resolver. Not
  emitted by this handler directly; the standard envelope text
  flows through from `ResolvedRoot::Unresolvable`.

Error codes follow [[mcp-error-codes]] taxonomy.

## 3. Invariants

- **INV-1.** Verb is registered with `CallerCwdContract::Required`
  and refuses with `code: "caller_cwd_required"` when invoked with
  empty `caller_cwd`.
- **INV-2.** Verb is registered in the `isEtagSupportedTool`
  allowlist and the response carries an `etag` field. Etag is
  stable across calls when ROADMAP mtime + `git rev-parse HEAD`
  + caller_cwd are unchanged.
- **INV-3.** SHA extractor regex is anchored by a `// ANTS-1583`
  source comment, with a context-prefix non-capturing group
  (`commit\s+|\(|^|merge|via|in|at`) AND a positive lookahead
  requiring ≥1 alpha char in the hex token. Source-grep on the
  comment + the lookahead pattern `(?=[0-9a-f]*[a-f])`.
- **INV-4.** Reachability classifier — runtime end-to-end test
  against a real `QTemporaryDir` git fixture (helper builds a
  3-commit chain A→B→C, HEAD at C with one orphan commit D).
  Asserts: SHAs of A, B, C ⇒ reachable; SHA of D ⇒
  `sha_not_in_HEAD`; a fabricated SHA (40 random hex) ⇒
  `sha_not_in_git`.
- **INV-5.** Short-SHA prefix index — drift classifier accepts a
  7-char prefix of an A/B/C SHA from INV-4 ⇒ reachable. Source-
  grep + runtime assertion that the short SHA `c.left(7)`
  resolves to `c`.
- **INV-6.** `max_drift` parameter is server-clamped to `[1, 100]`,
  default 20. When the scan hits the cap, `drift_truncated: true`
  on the envelope.
- **INV-7.** `caller_cwd` contract is `Required`; tool descriptor's
  schema declares `caller_cwd` required (matches existing
  `roadmap_query`).
- **INV-8.** No `git branch --contains` fork-per-SHA. Source-grep
  asserts that `cmdRoadmapBranchDrift` body contains no
  `"branch"` literal alongside `"--contains"`. Implementation
  uses one `git log` for the reachability set, plus at most one
  `git cat-file -e` per drifted-but-existing SHA.
- **INV-9.** `scanned_bullets`, `with_sha`, `drift_count` are
  non-negative integers; `scanned_bullets >= with_sha >=
  drift_count`. Runtime assertion on the live envelope.
- **INV-10.** Helper reuse — `cmdRoadmapBranchDrift` source-greps
  for `collectGitSnapshot(` (anti-pattern guard: no fresh
  `rev-parse HEAD` fork at handler entry).
- **INV-11.** `no_git_state` error code is listed in
  `docs/standards/mcp-error-codes.md` § 2 (Resource state).
  Source-grep on the standards doc.

## 5. Discoverability

Tool descriptor (`claudeintegration.cpp`):

- `description`: "Compare ROADMAP ✅ entries' cited commit SHAs
  against HEAD's reachable history. Returns a drift list when a
  claimed-shipped commit isn't reachable from current HEAD —
  useful for projects with multiple long-lived branches where
  fix commits and docs commits land on different branches and
  drift. Composes with `last_audit_summary`'s branch capture
  ([[ANTS-1576]]) — once the SARIF records its source branch,
  this verb's drift list tells the caller whether to trust the
  audit's claim. Use after a re-base / multi-branch merge to
  validate ROADMAP claims against actual code state."
- `selection_hint`: "Use when investigating 'ROADMAP says ✅
  but the bug is still there', or before claiming a fix shipped.
  Cross-checks against `last_audit_summary`'s `branch:` /
  `commit:` ([[ANTS-1576]]) — when the audit was run on a
  branch missing fix commits, this verb names which ROADMAP
  ✅ entries are unreachable from that branch's HEAD."
- `tool_info.kind`: "roadmap" (matches the family of
  `roadmap_query`, `roadmap_log`).

## 6. Out of scope (deferred)

- **Auto-fix drift entries.** Re-flipping ✅ → 📋 when a commit
  isn't reachable would be destructive — the user might just be
  on the wrong branch. The verb reports; it doesn't mutate.
- **Cross-branch reachability.** "SHA is in `local/fixes-2026-04`
  but not in `local/audit-2026-04` (current HEAD)" — the verb
  already names HEAD's drift; naming which branch *does* contain
  the SHA would need an extra `git branch --contains` per drifted
  SHA. Costly enough to defer; the caller can run that manually
  on the small drift list.
- **Tag-based citations** (`v0.7.91-2-gabc123`, `Released in
  v0.7.79`). The regex matches the trailing hex if present; pure
  version-tag citations without a hex suffix are ignored. Future
  work if it becomes common.
- **Multiple SHAs per bullet.** When a bullet body cites three
  SHAs, the verb today reports the first drifted one and stops
  per-bullet. A `drift_per_bullet[]` shape is logged as a
  follow-up if the noise becomes a problem.
- **Pre-commit hook integration.** A `pre-push` hook that runs
  this verb and refuses the push on non-zero drift_count is a
  separate ergonomic improvement.

## 7. RAM / build budget

- One `git log` per cache miss; bounded at 200 000 commits;
  output is ~41 bytes/commit = ~8 MB worst case for an ancient
  repo, more typically a few hundred KB for a 1-year-old project.
- **`QSet<QString>` of HEAD-reachable SHAs + `QMultiHash` prefix
  index** — each QString wraps a 40-char UTF-16 payload (~120 B
  with QString header). 200 K commits ⇒ ~24 MB resident worst
  case for the set alone; the prefix index adds ~150 B per
  entry (~30 MB). **Combined worst-case ~54 MB during the
  drift call**, dropped after the response is built. Typical
  1-year project (~3 K commits) ⇒ ~700 KB — well within
  budget. The cap stays at 200 K (the slower bound is `runGit`'s
  2 s wall-clock, not RAM).
- One `git cat-file -e` per drifted SHA (≤ `max_drift` = 100).
- Result envelope ≤ ~20 KB (drift entries are compact; `headline`
  is one-line).
- No persistent state. Idempotent-read cache keys this naturally
  via the standard request canonicaliser. The cache window
  bounds re-emission, not the per-call allocation.
