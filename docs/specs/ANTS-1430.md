# ANTS-1430 — `session_memory` `project_layout` scan helper

**Status:** in flight (Bundle C pull 12, 2026-05-16).
**Kind:** implement (perf-driven).
**Lanes:** `session_memory`, `remotecontrol`, new `projectlayoutengine`.
**Source:** vestige-cc-feedback-2026-05-16.
**Pairs with:** ANTS-1428 (adapter mode reads the cached
`roadmap.format` field to decide whether to engage the GFM
adapter without re-sniffing the header on every call).

## Problem

Every MCP tool that touches project-relative paths re-derives the
same layout on each call: probe `ROADMAP.md`, probe `CHANGELOG.md`,
locate `docs/standards/`, scan for `packaging/*.metainfo.xml`,
find `.roadmap-counter`. Stat calls are cheap individually but
add up across ~30 tools × ~hundred-call sessions.

Vestige CC feedback (2026-05-16): *"every other MCP tool
re-discovers these from scratch ... one scan per project per week
is plenty."*

The layout is also the natural carrier for **ANTS-1428's dialect
detection**: once a project's `ROADMAP.md` is sniffed and tagged
`ants-v1` / `github-task-list` / `unknown`, every subsequent
`roadmap_query` / `roadmap_log` reads that tag from the cache
rather than re-parsing the first 4 KB of the file.

## Goal

A single `project_layout` envelope per project, written to
`session_memory` under the well-known key `project_layout`, with
a 7-day TTL + mtime invalidation. New MCP read verb
`mcp__ants__project_layout` runs scan-if-stale and returns the
cached envelope.

## Design

### Engine (`src/projectlayoutengine.{h,cpp}`, `ants_core_lib`)

Pure-function module, Qt6::Core only. No QWidget dependencies; no
QProcess. Mirror of the `TokenUsageEngine` / `SessionMemoryEngine`
shape so non-GUI test targets and (future) ants-helper consumers
can link it directly.

```cpp
namespace ProjectLayoutEngine {

constexpr int kDefaultTtlDays = 7;

// Maximum bytes read from the head of ROADMAP.md when sniffing the
// format marker. The `<!-- ants-roadmap-format: 1 -->` marker lives
// on line 1 of any well-formed Ants ROADMAP (per
// docs/standards/roadmap-format.md § 1); 4 KB is generous headroom
// for a YAML/TOML-style preamble that might land above the marker
// in future variants. Files smaller than this are read whole.
constexpr int kFormatSniffBytes = 4096;

struct RoadmapInfo {
    QString  path;                  // relative to cwd, e.g. "ROADMAP.md"
    QString  format;                // "ants-v1" | "github-task-list" | "unknown"
    bool     formatMarkerPresent = false;
    int      bulletCountEstimate = 0;
    qint64   sizeBytes           = 0;
    qint64   mtimeMs             = 0;
};

struct ChangelogInfo {
    QString  path;
    qint64   sizeBytes = 0;
    qint64   mtimeMs   = 0;
};

struct LayoutEnvelope {
    qint64         scannedAtMs   = 0;
    int            ttlDays       = kDefaultTtlDays;
    QString        rootCwd;       // canonical project root the scan resolved
    RoadmapInfo    roadmap;
    ChangelogInfo  changelog;
    QString        specsDir;      // "docs/specs" if present, else empty
    QString        standardsDir;  // "docs/standards" if present, else empty
    QString        adrDir;        // "docs/decisions" if present, else empty
    QString        appstreamMetainfo;  // packaging/*.metainfo.xml first hit
    QString        counterFile;   // ".roadmap-counter" if present, else empty
    // Probe-tracking — populated only when the scan actually
    // statted a path (so invalidation knows what to re-mtime).
    QStringList    probedPaths;
};

LayoutEnvelope scanLayout(const QString &absoluteCwd);

// Mechanical case-mapping: camelCase struct fields ↔ snake_case
// JSON keys, 1:1, no renames or reshaping. `scannedAtMs` ↔
// `scanned_at_ms`, `rootCwd` ↔ `root_cwd`, etc. INV-6 round-trip
// applies on the entire envelope.
QJsonObject    toJson(const LayoutEnvelope &env);
LayoutEnvelope fromJson(const QJsonObject &obj);

// True when the cache is missing, has expired, or any probed path's
// mtime is newer than the cache's scannedAtMs. False when the cache
// is fresh.
bool isStale(const LayoutEnvelope &cached, qint64 nowMs);

}  // namespace ProjectLayoutEngine
```

### Scan logic

`scanLayout(cwd)` performs (in this order):

1. Stat `<cwd>/ROADMAP.md`. If present:
   - Read `min(file_size, kFormatSniffBytes)` bytes. Detect the
     `<!-- ants-roadmap-format: 1 -->` marker →
     `format = "ants-v1"`. Else scan for `^- \[[ x]\]` patterns →
     `format = "github-task-list"`. Else `format = "unknown"`.
   - `bulletCountEstimate` from one streaming pass over the whole
     file: count `^- (✅|📋|🚧|💭)` for ants-v1,
     `^- \[[ x]\]` for GFM. Reads the whole file (the scan is
     rare; a single pass is fine).
   - **If ROADMAP.md is absent**: `roadmap.path` is empty string,
     `roadmap.format` is empty string (not `"unknown"` —
     `"unknown"` is reserved for "present but not recognised"),
     and `bulletCountEstimate` / `sizeBytes` / `mtimeMs` are all
     zero.
2. Stat `<cwd>/CHANGELOG.md`. Record size + mtime. If absent, all
   `ChangelogInfo` fields stay zero / empty.
3. Probe `<cwd>/docs/specs`, `docs/standards`, `docs/decisions` —
   set the field only when the directory exists.
4. Probe `<cwd>/packaging/*.metainfo.xml` (single glob, first hit).
5. Probe `<cwd>/.roadmap-counter`.

`probedPaths` records every path that was statted (including ones
that didn't exist) so `isStale` can re-check them on the next call
— a created file is just as much a layout change as a modified
one. Directory probes (`docs/specs`, `docs/standards`,
`docs/decisions`) detect entry-add/remove/rename at the immediate
level only; in-place edits to files **inside** those directories
do NOT trigger invalidation (Linux directory mtime updates on
immediate-entry change, not descendant edit). This is intentional
— `project_layout` is the directory **shape** cache, not a docs
content cache; content-cache duties belong to consumers like
`roadmap_query` (which has its own mtime check).

### Cache invalidation (`isStale`)

```cpp
bool isStale(const LayoutEnvelope &cached, qint64 nowMs) {
    if (cached.scannedAtMs <= 0) return true;
    const qint64 ttlMs = qint64(cached.ttlDays) * 24 * 3600 * 1000;
    if (nowMs - cached.scannedAtMs > ttlMs) return true;
    // mtime check across every probed path. New files or modified
    // files both bump the directory's / file's mtime.
    for (const auto &p : cached.probedPaths) {
        const QFileInfo fi(cached.rootCwd + QLatin1Char('/') + p);
        if (fi.exists() && fi.lastModified().toMSecsSinceEpoch() >
                           cached.scannedAtMs) {
            return true;
        }
    }
    return false;
}
```

The mtime comparison uses the **cache's** `scannedAtMs` as the
reference point, not `nowMs`, so clock skew between scan and
re-check doesn't false-invalidate. Directory probes use the
directory's own mtime (entry-level change), not a recursive scan
— see § Scan logic above for the rationale.

### MCP verb (`mcp__ants__project_layout`)

Schema: zero required user args. `caller_cwd` required (gate-
classified `Required` — the verb is fundamentally per-project).

Optional args:
- `force_rescan: bool` (default `false`) — bypasses TTL + mtime
  checks and re-scans unconditionally. Useful when a tool that
  just landed a file wants a fresh view.
- `ttl_days: int` (default 7, clamped to [1, 30]) — overrides the
  envelope's TTL on the **write** side. Reads use whatever TTL is
  recorded in the existing cache.

```jsonc
// Successful read (cache hit):
{
  "ok": true,
  "cached": true,
  "scanned_at_ms": 1778900000000,
  "ttl_days": 7,
  "root_cwd": "/home/user/project",
  "roadmap": {
    "path": "ROADMAP.md",
    "format": "github-task-list",
    "format_marker_present": false,
    "bullet_count_estimate": 156,
    "size_bytes": 412345,
    "mtime_ms": 1778899999000
  },
  "changelog": {
    "path": "CHANGELOG.md",
    "size_bytes": 134567,
    "mtime_ms": 1778800000000
  },
  "specs_dir": "docs/specs",
  "standards_dir": "docs/standards",
  "adr_dir": "docs/decisions",
  "appstream_metainfo": "packaging/com.example.foo.metainfo.xml",
  "counter_file": ".roadmap-counter"
}

// Successful scan (cache miss or stale): same envelope, "cached": false.
```

`cached: false` distinguishes "I just scanned" from "I read from
cache." Callers don't usually care, but the field is useful for
debugging dialect-detection cache hit rates.

### Dispatcher (`RemoteControl::cmdProjectLayout`)

`project_layout` is classified `Required` in
`ClaudeIntegration::callerCwdContractFor`. The
dispatcher-level refusal fires **before** the verb body when
`caller_cwd` is empty:

```jsonc
// Dispatcher refusal (caller_cwd empty):
{"ok": false, "code": "caller_cwd_required",
 "error": "project_layout: caller_cwd required"}
```

The verb body then runs:

1. `RcGate::checkCallerCwd(focused, req, "project_layout")` —
   a second-line gate that catches the case where `caller_cwd`
   is present-but-doesn't-match the focused tab's project root
   (cross-project tenancy refusal, matching `cmdSessionMemory`'s
   ANTS-1336 pattern). On refusal:
   ```cpp
   if (!gate.ok)
       return QJsonDocument(RcGate::gateErrorEnvelope(gate));
   ```
   This matches the post-ANTS-1372 verbs at
   `src/remotecontrol.cpp:2859, 3020, 3087, 3339, 3571, 3907`.
   (The manual `smErr` form in `cmdSessionMemory` is legacy and
   should not be copied — it survives only because that verb
   needs a 4-field shape including `op`+`echo` that
   `gateErrorEnvelope` doesn't emit.) Typical codes from
   `RcGate`: `no_project`, `cwd_mismatch`.
2. `cached := SessionMemoryEngine::execute(cwd, Get,
   "project_layout", {})` (the `value` arg is required by the
   engine signature but ignored for Get).
3. If `!force_rescan` AND `cached.found` AND
   `!ProjectLayoutEngine::isStale(fromJson(cached.value), nowMs)`:
   return `cached.value` with `cached: true`.
4. Otherwise: `env := scanLayout(cwd)`; serialize;
   `SessionMemoryEngine::execute(cwd, Set, "project_layout",
   toJson(env))`; return `env` with `cached: false`.

**Double-gating rationale.** The Required-contract refusal is
the dispatcher-level fast-path (rejects empty `caller_cwd`
before the provider lambda runs); the `RcGate::checkCallerCwd`
call inside the verb body is the tenancy-mismatch refusal
(rejects present-but-wrong `caller_cwd`). The two paths report
different codes and are not redundant. This matches
`cmdSessionMemory`'s ANTS-1336 routing.

The Set call is best-effort — if the session_memory store is
already at its 100 KiB cap (ANTS-1283 INV-2) the layout
envelope (typically < 1 KiB) is unlikely to be the blocker, but
the verb still returns a fresh scan on store-write failure
(degraded mode: never-caches but never-fails either — see
INV-8).

### Adapter-mode cache hand-off (ANTS-1428)

ANTS-1428's read-side adapter will call `project_layout` (or read
the cached envelope directly via `session_memory`) to decide
whether to engage the GFM parser branch. The hand-off contract:

- `roadmap.format == "github-task-list"` → engage adapter without
  re-reading the file header.
- `roadmap.format == "ants-v1"` → use the native parser.
- `roadmap.format == "unknown"` → fall back to native parser; if
  it returns 0 bullets, the ANTS-1429 silent-empty guard fires
  with `code:"unrecognised_format"`.

This means **ANTS-1430 ships before ANTS-1428** even though they
land in the same week. The cache surface must exist before the
adapter learns to read from it.

## Invariants

- **INV-1 / First call scans.** When no cached `project_layout`
  exists for `cwd`, `cmdProjectLayout` runs `scanLayout` and
  returns `cached: false`.
- **INV-2 / Within-TTL is cached.** When `scannedAtMs + ttlDays`
  is in the future and no probed path's mtime has advanced past
  `scannedAtMs`, the second call returns `cached: true` and the
  envelope contents are byte-equal to the first call's.
- **INV-3 / mtime invalidation.** When any probed path's
  `lastModified()` is greater than the cached `scannedAtMs`,
  `isStale` returns true and the next call re-scans.
- **INV-4 / TTL invalidation.** When `nowMs - scannedAtMs >
  ttlDays * 86400000`, `isStale` returns true regardless of
  mtime state.
- **INV-5 / Envelope schema stable.** The envelope JSON object
  carries exactly the documented field set. Adding a new field is
  a non-breaking change (consumers must ignore unknown fields);
  removing one is breaking and requires a new spec.
- **INV-6 / Round-trip fidelity.**
  `fromJson(toJson(env)) == env` for every well-formed envelope.
  camelCase struct fields ↔ snake_case JSON keys is a mechanical
  1:1 mapping; no field renames or reshaping happens at
  serialisation time.
- **INV-7 / `force_rescan` bypasses cache.** When `force_rescan:
  true` is passed in the request, the dispatcher re-scans
  unconditionally (skipping the cache-fresh check) and overwrites
  the stored envelope, regardless of INV-2/3/4 cache-hit state.
- **INV-8 / Store-write failure is non-fatal.** If
  `SessionMemoryEngine::execute(..., Set, ...)` returns
  `ok == false` (e.g. the per-cwd 100 KiB store is full or a
  filesystem write fails), the verb returns the fresh scan
  envelope with `ok: true`, `cached: false`. The store-write
  error is logged via `qWarning` but not surfaced in the
  envelope.

## Tests

`tests/features/mcp_project_layout_scan/`:

- **`spec.md`** — mirrors the INVs above.
- **`test_project_layout_scan.cpp`** — pure-function tests on
  `ProjectLayoutEngine`. Uses `QTemporaryDir` to build fake
  project trees. No MCP roundtrip — the engine is the surface
  under test; the dispatcher is a thin wrapper that goes through
  `RemoteControl`'s already-tested gate + envelope path:
  - INV-1: `scanLayout(emptyDir)` returns an envelope with empty
    optional fields and `roadmap.path` empty.
  - INV-2: `scanLayout(populatedDir)` finds ROADMAP.md, sets
    `format` correctly based on file contents, populates
    `specsDir`/`standardsDir`/`adrDir` based on presence.
  - INV-3: `isStale(cached, scannedAtMs + 1000)` returns false
    when no probed path has advanced; touch one of the probed
    paths and `isStale` returns true.
  - INV-4: `isStale(cached, scannedAtMs + 8*86400000)` returns
    true even when no path has changed.
  - INV-5/6: `fromJson(toJson(env)) == env` for representative
    envelopes (empty-project, full-project, GFM-roadmap).

## RAM budget

`LayoutEnvelope` is roughly:
- 8 B `scannedAtMs` + 4 B `ttlDays`
- `rootCwd`: ~120 B (typical project path)
- `roadmap`: ~200 B (path + format + flag + count + 16 B numerics)
- `changelog`: ~80 B
- Four directory strings + counter + metainfo: ~200 B
- `probedPaths`: 8 entries × ~30 B ≈ 240 B

Total: **~850 B per project**, comfortably under the 16 KiB
`session_memory` per-value cap (ANTS-1283 INV-8). One cache entry
per project; sessions touching N projects pay N × ~850 B.

## Build cost

New translation unit (`projectlayoutengine.cpp`) added to
`ants_core_lib`. One new MCP verb (~50 LoC dispatcher in
`RemoteControl::cmdProjectLayout`). One new tool descriptor in
the `tools/list` reply. Expected incremental rebuild: **< 5 s**
for the engine + its consumers.

Total LoC added: ~150 (engine) + ~50 (dispatcher) + ~30 (schema)
+ ~150 (tests) = **~380 LoC** including tests.

## Migration

None. The verb is new; no existing behaviour changes. ANTS-1428
(adapter mode) will add a read of the cache to its parser path
when that spec lands.

## Pairs / cross-refs

(Cross-section, since the header `Pairs with:` line gives the
short version.)

- **ANTS-1283** — `session_memory` is the underlying storage. This
  verb is a read-through cache layered on top. Spec at
  [`ANTS-1283.md`](ANTS-1283.md).
- **ANTS-1336** — `caller_cwd` gate. ANTS-1336 INV-7 currently
  says `session_memory` is the **unique** read-only verb that
  joins the gated set because its storage is tenant-hashed.

  the session_memory store and so inherits the same
  tenant-hashed-storage gate requirement. **ANTS-1336 § INV-7
  must be amended in the same ship** to say "any read-only verb
  whose storage is tenant-hashed joins the gated set
  (`session_memory`, `project_layout`)." CLAUDE.md's
  session_memory bullet (in the project root) gets the same
  amendment. Spec at [`ANTS-1336.md`](ANTS-1336.md).
- **ANTS-1357** — idempotent-read cache (process-wide 5s TTL,
  allowlist at `src/claudeintegration.cpp::isIdempotentReadTool`).
  `project_layout` does **NOT** join the allowlist — it has its
  own TTL+mtime cache layer with different invalidation
  semantics; the idempotent cache would interact strangely with
  `force_rescan`.
- **ANTS-1404** — `CallerCwdContract::Required` classification.
  `project_layout` joins the registry at
  `src/claudeintegration.cpp::callerCwdContractFor`. Spec at

- **ANTS-1428** — primary consumer of the `roadmap.format` field.
  Spec at [`ANTS-1428.md`](ANTS-1428.md). Ordering: ANTS-1430 is

- **ANTS-1429** — `unrecognised_format` envelope is the fallback
  when `roadmap.format == "unknown"` and the native parser yields

## Open questions

- **Schema versioning** (loop-1 Open Q-3). INV-5's additive
  policy ("new fields are non-breaking") covers most evolution;
  a `schema_version: int` field could distinguish v1 from a
  future hypothetical v2 envelope. **Resolution for v1: defer.**
  No `schema_version` field on first ship — INV-5 makes
  versioning unnecessary until a *breaking* change is needed,
  and we have no concrete scenario that would force one.
  Consumers that need explicit version awareness can read
  presence/absence of well-known fields.
