# ANTS-2160 — Per-project Ants settings file (`.ants/project.json`)

**Status:** accepted (2026-06-24) — cold-eyes loops 1–5 folded, loop 5 nits-only. Flips to `shipped X.Y.Z` at the next release.
**Kind:** feature.
**Source:** ROADMAP.md ANTS-2160 (user-request-2026-06-24, prompted by DOOM `file_count:0` + cross-session layout-discovery feedback in `3D_Engine_Ants_MCP_Feedback.md` / `DOOM_Ants_MCP_Feedback.md`).

**Layman:** A small per-project file tells Ants exactly where the code, docs, roadmap and changelog live — so it stops guessing and works for projects that don't use a `src/` folder.

## 1. Problem

Ants MCP assumes a conventional `src/` + `tests/` + `docs/` layout and
finds each project artifact by a hardcoded heuristic probe. When a
project's layout differs, the verbs silently return nothing or guess
wrong:

1. **codebase_index** `candidates()` (`src/codebaseindex.cpp:119`) walks
   ONLY `src/` + `tests/`. DOOM Ants keeps its 65 `.c` files under
   `linuxdoom-1.10/`, so `session_orient` / `codebase_index` returned
   `file_count:0` even after ANTS-2148 admitted the `.c` suffix — the
   files are simply outside the walk. (Verified: the `.c` admission DID
   ship; the empty map is the layout, not the suffix.)
2. **roadmap_query** / **roadmap_log** / **roadmap_branch_drift** locate
   `ROADMAP.md` via `findRoadmapUnder()` (`src/remotecontrol.cpp:110`),
   an ordered candidate list.
3. **changelog_log** uses `findChangelogUnder()`
   (`src/remotecontrol.cpp:133`).
4. **spec_query** / **spec_log** hardcode the dir prefix `docs/specs/`
   (else `docs/phases/` for `phase_*` ids) — `cmdSpecQuery`
   (`src/remotecontrol.cpp:11942`), `cmdSpecLog`
   (`src/remotecontrol.cpp:9449`).
5. **current_state** computes its `spec_path` field from a hardcoded
   `docs/specs/<id>.md` probe (`src/remotecontrol.cpp:11253`).
6. **docs_index** `walkDocs()` (`src/docsindex.cpp:156`) walks
   `<root>/*.md` + a hardcoded `<root>/docs` subtree
   (`src/docsindex.cpp:170`).
7. **project_layout** `ProjectLayoutEngine::scanLayout()`
   (`src/projectlayoutengine.cpp:415`) probes per-doc-type candidate
   lists (constants at `src/projectlayoutengine.cpp:161`–`206`, probed
   inside `scanLayout`).

There is no way for a project to *tell* Ants where its code, docs,
roadmap, changelog and specs live. The fix is an opt-in, declarative,
in-repo settings file that every consumer consults before falling back
to its existing heuristic. This supersedes the deferred "non-`src`
layout follow-on" noted in the `admittedSuffix()` comment
(`src/codebaseindex.cpp`) — a declarative config is preferred over a
whole-repo walk heuristic.

## 2. Surface

### 2.1 The file

`<project-root>/.ants/project.json` — a committed-in-repo JSON object,
distinct from the per-app GLOBAL config at
`~/.config/ants-terminal/config.json` (see § 7). All keys optional; an
absent file, absent key, `null` value, empty array, empty/blank string,
or unparseable file all mean "no override" and the consumer uses its
current heuristic (§ 3, INV-1/6/7/10). Example:

```json
{
  "source_roots": ["linuxdoom-1.10"],
  "test_roots":   ["tests"],
  "docs_dir":     "docs",
  "roadmap":      "ROADMAP.md",
  "changelog":    "CHANGELOG.md",
  "specs_dir":    "docs/specs"
}
```

Every value is a repo-root-relative path. `source_roots` / `test_roots`
are arrays of directory paths; the rest are single paths
(`*_dir`/`*s_dir` = directory, `roadmap`/`changelog` = file).

| Key | Type | Consumer(s) | Fallback when unset/empty |
|---|---|---|---|
| `source_roots` | `string[]` (dirs) | codebase_index | `["src"]` |
| `test_roots` | `string[]` (dirs) | codebase_index | `["tests"]` |
| `docs_dir` | `string` (dir) | docs_index, project_layout | `docs` |
| `roadmap` | `string` (file) | roadmap_query, roadmap_log, roadmap_branch_drift, project_layout | `findRoadmapUnder()` list |
| `changelog` | `string` (file) | changelog_log, project_layout | `findChangelogUnder()` list |
| `specs_dir` | `string` (dir) | spec_query, spec_log, current_state, project_layout | `docs/specs` |

Out of scope for v1 (§ 6): `phase_*` spec routing (stays hardcoded
`docs/phases/`), and lane definitions.

### 2.2 The resolver module

A new pure helper `src/projectsettings.{h,cpp}` (Qt6::Core only — no
widgets, no subprocess; mirrors `codebaseindex.cpp` / `findsources.cpp`):

```cpp
namespace ProjectSettings {
    struct Settings {
        std::optional<QStringList> sourceRoots;   // validated, in-root, existing
        std::optional<QStringList> testRoots;
        std::optional<QString>     docsDir;
        std::optional<QString>     roadmap;
        std::optional<QString>     changelog;
        std::optional<QString>     specsDir;
    };
    // Reads + parses <rootCanonical>/.ants/project.json on every call
    // (no internal cache — the file is tiny and consulted at points that
    // already touch the filesystem; § 5). Returns an all-nullopt Settings
    // on absent / unreadable / malformed / non-object file (fail-safe).
    // Per entry: a value that is JSON null, an empty/blank string, or of
    // the wrong JSON type is DROPPED; and a path that fails
    // PathValidation::isInsideProject (escapes the root, OR does not
    // canonicalise — i.e. does not exist) is DROPPED too — not the whole
    // file (INV-4/INV-5/INV-8). For an array, surviving entries are kept
    // and an array that ends up empty is treated as nullopt (INV-10).
    // The dir-vs-file type check is left to the consumer (a declared
    // source_root that is a regular file passes isInsideProject but the
    // consumer rejects it — INV-5), so load() is a pure parse + in-root
    // existence/shape validation.
    Settings load(const QString &rootCanonical);
}
```

The helper returns *parsed-and-validated* values with presence flags
(`std::optional`); it does NOT apply per-consumer fallbacks — each
consumer keeps its own fallback so behaviour stays local and testable.

Path validation uses `PathValidation::isInsideProject`
(`src/pathvalidation.h:60`) — the shared boolean anchor check
purpose-built for *disk-derived* config paths (it canonicalises the
candidate, builds no error envelope, and returns false on either an
out-of-root resolve OR a canonicalisation miss, i.e. a non-existent
path). One call therefore drops escaping (INV-4), non-existent, and
case-mismatched (INV-5/INV-8) entries at load time. This is distinct
from `PathValidation::validatePath` — the MCP-arg validator that
`apply_edits` / `read_region` / `spec_query` / `spec_log` use, which
builds a `bad_path` *response envelope*, the wrong shape for an off-disk
config read.

No caching: `load()` re-reads the file each call. Every injection point
below already performs filesystem probes (directory walks, `exists()`
candidate scans), so one extra small-file read is negligible, and a
cacheless helper has no invalidation, no retained state, and no
test-order coupling.

### 2.3 Injection points

The two root-resolution families already in the code: the index/read
verbs route through `resolveRootCanonical(m_main, req)`; roadmap /
changelog / spec_log / project_layout canonicalise `caller_cwd` inline.
In every case the root in hand at the injection point is already
canonical, so `load(root)` is called against a canonical path. Each
consumer calls `load()` itself at its resolution point (no `Settings`
parameter threading), which keeps the override consistent across every
call-path of a multi-call-site helper (INV-12).

- **codebase_index** `candidates(rootCanonical)` calls
  `ProjectSettings::load(rootCanonical)` internally and, when
  `sourceRoots`/`testRoots` are set, walks each declared dir (via the
  existing `walkSubtree`), wholly REPLACING the corresponding default
  (`src`/`tests`), per-key (INV-2, INV-11). The concatenated file list
  is de-duplicated by relative-path string (INV-9). Because the load is
  inside `candidates()`, all three of its call-sites — `build()`
  (`codebaseindex.cpp:218`), `staleFiles()` (`:248`), `refresh()`
  (`:281`) — are settings-aware (INV-12). No signature change.
- **findRoadmapUnder / findChangelogUnder** call `load(rootCanonical)`
  internally; when the matching key is set AND the declared file exists
  under root, return it; else the existing candidate-list walk (INV-3,
  INV-5). No signature change.
- **spec routing** — `specsDir` overrides the literal `docs/specs`
  prefix in `cmdSpecQuery` (`:11942`), `cmdSpecLog` (`:9449`), and
  `cmdCurrentState`'s `spec_path` probe (`:11253`); the override flows
  into both the on-disk path probed and the relative path reported back
  (the `rel` / `spec_path` field). The `<id>.md` leaf and the `phase_*`
  → `docs/phases/` branch are unchanged.
- **docs_index** `walkDocs(rootCanonical)` calls `load()` internally and
  walks `<root>/*.md` (unchanged) + `<root>/<docsDir>` (default `docs`);
  its three call-sites — `build()` (`docsindex.cpp:222`), `staleDocs()`
  (`:245`), `refresh()` (`:274`) — are covered (INV-12). No signature
  change.
- **project_layout** `scanLayout()` receives an already-canonicalised
  cwd (its `absoluteCwd` parameter; `cmdProjectLayout` canonicalises at
  `src/remotecontrol.cpp:15742`) and calls `load()` against it. For
  roadmap / changelog / specs / docs, prefer a settings-declared path
  over the candidate-list probe; an unset key keeps the existing probe
  (INV-3, INV-7).

## 3. Invariants

- **INV-1** — With no `.ants/project.json` present, every listed
  consumer produces byte-identical output to today (zero regression for
  existing projects, including Ants itself, which ships no such file).
  *Test:* a populated-`src/` fixture with no settings file → the
  in-memory `CodebaseIndex::build()` `Index.files` matches the
  pre-change run; the feature test also asserts `ProjectSettings::load`
  returns all-`nullopt`.
- **INV-2** — With `source_roots:["engine"]` (the `src/` dir absent or
  empty), `codebase_index` walks `engine/` and reports a non-zero
  `file_count` carrying that subtree's symbols. *Test:* fixture
  `engine/foo.c`; drive the exported `CodebaseIndex::build(root, …)` and
  assert its in-memory `Index.files` is non-empty and contains `foo.c`
  (`candidates()` itself is an unexported file-static — `build` /
  `refresh` / `toJson` are the exported observers carrying the file
  list).
- **INV-3** — With `roadmap` / `changelog` / `specs_dir` / `docs_dir`
  set to an existing path, the corresponding consumer resolves to the
  declared location instead of its heuristic. *Test:* one single-key
  fixture per key, assert the resolved path equals the declared one.
- **INV-4** — Per-entry validation via `isInsideProject` drops only the
  offending entry: a path that canonicalises outside the root (absolute,
  or `..` escaping) — or fails to canonicalise — is DROPPED during
  `load()`, while a mixed array keeps its valid entries; the consumer
  falls back to its heuristic only when nothing survives, and `load()`
  never reads outside the root. *Test:* `"roadmap":"../outside.md"` and
  `"source_roots":["/etc"]` → dropped, heuristic used;
  `"source_roots":["engine","/etc"]` → keeps `engine`.
- **INV-5** — A declared path that does not exist (dropped by
  `isInsideProject` at load), or whose type is wrong, is treated as
  unset; the verb never errors purely because a declared path is stale
  or mistyped. The dir-vs-file check lives in the consumer: `candidates()`
  skips a `source_roots`/`test_roots` entry that is not a directory; the
  doc-finders skip a `roadmap`/`changelog` that is not a file. *Test:*
  non-existent `roadmap` → fallback; and `source_roots:["foo.c"]` (a
  regular file) with `src/` populated → the entry is dropped, so
  `source_roots` is effectively unset and `build()` falls back to the
  `src` default — `Index.files` equals the `src/` contents (non-empty),
  which distinguishes "rejected → fallback" from a broken
  "walked-to-empty replacement" (which would yield empty `Index.files`).
- **INV-6** — A malformed / non-object / wrong-typed / `null`-valued
  `.ants/project.json` yields an all-`nullopt` `Settings` (fail-safe);
  no consumer crashes, refuses, or changes its refusal code because the
  file is bad. *Test:* fixtures `{` (truncated), `[]` (non-object),
  `"source_roots":"src"` (string not array), `"roadmap":null` →
  all-`nullopt`, no throw.
- **INV-7** — Partial settings override ONLY the keys present; every
  unset key uses its existing heuristic (per-key independence). *Test:*
  `source_roots`-only fixture → roadmap/changelog still resolve via
  their candidate lists.
- **INV-8** — Declared relative paths resolve under the canonical root
  with the filesystem's native case sensitivity (the project is
  Linux-only / case-sensitive per CLAUDE.md); a case-mismatched path
  fails `isInsideProject` (no canonicalisation) and is treated as
  non-existent. *Test:* fixture declaring `"roadmap":"roadmap.md"` while
  the file is `ROADMAP.md` → dropped, heuristic used.
- **INV-9** — `source_roots` / `test_roots` accept multiple entries;
  the reworked `candidates()` walks each in listed order and adds
  de-duplication by relative-path string (NEW logic — the current
  concatenation does none, relying on `src`/`tests` being disjoint;
  nested declared roots can overlap), so a file reachable via two
  declared roots (e.g. nested `["a","a/b"]`) appears once. *Test:*
  nested-roots fixture with one file under both roots; `build()`'s
  `Index.files` contains it exactly once — the discriminator is that
  absent the new dedup it would appear twice (count 2 fails the test).
- **INV-10** — An empty array (`source_roots:[]`) or empty/blank string
  (`docs_dir:""`) is treated identically to an absent key (fall back to
  the default); there is no "index nothing" mode in v1. *Test:*
  `"source_roots":[]` → `build()`'s `Index.files` indexes the `src`
  default, not an empty set.
- **INV-11** — When `source_roots` is set, the `src` default is NOT also
  walked (full replacement, not union); `test_roots` is independent (an
  unset `test_roots` still walks `tests`). *Test:* `source_roots:["a"]`
  with both `a/` and `src/` populated → `build()`'s `Index.files`
  contains only `a/`'s files; `tests/` still walked.
- **INV-12** — The settings override applies on EVERY call-path of a
  multi-call-site walker, so a warm-cache incremental refresh does not
  revert to defaults: `candidates()` (build/`staleFiles`/`refresh`) and
  `walkDocs()` (build/`staleDocs`/`refresh`) each load settings
  internally. *Test:* call `build()` with `source_roots:["a"]`, then
  `refresh(prev, …, &refreshed)` against an unchanged tree →
  `refreshed == 0` (no spurious re-outline) and the refreshed
  `Index.files` still indexes only `a/`.

## 4. Tests

Feature-conformance suite `tests/features/project_settings/`
(`spec.md` + `test_project_settings.cpp`), added to the **`test_claude`**
bundle's `SOURCES` (alongside `tests/features/mcp_codebase_index/` — not
a standalone target, per `tests/features/README.md`). Label
`features;fast`. Drives the pure `ProjectSettings::load` against
`QTemporaryDir` fixtures (distinct temp roots per case → order-
independent) and the doc-finder helpers. The walk-related invariants
(INV-2/9/11/12) drive the exported pure builders
`CodebaseIndex::build()` / `refresh()` directly and assert against the
returned in-memory `Index.files` (and, for INV-12, `refresh`'s
`*refreshedOut`) — `candidates()` is an unexported file-static, and
testing the pure builders avoids the on-disk index cache entirely (no
`serve` / `cachePathOverride` needed). Per the project test convention,
each test is first **verified to FAIL against pre-implementation
source** before the implementation is restored. One test per invariant,
`Test N ⇒ INV-N` (the `*Test:*` clauses in § 3 carry each test's
detail).

## 5. RAM / build cost

**Memory:** none retained. `ProjectSettings::load` parses into a
short-lived `Settings` (a handful of `QString`s + two small
`QStringList`s, < 1 KiB) that the caller consumes and discards; there is
no cache, so no growth and no eviction policy to specify.

**Build:** one new small TU (`projectsettings.cpp`, Qt6::Core-only) in
the lib(s) hosting the consuming verbs. No new third-party dependency
(`QJsonDocument` already in use). All consumer edits are localised
inside the named functions (no signature changes — § 2.3).

## 6. Out of scope

- `phase_*` spec routing (`docs/phases/`) — stays hardcoded in v1; a
  `phases_dir` key is a follow-on if a project relocates phase docs.
- Lane definitions (which would subsume `docs/subsystems.md`) — a
  follow-on once the file format is field-proven.
- A whole-repo walk fallback for projects with neither `src/`/`tests/`
  nor a settings file — superseded by this declarative config.

  `~/.config/ants-terminal/config.json` (mode 0600): the new file is

- **CHANGELOG.md** — "Added" entry on ship.
- **docs/standards/mcp-behavioural-notes.md** — note the settings file

  changelog_log, spec_query/spec_log, project_layout).
- No `PLUGINS.md` change (no `ants.*` Lua surface change).

## 8. Security boundaries

The work crosses the **filesystem** trust boundary: it reads a
repo-committed file and uses its values to choose which paths the read
verbs walk. Defences, stated as invariants: every declared path is
validated under the canonical root via `PathValidation::isInsideProject`
and dropped on escape (INV-4) or non-existence / case mismatch
(INV-5/INV-8), so a settings file can never widen a verb's reach beyond
the project root it already had. A declared `source_root` can only point
the existing bounded `walkSubtree` at an in-root subtree — no broader
than today's `src/` walk and subject to the same `codebase_index` caps
(`maxIndexFiles` / `maxCacheBytes`); v1 adds no new file-count
amplification beyond a verb's existing limits.
