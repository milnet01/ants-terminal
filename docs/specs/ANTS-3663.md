# ANTS-3663 — `doc_lint`: every deterministic doc check in one call

**Status:** spec draft, cold-eyes loop 3 folded, then split (2026-07-28) — the
fix half moved to ANTS-3669; that seam has not been through the gate.
**Kind:** enhancement.
**Source:** ROADMAP.md ANTS-3663 (user-request-2026-07-27).
**Blocked by:** ANTS-3664 (the finding shape), and ANTS-3660 / ANTS-3661 /
ANTS-3662 existing to be composed.
**Composes with:** ANTS-3601 (`doc_integrity`) and ANTS-3636 (`doc_citations`),
the two producers that already ship and are adapted rather than rewritten.
**Blocker for:** ANTS-3669 (`doc_lint --fix`), the write half split out of § 2.3.

**Layman:** One button that runs all the document checks together. Repairing
what it finds is a separate piece of work (ANTS-3669), kept apart because
changing your files deserves a stricter review than reading them.

---

## 1. Problem

A `/cold-eyes` § 1e pre-pass currently means five or six separate verb calls
over the same tree. Each re-walks the same directory, re-reads the same files,
re-computes the same fence masks, and returns a differently-shaped envelope the
caller then reconciles by hand. **That reconciliation is the actual cost**, and
it is paid on every loop of every review.

Two consequences, and the second is the one that bites:

1. **Four walks and a caller-side loop, where one walk would do.**
   `doc_integrity` and the three new verbs each enumerate `*.md` under the same
   root with the same `QDirIterator` (cloned from
   `RemoteControl::docIntegrityEnumerate`, `src/remotecontrol.cpp`), and
   each re-reads every document. `doc_citations` does not walk at all — it is
   *file*-scoped, so the caller loops it, which is the same cost wearing a
   different hat.
2. **Five vocabularies.** Without ANTS-3664 the five checkers would report a
   problem five different ways, and the caller — a skill, not a program — would
   flatten them into prose to compare, which is what
   `ColdEyesEngine::BriefManifest` (`src/coldeyesengine.h`) already does by
   discarding structure. ANTS-3664 gives the three new verbs one shape; this
   spec adapts the two that ship into it.

## 2. Surface

### 2.1 One walk, five checkers

`doc_lint` enumerates once. It reads each document once and passes the **text**
to the three new checkers — which is a design constraint on them, not a
description of them: ANTS-3660/3661/3662 each take document text plus a
project-relative path, never a path alone, and this spec is where that
requirement is recorded.

**The two adapted checkers re-read, and pretending otherwise would be the
spec's most load-bearing lie.** § 2.2 freezes `doc_integrity` and
`doc_citations` as adapter-only, and neither engine accepts text:
`DocIntegrity::check` consumes a resolved relative-path list, and
`DocCitations::check` is handed one document path. Taking text would mean
changing a shipped, tested signature — the thing § 2.2 exists to forbid. So the
honest budget over a three-document tree with all five checks on is **nine
opens**: three shared by the new checkers, three by `doc_integrity`, three by
`doc_citations`. Against fifteen for five separate verb calls, the saving is
real; against three, the claim is false. INV-1 asserts nine.

```jsonc
// request
{ "caller_cwd": "…",          // required
  "path": "docs/",            // file or dir; absent → the docs_dir default,
                              //   matching doc_integrity, NOT doc_citations'
                              //   missing_field (that verb is file-scoped)
  "checks": ["doc_integrity"],// default: all five; unknown name → bad_args
  "fix": false,               // opt-in; §2.3
  "dry_run": false,           // preview; semantics ANTS-3669
  "max_findings": 500 }       // default 500, clamped to [1, 5000]
```

The cap is applied **after** INV-7's total sort, never before: the retained page
is therefore a deterministic prefix, and raising the cap only ever appends. A
cap applied during collection would return a different 500 findings per run from
the same tree, which is the failure the total order exists to prevent.

**Each checker declares which documents it is eligible for, and the shared walk
applies that predicate before dispatch.** The walk is `docs_dir`-wide, but the
checkers are not all corpus-wide: `spec_lint` is defined over specs only
(ANTS-3662 § 5 — "a README has no invariants to check"), and without a filter it
would emit `missing_section`, `invariant_id_gap` and `loop_row_no_outcome`
against every standard, journal and README under `docs/`. That is not a rare
edge: it is what `/cold-eyes` — the caller this verb is built for — gets on its
first run over a default path.

| Checker | Eligible documents |
|---|---|
| `doc_integrity` | every enumerated `*.md` |
| `doc_citations` | every enumerated `*.md` |
| `doc_dedup` | every enumerated `*.md` |
| `doc_symbols` | every enumerated `*.md` |
| `spec_lint` | those under `specs_dir` (ANTS-2160's key, else `docs/specs/`) |

A document filtered out of a checker is **not** a `skipped[]` entry — nothing
failed. The checker still appears in `checks_run[]` provided it was eligible for
at least one document; a run whose path selects no eligible document for a
checker leaves that checker out of `checks_run[]`, which is exactly the "did not
run" signal that array exists to carry.

```jsonc
// response
{ "ok": true,
  "findings": [ /* DocFinding::Finding, INV-7 order */ ],
  "counts":   { "doc_integrity": { "toc_gap": 2 } },  // whole run, before the cap
  "truncated": false,          // set when max_findings elided findings
  "checked_docs": ["a.md"],
  "checks_run":   ["doc_integrity"],   // ran clean ≠ did not run
  "check_stats":  { "doc_citations": { "unparsed_total": 1,
                                       "examples_suppressed": 57 } },
  "skipped":      [ { "file": "b.md", "reason": "read_failed" } ],
  "check_errors": [ { "verb": "doc_symbols", "file": "c.md",
                      "reason": "…" } ],
  "pairs":        [ /* doc_dedup only; element shape ANTS-3660 § 2.5 */ ],
  "fixed":        [ { "verb": "doc_integrity", "kind": "toc_gap",
                      "file": "a.md", "line": 12 } ],   // fix:true only
  "files_written": 1,                                    // fix:true only
  "fix_errors":   [ { "file": "d.md", "reason": "write_failed" } ] }
```

Three of these carry contracts stated elsewhere rather than inline:
`check_stats` in § 2.2 (the whole-document tallies that are not findings),
`skipped` / `check_errors` / `fix_errors` in § 2.4 (partial failure), and
`fixed` / `files_written` / `fix_errors` in ANTS-3669 § 2.2.

**Presence rule.** `ok`, `findings`, `counts`, `checked_docs` and `checks_run`
are **always present**, empty rather than absent when there is nothing to say —
a caller distinguishing "clean" from "malformed" needs them unconditionally.
`truncated` is omit-when-false, matching the ANTS-3636 INV-28 convention
ANTS-3664 INV-1 cites. `check_stats`, `skipped`, `check_errors` and `pairs` are
omit-when-empty. `fixed`, `files_written` and `fix_errors` are absent entirely
under `fix:false` — absent, not zero, because `files_written:0` on a report-only
run reads as "tried and wrote nothing" when the truth is "never entered the fix
path".

**`check_stats` is where a checker's envelope-level signals land.** The
per-check envelopes are gone (below), so any scalar a checker would have
returned at *its* top level needs a route or it is lost:

| Checker | `check_stats` entries |
|---|---|
| `doc_citations` | `unparsed_total`, `examples_suppressed`, `read_budget_exhausted` |
| `doc_symbols` | `candidates_total`, `truncated` |
| `spec_lint` | `sections_checked`, `line_count` |
| `doc_integrity` | — (its envelope carries no scalar beyond `counts`) |
| `doc_dedup` | — (`pairs[]` is hoisted to the top level instead) |

`spec_lint`'s `sections_checked` is the sharp one: ANTS-3662 ships that check
**disabled**, so without this route a `doc_lint` caller cannot tell a spec with
no missing sections from a spec whose section check never ran — the precise
distinction `checks_run[]` exists to preserve one level up.

The five legal `checks[]` values are exactly the `verb` strings ANTS-3664's
findings carry — one vocabulary, not two:

| `checks[]` value = `verb` | Engine |
|---|---|
| `doc_integrity` | `DocIntegrity::check` (adapter) |
| `doc_citations` | `DocCitations::check` (adapter) |
| `doc_dedup` | ANTS-3660 |
| `doc_symbols` | ANTS-3661 |
| `spec_lint` | ANTS-3662 |

`counts` comes from `DocFinding::countsByVerbAndKind` over the whole run.
`checks_run[]` is not decoration: it distinguishes "check ran and found nothing"
from "check did not run", which `counts` alone cannot express.

**Not** the full per-check envelopes. The first draft promised them and it was
wrong twice: `doc_citations`' envelope carries `text[]` for every healthy
citation, thousands corpus-wide on a verb whose premise is frugality; and that
verb is *file*-scoped, so "the envelope it would have returned alone" is N
envelopes with N copies of every top-level field. A caller wanting the full
shape calls the verb directly — they remain independently callable (§ 5). The
one structured payload that survives is `doc_dedup`'s `pairs[]`, because
`DocFinding::Finding` has no second-location field (ANTS-3660 § 2.5).

### 2.2 The two adapters

`doc_integrity` and `doc_citations` ship with tested envelopes and live callers,
so **neither is rewritten**. Each gains a pure adapter in the verb layer:

| Source | → `DocFinding::Finding` |
|---|---|
| `DocIntegrity::Finding` | `kind` from its `Kind` enum (`dead_anchor` / `broken_link` / `toc_gap`); `file`, `line`, `message` map straight across |
| a non-`ok` `doc_citations` citation | `kind` from `status` (`missing_file`, `out_of_range`, `ambiguous`, `read_error`, `unresolved`); `line` from `doc_line`; `message` composed from `raw` and the status |

Three rules the adapters obey, all load-bearing:

- **`file` is the document the finding was found *in*, never the target it
  points at.** A citation is the one finding shape in this set with two
  locations — the spec that wrote a line reference into `src/foo.cpp`, and the
  `src/foo.cpp` that cannot satisfy it — and `DocFinding::Finding` has one
  `file` field. It holds
  the scanned document, and `line` holds `doc_line`, so every finding in the run
  groups and sorts by the document a reader would open to fix it. The target is
  named in `message`, which is the only place it appears. Without this rule the
  adapter is a coin-flip: half the corpus's citation findings would sort under
  files that are not documents at all and that `checked_docs[]` never listed.
- **An `ok` citation is never a finding**, including one whose
  `anchor_found:false` (ANTS-3654). That flag is *advisory* — it says a needle
  moved, not that the citation is wrong — and promoting it to a finding would
  contradict the parent spec, where it is explicitly not a status.
- **`unparsed[]` entries are not findings.** ANTS-3653's design contains them:
  a prose token that happens to parse (`6.2:1`, `counts.missing_file:3`)
  resolves nowhere and lands there precisely so it never reaches `ok`. They are
  contained noise, and ANTS-3659 § 5 scopes them out by name. Surfacing them
  here would re-import the exact drowning problem that spec was written to fix.

**This deliberately diverges from `only:"stale"`, and the divergence is the
point.** ANTS-3654 INV-14 has that filter *keep* an `ok` citation whose
`anchor_found` is false — it is a **view** over citations, built for a reader
scanning drift. `findings[]` is a list of **defects**, and an advisory flag
saying a needle moved is not one; ANTS-3654 § 2 is explicit that `anchor_found`
is never a status. Two different questions, two different answers, and a caller
wanting the drift view calls `doc_citations` with `only:"stale"` directly.

**Reading convention.** Adapters and consumers read an absent `auto_fixable` as
false and a present `line:0` as document scope — the two conventions ANTS-3664
INV-1 fixes. The `doc_integrity` adapter sets `autoFixable` from a small
per-adapter kind list (today: `toc_gap` alone), because that struct predates the
flag; ANTS-3664 § 2.1 records why that is accepted rather than pushed upstream.

**Whole-document alarms are not dropped on the floor.** `doc_citations` returns
**six** per-document scalars that are not citations and so have no row in the
adapter table above — an adapter that only walks `citations[]` loses all six
silently. They split three ways, on whether the scalar describes a defect, a
statistic, or an *incomplete run*:

| Scalar | Becomes |
|---|---|
| `unterminated_fence` | a finding, `kind:"unterminated_fence"`, `line` = the opener |
| `unterminated_examples` | a finding, `kind:"unterminated_examples"`, `line` = the opener |
| `examples_suppressed` | `check_stats`, not a finding |
| `unparsed_total` | `check_stats`, not a finding — INV-4's second half asserts it |
| `read_budget_exhausted` | `check_errors[]` — the citation statuses are a floor |
| `basename_index_truncated` | `check_errors[]` — same, resolution was degraded |

The first two are defects by construction: an unterminated fence swallows the
rest of the document, and an unterminated `doc-examples` region suppresses every
citation after it. Both are invisible to a reader — the eye reconstructs what
the renderer ate — which is exactly why `/cold-eyes` § 1e adopted the fence
check, and § 1e reads it **from this field**. Dropping it here would break the
one caller this verb exists to serve. `examples_suppressed` and `unparsed_total`
are counts of things working as intended, so they are statistics.

The last two rows are neither, and putting them in `check_stats` would be the
quiet mistake. `read_budget_exhausted` says the engine stopped opening targets
before it ran out of citations, and `basename_index_truncated` says it resolved
against a partial index — in both cases the `ok`/`missing_file` split for that
document is a **floor**, not an answer, and a caller that reads `findings[]` as
complete is reading it wrong. `check_errors[]` is where this verb already says
"this checker's output for this document is not the whole story" (§ 2.4), so the
signal reuses it rather than inventing a third channel. Neither is a *failure*:
`ok` stays true and the findings that were produced are all valid.

### 2.3 The fix half lives in ANTS-3669

`fix:true` is opt-in per call, never the default, and applies only to findings
whose producer set `autoFixable` (ANTS-3664 § 2.1). **What may be repaired, the
write contract, and the `dry_run` and ETag consequences of writing are specified
in ANTS-3669**, split out of this document at the report/fix seam.

The seam is a risk boundary. Everything in this spec reads, computes and
returns; ANTS-3669 is the only part that modifies a file, and that one fact
drives three contracts nothing else here needs. Splitting also lets this half
ship and serve `/cold-eyes` § 1e before the write half exists, which is the
order the caller wants — the pre-pass reads far more often than it repairs.

What stays here: `fix` and `dry_run` appear in § 2.1's request schema, and
`fixed[]` / `files_written` / `fix_errors[]` in its response — absent entirely
under `fix:false`. Their *semantics* are ANTS-3669's. This section is kept as a
landing point for citations written against it rather than deleted, since
invariant and section references into a spec are cited from sibling specs.

### 2.4 Partial failure

One walk, five checkers, and they do not agree today on what an unreadable
document means: `DocIntegrity::check` silently excludes it, while
`DocCitations::check` refuses `read_failed`. Under one walk that collision needs
a decision, so:

- **A document that cannot be read or decoded is excluded from
  `checked_docs[]`, listed in `skipped[]` with a reason, and the run
  continues.** One bad file in a tree must not fail a whole review pass.
- **A fix that fails to write** (read-only file, permissions) appends to
  `fix_errors[]` and leaves `ok:true`. INV-5's byte-identical assertion would
  otherwise pass a silently-failed write, which is the worst of both.
- **A checker that fails on one document** — it refuses, throws, or hits its own
  internal cap — appends `{verb, file, reason}` to `check_errors[]`, and the
  walk continues with the remaining checkers on that document and with that
  checker on the remaining documents. The failure is *per document per checker*,
  never per run: one malformed spec must not silence `spec_lint` across a tree.
  The verb stays in `checks_run[]`, because it did run — but **a caller must
  read `checks_run[]` together with `check_errors[]`**, since a check with
  entries in the latter ran incompletely and its `counts` are a floor rather
  than a total. This is the one place in the envelope where a count is not
  authoritative, and it is stated rather than left to be discovered.

### 2.5 Files and hooks

Engine `src/doclint.{h,cpp}` in `ants_core_lib`, calling the five engines.
Verb layer mirrors `doc_integrity`: `cmdDocLint` plus `docLintEnumerate` and
`docLintBuildResponse`, and the registration set ANTS-3661 § 2.4 enumerates —
one `registerToolProvider` plus five `src/claudeintegration.cpp` hooks. Note
`doc_integrity` ships with **no** `selection_hint`; a five-checks-in-one verb is
the strongest candidate in this lane for one, so `doc_lint` adds it, making six
hooks rather than five.

**Two departures from that set, both forced by the write half.** `doc_lint` is
the only verb in this family that can write, so it declares `dry_run` through
the shared `makeDryRunProp()` factory and is deliberately **absent** from
`isEtagSupportedTool`. Both are specified in ANTS-3669 § 2.3, which owns the
reasoning; they are named here because they are departures from the
registration set *this* section inherits, and a reader assembling the hooks from
this list alone would otherwise add the ETag entry by symmetry with the
siblings — which is precisely the mistake that lets an `etag_match` swallow a
repair.

## 3. Invariants

- **INV-1** — One walk; **one shared read per enumerated document serving all
  three native checkers**, plus one read per adapted engine per document.
  *Test:* a `DocLint::Probe` open-counter over a three-document tree called with
  `checks:["doc_dedup","doc_symbols","spec_lint"]` → **three** opens — one per
  document, serving three checkers. An implementation that reads once per
  checker returns nine here, so this call discriminates and is the whole
  assertion.

  **The nine-open all-checks figure is a budget, not a test.** `doc_lint` can
  instrument only what it owns, and § 2.2 freezes the two adapted engines.
  `DocIntegrity` exposes no probe at all — its surface is `Finding`, `Options`,
  `check` and `gfmSlug` — and `DocCitations::Probe` counts `opens` as *target*
  files read, a different quantity from opening the document. Six of the nine
  are therefore unobservable without editing a frozen engine, so § 2.1 states
  nine as the honest budget and attaches no assertion to it. Target reads keep
  their own budget (ANTS-3636's `maxTargetReads`) and are out of scope here
  either way.
- **INV-2** — `checks[]` narrows findings *and* counts together; an unknown name
  refuses `bad_args`. *Test:* a fixture producing findings from two checkers →
  `checks:["doc_integrity"]` returns only those, with `counts` matching; plus
  `checks:["nope"]` → `bad_args`.
- **INV-3** — An `ok` citation is never a finding, including one with
  `anchor_found:false`. *Test:* a doc with a healthy citation, an
  anchor-missing-but-`ok` one, and a `missing_file` one → exactly one finding.
  The middle row is the one that fails against an adapter treating the advisory
  flag as a status.
- **INV-4** — `unparsed[]` entries never become findings, and are not lost
  either. *Test:* a doc whose only citation-shaped token is `6.2:1` → zero
  findings, **and** `check_stats["doc_citations"]["unparsed_total"] == 1`. Both
  halves are needed: without the first the verb re-imports ANTS-3659's problem,
  and without the second an adapter that discards `unparsed[]` entirely passes.
- **INV-5** — *moved to ANTS-3669* (its INV-1). The fix half's "changes only
  `autoFixable` findings" contract went with § 2.3.
- **INV-6** — *moved to ANTS-3669* (its INV-2). The report-only default is
  asserted where the write path is specified.

  Both ids are tombstoned rather than reused: `specs.md` § 5.5 forbids reflowing
  an invariant list, because ids are cited from sibling specs and a renumber
  silently redirects every citation. These are also the corpus's first instances
  of the `*moved to <ID>*` form ANTS-3662 INV-3 defines — which until now had a
  dozen occurrences of the observed form and none of a split.
- **INV-7** — Findings are in a **total** order: `file`, then `line`, then
  `verb`, then `kind`, then `message`, and finally
  **`DocFinding::Finding::emissionIndex`** — the producer's own 0-based counter
  within one run (ANTS-3664 § 2.1, where the field lives). *Test:* a tree producing findings from three
  checkers on one file, including two findings from the same verb on the same
  line (two dead links in one line, or two citations sharing a `doc_line`)
  **and two whose `message` strings are byte-identical** — two `broken_link`s on
  one line pointing at the same missing target — → the stated order,
  byte-identical across two runs.

  The identical-message row is why the sixth key exists. The first five are all
  properties of a finding, so two findings can agree on every one of them, and
  a five-key comparator leaves those two in whatever order the underlying
  container happened to yield — the definition of *not* total. The emission
  index is the tiebreak of last resort and is well-defined because each producer
  emits in its own document order, which its own spec fixes (ANTS-3661 INV-5,
  ANTS-3653 INV-33). An unstable tail makes every caller's diff noise, which is
  the whole reason this invariant is here.
- **INV-8** — The verb-contract minimum: no `caller_cwd` →
  `caller_cwd_required`; root-escaping `path` → `bad_path`; well-formed
  non-existent in-root `path` → `ok:true` with empty findings. *Test:* three
  calls.
- **INV-9** — `doc_citations`' whole-document alarms survive the adapter:
  `unterminated_fence` and `unterminated_examples` become findings carrying the
  opener's line, `examples_suppressed` becomes a `check_stats` entry. *Test:* a
  document with an unterminated fence, one with an unterminated `doc-examples`
  region, and one with a closed region suppressing two citations → two findings
  with the two kinds and the two opener lines, and
  `check_stats["doc_citations"]["examples_suppressed"] == 2` with **no** finding
  of that kind. This is the row that fails against the obvious implementation —
  an adapter that walks `citations[]` and nothing else — and `/cold-eyes` § 1e
  reads the fence alarm from this field, so losing it breaks the caller this
  verb was built for.
- **INV-10** — A checker failing on one document does not stop the walk, and its
  incompleteness is visible. *Test:* a three-document tree where one document
  makes one checker fail → `check_errors[]` of length one naming that
  `{verb, file}`, that verb still in `checks_run[]`, findings still present from
  it on the other two documents, findings still present from the *other*
  checkers on the failing document, and `ok:true`. Five assertions because
  failure containment is two-dimensional: per document and per checker, and an
  implementation that gets one axis right routinely gets the other wrong.
- **INV-11** — `max_findings` truncates after the sort, and `counts` is computed
  before it. *Test:* a tree producing twelve findings run with
  `max_findings:5` → `findings[]` of length five that is **the first five of the
  same run at `max_findings:500`**, `truncated:true`, and `counts` totalling
  twelve. The prefix identity is the assertion: a cap applied during collection
  also returns five findings and also sets the flag, and only the comparison
  against the uncapped run tells the two apart.

## 4. RAM / build cost

Peak is **up to three copies of one document's text** — the shared read the
three native checkers consume, plus the private read each adapted engine
performs (§ 2.1) — together with the union of the five checkers' per-document
state, all held while that document is processed and dropped before the next.
Three copies rather than one is the price of § 2.2's adapter-only rule, and it
is a bounded price: `maxDocBytes` caps each. The saving over five separate verb
calls is the re-reads and the four walks, not the peak.

The exception is `doc_dedup`, which is corpus-scoped by nature: its inverted
shingle index lives for the whole run (ANTS-3660 § 4). So `doc_lint`'s peak is
`doc_dedup`'s index plus one document, and disabling that one check via
`checks[]` returns the run to per-document cost. Stated because a caller
watching memory needs to know which check is the expensive one.

Caps are inherited, not re-invented: `maxDocsPerRun` and `maxDocBytes` from
`DocIntegrity::Options`, `maxPassages` and `maxPostings` from ANTS-3660,
`maxSymbolsPerRun` from ANTS-3661. `doc_lint` adds exactly one of its own —
`max_findings`, with `truncated:true` past it — because `findings[]` is the one
thing it produces that none of the five bounds, and ANTS-3636's discipline is
that every truncation sets a flag. `counts` is computed before the cap, so a
truncated response still reports the true totals.

One new translation unit; one new feature-test source into an existing bundle.

## 5. Out of scope

- **The fix half entirely.** `fix:true`'s contract, the one repairable kind, and
  the write-path consequences are ANTS-3669's (§ 2.3). This spec specifies the
  walk, the composition and the envelope.
- **Replacing the five verbs.** Each stays independently callable; this is a
  convenience and a shared walk, not a deprecation.
- **`AuditEngine` / `DebtSweep` findings.** Different lane, different consumer,
  and ANTS-3664 § 5 draws that boundary.
- **Running an LLM over anything.** Every check here is deterministic; the
  judgement calls are what the reviewer lanes are for.
