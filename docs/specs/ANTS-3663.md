# ANTS-3663 — `doc_lint`: every deterministic doc check in one call

**Status:** spec draft (2026-07-27).
**Kind:** enhancement.
**Source:** ROADMAP.md ANTS-3663 (user-request-2026-07-27).
**Blocked by:** ANTS-3664 (the finding shape), and ANTS-3660 / ANTS-3661 /
ANTS-3662 existing to be composed.
**Composes with:** ANTS-3601 (`doc_integrity`) and ANTS-3636 (`doc_citations`),
the two producers that already ship and are adapted rather than rewritten.

**Layman:** One button that runs all the document checks together, and repairs
the handful it can repair without guessing.

---

## 1. Problem

A `/cold-eyes` § 1e pre-pass currently means five or six separate verb calls
over the same tree. Each re-walks the same directory, re-reads the same files,
re-computes the same fence masks, and returns a differently-shaped envelope the
caller then reconciles by hand. **That reconciliation is the actual cost**, and
it is paid on every loop of every review.

Two consequences, and the second is the one that bites:

1. **Six walks where one would do.** `doc_integrity` and the three new verbs all
   enumerate `*.md` under the same root with the same `QDirIterator` (cloned from
   `RemoteControl::docIntegrityEnumerate`, `src/remotecontrol.cpp:12317`), and
   each re-reads every document.
2. **Six vocabularies.** Without ANTS-3664 they would report a problem six
   different ways, and the caller — a skill, not a program — would flatten them
   into prose to compare, which is what `ColdEyesEngine::BriefManifest`
   (`src/coldeyesengine.h:143`) already does by discarding structure. ANTS-3664
   removes that for the three new verbs; this spec removes it for the two that
   ship, by adapting them.

## 2. Surface

### 2.1 One walk, five checkers

`doc_lint` enumerates once, reads each document once, and passes the text to
each enabled checker. `checks[]` narrows the set (default: all); an unknown name
refuses `bad_args` rather than being silently ignored, because a caller that
misspells a check and gets a clean run has been told the wrong thing.

Response: `findings[]` as `DocFinding::Finding` (ANTS-3664) in document order,
`counts` from `DocFinding::countsByVerbAndKind`, `checked_docs[]`, and the
per-check envelopes each verb would have returned alone — so nothing a caller
could learn from six calls is lost in one.

### 2.2 The two adapters

`doc_integrity` and `doc_citations` ship with tested envelopes and live callers,
so **neither is rewritten**. Each gains a pure adapter in the verb layer:

| Source | → `DocFinding::Finding` |
|---|---|
| `DocIntegrity::Finding` | `kind` from its `Kind` enum (`dead_anchor` / `broken_link` / `toc_gap`); `file`, `line`, `message` map straight across |
| a non-`ok` `doc_citations` citation | `kind` from `status` (`missing_file`, `out_of_range`, `ambiguous`, `read_error`, `unresolved`); `line` from `doc_line`; `message` composed from `raw` and the status |

Two rules the adapters obey, both load-bearing:

- **An `ok` citation is never a finding**, including one whose
  `anchor_found:false` (ANTS-3654). That flag is *advisory* — it says a needle
  moved, not that the citation is wrong — and promoting it to a finding would
  contradict the parent spec, where it is explicitly not a status.
- **`unparsed[]` entries are not findings.** ANTS-3653's design contains them:
  a prose token that happens to parse (`6.2:1`, `counts.missing_file:3`)
  resolves nowhere and lands there precisely so it never reaches `ok`. They are
  contained noise, and ANTS-3659 § 5 scopes them out by name. Surfacing them
  here would re-import the exact drowning problem that spec was written to fix.

### 2.3 The fix half stays narrow, by design

Auto-fixable is exactly two kinds, and both are *derivations* rather than
judgements:

- **`toc_gap`** — a hand-maintained table of contents is regenerable from the
  document's own headings. There is one correct answer and the document contains
  it.
- **a version string disagreeing with the build system's single source of
  truth** — `project(... VERSION X.Y.Z)` in `CMakeLists.txt`. Same property: the
  answer is not a matter of taste.

**Everything else is report-only by design, not by omission**, and each refusal
has a reason rather than a shrug:

- deleting one of two duplicated facts needs a decision about which is
  canonical, and the wrong choice destroys the authoritative copy (ANTS-3660
  § 2.4);
- an unresolved symbol may be a forward reference to something the doc is about
  to create, which the verb must not adjudicate (ANTS-3661 § 2.3);
- renumbering an `INV-N` breaks every citation of it, which `specs.md` § 5.5
  forbids and `/cold-eyes` Phase 4 forbids again;
- a missing section needs prose only an author can write.

`--fix` is opt-in per call, never the default, and applies only to findings
whose producer set `autoFixable`. A run with `fix:true` reports what it changed
as `fixed[]`, so the caller never has to diff to find out.

### 2.4 Files and hooks

Engine `src/doclint.{h,cpp}` in `ants_core_lib`, calling the five engines.
Verb layer mirrors `doc_integrity`: `cmdDocLint` plus `docLintEnumerate` and
`docLintBuildResponse`, and the same six registration hooks.

## 3. Invariants

- **INV-1** — One walk, one read per document, whatever the check set. *Test:*
  a `Probe` counter on file opens (the ANTS-3636 `Options::probe` idiom) over a
  three-document tree with all checks on → three opens, not fifteen. This is the
  verb's whole premise and nothing else asserts it.
- **INV-2** — `checks[]` narrows findings *and* counts together; an unknown name
  refuses `bad_args`. *Test:* a fixture producing findings from two checkers →
  `checks:["doc_integrity"]` returns only those, with `counts` matching; plus
  `checks:["nope"]` → `bad_args`.
- **INV-3** — An `ok` citation is never a finding, including one with
  `anchor_found:false`. *Test:* a doc with a healthy citation, an
  anchor-missing-but-`ok` one, and a `missing_file` one → exactly one finding.
  The middle row is the one that fails against an adapter treating the advisory
  flag as a status.
- **INV-4** — `unparsed[]` entries never become findings. *Test:* a doc whose
  only citation-shaped token is `6.2:1` → zero findings, and the `doc_citations`
  sub-envelope still reporting `unparsed_total:1`. Without this row the verb
  re-imports ANTS-3659's problem.
- **INV-5** — `fix:true` changes only `autoFixable` findings, and `fixed[]`
  names each. *Test:* a tree with a stale TOC, a drifted version string, a
  near-duplicate pair and an unresolved symbol → `fixed[]` of length two, the
  other two files byte-identical afterwards. The byte-identical half is the
  assertion: a `fixed[]` of the right length proves nothing about what was left
  alone.
- **INV-6** — Default is report-only: without `fix`, no file is written.
  *Test:* the INV-5 tree run without the flag → every file byte-identical, and
  a source-scrape confirming the write path is reachable only under the flag.
- **INV-7** — Findings are in document order across checkers — by file, then
  `line`, then `verb` — so two runs are byte-identical. *Test:* a tree
  producing findings from three checkers on one file → the stated order, stable
  across two runs. Ordering must be total, or the response is unstable and every
  caller's diff is noise.
- **INV-8** — The verb-contract minimum: no `caller_cwd` →
  `caller_cwd_required`; root-escaping `path` → `bad_path`; well-formed
  non-existent in-root `path` → `ok:true` with empty findings. *Test:* three
  calls.

## 4. RAM / build cost

Peak is one document's text plus the union of the five checkers' per-document
state, held while that document is processed and dropped before the next — the
saving over five separate calls is the re-reads, not the peak.

The exception is `doc_dedup`, which is corpus-scoped by nature: its inverted
shingle index lives for the whole run (ANTS-3660 § 4). So `doc_lint`'s peak is
`doc_dedup`'s index plus one document, and disabling that one check via
`checks[]` returns the run to per-document cost. Stated because a caller
watching memory needs to know which check is the expensive one.

Caps are inherited, not re-invented: `maxDocsPerRun` and `maxDocBytes` from
`DocIntegrity::Options`, `maxPassages` from ANTS-3660, `maxSymbolsPerRun` from
ANTS-3661. `doc_lint` adds no cap of its own.

One new translation unit; one new feature-test source into an existing bundle.

## 5. Out of scope

- **Any fix beyond the two in § 2.3.** The narrowness is the design.
- **Replacing the five verbs.** Each stays independently callable; this is a
  convenience and a shared walk, not a deprecation.
- **`AuditEngine` / `DebtSweep` findings.** Different lane, different consumer,
  and ANTS-3664 § 5 draws that boundary.
- **Running an LLM over anything.** Every check here is deterministic; the
  judgement calls are what the reviewer lanes are for.

finding, adapt `unparsed[]` into findings, and make the write path
unconditional — recording what each actually turns red.

## 7. Cross-doc impact

- **ANTS-3664, ANTS-3660, ANTS-3661, ANTS-3662** are blockers.
- **`doc_integrity` and `doc_citations`** gain adapters only; ANTS-3601's and
  ANTS-3636's own contracts, envelopes and tests are untouched.
- **`/cold-eyes` § 1e** can collapse its per-verb calls to one — **but the
  caveat is load-bearing.** ANTS-1581 settled that the skill is global and these
  verbs are not, so § 1e may name `doc_lint` only alongside a stated hand-rolled
  fallback. Without that sentence every non-Ants project regresses, which is the
  failure this whole family has to keep avoiding.
- **`docs/subsystems.md`** — `src/doclint.{h,cpp}` joins `ants_core_lib`.
- **`docs/standards/mcp-tools.md`** — no change; this follows the checklist.
