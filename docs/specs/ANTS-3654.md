# ANTS-3654 — anchor-symbol drift check and the `only:"stale"` filter

**Status:** spec draft (2026-07-27).
**Kind:** implement.
**Source:** split out of ANTS-3636 (user-request-2026-07-27).
**Blocked by:** ANTS-3649 — `CodeSpan::delimLen`, without which the anchor-gap
measurement cannot find a multi-backtick span's opening column; and
ANTS-3653, whose scan locates the spans this check keys on.
**Extends:** ANTS-3636 (`doc_citations`). The verb is complete and useful
without this; nothing here is on its critical path.
**Residual:** ANTS-3642 — the un-anchored remainder and the caller-supplied
`expect` map.

**Layman:** A document often names a function right before pointing at the
lines it lives on. This checks whether that name is still on those lines — a
free staleness signal, no extra work for whoever wrote the doc.

---

## 1. Problem

`doc_citations` (ANTS-3636) answers "did this citation resolve". It does not
answer "does the cited text still say what the document claims", which is the
question the ROADMAP bullet actually asked and the reason citation rot goes
unnoticed.

This is a **derived, advisory signal layered on a resolved `ok` citation** —
which is why it is specified apart from the contract it derives from. It adds
two response fields (`anchor_symbol`, `anchor_found`) and one request value
(`only:"stale"`). It never produces a `status`, never changes one, and never
changes which citations resolve.

Splitting it also isolates the risk. This is the most speculative surface in
the original spec: its coverage is a fraction of the corpus, its
false-positive rate is deliberately unquantified, and its value rests on an
authoring convention rather than a rule. Those are honest properties of a
heuristic, and they should not sit in the same document as the read path's
hard contract, where a reader cannot tell which register they are in.

**Limits.** `maxAnchorGap` is a field of ANTS-3636 § 2.7's `Options` struct,
which is the single source of truth for its value. This spec names it and never
restates a number.

## 2. The check

The ROADMAP bullet asks for an `expect` mode ("does the cited line still
contain this substring?"). The corpus supplies a weaker version for free: its
commonest anchorable idiom names the symbol immediately before the location.

```
`RemoteControl::filterControlChars` (`remotecontrol.h:95-113`) strips C0
`uniqueSlug` (`roadmapindex.cpp:72-86`) DOES auto-append `-2`, `-3`
```

Both lines are verbatim from the corpus, and — checked 2026-07-26 — **the first
one has already drifted.** `filterControlChars` is declared at
`src/remotecontrol.h:128`, outside the cited `95-113`, so the verb would resolve
that citation `ok`, show three lines of unrelated comment text, and report
`anchor_found:false`. The second is healthy: `uniqueSlug` is defined at
`src/roadmapindex.cpp:73`, inside the cited range, so its needle is found. The
pair is kept exactly as written because a live true-positive standing beside a
live true-negative is a better specification of this check than anything
invented — and because a spec about citation rot that carried only pristine
examples would be making the wrong point.

Pinned precisely, so two implementers build the same thing:

- **Anchor** = the immediately preceding inline code span (located by
  `MarkdownScan::codeSpans`) whose content matches `^[A-Za-z_][A-Za-z0-9_:]*$`
  and whose closing delimiter run ends on the **same line as the opening
  delimiter of the span containing the citation**. That is the citation *span's*
  opening line, which for the rare span crossing a newline is not the citation's
  own `doc_line` (ANTS-3653 § 2) — naming it fixes both endpoints on one line, which a
  character-distance measurement needs. **Immediately** preceding: if any other
  code span sits between it and the citation's span, there is no anchor — the
  rule does not skip over non-identifier spans looking for a match, which is
  also what ANTS-3636 § 1's measurement command assumes. The gap between the two, measured
  on that raw line from the anchor's `endCol + delimLen` to the citation span's
  `startCol - delimLen` (ANTS-3636 § 2.7's `CodeSpan`, whose columns bound content and
  exclude delimiters), must be at most `maxAnchorGap` characters. A citation
  **not inside a code span** has no anchor, regardless of what precedes it.
- **Needle** = the anchor's final `::` component (`A::b` → `b`). An anchor
  ending in `::` yields an empty component and is discarded — no anchor.
- **Match** = case-sensitive, whole-identifier (the needle's occurrence must
  not be flanked by `[A-Za-z0-9_]`, so `id` does not match `invalid`), searched
  over the **full resolved range** — not the `max_range_lines`-clipped `text`,
  so display width never changes a verdict. That range is wider than the lines
  the engine reads today, so this rule moves the read call; § 6 carries the
  cost. When the range was clamped at EOF
  (ANTS-3636 § 2.6) the search covers the existing portion. A trailing `\r` is stripped
  from every emitted line and before this comparison, so a CRLF target produces
  no phantom mismatch (ANTS-3636 INV-23).
- `anchor_symbol` / `anchor_found` are **absent** when no anchor is found, and
  absent for every status that emits no text (`missing_file`, `out_of_range`,
  `read_error`, `ambiguous`, `unresolved`).
- **Two `counts` placeholders retire here.** `anchor_missing` becomes the number
  of `ok` citations with `anchor_found:false` — it ships hardcoded to `0`. And
  `unchecked` narrows from *every* `ok` citation, ANTS-3636's honest stand-in
  while nothing judged them (`src/doccitations.cpp:707-711`), to the `ok`
  citations this check left unjudged: those with no anchor. The two, plus the
  anchored-and-found remainder, partition `counts.ok`. Both stay whole-doc, so
  `only:"stale"` never moves them. Stated here because INV-14's fixture asserts
  the narrowed `unchecked` and an implementation that keeps the stand-in fails
  it with no rule to consult.

`anchor_found:false` is **advisory, not a `status`**: `status` answers "did the
citation resolve", this answers "does it still say what the doc claims".

**Coverage is ANTS-3636 § 1's 20%, and two caveats keep it honest rather than
flattering.** The anchor is only ever *evaluated* on an `ok` citation — one that
resolved and was read — so the share of the corpus this check actually judges is
that 20% intersected with the resolvable population, which ANTS-3636 § 2.4 notes is itself
less than the whole. And an anchored citation that fails to resolve reports its
status, not an anchor verdict.

The check is still worth its cost — it catches precisely the drift the ROADMAP
bullet describes, at zero authoring cost — but it is a *default*, not the
`expect` mode. The residual (the un-anchored remainder, and the scripted
re-verification case where a caller genuinely does hold an expectation) is
deferred to **ANTS-3642**, not quietly dropped.

**`anchor_found:false` is a prompt to look, not a verdict — and it is what
`only:"stale"` selects on, so its false-positive shapes are stated rather than
measured away.** Two shapes produce a false positive by construction. A citation
naming a symbol that sits a line or two *outside* the cited range reports stale
although the range may be fine. And a citation pointing at a *call site* rather
than a definition will not contain the symbol at all. **The rate is not
quantified** — these two shapes are the known sources and no measurement bounds
their frequency, so a reviewer should read the flag as "check this one", not as
a calibrated score. Neither is tunable away: widening the search past the cited
range would silently convert real drift into "found", which is the failure
direction this verb must never take.

## 3. Invariants

**The ids start at 13 by design.** They keep the numbers they held in
ANTS-3636, where both are now tombstones (`specs.md` § 5.5), so every existing
citation of INV-13 or INV-14 still resolves. Renumbering would break every
reference in the parent and its cold-eyes log.

- **INV-13** — `anchor_symbol` is the **immediately** preceding code span on
  the line § 2 pins — which must itself be an identifier; the rule does not
  skip a non-identifier span to find one — within `maxAnchorGap`, compared on
  its final `::`
  component, case-sensitively, whole-identifier, over the **full** resolved
  range regardless of `max_range_lines`; both fields absent when no anchor is
  found or the status emits no text. *Test:* a fixture table covering match;
  no-match; substring-only (`id` vs `invalid` → false); `A::b`; `Foo::` (no
  anchor); one character past `maxAnchorGap` (no anchor); case-differing
  (`Parse` vs `parse` → false, which a `Qt::CaseInsensitive` implementation
  would fail); an identifier before a citation **not** in a code span (no
  anchor); an identifier span with a **non-identifier span between it and the
  citation** (no anchor — the row that separates "immediately preceding" from
  "nearest preceding", which every other row passes either way); and `:1-10`
  with the needle on line 8 at `max_range_lines:3` → true.
- **INV-14** — `only:"stale"` keeps non-`ok` entries and `ok` entries with
  `anchor_found:false`, drops anchored-and-found and unanchored `ok`, never
  filters `unparsed[]`, and leaves `count`/`counts` whole-doc. *Test:* 3
  anchored-found-ok, 1 anchor-missing-ok, 2 unanchored-ok, 1 missing_file, 1
  unparsed → `returned:2`, `count:7`, `counts.ok:6`, `anchor_missing:1`,
  `unchecked:2`, `unparsed:1`, `unparsed_total:1`.

## 5. Cross-doc impact

- **ANTS-3636 § 2.5** is now a one-line pointer here. Its INV-13 and INV-14
  are `moved to ANTS-3654` stubs, keeping their original numbers so existing
  citations still resolve.
- **ANTS-3636 § 2.1** keeps the `anchor_symbol` / `anchor_found` / `only`
  entries in the response and options schema, since it owns the response
  shape; their *semantics* are here. That is the one fact this split leaves
  in two documents, and it is a schema row pointing at its own definition,
  not a restatement of it.
- **`Options::maxAnchorGap` is not in the shipped struct yet.** ANTS-3636
  § 2.7 declares it (`= 40`), but the implementation left it out rather than
  ship a field nothing reads — `src/doccitations.h`'s `Options` carries no such
  member. Adding it is this item's work, and it closes the only gap between
  that § 2.7 listing and the header. An implementer who reads § 1's "is a field
  of" as "already compiles" will not find it.
- **ANTS-3642** owns the residual: the un-anchored remainder and a
  caller-supplied `expect` map.

## 6. RAM / build cost

**The full-range match changes the read shape, and that is this item's whole
cost.** `src/doccitations.cpp:653` reads `qMin(maxRangeLines, cited)` lines —
the clip is a *read* bound today, not a display one, so § 2's "over the full
resolved range" cannot be satisfied by the lines currently in hand. The call
must ask for the full `cited` count when a citation carries an anchor, and only
then.

No new cap is introduced, deliberately. The worst case is already bounded by
the parent's `Options` — `maxTargetBytes` (8 MiB per target), `maxTargetReads`
(1000) and `maxCacheBytes` (24 MiB in-memory), all in `src/doccitations.h` —
and a citation wide enough to matter (`:1-9999`) is both rare and exactly the
one where a missed needle would be a **false stale**. Capping the anchor scan
below the cited range would buy bounded reads with silent false positives,
which is the direction § 2 already refuses.

Everything else is small: one `int` on `Options` (`maxAnchorGap`), and two
fields on `ok` citations only — `anchor_symbol`, a short identifier bounded by
the code span it came from, and a bool. Response growth is bounded by the
existing `maxCitations` (400) and `maxBytes`. No new build target: the test
directory joins an existing bundle's `SOURCES` per `tests/features/README.md`.
No new external library.
