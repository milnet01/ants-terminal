## 1. Problem

`/test-audit` skill is ~15 KiB SKILL.md + ~23 KiB references
(dimensions.md / framework-detection.md / grep-patterns.md) — ~38 KiB as
measured 2026-07-25; the draft's "9.5 + 22 = 32 KiB" predates several
skill revisions. ≈ **~8 K tokens first-session displaced** (corrected from
v3's overstated 14 K — loop 3 token H2). Subsequent sessions in the
same Claude session pay zero skill load.

Net per-sweep wins (after envelope+wrap costs):

| Source | Win |
|---|---:|
| First-session skill+refs displacement | ~8 K (one-time) |
| Per-chunk subagent brief shrink (3 KiB → 1 KiB × 17 chunks) | ~20 KiB ≈ 5 K tokens |
| Synth disk-input (~50 KiB report bodies stay on disk) | ~12 K tokens |
| Subtract: synth prompt + envelopes carry ~5 KiB to parent | -1.2 K |

**Per repeat sweep: ~16 K tokens; first sweep: ~24 K.** Loop 3
token-savings lane confirmed v3's 14 K claim was inflated on skill
load but DEFLATED on synth + per-chunk wins; honest restatement
above.

Per-chunk subagent dispatch cost (~68 K for a 17-chunk sweep) is
inherent and unchanged.

## 2. Surface

### 2.1 The verb family (matches cold-eyes / indie-review / debt-sweep)

| Verb | Phase | Return |
|---|---|---|
| `test_audit_partition` | Probe framework + enumerate test files; pack into chunks. | `{ok, framework, test_globs[], chunks[], total_files, chunks_count, dimensions_active[], pre_pass_findings_by_chunk{}?, pre_pass_cached, pre_pass_chunk_ids[], pre_pass_omitted?, pre_pass_omitted_bytes?, additional_frameworks[]? ### 2.2 `test_audit_partition` request/response

**Request:**
```json
{
  "caller_cwd": "/abs/path/to/project",
  "scope":      "auto | path:<subdir> | files:<csv>",
  "dimensions": "auto | csv:<d1,d2,...>",
  "chunk_size": 12,
  "quick":      false,          // ACCEPTED AND IGNORED — see below
  "offset":     0,
  "limit":      -1
}
```

**Response:**
```json
{
  "ok": true,
  "framework": "pytest",
  "test_globs": ["tests/**/*.py", "test_*.py"],
  "total_files": 192,
  "chunks_count": 16,
  "chunks": [
    { "id": "c-001", "paths": ["tests/api/test_a.py", "tests/api/test_b.py"],
      "pre_pass_dimensions": ["flakiness", "duplication"] }
  ],
  "dimensions_active": ["performance", "flakiness", "duplication", "security"],
  "dimensions_skipped": ["coverage_gaps"],
  "skip_reason_per_dimension": { "coverage_gaps": "restricted by config dimensions.deny" },
  "additional_frameworks": [ { "name": "jest", "root_rel": "web" } ],
  "pre_pass_findings_by_chunk": {
    "c-001": [ { "file": "tests/api/test_a.py", "line": 47,
                 "pattern_id": "sleep_call", "dimension": "flakiness" } ]
  },
  "pre_pass_cached": false,
  "pre_pass_chunk_ids": ["c-001"],
  "partition_token": "<qHash 4-byte hex>",
  "offset": 0, "limit": -1, "total": 16, "truncated": false,
  "byte_count": 41
}
```

`pre_pass_findings_by_chunk` entries carry `{file, line, pattern_id,
dimension}` ONLY — never matched text (INV-13). It is omitted, with
`pre_pass_cached: true` set, in **two** cases (the second was added by
ANTS-2070 after this section was written):

1. **Paging** — on pages 2+ of a paged partition (e.g. `offset:10,
   limit:10` on a 30-chunk project), since the orchestrator already
   retrieved them on page 1 and can look up locally (loop 3 token M2).
   Saves ~13 KiB on multi-page partitions.
2. **Envelope size** — even on page 1, when including the map would blow
   the envelope budget. A caller must therefore treat `pre_pass_cached`
   as "fetch these another way", not as "you are past page 1".

`pre_pass_chunk_ids[]` lists the chunk ids that *have* pre-pass
findings, so a caller can request briefs selectively. It is emitted
**unconditionally**, not only when the map is omitted.

**Not yet implemented:** `dimensions_skipped` and
`skip_reason_per_dimension` exist as `TestAuditEngine` struct members but
nothing populates them and the partition envelope builder never writes
either key. They are shown above as the intended shape; do not code
against them yet. `additional_frameworks[]` (ANTS-1623) *is* emitted.

**`quick` is a no-op (ANTS-3630).** The field is declared, forwarded
from the dispatch lambda, and never read by the engine — `quick:true`
performs the identical full walk + full pre-pass scan. § 7's flag
mapping is annotated accordingly, and the live skill now does the
`--quick` skipping caller-side.

**Paths are absolute.** `chunks[].paths`, `source_paths[]` and
`pre_pass_findings[].file` all carry the absolute walk-rooted path the
engine produced; nothing relativises them. The examples above are
abbreviated for readability. `byte_count` on partition measures a 2-key
stub (`{framework, chunks_count}`), not the emitted envelope.

Math: `chunks_count = ceil(total_files / clamped_chunk_size)`.
Example: 192/12 = 16 (corrected from v3's 187/12 → 17 inconsistency).

**Request:**
```json
{
  "caller_cwd": "/abs/path/to/project",
  "chunk_id":   "c-001",
  "partition_token": "<echo from partition>"
}
```

**Response:**
```json
{
  "ok": true,
  "chunk_id": "c-001",
  "source_paths": ["tests/api/test_a.py", "tests/api/test_b.py"],
  "dimensions": ["flakiness", "duplication", "performance", "security"],

  ],
  "prior_false_positives": [
    { "claim": "sleep in test_a is a deliberate timing fixture",
```

**No `brief` string field** (loop 3 opt H4 + user decision 2026-05-17).

markdown ships a 6-line "compose your brief like this" snippet
showing the canonical template. Saves ~3.4 KiB per sweep + a
string-template path on the hot path. Departs from ANTS-1281's
backwards-compat carry of the `brief` field (this is greenfield;
no legacy callers).

ANTS-1281 manifest-only rule preserved: `source_paths` lists
paths, never bodies.

### 2.4 `test_audit_synthesis_prompt` request/response

**Request:**
```json
{
  "caller_cwd": "/abs/path/to/project",
  "partition_token": "<echo>",
  "reports_dir": "<project-relative dir of per-chunk reports>",
  "calibration_anchor": { "raw": 412, "actionable": 38 },
  "allow_outside_project": false,
  "mode":   "summary | full | hybrid",
  "offset": 0,
  "limit":  -1
}
```

**Response:**
```json
{
  "ok": true,
  "prompt": "<single string the orchestrator hands to audit-triage>",
  "mode": "summary",
  "dimension_summaries": { "flakiness": { "count": 22 },
                           "duplication": { "count": 8 } },
  "top_dimensions": [ { "dimension": "flakiness", "count": 22 } ],
  "file_index": [ { "file": "/abs/path/tests/api/test_a.py",
                    "dimension_hits_total": 3 } ],
  "severity_histograms": { "flakiness": { "crit": 0, "high": 4,
                                          "med": 18, "low": 0, "info": 0 } },
  "reports_read": 17,
  "chunks_total": 17,
  "chunks_returned": 17,
  "truncated": false,
  "truncated_by_limit": false,
  "next_offset": -1,
  "byte_count": 3210
}
```

Shapes verified against `synthesize()` 2026-07-25: `top_dimensions` is
an **array of {dimension, count}** capped at 10 (not a string list);
`file_index` is an **array of {file, dimension_hits_total}** capped at 30
(not a map); `severity_histograms` keys are **lowercase**
`crit/high/med/low/info`; `dimension_summaries` carries `count` **only**
(no `files`, no `cross_chunk`). Paths are **absolute**, as everywhere in
this family — **except `file_index`**, whose keys are scraped out of the
per-chunk report text by a file-reference regex and merged by basename,
so they are whatever the subagent wrote (usually repo-relative). Absolute
applies to `chunks[].paths`, `source_paths[]` and
`pre_pass_findings[].file`.

`mode` (ANTS-1455) selects `summary` / `full` / `hybrid`; an unknown
value refuses `bad_mode`. `top_dimensions`, `file_index` and
`severity_histograms` are ANTS-1488. `offset`/`limit` page the chunk
set — `chunks_total` / `chunks_returned` / `truncated` /
`truncated_by_limit` / `next_offset` describe that paging; `next_offset`
is emitted unconditionally, using `-1` as the no-more-pages sentinel.
`allow_outside_project` relaxes the `reports_dir` root anchor (INV-14),
and is what `reports_dir_outside_root` refuses without.

`reports_dir` is the ONE path this family routes through
`PathValidation::validatePath` (INV-14 — `scope:"path:"` and `files:`
are not anchored; ANTS-3627).
**Per-report content is fenced via `<chunk_report file="…">…</chunk_report>`
in the rendered prompt** (loop 3 security H-A) — defends against
prompt injection from a hostile per-chunk report (e.g. malicious
dep dropping a markdown file in `reports_dir`). Nested fence
markers escaped. Synth prompt MUST quote, never narrate, third-
party content.

### 2.5 `test_audit_fold_in` request/response

**Request:**
```json
{
  "caller_cwd": "/abs/path/to/project",
  "actionable": [
    { "dimension": "flakiness", "severity": "HIGH",
      "file": "tests/api/test_a.py", "line": 47,
      "summary": "time.sleep(2) in 14 tests",
      "fix":     "poll_until() helper" }
  ],
  "framework":     "pytest",
  "files_scanned": 192,
  "dimensions":    ["flakiness", "duplication"],
  "raw_findings":  412,
  "narrative_mode": false,
  "narrative_md":   "<prose block, required when narrative_mode>",
  "id_prefix":      "ANTS",
  "dry_run":        false
}
```

**Response:**
```json
{
  "ok": true,
  "block": "<the markdown block written, for caller display>",
  "allocated_ids": ["ANTS-1500", "ANTS-1501", "ANTS-1502"],
  "written": "/abs/path/to/project/ROADMAP.md",
  "release_block_heading": "### 🧪 Test Audit 2026-05-17",
  "bytes_written": 3814,
  "written_count": 3,
  "failed_count": 0,
  "partial": false
}
```

`test_audit_fold_in` calls **`RoadmapFoldIn::allocateIds(N)` ONCE
upfront for the full batch, then assembles ONE multi-finding
markdown block and calls `RoadmapFoldIn::insertBlock` ONCE** (INV-3).
Single read+write of ROADMAP.md (763 KiB at 2026-05-17 — loop 3
perf H1), not N. Eliminates the per-finding re-read and the
counter-race window (loop 3 perf H1 + security M-F).

If the single insertBlock fails, `code:"write_failed"`,
`allocated_ids` returned (the counter advanced; the orchestrator
sees IDs that won't appear in the roadmap until the next call —
acceptable side effect, alternative is rolling back the counter
which races against any concurrent `roadmap_log` caller).

### 2.7 Worker thread placement

> **Correction (ANTS-3612, 2026-07-25).** The `m_auditPool` thread pool
> this section shares with ANTS-1351 was never built — it was always
> aspirational v2. ANTS-1351 INV-9 now describes what shipped: an ad-hoc
> `QThread::create()` per call plus an engine-side aggregate concurrency
> cap (`AuditRunner::kMaxConcurrentRuns = 2`) that refuses `server_busy`.
> The `server_busy` code below is therefore real, but it is emitted by
> `AuditRunner::runAudit`'s counting gate, not by a pool; and it bounds
> `audit_run` only — `test_audit_partition` has no such gate, so the
> draft's "`/audit && /test-audit` co-run, saturate beyond 2" model (since
> removed from this section) never held. Wiring the partition sweep to the same cap (or stating
> that it needs none) is open work — see § 9 Q3. (The spec as a whole is
> implemented; only this decision is outstanding.)

Partition's pre-pass regex sweep over ~2 MiB is a bounded in-process
walk (no child processes, unlike `audit_run`'s tool fan-out). Brief + synth + fold_in are fast (<200 ms) — run
on the dispatcher thread.

## 3. Invariants

- **INV-1 / partition is pure data, no shell.** File-system walk +
  pre-compiled `QRegularExpression` multi-pattern scan. Patterns are
  **compiled into the engine** as `QStringLiteral` regexes — nothing is
  read at runtime, which is what makes the engine self-contained (loop 3
  opt H2 — was an external skill-markdown read). The project-internal
  `docs/standards/test-audit-grep-patterns.json` is a *mirrored* source
  of truth, not a load path: a drift-guard test
  (`tests/features/test_audit_pattern_drift/`) asserts the two agree.
  Skill markdown documents the patterns inline as human reference. **Corrected 2026-07-25: there is no alternation.** The engine compiles
  the 17 `g_kPrePatterns()` entries into a `static QVector` of separate
  `QRegularExpression`s once per process (ANTS-1647) and loops them per
  line. Nothing is combined, ordered longest-first, or grouped by
  language — the only language-awareness is the literal/comment strip
  (`isCxxPath` / `isPyPath`). The loop-3 "perf M4" alternation design
  below was never built:
  *~~longest-alternative-first + common-prefix factoring; per-language-family combined regexes~~*
  built once at startup.
- **INV-2 / brief is path-only, NEVER file bodies.** ANTS-1281's
  rule. `source_paths` lists paths; subagent reads them.
  `byte_count` ≤ 8 KiB per chunk is an **unenforced target, not a cap** —
  nothing truncates. The unbounded term is `prior_false_positives`
  (ANTS-1457): up to 50 ledger entries, each `claim` ≤ 280 + `rationale`
  ≤ 1024 chars, with no byte cap on the JSON form, so a populated ledger
  can push a brief past 60 KiB.
- **INV-3 / fold-in delegates to `RoadmapFoldIn::*` (engine
  level) via SINGLE batched call.** `test_audit_fold_in` MUST
  NOT re-implement ID alloc, atomic write, or counter increment.
  Calls `RoadmapFoldIn::allocateIds(N)` ONCE for the batch + builds
  ONE multi-finding block + calls `RoadmapFoldIn::insertBlock`
  ONCE (loop 3 perf H1 + security M-F). NO MCP re-entry (loop 2
  impl M5). Source-scrape regression: no `QSaveFile` or
  `.roadmap-counter` access in `testauditengine.cpp`; one
  `RoadmapFoldIn::allocateIds` call per `foldIn` invocation.
- **INV-4 / `partition_token` via qHash** (loop 3 opt M9 + user
  decision 2026-05-17). Token =
  `qHash(callerCwd) ^ qHash(dimensionsSorted) ^ qHash(scope) ^
   qHash(maxMtime)` — **four** inputs; the design's fifth
  `qHash(engineVersion)` term was never implemented, so a token does not
  invalidate across engine versions. Emitted as 8-char hex via
  `QStringLiteral("%1").arg(h, 8, 16, '0')`.
  Collision 2⁻³² acceptable for staleness detection (NOT a
  capability — same-uid callers can reuse another session's token
  trivially, see § 9 Q-G). ~95 % cheaper than v3's SHA-256.
  **NOT a freshness guarantee (corrected 2026-07-25).** `computeToken`
  is called from `partition()` only. `brief` and `synth` do **not**
  recompute it — they do a bare lookup of the token in an in-memory
  partition cache (LRU, cap 16). So the token detects *eviction or
  process restart*, never a changed file set: edit or add a test file
  and the same token still resolves. The loop-3 security-M8 ordering
  claim ("recompute before any cache lookup") describes a mechanism that
  was never built — the lookup **is** the check. A miss →
  `stale_partition`.
- **INV-5 / `Required` contract on all verbs.** *(Corrected 2026-07-25 —
  the spec previously said `Optional`, which never shipped.)* All five
  `test_audit_*` verbs — `brief`, `fold_in`, `partition`,
  `synthesis_prompt` and `recheck` (ANTS-1722) — register
  `CallerCwdContract::Required` in `mainwindow.cpp` and are listed as
  `Required` in `ClaudeIntegration::callerCwdContractFor`, the latter
  (the block is commented simply `// Test-audit verb cluster
  (ANTS-1397).` — an earlier pass attributed a "parity with audit_run"
  citation here, but that comment belongs to `audit_poll`). So the
  **dispatcher** refuses
  `caller_cwd_required` on *every* verb in this family before any handler
  runs — it is not scoped to the one RcGate-gated write, and the read
  verbs do **not** accept an absent `caller_cwd`. RcGate handler-level
  enforcement still applies additionally to the write verb
  (`test_audit_fold_in`).
- **INV-6 / dimension list is engine canonical AND injected into
  brief.** 18 dimensions in `testauditengine.cpp` as
  the `TestAuditEngine::kDimensions()` accessor over a file-static `g_kDimensions()`. Brief carries active
  subset verbatim (§ 2.3 `dimensions[]`). Subagents do NOT depend
  on `references/dimensions.md`. **Schema dimensions arg is
  typed `string` (no enum)**; engine validates at request time
  and returns `unknown_dimension` if not in `kDimensions` (loop 3
  opt H1 — drops the redundant schema enum + the drift-guard
  test). Single writer.
- **INV-7 / per-chunk pre-pass cap.** Each chunk's pre-pass
  findings capped 20 entries (`kPrePassPerChunkCap = 20`).
  Excess is dropped **silently** — there is no `DBGLOG`/`qWarning` in
  the engine at all (corrected 2026-07-25). Total envelope: 17 × 20 × ~80 B
  = ~27 KiB.
- **INV-8 / Synthesis reads from disk.** `reports_dir` validated
  (INV-14). 64 KiB truncate per file; top-level only. Per-report
  content fenced via `<chunk_report file="…">…</chunk_report>`
  (loop 3 security H-A). Synth prompt is the only path that
  splices third-party content; fence makes it unambiguously
  data to the consuming subagent.
- **INV-9 / chunk size honours request.** Default 12. Clamped
  [4, 30]. Out-of-range → silent clamp, **not** echoed (corrected
  2026-07-25: `PartitionResult` has no `chunkSize` member and the
  envelope emits no `chunk_size` key — infer it from `chunks_count`). Total-files = 0
  → `{ok:false, code:"no_tests_found"}`.
- **INV-10 / partition envelope is paginated.** `chunks[]`
  paginated via offset/limit/total/truncated/next_offset using
  a hand-rolled `std::min` slice over `QVector<Chunk>` in `partition()` —
  no `PaginationEngine` involvement. `pre_pass_findings_by_chunk` filtered
  to page 1 chunks AND OMITTED from pages 2+ with
  `pre_pass_cached:true` (loop 3 token M2). Other three verbs
  fit under 20 KiB for synth and fold_in; **brief does not** — see
  INV-2, whose `prior_false_positives` term is unbounded. `truncated` here carries pagination
  semantics with `next_offset`; ANTS-1351's `samples_truncated`
  has different (irrecoverable) semantics.
- **INV-11 / fold-in respects rotation.** Generated bullets carry
  IDs from `.roadmap-counter` via `RoadmapFoldIn`. ANTS-1408
  archive-rotation rule applies once implemented.
- **INV-12 / NOT IMPLEMENTED — partition is ungated.** *(Corrected
  2026-07-25.)* The design called for a single in-flight partition per
  canonical projectRoot via the inline gate (ANTS-1351 § 2.4) keyed by
  `("test_audit_partition", canonicalProjectRoot)`. That was never wired:
  `verbInFlightTryAcquire` has exactly two call sites in the tree —
  `audit_run` and `indie_review_dispatch` — and `test_audit_partition`'s
  registration calls neither. **Consequently no verb in this family can
  emit `already_running`, and there is no slot for a reaper to reclaim.**
  Concurrent partitions on the same root simply both run. This matches
  § 2.7 / § 6, which already say the partition sweep is ungated.
  Whether to wire the gate (the sweep is an in-process walk with no child
  processes, so the case is weaker than for `audit_run`) or to ratify
  ungated is an open decision — see § 9 Q3.
- **INV-13 / pre-pass findings carry NO matched text.** Entries:
  `{file, line, pattern_id, dimension}` only. Engine type doesn't
  even have a "matched text" field (defence in depth). `pattern_id`
  is the stable id of the grep pattern; human description in
  `docs/standards/test-audit-grep-patterns.json`. **`pattern_id +
  file + line` is a read primitive under same-uid trust** (same-uid
  callers can already read the file; the spec is explicit so future
  readers don't treat `pattern_id` as a redaction — loop 3 security
  L-I).
- **INV-14 / path validation is PARTIAL — corrected 2026-07-25.**
  Only `reports_dir` routes through `PathValidation::validatePath` (the
  two call sites in `testauditengine.cpp`). `caller_cwd` gets a bare
  `canonicalFilePath()` + `isDir` check. **`scope:"path:<sub>"` is
  concatenated onto the project root with no anchor at all**, so
  `path:../..` walks outside the project; `files:<csv>` refuses only
  when the scope STRING contains a backslash — individual entries are
  never refused, empty and backslash-bearing ones are silently skipped
  by the walk, and `../` passes. The original text below
  describes the intended design, not the shipped one — the gap is
  tracked as **ANTS-3627**, and § 5's test 14, which would have caught
  it, was never built. Original intent: `caller_cwd` validated;
  canonical = `projectRoot`. `scope:"path:<subdir>"` validated.
  **`scope:"files:<csv>"` split on `,`; reject if any entry empty
  after trim; no escaping; reject backslash** (loop 3 security M-D
  — matches PathValidation's existing backslash-reject from
  ANTS-1295). `reports_dir` (synth) validated against projectRoot.
  TOCTOU window between validate and read accepted under same-uid.
- **INV-15 / NO recheck is implemented (corrected 2026-07-25).**
  `partition` records `mtimeWalkComputedAt`, and **nothing ever reads
  it**. The `brief` "recheck" block stats nothing (`synth` has no
  recheck block at all) — it writes a
  timestamp and returns, carrying the in-code comment *"(Recursive
  recheck would walk the test_globs roots; v1 skips…)"*. The only
  shipped part of this invariant is the **rate-limit timestamp**
  (`kMtimeRecheckRateLimitMs = 5'000`), which now throttles a check that
  does not happen.
  The consequence is stronger than the "deep-tree mtime gap" the
  original text conceded: the gap is **total**, not deep-subdir-only. A
  `brief` or `synth` against a stale token returns the partition as it
  was when computed, however much the test tree has changed since.
  Callers who need freshness must re-call `partition` — that is not a
  performance suggestion, it is the only way to get it. The original
  design intent is retained below for whoever wires it:
  *bounded recheck — stat the top-level test_globs roots (typically 1-2
  entries) and the expansion's modified-since `mtimeWalkComputedAt`;
  reuse the token if unchanged; rate-limit to once per 5 s per token
  (loop 3 security M-E DoS mitigation).*

  **Deep-tree mtime gap (ANTS-1447) — SUPERSEDED design intent; see
INV-15, which retracts the whole recheck.** The paragraph below describes
the *planned* shallow recheck, not shipped behaviour: nothing is stat'ed
and there is no token TTL. Retained for whoever wires the remainder, which sits under **ANTS-1450**
(ANTS-1447 shipped doc-only — it documented the gap as an accepted v1
limitation rather than closing it).
*Original text:* **.** The shallow recheck stats
  only the top-level `test_globs` roots. Adding a file in a deep
  subdir (e.g. `tests/api/integration/`) does not bump the
  parent root's mtime on most filesystems, so a `brief` / `synth`
  call inside the token TTL can return findings computed before
  that file existed, until the next full `partition` recompute.
  This is an **accepted v1 limitation**, not a bug: the staleness
  window is bounded (one partition TTL) and never produces a
  *wrong* answer about files the partition did see — only a
  *stale set* missing a just-added file. The resolution for v1 is
  this documentation plus the "re-call `partition` after editing
  tests" guidance above. v2 options, to revisit only if a
  stale-brief symptom is reported (tracked under ANTS-1450):
  (a) inotify watch on the test tree (new infra cost);
  (b) recursive mtime aggregation (`du`-style) on the recheck;
  (c) keep the gap, lean on the partition TTL. No option is
  scheduled — option (c) is the de facto v1 behaviour.

## 6. Performance / RAM budget

**Partition wall time:**
- File-tree walk + glob: ~50 ms / 200 files.
- Pre-pass regex scan: 17 patterns × 200 files × ~10 KiB = 2 MiB.
  17 separate pre-compiled regexes, looped per line (INV-1 — there is
  no alternation and no combined regex) → ~300 ms cold cache (32 GiB
  workstation); ~800 ms worst case (slower hardware).
- Every `partition` call re-walks and re-scans: it never reads the
  partition cache, only writes to it (the cache exists for `brief` /
  `synth` lookup). **There is no TTL** — `kMtimeRecheckRateLimitMs` is a
  per-token rate-limit stamp, not a cache lifetime.
- Runs **inline on the dispatcher thread** — there is no worker and no
  pool (see § 2.7's ANTS-3612 correction; the four `QThread::create`
  sites in `mainwindow.cpp` belong to `audit_run`,
  `indie_review_dispatch` and the generic `rcDelegateWorker` — none to
  `test_audit_*`). The GUI is therefore
  blocked for the partition's duration; § 6's partition budget (~50 ms walk + ~300 ms scan typical, ~800 ms
  worst case) is what keeps that acceptable — there is no separate
  400 ms figure.

**Brief wall time:** ≤ 50 ms (token recheck rate-limited per
INV-15; path list assembly).

**Synth wall time:** ≤ 200 ms (17 files × ~5 ms open + 1 MiB
read + prompt render with fencing).

**Fold-in wall time:** SINGLE read+write of ROADMAP.md (~2.44 MiB as
measured 2026-07-25; the 763 KiB figures below date from 2026-05-17).
Per-call ~80 ms at current size (read + splice + write + rename).
Was 30× this in v3's per-finding-write model (loop 3 perf H1).

**RAM:**
- Partition working set: 17 × 20 × ~80 B = ~27 KiB (no match text
  per INV-13).
- Brief: < 10 KiB transient.
- Synth: ≤ 100 KiB during read; ~5 KiB rendered prompt.
- Fold-in: ROADMAP.md held ~2.44 MiB transient during single splice
  (2026-07-25 measurement);
  released at return.
- Pre-compiled regex cache: ~10 KiB.

**Concurrency vs ANTS-1351 (corrected by ANTS-3612):** there is no shared
`m_auditPool`. `audit_run` bounds itself with an engine-side counting cap
(`kMaxConcurrentRuns = 2`, refusing `server_busy`); the partition sweep is
an in-process walk with no child processes and is currently ungated. See
§ 2.7's correction note.

**Disk:** Synth reads `reports_dir` (~51 KiB); fold-in writes
ROADMAP.md (~2.44 MiB at 2026-07-25).

**Schema/engine cost:** `kDimensions` static < 1 KiB; pre-compiled
regexes ~10 KiB; project-internal grep-patterns.json resource ~3 KiB.

## 8. Decisions

- **A verb family, not one verb.** Test-audit is intrinsically parallel.
- **Fold-in batched single write.** One `RoadmapFoldIn::insertBlock`
  with the full N-finding block; ROADMAP.md read+write once per
  call (loop 3 perf H1 fix).
- **All verbs Required** (corrected 2026-07-25 — "Optional" was the
  original design and never shipped). RcGate additionally at the handler for the write.
- **Pre-pass engine-side, no matched text.** Pure regex; secret
  leak impossible by type.
- **`partition_token` via qHash, not SHA-256** (user decision
  2026-05-17). Staleness check is not a capability.
- **No `brief` string field; structured-only response** (user
  decision 2026-05-17). Caller composes prompt from structured
  fields.
- **Pre-pass findings cached across partition pages.** Page 2+
  omits the field with `pre_pass_cached:true`.
- **Synth prompt fences per-chunk reports.** Defends against
  prompt-injection from hostile dep reports.
- **Namespace `TestAuditEngine` PascalCase.** Matches in-tree.
- **Inline in-flight gate (shared with ANTS-1351). NEVER WIRED** — the
  decision stands for `audit_run`, but no `test_audit_*` verb acquires a
  slot, so this family has no gate at all. See INV-12 and § 9 Q3.
- **Patterns ship as project-internal JSON resource.** Engine
  self-contained; skill markdown documents inline.
- **No `with_timing` v1.** Suite side-effects.
