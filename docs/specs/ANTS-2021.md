# ANTS-2021 — `read_region` MCP tool (read a line range or symbol body from a project file)

**Status:** shipped (unreleased — landed 2026-06-05) — 5 cold-eyes loops,
converged; implemented + feature-tested (tests/features/mcp_read_region/,
951/951 bundle green).
**Kind:** feature.
**Source:** ROADMAP.md ANTS-2021 (in-session-2026-06-04 — reading-to-edit
falls back to native Read because no MCP verb returns a slice of a file).
**Pairs with:** ANTS-2022 (`apply_edits` — the write half of the
read-slice/edit token-saver bundle), ANTS-1249 (`file_outline` — the
symbol scanner reused here), ANTS-1499 (ETag-304 pattern).

## 1. Problem

No MCP verb returns an arbitrary line range or a named symbol's body from
a project file. The existing read surface does not fit:

1. `file_outline` (`FileOutline::compute`, `src/fileoutline.h:44`) returns
   a symbol *index* (name + start line), not the bytes of any region.
2. `find_definition` returns a symbol's *location* (file + line), not its
   body (`RemoteControl::cmdFindDefinition`, `src/remotecontrol.cpp:9738`).
3. `read_log` (`ReadLog::filter`, `src/readlog.h:43`) filters a log file
   by line content; it has no line-range or symbol selector.

So a session that has located a function (via `find_definition` /
`file_outline`) and wants to read just that function falls back to native
`Read`, which over-reads: to see one 40-line function in a 2 000-line file
it either reads the whole file or guesses an `offset`/`limit`. There is no
free re-read either — re-`Read`ing an unchanged file re-emits every byte.

`read_region` is **not** a raw-byte saving over native `Read` on a first
read of an identical slice. Its value is two specific wins (frame it this
way, not as blanket savings):

1. **Under-read** — a symbol-scoped read returns one function's body
   without materialising the whole file into context.
2. **Free re-read** — an ETag-304 short-circuit makes re-reading an
   unchanged region cost nothing (the read-to-edit loop re-checks a region
   it already saw).

**Layman:** let a Claude session pull an exact slice of a file through
Ants — a line range or a named function — and re-read it for free when
nothing changed, instead of falling back to the built-in file reader that
re-sends the whole file.

### 2.1 Selector — exactly one of {line range, symbol}

- `path` (string, **required**) — project file. Resolved under
  `caller_cwd` and validated with
  `PathValidation::validatePath(rawPath, rootCanonical, "read_region",
  "path", /*allowOutsideRoot=*/false)` (`src/pathvalidation.h`). A malformed
  path or one canonicalising outside the project root → `check.bad` →
  return `check.err` (code `bad_path`). An in-root path that does not
  exist → `check.resolved` empty → `{ok:false, code:"not_found"}`.
- `start_line` (int, optional, 1-based) + `end_line` (int, optional,
  1-based, inclusive). Line-range mode.
- `symbol` (string, optional) — symbol-body mode.
- **Exactly one selector must be present.** Neither, or both a line
  selector and `symbol`, → `{ok:false, code:"bad_args"}`. In line mode
  `start_line` is required; `end_line` defaults to `start_line` (a single
  line) when omitted. `start_line < 1` or `end_line < start_line` →
  `bad_args`. A `start_line` past EOF returns an empty `lines:[]` with
  `ok:true` (not a refusal — the file is shorter than asked).

### 2.2 Line-range mode

Stream the file with `QFile::readLine` (no `readAll` slurp), discard lines
before `start_line`, collect `[start_line, end_line]` (clamped to the last
line), stop reading at `end_line`. `end_line` clamps silently to the
file's line count; the response echoes the **effective** `end_line` after
clamping.

### 2.3 Symbol-body mode

Resolve the symbol by reusing `FileOutline::compute(absPath,
Mode::Auto, /*includeDocComment*/false, /*maxSymbols=*/kMaxSymbolsCap)` and
scanning its `symbols[]` for an entry whose `name` equals `symbol` (exact,
case-sensitive). **Known limit:** `compute` hard-clamps `maxSymbols` to
`kMaxSymbolsCap = 1000` (`src/fileoutline.cpp:16,152`), so symbol mode can
resolve only the first 1000 outline symbols in a file; a symbol defined
past the 1000th outline entry resolves as `symbol_not_found` even though it
exists. This bites only pathologically symbol-dense files (≥ 1000
functions/classes — far above the project's largest); the caller falls
back to line mode there. Pass the constant explicitly (not a literal) so it
tracks any future `kMaxSymbolsCap` change. Second caveat:
`file_outline`'s 1024-byte per-line scan cap (`kMaxLineBytes`,
`src/fileoutline.cpp:15`; described at `fileoutline.h:8-9`) means a symbol
whose *declaration line* exceeds 1024 bytes may have that line truncated
before the scanner matches it, so the symbol can be missed — also rare,
same line-mode fallback. The body is the half-open line range
`[match.line, nextSymbolLine)` where `nextSymbolLine` is the `line` of the
**next entry in `symbols[]`** (outline order), or EOF when the match is the
last symbol. The outline is a **flat list with no nesting level** —
`appendSymbol` (`src/fileoutline.cpp:115-126`) emits only
`{line, kind, name, signature}`, no depth field — so this is the only range
the outline supports. Consequence (state it plainly): for a **leaf** symbol
(a free function / method, which contains no further outline symbols) the
range is the whole body; for an **aggregate** (a class/struct that contains
its own outline symbols) the range stops at the first nested symbol, i.e.
it returns the declaration head, not the whole class. Symbol mode is for
"read this function"; use **line mode** for a whole class body. Third
caveat (a `file_outline` limit, tracked by **ANTS-2028**): its
free-function regex `rxCppFunc` (`src/fileoutline.cpp:50`) has a
possessive-quantifier gap that never matches a free function with a
single-token return type (e.g. `int alpha()`), so symbol mode reliably
resolves only class/struct/namespace and qualified `Class::method` forms
until ANTS-2028 lands; a free-function name falls back to line mode. This is a
deliberately simple, outline-derived range (the "90% case" posture
`fileoutline.h:7-9` already takes), **not** a brace-accurate extent — see
§ 5. A `symbol` matching no outline entry →
`{ok:false, code:"symbol_not_found"}` (new code — added to
`mcp-error-codes.md` in the same change). When the same name appears more
than once (overload / shadow), the **first** outline occurrence wins and
the response echoes `symbol_ambiguous:true` + `symbol_match_count:N` so the
caller can fall back to line mode; it is not a refusal.

### 2.4 Output envelope

```json
{
  "ok": true,
  "path": "/abs/path/to/file.cpp",   // absolute resolved path
  "start_line": 120,                 // 1-based, effective (post-clamp)
  "end_line": 158,                   // 1-based inclusive, effective
  "lines": ["line 120 text", "..."], // the region, in order
  "returned": 39,                    // lines.length after the byte cap
  "truncated": false,                // true when the byte cap stopped the read early
  "bytes_cap_clamped": false,        // present iff max_bytes exceeded the 4 MiB ceiling
  "symbol": "TerminalGrid::reset",   // present in symbol mode (echo)
  "symbol_ambiguous": false,         // present in symbol mode iff > 1 match
  "symbol_match_count": 1,           // present in symbol mode iff ambiguous
  "etag": "<payload sha256 — injected by the dispatcher, not the handler>"
}
```

`end_line` always echoes the **last emitted line** — after both the EOF
clamp (§ 2.2) and the byte-cap truncation (§ 2.5), which runs last.
`truncated` is the **sole** signal that the byte cap (not the EOF clamp)
cut the region: `truncated:false` with `end_line < requested end_line`
means the file simply ended; `truncated:true` means the cap stopped it
early. No whole-file line count (`total_lines`) is returned — that would
force a full-file scan and defeat the bounded "stop at `end_line`" read
(INV-9); a caller that needs the file's length uses `file_outline`.

### 2.5 Byte cap

`max_bytes` (int, optional; default `RemoteControl::kReadToolDefaultBytesCap`
= 512 KiB, clamped to `RemoteControl::kReadToolMaxBytesCeiling` = 4 MiB —
`src/remotecontrol.h:233-234`). The cap is applied **incrementally during
the read** — read_region does **not** reuse `capJsonArrayToBytes`
(`src/remotecontrol.h:246`), which trims an already-built array (it would
first materialise the whole `[start_line, end_line]` slice, breaking the
heap bound when the requested range is large). Instead: as each line is
read it is appended and a running **serialised**-byte total is updated
(each line's JSON contribution — quotes + comma + escapes, the *same
accounting* `capJsonArrayToBytes` uses, just computed incrementally); once
the next line would push the total over `max_bytes`, reading **stops** —
that line and all later ones are never read, `truncated:true` is set, and
`end_line` echoes the last **emitted** line. A region is head-anchored, so
this naturally **keeps the head and drops the tail**. No `lines_dropped`
count is emitted: it would require reading past the cut (defeating INV-9's
heap bound), and `truncated` + the effective `end_line` already tell the
caller exactly where the read stopped and where to resume. A requested `max_bytes` above the ceiling sets
`bytes_cap_clamped:true`. Because the read stops at the earlier of
`end_line` or the `max_bytes` boundary and never materialises beyond it,
peak heap is bounded by `max_bytes` (≤ 4 MiB) regardless of the requested
range or file size. The eviction direction is the **opposite** of
read_log's: a region drops the **tail**, whereas read_log tails a growing
log and uses a drop-**oldest** deque (ANTS-1855 § 2.3). An implementer building
both must not cross the wires.

### 2.6 Standard contracts

- **caller_cwd: Required** (`callerCwdContractFor`). Empty `caller_cwd` →
  `code:"caller_cwd_required"` before the handler runs. A non-empty but
  non-resolving `caller_cwd` is handled upstream by `resolveCallerCwdRoot`
  (ANTS-1401/1404).
- **ETag-304 (ANTS-1499)** — add `read_region` to `isEtagSupportedTool`
  (`src/claudeintegration.cpp`) and a `makeEtagMatchProp()` line to the
  schema. The handler does **not** compute or emit an `etag`: the dispatch
  layer's `applyEtagPattern` (`src/claudeintegration.cpp:8391`) hashes the
  handler's response payload via `etagFor` (`:8384`,
  `hex16(sha256(responseText))`) and injects the `etag` field for any tool
  in `isEtagSupportedTool` — the same content-hash mechanism every other
  read tool uses (see the comment at `src/remotecontrol.cpp:6354-6357`). A
  matching `etag_match` short-circuits the *response* to
  `{ok:true, unchanged:true, etag:"<same>"}`. Note the saving is on the
  **output** side: because the payload is a content hash, the handler still
  runs and reads the region, but when the etag matches the dispatcher
  returns the short envelope instead of re-emitting the region bytes to the
  model — that is the "free re-read" (no output/context-token cost), not a
  skipped file read. Any edit to the file changes the slice, hence the
  payload, hence the etag.
- **fields projection (ANTS-1720)** — add `read_region` to
  `mcp::isFieldProjectionTool` (`src/mcpprojection.cpp`) and register
  `props["fields"] = makeFieldsProp()`. Lets a caller narrow to
  `["lines"]`. List `"etag"` in `fields` to keep 304.
- **No since_cursor.** ANTS-2021's headline floated "ETag-304 +
  since-cursor", but a region read is a fixed `[start,end]`/symbol slice
  with no append semantics — the only meaningful "has it changed since I
  last looked" signal is the file ETag, which § 2.6 already provides.
  Adding a byte-offset cursor (read_log's tailing mechanism) would
  duplicate the ETag with no extra saving and add surface for no value
  (Karpathy § 2). Resolved to ETag-only; flagged for cold-eyes (§ 7).

## 3. Invariants

- **INV-1** — Line-range mode returns exactly the lines `[start_line,
  end_line]` (1-based, inclusive) in order; `end_line` clamps to the
  file's last line and the response echoes the effective post-clamp range.
  A `start_line` past EOF returns `ok:true, lines:[]`. *Test:* fixture
  file, assert slice bytes + echoed range + past-EOF empty.
- **INV-2** — Symbol mode resolves via `FileOutline::compute` and returns
  `[match.line, nextSymbolLine)` where `nextSymbolLine` is the next
  `symbols[]` entry's line (flat outline order; no nesting level exists),
  or EOF; a leaf function returns its whole body, an aggregate returns to
  its first nested symbol. Resolution sees only the first
  `kMaxSymbolsCap`=1000 outline symbols (the `compute` clamp). A name with
  no outline match refuses with `code:"symbol_not_found"`; a name matching
  > 1 outline symbol returns the first with `symbol_ambiguous:true` +
  `symbol_match_count:N`. *Test:* C++
  fixture with a known free function (whole body) + a missing name
  (`symbol_not_found`) + a duplicated name (`symbol_ambiguous`,
  `symbol_match_count:2`).
- **INV-3** — Exactly one selector: neither selector, or a line selector
  together with `symbol`, refuses with `bad_args`; `start_line < 1` or
  `end_line < start_line` refuses with `bad_args`. *Test:* arg-matrix
  fixture.
- **INV-4** — A `path` routes through `PathValidation::validatePath` under
  `caller_cwd`; a path outside the root or malformed refuses with
  `bad_path`; an in-root path that does not exist refuses with
  `not_found`. *Test:* `read_region{path:"../../etc/passwd",start_line:1}`
  → `bad_path`; a missing in-root path → `not_found`.
- **INV-5** — caller_cwd is Required: empty `caller_cwd` refuses with
  `caller_cwd_required`. *Test:* source-scrape `callerCwdContractFor`
  returns `Required` for `read_region` + dispatch test.
- **INV-6** — ETag-304: `read_region` is in `isEtagSupportedTool` and the
  schema carries `etag_match`; the dispatcher injects the `etag`
  (payload sha256 via `applyEtagPattern`/`etagFor`, not handler-computed),
  and a matching `etag_match` short-circuits the response to
  `{ok:true, unchanged:true, etag}` (`applyEtagPattern` always sets all
  three); an edit to the file changes the slice payload and busts the etag. *Test:* source-scrape (`read_region` in
  `isEtagSupportedTool`, no handler-side `etag` field) + two-call feature
  test (match → 304, then touch file → fresh body).
- **INV-7** — fields projection: `read_region` is in
  `isFieldProjectionTool` and `fields:["lines"]` narrows the envelope.
  *Test:* source-scrape + projection feature test.
- **INV-8** — Byte cap keeps the head: `max_bytes` defaults to
  `kReadToolDefaultBytesCap` (512 KiB), clamps to `kReadToolMaxBytesCeiling`
  (4 MiB) with `bytes_cap_clamped:true` when over; when the region's
  serialised size exceeds the cap, the read stops early (head kept, tail
  never read), `truncated:true` set, and `end_line` echoes the last emitted
  line (no `lines_dropped`). *Test:* small-`max_bytes` fixture asserting
  head-kept + `truncated` + effective `end_line` < requested, plus an
  over-ceiling fixture.
- **INV-9** — Bounded read: the file is read line-by-line
  (`QFile::readLine`, no `readAll` slurp) and the read stops at the earlier
  of `end_line` or the incremental `max_bytes` boundary (§ 2.5) — it never
  reuses the build-then-trim `capJsonArrayToBytes`, so peak heap is bounded
  by `max_bytes` (≤ 4 MiB) regardless of the requested range or file size.
  *Test:* source-scrape (`readLine`, no `readAll`, no `capJsonArrayToBytes`)
  + a large-range/small-`max_bytes` fixture asserting bounded growth.

## 4. RAM / build cost

No persistent state, no cache, no new build target (helper lands in
`ants_core_lib` via `src/readregion.{h,cpp}`; schema in the existing
`ants_claude_lib`). No new external library. Line-range mode reads only up
to the earlier of `end_line` or the incremental `max_bytes` boundary
(§ 2.5), so the emitted array is bounded by `max_bytes` (≤ 4 MiB read-tool
ceiling). Symbol mode runs one `FileOutline::compute` pass, whose own caps
(`kMaxLineBytes`=1024 + `kMaxSymbolsCap`=1000, `src/fileoutline.cpp:15-16`)
bound it; the emitted body array is then bounded by the same `max_bytes`.
`max_bytes` is the named cap satisfying the no-unbounded-growth rule.

## 5. Out of scope

- Brace-accurate / AST-accurate symbol extents — v1 uses the outline's
  next-symbol heuristic. Revisit (ANTS follow-up) only if the heuristic
  proves too loose in practice.
- Multi-region / multi-file reads in one call — one `path` + one selector
  per call.
- `since_cursor` byte-offset tailing — ETag covers the free-re-read case
  (§ 2.6); not adding a second mechanism.
