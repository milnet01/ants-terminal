# ANTS-1429 — `roadmap_query` / `roadmap_log` `unrecognised_format` gate

## Problem

`mcp__ants__roadmap_query` against the Vestige engine roadmap
(`/mnt/Games/Scripts/Linux/3D_Engine/ROADMAP.md`, ~2130 lines,
402 KB of GFM-task-list content) returns
`{ok:true, bullets:[], count:0}`. That envelope is structurally
identical to two very different conditions:

1. **"No work pending"** — a normal Ants-format roadmap with all
   sections empty (legitimate, the caller can act on it).
2. **"Tool can't parse this file"** — Vestige hits this; the format
   isn't recognised and zero bullets are extracted from a 400 KB
   file (caller is in the dark; falls back to Read+grep only after
   tokens have already been wasted on the failing query).

The same shape also affects `mcp__ants__roadmap_log` indirectly:
`RoadmapIndex::buildIndex` parses the same emoji-anchored headings,
so a write against an unparseable file either fires `bad_section`
(misleading — the format is the problem, not the slug) or worse,
splices an Ants-emoji bullet into a file that won't render it.

Source: 2026-05-16 Vestige CC feedback: *"MCP cost tokens for the
failed query and saved none."*

## Goal

Fail-fast envelope when the file is non-empty but parseBullets
returns zero hits. New error code `unrecognised_format` joins the
remotecontrol error taxonomy. Both read (`cmdRoadmapQuery`) and
write (`cmdRoadmapLog`) gate on the same predicate so format
mixing can't happen.

Specifically: when the roadmap file is **larger than 1 KB** and
`RoadmapDialog::parseBullets` returns zero bullets, return:

```json
{
  "ok": false,
  "code": "unrecognised_format",
  "error": "roadmap_query: <path> parsed zero bullets from <N> bytes — format not recognised",
  "path": "<absolute path>",
  "bytes": <N>,
  "hint": "this tool expects roadmap-format.md emoji bullets; see ANTS-1428 for adapter mode status"
}
```

The 1 KB threshold avoids false positives on genuinely-empty stub
roadmaps. Worked counter-examples to defend the threshold:

- Minimum stub `# Roadmap\n\n_Under construction._` — 35 bytes.
- Section-titled stub with 4 empty `## Phase` headings and a
  brief intro paragraph — ~600 bytes.
- A real Ants-format roadmap (this project's, 2026-05-16) —
  ~770 KB, ~5400 lines.

A pathological stub — say, a verbose intro paragraph + 10 empty
section headings + a preamble describing each phase — could in
principle exceed 1 KB without any bullets. If that case ever
materialises, the gate's `hint` field points to ANTS-1428
(adapter mode) so the caller has a clear next step. Raising the
threshold beyond 1 KB would weaken the Vestige-style signal
(Vestige's 402 KB unparseable file is the canary; 1 KB is
already 400× below it).

## Design

### Read path (`cmdRoadmapQuery`)

The full-file branch (`section.isEmpty()`) is the only one that
sees parseBullets directly. After
`RoadmapDialog::parseBullets(markdown)` populates the cache, check:

```cpp
if (bullets.isEmpty() && fi.size() > kRoadmapMinParseableSize) {
    // ANTS-1429 — unrecognised_format gate.
    QJsonObject env;
    env["ok"]    = false;
    env["code"]  = QStringLiteral("unrecognised_format");
    env["error"] = QStringLiteral(
        "roadmap_query: \"%1\" parsed zero bullets from %2 "
        "bytes — format not recognised").arg(path).arg(fi.size());
    env["path"]  = path;
    env["bytes"] = fi.size();
    env["hint"]  = QStringLiteral(
        "this tool expects roadmap-format.md emoji bullets; "
        "see ANTS-1428 for adapter mode status");
    return QJsonDocument(env);
}
```

The section path (`section.isEmpty() == false`) is left
unchanged. A real section can legitimately be empty post-filter,
and the existing `bad_section` envelope already fires when the
index itself is empty (because `RoadmapIndex::buildIndex` finds
no headings — a strict-stricter signal than parseBullets).
Promoting `bad_section` → `unrecognised_format` is out of scope
for v1; the read-side full-file gate is enough to unblock the
Vestige caller.

### Write path (`cmdRoadmapLog`)

After reading the markdown (existing line ~1207), insert the same
gate **before** the `RoadmapIndex::buildIndex` call. The gate
inline-constructs the envelope (rather than routing through
`rlErr`) so the response carries `path` + `bytes` matching the
read-side shape:

```cpp
const auto preflightBullets =
    RoadmapDialog::parseBullets(markdown);
const qint64 markdownBytes = markdown.toUtf8().size();
if (preflightBullets.isEmpty() &&
    markdownBytes > kRoadmapMinParseableSize) {
    // ANTS-1429 — refuse the write rather than splice an
    // Ants-format bullet into an unrecognised target.
    QJsonObject env;
    env["ok"]    = false;
    env["code"]  = QStringLiteral("unrecognised_format");
    env["error"] = QStringLiteral(
        "roadmap_log: \"%1\" parsed zero bullets from %2 "
        "bytes — format not recognised; cannot safely splice")
            .arg(roadmapPath).arg(markdownBytes);
    env["path"]  = roadmapPath;
    env["bytes"] = markdownBytes;
    env["hint"]  = QStringLiteral(
        "this tool expects roadmap-format.md emoji bullets; "
        "see ANTS-1428 for adapter mode status");
    return QJsonDocument(env);
}
```

`parseBullets` on the markdown is **new work for the write path** —
the existing `cmdRoadmapLog` only calls `RoadmapIndex::buildIndex`
(line 1211), never parseBullets. The gate therefore adds one full
parse pass per write. Cost: a single linear scan; on a 400 KB
roadmap this is small (sub-10 ms on commodity hardware). The cost
is paid only on the success path; the error path returns before
buildIndex runs.

### Constant placement

`kRoadmapMinParseableSize` is declared as
`static constexpr qint64 kRoadmapMinParseableSize = 1024;` in
`src/remotecontrol.h` alongside `kRoadmapCacheTtlMs` (line 432)
and `kRoadmapSectionCacheCap`. Single source of truth so both
call sites in `remotecontrol.cpp` reference the same threshold,
and the test's INV-2 source-scrape lives in the header next to
the existing constants.

## Invariants

- **INV-1.** `cmdRoadmapQuery` full-file branch emits a
  `code:"unrecognised_format"` envelope when
  `RoadmapDialog::parseBullets(markdown).isEmpty()` AND
  `fi.size() > kRoadmapMinParseableSize`. Anchor: `ANTS-1429`
  comment at the gate.
- **INV-2.** Genuinely-empty roadmaps (size ≤ 1 KB) still take
  the existing `{ok:true, bullets:[], count:0}` path — no false
  positive on stubs. Anchor: the `> kRoadmapMinParseableSize`
  inequality is strict.
- **INV-3.** `cmdRoadmapLog` emits the same
  `code:"unrecognised_format"` envelope before
  `RoadmapIndex::buildIndex` runs. Anchor: `ANTS-1429` comment at
  the write-path gate.
- **INV-4.** Single source of truth for the threshold —
  `kRoadmapMinParseableSize` is declared once in
  `remotecontrol.h` (as a `static constexpr` class member
  alongside `kRoadmapCacheTtlMs`) and referenced from both gate
  sites in `remotecontrol.cpp`.
- **INV-5.** Both gate envelopes carry `path` + `bytes` + `hint`
  fields. The write-path envelope is inline-constructed (not
  routed through the file's existing `rlErr` helper) so the
  response shape matches the read path. Callers can correlate
  the failure with a specific file size — useful when the
  caller doesn't know whether `caller_cwd` resolved to the
  project root it expected.

## Test

`tests/features/mcp_roadmap_unrecognised_format/` — source-scrape
pattern matching the ANTS-1424 / ANTS-1427 style; same
`ANTS_TEST_SCOPE` + `slurp` + `SRC_REMOTECONTROL_CPP_PATH` harness
as `tests/features/mcp_roadmap_log_verb/`. No temp-file fixtures
(the behavioural surface is covered indirectly by every other
`mcp_roadmap_*` test going through cmdRoadmapQuery).

1. **INV-1 anchor + literal in `cmdRoadmapQuery`.**
   `remotecontrol.cpp` contains the `ANTS-1429` anchor comment
   AND the `"unrecognised_format"` literal AND a reference to
   `kRoadmapMinParseableSize`, AND the literal appears within
   `cmdRoadmapQuery`'s body — file-position bounded between
   `QJsonDocument RemoteControl::cmdRoadmapQuery(` (currently
   line 712) and `QJsonDocument RemoteControl::cmdRoadmapLog(`
   (currently line 1041). The substring length is asserted
   ≤ 16 KB so a future reorder that widens the bound trips the
   test loudly.
2. **INV-2 threshold.** `kRoadmapMinParseableSize = 1024` is
   declared in `remotecontrol.h` (header source-scrape) next to
   `kRoadmapCacheTtlMs`.
3. **INV-3 write-path literal in `cmdRoadmapLog`.** The
   `unrecognised_format` literal also appears within
   `cmdRoadmapLog`'s body — bounded between
   `QJsonDocument RemoteControl::cmdRoadmapLog(` (line 1041) and
   `QJsonDocument RemoteControl::cmdWorkspaceSearch(` (currently
   line 1359), with the same ≤ 16 KB length assertion. Write-path
   envelope shape parity with read path: scrape confirms both
   `env["path"]` and `env["bytes"]` are assigned alongside the
   `unrecognised_format` literal within the bounded substring.

Label `features;fast`. Behavioural coverage is the existing
`remote_control_roadmap_query` test plus the live MCP fleet —
nothing in those changes shape because the gate fires only on
files that no existing fixture exercises.

## Migration

None. Ants's own roadmap is Ants-format and well over 1 KB, so
the gate never fires here. For non-Ants projects (Vestige), the
silent-empty response becomes a typed error envelope —
strict improvement, callers couldn't act on silent-empty anyway.

## RAM budget

Zero net change on the success path's response shape. The gate
runs `parseBullets` on the write path (new work; ~5-10 ms on a
400 KB file), but allocates nothing beyond a transient
`QList<Bullet>` that drops at scope exit. Read path is
unchanged — parseBullets was already called.

## Build cost

~25 LoC across `cmdRoadmapQuery` (gate + envelope) +
`cmdRoadmapLog` (gate + envelope) + 1 header constant. New
`tests/features/mcp_roadmap_unrecognised_format/` fixture
(~110 LoC test, 3 invariants). No new dependencies.

## Pairs with

- **ANTS-1428** — adapter mode survives this gate. Once adapter
  mode lands, the gate still fires for files that are neither
  Ants format nor a recognised foreign dialect.
- **ANTS-1432** — failed-call metric will count gate hits as
  waste-bytes attributable to format mismatch.
