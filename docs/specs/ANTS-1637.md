## 1. Problem

Today every Claude session re-derives the project's shape from scratch.
There is no MCP verb that returns a project-wide structural map, so a
session that wants "where is symbol `Foo::bar`", "what files are in the
`testauditengine` lane", or "what is this project's overall shape" falls
back to repeated native tooling:

1. `workspace_search` finds exact symbol/string matches but the caller
   must already know the token, and each call re-walks the tree.
2. `find_definition` (`RemoteControl::cmdFindDefinition`,
   `src/remotecontrol.cpp:9939`) re-greps live on every call and has an open
   mis-classification bug (ANTS-1700).
3. `file_outline` (`FileOutline::compute`, `src/fileoutline.h:44`) returns
   one file's outline — the caller must already know which file, and there
   is no project-wide rollup.
4. `subsystem op=files lane=<lane>` (`SubsystemMap`, `src/subsystemmap.h`)
   returns a lane's files, but only for lanes parsed out of
   `docs/subsystems.md`/CLAUDE.md — many real subsystems (`testauditengine`,
   `coldeyesengine`, …) are not listed there and return `unknown_lane`
   (the gap ANTS-1636 documented).

So a session re-pays `grep -r` / `file_outline` / CLAUDE.md reads at the
start of every task to learn the same fixed project shape. The Ants
process already has the focused project's path, `docs/subsystems.md` parse,
and the file tree available; computing a structural map **once** and
serving it cheaply collapses that recurring re-derivation to a single call.

Frame the value precisely (not as blanket savings on a one-off read):

1. **Pre-computed shape** — one `codebase_index` summary call returns
   file/lane/language counts a session otherwise reconstructs from several
   `grep`/`ls`/CLAUDE.md reads.
2. **Pre-indexed symbol lookup** — `symbol=`/`lane=` answer from the cache
   without re-walking or re-grepping the tree.
3. **Free re-read** — an ETag-304 short-circuit makes an unchanged query
   cost no output tokens (ANTS-1499).

**Layman:** Ants builds a one-time map of your project — which files exist,
what functions they define, which subsystem each belongs to — caches it,
and hands it to a Claude session in one call, so the session stops
re-scanning the whole project every time it needs to find its way around.

## 2. Surface

New MCP **read** tool `codebase_index`, wired across the standard read-tool
sites and backed by a pure, Core-only helper so the build/refresh/query
logic is unit-testable without a live tab (mirrors `readregion` /
`fileoutline` / `findsources`):

- Pure helper module `CodebaseIndex` in `src/codebaseindex.{h,cpp}`,
  joining `ants_core_lib` (the lib `fileoutline.cpp` / `findsources.cpp` /
  `subsystemmap.cpp` are in). It does FS reads (`QDir`/`QFile`) but no Qt
  Widgets and no subprocess — the same posture as `findsources`
  (`src/findsources.h:1-15`).
- Handler `RemoteControl::cmdCodebaseIndex` (`src/remotecontrol.cpp`,
  `ants_core_lib`) — resolves the project root from `caller_cwd`, validates
  a `file_path` arg when present, then orchestrates load → refresh → query
  → cache-write (§ 2.5) by calling the pure helper.
- inputSchema built **inside** the `tools/list` builder block of
  `src/claudeintegration.cpp` (the block-local `makeEtagMatchProp()` /
  `makeFieldsProp()` lambdas are defined and reused there — there is no
  `registerBuiltinTools` function; per ANTS-2021 § 2).
- Dispatch `registerToolProvider("codebase_index",
  ClaudeIntegration::CallerCwdContract::Required,
  rcDelegate(&RemoteControl::cmdCodebaseIndex))` in `MainWindow`, alongside
  the existing read-tool registration block at `src/mainwindow.cpp`
  (`workspace_search` / `file_outline` / `read_region`, all `Required`).
- `callerCwdContractFor` gains a `codebase_index → Required` entry
  (`src/claudeintegration.cpp`) — `registerToolProvider` asserts the two
  agree.

### 2.1 Index data shape (v1)

The on-disk cache and the in-memory `CodebaseIndex::Index` struct share one
shape:

```cpp
namespace CodebaseIndex {

struct Symbol {            // a subset of FileOutline's symbol entry
    QString name;          // qualified as FileOutline emits, e.g. "TestAuditEngine::foldIn"
    int     line = 0;      // 1-based
    QString kind;          // FileOutline's kind verbatim: "func" | "class" | "qt"
                           //   ("heading" is unreachable — md not in the indexed-suffix set)
};

struct FileEntry {
    QString         path;       // project-relative ("src/testauditengine.cpp")
    QString         language;   // FileOutline language; "cpp"|"py" in v1 (§ 2.2 indexed-suffix set)
    QString         role;       // "impl" | "header" | "test"
    QString         lane;       // "" when no lane resolves
    int             lines = 0;  // FileOutline total_lines
    qint64          mtimeMs = 0;
    QVector<Symbol> symbols;    // capped at FileOutline's 1000/file (no per-file overflow flag, § 2.4)
};

struct Index {
    int                              version = kIndexVersion;  // = 1
    QString                          rootCanonical;
    qint64                           generatedAtMs = 0;        // injected, not clock-read (testability)
    qint64                           mapSourceMtimeMs = 0;     // docs/subsystems.md|CLAUDE.md mtime (§ 2.3)
    QVector<FileEntry>               files;                    // sorted: src/ (sorted) then tests/ (sorted)
    QMap<QString, QStringList>       laneToFiles;             // lane → [relative paths], each list sorted
    bool                             filesTruncated = false;   // INV-11/INV-15 build ceiling hit
};

}  // namespace CodebaseIndex
```

JSON serialisation (`toJson` / `fromJson`) mirrors this 1:1. `signature`
from `FileOutline` is **not** stored (a caller wanting a signature uses
`file_outline` / `read_region`) — keeps the cache small.

### 2.2 Pure helper API

```cpp
namespace CodebaseIndex {

constexpr int    kIndexVersion    = 1;
constexpr int    kMaxIndexFiles   = 5000;            // INV-11 build file-count ceiling
constexpr qint64 kMaxCacheBytes   = 16 * 1024 * 1024; // INV-11 hard cache/heap ceiling (16 MiB)
constexpr int    kMaxQuerySymbols = 2000;            // INV-14 lane= response cap
// Per-file symbol resolution is bounded by FileOutline's own clamps —
// kMaxSymbolsCap=1000 / kMaxLineBytes=1024 — which are FILE-PRIVATE to
// fileoutline.cpp (anonymous namespace opening at :13; constants at
// fileoutline.cpp:15-16): NOT exported from the header, so they cannot be
// referenced by name here. compute()
// clamps maxSymbols internally (fileoutline.cpp:152), so the build just
// passes a literal 1000 (≥ the clamp) — no symbol is imported.

struct Options {                       // all overridable for tests
    int    maxIndexFiles   = kMaxIndexFiles;
    qint64 maxCacheBytes   = kMaxCacheBytes;
    int    maxQuerySymbols = kMaxQuerySymbols;
};

// Full cold build: walk <root>/src + <root>/tests admitting source files by
// the indexed-suffix set (§ 2.2), FileOutline::compute per file (passing
// maxSymbols=1000, ≥ compute's internal clamp), assign each file's lane
// (§ 2.2) and invert to laneToFiles (each list sorted — determinism). Stops
// adding files at maxIndexFiles (INV-11) OR when the serialised index would
// exceed maxCacheBytes (INV-15), whichever first, setting filesTruncated.
// generatedAtMs + mapSourceMtimeMs are passed in by the caller (no internal
// clock read — testability).
Index build(const QString &rootCanonical, qint64 generatedAtMs, const Options &opts = {});

// What changed on disk vs `prev`: files whose mtime differs, files present
// on disk but not in `prev` (added), and `prev` files gone from disk
// (removed). A non-zero delta OR a changed map-source mtime means a refresh
// is needed.
struct StaleSet { QStringList changed, added, removed; bool mapSourceChanged = false; };
StaleSet staleFiles(const Index &prev, const QString &rootCanonical, qint64 currentMapSourceMtimeMs);

// Apply a StaleSet: re-outline only changed+added files, drop removed,
// reuse prev's symbols for untouched files, re-derive laneToFiles when the
// map source changed. Returns the count of files re-outlined in *refreshedOut.
Index refresh(const Index &prev, const QString &rootCanonical,
              qint64 generatedAtMs, qint64 currentMapSourceMtimeMs,
              const Options &opts, int *refreshedOut);

// One query's selectors (§ 2.4): at most one member is non-empty; the
// non-empty one picks the filter, none → summary. The handler rejects ≥2
// non-empty with bad_args *before* calling query().
struct QueryParams { QString symbol; QString lane; QString filePath; };

// Filter the index for one query (§ 2.4). Returns the response JSON object
// body (without the dispatcher-injected etag).
QJsonObject query(const Index &idx, const QueryParams &params);

QJsonObject toJson(const Index &);
Index       fromJson(const QJsonObject &);

}  // namespace CodebaseIndex
```

**Indexed-suffix set.** The walk admits a file iff its suffix ∈
**`{.cpp, .cc, .h, .hpp, .hh, .py}`**; anything else (`.md`, `.json`,
assets) is skipped. So in v1 `FileEntry.language` is `cpp` or `py`; the
`md`/`json`/`""` values the `language` type allows are reserved for a
future walk that admits them.

`role` classifier (local to `codebaseindex.cpp`, mirrors `findsources`'
impl/header/test idea): `header` iff suffix ∈ {`.h`,`.hpp`,`.hh`}; else
`test` iff the relative path starts `tests/` **or** the basename matches
`^test_`; else `impl`. Each file gets exactly one role, so the summary
`roles{}` counts always sum to `file_count`.

`lane` resolution per file — `SubsystemMap::parse` yields lane **names** +
summaries (`Lane{name, summary}`, `src/subsystemmap.h:20-23`), **not** a
file list, so membership is *computed*:

1. **Module-map lane** — the file's basename starts with a `SubsystemMap`
   lane name. For a `src/` file this is the same `src/<lane>*` prefix rule
   the live `subsystem op=files` uses (`resolveLaneFiles`,
   `src/remotecontrol.cpp:7626-7652`, ANTS-1251-INV-4), so `codebase_index`
   and `subsystem` agree on a **`src/` file's** lane. `resolveLaneFiles`
   globs `src/` only — a `tests/` file matching a lane-name prefix is
   lane-assigned by `codebase_index` with **no** `subsystem op=files`
   counterpart (tests/ lane membership is `codebase_index`-only; the two
   cannot disagree because `subsystem` never reports a `tests/` file).
2. **Unlisted family** (the ANTS-1636 gap — `testauditengine`,
   `coldeyesengine`, … are not in the module map) — when the basename matches
   `^[a-z0-9]+(?:engine|dialog|widget|cache|helper)\.(?:cpp|cc|h|hpp|hh)$`, the
   lane is the **basename stem** (extension stripped), so
   `testauditengine.cpp` and `testauditengine.h` share lane `testauditengine`.
   The extension alternation matches the indexed-suffix set so a
   `foowidget.hpp` is laned, not silently un-laned.
3. else `""`.

`laneToFiles` is the inversion of this per-file assignment (module-map
names win over a regex-captured name on a collision).

### 2.3 Build & staleness (lazy, on-demand)

There is **no** background timer. The token saving is in *serving* a
pre-computed map, not in keeping it pre-warm; a daemon would burn steady CPU
on every focused tab to shave a one-time cold-build latency that only a
session's first query ever pays. Each `codebase_index` call:

1. Resolve `rootCanonical` from `caller_cwd`: `expandGlobalConfigSentinel`
   (the `~global` / `~claude-config` sentinel, ANTS-1390) then, when not a
   sentinel, `resolveRootCanonical(m_main, req)`
   (`src/remotecontrol.cpp:8322-8325`).
2. Load the disk cache at the path in § 2.5. **Cold-build** (build from
   scratch) on any of these triggers (INV-13):
   - the cache file is **absent**;
   - its bytes **do not parse** as JSON (`fromJson` fails on a
     truncated/garbage file);
   - its `version` ≠ `kIndexVersion`;
   - its `rootCanonical` ≠ the resolved root (the last two a defensive
     guard against a hash collision or a relocated project).
3. Otherwise compute `currentMapSourceMtimeMs` = mtime of
   `SubsystemMap::resolveSource(<root>/CLAUDE.md)` (the canonical lane
   source — `docs/subsystems.md` when present, else CLAUDE.md), call
   `staleFiles`, and `refresh` only the delta. **The map-source mtime is
   part of staleness** so a `docs/subsystems.md` edit that re-homes a lane
   re-derives `laneToFiles` even when no `src` file changed (INV-3).
4. If the build/refresh changed anything (cold build, non-zero
   `StaleSet`, or `mapSourceChanged`), write the cache back atomically
   (§ 2.5), honouring the `maxCacheBytes` ceiling (a build or a refresh that
   would push the serialised index over the cap stops adding files and sets
   `filesTruncated`, INV-11). The number of files re-outlined this call is
   echoed as `refreshed_files`.
5. Filter + serve (§ 2.4).

`staleFiles` walks `<root>/src` + `<root>/tests` (one `readdir` subtree
each — an absent `src/` or `tests/` is skipped silently, not an error) to
catch added/removed files, plus one `stat` per known file to catch mtime
changes; `FileOutline::compute` (the only non-trivial cost) runs **only**
for the `changed`+`added` delta — so the warm-path cost is *one stat per
indexed file + zero outline passes* when nothing changed. A root with no
source files under either subtree yields `file_count:0` and an `ok:true`
empty summary (§ 2.4), never a refusal.

### 2.4 Query selectors

```json
{ "caller_cwd": "/abs/project",   // required
  "symbol":    "Foo::bar",         // optional — exact, case-sensitive
  "lane":      "testauditengine",  // optional
  "file_path": "src/foo.cpp" }     // optional
```

| selector | hit body | miss / refusal |
|---|---|---|
| *(none)* | summary: `{file_count, lane_count, lanes:[{lane, file_count}], languages:{cpp:N,…}, roles:{impl:N,header:N,test:N}, files_truncated}` (`file_count` = count of *indexed* files, ≤ on-disk when `files_truncated`; the `""` lane is **excluded** from `lane_count`/`lanes[]`) | — (a zero-file root is an `ok:true` empty summary, not a miss) |
| `symbol=` | `matches:[{path, line, kind}]` — every file/line defining that exact name (overloads + multi-file) | `ok:true, found:false, matches:[]` |
| `lane=` | `{lane, files:[{path, role, language, lines, symbols:[{name,line,kind}]}], symbols_truncated}` | unknown lane → `ok:true, found:false, lanes:[<available names>]` |
| `file_path=` | the file's indexed entry `{path, role, language, lines, lane, symbols}` | in-root but unindexed (incl. a path resolving to a **directory**) → `ok:true, found:false`; outside-root/malformed, **or an in-root symlink canonicalising outside root** → `ok:false, code:"bad_path"` |
| *(≥2 selectors)* | — | `ok:false, code:"bad_args"` |

All hit/miss bodies ride alongside the § 2.6 meta block. Caveats:

- **Soft miss, not a code.** A `symbol`/`lane`/`file_path`-in-root miss is
  `ok:true, found:false` — querying an index, absence is a valid answer.
  This follows `find_definition` (absence is `ok:true`, not a refusal) and
  **deliberately diverges** from the sibling read tool `read_region`, which
  mints a `symbol_not_found` code (ANTS-2021): an *index-query* absence is a
  valid answer, a *region-extract* failure is an error — the split is
  chosen, not accidental, and `found` is `codebase_index`'s own field. Only
  an outside-root `file_path` (`bad_path`) and `≥2 selectors` (`bad_args`)
  are refusals.
- **Empty selector = absent.** A selector member that is the empty string
  (`{symbol:""}`) counts as *not provided* (§ 2.2: "non-empty member picks
  the filter"), so it falls through to the summary — not `bad_args`.
- **`symbol=` coverage equals `FileOutline` coverage** — it inherits the
  open ANTS-2028 free-function regex gap (a free function with a
  single-token return type is not in the outline) and the per-file
  `kMaxSymbolsCap`=1000 / `kMaxLineBytes`=1024 caps
  (`src/fileoutline.cpp:15-16`). A symbol the outline misses is a soft
  `found:false`, not a complete-table guarantee.
- `lane=` echoes the available lane names on an unknown lane (mirrors
  `subsystem`'s `unknown_lane` lane echo). `file_path=` returns the
  *indexed outline*, never the file's source bytes — for bytes use
  `read_region`.
- **Per-file outline cap (silent).** A `file_path=` or `lane=` body returns
  a file's stored `symbols[]`, which `FileOutline` already capped at 1000
  per file (§ 2.1); v1 carries **no** per-file overflow flag, so a
  ≥1000-symbol file's list is silently truncated (rare — far above any real
  file; a caller needing certainty uses `file_outline` on that path).
- **Response symbol cap.** A `lane=` answer drops trailing symbols past
  `maxQuerySymbols` with `symbols_truncated:true`; pinned (with its
  deterministic order and its split from `files_truncated`) by **INV-14**.
  `symbols_truncated` rides the shared meta block (§ 2.6) but is always
  `false` for summary / `symbol=` / `file_path=` bodies — only `lane=` can
  set it true.

### 2.5 Cache file (disk-only, derived, atomic)

`~/.cache/ants-terminal/codebase-index/<cwdHash(rootCanonical)>.json`
(`GenericCacheLocation` + `/ants-terminal/codebase-index`), reusing
`SessionMemoryEngine::cwdHash` (`src/sessionmemoryengine.h:41`) keyed on the
**canonical resolved root** so the key is stable under cwd spelling — the
`mcp-caches.md` never-shadow contract (a relocated project yields a new key
and the old cache goes cold, but the key never aliases two roots).

- **`kIndexVersion` gates schema *and* outline format.** Bump
  `kIndexVersion` whenever the cached shape (§ 2.1) **or** `FileOutline`'s
  symbol-output format changes, so an Ants upgrade that alters outline output
  invalidates every stale cache via the version-mismatch cold-build trigger
  (INV-13) rather than serving a pre-upgrade symbol table.
- **Not in-repo.** The roadmap bullet floated an in-repo `.ants_cache/`
  directory; **no such convention exists** — every Ants derived cache lives
  under `~/.cache/ants-terminal/` (`sessionmemoryengine.cpp:38-42`,
  `modelswitchledger.h:231`). This spec follows that and does **not** write
  into the managed repo (no `.gitignore` churn, no repo pollution).
- **Atomic write** via `QSaveFile` (write-full-or-fail → `commit()`), so a
  concurrent same-root reader never sees a torn file (INV-12).
- **Last-writer-wins is safe.** Two same-root sessions refreshing
  concurrently may clobber each other's cache write; unlike
  `session_memory` (which added `mutateLocked` to protect user keys) the
  codebase index is **purely derived** — a clobbered cache is rebuilt on
  the next query with no data loss. No cross-process lock (the shortest
  correct design — a lock would guard derived, rebuildable bytes).
- **Concurrent cold build is duplicated, not unsafe.** Two same-root
  sessions that both find the cache absent each run a full cold build (up
  to `kMaxIndexFiles` `FileOutline` passes) — duplicated CPU, accepted as a
  rare one-time cost (the build is lazy + cheap and a lock for derived bytes
  is not worth the complexity); the writes still land atomically.
- **No RcGate.** Like the other read tools, `codebase_index` is project
  read anchored by `caller_cwd`; its only write is this derived cache under
  `~/.cache`, not a project file and not the tenant-hashed
  `mcp-state` store, so it does not route through RcGate.

### 2.6 Output envelope & standard contracts

Every response carries a meta block:

```json
{ "ok": true,
  "generated_at_ms": 1780000000000, // last build/refresh write; preserved verbatim on a fully-warm no-write query
  "file_count": 287,
  "refreshed_files": 0,        // files re-outlined on THIS call (0 = fully warm)
  "cache_path": "/home/…/codebase-index/<hash>.json",
  "files_truncated": false,    // INV-11 — build file-count ceiling hit
  "symbols_truncated": false,  // INV-14 — lane= query symbol cap hit
  "etag": "<payload sha256 — injected by the dispatcher, not the handler>"
  /* + the selector-specific body from § 2.4 */ }
```

Assembled no-selector summary (meta + summary body):

```json
{ "ok": true, "generated_at_ms": 1780000000000, "file_count": 287,
  "refreshed_files": 0, "cache_path": "/home/…/<hash>.json",
  "files_truncated": false, "symbols_truncated": false, "etag": "…",
  "lane_count": 41, "lanes": [{"lane":"testauditengine","file_count":2}, …],
  "languages": {"cpp": 283, "py": 4}, "roles": {"impl": 140, "header": 130, "test": 17} }
```

(`languages` and `roles` each sum to `file_count` — every indexed file has
exactly one language and one role.)

These are the **standard read-tool contracts** per
`docs/standards/mcp-tools.md` (the umbrella checklist all read tools share);
listed here only for the `codebase_index`-specific wiring sites:

- **caller_cwd: Required** (`callerCwdContractFor`). Empty `caller_cwd` →
  `code:"caller_cwd_required"` before the handler runs (ANTS-1404). A
  non-empty but non-resolving `caller_cwd` yields an empty `rootCanonical`
  from `resolveRootCanonical`, which the handler maps to `code:"bad_path"`
  ("no focused project").
- **Path validation.** A `file_path` arg routes through
  `PathValidation::validatePath(rawPath, rootCanonical, "codebase_index",
  "file_path", /*allowOutsideRoot=*/false)` (`src/pathvalidation.h`); a
  malformed path or one canonicalising outside the root → `code:"bad_path"`.
  (`symbol`/`lane` are not path-typed.)
- **ETag-304 (ANTS-1499).** Wiring: add `codebase_index` to
  `isEtagSupportedTool` (`src/claudeintegration.cpp`) + a
  `makeEtagMatchProp()` line on the schema; the handler emits no `etag`
  (the dispatcher hashes the whole payload and injects it). The
  warm-stability argument (the § 1 "free re-read" relies on it, given the
  hash covers the volatile `refreshed_files` / `generated_at_ms` meta) lives
  in **INV-9** — not restated here.
- **fields projection (ANTS-1720).** Add `codebase_index` to
  `mcp::isFieldProjectionTool` (`src/mcpprojection.cpp`) + register
  `props["fields"] = makeFieldsProp()`. `fields` narrows whichever body is
  present (summary or a selector body); list `"etag"` to keep 304.
- Auto-wrapped in `<ants_mcp_data tool="codebase_index">` (not control-plane).

## 3. Invariants

- **INV-1** — A cold `build` walks `<root>/src` + `<root>/tests` (an absent
  subtree skipped silently), runs one `FileOutline::compute` per source
  file, and produces `files[]` of `{path, language, role, lane, lines,
  mtimeMs, symbols[]}` plus `laneToFiles`; a root with no source files →
  `file_count:0`, an `ok:true` empty summary (not a refusal). *Test:*
  `build` over a fixture tree (assert a known file's entry shape + a known
  symbol) and over a root with no `src/`/`tests/` (assert `file_count:0`,
  `ok:true`).
- **INV-2** — `refresh` re-outlines only files whose mtime changed or that
  were added, drops removed files (from `files[]` **and** every
  `laneToFiles[]` list), reuses `prev`'s symbols for untouched files, and
  assigns an added file its computed lane (§ 2.2); `refreshedOut` equals the
  changed+added count. *Test:* build, then in one `refresh`: bump one file's
  mtime (re-outlined), delete a second (gone from `files[]` *and* its lane's
  `laneToFiles` list), add a third matching a lane prefix (present with its
  lane) → `refreshedOut==2` (changed+added), the untouched files unchanged.
- **INV-3** — Staleness includes the lane-map source mtime: editing
  `docs/subsystems.md` (or CLAUDE.md when unmigrated) re-derives
  `laneToFiles` on the next query even when no `src` file changed. *Test:*
  build, rewrite the fixture map source's lane bullet, `staleFiles` reports
  `mapSourceChanged`, `refresh` reflects the new lane mapping with
  `refreshedOut==0` (a map-source-only change re-outlines no files).
- **INV-4** — At most one of `{symbol, lane, file_path}`; two or more →

  invariant — a purely derived cache has no user data to lose.)
- **INV-13** — A cache whose bytes do not parse as JSON, whose `version` ≠
  `kIndexVersion`, or whose `rootCanonical` ≠ the resolved root is
  discarded and rebuilt (never served stale, corrupt, or cross-root). The
  `rootCanonical` body-check is belt-and-suspenders: the `cwdHash(root)` key
  contract (§ 2.5) makes a cross-root hit unreachable in practice, but the
  check catches a `cwdHash` collision if one ever occurred. *Test:* seed

  `Options{maxQuerySymbols:1}` over a lane with ≥2 symbols across 2 files →
  `symbols_truncated:true`, and the surviving symbol is the first in the
  sorted-file / outline order (asserts *which*, not just the count).
- **INV-15** — Build byte ceiling (the binding RAM bound): a build stops
  adding files once the serialised index would exceed `maxCacheBytes`,
  setting `files_truncated:true`, so neither the on-disk cache nor the
  per-query parse exceeds the ceiling regardless of file/symbol counts. The
  walk uses the **same deterministic order as INV-11** (`src/` sorted, then
  `tests/` sorted), so *which* files survive a byte-cut is reproducible.
  (INV-15/INV-16 split late from earlier invariants — kept at the list end
  per the never-renumber rule.) *Test:* a tiny-`maxCacheBytes` `Options`
  over an ordered multi-file fixture → `files_truncated:true`, the
  serialised cache ≤ the cap, and the surviving files are the
  deterministic-order prefix (asserts *which*, not just ≤).
- **INV-16** — Summary count integrity: the summary's `roles{}` and
  `languages{}` each sum to `file_count`, and `sum(lanes[].file_count)` ≤
  `file_count` (a file is in at most one lane; the `""` lane is excluded).
  *Test:* a multi-lane fixture asserts both sums equal `file_count` and the
  lane-total does not exceed it.

## 4. RAM / build cost

No persistent in-process state and no in-process MRU cache (v1 loads the
disk cache per query, refreshes, serves, frees) — so there is no eviction
policy to maintain. Peak heap during a query ≈ the parsed cache plus one
file's `FileOutline` pass at a time (itself bounded by `kMaxLineBytes`=1024
/ `kMaxSymbolsCap`=1000), freed when the call returns. The disk cache **and**
the per-query parse share **one hard ceiling**, `kMaxCacheBytes` = 16 MiB:
the build stops adding files once the serialised index would exceed it
(`files_truncated`, INV-15), so neither can exceed 16 MiB however
pathological the tree — this is the binding RAM bound. A naive
`kMaxIndexFiles`×`kMaxSymbolsCap`×bytes product would reach gigabytes, which
is exactly why the byte ceiling, not the file count, is the cap that
satisfies the no-unbounded-growth rule. `kMaxIndexFiles`=5000 is the
secondary guard bounding the *number* of `FileOutline` passes. At this
repo's scale the index is far below the ceiling: 621 files × ~30
symbols/file × ~120 B/serialised symbol (name+line+kind, no `signature`) ≈
2 MB — two orders below the 16 MiB ceiling. No new external library. Helper
in `ants_core_lib`
(`src/codebaseindex.{h,cpp}`); schema in the existing `ants_claude_lib`.

Cost model (derived, not wall-clock-measured — no fake-precision figure is
asserted): a cold build runs **one `FileOutline::compute` per source file**,
bounded by `kMaxIndexFiles` passes — one-time, and reused from the disk
cache across Ants restarts, so a true cold build is rare. A warm query (no
`src` change) is *one `stat` per indexed file + one JSON parse of the cache
+ serve* — zero outline passes; an ETag-304 match additionally skips
re-emitting the body. The warm path is "walk + stat + parse + serve", not
zero work. The cold build's dominant cost is one `FileOutline` regex pass
per admitted line, bounded by `kMaxIndexFiles` files × `kMaxSymbolsCap`
symbols — CPU on line count, not I/O on file count.

## 5. Out of scope

- **`tests_for_symbol` reverse map** — the roadmap's best-effort
  "grep tests for symbol calls" map. Expensive (a full tests/ content scan)
  for little token saving; deferred to a follow-up ANTS id if a session
  actually wants it.
- **Background warm-keeping / git-HEAD invalidation watcher** — lazy build
  was chosen (§ 2.3); per-file mtime + map-source mtime already catch a
  checkout's changed files. Deferred.
- **`topic=` selector** — `find_sources` (ANTS-1636) already does
  content-aware topic→files scoring; `codebase_index` stores symbols +
  paths but **not file content**, so a topic search over it would be
  strictly weaker. Not duplicated here (reuse-before-rewriting). A future
  `find_sources` can consume this index as its front-end (ANTS-1636 noted
  it as the "natural front-end consumer").
- **In-process MRU index cache** — a latency optimisation (skips the ~MB
  JSON parse on a repeat query); deferred until a measured need.
- **`current_state` aggregator slot** (ANTS-1569 `codebase_index_meta`) —
  composes later; not built here.
- **A second `codebase_index_meta` verb** — the meta block rides in every
  `codebase_index` envelope (§ 2.6); one verb, not two.
- **Sub-second mtime content detection** — staleness is `mtimeMs`-only by
  design (INV-2); a content edit that preserves or coarsely rounds the mtime
  is not detected until the next mtime-changing write. A content-hash
  fallback is deferred (the mtime path matches the rest of Ants' caches —
  `subsystemmap`, roadmap-query).

   not v1).

   not a whole-build refusal — `src/` before `tests/`, each sorted (INV-11),
