# ANTS-1894 — Near-miss telemetry: log gate-hit-but-blocked decisions

**Status:** spec draft, cold-eyes loops 1 + 2 + 3 + 4 + 5 folded (2026-05-27).
**Kind:** implement.
**Source:** ROADMAP.md ANTS-1894 (in-session-2026-05-26 — ANTS-1891
brainstorm; diagnostic gap surfaced once the trust-signal v2 headline
read "auto-switch ON (floor=haiku) in this project: no switches yet"
with no way to tell *why* no switch had fired).

**Layman:** When the auto-model-switcher decides NOT to switch, Ants
now writes down why; the end-of-session summary tells you something
like "switcher held back 42 times today, mostly because you were
typing in the composer" instead of "no switches yet" with no
explanation.

**Pairs with:** ANTS-1891 (trust signal v2 — once near-miss is recorded,
"insufficient data" can be qualified as "0 firings but 47 near-misses
dominated by composer_not_empty" instead of an opaque silence).
**Composes with:** ANTS-1735 §2.3 (the gate this spec instruments) and
the ANTS-1735 ledger contract (this spec adds a *sibling* ledger, not
a change to the existing one).
**Blocker for:** ANTS-1895 (dry-run mode reuses this spec's emit /
throttle / stats infrastructure to record `would_have_switched`
records); ANTS-1896 (recommender confidence calibration uses the
near-miss + dry-run distributions to pick a confidence floor). The
dependency-driven sequencing 1894 → 1895 → 1893 → 1896 was agreed
in-session.

## 1. Problem

The auto-switcher's decide gate
(`src/modelautoswitch.cpp` `decide`, L14–36) short-circuits at the
first failing guard and returns an empty `Decision`. The controller
(`src/claudestatuswidgets.cpp` L1417–1418) silently drops the result.
Nothing is recorded when a switch was *almost* fired but blocked.

On 2026-05-26 the live ledger for
`/mnt/Games/Scripts/Linux/Ants_Terminal` held 0 firing records
(`model_switch_stats` headline: `"in this project: no switches yet"`).
A user asking "why doesn't the auto-switcher fire in this project?"
cannot today distinguish four very different states:

1. The recommender silently agrees with the current tier on every
   tick — the switcher would have done nothing anyway, regardless of
   guards. The "feature dormant because the recommender approves of
   the current tier" case.
2. The recommender disagrees, but the user is always typing in the
   composer (`composerEmpty=false`) — every tick the switcher hits the
   gate, wants to switch, but is blocked by INV-3.
3. The recommender disagrees, the composer is idle, but the dwell
   floor (default 90 s, configurable to 1800 s) is never met because
   the user closes the tab inside 90 s.
4. The recommender disagrees, every other guard passes, but the
   per-project override cool-down (ANTS-1890, 10 min) has been active
   since an earlier override.

Each of (1)–(4) wants a different remedy (lower the recommender's
confidence floor; relax the composer guard; lower min-dwell; tune the
override cool-down). With no observable record of "gate evaluated,
declined to fire, here is why," neither the user nor a future change
can pick the right remedy.

The diagnostic question repeats at every brainstorm of the autoswitch
lane — ANTS-1891 §1 problem (d), ANTS-1893's "I haven't seen it
change once since the implementation" framing, and the ANTS-1896
confidence-threshold calibration all need this data. Without near-miss
telemetry every further calibration is a guess.

## 2. Surface

Four concerns. Pure-infra: no new external libraries, no MCP tool
additions (one new mode on an existing tool), no schema break for the
firing ledger, no behavioural change to the firing-side path.

### 2.1 `ModelAutoSwitch::decide` — evaluate-all refactor

Today `decide()` short-circuits on the first failing guard (`return d`
at lines 16, 17, 18, 24, 25, 26, and 30–31 — the last guard is the
ANTS-1890 override cool-down whose `if` wraps across two source
lines, with the `return d` landing on L31). For near-miss telemetry the
caller needs **the full list of guards that would have blocked the
switch on this tick**, not just the first one. Refactor `decide()` to
evaluate every guard and accumulate blocker reasons into a list. The
"would have fired" path is unchanged bit-for-bit — when the
accumulated list is empty, `act=true` and `tierArg` is computed
exactly as today.

Extend `Decision` (`src/modelautoswitch.h` L41–44):

```cpp
struct Decision {
    bool        act = false;
    QString     tierArg;          // unchanged
    QStringList blockedBy;        // NEW — populated when act=false (see § 2.2)
    ModelRecommender::Tier currentTier     = ModelRecommender::Tier::Sonnet;
    ModelRecommender::Tier recommendedTier = ModelRecommender::Tier::Sonnet;
};
```

`currentTier` echoes `gate.current`; `recommendedTier` is the
*clamped* target (`clampToFloor(gate.recommended, gate.floor)`) so the
caller doesn't recompute. Both are set on every call regardless of
`act` (the near-miss record needs them whether or not the switch
fired).

Replace the body of `decide()` (`src/modelautoswitch.cpp` L14–36)
with the evaluate-all form:

```cpp
Decision decide(const Gate &g) {
    Decision d;
    d.currentTier = g.current;
    const ModelRecommender::Tier target = clampToFloor(g.recommended, g.floor);
    d.recommendedTier = target;

    if (!g.enabled)                          d.blockedBy << QStringLiteral("auto_switch_disabled");
    if (g.focusedState != ClaudeState::Idle) d.blockedBy << QStringLiteral("focused_state_not_idle");
    if (!g.composerEmpty)                    d.blockedBy << QStringLiteral("composer_not_empty");
    if (target == g.current)                 d.blockedBy << QStringLiteral("target_equals_current");
    if (g.ticksTargetStable < kStableTicks)  d.blockedBy << QStringLiteral("ticks_target_stable_insufficient");
    if (g.msSinceLastSwitch < effectiveMinDwellMs(g))
                                             d.blockedBy << QStringLiteral("dwell_time_insufficient");
    if (g.msSinceLastOverride >= 0
            && g.msSinceLastOverride < kOverrideCooldownMs)
                                             d.blockedBy << QStringLiteral("override_cooldown_active");

    if (d.blockedBy.isEmpty()) {
        d.act     = true;
        d.tierArg = ModelRecommender::tierName(target);
    }
    return d;
}
```

Where `effectiveMinDwellMs(g) = std::max(kMinDwellMs, g.configuredMinDwellMs)`
is a file-static helper inside `modelautoswitch.cpp` that folds in the
configurable min-dwell floor the controller pre-checks today (see
§ 2.2). The 7 blocker tokens are the canonical taxonomy — see INV-9
for the stability contract.

`Decision`'s `tierArg` stays empty (the existing default) when
`act=false` — no caller reads `tierArg` on a non-acting decision, and
keeping it empty makes the near-miss record's "would have switched
to" derive solely from `recommendedTier` (a tier enum), not a string
that might mismatch `tierName(recommendedTier)`.

### 2.2 `ModelAutoSwitch::Gate` — `configuredMinDwellMs`

Add one field to `Gate` (`src/modelautoswitch.h` L25–39, slotting
alongside `msSinceLastSwitch`):

```cpp
qint64 configuredMinDwellMs = kMinDwellMs;   // NEW — per-config dwell floor;
                                             // slot between msSinceLastSwitch
                                             // (currently L33) and
                                             // msSinceLastOverride (currently
                                             // L38) so it reads as a
                                             // dwell-family field.
```

Default value `kMinDwellMs` (90 s) means a v1 caller that constructs

**drop** the pre-decide short-circuit at L1415 so the new gate-level
check is reached.

### 2.3 `modelnearmissledger.{h,cpp}` — new module

New TU pair in **`ants_core_lib`** — placed alongside
`modelswitchledger.cpp` (`CMakeLists.txt` L230 SRC list), parallel to
the firing ledger and reachable from `RemoteControl::cmdModelSwitchStats`
(also in `ants_core_lib`) without cross-lib calls. The producer side
(`maybeEmitNearMiss` on `ClaudeStatusBarController` in
`ants_claude_lib`) calls across libs the same way it already does for
`ModelSwitchLedger::appendRecord`. Mirrors the existing
`modelswitchledger` writer + reader pattern.

**File layout:**

```
src/modelnearmissledger.h         — public API
src/modelnearmissledger.cpp       — Record, append, evict, parse, stats
```

**Record struct** (`src/modelnearmissledger.h`):

```cpp
struct Record {
    QString     ts;                  // ISO-8601 UTC, second precision
                                     // ("2026-05-27T09:30:00Z") via the
                                     // reused ModelSwitchLedger::nowIso8601()
                                     // helper — Qt::ISODate format.
    QString     sessionId;           // ClaudeIntegration::lastHookSessionId() or ""
    QString     project;             // focused tab shellCwd()
    QString     currentTier;         // "haiku" | "sonnet" | "opus"
    QString     recommendedTier;     // "haiku" | "sonnet" | "opus" (clamped)
    QStringList blockedBy;           // ordered subset of the 7 taxonomy tokens
    // Gate snapshot — small ints/bools, no nested objects, for cheap JSON.
    bool        composerEmpty   = true;
    QString     focusedState;        // ClaudeState as lowercase snake_case
                                     // ("not_running"|"idle"|"thinking"|"tool_use"|"compacting")
    int         ticksTargetStable = 0;
    qint64      dwellMs           = 0;
    qint64      msSinceLastOverride = -1;
};
```

**JSON shape** (one line per record, `QJsonDocument::Compact`):

```json
{"ts":"2026-05-27T09:30:00Z","session_id":"abc123","project":"/path/to/proj",
 "current_tier":"opus","recommended_tier":"haiku","blocked_by":["composer_not_empty","dwell_time_insufficient"],
 "composer_empty":false,"focused_state":"thinking","ticks_target_stable":1,
 "dwell_ms":45000,"ms_since_last_override":-1}
```

snake_case JSON keys match the existing firing-ledger key style.

**Public API** (`src/modelnearmissledger.h`):

```cpp
namespace ModelNearMissLedger {

constexpr qint64 kMaxLedgerBytes = 256 * 1024;   // matches firing ledger
constexpr qint64 kStatsWindowMs  = 24 * 60 * 60 * 1000;   // 24 h cutoff used
                                                          //   by statsSlim /
                                                          //   statsFull

struct Record { /* as above */ };

QString defaultLedgerPath();        // ~/.cache/ants-terminal/model-switch-nearmiss.jsonl
QJsonObject toJson(const Record &r);
Record      fromJson(const QJsonObject &o);   // missing fields → struct defaults (INV-13)

bool appendRecord(const QString &ledgerPath, const Record &r);
QList<Record> readRecords(const QString &ledgerPath);

// Aggregation. Returns the slim near_misses block that
// model_switch_stats folds into its default envelope (§ 2.5).
struct StatsSlim {
    int     total24h        = 0;
    QString dominantBlocker;        // "" when total24h == 0
};
StatsSlim statsSlim(const QList<Record> &recs,
                    const QString       &projectScope,   // "" for global
                    qint64               nowMs);

// Full breakdown — returned when model_switch_stats is called with
// mode:"near_misses" (§ 2.5).
QJsonObject statsFull(const QList<Record> &recs,
                      const QString       &projectScope,
                      qint64               nowMs);

}  // namespace ModelNearMissLedger
```

**Eviction.** Mirrors `ModelSwitchLedger::evictToCap`
(`src/modelswitchledger.cpp` L109–126) — drop whole oldest lines
until total ≤ `kMaxLedgerBytes`. **No pending-pinning**: near-miss
records have no outcome backfill, so the firing-ledger's
`isPendingLine` skip is omitted and every line is fair game. The
newest line is never dropped (matches the firing ledger's
`lines.size() > 1` guard — keeps the file non-empty on a degenerate
over-cap append).

**File perms.** `setOwnerOnlyPerms` (0600), same as the firing ledger.

**Timestamp helpers.** `ModelNearMissLedger` reuses the firing-
ledger helpers `ModelSwitchLedger::nowIso8601()`
(`src/modelswitchledger.cpp:499–501`, second-precision Qt::ISODate)
on the write side and `ModelSwitchLedger::parseIso8601Ms()`
(`src/modelswitchledger.cpp:503–507`) on the stats / window-filter
side — no parallel helper, no format divergence between the two
ledgers.

**`statsSlim` algorithm:**

```
filter recs to (nowMs - parseIso8601Ms(ts) <= kStatsWindowMs) AND (projectScope == "" OR project == projectScope)
total24h = size of filtered list
dominantBlocker = the blocker token with the highest occurrence count
                  across all filtered records' blocked_by arrays
                  (ties broken by taxonomy order; "" if total24h == 0)
```

A record contributes one count per *distinct* token it carries (a
record with `["composer_not_empty", "dwell_time_insufficient"]`
contributes +1 to each of those two counters). This matches the
"why did the switcher hold back this minute" semantics — a tick can
be blocked for multiple reasons and each should be visible.

**`statsFull` envelope:**

```json
{
  "ok": true,
  "mode": "near_misses",
  "scope": "project",
  "window_24h": {
    "total": 42,
    "by_blocked_by": {
      "composer_not_empty": 31,
      "target_equals_current": 9,
      "dwell_time_insufficient": 2
    },
    "dominant_blocker": "composer_not_empty",
    "distinct_signatures": 5
  },
  "all_time": {
    "total": 187,
    "by_blocked_by": { /* … */ },
    "distinct_signatures": 12
  },
  "headline": "42 near-misses in last 24 h, dominated by composer_not_empty (74%)"
}
```

`distinct_signatures` is the count of distinct `blocked_by` arrays
seen (after sorting tokens within each array) — diagnostic value for
"the recommender's blockage shape is consistent across the window"
vs "it's hitting many different walls."

### 2.5 `maybeEmitNearMiss` — emit-on-change rule

New private method on `ClaudeStatusBarController`:

```cpp
void ClaudeStatusBarController::maybeEmitNearMiss(
        const ModelAutoSwitch::Decision &dec,
        const ModelAutoSwitch::Gate     &gate,
        const QString                   &projectRoot,
        qint64                           nowMs)
{
    if (dec.blockedBy.isEmpty()) return;  // defensive — act must be false
    if (projectRoot.isEmpty())   return;  // can't key the throttle

    // Sort tokens for a stable, order-independent signature comparison.
    // The emitted record preserves the original order so the diagnostic
    // chain ("typing AND past cool-down") reads in evaluation order.
    QStringList sig = dec.blockedBy;
    std::sort(sig.begin(), sig.end());

    const QStringList &lastSig = m_nearMissLastSigByProject.value(projectRoot);
    const qint64       lastMs  = m_nearMissLastEmitMsByProject.value(projectRoot, 0);

    if (sig == lastSig) return;                          // INV-5 — same shape, skip
    if (nowMs - lastMs < kNearMissEmitFloorMs) return;  // INV-6 — 5 s floor

    ModelNearMissLedger::Record r;
    r.ts                  = ModelSwitchLedger::nowIso8601();
    // `m_integration` is the existing `ClaudeIntegration *` member on
    // ClaudeStatusBarController (declared in claudestatuswidgets.h).
    r.sessionId           = m_integration ? m_integration->lastHookSessionId() : QString();
    r.project             = projectRoot;
    r.currentTier         = ModelRecommender::tierName(dec.currentTier);
    r.recommendedTier     = ModelRecommender::tierName(dec.recommendedTier);
    r.blockedBy           = dec.blockedBy;       // original order, not sorted
    r.composerEmpty       = gate.composerEmpty;
    r.focusedState        = claudeStateName(gate.focusedState);
    r.ticksTargetStable   = gate.ticksTargetStable;
    r.dwellMs             = gate.msSinceLastSwitch;
    r.msSinceLastOverride = gate.msSinceLastOverride;

    ModelNearMissLedger::appendRecord(
        ModelNearMissLedger::defaultLedgerPath(), r);

    m_nearMissLastSigByProject[projectRoot]    = sig;
    m_nearMissLastEmitMsByProject[projectRoot] = nowMs;
}
```

Constant declared in `src/claudestatuswidgets.h`:

```cpp
static constexpr qint64 kNearMissEmitFloorMs = 5 * 1000;   // 5 s per project
```

`claudeStateName(ClaudeState)` is a **new** file-static helper added
in `src/claudestatuswidgets.cpp` (no equivalent exists today — grep
confirms `claudestateresolver.cpp:34`'s switch maps to
`Display::Idle`-style glyph enums, a different domain). The new
helper is a 5-case switch over the enum at `src/claudeintegration.h`
L47–53, returning lowercase snake_case: `ClaudeState::NotRunning →
"not_running"`, `Idle → "idle"`, `Thinking → "thinking"`,
`ToolUse → "tool_use"`, `Compacting → "compacting"`.

### 2.6 `model_switch_stats` — slim block + `mode:"near_misses"` arm

Update `src/remotecontrol.cpp` `cmdModelSwitchStats` (L7553):

3. The tool descriptor in `src/claudeintegration.cpp` (the
   `model_switch_stats` entry — the descriptor block runs from
   ~L2152 to the `tools.append(t);` at L2225) gains:

   - Schema: `mode` enum `["firings","near_misses"]`, default
     `"firings"`. Slots into the existing `props` object alongside
     `caller_cwd` / `etag_match` / `fields` / `scope`. Per
     `docs/standards/mcp-tools.md` § 10 schema-hygiene checklist:
     (a) `additionalProperties:false` on the inputSchema continues
     to hold (additive `props` entry); (b) `mode` is **NOT** added

     the firing envelope with a slim near-miss block; `\"near_misses\"`

   - Description: appended sentence — "ANTS-1894 — envelope

4. **`fields=` projection (ANTS-1720)** composes — a caller passing

   `feedback_model_switch_stats_each_session.md`).

5. **ETag** — the envelope's ETag computation already covers all
   top-level fields. Adding `near_misses` to the body naturally bumps
   the ETag whenever the near-miss ledger changes. No special

## 3. Invariants

- **INV-1** — `decide()` returns `act=true` if and only if
  `blockedBy.isEmpty()`. When `act=true`, `tierArg` equals
  `ModelRecommender::tierName(recommendedTier)` (where
  `recommendedTier` is the *clamped* target per INV-4 — preserves
  ANTS-1735 INV-7's contract that `tierArg` derives from
  `clampToFloor(recommended, floor)` and nothing else). Any gate
  state that fired a switch pre-1894 still fires now. *Test:*
  `tests/features/model_near_miss_ledger/test_decide_act_iff_unblocked.cpp`.
- **INV-2** — For each of the 7 guards in § 2.1, `decide()` appends
  the canonical blocker token to `blockedBy` when (and only when) the
  guard fails. A gate that fails N guards produces a `blockedBy` list
  of length N with tokens in the evaluation order shown in § 2.1
  (`auto_switch_disabled` first; `override_cooldown_active` last).
  *Test:*
  `tests/features/model_near_miss_ledger/test_decide_all_blockers.cpp`
  (table-driven over a representative subset of the 2^7 guard
  combinations; verifies token order matches evaluation order).
- **INV-3** — `effectiveMinDwellMs(g)` equals
  `std::max(kMinDwellMs, g.configuredMinDwellMs)`. A `Gate` with
  `configuredMinDwellMs = 0` (degenerate input) still respects the
  hard 90 s floor. A `Gate` with `configuredMinDwellMs = 300_000`
  (5 min) requires 5 min of dwell. *Test:*
  `tests/features/model_near_miss_ledger/test_effective_min_dwell.cpp`.
- **INV-4** — `Decision.currentTier` and `Decision.recommendedTier`
  are set on every `decide()` call regardless of `act`.
  `recommendedTier` is the *clamped* target
  (`clampToFloor(g.recommended, g.floor)`), not the raw
  `g.recommended`. *Test:*
  `tests/features/model_near_miss_ledger/test_decision_tiers_always_set.cpp`.
- **INV-5** — `maybeEmitNearMiss` writes a record iff
  `sort(dec.blockedBy) != sort(m_nearMissLastSigByProject[project])`.
  Two consecutive ticks with the same (post-sort) signature produce
  exactly one record. The signature is order-independent; the
  *recorded* `blocked_by` field preserves evaluation order. *Test:*
  `tests/features/model_near_miss_ledger/test_emit_on_sig_change.cpp`.
- **INV-6** — `maybeEmitNearMiss` skips emission when
  `nowMs - m_nearMissLastEmitMsByProject[project] < kNearMissEmitFloorMs`
  (5 s). A second signature transition inside the floor is dropped —
  not deferred, not queued — and the throttle state is NOT updated
  (so a third transition past the floor still fires, regardless of
  whether the second was suppressed). *Test:*
  `tests/features/model_near_miss_ledger/test_emit_floor_throttle.cpp`.
- **INV-7** — The on-disk file at
  `ModelNearMissLedger::defaultLedgerPath()` resolves to
  `~/.cache/ants-terminal/model-switch-nearmiss.jsonl` (XDG_CACHE_HOME
  honoured), is created with mode 0600, and is one JSON-per-line
  (no array wrapper, no comments, no leading/trailing whitespace).
  *Test:*
  `tests/features/model_near_miss_ledger/test_ledger_file_shape.cpp`.
- **INV-8** — `appendRecord` after a write that would exceed
  `kMaxLedgerBytes` (256 KiB) evicts whole oldest lines until ≤ cap;
  the newest line is never dropped. No mid-line truncation. (Mirrors
  ANTS-1735 ledger INV-10; no pending-pinning — every line is fair
  game.) *Test:*
  `tests/features/model_near_miss_ledger/test_evict_to_cap.cpp`.
- **INV-9** — The 7 blocker tokens (`auto_switch_disabled`,
  `focused_state_not_idle`, `composer_not_empty`,
  `target_equals_current`, `ticks_target_stable_insufficient`,
  `dwell_time_insufficient`, `override_cooldown_active`) are the
  v1 taxonomy. They are stable handles — never renamed or
  renumbered once written to disk. Adding a new token requires a
  superseding spec and is gated on the same compatibility rule as
  invariant ids (`docs/standards/specs.md` § 5.5 *Invariant
  immutability*). *Test:* source-grep —
  `tests/features/model_near_miss_ledger/test_blocker_taxonomy.cpp`
  greps `modelautoswitch.cpp` for the literal alternation
  `"auto_switch_disabled|focused_state_not_idle|composer_not_empty|target_equals_current|ticks_target_stable_insufficient|dwell_time_insufficient|override_cooldown_active"`
  and asserts exactly 7 distinct token-string-literals appear.
- **INV-10** — `statsSlim`'s `dominantBlocker` is the token with the
  highest *occurrence* count across the 24 h window's filtered
  records (where each record contributes one count per distinct
  token in its `blocked_by` array). Ties broken by taxonomy order
  (INV-9). `total24h == 0` ⇒ `dominantBlocker == ""`. *Test:*
  `tests/features/model_near_miss_ledger/test_stats_slim_dominant.cpp`.
- **INV-11** — `statsFull`'s `window_24h.total` equals the count of
  records whose `ts` is within 24 h of `nowMs` and (when
  `projectScope` is non-empty) whose `project` matches. `all_time`
  has no window filter. `distinct_signatures` counts distinct
  *post-sort* `blocked_by` arrays. *Test:*
  `tests/features/model_near_miss_ledger/test_stats_full_windows.cpp`.
- **INV-12** — The default `model_switch_stats` envelope
  (`mode:"firings"`, the default) carries a slim `near_misses` key
  (`{total_24h, dominant_blocker}`) alongside every existing firing
  field, **including the ANTS-1889 config triple**
  (`auto_model_switch_enabled`, `floor_tier`, `min_dwell_sec`) and
  the `scope` echo. The `mode:"near_misses"` envelope replaces the
  firing fields with the full near-miss breakdown (§ 2.3 `statsFull`
  shape) but preserves the config triple + `scope` echo so a caller
  in this mode can still distinguish "feature OFF" from "ON". An
  unknown `mode` value returns refusal envelope
  `{ok:false, code:"bad_mode"}` (canonical taxonomy entry under
  `docs/standards/mcp-error-codes.md` § "Input validation").
  *Test:*
  `tests/features/mcp_model_switch_stats_near_misses/test_mode_arm.cpp`.
- **INV-13** — `fromJson` of a near-miss Record JSON missing any
  optional field (e.g. `ms_since_last_override`) returns a Record
  with that field defaulted (`-1` for `msSinceLastOverride`, `0` for
  `dwellMs`/`ticksTargetStable`, `true` for `composerEmpty`, etc.) —
  matching the struct defaults. Idempotent re-serialisation:
  `toJson(fromJson(toJson(r)))` equals `toJson(r)` for any
  well-formed Record. Legacy JSON missing optional keys round-trips
  to the **canonical form** (the writer always emits every key);
  this means `fromJson(toJson(r)) == r` holds for any Record produced
  by `toJson`, but does NOT hold for legacy partial JSON
  hand-crafted to omit fields — that's the by-design back-compat
  path mirroring ANTS-1891 INV-10. *Test:*
  `tests/features/model_near_miss_ledger/test_json_roundtrip.cpp`.

## 4. RAM / build cost

- **Disk:** 256 KiB cap on
  `~/.cache/ants-terminal/model-switch-nearmiss.jsonl`. Per-record
  size ≈ 250–350 bytes (JSON), so ~750–1000 records at cap. With
  emit-on-sig-change throttling (§ 2.5), typical 24 h emission is
  10–50 records per active project; cap pressure is rare except on a
  project that flickers many distinct signatures rapidly.
- **RAM (per process):** two `QHash<QString, …>` on the controller —
  `m_nearMissLastSigByProject` and `m_nearMissLastEmitMsByProject`.
  One entry per project seen this process. Per-entry footprint
  ~120 bytes (QString key + small value); 10 active projects =
  ~1.2 KiB. **Eviction policy:** none required (process-lifetime
  cache; rebuilt from disk-less state on relaunch). Bounded by the
  number of distinct `shellCwd()` values a session encounters.
- **CPU per tick:** `decide()` now evaluates all 7 guards instead of
  short-circuiting. Each guard is a cheap boolean — a single
  comparison or a struct-field read. Worst case adds ~6 boolean
  evaluations per tick to the existing 1; at the 2 s tick rate this
  is < 1 µs per tick on any plausible hardware. Below measurement
  noise; no benchmark needed.
- **I/O per tick:** zero on stable signatures (the dominant case).
  Writes only on signature transitions past the 5 s floor — typical
  rate well under 1/minute per project.
- **Build cost:** one new TU pair in `ants_core_lib`
  (`modelnearmissledger.{h,cpp}`), ~250 lines total (mirrors
  `modelswitchledger`'s shape but smaller — no outcome backfill, no
  settlement clauses). Test files split across two existing bundles
  per the no-new-exe convention (ANTS-1217), based on which lib each
  test exercises:
  - `test_core` (`ants_core_lib` only) gets 10 pure ledger/decide
    tests + 1 MCP test (11 total):
    `test_decide_act_iff_unblocked.cpp`,
    `test_decide_all_blockers.cpp`, `test_effective_min_dwell.cpp`,
    `test_decision_tiers_always_set.cpp`,
    `test_ledger_file_shape.cpp`, `test_evict_to_cap.cpp`,

    `test_stats_slim_dominant.cpp`, `test_stats_full_windows.cpp`,
    `test_json_roundtrip.cpp`, and the MCP-side
    `mcp_model_switch_stats_near_misses/test_mode_arm.cpp` (all
    behaviours exercised live in `ants_core_lib` or are pure / IPC).
  - `test_claude` (`ants_claude_lib` + `ants_core_lib`) gets 2

## 6. Migration / compatibility

- **No existing on-disk file** for near-miss — the file is created
  on first append. No legacy schema to read.
- **`Decision` struct gains two new fields + `blockedBy`.** No
  external out-of-tree consumer exists; in-tree the firing-side
  caller (`claudestatuswidgets.cpp` L1417) reads `dec.act` and
  `dec.tierArg` unchanged. The new fields are additive — every
  existing access still compiles.
- **`Gate` struct gains `configuredMinDwellMs`.** Default value
  `kMinDwellMs` preserves bit-for-bit pre-1894 behaviour for any
  caller that constructs a Gate without setting the field (the
  existing `test_model_auto_switch.cpp` tests, where applicable).
- **`decide()` body changes from short-circuit to evaluate-all.**
  Observable behaviour for the `act=true` path is unchanged; the
  test `test_decide_act_iff_unblocked.cpp` (INV-1) locks the
  equivalence. The `act=false` path now carries blocker reasons —
  observable but additive (every existing test that asserted
  `!dec.act` still passes; the new field is ignored unless read).
- **`model_switch_stats` envelope gains the `near_misses` key.**
  Additive. Existing readers ignoring unknown keys (the standard
  JSON-tolerance pattern; ANTS-1891 § 6 confirmed for the firing
  envelope) are unaffected. ETag bumps when the near-miss ledger
  changes.
- **`model_switch_stats` gains the `mode` arg.** Default is
  `"firings"`; absence of the arg behaves identically to today.
  `mode:"near_misses"` is a new shape (no firing fields); a v1
  caller that omits the arg never sees the new shape.

## 9. Open questions

- **OQ-1: 5 s per-project emit floor.** Picked to bound a flickering
  signature (e.g. composer typing pauses producing
  `[composer_not_empty]` → `[]` → `[composer_not_empty]` on
  successive ticks). Could legitimately be 2 s (matches the tick
  rate, tighter trace) or 10 s (coarser but more cap headroom). The
  constant is centralised (`kNearMissEmitFloorMs`) for easy
  adjustment. Re-tune if cap pressure on real-world ledgers
  warrants.
- **OQ-2: Slim block contents.** Today the slim block carries only
  `total_24h` + `dominant_blocker`. The end-of-session
  `model_switch_stats` summary call could benefit from a
  `recommender_silent_pct` field (the 24 h share of records whose
  *only* blocker is `target_equals_current`) — that's the
  "switcher is dormant because the recommender approves" signal.
  Holding off in v1 to keep the slim block truly slim; can be added
  in a follow-up without breaking INV-12.
- **OQ-3: Should `auto_switch_disabled` be elided from records?**
  The controller's L1349 `if (!enabled) return;` short-circuit
  means `decide()` is never called when the feature is off, so
  `auto_switch_disabled` records never appear in real ledger files
  via the production path. The token still exists in `decide()`'s
  taxonomy (and tests exercise it directly). The pure function and
  the producer-side path stay aligned without an extra suppression
  rule; the consequence is benign (no spurious "feature disabled"
  noise in real data). Decision: keep the token in the taxonomy for
  test/API symmetry, document the elision-in-practice here.
