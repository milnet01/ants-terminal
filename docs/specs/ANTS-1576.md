## 1. Problem

`last_audit_summary` is the token-frugal "what did the last audit
find?" surface — but three RetroArch bundles surfaced friction on
exactly the cases it should serve best:

- **Bundle 66.** Caller wanted to filter the top-findings to two
  specific cppcheck rules (`autoVariables`,
  `duplicateExpressionTernary`). The existing envelope had no
  `rule_ids[]` knob; caller fell back to two grep calls. **(Already
  shipped as [[ANTS-1540]] — pull 3, 2026-05-17. Verified here.)**
- **Bundle 67.** Two long-lived branches (`local/audit-2026-04` and
  `local/fixes-2026-04`) on the project. SARIF surfaced findings
  the user *thought* were fixed; turned out the audit ran on the
  branch that didn't have the fix commits. `last_audit_summary`
  surfaced no `branch:` / `commit:` for the cppcheck-XML and
  clang-tidy-text reports the project relies on — [[ANTS-1539]]'s
  reader-side scrape only fires on SARIF that carries
  `versionControlProvenance`. Ants's own SARIF writer
  (`auditrunner.cpp::writeSarif`) doesn't emit that block either,
  so the SARIF path is also blind.
- **Bundle 69.** Caller hit a `{counts: {error:0, warning:0}}`
  envelope and assumed the project was clean. The picked file was
  `.audit_cache/cppcheck-b68-ozone-postfix.xml` — a narrow
  single-file rerun on one source path. 25 other broader cppcheck
  XMLs lived in the same dir; the lex-max picker silently chose
  the wrong one because `-postfix` sorts later than ISO timestamps.

Cosmetic spin-off observed during the dispatch: the envelope emits
`run_at: ""` and `html_path: ""` when those fields are genuinely
absent. `null` (or omit) is the clearer signal — "always emit every
key as a string" makes Optional-vs-missing harder for the caller.

## 2. Fix — four landing-together changes

### 2.1 Write-side git provenance (Bundle 67)

#### Shared helper

A new free helper in `auditengine` builds the SARIF provenance
block from a canonical project root:

```c++
namespace AuditEngine {
    // Capture best-effort VCS state for the project at `rootCanonical`
    // (canonical, symlink-resolved). Returns a SARIF
    // versionControlProvenance array (§ 3.14.18) suitable for
    // `run["versionControlProvenance"] = ...`. Empty array when
    // `git rev-parse HEAD` returns empty — don't emit a half-empty
    // record. Forks at most three git subprocesses (rev-parse,
    // symbolic-ref, config), each with the 2 s cap from `runGit`.
    QJsonArray buildVcsProvenanceBlock(const QString &rootCanonical);
}
```

The helper lives next to the reader-side scrape (`auditengine.cpp:351`)
to keep producer and consumer code on the same page. Both writer
call sites consume it:

- **`auditrunner.cpp::writeSarif`** — signature changes from
  `writeSarif(path, byTool, rawByTool)` to
  `writeSarif(path, byTool, rawByTool, rootCanonical)`. The single
  internal call at `auditrunner.cpp:977-978` threads `r.rootCanonical`
  (already a member of `RunResult` via the `audit_run` path).
- **`auditdialog::exportSarif`** — gains the same helper call.
  The dialog already owns `m_projectPath` (canonical project root);
  the produced SARIF includes the block.

Capture is best-effort, runs once per writer call:

- `git -C <root> rev-parse HEAD` → `revisionId`. Failure ⇒ helper
  returns **empty array** (don't surface a half-empty record).
- `git -C <root> symbolic-ref --short HEAD` → `branch`. Detached-HEAD
  failure ⇒ `branch` left empty (still emit the block; commit is
  the load-bearing field).
- `git -C <root> config --get remote.origin.url` → `repositoryUri`.
  Missing remote ⇒ fall back to `file://<absolute root>`.

The block lands at the SARIF root, mirroring § 3.14.18:

```json
"runs": [{
  "tool": {...},
  "versionControlProvenance": [{
    "repositoryUri": "<repo origin url or file:// fallback>",
    "revisionId":    "<HEAD sha>",
    "branch":        "<symbolic-ref short>"
  }],
  ...
}]
```

Cost ceiling: one `writeSarif` call per `audit_run` invocation +
one `exportSarif` per AuditDialog "Export SARIF" button click ⇒
**3 git forks per write event**, bounded by user interaction
frequency (audit_run isn't on a tight loop).

#### Reader-side read-time fallback

For non-SARIF formats (`cppcheck-*.xml`, `clang-tidy-*.txt`,
`semgrep-*.json` — Ants is not the writer; external tools dropped
the file in `.audit_cache/`) the engine cannot scrape a provenance
block. `cmdLastAuditSummary` gains a fallback that fires **before**
storing into the existing single-entry mtime cache, so cache hits
inherit the populated data for free.

`AuditSummary` gains one new field:

```c++
struct AuditSummary {
    // ...existing fields (sarifPath, runAtIso, branch, commit,
    //  repositoryUri, etc.)
    // ANTS-1576 — provenance origin tag.
    QString branchSource;  // "file_provenance" | "read_time" | ""
};
```

Population flow in `cmdLastAuditSummary` cache-miss path:

1. Parse summary via the format-appropriate engine helper (existing).
2. If `summary.branch.isEmpty() && summary.commit.isEmpty()`:
   - Probe `git rev-parse HEAD` + `git symbolic-ref --short HEAD`
     against `rootCanonical`.
   - On non-empty rev-parse: set `summary.branch` / `summary.commit`
     and `summary.branchSource = "read_time"`.
3. Otherwise (parser populated the fields): set
   `summary.branchSource = "file_provenance"`.
4. Store into the cache.

Cache hits return the same populated summary — no per-hit forking.
The cache invalidates on `(path, mtime, parserTopN, floor)` change
(existing `m_auditSummary*` keys at `remotecontrol.cpp:4381-4384`);
since file mtime changes invalidate, a re-emit of the same report
also picks up live HEAD changes via the normal expiry path.

`buildLasEnvelope` emits:

- `branch`, `commit`, `repository_uri` — when non-empty (existing
  ANTS-1539 path).
- `branch_source` — when `summary.branchSource` non-empty.
- Omits all four when no probe succeeded (existing fallback).

### 2.2 Scope-aware picker (Bundle 69)

`cmdLastAuditSummary`'s picker today is "lex-max name within the
first-matched glob set." Add a **post-pick scope classifier** that
inspects the parsed `AuditSummary` and tags the envelope:

```c++
// Pseudocode — runs after summariseXxx() returns successfully.
const int distinctFiles = countDistinctFilesIn(summary.topFindings);
const bool narrowFilenameHint =
    QFileInfo(reportPath).baseName().contains(QStringLiteral("-postfix")) ||
    QFileInfo(reportPath).baseName().contains(QStringLiteral("-single"))  ||
    QFileInfo(reportPath).baseName().contains(QStringLiteral("-narrow"));

QString scopeTag;
if (distinctFiles == 1 && !narrowFilenameHint)       scopeTag = "single_file";
else if (distinctFiles == 1 ||
         distinctFiles <= 5 || narrowFilenameHint)   scopeTag = "narrow";
else                                                 scopeTag = "broad";
```

Three-tag taxonomy matches the original ROADMAP entry (Bundle 69):

- `single_file` — exactly one distinct file in `topFindings[]`,
  no narrow-name hint. The classic "ran cppcheck against one file
  after a fix" case.
- `narrow` — `distinctFiles ∈ [1, 5]` with a name hint
  (`-postfix` / `-single` / `-narrow`), or distinctFiles ∈ [2, 5]
  without a hint. Suggests a small-scope rerun rather than a
  project-wide sweep.
- `broad` — `distinctFiles > 5`. Treat as the trustworthy "project
  sweep" answer.

Envelope gains:

- `scope: "single_file" | "narrow" | "broad"` — always emitted.
- `narrow_run_warning: "<file> looks like a single-file rerun (1
  distinct file in top findings). A broader recent file may exist
  in .audit_cache/."` — only when `scope ∈ {single_file, narrow}`.
- `narrow_run_files: ["src/foo.cpp"]` — distinct file list when
  scope ≠ broad, up to 5 entries (prevents giant envelopes).

The classifier counts distinct files in `topFindings[]`, not in the
raw findings, to keep the cost O(topN). topN is server-clamped to
50 already, so the classifier touches ≤ 50 entries.

**Out of scope for this pull:** preferring a broader file when
two candidates tie on recency. The picker stays lex-max; the
classifier just warns the caller. Re-picking would need either
content-pre-scan on all candidates (expensive) or a manifest the
external scanners don't write today. ANTS-1555 (audit cache infra)
is the right place to land an in-process manifest later; until
then the warning shifts the choice to the caller.

### 2.3 Null-or-omit normalisation (Bundle 69 cosmetic)

`buildLasEnvelope` currently always sets `ok["run_at"]` and
`ok["html_path"]`, even when blank. Change to omit-when-empty:

```c++
if (!s.runAtIso.isEmpty())  ok["run_at"]    = s.runAtIso;
if (!s.htmlPath.isEmpty())  ok["html_path"] = s.htmlPath;
```

`sarif_path`, `source_format`, `counts` stay always-emitted —
they're the load-bearing fields. The change applies only to
fields whose absence is a meaningful signal ("there's no HTML
sibling" / "the SARIF lacked an invocation block").

**Wire compat.** Callers that read `obj["run_at"].toString()` get
an empty string either way (Qt 6 `QJsonValue::toString()` returns
`QString()` on a missing key — verified). Callers that distinguish
via `obj.contains("run_at")` get the cleaner signal.

**Caveat:** callers that probe `obj["run_at"].toVariant().isNull()`
*will* see a behavioural shift — a missing key surfaces as
`isNull()==true`, where the old shape was a non-null empty string.
Searched the codebase (`tests/`, `src/`) for this pattern: zero
hits. External callers (RetroDB / Vestige / RetroArch sessions
per the cross-session reports) read via `obj["run_at"].toString()`.
Documented for future-Claude in the CHANGELOG entry.

### 2.4 `rule_ids[]` filter — already verified (Bundle 66)

Verified shipped as [[ANTS-1540]] in pull 3 (2026-05-17). The
implementation lives at `remotecontrol.cpp:4258-4273` +
`:4426-4433`:

- Schema accepts `rule_ids: ["ruleA", "ruleB"]`.
- Parser uses an expanded `topN=50` when filter is active so rare
  rules surface.
- Post-cap filter narrows to the requested set, then re-caps to
  the caller's `topN`.
- Envelope echoes `rule_ids_filter: [...]` so callers confirm what
  was applied.

**Regression coverage.** This pull adds one **behavioural** test
(not a source-grep tripwire — those rot when literals are renamed
without behaviour change). The test drives the live cache path via
`cmdLastAuditSummary` against `fixture_min.sarif` with `rule_ids:
["rule-blocker"]` and asserts the envelope's `rule_ids_filter`
echo + `top_findings.size() == 1`. Cheaper to maintain, asserts
the actual contract.

## 5. Out of scope (deferred)

- **Preferring broader file on recency tie.** Surfaces the warning,
  doesn't auto-re-pick. Needs ANTS-1555 (audit cache manifest) to
  land a low-cost cross-file scope view.
- **Caching the `git rev-parse` probe.** Re-runs once per
  `cmdLastAuditSummary` call. The MCP call's idempotent-read
  cache (5 min TTL, [[ANTS-1359]]) already covers the macro
  case; a finer-grained cache is unwarranted for the read-time
  fallback path.
- **Surfacing dirty-tree state** (`git status --porcelain` count).
  Caller can ask separately via `git_state`. Avoid duplicating
  that surface here.
- **Per-tool scope classification.** A SARIF with two tools (one
  full, one narrow) gets a single envelope scope tag. Acceptable
  for v1 — the case is rare enough that the warning's caller
  can drill down via the cited `narrow_run_files`.
- **Backfilling provenance for old SARIFs in `.audit_cache/`.**
  Pre-1576 SARIFs lack the block; the reader-side fallback
  populates branch/commit from live HEAD with
  `branch_source: "read_time"` which is the right answer.

## 6. RAM / build budget

- Write-side: one `git rev-parse` + one `git symbolic-ref` +
  one `git config --get remote.origin.url` per `writeSarif` call.
  Each is a forked subprocess, < 50 ms typical. Bounded by
  user-driven cadence: one `audit_run` invocation per call to
  the verb (`writeSarif` is the only caller from the runner
  path; AuditDialog's "Export SARIF" button is the second
  caller and is user-click-bounded).
- Reader-side fallback: same two probes (rev-parse + symbolic-ref;
  no remote.origin.url at read time), runs once per
  `cmdLastAuditSummary` **cache miss**. The result lands inside
  the cached `AuditSummary` (new `branchSource` field), so
  subsequent calls within the 5-minute idempotent-read cache
  window AND mtime-stable subsequent calls return the cached
  data without re-forking.
- Scope classifier: single linear pass over `topFindings[]`
  (≤ 50 entries by server clamp). `QSet<QString>` for distinct
  files is bounded above by topN.
- Envelope size: + ~80 bytes typical (branch + commit + scope tag),
  +~300 bytes when `narrow_run_warning` + `narrow_run_files` fire.
  All bounded.
- No new persistent state. No new fields on `AuditSummary` beyond
  the existing `branch` / `commit` / `repositoryUri` — these gain
  a read-time write path.
