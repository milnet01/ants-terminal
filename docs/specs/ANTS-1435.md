# ANTS-1435 — `session_memory` (+ `project_layout`) reads honour `caller_cwd`

**Status:** spec drafting (Vestige sweep — pending implementation).
**Kind:** fix (security-model adjustment).
**Lanes:** `remotecontrol` (`cmdSessionMemory`, `cmdProjectLayout`),
`remotecontrolgate`, `ANTS-1336` (amend INV-7).
**Source:** vestige-cc-feedback-2026-05-16.
**Pairs with:** ANTS-1283 (`session_memory` underlying engine),
ANTS-1336 (introduced the RcGate routing being amended here),
ANTS-1372 (the gate itself), ANTS-1391 (`caller_cwd` convention),
ANTS-1430 (`project_layout` — joins the same fix).

## Problem

Vestige CC session 2026-05-16: `session_memory op:"list"` refused
with `code:"cwd_mismatch"` even though Vestige correctly supplied
`caller_cwd:"/mnt/Games/Scripts/Linux/3D_Engine"`. The refusal fired
because the Ants tab was focused on a different project — but the
WHOLE POINT of `caller_cwd` (per ANTS-1391) is to **anchor the read
to the caller's project**, not to whichever tab Ants happens to have
focused.

Other read-only verbs (`roadmap_query`, `subsystem`, `git_state`,
`tab_list` with `caller_cwd` matching) treat `caller_cwd` as the
tenancy assertion. `session_memory`'s reads were routed through
RcGate by ANTS-1336 specifically to prevent cross-tenant reads of
the tenant-hashed `~/.cache/ants-terminal/mcp-state/<sha256(cwd)>.json`
store — but that protection is **overly strict for reads**: if the
storage is hashed by cwd and the caller supplies their own cwd, they
read their own bucket. There's no cross-tenant leak.

The same overstrictness applies to `project_layout` (ANTS-1430)
which also stores under `~/.cache/.../sha256(cwd).json` via
session_memory. Both verbs share the same read-only-tenant-hashed-
storage pattern; both should share the same fix.

## Goal

Read ops (`Get`, `List` on `session_memory`; entire `project_layout`
verb since it's read-only) honour `caller_cwd` directly:

- `caller_cwd` empty → still refuse (`cwd_missing`).
- `caller_cwd` non-empty but not a real path → still refuse (`cwd_bad`).
- `caller_cwd` valid → canonicalise, hash, read from the matching
  bucket. **No focused-tab match required.**

Write ops (`Set`, `Delete` on `session_memory`) keep the current
RcGate flow (focused-tab match) so a buggy / malicious session can't
write to an arbitrary project's bucket.

## Threat model — why reads are safe to relax

Same-UID assumption: the Ants MCP socket is UID-scoped (`/tmp/ants-
terminal-<uid>.sock` + `0700` perms; verified `lstat S_ISSOCK`).
Only the user (and sub-processes spawned by the user) can connect.

Storage path: `~/.cache/ants-terminal/mcp-state/<sha256(cwd)>.json`.
Per-cwd bucket. Files are owned by the user (0600); not world-
readable.

Within the same-UID boundary:
- A caller supplies any `caller_cwd` string they choose.
- The cwd is canonicalised + SHA-256-hashed → that's the bucket file
  to read.
- If the bucket exists, the caller reads it. If not, `found:false` /
  `keys:[]`.

What an attacker (here, "another script running as the user") could
do with caller_cwd-anchored reads:
- Read any bucket they can name. But they can already read the entire
  `~/.cache/ants-terminal/mcp-state/` directory directly via the
  filesystem — the gate adds no protection that the filesystem
  doesn't already remove.
- Enumerate buckets by guessing cwd paths and observing
  `found:true`/`false`. Same: `ls ~/.cache/ants-terminal/mcp-state/`
  exposes the SHA filenames, and the hash is unkeyed (anyone can
  recompute it from a known cwd).

Conclusion: the focused-tab gate on read ops adds zero security
beyond the underlying file permissions. It only blocks legitimate
cross-project queries. ANTS-1336's intent was to close the **write**
side (a session in project A writing to project B's bucket would
contaminate B's future reads); reads were swept up incidentally.

What the write gate genuinely prevents:
- A session in /wrong/path writes "foo" with `caller_cwd:"/right/path"`.
- Later a session in /right/path lists keys → sees "foo" attributed
  to /right/path it never wrote.
- Result: memory pollution / confused-deputy. Keeping the gate on
  write ops blocks this.

## Design

### `cmdSessionMemory` — per-op gate

Replace the unconditional `RcGate::checkCallerCwd` call at
`remotecontrol.cpp:4848-4856` with a branch on `op`:

```cpp
const QString opRaw = req.value("op").toString();
SessionMemoryEngine::Op op = SessionMemoryEngine::Op::Get;
if (!SessionMemoryEngine::parseOp(opRaw, &op)) {
    return /* bad_op */;
}

QString cwd;  // resolved tenant cwd

const bool isReadOp = (op == SessionMemoryEngine::Op::Get ||
                       op == SessionMemoryEngine::Op::List);
if (isReadOp) {
    // ANTS-1435 — read ops anchor to caller_cwd directly. No
    // focused-tab match required; the storage is per-cwd-hashed
    // and the caller's bucket is self-scoped.
    const QString rawCaller =
        req.value("caller_cwd").toString();
    if (rawCaller.isEmpty()) {
        return /* cwd_missing — same envelope shape as RcGate */;
    }
    const QFileInfo fi(rawCaller);
    const QString canon = fi.canonicalFilePath();
    if (canon.isEmpty()) {
        return /* cwd_bad — path doesn't exist */;
    }
    // ANTS-1435 INV-4b (cold-eyes H2): canonicalFilePath returns
    // non-empty for ANY existing path (file, FIFO, device — not
    // just dirs). A read against caller_cwd:"/etc/passwd" would
    // hash to a real bucket file and silently return an empty
    // envelope. Reject non-directories explicitly.
    if (!QFileInfo(canon).isDir()) {
        return /* cwd_bad — path is not a directory */;
    }
    cwd = canon;
} else {
    // Write ops (Set, Delete) — keep RcGate flow. Prevents the
    // confused-deputy attack: a session in /wrong/path writing
    // to /right/path's bucket.
    const auto gate = RcGate::checkCallerCwd(
        resolveRootCanonical(m_main), req,
        QStringLiteral("session_memory"));
    if (!gate.ok) {
        return /* materialise gate refusal via smErr */;
    }
    cwd = gate.focused;
}
```

### `cmdProjectLayout` — same fix, simpler

`project_layout` has only one op (read). Replace the
`RcGate::checkCallerCwd` call at `cmdProjectLayout` with the
caller_cwd-anchor path:

```cpp
// Required-contract dispatcher refusal (ANTS-1404) catches empty
// caller_cwd upstream. Here we just need to canonicalise + isDir
// (parity with cmdSessionMemory's read branch, cold-eyes H2 + M3).
const QString rawCaller = req.value("caller_cwd").toString();
const QFileInfo fi(rawCaller);
const QString canon = fi.canonicalFilePath();
if (canon.isEmpty() || !QFileInfo(canon).isDir()) {
    QJsonObject env;
    env["ok"]    = false;
    env["error"] = QStringLiteral(
        "project_layout: caller_cwd \"%1\" is not a directory")
            .arg(rawCaller);
    env["code"]  = QStringLiteral("cwd_bad");
    return QJsonDocument(env);
}
const QString cwd = canon;
```

`ANTS-1430 § Dispatcher / Double-gating rationale` block becomes
stale once this lands — the body's RcGate call is gone. Add an
amendment in §Cross-doc amendments.

### Envelope parity

Error envelopes from the new caller_cwd path must match the existing
RcGate refusal shape so consumers don't need a separate parser:

```jsonc
// Read-op refusals (new path):
{"ok": false, "code": "cwd_missing", "error": "session_memory: caller_cwd argument required (pass your $PWD; refuses on missing)"}
{"ok": false, "code": "cwd_bad",     "error": "session_memory: caller_cwd \"/non/existent\" does not exist"}

// Write-op refusals (existing RcGate path, unchanged):
{"ok": false, "code": "cwd_missing", "error": "session_memory: caller_cwd argument required ..."}
{"ok": false, "code": "cwd_mismatch", "error": "session_memory: calling session cwd \"...\" does not match focused tab cwd \"...\""}
```

Both paths emit `cwd_missing` / `cwd_bad` for the same reasons;
`cwd_mismatch` only ever fires on writes. For session_memory the
envelope is wrapped via `smErr` (4-field shape including op+key);
project_layout uses the bare envelope.

## Invariants

- **INV-1 / Read-op + caller_cwd-only succeeds across tabs.**
  `session_memory{op:"list", caller_cwd:"/path/A"}` returns
  `{ok:true, keys:[...]}` for /path/A's bucket regardless of which
  tab Ants is focused on. Same for `op:"get"` and the entire
  `project_layout` verb.
- **INV-2 / Write-op cross-tenant still refuses.**
  `session_memory{op:"set", caller_cwd:"/path/A", ...}` returns
  `{ok:false, code:"cwd_mismatch"}` when the focused tab is /path/B.
  Same for `op:"delete"`.
- **INV-3 / Empty caller_cwd still refused on reads.**
  `session_memory{op:"list"}` (no caller_cwd) returns
  `{ok:false, code:"cwd_missing"}` — write-op behaviour, same code.
  We don't fall through to the focused tab.
- **INV-4 / Invalid caller_cwd still refused on reads.**
  `session_memory{op:"get", caller_cwd:"/does/not/exist", ...}`
  returns `{ok:false, code:"cwd_bad"}`. canonicalFilePath returning
  empty is the trigger.
- **INV-4b / Non-directory caller_cwd refused on reads.**
  `session_memory{op:"get", caller_cwd:"/etc/passwd", ...}`
  returns `{ok:false, code:"cwd_bad"}` because `QFileInfo::isDir()`
  returns false on a regular file. Cold-eyes H2: without this gate,
  `canonicalFilePath` accepts any existing path (file, FIFO,
  device) and hashes to a real bucket file; the read would silently
  return an empty envelope from a path that's not a project. Same
  check applies to `cmdProjectLayout`.
- **INV-5 / Read bucket isolation.** A read from /path/A's bucket
  never returns entries from /path/B. Verified by writing distinct
  values to A and B from the appropriate focused tabs, then reading
  from A's `caller_cwd` while focused on B — receives only A's
  entries.
- **INV-6 / Write bucket isolation preserved.** A write from /path/A
  (focused) cannot write to /path/B's bucket regardless of
  caller_cwd supplied. INV-2's refusal is the gate.
- **INV-7 / Same envelope shape per verb on refusal.**
  `session_memory` refusals from EITHER branch (read or write)
  emit the 4-field `smErr` shape `{ok, code, error, op, echo}`;
  `project_layout` refusals emit the bare 3-field shape
  `{ok, error, code}`. The two verbs were already asymmetric
  pre-1435 (per `src/remotecontrol.cpp:4805-4814` vs
  `src/remotecontrolgate.cpp:53-59`); this spec preserves that.
  Cold-eyes M7 — honest framing of the asymmetry.
- **INV-8 / `project_layout` honours caller_cwd cross-tab.**
  `project_layout{caller_cwd:"/path/A"}` succeeds when focused on
  /path/B. Returns A's layout (cached or freshly scanned per
  ANTS-1430's TTL + mtime predicates).

## Open questions

- **Audit-trail / logging.** Resolved (cold-eyes L5): read-op
  refusals (`cwd_missing` / `cwd_bad`) do NOT log, matching
  ANTS-1372 INV-11. RcGate's `cwd_mismatch` warning is for
  cross-tenant attempts (security signal); caller-side bad-arg
  refusals are not.
- **Race: bucket creation by another process between canonicalise and
  read.** If two sessions race on a `Set` to the same bucket, the
  underlying SessionMemoryEngine already serialises via QSaveFile
  atomic rename. No additional concern here.
- **Edge case: `caller_cwd` resolves to a bucket whose owner UID
  differs from current.** Filesystem permissions handle this —
  reading another user's `~/.cache/` requires permissions we don't
  have. The verb fails with the engine's `io_error` envelope, which
  is the correct behaviour. No special-case handling needed.

## Limitations (cold-eyes H1, surfaced for sign-off)

The current ANTS-1336 gate makes a cross-project read NOISY: the
caller has to focus an Ants tab on the target project before the
read succeeds. After this fix, a same-UID process can read any
project's bucket by guessing the cwd path and supplying it as
`caller_cwd`, with no UI side-effect.

Filesystem permissions (`~/.cache/ants-terminal/mcp-state/` is
0700 + files 0600) DO prevent cross-USER reads, so this is not a
secrecy vulnerability. The concern is purely the same-UID
observability — a hostile script running as the user could
enumerate buckets without flipping any visible focus.

**Trade-off options** (mutually exclusive — pick one before
implementation):

- **(A) Accept and document.** This spec as-shipped. The
  "Limitations" block is the user-visible acknowledgement. Rationale:
  Vestige's cross-tab read is a legitimate workflow; the noise the
  current gate provides is incidental, not designed.
- **(B) Tighten: caller_cwd must match SOME open tab.** Walk
  `m_main->tabs()` and accept caller_cwd if it matches *any* open
  Ants tab's `shellCwd`, not just the focused one. Vestige's use
  case still works as long as the target project is open in some
  tab. A hostile script can't read a bucket addressed by a project
  the user doesn't have open in Ants. Costs: ~5 LoC in the read
  branch, one O(N_tabs) walk per call. The "all my projects must
  be open in tabs" requirement is a minor UX constraint.

Option (A) is the v1 default if no objection; option (B) costs
little extra and preserves more of ANTS-1336's intent. Surfacing
the choice rather than picking silently per CLAUDE.md rule 8.
