## 1. Problem

The index-enforcement chain is: **build the codebase index → refresh it at
session start → actually USE it instead of grepping.** Layers 1-2 ship
(`codebase_index`, `session_orient` eager refresh — ANTS-1637 / ANTS-2140).
Layer 3 — getting the session to *query the index rather than grep* — is the
gap ANTS-2141 closes.

A partial Layer 3 already exists, but it is the wrong shape.
`hooks/ants-bash-veto.sh:34-45` intercepts a Bash `grep -r … src/` /
`grep -R … src/` / `find src/ -name` and **hard-blocks it** with
`{"decision":"block","reason":"use mcp__ants__workspace_search …"}`
(`hooks/ants-bash-veto.sh:54`). Consequences:

1. **False-positive friction.** A hard block aborts the call, so a legitimate
   non-source / log / build-tree search that happens to match the glob forces a
   `# ants-bypass` retry. The user's 2026-06-15 decision was explicit: *let the
   command run, just remind.* Blocking is too blunt for a heuristic.
2. **Narrow coverage.** The current globs require the literal `src/` and miss
   `rg`/`ag`/`ack` (default-recursive), pathless `grep -rn foo`, `git grep`,
   and searches over `tests/` / `include/`. Because a block is high-friction,
   the patterns were kept conservative — softening to a warn lets the net
   widen safely.
3. **No effectiveness signal.** ANTS-1252 §8 explicitly deferred veto telemetry
   ("counts of vetos fired … add when the pack matures"). There is no way to
   see whether the session greps or queries the index, so the nudge's value is
   unmeasurable.

The install/scope question the ROADMAP bullet raised is **already answered** by
the existing pack: hooks install **user-globally** into `~/.claude/settings.json`
(`tools/install-hooks.sh`) and are **gated per-project** by the `.ants-project`
marker via `ants_in_project_or_exit` (`hooks/_common.sh:13-32`,
ANTS-1252 INV-9). ANTS-2141 inherits that scope — no new hook, no project-local
`.claude/settings.json`.

**Layman:** When the assistant runs a plain text-search over the project, Ants
now *gently reminds* it to use the faster indexed search instead of *blocking*
the search outright — and keeps a tally so we can see if the reminder is working.

## 2. Surface

All changes are in the existing pack (bash + jq, no C++). The verb the nudge
points at (`mcp__ants__workspace_search` etc.) is unchanged.

In `hooks/ants-bash-veto.sh`, the single `case` splits into two routing classes:

- **Reroute-with-block (unchanged):** `git status` / `git log --oneline` /
  `git diff --stat` → the existing reason `use mcp__ants__get_git_status /
  mcp__ants__roadmap_query` (`ants-bash-veto.sh:40`); `cat ROADMAP.md | grep` →
  reason `use mcp__ants__roadmap_query` (`ants-bash-veto.sh:43`). These stay
  `{"decision":"block","reason":…}` **verbatim** with the existing ≤ 200 B
  `reason` cap (ANTS-1252 INV-4) — precise, low false-positive, out of this
  item's lane. ("Unchanged" = the literal reason strings are preserved; this
  spec adds no `git_state`-style relabel.)
- **Reroute-with-warn (replaces the old grep/find block):** a raw source search
  (§2.2) → a **non-blocking** reminder (§2.1). The existing `*grep -r…src/*` /
  `find src…-name` → block case (`ants-bash-veto.sh:35-38`, reason text at `:37`)
  is **removed** and superseded by this warn branch. So after this change **no**
  grep/find produces a block; only the git/roadmap branches above still block.

### 2.1 The warn envelope (non-blocking, model-visible)

```json
{
  "hookSpecificOutput": {
    "hookEventName": "PreToolUse",
    "additionalContext": "Ants tip: that was a raw source search. Prefer mcp__ants__workspace_search (project-wide code search) / find_definition / find_sources — indexed, far fewer tokens than streaming grep/find output back. Append `# ants-bypass` to silence."
  }
}
```

No `permissionDecision` field. Verified against the official Claude Code hooks
reference (claude-code-guide, fetched 2026-06-16 from
`docs.claude.com/en/docs/claude-code/hooks`): on **PreToolUse**, exit 0 with
`hookSpecificOutput.additionalContext` and **no** `permissionDecision` (a) injects
the text into the model's context and (b) lets the tool proceed through the
normal permission flow — the hook neither force-allows nor blocks. This is the
purest soft-warn: it cannot escalate a permission the user hasn't granted, and
it cannot abort the command. (Earlier drafts paired it with
`permissionDecision:"allow"`; dropped because force-allow would auto-approve a
command the user might not have allow-listed — a permission change the soft-warn
must not make.)

Both warn outcomes are non-blocking: the warn envelope (above) and the
throttle-suppressed path (§2.3, empty stdout). In the warn class the command
**always runs**; the implementer must NOT `exit 2` or emit `{}`/a `decision`
on either path.

### 2.2 Match algorithm — what counts as "raw source search"

Matching runs on the **jq-decoded** command string `$cmd` (ANTS-1252 INV-7:
never regex the raw JSON). The predicate is the pure helper
`ants_is_source_search "$cmd"` in `_common.sh` — it must **`return 0` (match) /
`return 1` (no match), never `exit`**, so the harness can call it in-process
(`if ants_is_source_search "$c"; then …`). It mirrors the *table-test style* of
`ants_validate_session_id`, but NOT its control flow: that validator `exit`s on
reject (`_common.sh:42,47`) and so must be tested via a subshell — the new
predicate must avoid `exit` precisely so it stays in-process testable.

```
pre = $cmd up to (not including) the first unquoted '|'     # excludes "X | grep"
strip from pre: leading `VAR=val ` assignments and a single leading `cd … &&`
                (only a leading `cd`, not any other command before `&&`)

RECURSIVE_GREP = pre has a leading-or-post-`&&`/`;` token in
    {grep,egrep,fgrep} carrying -r | -R | --recursive,
    OR a token in {rg,ag,ack,ack-grep}            # these are recursive by default
PROJECT_FIND   = pre has a `find` token AND a -name|-iname|-path|-ipath primary
    AND its first path operand is a project SOURCE location — `.`, `./`, or a
        path under `src`/`tests`/`include` (with or without a trailing `/`).
        Anything else (absolute, `build`, `docs`, `node_modules`, …) is skipped —
        conservative no-warn (an explicit source whitelist, NOT "any relative
        path", so build/output dirs never warn)
    AND pre has NO mutating/exec primary
        (-delete,-exec,-execdir,-ok,-okdir,-fprint,-fprintf,-fls)
GIT_GREP       = pre has `git grep`   # always repo-scoped; no path guard needed

eligible = (RECURSIVE_GREP or PROJECT_FIND or GIT_GREP) and not EXEMPT
```

`EXEMPT` (no warn — the command runs untouched) when:

- the **whole `$cmd`** contains `# ants-bypass` (the existing override,
  ANTS-1252 INV-12); OR
- `pre` contains `--help`, `--version`, `-h`, or `-V`; OR
- `pre` contains a **non-source-root** token: `/tmp`, `/var`, `/etc`, `/usr`,
  `/proc`, `/sys`, `build/`, `build-`, `.git/`, `node_modules`, or a token
  **ending in `.log`**.

These EXEMPT checks are **substring** tests on `pre` (not word-split tokens) —
that is the reading blind spot (c) below depends on. The non-source-root + flag
scans run on **`pre`**, not the whole `$cmd`, so a
source search that merely *pipes into* a non-source path —
`grep -rn x src/ | tee /var/log/out` — still warns. Only the `# ants-bypass`
override scans the whole `$cmd`. (No blanket "any absolute path" exemption — an
absolute path *into the repo*, e.g. `grep -rn foo /home/me/repo/src`, is still a
source search and warns.)

Destructive/exec `find` primaries (`-delete`, `-exec`, …) are **not** in the
EXEMPT list — they are excluded inside the **PROJECT_FIND guard** (its "NO
mutating/exec primary" clause, evaluated on `pre`). So `find … -exec/-delete`
fails PROJECT_FIND and never becomes eligible; an implementer must keep that
test in the guard, not in the EXEMPT token-scan (the two run on the same `pre`
here but would diverge for piped/chained forms).

**Parsing strategy.** `ants_is_source_search` is a **parsed-token** predicate,
not a glob `case` (the existing veto's style cannot express "first pipe
boundary" or "token ending in `.log`"). Implement with bash on the **jq-decoded**
value only (never raw JSON — ANTS-1252 INV-7): `pre="${cmd%%|*}"` for the pipe
split, parameter-expansion strips for the `VAR=…`/`cd … &&` prefixes, and
`[[ … =~ … ]]` regex (or word-split array) scans for the token tests.
`pre="${cmd%%|*}"` splits on the first `|` regardless of quoting; a literal `|`
inside a quoted search pattern is an accepted, benign approximation — it can only
*shorten* `pre`, never invent a match (`grep -rn 'a|b' src/` still surfaces the
recursive `grep` in `pre`).

Worked cases (→ test table, INV-6):

| Command | Result | Why |
|---|---|---|
| `grep -rn foo src/` | warn | recursive grep, project path |
| `grep -rn foo` (no path) | warn | recursive grep over cwd |
| `rg foo` / `rg foo src/` | warn | rg is recursive by default |
| `git grep TerminalGrid` | warn | git grep over source |
| `find src -name '*.cpp'` | warn | project find |
| `grep foo file.txt` | no warn | non-recursive single-file grep (not a tree search) |
| `cmake … 2>&1 \| grep error` | no warn | grep is downstream of a pipe (`pre` = `cmake …`) |
| `grep -rn x src/ \| head` | warn | grep leads `pre`; pipe only caps output |
| `grep -rn x /var/log` | no warn | non-source root `/var` |
| `find build -name x` | no warn | `build` not a source dir (PROJECT_FIND whitelist is `.`/`./`/`src`/`tests`/`include`) |
| `find . -name x -delete` | no warn | mutating primary `-delete` |
| `grep -rn foo /home/me/repo/src` | warn | absolute path *into* the repo |
| `cat x && grep -rn y src/` | no warn (accepted) | leading command of `pre` is `cat`; the `&&`-tail grep is not inspected — conservative, see blind spots |

**Accepted blind spots** (documented, not bugs): (a) a search invoked via
`find … -exec grep …` does not warn — PROJECT_FIND rejects it on the `-exec`
primary (a `find` exec is an action, not a search we route); (b) a source
search that is not the leading command of a `&&`/`;` chain after the first `cd`
strip (e.g. `cat x && grep -r y src/`) is not warned; (c) the EXEMPT path-token
scan is substring-based, so a search whose *pattern* contains a non-source-root
substring or ends in `.log` (e.g. `grep -rn 'error.log' src/`,
`grep -rn '/var/x' src/`) is wrongly exempted and not warned. All three favour
*fewer* false positives (a missed nudge is harmless; a spurious one is friction),
consistent with the soft-warn posture.

### 2.3 Anti-nag throttle (fail-open)

A warn costs `additionalContext` tokens per fire; nudging on every grep in a
grep-heavy session would burn the tokens the feature exists to save. The warn
**emission** (not the count — §2.4) is throttled to once per
`ANTS_GREP_NUDGE_THROTTLE_SEC` (default 600, env-overridable) per Claude
process, keyed by the hook's `$PPID`:

- Stamp file: `<cache>/grep-nudge/<key>.stamp` where `<key>` is
  `${ANTS_GREP_NUDGE_KEY:-$PPID}` sanitised to `[A-Za-z0-9_-]` (the env override
  is the seam for a future session-id key per §6, and makes the throttle
  deterministically testable; default is `$PPID`). mtime = last warn; see §2.5
  for `<cache>`. `now - mtime` is computed with `stat -c %Y` (integer seconds; GNU
  coreutils, the pack's assumed environment per ANTS-1252 §4). If
  `now - mtime < window`, skip the warn emission and exit 0 with **empty stdout**
  (the command still runs — nothing blocked). On emit, `touch` the stamp.
- **Fail-open.** If the stamp cannot be read or written (cache dir absent and
  un-creatable, unwritable, etc.), the throttle is treated as *expired* and the
  warn IS emitted. A broken cache must never silence the nudge — at worst the
  session sees a few extra reminders. `ants_grep_nudge_throttled` returns 1
  (not throttled) on any I/O error. Every filesystem op in **both** helpers
  (`mkdir -p`, `stat`, `touch`, the counter append/`tail`) is guarded
  (`… 2>/dev/null || true` / explicit status check) so a failure degrades to
  fail-open and never aborts — the helpers must be safe even though the veto
  runs under `set -u` only (not `set -e`).
- **`$PPID` fallback.** If `$PPID` is empty or `0`, skip the throttle entirely
  (warn-always); do not collapse to a shared `…/.stamp` key that would
  cross-throttle unrelated processes. The throttle key only needs to be
  stable-per-session for correctness; an unstable key degrades to more warns,
  which is harmless.

### 2.4 Observability — the grep side of the readout

`ants_grep_nudge_record` appends one compact JSONL line to `<cache>/grep-nudge/count.jsonl`
on **every eligible match** (after the §2.2 predicate passes — a `find` that
failed PROJECT_FIND, or any non-eligible/exempt command, never records),
**before the throttle check**, so the tally reflects true grep volume even when
a nudge is suppressed:

```json
{"ts":"2026-06-16T12:00:00Z","tool":"grep","warned":true}
```

`tool` is one of a fixed vocabulary — `grep` (covers `grep`/`egrep`/`fgrep`),
`rg`, `ag`, `ack` (`ack-grep` buckets as `ack`), `git-grep`, `find` — derived
from the matched leading token; `tools/grep-vs-index.sh` buckets on it and
**skips any malformed line** (tolerating the lossy-concurrency case below).
`warned` is `false` when the throttle suppressed the emission. The file is
**bounded** by one pre-append rule: if `wc -l` ≥ 500, replace it with its last
250 (best-effort `tail`), then append the new line — so it sits at ≤ 500 lines
(== 251 immediately after a truncate). No post-append re-check. All writes are
best-effort (`… 2>/dev/null || true`) — a write failure never changes the exit
code or suppresses the warn (INV-9). Concurrent parallel Bash tool calls can
interleave the `tail`-rewrite with no lock; this is **accepted as lossy** (a
counter, not a ledger) — `flock` is deliberately not used (over-engineering for a
tally; the worst case is a few miscounted or malformed lines, which the readout
skips).

The **index side** already exists: `token_usage` reports per-verb `n_calls`
for `workspace_search` / `find_definition` / `find_sources`. The readout is
their comparison. A thin `tools/grep-vs-index.sh` prints the grep-nudge tally
(total + warned-count + last-N) and reminds the reader to compare it against
`token_usage` — a one-screen "are we greping or querying?" check. No C++; no
new MCP verb (a unified single-call readout is §5 out-of-scope).

### 2.5 Cache tree + helper ordering

One directory holds both artifacts:

```
~/.cache/ants-terminal/grep-nudge/
    <PPID>.stamp      # throttle, mtime = last warn, 0 bytes
    count.jsonl       # tally, ≤ 500 lines
```

Referred to as `<cache>` above; it derives from `$HOME`
(`${HOME}/.cache/ants-terminal/grep-nudge/`), so the harness's `HOME=$tmp`
override redirects every stamp/counter write into the fixture dir — that is what
makes the INV-9 and INV-11 tests hermetic. `ants_grep_nudge_record` /
`ants_grep_nudge_throttled` `mkdir -p` this directory best-effort; on failure
they fail-open (warn, no throttle) per §2.3.

**Ordering invariant.** All nudge bookkeeping (`record`, `throttled`) runs
**only after** `ants_in_project_or_exit` has returned 0 — i.e. on its success
path (`_common.sh:24`, `return 0`). On a non-ants session that function instead
`exit`s the whole script (`_common.sh:19`/`:28`/`:31`) before the veto body
runs, so the session never writes a stamp or counter line — it pays only the
existing sub-millisecond stat-ascent (ANTS-1252 INV-9), zero tokens, zero files.

## 3. Invariants

*All `INV-N` here are ANTS-2141's; `ANTS-1252 INV-N` denotes the other spec's.*

- **INV-1** — A warn-eligible source search produces
  `{"hookSpecificOutput":{"hookEventName":"PreToolUse","additionalContext":<non-empty>}}`
  with **no** `permissionDecision` and **no** top-level `decision`. *Test:* feed
  `{"tool_input":{"command":"grep -rn foo src/"}}`; assert with a single jq
  program:
  `jq -e '(.hookSpecificOutput.additionalContext|length>0) and (.hookSpecificOutput|has("permissionDecision")|not) and ((.decision//"")=="")'`.
- **INV-2** — The git-status and `cat ROADMAP.md | grep` branches still emit
  `{"decision":"block"}` with a `reason`. *Test:* those two assertion-7 cases
  still produce `.decision=="block"`.
- **INV-3** — The warn `additionalContext` is ≤ 400 bytes. *Test:* harness
  extracts `.hookSpecificOutput.additionalContext` via `jq -r` and asserts its
  byte length — the cap is on the **field value**, not the whole stdout envelope
  (which adds ~80 B of JSON wrapping). (The §2.1 body measures 237 B — headroom
  under the cap. The block branches keep ANTS-1252 INV-4's ≤ 200 B `reason` cap;
  the two caps are on different fields/branches.)
- **INV-4** — Non-warning commands produce empty stdout (command runs
  untouched), one case per class, distinguishing the two no-warn mechanisms:
  **EXEMPT** (`# ants-bypass`; `--help`/`--version`; non-source-root path
  `grep -r x /var/log`; `.log`-suffix token `grep -rn x app.log`) and
  **non-eligible** (destructive find `find . -name x -delete`, and
  non-source-dir find `find build -name x` — both fail the PROJECT_FIND guard,
  *not* the EXEMPT scan, per §2.2). *Test:* one harness case per class
  (including the `.log`-suffix exemption that blind spot (c) relies on) asserts
  empty stdout.
- **INV-5** — Piped grep does not warn (`cmake … | grep error` → empty stdout);
  a leading grep with a trailing pipe still warns (`grep -rn x src/ | head` →
  warn envelope). *Test:* two harness cases.
- **INV-6** — `ants_is_source_search` is a pure predicate in `_common.sh`,
  source-able and unit-testable, returning 0 (match) / 1 (no match). *Test:*
  harness sources `_common.sh` and table-tests the §2.2 worked cases
  (positive / negative / exempt), mirroring the ANTS-1252 INV-2 sessionId table.
- **INV-7** — The warn emission is throttled per `$PPID` per
  `ANTS_GREP_NUDGE_THROTTLE_SEC`; a second eligible match **inside** the window
  emits empty stdout, and a match **after** the window emits again. *Test:* with
  a fixed `PPID`, temp writable `HOME`, and `ANTS_GREP_NUDGE_THROTTLE_SEC=2`:
  fire → warn; fire again immediately → empty (suppressed); `touch -d '5 seconds
  ago'` the stamp (past the 2 s window) → fire → warn (expiry). Pinning the
  window small decouples the assertion from the 600 s default. (Counter still
  records all three — INV-8.) This proves the throttle *mechanism* given a stable
  key; whether CC supplies a session-stable `$PPID` is the §6 manual-smoke check,
  not an automated assertion.
- **INV-8** — Every eligible match appends one line to `count.jsonl`
  (`warned` true/false) regardless of throttle; the file never exceeds 500 lines
  (truncated to its last 250 when it would). *Test:* fire N (>1) times into a
  temp `HOME`; assert line count == N and a `warned:false` line is present on
  the throttled fire; seed 600 lines (any value ≥ 500 gives the same result),
  fire once, assert resulting count is **== 251** (last 250 + the new line — a `== ` bound proves the truncate
  path, where `≤ 251` would also pass a truncate-to-zero bug). The test runs
  **single-threaded** in its own `mktemp -d` `HOME` (not shared with any other
  case), so the `≥ 500` truncate is exercised as a hard step; the `… || true`
  guard is production resilience, not a test escape.
- **INV-9** — All counter/throttle writes are best-effort and never alter the
  exit code or suppress the warn: with an **unwritable** cache dir the hook
  exits 0 AND **still emits the warn** (throttle fails open, §2.3). *Test:*
  canonical fixture — set `HOME` to a temp dir and pre-create
  `<cache>/grep-nudge` as a **regular file** so `mkdir -p` of that path fails
  (root-independent; a `chmod 000` parent is bypassed by root in CI, so it is
  not used). Feed a warn-eligible command; assert exit 0 + non-empty
  `additionalContext`. (This fixture exercises the `mkdir -p` failure branch; the
  dir-present-but-file-unwritable branch is covered by the same
  `… 2>/dev/null || true` guard and is asserted by code inspection, not a
  separate fixture.) The existing ANTS-1252 INV-1 (`{}` → exit 0) and INV-9
  (silent outside project) cases stay green.
- **INV-10** — ANTS-1252 INV-7 still holds: the script parses the payload via
  `jq -r` only; the new match runs on the decoded `$cmd`, never on raw
  `tool_input`. *Test:* the existing ANTS-1252 INV-7 source-grep assertion stays
  green (no `grep -P`/`sed -E`/`perl -ne` over `tool_input`).
- **INV-11** — Nudge bookkeeping runs only after `ants_in_project_or_exit`
  returns 0; a non-ants session writes no stamp and no counter line. *Test:* run
  the veto from a temp dir with no `.ants-project` ancestor and a temp `HOME`;

## 4. RAM / build cost

- **Disk:** one stamp file per live Claude process (`<PPID>.stamp`, 0 bytes) and
  one JSONL counter capped at 500 lines (~40 KiB worst case) under
  `~/.cache/ants-terminal/grep-nudge/` (the same `~/.cache/ants-terminal` base
  the pack already uses for `drift-check.log` — ANTS-1252 §1.4; reuse, don't
  re-derive). Both self-bounded. Stale 0-byte `<PPID>.stamp` files accumulate as
  PIDs recycle but are harmless (each only gates the *next* warn for that PID
  within a window); no reaper is specified.
- **Token cost:** a warn injects its `additionalContext` body (≤ 400 B ≈ ~100
  tokens, INV-3), throttled to ~once per session per window (§2.3). This is a
  *new* cost class not in ANTS-1252 §0's table, which predates PreToolUse
  `additionalContext` (it priced only `decision:block` reasons); the throttle
  exists precisely to bound it.
- **Memory / latency:** within the ANTS-1252 §4 budget (bash + jq, ≤ 20 ms p99
  PreToolUse), but it does add filesystem work per *eligible* match — the
  predicate, a best-effort `mkdir -p`, one `stat`, one short append. These run
  only on a match (most Bash calls skip them at the predicate), so the typical
  call is unaffected; if a cold spawn ever approaches the 20 ms budget the manual
  smoke is the place to catch it.
- **No new build target** (the shell test runs under the existing `hook_pack`
  ctest); **no new external libs** (jq already required by the pack).

## 5. Out of scope

- **Strict-deny escalation** (block again if warnings are ignored) — deferred
  per the user's 2026-06-15 posture; revisit if the readout shows warnings
  aren't changing behaviour. A follow-up ROADMAP id will carry it if needed.
- **A unified single-call "index vs grep" MCP verb** — the readout is assembled
  from `token_usage` + `count.jsonl` + `tools/grep-vs-index.sh`. A dedicated
  verb folding both sides into one envelope is a separate item if the manual
  comparison proves clumsy.
- **Softening the git-status / ROADMAP-grep branches** — out of this item's lane
  (scoped to grep/find over source).
- **Catching `&&`-chained / `find -exec` searches** — accepted blind spots
  (§2.2); favour fewer false positives.

## Implementation notes (2026-06-16, shipped)

Two refinements surfaced while coding the predicate and were folded into the
spec above (design unchanged):

- **PROJECT_FIND source whitelist.** The original "any bare relative path"
  wording would have warned on `find build -name x` (build is not source). The
  operand check is now an explicit source whitelist — `.`/`./` or under
  `src`/`tests`/`include` (§2.2); `find build` is *non-eligible* (INV-4).
- **Throttle key seam.** The throttle key is `${ANTS_GREP_NUDGE_KEY:-$PPID}`
  (sanitised), not bare `$PPID` (§2.3). This makes the throttle deterministically
  testable (command-substitution `$(…)` in the harness changes `$PPID` per call)
  and gives the §6 "key on a session id" follow-up a ready seam.
