# ANTS-1409 — `callerCwdSuffix()` helper for tool-description phrasing

## Problem

ANTS-1391 introduced the `caller_cwd` argument as the per-call
project anchor and centralised the *schema-property* description
via the `makeCallerCwdReadProp` lambda inside the `tools/list`
handler (`claudeintegration.cpp:1340–1352`). The outer
*tool descriptions* never got the same treatment: three tool
blurbs carry the canonical short form **"Pass `caller_cwd` to
anchor to your tab (ANTS-1392)."** spelled out independently at:

| Line | Tool |
|------|------|
| 1424 | `get_last_command` |
| 1440 | `get_git_status` |
| 1456 | `get_environment` |

Two more sites carry related but non-identical phrasing:

- `claudeintegration.cpp:1358` (`get_scrollback`) — long form
  with "without it the result comes from whichever tab Ants
  happens to have focused" addendum.
- `claudeintegration.cpp:1540` (`get_text`) — inline arg-list
  form "`caller_cwd` (your $PWD — ANTS-1392, anchors to…)".

These two stay verbatim because they make tool-specific
guarantees the canonical short form doesn't.

## Scope correction

The original ROADMAP entry estimated "~120 B × ~13 tools =
~1.5 KiB" savings on every `tools/list` response. After
counting actual sites, the real shape is **3 byte-identical
short-form occurrences**. The wire payload doesn't change
either way — each tool's full description is still emitted —
so this refactor's payoff is **source-level dedup**, not wire
bytes. The win is single source of truth: future MCP tools
add `+ callerCwdSuffix()` to their description and inherit the
canonical phrasing instead of re-typing (and possibly mis-
phrasing) it.

## Goal

Extract one private helper inside the `tools/list` handler that
returns the canonical short-form suffix; replace the 3 byte-
identical sites with concatenation against the helper.

## Design

In `claudeintegration.cpp`'s `tools/list` block, alongside
`makeCallerCwdReadProp`:

```cpp
// ANTS-1409 — canonical "Pass caller_cwd to anchor" suffix.
// Three tools (get_last_command, get_git_status,
// get_environment) carry this byte-for-byte today; the helper
// keeps the phrasing in one place so future tools opt in via
// `+ callerCwdSuffix()` rather than retyping it.
auto callerCwdSuffix = []{
    return QStringLiteral(
        "Pass `caller_cwd` to anchor to your tab (ANTS-1392).");
};
```

Each of the three sites changes from:

```cpp
fooTool["description"] = QStringLiteral(
    "Foo's description. Pass `caller_cwd` to anchor "
    "to your tab (ANTS-1392).");
```

to:

```cpp
fooTool["description"] = QStringLiteral(
    "Foo's description. ") + callerCwdSuffix();
```

## Invariants

- **INV-1.** `callerCwdSuffix` lambda is declared in
  `claudeintegration.cpp`'s `tools/list` handler block,
  adjacent to `makeCallerCwdReadProp`.

- **INV-2.** The lambda returns the literal
  `"Pass \`caller_cwd\` to anchor to your tab (ANTS-1392)."`
  exactly — byte-for-byte. Any future copy-edit of the
  canonical phrasing flows through this one location.

- **INV-3.** Three tool descriptions in the registry
  (`get_last_command`, `get_git_status`, `get_environment`)
  call `callerCwdSuffix()` rather than spelling out the
  suffix inline.

- **INV-4.** Two tool descriptions retain their non-identical
  caller_cwd phrasing because the phrasing is tool-specific:
  `get_scrollback` (long form with focused-tab fallback
  caveat) and `get_text` (inline arg-list form). The helper
  is **not** retrofitted to them — their phrasing carries
  semantic content the canonical suffix doesn't.

- **INV-5.** Refactor is observable-behaviour-equivalent. The
  emitted `tools/list` response is byte-identical pre vs post
  for the three affected tools.

## Test

`tests/features/mcp_caller_cwd_suffix_helper/`:

1. **INV-1 (source-scrape).** `callerCwdSuffix` lambda
   present in `claudeintegration.cpp`, in the same scope as
   `makeCallerCwdReadProp` (cheap proxy: appears within 5000
   bytes after the `makeCallerCwdReadProp` definition).

2. **INV-2 (source-scrape).** The lambda returns the canonical
   literal — grep for the exact byte-for-byte string.

3. **INV-3 (source-scrape).** Each of `get_last_command`,
   `get_git_status`, `get_environment` descriptor blocks
   reference `callerCwdSuffix()`.

4. **INV-4 (source-scrape).** The `get_scrollback` and
   `get_text` descriptor blocks **do not** call
   `callerCwdSuffix()` (they keep their tool-specific
   phrasing).

Label `features;fast`. Source-scrape only — no Qt event loop
required; the schema's wire shape is already covered by the
`mcp_caller_cwd_contracts` test.

## Out of scope

- Retrofitting the long-form / inline-arg variants to share
  text with the canonical short form — those carry semantic
  content the canonical suffix doesn't.
- Wire-side compression of the duplicated phrasing across
  tools (would need a JSON-Pointer / `$ref` rewrite of the
  MCP `tools/list` envelope — out of MCP spec).
- Renaming or restructuring `makeCallerCwdReadProp`. ANTS-1419
  covers hoisting the contract declaration into
  `registerToolProvider`.

## RAM budget

Zero. `QStringLiteral` is compile-time-emitted into the binary's
read-only segment; the lambda just returns the same `QString`
view on every call.

## Build cost

Trivial. ~5 LoC added (lambda + comment), ~15 LoC modified
(3 description concatenations). Same translation unit; no
header surface change.

## Migration

None — purely internal. Consumers of `tools/list` see the
same byte sequence.
