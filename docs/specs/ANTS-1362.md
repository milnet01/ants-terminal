# ANTS-1362 — Cell-buffer free pool cap tuning

## Problem

`m_freeCellBuffers` recycles `vector<Cell>(m_cols)` allocations
across scrollUp/scrollDown/insertLines/deleteLines (`terminalgrid.h:475–
481`, `:482 static constexpr int kFreePoolCap = 4`). Cap of 4 was
sized for steady-state scrolling; bursty paths overflow the pool.

Hot paths that overflow `kFreePoolCap = 4`:

- `clear` (CSI 2 J) on a 24+ row terminal — scrollback eviction
  burst returns N cells_row, only 4 land in the pool, N-4 destruct
  immediately. The next bottom-fill paints N rows → N - 4 fresh
  `vector<Cell>(m_cols)` allocations.
- `dmesg` / build-log spam → 50+ row bursts at frame boundaries.
- `tmux` window flip / resize — full-screen redraw burst.

The free-pool win only materialises when the pool is large enough
to *bridge* a burst. At cap 4, every burst > 4 rows pays full
allocation cost for the tail.

## Fix

Raise `kFreePoolCap` from 4 to 32. Covers:

- 24-row `clear` on standard 80×24 terminals.
- 30-row `clear` on common 200×30 wide terminals.
- Most `dmesg` / build-log bursts (typical 20–40 rows per
  frame flush).
- tmux split-screen redraw (24 rows / pane).

## RAM budget

Per pool entry: `sizeof(Cell) × m_cols`.

`Cell` layout (terminalgrid.h, current shape):
~40 B (`codepoint` u32, `attrs` ~28 B with packed flags + fg/bg
QColor pair, `isWideChar/isWideCont` bools, …).

| Cols | Pool entries | Bytes |
|------|--------------|-------|
| 80   | 32           | ~100 KiB |
| 200  | 32           | ~256 KiB |
| 400  | 32           | ~512 KiB |

Worst-case at the wildest terminal width (400) we've ever seen
the user run: ~512 KiB. Cf. `m_scrollback` at 50k rows ×
~7 KiB/row = ~360 MiB upper bound (config-cap protected).
Pool-cap RAM is 0.14 % of scrollback RAM. Acceptable.

Eviction: pool is bounded by `kFreePoolCap` on entry (line 107).
Resize wipes the pool (`m_freeCellBuffers.clear()` at `:2713`)
because pool buffers are sized for the OLD `m_cols`. No further
eviction policy needed — pool always shrinks to ≤ cap or to 0
on resize.

## Out of scope

- Per-cols pool sizing (one cap fits all widths today).
- Cell-size shrinkage (separate concern; cf. ANTS-1062).
- Adaptive cap (autotune to observed burst size — overkill
  for a 32-entry pool).

## No new test

Single-line constant change. Behavioural correctness is covered
by existing scrollUp / clear / scrollback tests (`scrollback_redraw`,
`scrollback_frozen_view`, `scroll_region_rotate`, etc.). Perf
improvement is a tunable, not a contract; no source-grep
tripwire added (per ANTS-1381 hygiene).
