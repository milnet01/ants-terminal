# ANTS-1301 — `recent_errors` MCP — extract compile/test/runtime errors from scrollback

**Status:** spec draft (2026-05-20).
**Kind:** implement.
**Source:** indie-review-2026-05-13 (roadmap bundle plan pull 36).

A read-only MCP tool that scans the most recent N lines of the focused
terminal's scrollback with a per-language regex bank and returns a
structured `errors[]` list (file:line + message + category). Saves the
"let me check what just went wrong" round trip — Claude would otherwise
re-run the command or `get_text` the whole scrollback (~2–5 K tokens)
and re-derive the structure by eye. A new Qt6::Core-only
`ScrollbackErrors` parser does the work; the MCP layer is a thin
read-scrollback-then-parse delegate.

## 1. Problem

After the user runs `cmake --build` / `ctest` / `ruff` / a script and
it fails, Claude has two options today:

1. Re-run the command (wastes wall-clock + may not reproduce).
2. `get_text` the whole scrollback and read it line by line to find
   the `error:` / traceback / `FAILED` lines (~2–5 K tokens, and the
   structure must be re-derived by eye every time).

Both are wasteful for the common "what just broke?" question. The
errors are already on screen in a small number of recognisable shapes
(GCC/clang `file:line:col: error:`, Python tracebacks, ctest
`***Failed`, ruff `file:line:col: CODE msg`, Lua `lua: file:line:`).

`build_status` (ANTS-1299) and `test_results` (ANTS-1300) cover the
*recorded* build/test path (the caller passes captured output to
`op=record`). `recent_errors` is the *unrecorded* path — it reads
whatever is already in the focused terminal's scrollback, no record
step, no re-run.

## 2. Goal

One tool, `recent_errors`, input `{caller_cwd?, tab?, lines?,
max_results?}`, returns `errors:[{category, file?, line?, column?,
message, text}]` extracted from the trailing `lines` of the focused
terminal's scrollback. Regex-only, no language runtime, no re-execution.

## 3. Surface

### 3.1 New lib — `src/scrollbackerrors.{h,cpp}` (Qt6::Core only)

`namespace ScrollbackErrors`. Pure function — no GUI, no terminal, no
filesystem deps; takes the scrollback string, returns the parse. Lives
in `ants_core_lib` next to `buildcache` / `fileoutline`. Public API:

```cpp
struct ErrorEntry {
    QString category;   // "compiler" | "python" | "test" | "lint" | "lua"
    QString file;       // captured path, or empty
    int     line = 0;   // captured source line, or 0
    int     column = 0; // captured column, or 0
    QString message;    // the error message
    QString text;       // the matched scrollback line (trimmed); anchor line for multi-line
};

struct Options { int maxResults = 0; };   // ≤0 ⇒ default 50; >1000 ⇒ clamped to 1000

struct Result {
    QVector<ErrorEntry> errors;
    int  errorsTotal  = 0;   // pre-cap count
    int  linesScanned = 0;
    bool truncated    = false;
};

Result parse(const QString &scrollback, const Options &opts);
```

The caller passes the already-trimmed trailing window (the handler
reads `recentOutput(lines)`); `parse` scans every line of what it is
given and reports `linesScanned` = the line count of that input.

### 3.2 Pattern bank

Single forward pass over the lines. First matching category wins per
line (order below). Patterns compile once (`static const`,
`.optimize()`); they are symbol-free so process-static is correct
(unlike ANTS-1303's per-call symbol splice).

| Category | Anchor (per line unless noted) | Captures |
|----------|-------------------------------|----------|
| `compiler` | `^\s*(\S.*?):(\d+):(?:(\d+):)?\s+(?:fatal\s+)?error:\s*(.+)$` | file, line, col?, message |
| `lint` | `^\s*(\S.*?):(\d+):(\d+):\s+([A-Z]{1,5}\d{1,4})\b\s*(.*)$` | file, line, col, `CODE msg` |
| `lua` | `^\s*lua:\s+(\S.*?):(\d+):\s*(.+)$` | file, line, message |
| `test` | `^\s*\d+\s*-\s*(\S.+?)\s+\((Failed\|Timeout\|Exception\|Not Run\|Subprocess aborted)\)\s*$` OR a line containing `***Failed` / `***Timeout` / `***Exception` | name (or whole line), status |
| `python` | multi-line — see § 3.3 | file, line (deepest frame), message (exception line) |

Classification is by **try-order**, not mutual exclusion: a line is
classified by the **first** category (in the table order above) whose
anchor matches, and is never double-counted. In practice the two
`file:line` categories don't overlap — `compiler` requires the literal
`error:` keyword; `lint` requires a `[A-Z]{1,5}\d{1,4}` rule-code token
right after the column (a ruff `E501` line has no `error:`; a GCC
`error:` line has no rule-code token in the code position) — but the
guarantee that protects a hypothetical dual-match line is the
compiler-before-lint ordering, NOT a claim that the regexes are
provably disjoint.

Path capture: the non-greedy `(\S.*?)` before `:(\d+):` lets the
`:(\d+):` anchor lock onto the real line-number colon, so a path that
itself contains a colon (`./a:b.cpp:5: error: …`) is captured whole —
the engine backtracks the path forward to the first `:(\d+):` it can
satisfy.

`test` captures: the block-line form (`N - name (Status)`) sets
`message` = the captured test name and `text` = the trimmed line; the
marker form (a line containing `***Failed` / `***Timeout` /
`***Exception`) sets `message` = `text` = the trimmed line. Both use
`category:"test"` with empty `file`/`line`.

### 3.3 Multi-line: Python tracebacks

A deterministic single-pass state machine, entered when a line's
trimmed value is exactly `Traceback (most recent call last):`. While in
traceback mode, each following line is one of:

1. **Frame** — matches `^\s+File "(.+?)", line (\d+)(?:, in .+)?$`.
   Record it as the current frame (the **last** frame recorded wins =
   deepest call = where it raised). Stay in mode.
2. **Indented non-frame** — matches `^\s+\S` (a source-echo line like
   `    x = compute()`, or a caret line). Ignored; stay in mode.
3. **Anything else (the first non-indented line, including blank)** —
   ends the block. If that line matches the exception shape
   `^([A-Za-z_][\w.]*)(?::\s*(.*))?$` (a bare or dotted exception name,
   optionally `: message`), it is the exception: emit ONE
   `ErrorEntry{category:"python", file/line = last frame, message =
   the trimmed terminating line, text = same}`. Otherwise (blank line,
   or unrelated output) emit ONE entry with `message` = `text` = the
   last frame's `File …` text (so a block with frames but no
   recognisable exception is not silently dropped), and the
   terminating line is left for the main loop to classify normally (it
   is not consumed as part of the traceback).

A traceback with the anchor but zero frames before it ends emits no
entry (nothing to report). Chained tracebacks (`During handling of the
above exception, another exception occurred:` between two blocks) emit
one entry per `Traceback (most recent call last):` anchor: the
`During handling…` line is a non-indented non-exception line that
closes the first block, and the next anchor opens the second.

### 3.4 Result ordering, caps, RAM

- Errors are emitted in scrollback order (top-to-bottom of the scanned
  window = oldest-to-newest), so the **last** entry is the most recent
  failure on screen.
- `maxResults` default 50. When more than `maxResults` are found, the
  array keeps the **last** `maxResults` (the most recent — drop from
  the front), sets `truncated:true`, and `errorsTotal` carries the
  full pre-cap count. Rationale: "what just broke" wants the newest,
  not the oldest, when capped.
- Memory: one streamed pass; a small ring of at most `maxResults`
  entries (each ≤ ~1 KiB). No persistent state. Peak ≤ ~100 KiB at
  the default cap plus the input string the handler already holds.

### 3.5 MCP wiring

- `RemoteControl::cmdRecentErrors(const QJsonObject &req) ->
  QJsonDocument`, declared public in `remotecontrol.h` next to
  `cmdGetText`; defined in `remotecontrol.cpp` with an `ANTS-1301`
  anchor comment. Resolves the target terminal with the **same chain
  as `cmdGetText`** (ANTS-1392): explicit `tab` (int) →
  `terminalAtTab`; else `caller_cwd` → `terminalForCaller` (falls
  back to the focused terminal). Reads `recentOutput(lines)` (default
  500, clamp 1..10000, non-positive → default), passes the string to
  `ScrollbackErrors::parse`, serialises the result. `max_results` is
  passed through to `Options.maxResults` (the lib clamps: ≤ 0 →
  default 50, > 1000 → 1000); like `lines`, it is clamped, never
  refused. When no terminal resolves it refuses with
  `code:"no_window"`. Note `cmdGetText`
  emits this same condition codeless (`{ok:false, error}`);
  `recent_errors` copies the resolution *logic* but upgrades the
  refusal *envelope* to carry the structured code per
  `mcp-error-codes.md`.
- MCP-only (mirrors `get_scrollback`): **no** IPC `dispatch()` branch
  and **no** `CLAUDE.md` `remotecontrol` verb-list line — unlike
  `get-text`, which has both. Registered in
  `MainWindow::setupClaudeMcpProviders` via `registerToolProvider`
  with `CallerCwdContract::TabSpecific`, delegating to
  `cmdRecentErrors` (lambda hands `args` straight to the handler, so
  ANTS-1642 dispatch-forward is satisfied via INV-2).

### 3.6 Envelope

```json
{ "ok": true,
  "errors": [
    {"category":"compiler","file":"src/foo.cpp","line":42,"column":17,
     "message":"'x' was not declared in this scope",
     "text":"src/foo.cpp:42:17: error: 'x' was not declared in this scope"},
    {"category":"python","file":"app/run.py","line":88,
     "message":"KeyError: 'name'",
     "text":"KeyError: 'name'"} ],
  "errors_count": 2, "lines_scanned": 500, "truncated": false }
```

Struct→wire renames: `errorsTotal` → `errors_count`, `linesScanned`
→ `lines_scanned`. `file`/`line`/`column` are omitted from an entry
when empty/zero. Empty result is `ok:true` with `errors:[]` — "no
errors on screen" is a valid answer, not a refusal.

### 3.7 Refusal codes

| code | when |
|------|------|
| `no_window` | `tab` given but no terminal at that index, OR no terminal resolves at all (no `tab`, no `caller_cwd` match, no focused tab). Reuses the resource-state code from `mcp-error-codes.md` § 2 ("No focused tab when one was needed") — the purpose-built code for exactly this miss; no new code added. |

`lines` / `max_results` are clamped, never refused (matches
`cmdGetText`'s lenient numeric handling). `caller_cwd` absence is
allowed (TabSpecific tools fall back to the focused tab); the
dispatcher does not force `caller_cwd_required`.

### 3.8 Edge cases

| Input | Behaviour |
|-------|-----------|
| Empty scrollback / no matching lines | `ok:true`, `errors:[]`, `errors_count:0`, `lines_scanned` = lines read. |
| > `max_results` matches | keep the last `max_results` (newest), `truncated:true`, `errors_count` = pre-cap total. |
| Truncated-at-top traceback (anchor scrolled off) | not entered — without the `Traceback (most recent call last):` anchor the block never starts (documented limitation, § 6). Raise `lines` to capture it. |
| A line matching two categories | the first category in the § 3.2 try-order wins; the line is not double-counted. |
| ANSI escape sequences in scrollback | `recentOutput` returns already-rendered cell text (`lineText` joined with `\n` — no SGR/OSC bytes), so the parser sees clean text. |
| CRLF / trailing `\r` | `parse` splits on `\n` and strips a single trailing `\r` per line before matching, so `$`-anchored patterns hold even if fed CRLF text directly (the `recentOutput` source is already `\n`-only; this is defensive for direct-string callers/tests). |
| Non-indented output interleaved between traceback frames | ends the traceback block early (treated as the terminating line per § 3.3) — captured-stdout printed mid-traceback is a documented limitation. |
| Non-positive `lines` | falls back to the 500 default (mirrors `cmdGetText`). |

## 5. Memory & cost budget

- Per call: one `QString` (the scrollback window the handler already
  read for `get_text`-class tools), one `QVector<ErrorEntry>` capped at
  `maxResults`, one `QJsonDocument`. No persistent state, no cache.
- Worst-case heap: `maxResults` entries × (≤ 1 KiB) ≈ ≤ 50 KiB at the
  default cap, plus the input string (≤ the `get_text` 1 MiB window).
- Time: single pass over ≤ `lines` (default 500, cap 10000) lines;
  sub-millisecond on a 500-line window. The per-line regex set is
  small and possessive where it matters.
- The default scan window is 500 lines, not the full scrollback —
  "what just happened" lives in the recent tail; scanning 50 K lines
  would cost tokens and time for stale errors. Caller raises `lines`
  when they need deeper history.

## 6. Out of scope

- Compiler **warnings** (`warning:`) — `build_status` (ANTS-1299)
  already surfaces `warnings_count` from recorded build output;
  `recent_errors` stays errors-only to avoid drowning the signal.
- Authoritative ctest parsing — `test_results` (ANTS-1300) is the
  dedicated ctest parser (op=record). `recent_errors`' `test`
  category is a quick on-screen heuristic, not a replacement.
- bandit's two-line `>> Issue:` / `Location:` format, mypy, eslint,
  Go `panic:`, Rust `error[E…]` multi-line, Java stack traces — v1
  covers the project's own toolchain (C++/Python/Lua/ctest/ruff);
  more language banks are a follow-up.
- A traceback whose `Traceback (most recent call last):` anchor has
  scrolled off the top of the scanned window — the block is not
  entered (raise `lines` to capture it).
- De-duplication of identical repeated errors (a build that prints the
  same `error:` 5×) — each occurrence is one entry; the `maxResults`
  cap bounds the count.
- Project-relative path normalisation — `file` is reported exactly as
  the tool printed it (relative or absolute); the caller resolves.
