## 1. Problem

The Roadmap dialog's CSS font sizes and per-card paddings are
currently hard-coded to a single "cozy" tier (e.g. `body 13px`,
`h1 16px`, `rm-state-label 10px`, `rm-card padding:4px 8px`). At
the time of writing the embedded CSS block at
`src/roadmapdialog.cpp:1054-1101` emits **19 `font-size:NNpx`
declarations across 5 distinct px values** (`10`, `11`, `12`, `13`,
`16`) — verified by `grep -oE "font-size:[0-9]+px"` against that
range. Two distinct user populations miss the tier they want:

1. **Laptop / sidebar users** want a *compact* tier so more cards
   fit per viewport. Linear, GitHub Projects, and Material 3 all
   ship a compact density specifically for this workflow.

2. **Big-monitor users** and **low-vision users** want a
   *comfortable* tier with larger type + more vertical headroom.
   The dialog already respects system font scaling (Qt picks up
   `xdg-desktop-portal`'s font-DPI), but system-wide scaling
   trades terminal legibility for dialog legibility — a Roadmap-
   local density toggle decouples them.

The bullet's verbatim hint reads: "Driven by CSS class on the
dialog root: `compact` 10/11/12px, `cozy` (current default)
12/13/14px, `comfortable` 14/15/16px with more vertical padding."
**Those three-number triples are approximations.** The actual cozy
CSS at `src/roadmapdialog.cpp:1054-1101` reads across 5 distinct
px values (10, 11, 12, 13, 16) — not just 12/13/14. This spec
refines those approximate tier values into the exact per-CSS-class
px values that map onto the existing renderer's CSS literals (see
§ 2.f table for the full mapping), plus a small padding/margin
scale, plus a persistence slot and a UI surface.

User-impact: this is purely visual; no filter/search/Kind
semantics change. Density is a per-user preference (not per-tab,
not per-preset), stored once in `~/.config/ants-terminal/config.json`
under a new key.

## 2. Mechanism — what was investigated, what was chosen

### 2.a Rejected — `QFont` pointSize on the QTextBrowser

`m_viewer->setFont(QFont("sans-serif", N))` only scales any text
that doesn't have an explicit CSS `font-size`. Every Roadmap CSS
class already pins a px size — so the QFont default would scale
nothing visible. Result: cards stay cozy regardless of the QFont.
Also: QFont's point-size is DPI-aware, which would re-scale at
every monitor change and surprise users who set "compact" on
their laptop and then docked to an external display.

### 2.b Rejected — `QTextBrowser::setZoomFactor()`

`setZoomFactor(0.85)` / `setZoomFactor(1.15)` would uniformly
scale text, images, and tables. Drawbacks:

- Doesn't persist across opens. Would need a persistence slot
  anyway — same surface as the chosen approach, weaker UX
  (numeric step vs named tier).
- Scales images and inline emoji along with text. Compact (0.85)
  ends up blurry on the 16-px state-icon glyphs that Roadmap
  cards lead with.
- Doesn't proportionally adjust `padding:` or `margin:` — at
  0.85 zoom the cards look squeezed (text shrinks but gaps don't).

### 2.c Rejected — System font scaling only

Users could already scale the whole desktop via
KDE/GNOME/Plasma's font-DPI control. But that scales every
application — terminal, AI dialog, status bar — to match the
Roadmap. We want decoupling: a Roadmap-only density tier without
making the terminal text wider.

### 2.d Rejected — Single root CSS class with all three tier rules emitted

`<body class="density-cozy">` plus `.density-compact .rm-summary
{ ... }` rules in the embedded `<style>` block. Cleaner CSS, but
Qt's `QTextDocument` HTML/CSS subset historically struggles with
descendant selectors past one level — `.density-compact
.rm-card-summary` is not guaranteed to match. Verified Qt docs at
<https://doc.qt.io/qt-6/richtext-html-subset.html> list only a
limited CSS subset (no compound descendant selectors). Plus
emitting three tiers' worth of rules trebles the CSS payload
when only one tier is active per render.

### 2.e Chosen — emit one tier's px values directly into the CSS block

`renderCardsHtml` already regenerates the entire HTML document
every render (preset change, filter change, search change,
file-watcher change). Adding the active density to the cache key
is one byte. The CSS block emits exactly the active tier's px
values — same shape as today, only the literals change.

Implementation surface (delta only):

1. New `enum class Density { Compact, Cozy, Comfortable };` next
   to `Preset` in `src/roadmapdialog.h`.
2. New `Density density;` field on `CardRenderOptions` whose
   default value is `Density::Cozy` (so `CardRenderOptions{}`
   produces byte-equal output to today's renderer — § 3.a names
   the two equivalent ways to spell that default).
3. `renderCardsHtml` looks up a file-scope `kDensityTable[3]`
   array of `DensityTier { int body; int h1; int h2; int h3; int
   h4; int meta; int state; int code; int cardPaddingY; int
   cardPaddingX; int cardMarginY; int pMargin; }` and inlines
   the active tier's values via `QString::arg` (the existing
   substitution mechanism for the theme-colour args). § 3.b makes
   this the required emission strategy because INV-1's byte-equality
   contract is sensitive to layout differences that string
   concatenation could introduce.
4. New `roadmapDensity` Config key (string: `"compact"` /
   `"cozy"` / `"comfortable"`). Read in `RoadmapDialog`
   constructor; written by the density combo's `currentIndexChanged`
   slot. Unknown / missing value → `"cozy"` (graceful fallback).
5. UI: one `QComboBox` ("Density: Compact / Cozy / Comfortable")
   appended to `filterRow` after the existing
   `filterRow->addStretch(1);` at `src/roadmapdialog.cpp:1675`.
   The stretch is **retained**; the combo sits flush-right after
   the stretch, so the row flows
   `[5 checkboxes] [stretch(1)] [density combo]`. Combo signal
   triggers `rebuild()`.

### 2.f Density tier table

Each tier is a uniform shift on the per-class CSS literals.
"Compact" is `-2px` on the body / state / section / body-line
font sizes and `-1px` on the meta tier (the meta tier is already
at 10/11px in cozy). The meta + `.rm-state-label` groups are floored
at 11px (ANTS-2211, raised from 9px for readability); no other value
drops below 10px.

| CSS class                                           | Compact | **Cozy** *(default)* | Comfortable |
|-----------------------------------------------------|--------:|---------------------:|------------:|
| `body`, `.rm-summary`, `.rm-state`, `.rm-section-toggle`, `.rm-body-first`, `.rm-body-line` | **11px** | **13px** | **15px** |
| `h1`                                                | **14px** | **16px** | **18px** |
| `h2`                                                | **11px** | **13px** | **15px** |
| `h3`                                                | **10px** | **12px** | **14px** |
| `h4`                                                | **10px** | **11px** | **13px** |
| `code`, `.rm-toggle`, `.rm-id`, `td`, `th`         | **10px** | **12px** | **14px** |
| `.rm-state-label` *(at Compact, floored equal to the meta tier — ANTS-2211)* | **11px** *(floor)* | **10px** | **12px** |
| `.rm-kind`, `.rm-section-counts`, `.rm-parent`, `.rm-date` | **11px** *(floor, ANTS-2211)* | **11px** | **13px** |
| `.rm-card` padding                                  | **2px 6px** | **4px 8px** | **6px 12px** |
| `.rm-card` margin                                   | **1px 0** | **2px 0** | **4px 0** |
| `p` margin                                          | **1px 0** | **3px 0** | **5px 0** |
| h1-h4 margin                                        | **2px 0 1px 0** | **4px 0 2px 0** | **6px 0 4px 0** |
| `.rm-body-first` padding-top                        | **2px** | **4px** | **6px** |
| `.rm-body-first` margin-top                         | **1px** | **2px** | **3px** |

Verification: every cozy column value above was read from
`src/roadmapdialog.cpp:1054-1101` (the 19 `font-size:NNpx`
declarations + the listed `padding:`/`margin:` literals) on
2026-05-11. Compact and Comfortable columns are derived; no
current renderer reads them yet.

**Fixed across densities** (intentionally NOT in the tier table):

- Inline-spacing constants between elements on one row:
  `.rm-state padding-right:6px`, `.rm-state-label padding-right:6px`,
  `.rm-kind padding-right:6px`, `.rm-toggle padding-left:12px /
  padding-right:4px`, `.rm-id padding-left:8px`, `.rm-date
  padding-left:6px`, `.rm-section-toggle padding-right:12px /
  padding-left:4px`, `.rm-section-counts padding-right:10px`,
  `.rm-parent padding-left:8px`, `.rm-body-first padding-left:20px`,
  `.rm-body-line padding-left:20px`.
- Table cell padding (`td,th { padding:2px 6px; }`) — gridlines
  read uniformly regardless of tier.
- Inline-code chip padding (`code { padding:0 4px;
  border-radius:3px; }`) — chip shape, not vertical rhythm.
- Card visual accents (`border-left:3px solid`,
  `.rm-card.rm-current { background:rgba(229,194,74,0.08); }`,
  `.rm-body-first { border-top:1px dotted; }`) — colours and
  accents, not metric quantities.

Inline spacings stay fixed because they're sized by the *content*
they separate (an emoji + a 12-px chip + a number), not by the
density tier's vertical rhythm. Future implementer: if a feedback
loop later argues for tier-scaling some of these (e.g. `code`
padding feels squeezed at Comfortable), promote them into the
table and add a regression test.

### 2.g Sub-options considered but rejected at the design step

- **Per-preset density** — different density per Full/Current/
  Next tab. Rejected: a user's "compact" preference is about
  *their screen*, not the content of a given preset.
- **Density keyboard shortcut** — e.g. `Ctrl++` / `Ctrl+-`.
  Deferred to follow-up; the cheatsheet (ANTS-1236) gains the
  combo's existence as an entry, not a shortcut.
- **A fourth "ultra-compact" tier** at 9/10/11px. Rejected:
  going below the Compact tier's 11px meta/label floor (ANTS-2211,
  raised from 9px) makes meta unreadable on the dev workstation +
  three tested themes.
- **CSS rems / em units** in place of px. Qt's `QTextDocument`
  HTML subset does not reliably support `rem`. `em` works
  (relative to parent), but most existing rules are already px;
  changing all of them mid-flight is a bigger refactor than the
  feature warrants.

3.b `src/roadmapdialog.cpp`

  - File-scope `kDensityTable[3]` constant array (in the existing

3.h Failure modes

  - **Config write fails** (full disk, EACCES on
    `~/.config/ants-terminal/config.json`, JSON serialise error):
    `Config::setRoadmapDensity(...)` returns silently — the call
    is fire-and-forget. The live `m_density` still advances; the
    next render reflects the new tier. On next launch the on-disk
    value (the pre-failure state) is what `Config` reads back.
    No error popup. Same contract as every other `roadmap*`
    setter, locked by INV-9 / test 5.g.
  - **`m_config == nullptr` at combo construction:** undefined.
    `RoadmapDialog`'s constructor takes `Config *config` and
    every existing accessor (e.g.
    `m_config->roadmapActivePreset()`) is uncondition-ally
    de-referenced. A null `m_config` is a constructor-precondition
    violation — no defensive null-check is added for the new
    `roadmapDensity()` call either. The dialog has never been
    constructible with a null `Config` and this spec does not
    change that.
  - **Two parallel `RoadmapDialog` instances** (theoretically
    possible if a future feature opens a second dialog before the
    first closes — currently the dialog is single-instance
    `Help → Roadmap…`): both combos write to the same JSON file
    on each combo change; last-writer-wins. Both instances'
    live `m_density` advance independently. Acceptable: the
    value is one of three known strings, the user sees consistent
    UX within each instance.
  - **`indexToDensity(-1)`** (QComboBox emits -1 when its model
    is cleared): clamped to `Density::Cozy` per the helper's
    contract in § 3.a. `indexToDensity(3)` or larger: same
    clamp. No exceptions thrown.

## 5. Acceptance tests

`tests/features/roadmap_density/` — one spec.md plus the test
source files below, all wired into `tests/CMakeLists.txt`. The
renderer-side tests (5.a, 5.b, 5.e) link the existing
`src/roadmapdialog.cpp` + `src/config.cpp` + `src/themes.cpp`
objects in a GUI-free build (no QApplication, no QTextBrowser
construction). The state-preservation tests (5.d, 5.f, 5.g) need
a `QApplication` for QComboBox + QCheckBox construction; they go
in the same bundle but run cleanly under `QT_QPA_PLATFORM=
offscreen` (the test runner already exports this).

5.a `test_density_default_byte_equal.cpp` — covers **INV-1**.
Renders one fixture twice: the first with a default-constructed
`CardRenderOptions o1;`, the second with an explicit-cozy
`CardRenderOptions o2; o2.density = Density::Cozy;`. Calls
`renderCardsHtml(..., o1)` and `renderCardsHtml(..., o2)`.
Asserts the two `QString`s compare `==`. Failure mode: cozy
default drifted away from the pre-1238 baseline.

(Note: member assignment, not designated initializer. The
`CardRenderOptions{ .density = … }` form is not valid because
the struct has a user-provided default ctor — see INV-1 row of
§ 4 and `src/roadmapdialog.h:183`.)

5.b `test_density_three_tiers_distinct.cpp` — covers **INV-2 +
INV-8**. For the same fixture, renders three outputs, one per
density. Asserts:
  - (INV-2 pairwise distinct) all three are pairwise `!=`.
  - (INV-2 sentinels) `compact.contains("h1{font-size:14px;}")` AND
    `!cozy.contains("h1{font-size:14px;}")` AND
    `!comfortable.contains("h1{font-size:14px;}")` — i.e. the
    Compact h1 rule is Compact-only (ANTS-2211 raised the meta/label
    floor 9px→11px, retiring the old 9px sentinel). Repeat for
    `font-size:16px` (Cozy-only) and `font-size:18px` (Comfortable-only).
  - (INV-8) every `font-size:N` captured by `QRegularExpression`
    has N ≥ 9, across all three outputs.

5.c `test_density_config_roundtrip.cpp` — covers **INV-3 + INV-4**.
Uses a temp `Config` backed by `QTemporaryFile`. For each name in
`{"compact", "cozy", "comfortable"}`: write via setter, re-read,
assert equal. Then write each of `{"", "humungous", non-string-
JSON}` and assert getter returns `"cozy"`. Then delete the key
and assert getter returns `"cozy"`.

5.d `test_density_state_preservation.cpp` — covers **INV-5**.
Constructs a `RoadmapDialog` under `offscreen` QPA. Seeds
`m_expandedItems`, `m_expandedSections`, `m_tableSections`,
`m_searchBox` text, `m_kindFilter`, two of the five filter
checkboxes' checked-state, and `m_activePreset`. Reads all eight
state values into a snapshot. Calls
`m_densityCombo->setCurrentIndex((m_density == Compact) ? 2 : 0)`
to force a density flip + `rebuild()`. Re-reads the eight values
and asserts byte-equal against the snapshot.

5.e `test_density_content_unaffected.cpp` — covers **INV-6**.
Renders the same fixture markdown through `renderCardsHtml` three
times (one per density). For each output, strips the embedded
`<style>...</style>` block via regex
`QRegularExpression("<style>.*?</style>",

## 7. Memory + render-time budget

Per the cold-eyes-feedback memory: every new feature names its
memory cost at design time.

- **Persistent (per-config):** one JSON string key,
  `"roadmap_density"`. Worst case 12 bytes (`"comfortable"` +
  quote overhead) on disk in `~/.config/ants-terminal/config.json`
  (the project uses raw JSON, not `QSettings`), ≤ 50 B in the
  `Config` in-memory cache.
- **Per-dialog runtime:** one `Density` enum (1 B + padding) on
  the dialog and inside `CardRenderOptions`. One `QComboBox *`
  pointer (8 B on 64-bit). The combo widget itself: ~few hundred
  B for QComboBox + three QStandardItems.
- **Per-render delta:** density influences the emitted CSS string
  literals only. The CSS block is ~3 KB in cozy today; compact
  shaves ~30 B (smaller numbers), comfortable adds ~30 B. The
  rendered HTML body for the full Roadmap (8800-line markdown)
  is ~ 1.5 MB regardless of density — only the embedded
  `<style>` block differs. Net per-render swing: **≤ 60 B**.
- **Cache impact:** the existing `m_lastHtml` dedup at
  `src/roadmapdialog.cpp:2506` is a **full-string `operator==`
  equality check** on the previously-emitted HTML, not a keyed
  cache. Density appears as a byte-level difference inside the
  emitted CSS, so a density change naturally invalidates the
  cache via inequality. No schema change to `m_lastHtml` is
  needed.
- **No new allocations on the hot path.** No new threads, no new
  timers, no new file I/O. Density change → `rebuild()` → exactly
  the same render path the dialog already uses for preset / filter
  / search changes.
- **Render-time budget:** the per-density CSS rebuild adds zero
  algorithmic cost — same `renderCardsHtml` walk, only the
  integer arguments to `QString::arg` differ. The marginal
  contribution to the per-render wall time is bounded by the
  cost of 8-12 extra integer→string substitutions inside one
  `QString::arg` chain (sub-microsecond). The dominant render
  cost remains the `renderCardsHtml` markdown walk + Qt's
  `QTextDocument::setHtml` parse, both of which are unchanged.
  Compact renders **more cards visible per viewport scroll
  position** (smaller fonts → more rows fit), which marginally
  increases the per-paint cost inside Qt's text-layout pass —
  but per-frame paint is dominated by `QTextDocument::draw` over
  the visible region, not by total card count, so the increase
  is below the user's perception threshold.

The combo's compact width (~120 px) sits on the right of

`[5 checkboxes: ✅ Shipped, 📋 Planned, 🚧 In progress, 💭
Considered, Currently being tackled] [stretch(1)] [Density combo]`
— stretch is retained. On a window narrower than the sum of all
checkbox widths + combo width, Qt's `QHBoxLayout` will compress
the stretch first and squeeze the combo to its `sizeHint`. The

and restored on launch; no explicit `setMinimumWidth` is added
by this feature, but the saved geometry (~960 px) keeps the
single-row layout at the user's last-used dimensions.

## 9. Re-open conditions

If after the spec ships and the feature lands, any of the below
happens, the bullet is re-opened with a new sub-spec:

1. **Density keyboard shortcut requested.** v1 ships mouse + Tab
   focus only. If user feedback asks for `Ctrl++` / `Ctrl+-` /
   `Ctrl+0` (or platform equivalent), a follow-up bullet lands
   the shortcut + adds three rows to `kRoadmapShortcuts[]`.
2. **A fourth density tier needed.** If a user reports that
   compact is still too tall on a 13" laptop or comfortable
   still too small on a 4K monitor, consider an "ultra-compact"
   or "huge" tier. Floor at 11px (ANTS-2211, raised from 9px) stays; "huge" could go to
   17/18/20px.
3. **Per-theme density default.** If a specific theme renders
   inconsistently across densities (e.g. light themes look
   washed at compact + low contrast), per-theme density default
   becomes useful. Not v1.
4. **Density affects content density** (e.g. compact hides
   `.rm-state-label` text and shows emoji-only). Bigger UX
   decision — re-open and design separately.
5. **Density should be per-tab.** Currently density is a
   user-global preference. If a user wants compact on `Full`
   and comfortable on `Current`, the persistence shape changes
   from one string to a QJsonObject keyed by Preset.

## 10. Out of scope

- Animation between density changes (the re-render is one shot).
- Per-card density overrides (everything in the dialog renders
  at one tier).
- Density-aware images / icons (none are emitted today).
- Touch-target densification (the dialog has no tap targets
  outside the existing toggle anchors + the standard window
  chrome).
- Changes to non-Roadmap dialogs (Audit, Settings, SSH, …) —
  each has its own font-size story; this spec only covers
  RoadmapDialog.
