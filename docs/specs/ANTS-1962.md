# ANTS-1962 — `feedback_log` MCP tool (append to a `*_Ants_MCP_Feedback.md` file)

**Status:** accepted (2026-06-03) — implemented on main, feature tests green (cold-eyes loops 1–4 folded). Amended 2026-06-30 (ANTS-3376 default-path derivation, INV-15; `dry_run` documented) and re-run through a fresh 4-loop cold-eyes pass — see § 8.
**Kind:** implement.
**Source:** ROADMAP.md ANTS-1962 (user-request-2026-06-03).
**Pairs with:** ANTS-1961 (`feedback_query`, the read counterpart — shares
the `FeedbackFile` module and the suffix guard); `roadmap_log` (the write
verb whose op-routing, allocates-no-IDs, append-at-end, atomic-write
design this mirrors).
**Format contract:** [`docs/standards/mcp-feedback-files.md`](../standards/mcp-feedback-files.md).

## 1. Problem

The write counterpart to `feedback_query`. Today a contributor session
adds feedback by hand-editing markdown at the shared root, and the
maintainer stamps the tracking table by hand-editing too. Both are
error-prone against the format contract (`mcp-feedback-files.md`): a
contributor can accidentally insert above a maintainer block (corrupting
the delta watermark), mis-shape a finding, or assign itself an
`ANTS-NNNN`; the maintainer can drop the `📋` anchor and silently break
every downstream `feedback_query`. A verb that renders the blocks from
structured args removes all of that.

**Layman:** lets any CC session add feedback to the shared report files,
and lets the maintainer session stamp a tracking block with roadmap IDs,
without hand-editing markdown.

## 2. Surface

  call has no matching branch (the `callerCwdContractFor` fall-through in

- Rendering is delegated to pure helpers in `FeedbackFile`

```cpp
namespace FeedbackFile {
struct Finding { QString title, what, repro, impact, suggestedFix; };
struct TrackingRow { QString item; QStringList ids; QString status, notes; };

QString renderFindingBlock(const QString &date, const QString &sessionLabel,
                           bool h1Heading, const QString &note,
                           const QVector<Finding> &findings);

                            const QVector<TrackingRow> &rows, bool sentinel);
QString skeleton(const QString &projectTitle); // marker + H1 + pointer blockquote
}
```

### 2.1 Common args + target resolution

- `caller_cwd` (Required), `path` (**optional** since ANTS-3376) —
  identical resolution + suffix guard to ANTS-1961 § 2.1, whose canonical
  home is `mcp-feedback-files.md` § "File location & name": the resolved
  basename must end in the exact case-sensitive `_Ants_MCP_Feedback.md`
  (else `not_feedback_file`); `PathValidation::validatePath(...,
  "feedback_log", "path", /*allowOutsideRoot=*/true)` (the 5-arg form,
  `src/pathvalidation.h:46-50`); traversal/malformed → `bad_path`. **When
  `path` is omitted** the verb derives the conventional
  `<caller_cwd-leaf>_Ants_MCP_Feedback.md` at the shared root (the parent
  of `caller_cwd`) and sets `path_derived:true` on the reply — so a
  first-time contributor log needs no filesystem hunt. Omitting `path`
  with no resolvable `caller_cwd` (nothing to derive from) → `bad_args`.
- `op` (string, required) — one of `append_finding` | `append_tracking`;
  unknown or absent → `bad_mode` (the `op` selector is the mode-enum, per
  the `mcp-error-codes.md` § 1 `bad_mode` code).
- `date` (string, optional) — `YYYY-MM-DD`. Defaults to the current local
  date (`QDate::currentDate()`). An explicit value must match
  `^\d{4}-\d{2}-\d{2}$` else `bad_args`. (Explicit `date` is the
  determinism seam for tests.)
- `dry_run` (bool, optional, default false; ANTS-2227) — render the block
  and compute the would-be `bytes_appended` / `created`, then return the
  preview envelope (§ 2.4) **without writing the file**. The preview
  carries `dry_run:true` and the same `path` / `path_derived` the real
  write would.

### 2.2 `op:"append_finding"` (contributor)

Args: `session_label` (string, optional — heading suffix),
`heading_level` (`"h1"`|`"h2"`, default `"h2"`), `note` (string,
optional — prose under the session heading), `findings` (array, **≥1**;
empty/absent → `bad_args`). Each finding: `title` (required, else
`bad_args`) + optional `what`, `repro`, `impact`, `suggested_fix`.

Renders (h2 default form):

```markdown
## 2026-06-03 — <session_label>

<note>

### <title>

- **What:** <what>
- **Repro:** <repro>
- **Impact:** <impact>
- **Suggested fix:** <suggested_fix>
- **Proposed ID:** _(maintainer to assign)_
```

- Only provided field bullets are emitted (an omitted `repro` drops the
  `**Repro:**` line). `**Proposed ID:**` is always emitted blank as the
  contributor reminder (the contributor never assigns an ID — INV-6).
- `heading_level:"h1"` emits `# 2026-06-03 — <label>` instead (the
  H1-dominant corpus form). When `session_label` is empty the heading is
  just the date.

### 2.3 `op:"append_tracking"` (maintainer)

Args: `note` (string, optional — prose before the table), `rows`
(array, **≥1**; empty/absent → `bad_args`), `sentinel` (bool, default
`true`). Each row: `item` (required), `ids` (array of `ANTS-NNNN`, may be
empty), `status` (required — an emoji from the machine-readable set),
`notes` (optional).

Renders the **recommended, fully-qualified** watermark form (the one the
ANTS-1961 anchor regex matches — see `mcp-feedback-files.md` § "Maintainer
tracking block"):

```markdown
## 📋 Ants Terminal roadmap tracking update (2026-06-03, maintainer)

<note>

| Item | ID(s) | Status |
|------|-------|--------|
| <item> | ANTS-1961, ANTS-1962 | 📋 |

End of 2026-06-03 maintainer roadmap-tracking update.
```

- `status` must be in the machine-readable set `{📋, 🚧, ✅, 💭, 🔄, ❓}`
  (the standard's `§ Status emojis` table + its "…are the machine-readable
  set" sentence) — else `bad_status`. The advisory `—`
  (no-evidence) value is **intentionally unwritable**: it saturates normal
  prose and is not machine-parseable, so use a populated status or omit
  the row.
- Each id in `ids` must match `^ANTS-[0-9]+$` else `bad_args`. An empty
  `ids` is allowed (a not-tracked row) and renders as the literal `n/a` in
  the ID cell. The standard's other ID-less parentheticals
  (`(self-resolved)`, `(schema fix)`, `(no roadmap item)` — in
  `mcp-feedback-files.md` § "Maintainer tracking block") are **out of
  scope** for v1 — record that reason in the row's `notes` field (which
  the parser ignores), not the ID cell. An `n/a` row still advances the
  watermark (empties the delta) but contributes **no** `mapped_ids` — only
  rows carrying an `ANTS-NNNN` add to the reader's mapped-ID set.
- A `Notes` 4th column is added (for all rows) iff any row supplies
  `notes`; otherwise the 3-column form is used. When the column is added,
  a row without `notes` renders an empty cell (so the GFM table stays
  well-formed — every row has the same column count).
- `sentinel:false` drops the trailing `End of … update.` breadcrumb (it
  is advisory only — the delta is computed from heading position).

### 2.4 File handling

- **Append-at-end, always.** Both ops read the existing file, ensure it
  ends with a blank-line separator, and append the rendered block at EOF.
  There is no position arg — so a contributor structurally *cannot* insert
  above a maintainer block, satisfying the standard's append-at-end rule
  by construction.
- **Absent file:** `append_finding` creates it with `FeedbackFile::skeleton`
  (the `<!-- ants-mcp-feedback: 1 -->` marker + the literal H1
  `# Ants MCP Feedback — <Project>` + the contributor-pointer blockquote;
  `<Project>` derived from the basename minus the `_Ants_MCP_Feedback.md`
  suffix — the standard's H1 is free-form, `mcp-feedback-files.md`
  § "File skeleton", so the derived title need not match any prior
  convention). `append_tracking` on an absent file refuses `not_found` —
  there is nothing to triage; that envelope carries the ANTS-3366
  `candidates` list (+ `hint`, and `all_other_projects:true` whenever the
  caller's leaf matches no sibling — not specifically a derived-path miss)
  exactly as ANTS-1961's `not_found` does (shared `fbNotFound` helper).
- **Read failure:** if the existing file cannot be opened for the
  append-step read, the verb refuses `read_failed` (a rare I/O path,
  distinct from `write_failed`).
- **Atomic:** write via `QSaveFile` (the `cmdRoadmapLog` atomic-write
  pattern); a failed write leaves the original file byte-for-byte
  untouched and returns `write_failed`. A test-only failure seam
  (`setForceFeedbackWriteFailForTest`, mirroring the
  `g_forceCounterCommitFail` convention in `src/remotecontrol.cpp` — cite
  by symbol; line numbers drift) calls `cancelWriting()` so the temp file
  is discarded (never committed) and T8 can assert atomicity. Default file
  permissions (these are shared, same-user markdown files — NOT 0600
  config files).
- Success response: `{ok:true, op, path, bytes_appended, date,
  created:<bool>}` (plus `path_derived:true` when the path was derived —
  INV-15). The `dry_run` preview is the same shape with an added
  `dry_run:true` and no on-disk write.

## 3. Invariants

- **INV-1** — `feedback_log` only ever **appends at EOF**; it never
  inserts above an existing block and never edits, reflows, or deletes
  existing content. *Test:* T7.
- **INV-2** — Suffix guard shared with ANTS-1961: resolved basename must
  end in the exact case-sensitive `_Ants_MCP_Feedback.md`, else
  `not_feedback_file`. *Test:* T5.
- **INV-3** — A supplied `path` is routed through
  `PathValidation::validatePath` with `allowOutsideRoot=true`;
  traversal/malformed → `bad_path`. `path` is **optional** (ANTS-3376,
  INV-15): when omitted the verb derives
  `<caller_cwd-leaf>_Ants_MCP_Feedback.md` at the shared root (parent of
  `caller_cwd`); only when there is no resolvable `caller_cwd` to derive
  from does omitting it refuse `bad_args`. *Test:* T5, T9.
- **INV-4** — `caller_cwd` is Required (empty → `caller_cwd_required`).
  *Test:* T5.
- **INV-5** — `op` ∈ {`append_finding`, `append_tracking`}; unknown or
  absent → `bad_mode`. *Test:* T5.
- **INV-6** — `append_finding` requires ≥1 finding (else `bad_args`) and
  each finding a non-empty `title` (else `bad_args`); it renders a dated
  session heading (`## ` default, `# ` when `heading_level:"h1"`) + one
  `### <title>` sub-block per finding, emitting only provided field
  bullets plus an always-blank `**Proposed ID:**` line. *Test:* T1, T5.
- **INV-7** — `append_tracking` requires ≥1 row (else `bad_args`) and
  renders the fully-qualified watermark heading `## 📋 Ants Terminal
  roadmap tracking update (<date>, maintainer)` + a mapping table. *Test:*
  T2, T4.
- **INV-8** — A tracking row `status` must be in `{📋, 🚧, ✅, 💭, 🔄, ❓}`
  (else `bad_status`); the advisory `—` is unwritable; each `ids` entry
  must match `^ANTS-[0-9]+$` (else `bad_args`); an empty `ids` is allowed
  and renders `n/a`. *Test:* T4, T5.
- **INV-9** — `date` defaults to the current local date; an explicit
  `date` must match `^\d{4}-\d{2}-\d{2}$` (else `bad_args`). *Test:* T5.
- **INV-10** — `append_finding` creates an absent file with a conforming
  skeleton (marker + H1 + pointer blockquote); `append_tracking` refuses
  `not_found` on an absent file, the envelope carrying the ANTS-3366
  `candidates` + `hint` sibling list (shared `fbNotFound`). *Test:* T5, T6.
- **INV-11** — Writes are atomic (`QSaveFile`); a failed write leaves the
  original untouched and returns `write_failed`. *Test:* T8.
- **INV-12** — Round-trip: after `append_finding`, the new findings appear
  in `FeedbackFile::parse`'s delta; after `append_tracking`, the watermark
  advances and the delta empties — i.e. the rendered tracking heading
  matches the ANTS-1961 anchor regex exactly (the writer emits precisely
  what the reader recognises). *Test:* T3.
- **INV-13** — `renderFindingBlock`, `renderTrackingBlock`, and `skeleton`
  are pure functions in `ants_core_lib`, unit-testable without the MCP
  layer. *Test:* T1, T2, T4 drive them directly.
- **INV-14** — A successful call returns `{ok:true, op, path,
  bytes_appended, date, created}` (`created:true` only when
  `append_finding` created an absent file), plus `path_derived:true` when
  the path was derived (INV-15). The `dry_run` preview (§ 2.1) returns the
  same shape with `dry_run:true` added and no write — and propagates the
  same `path_derived` flag through the shared resolution path. *Test:* T1,
  T6, T9 (real-write envelope), T10 (dry_run preview: `path_derived`
  propagated, nothing written).
- **INV-15** (ANTS-3376) — When `path` is omitted, the verb derives
  `<caller_cwd-leaf>_Ants_MCP_Feedback.md` at the shared root (the parent
  of `caller_cwd`) and sets `path_derived:true`; with no resolvable
  `caller_cwd` it refuses `bad_args`. `append_finding` on a derived,
  not-yet-existing path creates it exactly as for an explicit path (INV-10);
  `append_tracking` on a derived absent path still refuses `not_found` with
  the ANTS-3366/3376 candidate list (own file first, or
  `all_other_projects:true`). *Test:* T9.

## 4. RAM / build cost

- The render helpers and `skeleton` are pure in-memory string builders;
  the only retained-for-the-call buffer is the existing file content read
  to append onto, bounded by the file size. No cache, no retained state.
- New sources `src/feedbackfile.{h,cpp}` are shared with ANTS-1961 and
  join the existing `ants_core_lib` — **no new build target**. The
  feature-conformance test joins an existing `tests/features/*` bundle.
  External libs: none beyond Qt6 Core.

## 5. Out of scope

- ID allocation — `feedback_log` allocates no `ANTS-NNNN` (mirrors
  `roadmap_log`); the maintainer passes IDs explicitly in `rows[].ids`.
- Editing / amending existing blocks — append-only by design (INV-1).
- Auto-deriving the contributor `session_label` from the calling project
  — passed explicitly; absent → date-only heading.

Feature-conformance bundle `tests/features/mcp_feedback_log/`
(`spec.md` + `test_mcp_feedback_log.cpp`; label `features;fast`). Verify

- **T1** — `append_finding` with all fields renders the full template;
  omitting `repro` drops only the `**Repro:**` line; `**Proposed ID:**`
  always present and blank.
- **T2** — `append_tracking` renders the fully-qualified watermark; the
  rendered heading matches the ANTS-1961 anchor regex
  `^## 📋 Ants Terminal roadmap tracking( update)? \(`.
- **T3** — **round-trip (INV-12):** start from a fixture with a maintainer
  block + un-triaged findings → `feedback_query` returns a non-empty
  delta → `append_tracking` with a row carrying ≥1 `ANTS-NNNN` →
  `feedback_query` returns an empty delta and those IDs in `mapped_ids`.
  (An `n/a`-only tracking row would empty the delta but add no
  `mapped_ids` — the fixture uses an ID-bearing row to exercise both.)
- **T4** — empty `ids` row renders `n/a`; multi-id row renders
  `ANTS-1961, ANTS-1962`; a 4th `Notes` column appears iff any row has
  notes.
- **T5** — refusals: bad `op` → `bad_mode`; no findings → `bad_args`;
  finding with empty title → `bad_args`; bad status emoji → `bad_status`;
  `ids:["1234"]` (no `ANTS-` prefix) → `bad_args`; `date:"06-2026"` →
  `bad_args`; non-`_Ants_MCP_Feedback.md` path → `not_feedback_file`;
  `append_tracking` on absent file → `not_found`.
- **T6** — absent file + `append_finding` creates it with the marker
  comment, a derived H1, and the pointer blockquote; `created:true`.
- **T7** — append-at-end: an `append_finding` into a file that already
  ends with a maintainer block lands strictly below it (verified by
  `feedback_query` placing it in the delta) — never inserts above.
- **T8** — atomicity: the `setForceFeedbackWriteFailForTest` seam forces a
  write failure; the original file is left byte-identical and the verb
  returns `write_failed`.
- **T9** (ANTS-3376, `DerivesDefaultPathOnCreate`) — `append_finding` with
  `path` omitted and `caller_cwd` a project dir under a shared root creates
  `<leaf>_Ants_MCP_Feedback.md` at that shared root (`created:true`,
  `path_derived:true`, file on disk, finding present); omitting both `path`
  and a resolvable `caller_cwd` still refuses `bad_args`.
- **T10** (ANTS-3376 / ANTS-2227, `DryRunPreviewCarriesPathDerivedNoWrite`)
  — `dry_run:true` with an omitted `path` returns `dry_run:true`,
  `path_derived:true`, `created:true` (would-create) and a non-zero
  `bytes_appended`, while writing nothing to disk (the derived file does
