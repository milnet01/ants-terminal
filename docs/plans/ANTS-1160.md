# ANTS-1160 — Roadmap dialog redesign implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Redesign the Roadmap dialog and format per `docs/specs/ANTS-1160.md` (commit `844d13b`). Replace the wall-of-text HTML rendering with a card-based widget model; introduce universal `TASK-NNNN` IDs (preserving legacy `ANTS-NNNN`); fold three new `Kind:` values plus a `Layman:` field into the format spec; add five Phase-1 IPC verbs; ship the broader doc-tree alignment in lockstep so the rest of the project's docs reflect v2 reality.

**Architecture:** Markdown stays as the source of truth (no schema change). Dialog rewrites from `renderHtml → QTextBrowser` to a `QListView` with a custom `QStyledItemDelegate` that renders one card per actionable bullet (collapsed / open-Layman / open-Detail). Section headings render as their own collapsible row widgets. Filtering operates by inclusion (Tab × Kind × Status × Search compose with AND); transitive-parent inclusion fires off the Tab predicate only. Persistence migrates from single-key `Config::roadmap*` entries to a per-project TOML file at `~/.config/ants-terminal/roadmap-state.toml` keyed by SHA-1 of the project path. IPC verbs ride on the existing `remotecontrol.cpp` socket dispatch; allocation runs on a worker thread to avoid wedging the event loop.

**Tech Stack:** Qt 6, C++20, CMake. No new runtime dependencies. New `roadmap-state.toml` parsing leverages the existing `tomlplusplus` if present, or hand-rolled minimal TOML reader (the file is shape-controlled by us). Feature tests follow the project's `tests/features/<name>/spec.md + test_<name>.cpp` pattern per `tests/features/README.md`.

**Spec:** `docs/specs/ANTS-1160.md` (commit `844d13b`) is the source of truth for behaviour, acceptance criteria, IPC verb shapes, and the 11-criterion gate set. This plan describes execution order and per-task verification; consult the spec for any "what" question.

**Repo visibility:** PUBLIC. Per global rule §6, push freely after each phase ships green CI; no batching required.

**Buildable-state contract:** every task (or sub-task, where the task decomposes — P3.x and P4.x) produces a buildable tree (compiles + existing `ctest` green) unless explicitly noted otherwise. Commits land at task or sub-task boundaries depending on size. Acceptance criteria are verified at the end of the phase that ships them.

## Common task scaffold (referenced by P3.3, P3.4, P3.5, P4.1–P4.5)

Tasks P3.3 onward and P4.1 onward follow the same shape as P3.1/P3.2; rather than repeat the full body in each task, refer to this recipe and replace the placeholders. **An executor agent following this scaffold should produce structurally identical artifacts to what P3.1/P3.2 do explicitly.**

**Recipe per "TDD feature task":**

1. **Write `tests/features/<name>/spec.md`** — the human contract. Header: 1-paragraph problem framing. Body: the INV list (numbered, each one greppable from the test). Cross-link to ANTS-1160 §X.Y the test enforces. Mirror `tests/features/claude_statusbar_extraction/spec.md` for shape. Manual gate: declare presence/absence at top of file.

2. **Write `tests/features/<name>/test_<name>.cpp`** — runnable executable that exercises the feature. Two flavors:
   - **Pure-function INV tests** — drive `parseItems`, `renderHtml`, filter engine, validator, etc. directly with inline `QString` fixtures. Pattern: `#include` the public header, set up fixture, call function, assert with `must(cond, msg)` helper that exits 1 on fail. Compile-link only the source files exercised, not the whole `ants-terminal` target.
   - **Source-grep INV tests** — for "code shape" invariants (e.g. "regex literal contains `[A-Z]{3,6}`"). Pattern: `#define SRC_X_PATH` per file, `slurp()` helper, `find(...)` substring or count predicates. Mirror `tests/features/claude_statusbar_extraction/test_*.cpp`.

3. **Wire `CMakeLists.txt`** — `add_executable` + (for pure-fn tests) `target_link_libraries(... PRIVATE Qt6::Core Qt6::Gui Qt6::Widgets)` + `target_compile_definitions` for any `SRC_*_PATH` defines + `add_test(NAME features.<name>)` + `set_tests_properties(... LABELS "features;fast")`. Mirror the most recent `add_executable(test_*)` block; when in doubt, `claude_statusbar_extraction` is the model.

4. **Build the test target alone, run it, assert it FAILS** with a meaningful diagnostic naming the INV that failed. If it passes accidentally (e.g. behaviour already exists), the INV is wrong — strengthen it before continuing.

5. **Implement the production change** — minimal code to make the test pass. Code blocks in this plan show the body; type signatures named here MUST be used verbatim downstream (per the plan's type-consistency contract).

6. **Build the full tree, run `ctest -L features`, assert ALL features tests still pass** — the new test green AND no existing test red. If existing tests red, the change broke contract; fix or rewrite the existing test in lockstep (P4.6 is the only place this is normal — every other task should preserve existing tests).

7. **Commit** with the standard subject form: `ANTS-1160: P<phase>.<sub> — <one-line summary> (<criterion if applicable>)`. Body explains *why* and lists INVs covered.

8. **Push** (public repo, free runner minutes; no batching).

**Recipe per "fixture-generation timed test"** (used in P4.6 for criteria 3 and 4):

```cpp
// Generate a synthetic roadmap of approx N KiB of bullets, write to
// tmpdir, parse + render, time with QElapsedTimer.
QString synthRoadmap(int targetKiB) {
    QString out = "<!-- ants-roadmap-format: 2 -->\n# t\n\n## 0.7.x — t\n";
    int counter = 1;
    while (out.size() < targetKiB * 1024) {
        out += QStringLiteral(
            "- 📋 [TASK-%1] **Synthetic bullet %1.**\n"
            "  Layman: Plain-English summary line for testing render perf.\n"
            "  Body prose. Kind: implement. Lanes: synth.\n")
            .arg(counter++, 4, 10, QLatin1Char('0'));
    }
    return out;
}

QElapsedTimer t; t.start();
RoadmapDialog dlg(tmp.filePath("ROADMAP.md"), "default");
dlg.show();  // forces first paint
QApplication::processEvents();
must(t.elapsed() < 200, "criterion 3: cold-open under 200 ms");
```

For 60 fps scroll (criterion 4), use a 1.5 MiB fixture, programmatically scroll via `QScrollBar::setValue` over a sequence of positions, time the per-frame `paintEvent` cost via a custom `QStyledItemDelegate` wrapper that records per-paint duration into a vector. Assert the 99th-percentile per-frame paint cost ≤ 16.67 ms.

Concrete instrumentation pattern (5 lines, drop into the test wrapper delegate):

```cpp
class TimingDelegate : public RoadmapCardDelegate {
public:
    mutable std::vector<int> paint_us;  // microseconds per paint
    void paint(QPainter *p, const QStyleOptionViewItem &o, const QModelIndex &i) const override {
        const auto t0 = std::chrono::steady_clock::now();
        RoadmapCardDelegate::paint(p, o, i);
        paint_us.push_back(std::chrono::duration_cast<std::chrono::microseconds>(
            std::chrono::steady_clock::now() - t0).count());
    }
};

// After scroll sequence completes:
std::sort(d.paint_us.begin(), d.paint_us.end());
const int p99 = d.paint_us[d.paint_us.size() * 99 / 100];
must(p99 <= 16670, "criterion 4: 99th-pct paint <= 16.67 ms");
```

This timed-test scaffold MUST be reused for both P4.6c (`roadmap_dialog_v2_perf` test) and any future perf regressions — extract into `tests/features/_perf_helpers.h` if a third user appears.

```markdown
**Prefix.** New roadmap items use the literal prefix `TASK`. Existing
items in legacy projects retain their original prefix (`ANTS`, `MYPRJ`,
etc.) **forever** — once an ID is assigned it never changes, even when
the project's prefix policy does. Parsers MUST accept any 3–6
character all-caps prefix as valid; `TASK` is the canonical prefix
for new bullets in v2-conforming projects.

**Why universal `TASK-`, not per-kind prefixes** (`DSN-`, `PHS-`,
`DOC-` etc.): three reasons. (1) The `Kind:` field is already on
every bullet (mandatory in v1.1) and carries the same information —
a per-kind prefix would duplicate it. (2) IDs are immutable for life;
if a bullet's Kind ever changes, a per-kind prefix would freeze a
wrong category onto the ID forever. The Kind field can change; the
ID can't. (3) Cross-project portability — every roadmap item is
uniformly a Task across all projects.
```

QString roadmap::allocateId(const QString &cwd) {
    // 1. Find project root (walk up from cwd until ROADMAP.md found)
    QDir d(cwd);
    while (!d.exists("ROADMAP.md")) {
        if (!d.cdUp()) return errorJson("no project root");
    }
    const QString counterPath = d.filePath(".roadmap-counter");
    QFile f(counterPath);
    if (!f.exists()) return errorJson("no counter file");

    // 2. Try non-blocking flock first (GUI thread)
    int fd = ::open(counterPath.toLocal8Bit().constData(), O_RDWR);
    if (fd < 0) return errorJson("counter open failed");

    if (::flock(fd, LOCK_EX | LOCK_NB) == -1 && errno == EWOULDBLOCK) {
        // 3. Contended → retry on a worker thread (blocking acquire)
        ::close(fd);
        QFuture<QString> fut = QtConcurrent::run([counterPath]() {
            int wfd = ::open(counterPath.toLocal8Bit().constData(), O_RDWR);
            if (wfd < 0) return errorJson("counter open failed");
            ::flock(wfd, LOCK_EX);  // blocking
            QString r = readIncrementWriteUnderLock(wfd, counterPath);
            ::flock(wfd, LOCK_UN);
            ::close(wfd);
            return r;
        });
        fut.waitForFinished();
        return fut.result();
    }

    // 4. Got the lock cleanly on GUI thread
    QString r = readIncrementWriteUnderLock(fd, counterPath);
    ::flock(fd, LOCK_UN);
    ::close(fd);
    return r;
}

static QString readIncrementWriteUnderLock(int fd, const QString &counterPath) {
    QFile f; f.open(fd, QIODevice::ReadWrite, QFileDevice::DontCloseHandle);
    f.seek(0);
    bool ok = false;
    qint64 cur = QString::fromUtf8(f.readAll().trimmed()).toLongLong(&ok);
    if (!ok) return errorJson("counter parse failed");
    qint64 next = cur + 1;
    f.resize(0);
    f.seek(0);
    f.write(QString::number(next).toUtf8() + "\n");
    f.flush();
    ::fsync(f.handle());
    QJsonObject o;
    o["id"] = QStringLiteral("TASK-%1").arg(next, 4, 10, QLatin1Char('0'));
    o["counter_path"] = ".roadmap-counter";
    return QJsonDocument(QJsonObject(o)).toJson(QJsonDocument::Compact);
}

static QString errorJson(const char *msg) {
    QJsonObject o; o["error"] = QString::fromUtf8(msg);
    return QJsonDocument(o).toJson(QJsonDocument::Compact);
}
