# ANTS-1160 — Roadmap dialog redesign implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Redesign the Roadmap dialog and format per `docs/specs/ANTS-1160.md` (commit `844d13b`). Replace the wall-of-text HTML rendering with a card-based widget model; introduce universal `TASK-NNNN` IDs (preserving legacy `ANTS-NNNN`); fold three new `Kind:` values plus a `Layman:` field into the format spec; add five Phase-1 IPC verbs; ship the broader doc-tree alignment in lockstep so the rest of the project's docs reflect v2 reality.

**Architecture:** Markdown stays as the source of truth (no schema change). Dialog rewrites from `renderHtml → QTextBrowser` to a `QListView` with a custom `QStyledItemDelegate` that renders one card per actionable bullet (collapsed / open-Layman / open-Detail). Section headings render as their own collapsible row widgets. Filtering operates by inclusion (Tab × Kind × Status × Search compose with AND); transitive-parent inclusion fires off the Tab predicate only. Persistence migrates from single-key `Config::roadmap*` entries to a per-project TOML file at `~/.config/ants-terminal/roadmap-state.toml` keyed by SHA-1 of the project path. IPC verbs ride on the existing `remotecontrol.cpp` socket dispatch; allocation runs on a worker thread to avoid wedging the event loop.

**Tech Stack:** Qt 6, C++20, CMake. No new runtime dependencies. New `roadmap-state.toml` parsing leverages the existing `tomlplusplus` if present, or hand-rolled minimal TOML reader (the file is shape-controlled by us). Feature tests follow the project's `tests/features/<name>/spec.md + test_<name>.cpp` pattern per `tests/features/README.md`.

**Spec:** `docs/specs/ANTS-1160.md` (commit `844d13b`) is the source of truth for behaviour, acceptance criteria, IPC verb shapes, and the 11-criterion gate set. This plan describes execution order and per-task verification; consult the spec for any "what" question.

**Repo visibility:** PUBLIC. Per global rule §6, push freely after each phase ships green CI; no batching required.

**Buildable-state contract:** every task produces a buildable tree (compiles + existing `ctest` green) unless explicitly noted otherwise. Phase boundaries are commit boundaries. Acceptance criteria are verified at the end of the phase that ships them.

```markdown
**Prefix.** New roadmap items use the literal prefix `TASK`. Existing
items in legacy projects retain their original prefix (`ANTS`, `MYPRJ`,
etc.) **forever** — once an ID is assigned it never changes, even when
the project's prefix policy does. Parsers MUST accept any 3–6
character all-caps prefix as valid; `TASK` is the canonical prefix
for new bullets in v2-conforming projects.

**Why universal `TASK-`, not per-kind prefixes** (`DSN-`, `PHS-`,
`DOC-` etc.): three reasons. (1) The `Kind:` field is already on
every bullet (mandatory in v1.1) and carries the same information —
a per-kind prefix would duplicate it. (2) IDs are immutable for life;
if a bullet's Kind ever changes, a per-kind prefix would freeze a
wrong category onto the ID forever. The Kind field can change; the
ID can't. (3) Cross-project portability — every roadmap item is
uniformly a Task across all projects.
```

#include <string>

std::string slurp(const char *path) {
    std::ifstream in(path);
    if (!in) {
        std::cerr << "FAIL: cannot read " << path << "\n";
        std::exit(2);
    }
    std::stringstream ss;
    ss << in.rdbuf();
    return ss.str();
}

bool contains(const std::string &hay, const std::string &needle) {
    return hay.find(needle) != std::string::npos;
}
}

int main() {
    const std::string mw = slurp(SRC_MAINWINDOW_CPP_PATH);
    const std::string sb = slurp(DOCS_STATUS_BAR_STANDARD_PATH);

    auto must = [](bool ok, const char *msg) {

QString RemoteControl::handleRoadmapAllocateId(const QString &cwd) {
    // 1. Find project root (walk up from cwd until ROADMAP.md found)
    QDir d(cwd);
    while (!d.exists("ROADMAP.md")) {
        if (!d.cdUp()) return errorJson("no project root");
    }
    const QString counterPath = d.filePath(".roadmap-counter");
    QFile f(counterPath);
    if (!f.exists()) return errorJson("no counter file");

    // 2. Try non-blocking flock first (GUI thread)
    int fd = ::open(counterPath.toLocal8Bit().constData(), O_RDWR);
    if (fd < 0) return errorJson("counter open failed");

    if (::flock(fd, LOCK_EX | LOCK_NB) == -1 && errno == EWOULDBLOCK) {
        // 3. Contended → retry on a worker thread (blocking acquire)
        ::close(fd);
        QFuture<QString> fut = QtConcurrent::run([counterPath]() {
            int wfd = ::open(counterPath.toLocal8Bit().constData(), O_RDWR);
            if (wfd < 0) return errorJson("counter open failed");
            ::flock(wfd, LOCK_EX);  // blocking
            QString r = readIncrementWriteUnderLock(wfd, counterPath);
            ::flock(wfd, LOCK_UN);
            ::close(wfd);
            return r;
        });
        fut.waitForFinished();
        return fut.result();
    }

    // 4. Got the lock cleanly on GUI thread
    QString r = readIncrementWriteUnderLock(fd, counterPath);
    ::flock(fd, LOCK_UN);
    ::close(fd);
    return r;
}

    QFile f; f.open(fd, QIODevice::ReadWrite, QFileDevice::DontCloseHandle);
    f.seek(0);
    bool ok = false;
    qint64 cur = QString::fromUtf8(f.readAll().trimmed()).toLongLong(&ok);
    if (!ok) return errorJson("counter parse failed");
    qint64 next = cur + 1;
    f.resize(0);
    f.seek(0);
    f.write(QString::number(next).toUtf8() + "\n");

    return QJsonDocument(QJsonObject(o)).toJson(QJsonDocument::Compact);
}
